# 07. Aliases — псевдоніми команд у Bash

**Alias (псевдонім)** — це скорочення, яке Bash використовує для заміни введеного тексту команди іншим текстом.

Aliases допомагають скоротити довгі команди, спростити повсякденну роботу в терміналі та зробити часто використовувані команди зручнішими.

Наприклад, замість того щоб щоразу вводити `git status`, можна створити псевдонім `gs`.

    alias gs='git status'

Тепер достатньо виконати:

    gs

Bash підставить замість `gs` команду `git status`.

Aliases особливо корисні під час роботи з Linux, Git, файловою системою та проєктами Node.js. Водночас важливо розуміти їхні обмеження: aliases призначені переважно для інтерактивної роботи в оболонці, а не для створення повноцінних програмних функцій.

## 1. Основні поняття

✔ **Alias** — псевдонім, який замінює введений текст команди іншим текстом.

✔ **`alias`** — команда Bash для створення та перегляду псевдонімів.

✔ **`unalias`** — команда для видалення псевдоніма.

✔ **`alias name='command'`** — синтаксис створення псевдоніма.

✔ **`alias` без аргументів** — показує визначені псевдоніми.

✔ **`alias name`** — показує визначення конкретного псевдоніма.

✔ **`unalias name`** — видаляє конкретний псевдонім.

✔ **`unalias -a`** — видаляє всі псевдоніми поточної оболонки.

✔ **`~/.bashrc`** — типовий файл для збереження псевдонімів інтерактивного Bash.

✔ **`source ~/.bashrc`** — повторно виконує налаштування з `~/.bashrc` у поточній оболонці.

✔ **`command`** — дозволяє викликати команду, оминаючи псевдонім із такою назвою.

✔ **Function** — функція Bash, яка підходить для складніших операцій, аргументів і логіки.

## 2. Що потрібно пам'ятати

- Alias — це текстова заміна, а не окрема виконувана програма.
- Для створення псевдоніма використовують `alias name='command'`.
- Пробіли навколо `=` у визначенні псевдоніма не ставлять.
- Псевдоніми зазвичай діють лише в поточній оболонці Bash.
- Щоб зберегти псевдонім між сеансами, його додають до відповідного конфігураційного файлу, найчастіше `~/.bashrc`.
- Після редагування `~/.bashrc` можна виконати `source ~/.bashrc`, щоб застосувати зміни без перезапуску термінала.
- Alias не призначений для приймання аргументів як функція.
- У Bash псевдоніми зазвичай розгортаються під час читання команд, переважно в інтерактивній оболонці.
- Псевдоніми можуть змінювати поведінку знайомих команд, тому не варто створювати неоднозначні або небезпечні скорочення.
- Для складних команд, умов, циклів та обробки аргументів краще використовувати функції або скрипти.

## 3. Створення псевдоніма

### 3.1. Простий alias

Створимо псевдонім для команди `ls`.

    alias ll='ls -lah'

Тепер виконай:

    ll

Bash підставить команду:

    ls -lah

Параметри:

- `-l` — детальний список файлів;
- `-a` — показ прихованих файлів;
- `-h` — зручний для читання формат розмірів.

### 3.2. Alias для Git

Псевдоніми зручні для команд, які часто використовуються під час роботи з Git.

    alias gs='git status'
    alias gl='git log --oneline'
    alias ga='git add'
    alias gc='git commit'

Приклади використання:

    gs
    gl
    ga README.md
    gc -m "Update README"

Зверни увагу: псевдонім `ga='git add'` дозволяє додавати аргументи після назви псевдоніма. Але alias сам по собі не обробляє аргументи — Bash лише підставляє визначений текст перед рештою команди.

### 3.3. Alias для навігації

Можна створити короткі команди для переходу до часто використовуваних каталогів.

    alias croot='cd /'
    alias cproj='cd "$HOME/projects"'
    alias cdown='cd "$HOME/Downloads"'

Використання:

    cproj

Це виконає:

    cd "$HOME/projects"

Використовуй лапки для шляхів, які потенційно можуть містити пробіли.

Важливо: псевдонім для `cd` має сенс у поточній оболонці, оскільки `cd` змінює робочий каталог саме цієї оболонки.

## 4. Перегляд псевдонімів

### 4.1. Перегляд усіх aliases

Виконай:

    alias

Bash покаже визначені псевдоніми, наприклад:

    alias gs='git status'
    alias ll='ls -lah'
    alias gl='git log --oneline'

Точний список залежить від конфігурації твоєї оболонки.

### 4.2. Перегляд конкретного alias

    alias gs

Можливий результат:

    alias gs='git status'

Якщо псевдонім не визначено, Bash повідомить про це.

### 4.3. Перевірка команди через `type`

Команда `type` допомагає зрозуміти, як Bash інтерпретує назву.

    type ll

Якщо `ll` є псевдонімом, результат може бути таким:

    ll is aliased to `ls -lah'

Також можна перевірити звичайну команду:

    type cd

Bash повідомить, що `cd` — вбудована команда оболонки.

### 4.4. Перегляд псевдоніма без його виконання

Якщо потрібно перевірити визначення, використовуй:

    alias gs

Це безпечно показує визначення, не запускаючи саму команду `git status`.

## 5. Видалення псевдонімів

### 5.1. Видалення одного alias

Створимо псевдонім:

    alias testcmd='echo Hello'

Видалимо його:

    unalias testcmd

Перевіримо:

    alias testcmd

Після видалення Bash повідомить, що такий псевдонім не визначено.

### 5.2. Видалення всіх aliases

Команда:

    unalias -a

видаляє всі псевдоніми поточної оболонки.

**Застереження:** ця команда не видаляє псевдоніми з `~/.bashrc` або інших конфігураційних файлів. Якщо вони записані там, то можуть з'явитися знову після повторного завантаження налаштувань.

Не використовуй `unalias -a`, якщо хочеш видалити лише один псевдонім.

### 5.3. Тимчасове та постійне видалення

Якщо псевдонім створений лише в поточному терміналі:

    unalias gs

його буде видалено з поточної оболонки.

Якщо псевдонім також записаний у `~/.bashrc`, потрібно видалити або закоментувати відповідний рядок у файлі.

## 6. Постійні aliases у `~/.bashrc`

### 6.1. Чому псевдоніми зникають

Якщо виконати:

    alias gs='git status'

псевдонім зазвичай існуватиме лише в поточній оболонці.

Після закриття термінала та відкриття нового він може зникнути, якщо не був визначений у конфігурації.

### 6.2. Відкриття `~/.bashrc`

Відкрий конфігураційний файл:

    nano ~/.bashrc

Знайди секцію, призначену для aliases, або додай власну наприкінці файлу:

    # Custom aliases

    alias ll='ls -lah'
    alias gs='git status'
    alias gl='git log --oneline'

Збережи файл і вийди з редактора.

### 6.3. Застосування налаштувань

Щоб застосувати зміни в поточній оболонці, виконай:

    source ~/.bashrc

Або скорочений варіант:

    . ~/.bashrc

Перевір:

    alias ll
    alias gs
    alias gl

### 6.4. Перевірка в новому терміналі

Після збереження `~/.bashrc` відкрий новий термінал і перевір:

    alias

Якщо псевдоніми визначено правильно, вони будуть доступні в новому інтерактивному Bash, який завантажує цей файл.

**Важливо:** не кожна оболонка або кожен спосіб запуску Bash завантажує `~/.bashrc`. Поведінка залежить від того, чи є оболонка інтерактивною, як її запущено та як налаштовані файли конфігурації.

## 7. Рекомендовані aliases для Linux

Ці псевдоніми можуть зробити щоденну роботу з терміналом зручнішою.

### 7.1. Для перегляду файлів

    alias ll='ls -lah'
    alias la='ls -A'
    alias l='ls -CF'

Пояснення:

- `ll` — детальний список із прихованими файлами;
- `la` — список із прихованими файлами, крім спеціальних записів `.` і `..`;
- `l` — компактний формат списку.

Зверни увагу: деякі Linux-дистрибутиви вже визначають схожі aliases. Перед додаванням перевір:

    alias ll
    alias la
    alias l

### 7.2. Для переходу між каталогами

    alias ..='cd ..'
    alias ...='cd ../..'
    alias ....='cd ../../..'

Використання:

    ..

перейде на один рівень вище.

Команда:

    ...

перейде на два рівні вище.

Такі псевдоніми є зручними скороченнями, але не є стандартними командами Linux.

### 7.3. Для Git

    alias gs='git status'
    alias gl='git log --oneline'
    alias gd='git diff'
    alias gb='git branch'

Приклади:

    gs
    gl
    gd
    gb

Ці псевдоніми допомагають швидко перевіряти стан репозиторію, історію комітів, зміни та гілки.

### 7.4. Для роботи з каталогами проєктів

Якщо твої проєкти розташовані в `~/projects`, можна створити:

    alias cproj='cd "$HOME/projects"'

Якщо потрібно часто переходити до репозиторію `nest-exercises`, можна визначити:

    alias cnest='cd "$HOME/projects/nest-exercises"'

Перед використанням перевір, що відповідні каталоги справді існують.

    ls "$HOME/projects"

Якщо шлях до репозиторію відрізняється, адаптуй псевдонім до власної структури каталогів.

### 7.5. Не створюй зайвих aliases

Не обов'язково скорочувати кожну команду.

Наприклад, псевдонім:

    alias pwd='pwd'

нічого корисного не додає.

Краще створювати псевдоніми для команд, які ти часто використовуєш і які справді потребують скорочення.

## 8. Aliases та аргументи

### 8.1. Передавання аргументів після alias

Розглянемо:

    alias gs='git status'

Можна виконати:

    gs --short

Bash підставить команду, і фактично буде виконано:

    git status --short

Аналогічно:

    alias gl='git log --oneline'

Команда:

    gl -5

перетвориться на:

    git log --oneline -5

Отже, прості аргументи можна передавати після псевдоніма.

### 8.2. Чому alias не є функцією

Припустимо, ти хочеш створити команду, яка приймає назву каталогу як аргумент і переходить до нього.

Alias не має спеціального механізму для позиційних параметрів на кшталт `$1`, `$2` або `$@`.

Для такої задачі краще використати функцію Bash.

    cdir() {
        cd "$1"
    }

Використання:

    cdir "$HOME/projects"

Тут `$1` — перший аргумент функції.

Однак у цій простій функції не перевіряється, чи передано аргумент і чи існує каталог. Для надійнішого варіанта можна додати перевірки:

    cdir() {
        if [[ -z "${1:-}" ]]; then
            printf 'Вкажи шлях до каталогу.\n' >&2
            return 1
        fi

        if [[ ! -d "$1" ]]; then
            printf 'Каталог не існує: %s\n' "$1" >&2
            return 1
        fi

        cd -- "$1"
    }

Тепер функція перевіряє аргумент, перевіряє існування каталогу й переходить до нього лише тоді, коли перевірки успішні.

## 9. Alias, функція та скрипт

Ці механізми можуть використовуватися для скорочення або автоматизації команд, але мають різне призначення.

| Механізм | Для чого підходить | Приклад |
|---|---|---|
| Alias | Коротке скорочення команди | `alias gs='git status'` |
| Функція Bash | Логіка, аргументи, умови | `cdir() { cd "$1"; }` |
| Shell-скрипт | Окрема послідовність команд, яку можна запускати як файл | `./backup.sh` |

### 9.1. Коли використовувати alias

Якщо потрібно скоротити команду:

    git status

можна створити:

    alias gs='git status'

### 9.2. Коли використовувати функцію

Якщо потрібно перевірити аргумент, виконати декілька команд або обробити помилки, краще використати функцію.

    mkcd() {
        if [[ -z "${1:-}" ]]; then
            printf 'Вкажи назву каталогу.\n' >&2
            return 1
        fi

        mkdir -p -- "$1" && cd -- "$1"
    }

Використання:

    mkcd my-project

Функція створить каталог, якщо він ще не існує, а потім перейде до нього.

### 9.3. Коли використовувати скрипт

Якщо потрібно зберігати логіку в окремому файлі, запускати її з інших каталогів або використовувати в автоматизації, доцільно створити скрипт.

Наприклад:

    #!/usr/bin/env bash

    printf 'Current directory: %s\n' "$PWD"
    git status

Збережи його як `project-status.sh` і запускай відповідно до налаштувань прав доступу.

## 10. Як Bash розгортає aliases

### 10.1. Псевдоніми розгортаються під час читання команд

Bash зазвичай розгортає aliases під час читання командного тексту, до виконання команди.

Це означає, що alias — не механізм пошуку виконуваних файлів і не повноцінна система функцій.

### 10.2. Aliases у неінтерактивних скриптах

За замовчуванням aliases зазвичай увімкнені в інтерактивному Bash, але не в неінтерактивному.

Наприклад, у файлі `test-alias.sh`:

    #!/usr/bin/env bash

    alias hi='echo Hello'
    hi

звичайний запуск скрипту може завершитися повідомленням про те, що команда `hi` не знайдена.

Причина полягає в тому, що alias визначено під час виконання скрипту, але Bash за замовчуванням не виконує розгортання aliases у неінтерактивному режимі.

Для скриптів краще використовувати функції або звичайні команди, а не покладатися на aliases.

### 10.3. Чому `source ~/.bashrc` не завжди допомагає

Завантаження `~/.bashrc` саме по собі не гарантує, що aliases будуть розгортатися в неінтерактивному скрипті.

У Bash існує опція:

    shopt -s expand_aliases

Вона вмикає розгортання aliases у неінтерактивному режимі. Проте alias усе одно має бути визначений до того, як Bash прочитає команду, де він використовується.

Для звичайних автоматизованих скриптів краще застосовувати функції та явні команди. Це робить поведінку скрипту зрозумілішою та передбачуванішою.

## 11. Перевизначення команд і безпека

### 11.1. Alias із назвою системної команди

Bash дозволяє створити псевдонім із назвою вже наявної команди.

Наприклад:

    alias ls='ls --color=auto'

Це поширений приклад у Linux-конфігураціях.

Однак псевдонім може змінити звичну поведінку команди. Тому, якщо команда працює не так, як очікувалося, перевір її тип:

    type ls

### 11.2. Виклик команди в обхід alias

Якщо створено:

    alias ls='ls --color=auto'

можна викликати команду без розгортання псевдоніма:

    command ls

`command` наказує Bash шукати команду, оминаючи alias і функцію з таким ім'ям. Якщо існує зовнішня команда, буде виконано її.

Інший спосіб для простого випадку — екранувати назву команди:

    \ls

Це також запобігає розгортанню alias із назвою `ls`.

### 11.3. Небезпечні aliases

Не створюй псевдоніми, які приховують небезпечну поведінку або ускладнюють розуміння команди.

Особливо обережно стався до псевдонімів, що запускають:

- видалення файлів;
- зміну прав доступу;
- команди з `sudo`;
- масові зміни в репозиторії;
- команди, які перезаписують дані.

Перед використанням незнайомого alias перевір його визначення:

    alias назва_псевдоніма

Не запускай невідомий псевдонім, якщо не розумієш, які команди він виконує.

## 12. Типові помилки

### Помилка 1. Пробіли навколо `=`

Неправильно:

    alias gs = 'git status'

Правильно:

    alias gs='git status'

### Помилка 2. Неправильні лапки

Неправильно:

    alias gs=git status

У такому випадку Bash може спробувати створити псевдонім зі значенням, яке не відповідає очікуваному.

Правильно:

    alias gs='git status'

### Помилка 3. Очікування, що alias збережеться автоматично

    alias gs='git status'

Цей псевдонім зазвичай існуватиме лише в поточній оболонці.

Щоб зберегти його між сеансами, додай визначення до відповідного конфігураційного файлу, наприклад `~/.bashrc`.

### Помилка 4. Забутий `source`

Після редагування `~/.bashrc` новий псевдонім може бути недоступний у вже відкритому терміналі.

Застосуй налаштування:

    source ~/.bashrc

### Помилка 5. Використання alias замість функції

Не варто намагатися створювати складні конструкції з аргументами через aliases.

Для аргументів, умов і перевірок краще використовувати функції.

### Помилка 6. Використання aliases у скриптах

Aliases не є надійною основою для логіки скриптів, оскільки в неінтерактивному Bash вони за замовчуванням не розгортаються.

Використовуй явні команди, функції або окремі скрипти.

### Помилка 7. Випадкове видалення всіх aliases

Команда:

    unalias -a

видаляє всі псевдоніми поточної оболонки.

Якщо потрібно видалити лише один:

    unalias gs

### Помилка 8. Небезпечне перевизначення команди

Якщо ти перевизначив системну команду, спочатку перевір її через:

    type назва_команди

Для виклику зовнішньої команди без alias або функції можна використати:

    command назва_команди

### Помилка 9. Додавання дублікатів у `~/.bashrc`

Якщо багато разів додавати однакові визначення, конфігураційний файл стає неохайним.

Краще мати одну секцію для власних aliases і підтримувати її в порядку.

## 14. Рівні знань

### Core — базовий рівень

Потрібно вміти:

- пояснити, що таке alias;
- створити простий псевдонім;
- переглянути aliases через `alias`;
- перевірити один alias через `alias name`;
- видалити alias через `unalias`;
- розуміти, що aliases зазвичай діють у поточній оболонці;
- використовувати псевдоніми для скорочення довгих команд.

### Junior — практичний рівень

Потрібно вміти:

- зберігати власні aliases у `~/.bashrc`;
- застосовувати налаштування через `source ~/.bashrc`;
- створювати aliases для Git і навігації;
- перевіряти команди через `type`;
- пояснити різницю між alias і функцією;
- розуміти обмеження aliases у Bash-скриптах;
- не перевизначати команди без потреби.

### Middle — поглиблений рівень

Потрібно розуміти:

- коли Bash розгортає aliases;
- чому aliases зазвичай вимкнені для неінтерактивних оболонок;
- як працює `shopt -s expand_aliases`;
- чому порядок визначення aliases важливий;
- як aliases взаємодіють із функціями та зовнішніми командами;
- як організувати конфігурацію Bash без дублікатів;
- коли замінити alias функцією або окремим скриптом.

### Senior — системне розуміння

Потрібно розуміти:

- механізм розгортання aliases під час читання командного тексту Bash;
- особливості інтерактивного та неінтерактивного режимів;
- вплив aliases на відтворюваність команд і поведінку користувацького середовища;
- як створювати безпечні та зрозумілі конфігурації оболонки;
- чому автоматизація має спиратися на явні команди, функції та скрипти, а не на персональні aliases;
- як діагностувати конфлікти між aliases, функціями та командами.

## 15. Мінішпаргалка

    # Створити alias
    alias gs='git status'

    # Alias для детального списку файлів
    alias ll='ls -lah'

    # Alias для перегляду Git-історії
    alias gl='git log --oneline'

    # Переглянути всі aliases
    alias

    # Переглянути один alias
    alias gs

    # Перевірити тип команди
    type gs

    # Видалити один alias
    unalias gs

    # Видалити всі aliases поточної оболонки
    unalias -a

    # Відкрити конфігурацію Bash
    nano ~/.bashrc

    # Застосувати конфігурацію
    source ~/.bashrc

    # Викликати команду в обхід alias або функції
    command ls

    # Функція з аргументом
    cdir() {
        cd "$1"
    }

    # Використання функції
    cdir "$HOME/projects"

## 16. Практичні завдання

### Завдання 1. Створення простого alias

Створи псевдонім:

    alias hi='echo Hello Linux'

Виконай:

    hi

Очікуваний результат:

    Hello Linux

Перевір визначення:

    alias hi

### Завдання 2. Aliases для перегляду файлів

Створи три псевдоніми:

- `ll` — для `ls -lah`;
- `la` — для `ls -A`;
- `l` — для `ls -CF`.

Перевір їх через `type` і виконай кожен.

Якщо такі aliases вже існують, спочатку переглянь їхні визначення.

### Завдання 3. Aliases для Git

Створи псевдоніми:

    alias gs='git status'
    alias gl='git log --oneline'
    alias gd='git diff'

Виконай кожен у своєму Git-репозиторії.

Поясни, чому після `gs` можна передати додаткові аргументи.

### Завдання 4. Збереження aliases

1. Відкрий `~/.bashrc`.
2. Додай власну секцію `# Custom aliases`.
3. Додай до неї два або три псевдоніми.
4. Збережи файл.
5. Виконай `source ~/.bashrc`.
6. Перевір псевдоніми через `alias`.
7. Відкрий новий термінал і переконайся, що вони доступні.

### Завдання 5. Видалення alias

Створи псевдонім:

    alias testalias='echo Test'

Перевір його:

    alias testalias

Видали:

    unalias testalias

Перевір ще раз і поясни, що змінилося.

### Завдання 6. Alias чи функція?

Спробуй створити alias для переходу до каталогу проєкту:

    alias cproj='cd "$HOME/projects"'

Потім створи функцію, яка приймає шлях як аргумент.

Порівняй, який варіант зручніший для фіксованого каталогу, а який — для довільних шляхів.

### Завдання 7. Дослідження розгортання aliases

Створи файл `test-alias.sh`:

    #!/usr/bin/env bash

    alias hi='echo Hello'
    hi

Запусти його звичайним способом.

Поясни, чому alias може не розгорнутися в неінтерактивному Bash.

Потім досліди, що зміниться після ввімкнення `expand_aliases`. Пам'ятай, що для надійних скриптів краще використовувати функції або звичайні команди.

### Завдання 8. Діагностика команди

Виконай:

    type ls
    type cd
    type git

Якщо `ls` визначено як alias, переглянь його через:

    alias ls

Виклич зовнішню команду в обхід alias:

    command ls

Поясни різницю між alias, вбудованою командою Bash і зовнішньою програмою.

### Завдання 9. Власний набір aliases

Створи невеликий набір aliases для щоденної роботи:

- перегляд файлів;
- перевірка Git-репозиторію;
- перегляд історії комітів;
- перехід до каталогу проєктів.

Збережи їх у `~/.bashrc`, перевір і переконайся, що вони не перевизначають важливі команди несподіваним способом.

## 17. Підсумок

Aliases — простий інструмент Bash, який допомагає скоротити команди та зробити роботу в терміналі зручнішою.

Найважливіше запам'ятати:

- `alias name='command'` створює псевдонім.
- `alias` показує визначені aliases.
- `unalias name` видаляє конкретний псевдонім.
- `~/.bashrc` зазвичай використовують для постійних aliases інтерактивного Bash.
- `source ~/.bashrc` застосовує зміни в поточній оболонці.
- `type name` допомагає визначити, як Bash інтерпретує назву.
- `command name` дозволяє викликати команду в обхід alias або функції з такою назвою.
- Alias може приймати додаткові аргументи після себе, але не має власного механізму позиційних параметрів.
- Для аргументів, умов і складнішої логіки краще використовувати функції.
- Для автоматизації та повторного використання команд краще створювати скрипти.

**Головний принцип:** використовуй aliases для коротких командних скорочень, функції — для логіки та аргументів, а скрипти — для окремих послідовностей автоматизованих дій.
