# 02. Bash Variables

Variables (змінні) — це іменовані області збереження значень, які використовуються в Bash для роботи з текстом, числами, шляхами, параметрами команд та іншими даними.

Змінні дозволяють зберігати інформацію один раз і використовувати її багаторазово під час виконання команд або Bash-скриптів.

Змінні Bash використовуються, коли потрібно:

- зберегти ім'я користувача;
- зберегти шлях до каталогу або файла;
- зберегти результат виконання команди;
- передавати дані між командами;
- виконувати арифметичні операції;
- керувати поведінкою скрипту;
- працювати з параметрами функцій;
- зберігати тимчасові значення;
- створювати локальні змінні у функціях;
- передавати змінні середовища дочірнім процесам.

Наприклад:

    name="Valeriy"

    echo "$name"

Результат:

    Valeriy

Тут:

    name       → назва змінної
    "Valeriy"  → значення, яке присвоюється змінній
    "$name"    → звернення до значення змінної

Основні поняття Bash Variables:

    parameter expansion
    local variable
    global variable

## Що потрібно пам'ятати

• У Bash змінній можна присвоїти значення за допомогою `=`.

• Навколо `=` під час присвоєння не повинно бути пробілів.

• Правильно:

    name="Valeriy"

• Неправильно:

    name = "Valeriy"

• Щоб отримати значення змінної, використовують `$name` або `${name}`.

• Фігурні дужки `${name}` допомагають чітко визначити межі назви змінної.

• Подвійні лапки дозволяють розгортання змінних:

    echo "$name"

• Одинарні лапки зберігають `$name` як звичайний текст:

    echo '$name'

• Bash розрізняє великі та малі літери: `name`, `Name` і `NAME` — різні змінні.

• Змінні Bash зазвичай зберігають текстові значення. Арифметичні операції над цілими числами підтримуються окремими засобами Bash.

• Звичайна змінна Bash не передається автоматично всім дочірнім процесам.

• `export` позначає змінну для передавання в середовище дочірніх процесів.

• `local` створює змінну, локальну для функції.

• `readonly` робить змінну незмінною в межах поточної оболонки.

• `unset` видаляє змінну або її значення з поточного shell environment.

• `$?` містить статус завершення попередньої команди, тому його не слід плутати зі звичайною змінною користувача.

• `$1`, `$2` та інші позиційні параметри дозволяють отримувати аргументи скрипту або функції.

• `$#` показує кількість позиційних параметрів.

• `$@` і `$*` використовуються для роботи з усіма позиційними параметрами, але поводяться по-різному в подвійних лапках.

• `${variable:-default}` дозволяє використати значення за замовчуванням, якщо змінна не встановлена або порожня.

• Для надійного Bash-коду важливо розуміти різницю між unset variable та empty variable.

# Variable

Variable — змінна, яка має назву та значення.

Приклад:

    name="Valeriy"

Тепер змінна `name` містить текст:

    Valeriy

Можна створити декілька змінних:

    name="Valeriy"
    city="Vinnytsia"
    language="Bash"

Вивести їхні значення:

    echo "$name"
    echo "$city"
    echo "$language"

Результат:

    Valeriy
    Vinnytsia
    Bash

Змінні дозволяють уникнути повторного введення тих самих даних.

Наприклад:

    project="nest-exercises"

    echo "Project: $project"
    echo "Working with $project"
    echo "Repository: $project"

Результат:

    Project: nest-exercises
    Working with nest-exercises
    Repository: nest-exercises

Якщо потрібно змінити назву проєкту, достатньо змінити значення змінної.

---

# Variable Assignment

Variable assignment — присвоєння значення змінній.

Синтаксис:

    variable=value

Приклад:

    name="Valeriy"

Тут:

    name      → назва змінної
    =         → оператор присвоєння
    "Valeriy" → значення

У Bash під час звичайного присвоєння не можна ставити пробіли навколо `=`.

Правильно:

    name="Valeriy"
    age=56
    project="nest-exercises"

Неправильно:

    name = "Valeriy"

Чому?

Bash інтерпретує пробіли як роздільники команд та аргументів. Запис `name = "Valeriy"` не є звичайним присвоєнням змінній `name`.

Важливо: лапки навколо значення не завжди обов'язкові, але їх використання часто робить код безпечнішим і зрозумілішим.

Наприклад:

    name=Valeriy

Також працює:

    name="Valeriy"

Для тексту з пробілами лапки необхідні або потрібно екранувати пробіли:

    project="my Linux project"

Або:

    project=my\ Linux\ project

---

# Reading Variable Values

Щоб отримати значення змінної, використовують знак `$`.

Наприклад:

    name="Valeriy"

    echo "$name"

Результат:

    Valeriy

Символ `$` повідомляє Bash, що потрібно виконати розгортання змінної.

Без `$` назва змінної сприймається як звичайний текст:

    echo name

Результат:

    name

А з `$`:

    echo "$name"

Результат:

    Valeriy

Це фундаментальна відмінність між назвою змінної та її значенням.

---

# $variable

Форма `$variable` — короткий спосіб отримати значення змінної.

Приклад:

    name="Bash"

    echo "$name"

Результат:

    Bash

Інший приклад:

    directory="/home/taubu/projects"

    echo "$directory"

Результат:

    /home/taubu/projects

Однак у складніших текстових конструкціях `$variable` може бути неоднозначним.

Наприклад:

    name="Valeriy"

    echo "$nameDeveloper"

Bash шукатиме змінну `nameDeveloper`, а не `name` із доданим текстом `Developer`.

Для таких випадків використовують `${variable}`.

---

# ${variable}

Форма `${variable}` — розгорнутий синтаксис звернення до змінної.

Приклад:

    name="Valeriy"

    echo "${name}"

Результат:

    Valeriy

У простих випадках ці два записи еквівалентні:

    echo "$name"

    echo "${name}"

Але фігурні дужки допомагають визначити межі назви змінної.

Наприклад:

    name="Valeriy"

    echo "${name}Developer"

Результат:

    ValeriyDeveloper

Тут Bash розгортає змінну `name`, а потім додає текст `Developer`.

Інший приклад:

    project="nest-exercises"

    echo "Project directory: ${project}/practice"

Результат:

    Project directory: nest-exercises/practice

У складніших конструкціях `${...}` також використовується для значень за замовчуванням, перевірок та обробки рядків.

---

# Variable Reassignment

Значення змінної можна змінювати.

Приклад:

    name="Valeriy"

    echo "$name"

    name="Developer"

    echo "$name"

Результат:

    Valeriy
    Developer

Після другого присвоєння змінна містить нове значення.

Інший приклад:

    counter=1

    echo "$counter"

    counter=2

    echo "$counter"

Результат:

    1
    2

Звичайна змінна Bash не є константою: її значення можна переприсвоювати, якщо вона не оголошена як `readonly`.

---

# Variable Naming

Назви змінних Bash мають відповідати правилам іменування.

Зазвичай використовують:

    letters
    digits
    underscores

Назва не повинна починатися з цифри.

Правильні назви:

    name
    user_name
    project
    project_name
    file2
    count_10
    _internal

Некоректні для звичайних назв змінних:

    2name
    user-name
    project.name
    first name

У назвах змінних Bash не використовують дефіс як звичайний символ імені, оскільки він має інше значення в командному синтаксисі.

Регістр має значення:

    name="one"
    Name="two"
    NAME="three"

Це три окремі змінні.

Поширені стилі:

    user_name
    project_path
    file_count

У Bash часто використовують `snake_case` для власних змінних.

---

# Empty Variable

Empty variable — змінна, яка існує, але містить порожній рядок.

Приклад:

    name=""

Перевірити значення:

    echo "Name: [$name]"

Результат:

    Name: []

Змінна `name` встановлена, але її значення має нульову довжину.

Інший варіант:

    name=''

Обидва присвоєння створюють порожнє значення.

Це відрізняється від змінної, яку взагалі не встановлено.

---

# Unset Variable

Unset variable — змінна, якій не присвоєно значення або яку було видалено командою `unset`.

Приклад:

    echo "$unknown_variable"

Якщо змінна не встановлена, Bash зазвичай підставляє порожній рядок, якщо не ввімкнено спеціальні налаштування на кшталт `set -u`.

Тому результат:

    [ ]

може бути візуально схожим на результат порожньої змінної.

Порівняння:

    empty=""
    unset unset_variable

    printf 'empty=[%s]\n' "$empty"
    printf 'unset=[%s]\n' "$unset_variable"

Результат:

    empty=[]
    unset=[]

У цьому виведенні обидва значення виглядають порожніми.

Щоб перевірити, чи встановлена змінна, використовують `${variable+x}` або умовні конструкції Bash.

Наприклад:

    if [[ -v empty ]]; then
        echo "empty is set"
    fi

    if [[ -v unset_variable ]]; then
        echo "unset_variable is set"
    else
        echo "unset_variable is not set"
    fi

Результат:

    empty is set
    unset_variable is not set

Конструкція `[[ -v variable ]]` доступна в Bash і перевіряє, чи встановлений параметр.

---

# unset

`unset` — вбудована команда Bash, яка видаляє змінну або функцію.

Синтаксис для змінної:

    unset variable_name

Приклад:

    name="Valeriy"

    echo "$name"

    unset name

    echo "$name"

Результат:

    Valeriy

Після видалення змінної остання команда зазвичай нічого не виведе.

Перевірити стан:

    if [[ -v name ]]; then
        echo "name is set"
    else
        echo "name is not set"
    fi

Результат:

    name is not set

`unset` впливає на поточну оболонку або відповідний контекст виконання.

Якщо змінна була експортована, її видалення також прибирає її з середовища поточної оболонки.

---

# readonly

`readonly` — команда Bash для оголошення змінної незмінною.

Приклад:

    readonly APP_NAME="Linux Practice"

    echo "$APP_NAME"

Результат:

    Linux Practice

Після оголошення `readonly` звичайна спроба змінити змінну призведе до помилки.

Наприклад:

    readonly APP_NAME="Linux Practice"

    APP_NAME="Another Project"

Bash повідомить, що змінну не можна змінити.

Також можна оголосити змінну й потім зробити її незмінною:

    APP_VERSION="1.0"
    readonly APP_VERSION

Вивести список змінних, позначених як readonly:

    readonly

Важливо: `readonly` не означає, що значення неможливо підробити в будь-якому зовнішньому контексті. Це обмеження переприсвоєння в поточній оболонці та її відповідних контекстах.

---

# declare

`declare` — вбудована команда Bash для оголошення змінних і встановлення їхніх атрибутів.

Приклад:

    declare name="Valeriy"

    echo "$name"

`declare` особливо корисна для:

    local variables
    readonly variables
    indexed arrays
    associative arrays
    variable attributes

Переглянути оголошені змінні:

    declare -p name

Можливий результат:

    declare -- name="Valeriy"

Результат показує оголошення змінної та її значення.

Приклад оголошення цілочисельної змінної:

    declare -i count=10

    count=count+5

    echo "$count"

Результат:

    15

Атрибут `-i` змушує Bash обробляти присвоєння значення як арифметичний вираз.

Для початкового рівня достатньо знати, що `declare` дозволяє оголошувати змінні та задавати їхні атрибути.

# Local Variable

Local variable — змінна, локальна для функції Bash.

Для її створення використовують `local`.

Приклад:

    greet() {
        local name="Valeriy"

        echo "Hello, $name"
    }

    greet

Результат:

    Hello, Valeriy

Змінна `name` доступна всередині функції `greet`.

Після завершення функції локальне значення не стає звичайною глобальною змінною.

Наприклад:

    greet() {
        local name="Valeriy"

        echo "Inside: $name"
    }

    greet

    echo "Outside: ${name-unset}"

Результат:

    Inside: Valeriy
    Outside: unset

Тут `${name-unset}` повертає текст `unset`, якщо змінна `name` не встановлена.

Важливо: локальна змінна може тимчасово затінити однойменну змінну з зовнішнього контексту.

---

# Global Variable

Global variable у контексті Bash — змінна, яка не обмежена локальною областю певної функції.

Приклад:

    name="Valeriy"

    greet() {
        echo "Hello, $name"
    }

    greet

Результат:

    Hello, Valeriy

Функція читає значення змінної `name`, визначеної поза нею.

Змінна, створена без `local` усередині функції, зазвичай стає змінною оболонки й може впливати на подальші команди.

Наприклад:

    update_name() {
        name="Developer"
    }

    name="Valeriy"

    update_name

    echo "$name"

Результат:

    Developer

У великих скриптах локальні змінні допомагають зменшити небажані побічні ефекти.

---

# Variable Scope

Variable scope — область, у якій змінна доступна та впливає на виконання коду.

У Bash важливо розрізняти:

    shell variables
    local variables
    environment variables
    positional parameters

Звичайна змінна оболонки:

    project="nest-exercises"

Локальна змінна функції:

    build_project() {
        local project="demo"
        echo "$project"
    }

Змінна середовища:

    export NODE_ENV="development"

Позиційний параметр:

    echo "$1"

Область видимості Bash відрізняється від правил видимості змінних у JavaScript.

Зокрема, `local` у Bash зазвичай використовується всередині функцій, а звичайні змінні оболонки можуть бути доступні в ширшому контексті поточного shell.

# Shell Variable vs Environment Variable

Це важлива різниця.

## Shell variable

Звичайна змінна, створена в поточній оболонці.

    project="nest-exercises"

Перевірити:

    echo "$project"

Результат:

    nest-exercises

Зазвичай така змінна не передається автоматично зовнішнім програмам.

## Environment variable

Змінна, яка передається в середовище дочірніх процесів.

    export project="nest-exercises"

Тепер змінна позначена для експорту.

Запустити дочірню оболонку:

    bash -c 'echo "$project"'

Результат:

    nest-exercises

Порівняння:

    project="nest-exercises"

    bash -c 'echo "${project-unset}"'

Результат:

    unset

У звичайному випадку дочірній Bash не отримує неекспортовану змінну батьківської оболонки.

Тепер:

    export project="nest-exercises"

    bash -c 'echo "$project"'

Результат:

    nest-exercises

Це демонструє, що `export` дозволяє передавати змінну в середовище дочірніх процесів.

---

# export

`export` — вбудована команда Bash, яка позначає змінну для включення в середовище дочірніх процесів.

Синтаксис:

    export VARIABLE=value

Приклад:

    export APP_ENV="development"

Перевірити:

    echo "$APP_ENV"

Результат:

    development

Змінна буде доступна в дочірніх програмах, які запускаються з цього середовища, якщо її не вилучено або не перевизначено.

Наприклад:

    export APP_ENV="development"

    bash -c 'echo "$APP_ENV"'

Результат:

    development

Можна також спочатку створити змінну, а потім експортувати:

    APP_ENV="development"

    export APP_ENV

Обидва варіанти є поширеними.

# Перегляд Environment Variables

Для перегляду змінних середовища використовують кілька команд.

## env

Показує середовище, передане команді.

    env

Вивід може містити багато змінних.

Для фільтрації можна використати:

    env | grep '^HOME='

Приклад:

    HOME=/home/taubu

## printenv

Показує значення змінних середовища.

    printenv HOME

Приклад:

    /home/taubu

Переглянути іншу змінну:

    printenv PATH

Вивести кілька змінних:

    printenv HOME USER SHELL

Якщо змінна відсутня, команда може не вивести значення для неї.

## set

Команда `set` без аргументів у Bash показує змінні та функції поточної оболонки, зокрема змінні, які не обов'язково експортуються.

    set

Вивід може бути дуже великим, тому для початку зручніше використовувати:

    declare -p variable_name

або:

    printenv VARIABLE_NAME

Важливо: `set` також використовується для зміни параметрів поведінки Bash, тому це не просто команда перегляду змінних.

---

# Змінна HOME

`HOME` — змінна середовища, яка зазвичай містить шлях до домашнього каталогу користувача.

Перевірити:

    echo "$HOME"

Приклад:

    /home/taubu

Перейти до домашнього каталогу:

    cd "$HOME"

Також можна використовувати:

    cd ~

У багатьох типових ситуаціях ці варіанти приводять до домашнього каталогу.

`HOME` корисна для створення шляхів:

    config_file="$HOME/.bashrc"

    echo "$config_file"

Приклад:

    /home/taubu/.bashrc

Не слід жорстко записувати шлях до домашнього каталогу, якщо його можна отримати зі змінної `HOME`.

---

# Змінна USER

`USER` часто містить ім'я поточного користувача в середовищі.

    echo "$USER"

Приклад:

    taubu

Однак значення `USER` — це змінна середовища, а не гарантований спосіб автентифікації або перевірки реальних прав користувача.

Для перевірки ефективного імені користувача зазвичай використовують:

    whoami

Для додаткової інформації про ідентифікатори та групи:

    id

---

# Змінна PWD

`PWD` зазвичай містить шлях до поточного робочого каталогу, який підтримує оболонка.

    echo "$PWD"

Приклад:

    /home/taubu/projects

Для перевірки поточного каталогу також використовують:

    pwd

`PWD` може зберігати логічний шлях, який містить символічні посилання, тоді як фізичний шлях можна отримати окремими засобами, наприклад `pwd -P`.

Для звичайної навігації зручно використовувати:

    cd "$HOME"
    pwd

---

# Змінна PATH

`PATH` — змінна середовища, яка містить список каталогів для пошуку зовнішніх виконуваних програм.

Подивитися значення:

    echo "$PATH"

Приклад:

    /usr/local/bin:/usr/bin:/bin

Каталоги розділяються двокрапками `:`.

Коли ти вводиш:

    node --version

Bash шукає відповідну команду за правилами пошуку команд. Для зовнішніх програм одним із головних механізмів є пошук каталогами `PATH`.

Перевірити:

    command -v node

Додати каталог до `PATH` для поточного shell:

    export PATH="$HOME/bin:$PATH"

Тут:

    $HOME/bin → каталог, який додається
    $PATH     → попереднє значення PATH

Це поширений шаблон, який додає новий каталог на початок списку.

Важливо: додавай до `PATH` лише каталоги, яким довіряєш. Невдале налаштування `PATH` може призвести до запуску не тієї програми, яку ти очікуєш.

Змінна `PATH` буде детальніше розглянута в розділі:

    06-environment-variables

---

# Positional Parameters

Positional parameters — спеціальні параметри Bash, які містять аргументи скрипту або функції.

Наприклад, створимо файл `greet.sh`:

    #!/usr/bin/env bash

    echo "First argument: $1"
    echo "Second argument: $2"

Запуск:

    bash greet.sh Valeriy Linux

Результат:

    First argument: Valeriy
    Second argument: Linux

Тут:

    $1 → перший аргумент
    $2 → другий аргумент

Інший приклад:

    bash greet.sh Hello World

Результат:

    First argument: Hello
    Second argument: World

Позиційні параметри дозволяють робити скрипти універсальними.

---

# $0

`$0` — спеціальний параметр, який містить назву або спосіб виклику поточного скрипту чи оболонки.

Приклад файла `info.sh`:

    #!/usr/bin/env bash

    echo "Script name: $0"

Запуск:

    bash info.sh

Результат:

    Script name: info.sh

Якщо запускати скрипт за іншим шляхом, `$0` може містити цей шлях або інше представлення, яке залежить від способу запуску.

У команді:

    bash -c 'echo "$0"'

результат залежить від способу передавання аргументів; без додаткового імені Bash зазвичай використовує `bash` як `$0`.

---

# $1, $2, $3

Ці параметри містять окремі аргументи скрипту або функції.

Приклад:

    #!/usr/bin/env bash

    echo "Name: $1"
    echo "City: $2"
    echo "Project: $3"

Запуск:

    bash info.sh Valeriy Vinnytsia nest-exercises

Результат:

    Name: Valeriy
    City: Vinnytsia
    Project: nest-exercises

Якщо аргумент не передано, відповідний позиційний параметр зазвичай розгортається в порожній рядок, якщо не ввімкнено суворий режим на кшталт `set -u`.

---

# $# — кількість аргументів

`$#` містить кількість позиційних параметрів.

Приклад:

    #!/usr/bin/env bash

    echo "Argument count: $#"

Запуск:

    bash info.sh one two three

Результат:

    Argument count: 3

Якщо не передати жодного аргументу:

    bash info.sh

Результат:

    Argument count: 0

Це корисно, коли скрипт повинен перевіряти, чи передав користувач усі необхідні параметри.

Приклад:

    #!/usr/bin/env bash

    if [[ $# -lt 1 ]]; then
        echo "Usage: bash script.sh <name>"
        exit 1
    fi

    echo "Hello, $1"

Тут скрипт завершується з ненульовим статусом, якщо не передано жодного аргументу.

---

# "$@" — усі аргументи

`"$@"` дозволяє працювати з усіма позиційними параметрами, зберігаючи кожен аргумент окремо.

Приклад:

    #!/usr/bin/env bash

    printf '<%s>\n' "$@"

Запуск:

    bash args.sh apple "red apple" orange

Результат:

    <apple>
    <red apple>
    <orange>

Кожен аргумент зберігає свою межу, зокрема аргумент із пробілом.

`"$@"` особливо важливий під час передавання аргументів іншій команді або функції.

Наприклад:

    process_arguments() {
        printf 'Argument: <%s>\n' "$@"
    }

    process_arguments apple "red apple" orange

Результат:

    Argument: <apple>
    Argument: <red apple>
    Argument: <orange>

---

# "$*" — усі аргументи разом

`"$*"` у подвійних лапках розгортає всі позиційні параметри в один рядок, об'єднуючи їх першим символом змінної `IFS`.

Приклад:

    #!/usr/bin/env bash

    printf '<%s>\n' "$*"

Запуск:

    bash args.sh apple "red apple" orange

Типовий результат:

    <apple red apple orange>

Порівняння:

    "$@" → окремий аргумент для кожного позиційного параметра
    "$*" → один об'єднаний рядок у подвійних лапках

Для передавання аргументів далі зазвичай використовують `"$@"`, тому що він зберігає початкове розділення аргументів.

---

# $@ vs $*

Це одна з найважливіших відмінностей у Bash.

Приклад:

    #!/usr/bin/env bash

    printf 'Using "$@":\n'
    printf '<%s>\n' "$@"

    printf 'Using "$*":\n'
    printf '<%s>\n' "$*"

Запуск:

    bash args.sh one "two words" three

Результат:

    Using "$@":
    <one>
    <two words>
    <three>
    Using "$*":
    <one two words three>

Отже:

    "$@" → кілька окремих аргументів
    "$*" → один об'єднаний рядок

Без подвійних лапок обидві форми можуть зазнавати поділу слів та pathname expansion, тому в більшості практичних випадків для передачі всіх аргументів використовують саме `"$@"`.

---

# $? — Exit Status

`$?` містить статус завершення останньої виконаної команди.

Зазвичай:

    0     → success
    non-0 → error or another result

Приклад:

    true

    echo "$?"

Результат:

    0

Інший приклад:

    false

    echo "$?"

Результат:

    1

Важливо: статус може змінитися після виконання наступної команди.

Правильно зберегти статус:

    some_command
    status=$?

    echo "Exit status: $status"

Це дозволяє перевірити результат потрібної команди пізніше.

---

# $$ — PID поточної оболонки

`$$` — спеціальний параметр, який у Bash зазвичай містить PID оболонки, що виконує скрипт.

Приклад:

    echo "$$"

Результат:

    12345

Число наведене лише як приклад.

PID — ідентифікатор процесу.

Використання:

    echo "Shell PID: $$"

Це може бути корисно для діагностики процесів.

Важливо: у деяких контекстах, наприклад у subshell, створеному дужками, значення `$$` може залишатися PID початкової оболонки Bash. Для отримання PID поточного Bash-процесу використовують також `$BASHPID`.

---

# $! — PID останнього фонового процесу

`$!` містить PID останнього процесу, запущеного у фоні в поточній оболонці.

Приклад:

    sleep 30 &

    echo "$!"

Результат:

    12346

Число наведене лише як приклад.

Це корисно для роботи з фоновими процесами.

Наприклад:

    sleep 30 &

    process_id=$!

    echo "Background PID: $process_id"

`$!` не слід плутати з `$$`:

    $$ → PID оболонки
    $! → PID останнього фонового процесу

---

# Default Values

У Bash можна задавати значення за замовчуванням для змінних.

Це особливо корисно в скриптах, коли користувач може не передати певне значення.

Основні конструкції:

    ${variable:-default}
    ${variable:=default}
    ${variable:?message}
    ${variable:+value}

Вони відрізняються поведінкою щодо змінних, які не встановлені або мають порожнє значення.

---

# ${variable:-default}

Якщо змінна не встановлена або порожня, Bash використовує значення за замовчуванням.

Приклад:

    name=""

    echo "${name:-Guest}"

Результат:

    Guest

Інший приклад:

    unset name

    echo "${name:-Guest}"

Результат:

    Guest

Важливо: ця конструкція не змінює значення самої змінної.

Наприклад:

    name=""

    result="${name:-Guest}"

    echo "$result"
    echo "[$name]"

Результат:

    Guest
    []

Змінна `name` залишилася порожньою.

---

# ${variable-default}

Ця форма використовує значення за замовчуванням лише тоді, коли змінна не встановлена.

Приклад:

    unset name

    echo "${name-Guest}"

Результат:

    Guest

Але якщо змінна встановлена як порожній рядок:

    name=""

    echo "${name-Guest}"

Результат — порожній рядок.

Порівняння:

    ${name-default}
        → default, якщо змінна не встановлена

    ${name:-default}
        → default, якщо змінна не встановлена або порожня

Різниця полягає в наявності двокрапки `:`.

---

# ${variable:=default}

Якщо змінна не встановлена або порожня, Bash присвоює їй значення за замовчуванням і повертає це значення.

Приклад:

    unset name

    echo "${name:=Guest}"

Результат:

    Guest

Тепер змінна також містить:

    Guest

Перевірити:

    echo "$name"

Результат:

    Guest

Інший приклад:

    project=""

    project="${project:=linux-practice}"

    echo "$project"

Результат:

    linux-practice

Ця конструкція корисна, коли потрібно не тільки використати запасне значення, а й зберегти його у змінній.

---

# ${variable:?message}

Ця конструкція перевіряє, чи змінна встановлена та не порожня.

Якщо значення відсутнє або порожнє, Bash виводить повідомлення про помилку. У неінтерактивному Bash така помилка зазвичай призводить до завершення оболонки, що виконує розгортання.

Приклад:

    unset project

    echo "${project:?Project name is required}"

Очікувано Bash повідомить:

    Project name is required

Для безпечного тестування цієї поведінки можна використовувати окремий виклик Bash:

    bash -c 'unset project; echo "${project:?Project name is required}"'

Це дозволяє спостерігати помилку, не завершуючи поточну інтерактивну оболонку.

Варіант без двокрапки:

    ${variable?message}

перевіряє, чи змінна встановлена, але не вважає порожній рядок помилкою.

---

# ${variable:+value}

Якщо змінна встановлена та не порожня, Bash використовує альтернативне значення.

Приклад:

    name="Valeriy"

    echo "${name:+Name is available}"

Результат:

    Name is available

Якщо змінна порожня:

    name=""

    echo "${name:+Name is available}"

Результат — порожній рядок.

Це корисно, коли потрібно сформувати текст або параметр лише за наявності значення.

Порівняння:

    ${name:-Guest}
        → використати Guest, якщо name відсутня або порожня

    ${name:=Guest}
        → встановити Guest, якщо name відсутня або порожня

    ${name:?Error}
        → повідомити про помилку, якщо name відсутня або порожня

    ${name:+value}
        → використати value, якщо name встановлена й не порожня

---

# Arithmetic Expansion

Arithmetic expansion — механізм Bash для виконання арифметичних обчислень.

Синтаксис:

    $(( expression ))

Приклад:

    echo "$((2 + 3))"

Результат:

    5

Змінні також можна використовувати в арифметичних виразах.

    a=10
    b=5

    echo "$((a + b))"

Результат:

    15

Усередині арифметичного виразу знак `$` перед назвою змінної зазвичай не потрібен.

Можна виконувати:

    echo "$((10 + 5))"
    echo "$((10 - 5))"
    echo "$((10 * 5))"
    echo "$((10 / 5))"
    echo "$((10 % 3))"

Результат:

    15
    5
    50
    2
    1

Bash виконує цілочисельну арифметику. Тому:

    echo "$((7 / 2))"

Результат:

    3

Дробова частина відкидається.

Для арифметики з плаваючою комою зазвичай використовують зовнішні інструменти, наприклад `bc`, якщо він встановлений.

---

# Arithmetic Assignment

Змінні можна використовувати для збереження результатів арифметичних операцій.

Приклад:

    a=10
    b=5

    sum=$((a + b))

    echo "$sum"

Результат:

    15

Інший приклад:

    counter=0

    counter=$((counter + 1))

    echo "$counter"

Результат:

    1

Це поширений шаблон у Bash-скриптах.

Для збільшення лічильника також можна використовувати:

    ((counter++))

Або:

    ((counter += 1))

Важливо: арифметичні команди Bash можуть повертати статус завершення залежно від результату виразу. Наприклад, `((expression))` повертає статус `1`, якщо вираз обчислився до нуля, і `0`, якщо результат ненульовий.

Тому в скриптах із `set -e` потрібно уважно враховувати поведінку арифметичних команд.

---

# let

`let` — вбудована команда Bash для виконання арифметичних виразів.

Приклад:

    a=10
    b=5

    let sum=a+b

    echo "$sum"

Результат:

    15

Також:

    counter=0

    let counter=counter+1

    echo "$counter"

Результат:

    1

Для сучасного Bash часто зручніше використовувати:

    counter=$((counter + 1))

або:

    ((counter += 1))

Ці форми зазвичай легше читати в контексті арифметичних операцій.

---

# Integer Variables

Bash може працювати з цілими числами.

Приклад:

    age=56

    echo "$age"

Результат:

    56

Але звичайне присвоєння саме по собі не робить змінну числовим типом, як у JavaScript або TypeScript.

Наприклад:

    value="10"

    echo "$value"

Результат:

    10

Значення звичайної змінної Bash зберігається як текст, а арифметичні контексти інтерпретують відповідні значення як числа.

Приклад:

    a=10
    b=20

    result=$((a + b))

    echo "$result"

Результат:

    30

Для складних математичних обчислень Bash має обмеження. Він не є повноцінним інструментом для роботи з числами з плаваючою комою.

---

# Arrays — короткий вступ

Bash підтримує масиви, які дозволяють зберігати кілька значень під одним ім'ям.

Приклад індексованого масиву:

    fruits=("apple" "banana" "orange")

Отримати перший елемент:

    echo "${fruits[0]}"

Результат:

    apple

Отримати другий елемент:

    echo "${fruits[1]}"

Результат:

    banana

Індекси звичайних індексованих масивів Bash починаються з `0`.

Отримати всі елементи:

    echo "${fruits[@]}"

Порахувати кількість елементів:

    echo "${#fruits[@]}"

Масиви — окрема тема, але важливо знати, що вони розширюють можливості звичайних змінних.

---

# Змінні та лапки

Під час роботи зі змінними важливо правильно використовувати лапки.

Приклад:

    name="Valeriy"

    echo "$name"

Результат:

    Valeriy

Подвійні лапки дозволяють розгортання змінних.

Одинарні лапки:

    echo '$name'

Результат:

    $name

Bash сприймає `$name` як буквальний текст.

Розглянемо змінну з пробілами:

    project="Linux Practice"

    echo "$project"

Результат:

    Linux Practice

Якщо не використовувати подвійні лапки:

    printf '<%s>\n' $project

Bash може розділити значення на окремі слова, тому результат буде:

    <Linux>
    <Practice>

Для звичайного виведення змінних, передачі аргументів і роботи зі шляхами зазвичай використовують:

    "$variable"

або:

    "${variable}"

# Змінні та command substitution

Результат виконання команди можна зберегти у змінній.

Синтаксис:

    variable=$(command)

Приклад:

    current_dir=$(pwd)

    echo "$current_dir"

Результат може бути таким:

    /home/taubu/projects

Інший приклад:

    current_user=$(whoami)

    echo "$current_user"

Результат:

    taubu

Можна також зберегти результат обчислення команди:

    file_count=$(find . -maxdepth 1 -type f | wc -l)

    echo "$file_count"

Тут:

    find → знаходить файли
    wc   → рахує рядки
    $(...) → підставляє результат у змінну

Цей приклад рахує звичайні файли безпосередньо в поточному каталозі, не переходячи в підкаталоги.

Важливо: command substitution видаляє кінцеві символи нового рядка з результату команди. Якщо потрібно зберігати форматований багаторядковий текст, слід враховувати цю особливість.

Детальніше:

    04-command-substitution

# Змінні у функціях

Функції Bash можуть приймати аргументи через позиційні параметри.

Приклад:

    greet() {
        local name="$1"

        echo "Hello, $name!"
    }

    greet "Valeriy"

Результат:

    Hello, Valeriy!

Тут:

    $1    → перший аргумент функції
    local → локальна змінна
    name  → ім'я локальної змінної

Інший приклад:

    add() {
        local a="$1"
        local b="$2"

        echo "$((a + b))"
    }

    add 10 20

Результат:

    30

У Bash функції зазвичай передають результат через стандартне виведення, а не повертають довільне значення так, як функції JavaScript.

Команда `return` у Bash використовується для повернення статусу завершення функції, а не довільного текстового або числового значення.

# Типові помилки

## 1. Пробіли навколо `=`

Неправильно:

    name = "Valeriy"

Правильно:

    name="Valeriy"

У Bash присвоєння змінної має виконуватися без пробілів навколо оператора `=`.

---

## 2. Забувати `$` під час читання значення

Неправильно, якщо потрібно отримати значення змінної:

    echo name

Це виведе буквальний текст:

    name

Правильно:

    echo "$name"

---

## 3. Плутати одинарні та подвійні лапки

    name="Valeriy"

    echo '$name'

Результат:

    $name

Правильно для розгортання змінної:

    echo "$name"

---

## 4. Не використовувати лапки навколо змінної

Нехай:

    project="Linux Practice"

Команда:

    printf '<%s>\n' $project

може вивести:

    <Linux>
    <Practice>

Правильно:

    printf '<%s>\n' "$project"

Результат:

    <Linux Practice>

---

## 5. Плутати unset та empty

    name=""

Змінна встановлена, але порожня.

    unset name

Змінна видалена.

Перевіряти наявність змінної можна так:

    [[ -v name ]]

---

## 6. Плутати shell variable та environment variable

Звичайна змінна:

    APP_ENV="development"

Експортована змінна:

    export APP_ENV="development"

Лише другий варіант автоматично передає змінну в середовище дочірніх процесів, якщо вона не була перевизначена або видалена.

---

## 7. Використовувати глобальні змінні без потреби

Небажаний шаблон у великій функції:

    build_project() {
        project_name="demo"
    }

Така функція змінює змінну оболонки.

Часто краще:

    build_project() {
        local project_name="demo"
        echo "$project_name"
    }

---

## 8. Плутати `"$@"` та `"$*"`

    "$@" → зберігає кожний аргумент окремо
    "$*" → об'єднує аргументи в один рядок у подвійних лапках

Для передавання аргументів зазвичай використовують:

    "$@"

---

## 9. Забувати, що `$?` змінюється

Неправильно:

    some_command
    echo "Finished"
    echo "$?"

Останній рядок показує статус попередньої команди `echo`, а не `some_command`.

Правильно:

    some_command
    status=$?

    echo "$status"

---

## 10. Вважати, що Bash має всі типи JavaScript

У Bash звичайні змінні не працюють так само, як `number`, `string`, `boolean` або `object` у JavaScript.

Наприклад:

    value="10"

Значення звичайної змінної — текст. Арифметичний контекст може інтерпретувати його як ціле число:

    echo "$((value + 5))"

Результат:

    15

Але Bash не є заміною повноцінній системі типів.

---

## 11. Вважати, що `readonly` можна скасувати звичайним `unset`

Якщо змінна позначена як `readonly`, спроба видалити її або переприсвоїти значення призведе до помилки.

Приклад:

    readonly APP_NAME="Linux"

    unset APP_NAME

Тому `readonly` варто використовувати лише тоді, коли змінна справді має залишатися незмінною в межах оболонки.

---

## 12. Вважати, що `local` працює будь-де

`local` призначена для створення локальних змінних у функціях Bash.

Приклад:

    greet() {
        local name="Valeriy"
        echo "$name"
    }

Не використовуй `local` як універсальну заміну звичайному присвоєнню поза функцією.

---

## 13. Не перевіряти обов'язкові аргументи

Якщо скрипт очікує `$1`, але користувач не передав аргумент, змінна може бути порожньою.

Надійніший підхід:

    if [[ $# -lt 1 ]]; then
        echo "Usage: bash script.sh <name>"
        exit 1
    fi

    echo "Hello, $1"

# Міні-шпаргалка

## Створення змінної

    name="Valeriy"

## Отримання значення

    echo "$name"

## Розгорнутий синтаксис

    echo "${name}"

## Додавання тексту

    echo "${name}Developer"

## Переприсвоєння

    name="Developer"

## Видалення

    unset name

## Незмінна змінна

    readonly APP_NAME="Linux"

## Локальна змінна

    greet() {
        local name="Valeriy"
        echo "$name"
    }

## Змінна середовища

    export APP_ENV="development"

## Перевірка змінної середовища

    printenv APP_ENV

## Домашній каталог

    echo "$HOME"

## Поточний каталог

    echo "$PWD"

## Шлях пошуку команд

    echo "$PATH"

## Кількість аргументів

    echo "$#"

## Перший аргумент

    echo "$1"

## Усі аргументи

    printf '<%s>\n' "$@"

## Статус останньої команди

    echo "$?"

## PID оболонки

    echo "$$"

## PID останнього фонового процесу

    echo "$!"

## Значення за замовчуванням

    echo "${name:-Guest}"

## Присвоєння значення за замовчуванням

    echo "${name:=Guest}"

## Перевірка обов'язкової змінної

    : "${PROJECT_NAME:?Project name is required}"

## Арифметика

    a=10
    b=5

    result=$((a + b))

    echo "$result"

## Command substitution

    current_dir=$(pwd)

    echo "$current_dir"

# Головне

• Змінна Bash зберігає значення під певним ім'ям.

• Присвоєння виконується без пробілів навколо `=`:

    name="Valeriy"

• `$name` та `${name}` використовуються для отримання значення змінної.

• `${name}` зручніше використовувати, коли після змінної додається інший текст.

• Подвійні лапки дозволяють розгортання змінних:

    echo "$name"

• Одинарні лапки сприймають `$name` як звичайний текст:

    echo '$name'

• Звичайні змінні Bash не мають такої самої системи типів, як JavaScript або TypeScript.

• `local` дозволяє створювати локальні змінні у функціях.

• `readonly` забороняє звичайне переприсвоєння змінної.

• `unset` видаляє змінну.

• `export` передає змінну в середовище дочірніх процесів.

• `HOME` зазвичай містить шлях до домашнього каталогу.

• `PATH` визначає каталоги для пошуку зовнішніх команд.

• `$1`, `$2` та інші позиційні параметри містять аргументи скрипту або функції.

• `$#` містить кількість позиційних параметрів.

• `"$@"` зберігає кожний аргумент окремо, а `"$*"` у подвійних лапках об'єднує їх в один рядок.

• `$?` містить статус завершення попередньої команди.

• `$((expression))` дозволяє виконувати цілочисельні арифметичні операції.

• `${variable:-default}` дозволяє використати запасне значення, якщо змінна відсутня або порожня.

• `${variable:=default}` додатково присвоює запасне значення змінній.

• `${variable:?message}` дозволяє перевірити наявність обов'язкового значення.

• `$(command)` дозволяє зберігати результат команди у змінній.

• Для надійного Bash-коду потрібно уважно використовувати лапки, перевіряти аргументи та враховувати область видимості змінних.

• Змінні є основою Bash-скриптів: вони дозволяють передавати дані між командами, керувати налаштуваннями та автоматизувати повторювані задачі.
