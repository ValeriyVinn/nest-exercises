# 04. Command Substitution у Bash

Command substitution (підстановка результату команди) — це механізм Bash, який дозволяє виконати команду та використати її стандартний вивід як частину іншої команди або значення змінної.

Замість того щоб окремо виконувати команду, дивитися на результат і вручну переносити його в іншу команду, Bash може зробити це автоматично.

Command substitution часто використовується для:

- отримання поточної дати й часу;
- збереження результату команди у змінну;
- отримання шляху до поточного каталогу;
- підрахунку файлів або рядків;
- використання результату однієї команди в іншій;
- написання практичних Bash-скриптів.

---

## 1. Основні способи command substitution

У Bash є два основні синтаксиси підстановки результату команди.

### 1.1. Сучасний рекомендований синтаксис `$()`

    variable=$(command)

Bash виконує команду всередині `$(...)`, отримує її стандартний вивід і підставляє цей результат у зовнішній контекст.

Приклад:

    current_dir=$(pwd)
    printf 'Current directory: %s\n' "$current_dir"

Приклад результату:

    Current directory: /home/taubu/projects

Шлях буде залежати від каталогу, у якому ти виконуєш команду.

### 1.2. Старий синтаксис із backticks

    variable=`command`

Приклад:

    current_dir=`pwd`
    printf 'Current directory: %s\n' "$current_dir"

Це також працює, але такий синтаксис менш зручний для читання та вкладених команд.

У сучасних Bash-скриптах рекомендовано використовувати `$()`.

### 1.3. Порівняння синтаксисів

| Синтаксис | Приклад | Рекомендація |
|---|---|---|
| `$()` | `result=$(pwd)` | Використовуй переважно його |
| Backticks | `` result=`pwd` `` | Знай, як читати, але не обирай для нового коду без потреби |

**Що потрібно пам'ятати:**

- `$()` — рекомендований спосіб підстановки результату команди.
- Команда всередині `$()` виконується.
- Її стандартний вивід підставляється у зовнішній контекст.
- Зовнішні подвійні лапки навколо `$(...)` зазвичай потрібні, коли результат зберігається у змінну або передається як аргумент.
- Підстановка команди не є тим самим, що підстановка змінної.

---

## 2. Як працює command substitution

Розгляньмо приклад:

    current_date=$(date)
    printf 'Today: %s\n' "$current_date"

Bash виконує такі дії:

1. Виконує команду `date`.
2. Отримує її стандартний вивід.
3. Видаляє всі кінцеві символи нового рядка з отриманого результату.
4. Підставляє результат замість `$(date)`.
5. Присвоює отриманий текст змінній `current_date`.

Приклад результату:

    Today: Sat Oct 17 20:30:00 EEST 2026

Дата, час і формат залежать від системи та налаштувань.

### 2.1. Без збереження у змінну

Підстановку можна використати безпосередньо в команді:

    printf 'Current directory: %s\n' "$(pwd)"

Тут результат `pwd` відразу передається як аргумент `printf`.

### 2.2. Зі збереженням у змінну

    current_dir=$(pwd)

    printf '%s\n' "$current_dir"

Цей спосіб корисний, якщо результат потрібно використати кілька разів.

### 2.3. Підстановка не створює змінну автоматично

Команда:

    pwd

просто виводить шлях до поточного каталогу.

Команда:

    current_dir=$(pwd)

виконує `pwd`, а потім зберігає результат у змінну `current_dir`.

---

## 3. Підстановка команди та підстановка змінної

Це два різні механізми Bash.

### 3.1. Підстановка змінної

    name="Valeriy"
    printf '%s\n' "$name"

Bash підставляє значення вже наявної змінної.

### 3.2. Підстановка команди

    name=$(whoami)
    printf '%s\n' "$name"

Bash виконує команду `whoami`, а потім зберігає її стандартний вивід у змінну.

### 3.3. Порівняння

| Вираз | Що відбувається |
|---|---|
| `$name` | Підставляється значення змінної `name` |
| `$(whoami)` | Виконується команда `whoami` |
| `$(pwd)` | Виконується команда `pwd` |
| `$(date)` | Виконується команда `date` |
| `$(ls)` | Виконується команда `ls`, підставляється її стандартний вивід |

**Запам'ятай:**

- `$variable` читає значення змінної.
- `$(command)` виконує команду та підставляє її стандартний вивід.

---

## 4. Використання command substitution зі змінними

Один із найпоширеніших сценаріїв — збереження результату команди у змінну.

### 4.1. Поточний каталог

    current_dir=$(pwd)
    printf 'Directory: %s\n' "$current_dir"

### 4.2. Ім'я користувача

    current_user=$(whoami)
    printf 'User: %s\n' "$current_user"

### 4.3. Поточна дата

    current_date=$(date +%F)
    printf 'Date: %s\n' "$current_date"

Приклад результату:

    Date: 2026-10-17

Формат `%F` у команді `date` відповідає даті у форматі `YYYY-MM-DD`.

### 4.4. Поточний час

    current_time=$(date +%H:%M:%S)
    printf 'Time: %s\n' "$current_time"

Приклад результату:

    Time: 20:30:00

### 4.5. Версія Bash

    bash_version=$(bash --version | head -n 1)
    printf '%s\n' "$bash_version"

Команда всередині `$()` містить конвеєр. Спочатку виконується `bash --version`, а `head -n 1` залишає перший рядок виводу.

### 4.6. Кількість елементів у каталозі

    item_count=$(find . -maxdepth 1 -mindepth 1 -type f | wc -l)
    printf 'Files: %s\n' "$item_count"

Команда підраховує звичайні файли безпосередньо в поточному каталозі, не заходячи в підкаталоги.

Важливо: тут рахується саме кількість звичайних файлів, а не всіх об'єктів каталогу.

---

## 5. Command substitution у тексті

Результат команди можна підставити безпосередньо в рядок.

### 5.1. Привітання з ім'ям користувача

    printf 'Hello, %s!\n' "$(whoami)"

### 5.2. Повідомлення з датою

    printf 'Today is %s\n' "$(date +%F)"

### 5.3. Поточний каталог у повідомленні

    printf 'You are working in: %s\n' "$(pwd)"

### 5.4. Поєднання кількох підстановок

    printf 'User: %s | Directory: %s\n' "$(whoami)" "$(pwd)"

Приклад результату:

    User: taubu | Directory: /home/taubu/projects

Обидві команди виконуються окремо, а їхні результати передаються в `printf`.

---

## 6. Подвійні лапки навколо command substitution

Підстановка команди часто повертає текст із пробілами або кількома рядками. Тому важливо розуміти, як подвійні лапки впливають на результат.

### 6.1. Рекомендований варіант

    current_dir="$(pwd)"
    printf '%s\n' "$current_dir"

Подвійні лапки допомагають зберегти результат як одне значення змінної.

### 6.2. Підстановка як аргумент команди

    printf '<%s>\n' "$(printf 'My Linux Project')"

Результат:

    <My Linux Project>

Зовнішні подвійні лапки гарантують, що результат підстановки передається як один аргумент.

### 6.3. Що відбувається без лапок

    printf '<%s>\n' $(printf 'My Linux Project')

Результат:

    <My>
    <Linux>
    <Project>

У цьому прикладі результат підстановки розділяється на слова, тому `printf` отримує три аргументи.

Якщо вивід містить символи glob-шаблонів, наприклад `*`, вони також можуть розгорнутися у відповідні імена файлів.

**Практичне правило:**

Зазвичай використовуй:

    "$(command)"

Особливо коли результат команди передається як аргумент іншій команді або зберігається у змінну.

---

## 7. Видалення кінцевих символів нового рядка

Одна з особливостей command substitution — Bash видаляє всі кінцеві символи нового рядка зі стандартного виводу команди.

### 7.1. Приклад із `printf`

    result=$(printf 'Hello\n')
    printf '<%s>\n' "$result"

Результат:

    <Hello>

Новий рядок після `Hello` видаляється під час підстановки.

### 7.2. Кілька кінцевих нових рядків

    result=$(printf 'Hello\n\n\n')
    printf '<%s>\n' "$result"

Результат:

    <Hello>

Усі кінцеві символи нового рядка видаляються, а не лише один.

### 7.3. Новий рядок усередині тексту

    result=$(printf 'First\nSecond\n')
    printf '%s\n' "$result"

Результат:

    First
    Second

Внутрішній перенос рядка зберігається. Видаляються лише символи нового рядка в самому кінці результату.

### 7.4. Чи можна зберегти кінцевий новий рядок?

Звичайна command substitution видаляє кінцеві символи нового рядка. Якщо потрібно зберегти їх, можна використати інший механізм, наприклад перенаправлення у файл або `read` із відповідним підходом.

Для більшості звичайних командних задач видалення кінцевого нового рядка є зручним і очікуваним.

---

## 8. Багаторядковий результат команди

Команда може виводити багато рядків. Command substitution може зберегти цей вивід у змінній.

### 8.1. Приклад

    file_list=$(printf 'index.html\nstyle.css\nscript.js\n')
    printf '%s\n' "$file_list"

Результат:

    index.html
    style.css
    script.js

У змінній `file_list` міститься багаторядковий текст.

### 8.2. Перевірка кількості рядків

    file_list=$(printf 'index.html\nstyle.css\nscript.js\n')
    printf '%s\n' "$file_list" | wc -l

Результат:

    3

Тут `printf` виводить збережений текст, а `wc -l` підраховує рядки.

### 8.3. Обмеження для роботи зі списками файлів

Command substitution зручна для тексту, але не є надійним способом передавати довільні імена файлів, оскільки імена можуть містити пробіли, переноси рядків та інші спеціальні символи.

Для обробки довільних імен файлів краще використовувати конструкції з нульовим роздільником, наприклад `find -print0` разом із `read -d ''` або іншими сумісними механізмами.

Детальніше це варто вивчити в темах циклів, роботи з файлами та обробки тексту.

---

## 9. Вкладена command substitution

Bash дозволяє вкладати одну підстановку команди в іншу.

Для цього особливо зручний синтаксис `$()`.

### 9.1. Приклад

    current_year=$(date +%Y)
    printf 'Year: %s\n' "$current_year"

Тут вкладення ще не потрібне.

А тепер приклад із двома рівнями:

    first_char=$(printf '%s' "$(whoami)" | cut -c 1)
    printf 'First character of username: %s\n' "$first_char"

Внутрішня підстановка:

    $(whoami)

отримує ім'я користувача.

Зовнішня підстановка:

    $(printf '%s' "$(whoami)" | cut -c 1)

виконує конвеєр, який отримує перший символ імені користувача.

### 9.2. Навіщо використовувати `$()` для вкладення

Старий синтаксис із backticks складніше читати, коли підстановки вкладені одна в одну.

Наприклад, з `$()` вкладеність очевидна:

    result=$(printf '%s' "$(date +%F)")

У складніших випадках `$()` зазвичай значно зрозуміліший за backticks.

---

## 10. Використання command substitution у шляхах

Command substitution корисна для створення шляхів на основі поточного середовища.

### 10.1. Шлях до поточного каталогу

    current_dir=$(pwd)
    printf '%s\n' "$current_dir"

### 10.2. Шлях до домашнього каталогу

    home_dir=$(printf '%s' "$HOME")
    printf '%s\n' "$home_dir"

У цьому прикладі command substitution не обов'язкова, адже `$HOME` уже є змінною. Він лише показує, що підстановка команди може повернути значення, яке вже було доступне іншим способом.

### 10.3. Шлях до навчального каталогу

    project_dir="$(pwd)/linux"
    printf '%s\n' "$project_dir"

Якщо поточний каталог — `/home/taubu/projects/nest-exercises/practice`, результат буде схожим на:

    /home/taubu/projects/nest-exercises/practice/linux

### 10.4. Використання шляху в команді

    project_dir="$(pwd)/linux"
    ls "$project_dir"

Подвійні лапки важливі, якщо в будь-якій частині шляху можуть бути пробіли.

---

## 11. Command substitution та конвеєри

Command substitution може містити не одну команду, а цілий конвеєр.

### 11.1. Перший рядок виводу

    first_line=$(ls -1 | head -n 1)
    printf 'First item: %s\n' "$first_line"

Команда `ls -1` виводить об'єкти каталогу по одному на рядок, а `head -n 1` залишає перший рядок.

### 11.2. Підрахунок рядків

    line_count=$(printf 'one\ntwo\nthree\n' | wc -l)
    printf 'Lines: %s\n' "$line_count"

Результат:

    Lines: 3

Зверни увагу: `wc -l` може додавати пробіли перед числом у своєму виводі. Якщо потрібен чистий числовий результат, можна застосувати інші способи підрахунку або обробки виводу.

### 11.3. Пошук файлів певного типу

    md_count=$(find . -type f -name '*.md' | wc -l)
    printf 'Markdown files: %s\n' "$md_count"

Команда підраховує файли з розширенням `.md` у поточному каталозі та його підкаталогах.

Шаблон `'*.md'` узято в одинарні лапки, щоб Bash не розгортав його до запуску `find`. Сам шаблон має обробити команда `find`.

---

## 12. Command substitution та арифметика

Результат команди можна використати в арифметичних операціях.

### 12.1. Збереження числа

    file_count=$(find . -maxdepth 1 -type f | wc -l)
    printf 'Files: %s\n' "$file_count"

### 12.2. Арифметичне розширення

Якщо змінна містить число, Bash може виконати арифметичну операцію:

    file_count=$(find . -maxdepth 1 -type f | wc -l)
    next_count=$((file_count + 1))

    printf 'Current count: %s\n' "$file_count"
    printf 'Next count: %s\n' "$next_count"

Тут використовуються два різні механізми:

- `$(...)` виконує команду;
- `$((...))` обчислює арифметичний вираз.

### 12.3. Не плутай синтаксис

    result=$(date +%Y)

Це підстановка результату команди.

    result=$((10 + 5))

Це арифметичне розширення, яке обчислює вираз `10 + 5`.

Результат другого прикладу:

    15

**Запам'ятай:**

- `$()` — command substitution;
- `$(( ))` — arithmetic expansion.

---

## 13. Command substitution та стандартний вивід

Command substitution отримує саме стандартний вивід команди (`stdout`).

Стандартний потік помилок (`stderr`) за замовчуванням не стає частиною результату.

### 13.1. Стандартний вивід

    result=$(printf 'Hello Linux')
    printf 'Result: %s\n' "$result"

Змінна `result` містить `Hello Linux`.

### 13.2. Повідомлення про помилки

Якщо команда виводить повідомлення про помилку в `stderr`, воно зазвичай з'явиться в терміналі, а не потрапить у змінну.

Наприклад:

    result=$(ls /directory-that-does-not-exist)
    printf 'Captured output: <%s>\n' "$result"

Команда `ls` зазвичай виведе повідомлення про помилку в термінал. Змінна може залишитися порожньою, якщо стандартний вивід відсутній.

### 13.3. Перенаправлення `stderr` у `stdout`

Якщо потрібно включити повідомлення про помилки в результат, можна перенаправити `stderr` у `stdout`:

    result=$(ls /directory-that-does-not-exist 2>&1)
    printf '%s\n' "$result"

Тепер текст помилки також потрапить у змінну `result`.

Використовуй цей прийом лише тоді, коли справді потрібно зберегти повідомлення про помилки. Не кожен результат команди має бути змішаним зі звичайними даними.

---

## 14. Статус завершення команди та command substitution

У Bash команда має статус завершення (exit status).

Зазвичай:

- `0` означає успішне виконання;
- ненульове значення означає помилку або інший результат, визначений командою.

Command substitution зберігає стандартний вивід, але сам по собі результат підстановки не показує статус команди.

### 14.1. Отримання результату команди

    result=$(date +%F)
    printf '%s\n' "$result"

### 14.2. Отримання статусу

    result=$(date +%F)
    command_status=$?

    printf 'Result: %s\n' "$result"
    printf 'Exit status: %s\n' "$command_status"

Змінна `command_status` отримує статус завершення попередньої команди — у цьому випадку присвоєння з підстановкою.

**Важливо:** `$?` потрібно зчитати відразу після команди, статус якої тебе цікавить. Якщо виконати іншу команду перед присвоєнням `command_status`, значення `$?` уже може бути іншим.

### 14.3. Перевірка успіху без окремого `$?`

Для практичних скриптів часто краще перевіряти команду безпосередньо в умові:

    if result=$(date +%F); then
        printf 'Date: %s\n' "$result"
    else
        printf 'Could not get date\n' >&2
    fi

Тут перевіряється статус команди з підстановкою. Це надійніше, ніж виконувати команду, а потім випадково перезаписати `$?` іншою командою.

### 14.4. Особливість конвеєрів

Якщо всередині command substitution є конвеєр, наприклад:

    result=$(command_a | command_b)

за замовчуванням статус конвеєра зазвичай відповідає статусу останньої команди `command_b`, а не обов'язково першої.

У Bash параметр `pipefail` змінює цю поведінку, дозволяючи конвеєру повертати ненульовий статус, якщо одна з команд завершилася з помилкою. Це окрема тема, яку варто вивчати разом із конвеєрами та обробкою помилок.

## 15. Command substitution у Bash-скриптах

Розгляньмо невеликий скрипт, який збирає інформацію про середовище.

    #!/usr/bin/env bash

    current_user=$(whoami)
    current_dir=$(pwd)
    current_date=$(date +%F)

    printf 'User: %s\n' "$current_user"
    printf 'Directory: %s\n' "$current_dir"
    printf 'Date: %s\n' "$current_date"

Такий скрипт демонструє практичне використання command substitution.

### 15.1. Чому зберігати результати у змінних зручно

- результат можна використати кілька разів;
- код стає зрозумілішим;
- можна окремо перевіряти результат і статус виконання;
- значення можна передавати іншим командам.

### 15.2. Коли краще використати підстановку без змінної

Якщо результат потрібен лише один раз, можна передати його безпосередньо команді:

    printf 'User: %s\n' "$(whoami)"

Не потрібно створювати змінну для кожного тимчасового результату, якщо це не робить код зрозумілішим.

---

## 16. Command substitution та процеси

Зазвичай команда всередині `$()` виконується в окремому середовищі підпроцесу shell. Зміни звичайних shell-змінних усередині такого середовища не змінюють значення відповідних змінних у батьківському shell.

### 16.1. Приклад

    name="Parent"

    result=$(name="Child"; printf '%s' "$name")

    printf 'Parent variable: %s\n' "$name"
    printf 'Captured result: %s\n' "$result"

Результат:

    Parent variable: Parent
    Captured result: Child

Пояснення:

- зовнішня змінна `name` має значення `Parent`;
- усередині command substitution змінна `name` отримує значення `Child`;
- результат `printf` зберігається в `result`;
- зміна `name` усередині підстановки не змінює `name` у батьківському shell.

Це важливо розуміти, коли пишеш скрипти зі змінними та підстановками.

### 16.2. Не всі команди поводяться однаково

Command substitution запускає команду в окремому середовищі виконання. Зміни shell-змінних не переходять назад до батьківського shell.

Проте зовнішні ефекти — наприклад запис у файл або зміни, зроблені через зовнішню програму, — можуть зберігатися, оскільки вони відбуваються поза звичайним станом змінних батьківського shell.

## 17. Альтернатива: process substitution

Process substitution — це інша конструкція Bash, яка зовні схожа на command substitution, але має інше призначення.

Command substitution:

    result=$(command)

Отримує стандартний вивід команди як текст.

Process substitution:

    diff <(command_a) <(command_b)

Передає командам спеціальні шляхи, через які вони можуть читати результати інших команд.

Приклад:

    diff <(printf 'apple\nbanana\n') <(printf 'apple\norange\n')

`diff` порівнює результати двох команд, не вимагаючи попереднього збереження кожного результату в окремий файл.

Process substitution не є основною темою цього розділу, але важливо не плутати її з `$(...)`.

## 18. Типові помилки

### Помилка 1. Плутають `$()` і `$(( ))`

Неправильно для арифметики:

    result=$(10 + 5)

Bash сприймає вміст `$()` як команду, яку потрібно виконати.

Правильно для арифметики:

    result=$((10 + 5))
    printf '%s\n' "$result"

Результат:

    15

### Помилка 2. Забувають подвійні лапки навколо результату

    result=$(printf 'My Linux Project')
    printf '<%s>\n' $result

Результат може розділитися на кілька аргументів.

Правильно:

    printf '<%s>\n' "$result"

### Помилка 3. Очікують збереження кінцевого нового рядка

    result=$(printf 'Hello\n')
    printf '%s' "$result"

Результат не містить кінцевого нового рядка, який був у виводі початкової команди.

Це стандартна поведінка command substitution.

### Помилка 4. Вважають, що підстановка повертає і stdout, і stderr

    result=$(some_command)

За замовчуванням у `result` потрапляє стандартний вивід. Стандартний потік помилок залишається окремим.

Якщо справді потрібно об'єднати обидва потоки:

    result=$(some_command 2>&1)

### Помилка 5. Зчитують `$?` надто пізно

    result=$(date +%F)
    printf '%s\n' "$result"
    command_status=$?

Тут `command_status` міститиме статус `printf`, а не початкового присвоєння з підстановкою.

Правильно:

    result=$(date +%F)
    command_status=$?

    printf '%s\n' "$result"
    printf 'Status: %s\n' "$command_status"

А ще краще — використовувати `if`, якщо потрібно перевірити успіх команди.

### Помилка 6. Використовують backticks у вкладених командах без потреби

Старий синтаксис із backticks складніше читати, особливо коли підстановки вкладені.

Для нового коду краще:

    result=$(printf '%s' "$(date +%F)")

### Помилка 7. Використовують command substitution для довільних списків файлів

    files=$(find . -type f)

Такий підхід може бути ненадійним, якщо імена файлів містять переноси рядків або інші незвичайні символи.

Для звичайного навчального текстового виводу цей приклад допустимий, але для надійної обробки довільних файлів варто використовувати `find -print0` і відповідний механізм читання нуль-розділених значень.

### Помилка 8. Вважають, що змінні всередині підстановки змінять батьківський shell

    name="Parent"
    result=$(name="Child"; printf '%s' "$name")
    printf '%s\n' "$name"

Результат:

    Parent

Зміна змінної всередині підстановки не переходить у батьківський shell.

### Помилка 9. Створюють непотрібну підстановку

    current_dir=$(printf '%s' "$PWD")

Це працює, але тут command substitution не потрібна: значення `$PWD` можна використати безпосередньо.

Простіше:

    current_dir="$PWD"

Використовуй command substitution, коли справді потрібно виконати команду та отримати її результат.

## 19. Що потрібно пам'ятати

✔ Command substitution дозволяє отримати стандартний вивід команди як текст.

✔ Основний синтаксис — `$(command)`.

✔ Синтаксис із backticks працює, але для нового коду зазвичай краще використовувати `$()`.

✔ Command substitution можна використати безпосередньо в аргументі іншої команди або для присвоєння змінній.

✔ Bash видаляє всі кінцеві символи нового рядка з результату підстановки.

✔ Внутрішні переноси рядка можуть залишатися у результаті.

✔ Зазвичай використовуй `"$()"` у контекстах, де результат має бути одним аргументом.

✔ `$()` виконує команду, а `$(( ))` обчислює арифметичний вираз.

✔ Command substitution за замовчуванням отримує `stdout`, а не `stderr`.

✔ Статус завершення потрібно перевіряти одразу або через `if`.

✔ Зміни звичайних shell-змінних усередині command substitution не змінюють їх у батьківському shell.

✔ Для довільних імен файлів command substitution не завжди підходить через можливі пробіли й переноси рядків.

✔ Не використовуй command substitution, якщо результат уже доступний у змінній і додатковий запуск команди не потрібен.

## 24. Підсумок

Command substitution — важливий інструмент Bash, який дозволяє автоматично отримувати результат виконання команди та використовувати його в іншому виразі.

Основні правила:

1. Використовуй `$(command)` для підстановки результату команди.
2. Зберігай результат у змінну, якщо його потрібно використати повторно.
3. Використовуй `"$()"` у контекстах, де результат має залишатися одним аргументом.
4. Пам'ятай, що Bash видаляє всі кінцеві символи нового рядка з результату.
5. Розрізняй стандартний вивід і потік помилок.
6. Перевіряй статус завершення команди, якщо від нього залежить подальша робота скрипту.
7. Не плутай command substitution `$(...)` з arithmetic expansion `$((...))`.
8. Не використовуй command substitution для передачі довільних списків файлів без урахування спеціальних символів у назвах.
9. Для вкладених команд віддавай перевагу `$()`, а не старому синтаксису з backticks.
10. Використовуй найпростіший механізм, який розв'язує задачу.

**Головне правило:** якщо потрібно виконати команду й отримати її стандартний вивід як текст, використовуй `$(command)`. Якщо результат передається іншій команді, зазвичай захищай його подвійними лапками.
