# 01. Bash Basics

Bash (Bourne Again SHell) — це командна оболонка (shell), яка дозволяє взаємодіяти з операційною системою Linux через команди, запускати програми, працювати з файлами та каталогами, керувати процесами й автоматизувати повсякденні завдання.

Bash використовується для:

- виконання команд Linux;
- навігації файловою системою;
- запуску програм;
- передавання аргументів командам;
- використання команд у послідовностях;
- перенаправлення введення та виведення;
- роботи з операторами `&&`, `||` та `;`;
- виконання команд із підстановками;
- написання Bash-скриптів;
- автоматизації задач розробника;
- керування сервером через термінал.

Bash особливо важливий для Backend Developer, тому що Linux-команди регулярно використовуються під час розробки, налагодження, роботи із серверами та розгортання застосунків.

## Що потрібно пам'ятати

• Bash — це командна оболонка, яка інтерпретує команди та організовує їх виконання.

• Terminal — програма, у якій користувач працює з командною оболонкою.

• CLI — інтерфейс взаємодії з комп'ютером за допомогою текстових команд.

• Команда зазвичай складається з назви, опцій та аргументів.

• Опції змінюють поведінку команди, а аргументи визначають, до чого вона застосовується.

• Пробіли розділяють елементи команди, тому пробіл усередині назви шляху може змінити спосіб її інтерпретації.

• Bash чутливий до регістру: `HOME`, `Home` та `home` — різні назви.

• Команда `pwd` показує поточний робочий каталог.

• Команда `type` допомагає визначити, що саме Bash запускає за вказаною назвою.

• `;` дозволяє виконати кілька команд послідовно незалежно від результату попередніх.

• `&&` виконує наступну команду лише тоді, коли попередня завершилася успішно.

• `||` виконує наступну команду лише тоді, коли попередня завершилася з помилкою.

• `|` передає стандартне виведення однієї команди на стандартне введення іншої.

• Кожна завершена команда має статус завершення. Статус `0` зазвичай означає успіх, ненульовий статус — помилку або інший результат, визначений програмою.

• Bash має власні вбудовані команди, наприклад `cd` та `read`, і запускає зовнішні програми, наприклад `ls` та `grep`.

• Для отримання довідки використовують `help`, `man` та довідку конкретної програми.

• Bash працює не тільки інтерактивно в терміналі, а й виконує команди зі скриптів.

# Shell

Shell — командна оболонка, яка приймає команди користувача або скрипту, інтерпретує їх і організовує виконання.

Shell може:

- запускати програми;
- працювати з аргументами;
- інтерпретувати змінні;
- виконувати підстановки;
- організовувати перенаправлення;
- з'єднувати команди;
- керувати виконанням командних конструкцій;
- виконувати скрипти.

У Linux існують різні командні оболонки:

    Bash
    sh
    Zsh
    Fish
    Ksh

Bash — одна з найпоширеніших оболонок Linux.

Перевірити, яка оболонка зазначена в поточному процесі:

    echo "$0"

Приклад результату:

    bash

Це типовий результат для інтерактивного сеансу Bash, але значення може відрізнятися залежно від способу запуску оболонки.

# Bash

Bash — Bourne Again SHell.

Це командна оболонка, сумісна з багатьма конструкціями традиційного `sh`, яка також має власні можливості.

Bash підтримує:

    variables
    quoting
    command substitution
    arithmetic expansion
    conditional statements
    loops
    functions
    arrays
    pipelines
    redirections
    job control

Приклад простої команди Bash:

    echo "Hello, Linux!"

Результат:

    Hello, Linux!

Тут:

    echo        → команда
    "Hello, Linux!" → аргумент
    output      → текст у терміналі

Bash інтерпретує команду та викликає відповідний механізм її виконання.

---

# Terminal

Terminal — програма, яка надає текстовий інтерфейс для роботи з командною оболонкою.

У Linux можна використовувати різні термінальні програми.

Наприклад:

    GNOME Terminal
    Konsole
    Xfce Terminal

У терміналі запускається shell, наприклад Bash.

Спрощена модель:

    User
      ↓
    Terminal
      ↓
    Bash
      ↓
    Command
      ↓
    Program / system operation
      ↓
    Output

Важливо розрізняти:

    Terminal → програма для взаємодії з оболонкою
    Bash     → командна оболонка
    Linux    → операційна система та її ядро

Термінал сам по собі не є Bash, а Bash не є операційною системою.

---

# CLI

CLI (Command-Line Interface) — текстовий інтерфейс, у якому користувач керує програмами за допомогою команд.

Приклад CLI:

    pwd
    ls
    cd projects
    mkdir demo
    touch README.md

CLI особливо корисний для:

    Linux administration
    Backend development
    Server management
    Git
    Docker
    SSH
    Automation
    Deployment

Багато інструментів розробника доступні через CLI.

Наприклад:

    node --version
    npm --version
    git status
    psql --version

Команди `node`, `npm`, `git` та `psql` виконуються як програми або інструменти командного рядка, якщо вони встановлені й доступні через `PATH`.

# Command Prompt

Command prompt — запрошення командної оболонки, яке показує, що вона готова приймати команди.

Наприклад:

    taubu@taubu-lap:~/projects$

Умовно розберемо:

    taubu       → ім'я користувача
    taubu-lap   → ім'я комп'ютера
    ~/projects  → поточний каталог
    $           → типовий символ звичайного користувача

У Bash символи запрошення часто мають таке значення:

    $ → звичайний користувач
    # → часто root

Однак це лише поширена домовленість оформлення prompt. Символи можна змінювати, тому вони не є надійним способом визначити права поточного користувача.

Наприклад:

    taubu@taubu-lap:~/projects$

Команда:

    pwd

може вивести:

    /home/taubu/projects

Символ `~` зазвичай позначає домашній каталог поточного користувача.

---

# Command Syntax

Команда часто має таку структуру:

    command [options] [arguments]

Наприклад:

    ls -l /home/taubu

Тут:

    ls          → command
    -l          → option
    /home/taubu → argument

Опції та аргументи залежать від конкретної команди. Не кожна команда потребує їх усіх.

Інший приклад:

    mkdir -p projects/linux

Тут:

    mkdir          → назва команди
    -p             → опція
    projects/linux → аргумент, шлях до каталогу

Опція `-p` дозволяє створювати відсутні батьківські каталоги та не повідомляти про помилку, якщо каталог уже існує.

---

# Command Name

Command name — назва команди, яку Bash намагається розпізнати.

Приклади:

    pwd
    ls
    cd
    mkdir
    touch
    cat
    grep
    find

Назва може відповідати:

- вбудованій команді Bash;
- функції Bash;
- alias;
- зовнішній програмі;
- іншому доступному командному об'єкту.

Тому одна й та сама назва не завжди означає запуск зовнішнього виконуваного файла.

Перевірити назву:

    type cd

Типовий результат:

    cd is a shell builtin

Перевірити іншу команду:

    type ls

Результат залежить від системи. Наприклад:

    ls is aliased to `ls --color=auto`

або:

    ls is /usr/bin/ls

---

# Arguments

Arguments — аргументи, які передаються команді.

Приклад:

    mkdir project

Тут:

    project → argument

Інший приклад:

    cp file.txt backup.txt

Аргументи:

    file.txt
    backup.txt

Команда `cp` використовує їх як джерело та призначення копіювання.

Кілька аргументів можуть передаватися через пробіли:

    mkdir project-a project-b project-c

Команда створить три каталоги, якщо операція завершиться успішно.

Аргументи не обов'язково є файлами. Вони можуть бути шляхами, значеннями, параметрами або іншими даними, залежно від команди.

---

# Options and Flags

Options — опції, які змінюють поведінку команди.

Наприклад:

    ls -l

Опція:

    -l

виводить детальний список файлів.

Інший приклад:

    ls -a

Опція `-a` показує також приховані файли.

Можна поєднати короткі опції:

    ls -la

Зазвичай це еквівалентно:

    ls -l -a

Для багатьох програм існують довгі опції:

    ls --all
    ls --help

Коротка опція зазвичай починається з одного дефіса:

    -a
    -l
    -r

Довга опція зазвичай починається з двох дефісів:

    --all
    --help
    --version

Це поширена конвенція, але конкретний синтаксис визначається програмою.

Деякі опції приймають значення:

    command --option value

Наприклад, у багатьох програмах:

    program --output result.txt

Точний синтаксис потрібно перевіряти в довідці конкретної команди.

---

# Spaces in Commands

Пробіли розділяють назву команди, опції та аргументи.

Наприклад:

    mkdir my-project

Bash передає команді один аргумент:

    my-project

Але:

    mkdir my project

Bash передає два аргументи:

    my
    project

Тому команда намагається створити два каталоги.

Якщо назва містить пробіл, використовуй лапки:

    mkdir "my project"

Або екранування пробілу:

    mkdir my\ project

Обидва варіанти дозволяють передати назву як один аргумент.

---

# Case Sensitivity

Bash чутливий до регістру символів.

Наприклад:

    name
    Name
    NAME

Це три різні назви.

Для команд:

    pwd
    PWD

`pwd` — стандартна команда Bash.

`PWD` зазвичай є назвою змінної середовища, а не еквівалентною командою.

Для файлів:

    README.md
    readme.md
    Readme.md

У типовій файловій системі Linux це можуть бути три різні файли.

Не слід автоматично переносити правила регістру Windows на Linux.

# Current Working Directory

Current working directory (CWD) — поточний робочий каталог, відносно якого інтерпретуються відносні шляхи.

Перевірити його:

    pwd

Приклад:

    /home/taubu/projects

Якщо поточний каталог:

    /home/taubu/projects

то команда:

    ls

показує вміст цього каталогу.

А команда:

    ls linux

працює з відносним шляхом:

    /home/taubu/projects/linux

Поточний каталог впливає на багато команд, але не на всі. Деякі програми працюють із файлами або ресурсами за абсолютними шляхами чи власними правилами.

---

# Absolute Path

Absolute path — абсолютний шлях, який починається від кореневого каталогу `/`.

Приклади:

    /
    /home
    /home/taubu
    /home/taubu/projects
    /home/taubu/projects/nest-exercises

Абсолютний шлях не залежить від поточного робочого каталогу.

Наприклад:

    cd /home/taubu/projects

Команда переходить до зазначеного каталогу незалежно від того, де ти перебуваєш зараз.

---

# Relative Path

Relative path — відносний шлях, який визначається відносно поточного робочого каталогу.

Наприклад, якщо поточний каталог:

    /home/taubu/projects

то шлях:

    nest-exercises

відповідає:

    /home/taubu/projects/nest-exercises

Для переходу до батьківського каталогу використовують:

    cd ..

Для переходу на рівень вище та далі в інший каталог:

    cd ../Downloads

Відносні шляхи часто зручні під час роботи всередині проєкту.

---

# Command Execution

Коли ти вводиш команду в Bash, оболонка виконує кілька етапів обробки.

Спрощена модель:

    1. Read command
    2. Parse command
    3. Process expansions and quoting
    4. Apply redirections
    5. Execute command or builtin
    6. Collect exit status

Наприклад:

    echo "Hello, Linux!"

Bash розпізнає команду та її аргумент, після чого виконується `echo`.

Для зовнішніх команд Bash зазвичай шукає виконуваний файл за правилами пошуку команд, зокрема в каталогах, указаних у `PATH`.

Вбудовані команди, наприклад `cd`, обробляються самою оболонкою.

# Built-in Commands

Built-in commands — команди, реалізовані безпосередньо в Bash.

Приклади:

    cd
    echo
    pwd
    read
    type
    alias
    export
    unset
    source
    exit
    help

Наявність вбудованої реалізації можна перевірити:

    type cd

Результат:

    cd is a shell builtin

Для довідки щодо вбудованої команди:

    help cd

Або:

    help export

Вбудована команда `cd` змінює поточний робочий каталог самої оболонки.

Це важливо: якби `cd` виконувався лише в окремому дочірньому процесі, зміна каталогу не зберігалася б у батьківському Bash.

# External Commands

External commands — програми, які запускаються як окремі виконувані файли.

Приклади:

    ls
    grep
    find
    mkdir
    cp
    mv
    rm
    cat
    less

Перевірити, де розташована команда:

    type ls

Якщо `ls` не перевизначено alias або функцією, можна побачити шлях на зразок:

    ls is /usr/bin/ls

Можна також використати:

    command -v ls

Типовий результат:

    /usr/bin/ls

Шлях залежить від дистрибутива та встановленого програмного забезпечення.

Важливо пам'ятати, що деякі назви, наприклад `echo` або `pwd`, можуть мати як вбудовану реалізацію Bash, так і зовнішню програму.

# type

`type` — вбудована команда Bash, яка допомагає визначити, як оболонка інтерпретує певну назву.

Синтаксис:

    type command_name

Приклад:

    type cd

Результат:

    cd is a shell builtin

Приклад:

    type ls

Можливі результати:

    ls is /usr/bin/ls

або:

    ls is aliased to `ls --color=auto`

Також можна перевірити кілька назв:

    type cd ls grep

Це корисно, коли потрібно зрозуміти, чи є команда alias, функцією, вбудованою командою або зовнішньою програмою.

---

# command

`command` — вбудована команда Bash, яка дозволяє запускати команду, уникаючи звичайного пошуку alias із такою назвою.

Наприклад:

    command ls

Якщо `ls` визначено як alias, цей виклик не розгорне alias із назвою `ls`.

`command -v` використовується для перевірки доступності команди:

    command -v bash
    command -v node
    command -v git

Приклад результату:

    /usr/bin/bash
    /home/taubu/.nvm/versions/node/v24.21.0/bin/node
    /usr/bin/git

Це лише приклад: конкретні шляхи залежать від налаштувань системи.

Якщо команда не знайдена, результат може бути порожнім, а статус завершення — ненульовим.

---

# which

`which` — утиліта, яка зазвичай показує шлях до виконуваного файла, знайденого через `PATH`.

Приклад:

    which bash

Типовий результат:

    /usr/bin/bash

Інші приклади:

    which node
    which npm
    which git

Однак `which` не є універсальним засобом визначення всіх типів команд Bash. Вона може не показувати aliases, функції та вбудовані команди так, як це робить `type`.

Для діагностики Bash часто зручніше:

    type command_name

або:

    command -v command_name

---

# help

`help` — вбудована команда Bash для отримання довідки про вбудовані команди.

Приклади:

    help
    help cd
    help echo
    help export
    help read

Щоб отримати коротку довідку про доступні вбудовані команди:

    help

Щоб дізнатися про конкретну команду:

    help cd

Для зовнішніх програм `help` зазвичай не замінює їхню власну документацію.

Наприклад, для `grep` краще використовувати:

    grep --help

або:

    man grep

---

# man

`man` — команда для відкриття сторінок документації Linux.

Синтаксис:

    man command_name

Приклади:

    man ls
    man grep
    man find
    man chmod
    man bash

У сторінках `man` можна знайти:

    NAME
    SYNOPSIS
    DESCRIPTION
    OPTIONS
    EXAMPLES
    SEE ALSO

Для навігації в типовому переглядачі:

    Space → наступна сторінка
    b     → попередня сторінка
    /text → пошук тексту
    n     → наступний збіг
    q     → вихід

Наприклад:

    man ls

Відкриє документацію до `ls`.

Деякі програми мають власні довідкові параметри:

    node --help
    git --help
    npm --help

Не кожна програма використовує однакові параметри довідки.

---

# --help

Багато зовнішніх команд підтримують опцію `--help`.

Приклади:

    ls --help
    grep --help
    find --help
    node --help
    git --help

Довідка часто містить:

    Usage
    Options
    Arguments
    Examples

`--help` зручно використовувати для швидкого ознайомлення з основними параметрами.

Для детальнішої інформації можна відкрити сторінку:

    man ls

---

# Command Separator ;

`;` — оператор, який дозволяє розділити кілька команд в одному рядку.

Синтаксис:

    command1 ; command2 ; command3

Приклад:

    pwd; whoami; date

Bash виконує команди послідовно.

Навіть якщо перша команда завершиться з помилкою, Bash усе одно спробує виконати наступну.

Приклад:

    echo "First"; echo "Second"; echo "Third"

Результат:

    First
    Second
    Third

` ; ` — це роздільник команд, а не спосіб передавання даних між ними.

Важливо: статус завершення всього списку команд безпосередньо після виконання зазвичай відповідає статусу останньої виконаної команди.

---

# Logical AND &&

`&&` дозволяє виконати наступну команду лише тоді, коли попередня завершилася зі статусом `0`.

Синтаксис:

    command1 && command2

Приклад:

    mkdir demo && cd demo

Логіка:

    mkdir demo
        ↓
    exit status 0?
        ↓
    yes → execute cd demo
    no  → skip cd demo

Якщо каталог успішно створено, Bash перейде до нього.

Якщо створення завершиться помилкою, `cd demo` не буде виконано.

Інший приклад:

    echo "Step 1" && echo "Step 2"

Результат:

    Step 1
    Step 2

Оскільки `echo` зазвичай завершується успішно, виконається й друга команда.

`&&` часто використовують для побудови коротких послідовностей дій, у яких наступний крок залежить від успіху попереднього.

---

# Logical OR ||

`||` дозволяє виконати наступну команду лише тоді, коли попередня завершилася з ненульовим статусом.

Синтаксис:

    command1 || command2

Приклад:

    mkdir demo || echo "Could not create directory"

Якщо `mkdir demo` завершиться успішно, повідомлення не буде виведено.

Якщо `mkdir demo` завершиться помилкою, виконається `echo`.

Ще один приклад:

    cd /directory-that-does-not-exist || echo "Directory not found"

Очікуваний результат:

    Directory not found

`||` часто використовують для резервної дії або повідомлення про помилку.

Важливо: `||` реагує на статус завершення, а не аналізує текст повідомлення команди.

---

# ; vs && vs ||

Це три різні способи організації послідовності команд.

## Крапка з комою `;`

Наступна команда виконується незалежно від статусу попередньої.

    command1 ; command2

## Логічне AND `&&`

Наступна команда виконується, якщо попередня завершилася успішно.

    command1 && command2

## Логічне OR `||`

Наступна команда виконується, якщо попередня завершилася з помилкою.

    command1 || command2

Порівняння:

    mkdir demo; echo "Finished"

    mkdir demo && echo "Created successfully"

    mkdir demo || echo "Creation failed"

Ці конструкції перевіряють статус завершення команди. Вони не гарантують, що програма правильно виконала всі очікувані дії: конкретна програма визначає власну семантику статусів.

---

# Command Chaining

Command chaining — поєднання кількох команд у послідовність.

Наприклад:

    mkdir demo && cd demo && touch README.md

Логіка:

    mkdir demo
        ↓
    success?
        ↓
    cd demo
        ↓
    success?
        ↓
    touch README.md

Якщо створення каталогу не вдасться, решта команд після відповідного `&&` не виконається.

Інший приклад:

    pwd; ls; whoami

Тут усі три команди будуть запущені послідовно незалежно від результату попередніх.

У практиці важливо не плутати:

    ;  → виконати наступну команду
    && → продовжити лише після успіху
    || → продовжити лише після помилки

---

# Pipeline |

Pipeline (`|`) передає стандартне виведення однієї команди на стандартне введення іншої.

Синтаксис:

    command1 | command2

Приклад:

    ls | grep ".md"

Логіка:

    ls
      ↓ stdout
    pipe
      ↓ stdin
    grep ".md"
      ↓
    matching output

Команда `ls` передає свій текстовий вивід команді `grep`.

Інший приклад:

    printf "apple\nbanana\norange\n" | grep "banana"

Результат:

    banana

Pipeline дозволяє комбінувати прості команди для складніших задач.

Наприклад:

    ps aux | grep node

Це дозволяє відфільтрувати текстове представлення списку процесів за словом `node`, хоча для надійного пошуку процесів можуть бути зручніші спеціалізовані засоби.

Важливо: pipeline передає потік даних, а `&&` та `||` керують виконанням залежно від статусу завершення.

---

# Standard Input, Output and Error

У Linux процеси зазвичай мають три стандартні потоки.

    stdin  → file descriptor 0
    stdout → file descriptor 1
    stderr → file descriptor 2

## stdin

Standard input — стандартне введення даних.

За замовчуванням інтерактивна програма часто читає дані з клавіатури.

## stdout

Standard output — стандартне виведення результатів.

За замовчуванням результати часто відображаються в терміналі.

## stderr

Standard error — стандартне виведення повідомлень про помилки та діагностичної інформації.

За замовчуванням повідомлення також відображаються в терміналі.

Спрощена схема:

    keyboard
       ↓
      stdin
       ↓
     program
       ↓
    ┌─────────┐
    │ stdout  │ → normal output
    │ stderr  │ → error messages
    └─────────┘

Стандартні потоки можна перенаправляти у файли або з'єднувати через pipeline.

Детальніше перенаправлення розглядатиметься в темах про Bash та роботу з файлами.

# Exit Status

Exit status — числовий статус завершення команди.

Зазвичай:

    0     → success
    non-0 → error or another condition

Перевірити статус останньої команди:

    echo $?

Приклад:

    true
    echo $?

Результат:

    0

Команда `true` завершується зі статусом `0`.

Інший приклад:

    false
    echo $?

Результат:

    1

Команда `false` навмисно завершується з ненульовим статусом.

Важливо: `$?` містить статус останньої виконаної команди. Якщо між потрібною командою та `echo $?` виконати іншу команду, значення зміниться.

Наприклад:

    false
    echo "Hello"
    echo $?

Останній рядок зазвичай виведе:

    0

Тому що перевіряється статус `echo`, а не `false`.

Правильна перевірка:

    false
    status=$?
    echo "$status"

Результат:

    1

Змінні та присвоєння будуть детальніше розглянуті в розділі:

    02-variables

# Foreground Command

Foreground command — команда, виконання якої займає поточне керування терміналом.

Наприклад:

    sleep 10

Команда очікує приблизно 10 секунд.

Поки foreground-команда виконується, оболонка зазвичай не показує нове запрошення для введення наступної команди в тому самому інтерактивному сеансі.

Перервати поточну команду часто можна клавішами:

    Ctrl + C

Це надсилає сигнал переривання foreground-процесу або групі процесів, залежно від конфігурації термінала та оболонки.

Не всі програми завершуються від `Ctrl + C` однаково: вони можуть обробляти або ігнорувати відповідний сигнал.

---

# Background Command

Background command — команда, запущена у фоновому режимі.

У Bash для цього часто використовують `&`.

Приклад:

    sleep 30 &

Оболонка запускає команду у фоновому завданні та зазвичай одразу повертає запрошення.

Можна продовжувати вводити інші команди.

Наприклад:

    sleep 30 &
    echo "The shell is available"

Команда `echo` може виконатися, поки `sleep` продовжує працювати.

Переглянути завдання поточної оболонки:

    jobs

Важливо: background job — це не те саме, що повністю незалежний системний сервіс. Завдання залишається пов'язаним із оболонкою та її механізмами керування процесами.

Тема процесів і керування ними буде детальніше розглянута в розділі:

    06-processes-and-system

# Interactive and Non-interactive Bash

Bash може працювати в інтерактивному або неінтерактивному режимі.

## Interactive Bash

Інтерактивна оболонка призначена для безпосередньої взаємодії з користувачем.

Наприклад:

    taubu@taubu-lap:~/projects$

Ти вводиш команди, отримуєш результати та вводиш наступні команди.

## Non-interactive Bash

Неінтерактивна оболонка може виконувати команди зі скрипту або переданого рядка.

Наприклад:

    bash -c 'echo "Hello from Bash"'

Результат:

    Hello from Bash

Інший приклад:

    bash script.sh

Bash читає команди з файла та виконує їх.

Інтерактивна й неінтерактивна оболонки можуть мати різну поведінку щодо завантаження конфігураційних файлів, prompt, alias та інших налаштувань.

# bash -c

Опція `-c` дозволяє передати Bash командний рядок для виконання.

Синтаксис:

    bash -c 'command'

Приклад:

    bash -c 'pwd'

Команда виведе поточний робочий каталог дочірньої оболонки.

Інший приклад:

    bash -c 'echo "Hello"; echo "Linux"'

Результат:

    Hello
    Linux

Це зручно для коротких команд, тестування поведінки Bash та автоматизації.

Якщо командний рядок складний, потрібно уважно стежити за лапками та екрануванням.

# Bash Script

Bash script — текстовий файл, що містить послідовність команд та конструкцій Bash.

Скрипти використовують для:

- автоматизації повторюваних задач;
- створення каталогів і файлів;
- перевірки стану системи;
- запуску проєктів;
- резервного копіювання;
- обробки текстових даних;
- автоматизації розгортання застосунків.

Приклад файла `hello.sh`:

    #!/usr/bin/env bash

    echo "Hello, Linux!"
    echo "Hello, Bash!"

Вміст файла — це команди Bash, які можна виконати оболонкою.

Запустити через Bash:

    bash hello.sh

У цьому випадку файл не обов'язково має право на виконання, оскільки він передається як вхідний файл для Bash.

---

# Shebang

Shebang — спеціальний перший рядок скрипту, який починається з `#!`.

Приклад:

    #!/usr/bin/env bash

Він вказує системному механізму запуску, яку програму потрібно використати для інтерпретації файла, коли файл запускається безпосередньо як виконуваний.

Інший варіант:

    #!/bin/bash

Обидва варіанти поширені.

`#!/usr/bin/env bash` шукає `bash` через `PATH` за допомогою `env`.

`#!/bin/bash` указує на конкретний шлях до Bash.

У скриптах, які мають працювати на різних системах, вибір залежить від вимог середовища.

---

# Running a Bash Script

Створимо файл:

    nano hello.sh

Вміст:

    #!/usr/bin/env bash

    echo "Hello, Linux!"
    pwd

Збережи файл.

## Варіант 1 — запуск через Bash

    bash hello.sh

Цей спосіб не вимагає встановлення біта виконання файла.

## Варіант 2 — зробити файл виконуваним

    chmod +x hello.sh

Після цього:

    ./hello.sh

Тут:

    chmod +x → додає право виконання відповідно до наявних прав та правил доступу
    ./hello.sh → запускає файл із поточного каталогу

Префікс `./` указує, що виконуваний файл потрібно шукати в поточному каталозі.

З міркувань безпеки поточний каталог зазвичай не додають автоматично до `PATH`.

# Команди для перевірки системи

Під час роботи з Bash корисно знати базові команди, які допомагають зрозуміти поточне середовище.

## pwd

Показує поточний робочий каталог.

    pwd

Приклад:

    /home/taubu/projects

## whoami

Показує ім'я поточного користувача.

    whoami

Приклад:

    taubu

## hostname

Показує ім'я комп'ютера.

    hostname

Приклад:

    taubu-lap

## date

Показує поточні дату й час системи.

    date

## uname

Показує інформацію про систему.

    uname

Поширений варіант:

    uname -a

Виводить розширену інформацію про ядро та систему.

## id

Показує UID, GID та групи поточного користувача.

    id

## echo

Виводить текст або значення, передані команді.

    echo "Hello, Bash!"

## printf

Форматує та виводить текст.

    printf "Hello, %s!\n" "Linux"

Результат:

    Hello, Linux!

`printf` часто зручніший за `echo`, коли потрібен передбачуваний формат виведення.

# Перевірка Bash

Дізнатися версію Bash:

    bash --version

Приклад початку результату:

    GNU bash, version ...

Перевірити доступність Bash:

    command -v bash

Можливий результат:

    /usr/bin/bash

Перевірити змінну середовища, яка зазвичай містить оболонку входу користувача:

    echo "$SHELL"

Наприклад:

    /bin/bash

Важливо розрізняти:

    $SHELL → зазвичай оболонка входу користувача
    $0    → назва або спосіб виклику поточної оболонки чи скрипту

`$SHELL` не гарантує, що саме ця оболонка виконує поточну команду.

# Bash та PATH

`PATH` — змінна середовища, яка містить список каталогів, де оболонка шукає виконувані програми.

Подивитися значення:

    echo "$PATH"

Результат може містити кілька каталогів, розділених двокрапками:

    /usr/local/bin:/usr/bin:/bin

Якщо ти вводиш:

    node --version

Bash шукає доступну команду `node` за правилами пошуку команд. Для зовнішньої програми одним із головних джерел пошуку є `PATH`.

Перевірити розташування:

    command -v node

Приклад:

    /home/taubu/.nvm/versions/node/v24.21.0/bin/node

Якщо програма не встановлена або її каталог не входить до `PATH`, оболонка може вивести:

    command not found

`PATH` буде детальніше розглянуто в темі:

    06-environment-variables

# Bash Expansion

Expansion — процес, під час якого Bash перетворює певні конструкції команди перед її виконанням.

До основних видів належать:

    tilde expansion
    parameter expansion
    command substitution
    arithmetic expansion
    pathname expansion
    brace expansion

## Tilde expansion

Символ `~` зазвичай розгортається до домашнього каталогу.

    echo ~

Приклад:

    /home/taubu

## Parameter expansion

Дозволяє отримувати значення змінних.

    name="Bash"
    echo "$name"

Результат:

    Bash

## Command substitution

Дозволяє підставити результат виконання команди.

    echo "Current directory: $(pwd)"

Приклад результату:

    Current directory: /home/taubu/projects

## Arithmetic expansion

Дозволяє виконувати цілочисельні арифметичні обчислення.

    echo "$((2 + 3))"

Результат:

    5

## Pathname expansion

Дозволяє використовувати шаблони для пошуку відповідних імен файлів.

    ls *.md

Команда намагається передати `ls` імена файлів, що відповідають шаблону `*.md`.

## Brace expansion

Дозволяє створювати послідовності рядків.

    echo file{1,2,3}.txt

Результат:

    file1.txt file2.txt file3.txt

Ці можливості будуть детальніше розглянуті в наступних темах Bash.

# Quoting

Quoting — використання лапок та екранування для керування тим, як Bash інтерпретує символи.

Основні способи:

    'single quotes'
    "double quotes"
    \escaping

## Single quotes

Одинарні лапки зберігають буквальне значення майже всіх символів усередині них.

    echo '$HOME'

Результат:

    $HOME

## Double quotes

Подвійні лапки зберігають більшість символів буквально, але дозволяють, зокрема, розгортання змінних.

    echo "$HOME"

Приклад:

    /home/taubu

## Escaping

Зворотна скісна риска дозволяє екранувати спеціальний символ.

    echo \$HOME

Результат:

    $HOME

Лапки й екранування — одна з найважливіших тем Bash, особливо під час роботи зі шляхами, змінними та скриптами.

Детальніше:

    03-quotes-and-escaping

# Command Substitution

Command substitution — підстановка результату виконання команди.

Основний сучасний синтаксис:

    $(command)

Приклад:

    current_dir=$(pwd)

    echo "$current_dir"

Якщо поточний каталог:

    /home/taubu/projects

то змінна `current_dir` міститиме цей шлях.

Можна використовувати підстановку безпосередньо:

    echo "User: $(whoami)"

Результат:

    User: taubu

Старий синтаксис:

    `command`

Наприклад:

    current_dir=`pwd`

Для нового коду зазвичай рекомендують `$(...)`, тому що він краще читається та простіше вкладається.

# Shell vs Bash

Терміни shell і Bash не є синонімами.

    Shell → загальна категорія командних оболонок
    Bash  → конкретна командна оболонка

Приклади інших shell:

    sh
    zsh
    fish
    ksh

Різні оболонки можуть мати різні синтаксичні можливості, налаштування та поведінку.

Наприклад, масиви, розширені умовні конструкції й деякі оператори Bash не обов'язково працюватимуть в інших оболонках так само.

Якщо скрипт призначений для Bash, це варто явно зазначати:

    #!/usr/bin/env bash

Не слід автоматично вважати, що кожен shell-скрипт є Bash-скриптом.

# Bash vs Terminal

Це важлива різниця.

    Terminal
        ↓
    Bash
        ↓
    Commands

Terminal — середовище, у якому відбувається взаємодія.

Bash — оболонка, яка обробляє команди.

Команда:

    pwd

виконується через оболонку, а результат відображається в терміналі.

Якщо змінити термінальну програму, можна продовжити використовувати Bash.

Якщо змінити Bash на Zsh, можна залишити ту саму термінальну програму.

# Типові помилки

## 1. Плутати Bash і Terminal

❌ Bash — це вікно термінала.

✔ Terminal — програма для взаємодії з оболонкою, а Bash — сама оболонка.

---

## 2. Вважати, що кожна команда є зовнішньою програмою

❌ `cd` завжди запускає окремий виконуваний файл.

✔ `cd` — вбудована команда Bash.

Перевірка:

    type cd

---

## 3. Плутати аргументи й опції

Команда:

    ls -l /home/taubu

Тут:

    -l          → option
    /home/taubu → argument

---

## 4. Забувати про пробіли в назвах

❌

    mkdir my project

Ця команда сприймає `my` та `project` як два окремі аргументи.

✔

    mkdir "my project"

---

## 5. Плутати `;` та `&&`

❌ Вважати, що обидва оператори завжди припиняють виконання після помилки.

✔

    command1 ; command2

Виконує другу команду незалежно від статусу першої.

    command1 && command2

Виконує другу команду лише після успішного завершення першої.

---

## 6. Плутати `&&` та `||`

❌

    command1 || command2

означає виконати `command2` після успіху `command1`.

✔ `||` виконує наступну команду, коли попередня завершилася з ненульовим статусом.

---

## 7. Неправильно використовувати `$?`

❌

    mkdir demo
    echo "Finished"
    echo $?

Останній рядок показує статус `echo "Finished"`, а не `mkdir demo`.

✔

    mkdir demo
    status=$?
    echo "$status"

---

## 8. Вважати `which` універсальним засобом діагностики

❌ `which` завжди показує, що саме Bash виконає за певною назвою.

✔ Для перевірки типу команди використовуй:

    type command_name

Для перевірки доступності:

    command -v command_name

---

## 9. Забувати, що відносні шляхи залежать від CWD

Якщо ти перебуваєш у:

    /home/taubu/projects

то шлях:

    README.md

означає файл у поточному каталозі, а не будь-де у файловій системі.

Перевіряй поточний каталог:

    pwd

---

## 10. Вважати, що `echo "$SHELL"` завжди показує поточну оболонку

✔ `$SHELL` зазвичай містить назву оболонки входу користувача.

Для діагностики поточного Bash можна використати:

    ps -p $$ -o comm=

або:

    echo "$0"

Ці команди також мають свої обмеження залежно від середовища запуску.

---

## 11. Запускати скрипт без урахування прав виконання

Якщо спробувати:

    ./hello.sh

без відповідних прав виконання, система може відмовити в запуску.

Варіант запуску:

    bash hello.sh

Або:

    chmod +x hello.sh
    ./hello.sh

---

## 12. Вважати, що ненульовий статус завжди означає однакову помилку

Ненульовий статус означає, що команда завершилася не зі статусом успіху `0`.

Конкретне значення залежить від програми.

Наприклад, у деяких інструментів ненульовий статус може означати, що збігів не знайдено, а не те, що програма не змогла запуститися.

# Основні правила

• Bash — командна оболонка, а Terminal — програма для взаємодії з нею.

• CLI дозволяє керувати системою та інструментами за допомогою текстових команд.

• Команда часто має назву, опції та аргументи:

    command [options] [arguments]

• Bash чутливий до регістру символів.

• Пробіли розділяють аргументи. Для шляхів із пробілами використовуй лапки або escaping.

• `pwd` показує поточний робочий каталог.

• Абсолютний шлях починається з `/`, а відносний визначається від поточного каталогу.

• `type` допомагає визначити тип команди.

• `command -v` допомагає перевірити доступність команди.

• `help` призначений передусім для вбудованих команд Bash.

• `man` відкриває сторінки документації.

• `;` розділяє команди, `&&` продовжує після успіху, а `||` — після помилки.

• `|` передає дані між командами через стандартні потоки.

• `stdin` — стандартне введення, `stdout` — стандартне виведення, `stderr` — потік повідомлень про помилки.

• Exit status `0` зазвичай означає успіх, ненульовий статус — помилку або інший визначений програмою результат.

• `$?` містить статус останньої виконаної команди.

• `PATH` визначає каталоги, у яких оболонка шукає зовнішні команди.

• Bash може працювати інтерактивно в терміналі або виконувати команди зі скриптів.

• Shebang указує інтерпретатор для безпосереднього запуску скрипту.

• `bash script.sh` запускає файл через Bash, а `./script.sh` запускає його як виконуваний файл за умови належних прав і доступності потрібного інтерпретатора.

• Quoting, expansion, redirection і pipeline — фундаментальні інструменти для написання Bash-команд та скриптів.

• Bash є важливим інструментом Backend Developer для роботи з Linux, Git, Node.js, серверами, SSH та deployment.
