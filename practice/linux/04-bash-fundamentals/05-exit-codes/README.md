# 05. Exit Codes у Bash

Exit code (код завершення) — це числове значення, яке команда або програма повертає після завершення своєї роботи.

Код завершення допомагає визначити, чи виконалася команда успішно, чи виникла помилка, і чи потрібно продовжувати виконання Bash-скрипту.

Exit codes використовуються для:

- перевірки успішного виконання команд;
- обробки помилок у Bash-скриптах;
- керування умовами `if`, `else` та `elif`;
- поєднання команд через `&&` і `||`;
- зупинки скрипту при критичних помилках;
- діагностики проблем під час роботи з Linux;
- передавання результату роботи програми іншій програмі або shell.

---

## 1. Що таке exit code

Кожна завершена команда має статус завершення — ціле число.

Основне правило Bash:

- `0` — команда завершилася успішно;
- ненульове значення — команда завершилася з помилкою або повідомляє про інший результат.

Наприклад, команда `true` завершується зі статусом `0`, а команда `false` — зі статусом `1`.

    true
    echo $?

Результат:

    0

Тепер:

    false
    echo $?

Результат:

    1

Команда `true` завжди повертає успішний статус, а `false` — неуспішний.

**Що потрібно пам'ятати:**

✔ `0` означає успіх.

✔ Ненульовий статус означає, що команда не повернула звичайний успішний результат.

✔ Ненульовий статус не завжди означає аварію: наприклад, пошукова команда може використовувати його, щоб повідомити, що збігів не знайдено.

✔ Код завершення — це не текстове повідомлення про помилку, а числовий статус.

## 2. Спеціальна змінна `$?`

У Bash змінна `$?` містить статус завершення останньої виконаної команди.

### 2.1. Перевірка успішної команди

    pwd
    echo $?

Команда `pwd` зазвичай завершується успішно, тому результатом буде:

    0

### 2.2. Перевірка команди `false`

    false
    echo $?

Результат:

    1

### 2.3. `$?` змінюється після кожної команди

    false
    echo $?
    echo $?

Результат:

    1
    0

Пояснення:

1. `false` повертає статус `1`.
2. Перший `echo $?` виводить `1` і сам успішно завершується.
3. Другий `echo $?` уже читає статус першого `echo`, тобто `0`.

**Правило:** якщо потрібно зберегти статус конкретної команди, зроби це відразу після її виконання.

    false
    command_status=$?

    echo "Command status: $command_status"

Результат:

    Command status: 1

### 2.4. Коли використовувати `$?`

`$?` корисний, коли потрібно явно зберегти або вивести статус команди.

Проте для умов зазвичай читабельніше перевіряти команду безпосередньо через `if`.

    if mkdir practice-directory; then
        echo "Directory created successfully"
    else
        echo "Could not create directory"
    fi

Якщо каталог уже існує або створення не вдалося, виконається гілка `else`.

Увага: цей приклад створює каталог `practice-directory` у поточному каталозі. Для практики використовуй навчальну папку.

## 3. Коди завершення та стандартні потоки

Код завершення не слід плутати зі стандартним виводом або повідомленнями про помилки.

У Linux команди зазвичай використовують три стандартні потоки:

| Потік | Номер | Призначення |
|---|---:|---|
| `stdin` | `0` | Стандартне введення |
| `stdout` | `1` | Стандартний вивід |
| `stderr` | `2` | Вивід повідомлень про помилки |

Exit code — окремий механізм. Він повідомляє про результат завершення команди.

### 3.1. Успішний результат і код `0`

    printf 'Hello, Linux!\n'
    echo $?

Результат:

    Hello, Linux!
    0

`printf` виводить текст у `stdout`, а його статус завершення дорівнює `0`.

### 3.2. Повідомлення про помилку

    ls /directory-that-does-not-exist
    echo $?

Команда `ls` виведе повідомлення про помилку в `stderr` і поверне ненульовий статус.

Конкретне ненульове значення залежить від команди та ситуації.

### 3.3. Чи означає наявність тексту помилки ненульовий статус?

Не обов'язково. І навпаки, команда може завершитися з ненульовим статусом, навіть якщо нічого не вивела.

Наприклад:

    false
    echo $?

Команда `false` нічого не виводить, але повертає `1`.

**Висновок:** текст у терміналі та exit code — різні речі. Для програмної перевірки результату використовуй статус завершення.

## 4. Стандартні значення exit codes

У Bash немає єдиної універсальної таблиці кодів для всіх програм. Кожна команда може визначати власні значення.

Однак існують поширені домовленості.

| Код | Типове значення |
|---:|---|
| `0` | Успіх |
| `1` | Загальна помилка або невдалий результат |
| `2` | Часто помилка використання команди або некоректні аргументи |
| `126` | Команду знайдено, але її не вдалося виконати |
| `127` | Команду не знайдено |
| `128 + N` | Завершення через сигнал із номером `N` — поширена домовленість shell |
| `130` | Часто завершення через `SIGINT`, наприклад після `Ctrl+C` |
| `137` | Часто завершення через `SIGKILL` |
| `143` | Часто завершення через `SIGTERM` |

Це орієнтири, а не гарантія для кожної програми.

### 4.1. Код `0`

Успішне виконання:

    true
    echo $?

Результат:

    0

### 4.2. Код `1`

Команда `false` повертає `1`:

    false
    echo $?

Результат:

    1

Але не можна стверджувати, що кожна команда використовує `1` для однакової помилки.

### 4.3. Код `127` — команду не знайдено

Спробуй виконати команду з назвою, якої не існує:

    command_that_does_not_exist
    echo $?

У типовому Bash результатом буде:

    127

Shell повідомить, що команда не знайдена.

### 4.4. Код `126` — неможливо виконати команду

Код `126` використовується, коли shell знайшов команду, але не може її виконати.

Наприклад, це може статися, якщо файл не має потрібних прав на виконання або не є виконуваним файлом у відповідному контексті.

Точна поведінка залежить від ситуації.

### 4.5. Коди, пов'язані із сигналами

Якщо процес завершується через сигнал, shell часто повідомляє статус `128 + номер сигналу`.

Наприклад, `SIGINT` має номер `2`, тому поширений статус завершення після переривання через `Ctrl+C` — `130`.

Це не означає, що кожен статус понад `128` обов'язково виник через сигнал: програма може самостійно повернути такий числовий код.

## 5. Exit code у Bash-скриптах

Коли Bash-скрипт завершується, він також повертає статус завершення.

Для цього використовується команда `exit`.

### 5.1. Успішне завершення

    #!/usr/bin/env bash

    echo "Script completed successfully"
    exit 0

Після запуску скрипту його статус буде `0`.

### 5.2. Завершення з помилкою

    #!/usr/bin/env bash

    echo "An error occurred" >&2
    exit 1

Скрипт виведе повідомлення у стандартний потік помилок і завершиться зі статусом `1`.

### 5.3. Перевірка статусу скрипту

Припустімо, файл називається `example.sh`.

    bash example.sh
    echo $?

Якщо скрипт завершується через `exit 0`, результат буде `0`. Якщо через `exit 1`, результат буде `1`.

### 5.4. Команда `exit`

`exit N` завершує поточний shell або Bash-скрипт зі статусом `N`.

    exit 0

Увага: якщо виконати `exit` безпосередньо в інтерактивному терміналі, поточна shell-сесія завершиться. Для практики використовуй цю команду всередині окремого скрипту.

### 5.5. `exit` без аргументу

Команда:

    exit

завершує shell із поточним статусом завершення.

Оскільки цей статус міг змінитися після останньої команди, у скриптах краще явно вказувати потрібний код, коли це необхідно.

## 6. Команда `return` у функціях

`return` і `exit` мають різне призначення.

- `exit` завершує поточний shell або скрипт.
- `return` завершує виконання функції або повертається з shell-функції чи sourced-файлу, не завершуючи весь інтерактивний shell.

### 6.1. Функція з успішним статусом

    check_value() {
        return 0
    }

    check_value
    echo $?

Результат:

    0

### 6.2. Функція з ненульовим статусом

    check_value() {
        return 1
    }

    check_value
    echo $?

Результат:

    1

### 6.3. Важлива особливість `return`

У Bash `return` призначений для статусу завершення функції або sourced-файлу, а не для повернення довільного текстового значення.

Якщо функція повинна передати текст, вона зазвичай виводить його в `stdout`, а викликач може використати command substitution.

    get_greeting() {
        printf '%s\n' "Hello, Linux!"
    }

    greeting=$(get_greeting)
    printf '%s\n' "$greeting"

Результат:

    Hello, Linux!

Тут текст передається через стандартний вивід, а не через `return`.

## 7. Перевірка команди через `if`

Найпоширеніший спосіб роботи з exit codes — перевіряти команду безпосередньо в умові `if`.

### 7.1. Базовий приклад

    if true; then
        echo "Command succeeded"
    else
        echo "Command failed"
    fi

Результат:

    Command succeeded

Bash перевіряє статус завершення команди `true`.

Якщо статус дорівнює `0`, виконується гілка `then`. Якщо ненульовий — `else`.

### 7.2. Приклад із `false`

    if false; then
        echo "Command succeeded"
    else
        echo "Command failed"
    fi

Результат:

    Command failed

### 7.3. Перевірка існування каталогу

    if ls /tmp >/dev/null 2>&1; then
        echo "Directory is accessible"
    else
        echo "Could not access directory"
    fi

Команда перевіряється за своїм статусом завершення. Її стандартний вивід і повідомлення про помилки перенаправлено, щоб вони не засмічували термінал.

Цей приклад перевіряє успішність виконання `ls /tmp`, а не є універсальним способом перевірки будь-якого каталогу.

Для перевірки того, чи існує саме каталог, зручніше використовувати умовний оператор `-d`.

    if [[ -d /tmp ]]; then
        echo "Directory exists"
    else
        echo "Directory does not exist"
    fi

### 7.4. Перевірка створення каталогу

    if mkdir practice-directory; then
        echo "Directory created"
    else
        echo "Could not create directory"
    fi

Команда `mkdir` повертає `0`, якщо створення вдалося, і ненульовий статус, якщо виникла помилка.

Цей приклад створює каталог `practice-directory`, якщо такий каталог ще не існує.

## 8. Оператори `&&` та `||`

Bash дозволяє виконувати команди залежно від статусу попередньої команди.

### 8.1. Оператор `&&`

Синтаксис:

    command_a && command_b

Друга команда виконується лише тоді, коли перша завершилася зі статусом `0`.

Приклад:

    true && echo "First command succeeded"

Результат:

    First command succeeded

Тепер:

    false && echo "This message will not appear"

Друга команда не виконається.

### 8.2. Оператор `||`

Синтаксис:

    command_a || command_b

Друга команда виконується лише тоді, коли перша завершилася з ненульовим статусом.

Приклад:

    false || echo "First command failed"

Результат:

    First command failed

### 8.3. Поєднання `&&` та `||`

    mkdir practice-directory && echo "Created" || echo "Failed"

Цей приклад часто використовують як скорочений запис умовної логіки.

Проте є нюанс: якщо `mkdir` успішно завершиться, але команда `echo "Created"` не виконається успішно, Bash може перейти до останньої команди `echo "Failed"`.

Для важливих операцій краще використовувати `if`, оскільки він чіткіше показує, який саме результат перевіряється.

    if mkdir practice-directory; then
        echo "Created"
    else
        echo "Failed"
    fi

### 8.4. Коли використовувати ці оператори

Використовуй `&&`, коли друга команда повинна виконуватися тільки після успіху першої.

Використовуй `||`, коли потрібно виконати запасну дію після невдачі першої команди.

Для складної логіки обробки помилок віддавай перевагу `if`.

---

## 9. `!` — заперечення статусу

У Bash оператор `!` змінює логічний результат команди:

- якщо команда повернула `0`, результат `! command` буде неуспішним;
- якщо команда повернула ненульовий статус, результат `! command` буде успішним.

### 9.1. Приклад

    if ! false; then
        echo "The command was not successful"
    fi

Результат:

    The command was not successful

Оскільки `false` повертає ненульовий статус, `! false` має статус `0`, і гілка `then` виконується.

### 9.2. Приклад перевірки каталогу

    if ! [[ -d /directory-that-does-not-exist ]]; then
        echo "Directory does not exist"
    fi

Цей приклад виведе повідомлення, якщо зазначений каталог не існує.

Оператор `!` зручний, коли потрібно перевірити протилежну умову.

---

## 10. `command` і статус завершення

Bash може використовувати `command` для запуску команди без пошуку однойменної shell-функції.

У повсякденній практиці exit codes частіше перевіряють безпосередньо після потрібної команди.

    command true
    echo $?

Результат:

    0

Для цієї теми важливіше розуміти, що статус належить результату виконання команди, а не тексту, який вона вивела.

## 11. Exit codes та конвеєри

Конвеєр (pipeline) передає стандартний вивід однієї команди на стандартне введення іншої.

    command_a | command_b

За замовчуванням у Bash статус конвеєра зазвичай дорівнює статусу останньої команди — `command_b`.

### 11.1. Приклад

    false | true
    echo $?

Результат:

    0

Хоча перша команда `false` повернула `1`, остання команда `true` повернула `0`. Тому статус усього конвеєра за замовчуванням дорівнює `0`.

### 11.2. Перевірка через `PIPESTATUS`

Bash має спеціальний масив `PIPESTATUS`, який містить статуси команд останнього конвеєра.

    false | true
    printf 'First: %s\n' "${PIPESTATUS[0]}"
    printf 'Second: %s\n' "${PIPESTATUS[1]}"

Результат:

    First: 1
    Second: 0

Важливо: `PIPESTATUS` змінюється після наступних команд. Якщо потрібно зберегти всі статуси конвеєра, копіюй масив відразу після виконання конвеєра.

    false | true
    statuses=("${PIPESTATUS[@]}")

    printf 'First: %s\n' "${statuses[0]}"
    printf 'Second: %s\n' "${statuses[1]}"

Тут масив `statuses` зберігає статуси обох команд до виконання `printf`.

### 11.3. Опція `pipefail`

Bash підтримує опцію `pipefail`, яка змінює статус конвеєра: він стає ненульовим, якщо хоча б одна команда конвеєра завершилася з ненульовим статусом. Якщо декілька команд завершилися з помилкою, результатом буде статус крайньої праворуч команди з ненульовим статусом.

    set -o pipefail

    false | true
    echo $?

Результат:

    1

Тепер помилка першої команди впливає на статус конвеєра.

Перевірити поточне значення опції можна так:

    set -o | grep pipefail

Опція `pipefail` часто використовується в Bash-скриптах, де важливо не пропускати помилки всередині конвеєрів.

## 12. Exit codes та command substitution

Command substitution дозволяє отримати стандартний вивід команди, але також має статус завершення.

### 12.1. Приклад успішної підстановки

    result=$(printf 'Hello Linux')
    echo $?

Результат:

    0

### 12.2. Приклад невдалої підстановки

    result=$(false)
    echo $?

Результат:

    1

Статус присвоєння з command substitution у цьому випадку відповідає статусу останньої команди, виконаної всередині підстановки.

### 12.3. Не втрать статус

Неправильно:

    result=$(false)
    printf '%s\n' "$result"
    echo $?

Останній `echo $?` виведе статус попередньої команди `printf`, а не `false`.

Правильно:

    result=$(false)
    command_status=$?

    printf 'Status: %s\n' "$command_status"

### 12.4. Рекомендований спосіб — `if`

    if result=$(date +%F); then
        printf 'Date: %s\n' "$result"
    else
        printf 'Could not get date\n' >&2
    fi

Такий підхід дозволяє перевірити успішність підстановки без окремого читання `$?`.

## 13. Exit codes у власних скриптах

Коли ти створюєш Bash-скрипт, важливо повертати зрозумілий статус завершення.

### 13.1. Успішне завершення

    #!/usr/bin/env bash

    printf 'Task completed successfully\n'
    exit 0

### 13.2. Завершення через помилку

    #!/usr/bin/env bash

    printf 'Error: task failed\n' >&2
    exit 1

### 13.3. Перевірка аргументів

Приклад скрипту, який очікує один аргумент:

    #!/usr/bin/env bash

    if [[ $# -ne 1 ]]; then
        printf 'Usage: %s NAME\n' "$0" >&2
        exit 2
    fi

    printf 'Hello, %s!\n' "$1"
    exit 0

Пояснення:

- `$#` — кількість аргументів;
- `$0` — назва або шлях запуску скрипту;
- `$1` — перший аргумент;
- `[[ $# -ne 1 ]]` перевіряє, чи кількість аргументів не дорівнює `1`;
- `exit 2` завершує скрипт із ненульовим статусом, якщо аргументів неправильна кількість;
- `exit 0` позначає успішне завершення.

Цей приклад також показує, що ненульовий статус можна використовувати для різних категорій помилок. Значення `2` тут обрано як домовленість самого скрипту.

### 13.4. Перевірка такого скрипту

Припустімо, файл має назву `greet.sh`.

    bash greet.sh Valeriy
    echo $?

Результат:

    Hello, Valeriy!
    0

Якщо запустити скрипт без аргументу:

    bash greet.sh
    echo $?

Скрипт виведе повідомлення про використання і завершиться зі статусом `2`.

## 14. `set -e` — завершення при помилці

Bash має опцію:

    set -e

Вона призначена для завершення скрипту, коли команда завершується з ненульовим статусом у відповідних контекстах.

Приклад:

    #!/usr/bin/env bash

    set -e

    printf 'Step 1\n'
    false
    printf 'Step 2\n'

Зазвичай після `false` скрипт завершиться, і `Step 2` не буде виведено.

### 14.1. Важливі обмеження `set -e`

`set -e` не є універсальною системою обробки помилок.

Його поведінка залежить від контексту виконання, зокрема від умов `if`, списків `&&` та `||`, конвеєрів і функцій.

Тому не варто вважати, що `set -e` автоматично обробить усі можливі помилки.

Для критичних операцій часто краще явно перевіряти результат:

    if ! mkdir practice-directory; then
        printf 'Error: could not create directory\n' >&2
        exit 1
    fi

Такий код явно показує, яку саме помилку перевіряє скрипт.

### 14.2. `set -e` разом із `pipefail`

У багатьох Bash-скриптах використовують:

    set -e
    set -o pipefail

Це допомагає виявляти більше помилок, але не замінює продуману логіку перевірок.

На початковому етапі навчання важливо спершу добре зрозуміти exit codes, `if`, `&&`, `||` і статуси конвеєрів.

## 15. Відмінність між помилкою та очікуваним результатом

Ненульовий статус не завжди означає, що програма працює неправильно.

Деякі команди використовують exit codes для повідомлення про нормальні результати пошуку або перевірки.

### 15.1. Пошук тексту за допомогою `grep`

Команда `grep` зазвичай використовує такі статуси:

- `0` — знайдено хоча б один збіг;
- `1` — збігів не знайдено;
- `2` — сталася помилка.

Приклад:

    printf 'apple\nbanana\norange\n' | grep 'banana'
    echo $?

Результат:

    banana
    0

Тепер пошукаємо текст, якого немає:

    printf 'apple\nbanana\norange\n' | grep 'grape'
    echo $?

Результат:

    1

Відсутність збігів не обов'язково є помилкою програми. Це може бути звичайним результатом пошуку.

### 15.2. Правильна перевірка результату

    if printf 'apple\nbanana\norange\n' | grep -q 'grape'; then
        echo "Match found"
    else
        echo "No match found"
    fi

Результат:

    No match found

Опція `-q` наказує `grep` не виводити знайдені рядки, а повідомити про результат через exit code.

### 15.3. Чому це важливо

Не слід сприймати всі ненульові статуси однаково.

Потрібно розуміти документацію конкретної команди й визначати, які коди є очікуваними, а які свідчать про помилку.

## 16. `&&` і `||` не замінюють повноцінну обробку помилок

Для простих команд скорочені оператори зручні.

    mkdir practice-directory && echo "Created"

Проте для складної логіки краще використовувати `if`.

    if mkdir practice-directory; then
        echo "Created"
    else
        echo "Creation failed"
    fi

Переваги `if`:

- чітко видно, яка команда перевіряється;
- можна виконати кілька дій при успіху;
- можна виконати кілька дій при помилці;
- легше додати логування;
- простіше підтримувати код.

Особливо це важливо для скриптів, які працюють із файлами, каталогами, базами даних або системними налаштуваннями.

## 17. Типові помилки

### Помилка 1. Вважають, що `0` означає помилку

У Bash усе навпаки: `0` означає успіх, а ненульовий статус — неуспішний результат.

    true
    echo $?

Результат:

    0

### Помилка 2. Читають `$?` після іншої команди

    false
    printf 'Finished\n'
    echo $?

Остання команда `printf` зазвичай успішна, тому `echo $?` виведе `0`.

Правильно:

    false
    status=$?
    printf 'Status: %s\n' "$status"

### Помилка 3. Вважають, що будь-який ненульовий статус означає аварію

Наприклад, `grep` повертає `1`, якщо збігів не знайдено. Це може бути звичайним результатом пошуку.

### Помилка 4. Вважають, що текст помилки визначає exit code

Команда може вивести повідомлення в `stderr`, але її статус потрібно перевіряти окремо.

    ls /directory-that-does-not-exist
    echo $?

### Помилка 5. Використовують `exit` в інтерактивному терміналі

Команда `exit` завершує поточну shell-сесію.

Для вправ із завершенням скриптів використовуй окремий `.sh` файл.

### Помилка 6. Плутають `return` та `exit`

`return` завершує функцію або повертається з sourced-файлу. `exit` завершує поточний shell або скрипт.

### Помилка 7. Вважають, що статус конвеєра завжди відображає помилку будь-якої команди

За замовчуванням статус конвеєра зазвичай визначається останньою командою.

    false | true
    echo $?

Результат:

    0

Для іншої поведінки можна використати `set -o pipefail`.

### Помилка 8. Вважають `set -e` повною заміною перевірок

`set -e` має винятки та залежить від контексту. Для критичних операцій явно перевіряй статуси.

### Помилка 9. Вважають, що всі команди використовують однакові коди помилок

Коди `1`, `2` та інші значення мають сенс відповідно до документації конкретної програми.

### Помилка 10. Не передають статус зі скрипту

Якщо скрипт має повідомляти іншим програмам про успіх або помилку, потрібно завершувати його відповідним статусом.

    exit 0

або:

    exit 1

## 18. Що потрібно пам'ятати

✔ Exit code — це числовий статус завершення команди.

✔ `0` означає успіх, ненульовий статус — неуспішний результат або спеціальний стан.

✔ `$?` містить статус останньої виконаної команди.

✔ Якщо потрібно зберегти статус, роби це відразу.

✔ `exit N` завершує поточний shell або скрипт зі статусом `N`.

✔ `return N` повертає статус із функції або sourced-файлу.

✔ `if command; then ... else ... fi` — один із найзрозуміліших способів перевірити статус команди.

✔ `command_a && command_b` запускає другу команду, якщо перша успішна.

✔ `command_a || command_b` запускає другу команду, якщо перша неуспішна.

✔ `! command` інвертує логічний результат статусу команди.

✔ За замовчуванням статус конвеєра визначається статусом останньої команди.

✔ `PIPESTATUS` дозволяє отримати статуси окремих команд останнього конвеєра.

✔ `set -o pipefail` допомагає враховувати помилки в конвеєрах.

✔ `set -e` може допомогти зупиняти скрипт після певних помилок, але має нюанси.

✔ Ненульовий статус не завжди означає аварію: наприклад, `grep` повертає `1`, коли не знаходить збігів.

✔ Текст повідомлення, `stdout`, `stderr` і exit code — різні механізми.

## 23. Підсумок

Exit codes — фундаментальний механізм керування виконанням у Bash. Вони дозволяють командам, скриптам та іншим програмам повідомляти про результат своєї роботи.

Основні правила:

1. `0` означає успішне виконання, ненульовий статус — неуспішний результат або спеціальний стан.
2. `$?` містить статус останньої команди, тому потрібний статус потрібно зчитувати вчасно.
3. `exit` завершує shell або скрипт, а `return` повертає статус із функції чи sourced-файлу.
4. `if`, `&&`, `||` та `!` дозволяють керувати виконанням залежно від статусу.
5. Статус конвеєра за замовчуванням визначається останньою командою; `pipefail` допомагає враховувати помилки попередніх команд.
6. `set -e` може допомогти зупиняти скрипт після помилок, але не замінює продуманої обробки помилок.
7. Різні програми можуть використовувати різні ненульові коди, тому важливо розуміти документацію команди.
8. Для перевірки успіху команди зазвичай краще використовувати `if command; then ... fi`, а не вручну аналізувати `$?` після кількох операцій.

**Головне правило:** не визначай успіх команди лише за тим, що вона вивела на екран. Перевіряй її exit code і враховуй значення, яке ця команда використовує для конкретного результату.
