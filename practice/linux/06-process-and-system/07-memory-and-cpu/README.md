# Memory and CPU — Оперативна пам’ять і процесор у Linux

> Шпаргалка з моніторингу CPU, оперативної пам’яті (RAM), swap, системного навантаження та використання ресурсів процесами в Linux.

---

## 1. Що таке CPU та Memory?

Під час роботи Linux програми використовують процесорний час, оперативну пам’ять і підсистему введення-виведення. Якщо розуміти, як контролювати ці ресурси, можна знаходити причини повільної роботи системи та окремих програм.

### CPU — Central Processing Unit

**CPU** — центральний процесор, який виконує інструкції програм.

Важливі поняття:

- ✔ **Physical core** — фізичне ядро процесора.
- ✔ **Logical CPU** — логічний процесор, який операційна система бачить як окрему одиницю виконання.
- ✔ **CPU usage** — частка процесорного часу, зайнята роботою.
- ✔ **Load Average** — середнє навантаження системи за певний період.
- ✔ **Context switch** — перемикання CPU між процесами або потоками.
- ✔ **CPU-bound task** — завдання, яке переважно обмежене обчислювальною потужністю CPU.

### Memory — пам’ять

**RAM (Random Access Memory)** — оперативна пам’ять, у якій зберігаються дані та код програм, що працюють.

Важливі поняття:

- ✔ **Used memory** — пам’ять, яка зараз використовується відповідно до методики конкретної команди.
- ✔ **Free memory** — пам’ять, яка наразі не використовується.
- ✔ **Available memory** — оцінка пам’яті, доступної для нових програм без значного використання swap.
- ✔ **Page cache** — кеш файлових даних в оперативній пам’яті.
- ✔ **Swap** — простір на диску, який Linux може використовувати для переміщення частини сторінок пам’яті.
- ✔ **Memory pressure** — ситуація, коли системі бракує оперативної пам’яті для поточних потреб.
- ✔ **OOM killer** — механізм ядра, який може завершувати процеси, коли система не може забезпечити потрібну пам’ять.

## 2. Основні команди

| Команда | Призначення |
|---|---|
| `top` | Моніторинг процесів, CPU та пам’яті в реальному часі |
| `htop` | Інтерактивний монітор ресурсів із зручним інтерфейсом |
| `free -h` | Перегляд використання RAM і swap |
| `vmstat` | Статистика процесів, пам’яті, swap, CPU та введення-виведення |
| `uptime` | Час роботи та Load Average |
| `lscpu` | Характеристики процесора |
| `nproc` | Кількість процесорних одиниць, доступних процесу |
| `ps` | Інформація про процеси |
| `pidstat` | Статистика CPU, пам’яті та введення-виведення процесів |
| `mpstat` | Статистика використання CPU |
| `sar` | Збір та перегляд системної статистики, якщо встановлено `sysstat` |
| `watch` | Повторне виконання команди через заданий інтервал |
| `cat /proc/meminfo` | Детальна інформація про пам’ять |
| `cat /proc/stat` | Статистика CPU та інших системних лічильників |
| `cat /proc/pressure/` | Інформація про тиск ресурсів, якщо підтримується ядром |

Не всі команди встановлені за замовчуванням. Наприклад, `htop`, `pidstat`, `mpstat` і `sar` можуть потребувати додаткових пакетів.

## 3. Перевірка процесора — CPU

### 3.1. Команда `lscpu`

Команда `lscpu` показує основні характеристики процесора.

    lscpu

Приклад окремих полів:

    Architecture:             x86_64
    CPU(s):                   4
    Thread(s) per core:       2
    Core(s) per socket:       2
    Socket(s):                1
    Model name:               Example CPU

Це умовний приклад, а не фактичні характеристики конкретного комп’ютера.

Основні поля:

- `Architecture` — архітектура.
- `CPU(s)` — загальна кількість логічних CPU, видимих системі.
- `Thread(s) per core` — кількість апаратних потоків на ядро.
- `Core(s) per socket` — кількість ядер на один фізичний процесор.
- `Socket(s)` — кількість фізичних процесорів.
- `Model name` — назва моделі CPU.

**Запам’ятай:** кількість логічних CPU не обов’язково дорівнює кількості фізичних ядер.

### 3.2. Команда `nproc`

    nproc

Показує кількість процесорних одиниць, доступних поточному процесу.

Переглянути кількість усіх процесорних одиниць, відомих системі:

    nproc --all

Значення можуть відрізнятися, наприклад, через обмеження контейнера або CPU affinity.

### 3.3. Файл `/proc/cpuinfo`

    cat /proc/cpuinfo

Файл містить інформацію про процесори та їхні характеристики.

Показати назву моделі:

    grep -m 1 "model name" /proc/cpuinfo

Порахувати кількість записів `processor` у цьому файлі:

    grep -c '^processor' /proc/cpuinfo

На звичайній системі це часто відповідає кількості логічних CPU, але для визначення ресурсів, доступних конкретному процесу, краще також перевірити `nproc`.

## 4. CPU Usage — використання процесора

### 4.1. Що означає CPU Usage?

**CPU Usage** — показник того, наскільки активно використовувався процесор протягом певного інтервалу.

Наприклад:

- `0%` — процес майже не використовує CPU у вимірюваному інтервалі.
- `25%` — невелике або помірне навантаження, залежно від способу підрахунку.
- `100%` — може означати повне використання одного логічного CPU або всієї доступної процесорної потужності, залежно від інструмента й формату.

Не всі програми показують відсотки однаково. Деякі можуть рахувати 100% на кожний логічний CPU, тому багатопотоковий процес здатен показувати більше ніж 100%.

### 4.2. Команда `top`

    top

У верхній частині вікна можна побачити загальну статистику CPU.

Типові поля:

- `us` — час виконання коду користувацького простору.
- `sy` — час роботи ядра.
- `ni` — час виконання процесів зі зміненим nice.
- `id` — час простою CPU.
- `wa` — час, коли CPU очікував завершення операцій введення-виведення.
- `hi` — час обробки апаратних переривань.
- `si` — час обробки програмних переривань.
- `st` — час, коли віртуальна машина чекала на CPU, зайнятий гіпервізором, якщо цей показник доступний.

Приклад:

    %Cpu(s): 12.0 us, 4.0 sy, 0.0 ni, 80.0 id, 3.0 wa, 1.0 hi, 0.0 si, 0.0 st

Умовний приклад: CPU переважно простоює (`id`), частина часу витрачається на виконання програм (`us`, `sy`) та очікування введення-виведення (`wa`).

Корисні клавіші в `top`:

- `q` — вихід.
- `P` — сортування процесів за CPU.
- `M` — сортування за пам’яттю.
- `1` — перемикання відображення окремих CPU.
- `H` — перемикання відображення потоків, якщо підтримується поточною версією.

### 4.3. Команда `mpstat`

`mpstat` показує статистику використання процесора.

Команда може бути відсутньою за замовчуванням. В Ubuntu вона входить до пакета `sysstat`.

    sudo apt update
    sudo apt install sysstat

Показати статистику всіх CPU:

    mpstat -P ALL

Оновлювати статистику щосекунди п’ять разів:

    mpstat -P ALL 1 5

Основні поля:

- `%usr` — час у користувацькому просторі.
- `%sys` — час у ядрі.
- `%idle` — час простою.
- `%iowait` — час очікування введення-виведення.
- `%steal` — час, відібраний гіпервізором у віртуальної машини, якщо застосовно.

### 4.4. Перегляд CPU через `watch`

    watch -n 2 "grep '^cpu ' /proc/stat"

Команда повторно виконує заданий запит кожні дві секунди.

**Важливо:** значення в `/proc/stat` — це накопичені лічильники часу CPU, а не готовий відсоток використання. Для визначення CPU Usage їх потрібно порівнювати між вимірюваннями.

Для звичайного моніторингу простіше використовувати `top` або `mpstat`.

## 5. Load Average — середнє навантаження

### 5.1. Перегляд Load Average

    uptime

Приклад:

    20:45:10 up 3 days, 4:12, 2 users, load average: 0.30, 0.45, 0.40

Три числа показують середнє навантаження за:

1. Останню 1 хвилину.
2. Останні 5 хвилин.
3. Останні 15 хвилин.

Окремо можна переглянути ці значення:

    cat /proc/loadavg

### 5.2. Як інтерпретувати Load Average?

Load Average враховує процеси, які виконуються або очікують на виконання CPU, а також процеси в певних станах очікування, зокрема незворотного очікування введення-виведення.

Приблизний приклад для системи з чотирма логічними CPU:

| Load Average | Орієнтовна інтерпретація |
|---|---|
| `1.0` | Середнє навантаження приблизно на рівні одного процесорного ресурсу |
| `4.0` | Навантаження може відповідати повному використанню чотирьох CPU, якщо воно переважно CPU-залежне |
| `8.0` | Може бути черга процесів, які очікують CPU, або значне очікування введення-виведення |

Це орієнтири, а не точний вимір відсотка CPU.

**Важливо:** високий Load Average не завжди означає, що процесор повністю завантажений. Причиною можуть бути процеси, які очікують на диск або інші ресурси.

### 5.3. Як перевірити кількість CPU

    nproc

Після цього порівняй результат із Load Average та поточним завантаженням у `top`.

Наприклад, якщо доступні чотири CPU, Load Average `1.0` зазвичай не свідчить про перевантаження CPU сам по собі. Але для точного висновку потрібно також перевірити `id`, `wa`, стан процесів і характер навантаження.

## 6. Оперативна пам’ять — RAM

### 6.1. Команда `free`

    free

Зручний формат:

    free -h

Приклад:

    total        used        free      shared  buff/cache   available
    Mem:           7.6Gi       2.1Gi       1.8Gi       200Mi       3.7Gi       5.0Gi
    Swap:          2.0Gi          0B       2.0Gi

Це умовні значення.

Основні колонки:

- `total` — загальний обсяг пам’яті, доступний Linux.
- `used` — використана пам’ять за методикою команди.
- `free` — пам’ять, яка зараз не використовується.
- `shared` — спільно використовувана пам’ять, зокрема tmpfs.
- `buff/cache` — буфери й кеш.
- `available` — приблизний обсяг пам’яті, доступної для нових програм без активного використання swap.

### 6.2. Одиниці вимірювання

Показати значення у мегабайтах:

    free -m

Показати значення у гігабайтах:

    free -g

Показати значення в зручних одиницях:

    free -h

### 6.3. Оновлення статистики

    free -h -s 2

Команда оновлює статистику кожні дві секунди.

Зупинити виконання:

    Ctrl + C

### 6.4. Чому Linux використовує кеш?

Linux може використовувати вільну RAM для кешування даних, які читаються з диска. Це допомагає прискорювати повторний доступ до файлів.

Тому низьке значення `free` не обов’язково означає проблему.

Під час перевірки пам’яті насамперед звертай увагу на:

- `available` у `free -h`;
- активність swap;
- наявність помилок OOM;
- поведінку програм;
- загальне навантаження системи.

## 7. Детальна інформація про пам’ять — `/proc/meminfo`

Файл `/proc/meminfo` містить докладну статистику пам’яті.

    cat /proc/meminfo

Показати найважливіші поля:

    grep -E '^(MemTotal|MemFree|MemAvailable|Buffers|Cached|SwapTotal|SwapFree|Dirty|Slab):' /proc/meminfo

Основні поля:

- `MemTotal` — загальний обсяг RAM, видимий ядру.
- `MemFree` — вільна пам’ять.
- `MemAvailable` — оцінка пам’яті, доступної для нових програм.
- `Buffers` — буфери.
- `Cached` — кеш.
- `SwapTotal` — загальний обсяг swap.
- `SwapFree` — вільний swap.
- `Dirty` — сторінки пам’яті, які очікують запису на диск.
- `Slab` — пам’ять, яку використовує механізм кешування об’єктів ядра.

Більшість значень у `/proc/meminfo` подані в кілобайтах, якщо в назві поля або документації не зазначено інше.

**Запам’ятай:** `free -h` зручний для швидкого огляду, а `/proc/meminfo` — для детальнішого дослідження.

## 8. Swap — віртуальна пам’ять

### 8.1. Що таке Swap?

**Swap** — це простір на диску, який Linux може використовувати для збереження сторінок пам’яті, що тимчасово не потрібні в RAM.

Swap може бути:

- окремим розділом диска;
- файлом у файловій системі;
- кількома областями одночасно.

Swap не є повноцінною заміною оперативної пам’яті: доступ до диска зазвичай значно повільніший за доступ до RAM.

### 8.2. Переглянути використання swap

    free -h

Додатково:

    swapon --show

Або:

    cat /proc/swaps

Приклад `swapon --show`:

    NAME       TYPE SIZE USED PRIO
    /swapfile  file   2G   0B   -2

Це лише приклад формату.

### 8.3. Як зрозуміти, чи є проблема зі swap?

Сам факт використання swap не означає несправність.

Ознаки можливого дефіциту пам’яті:

- swap активно використовується й постійно зростає;
- спостерігається постійний рух сторінок у swap і назад;
- програми починають помітно зависати;
- `MemAvailable` стає дуже малим;
- у системних журналах з’являються повідомлення про нестачу пам’яті або OOM.

Перевір статистику swap:

    vmstat 1 5

Зверни увагу на поля:

- `si` — дані, що зчитуються зі swap;
- `so` — дані, що записуються у swap.

Якщо `si` та `so` постійно мають значні ненульові значення, це може свідчити про активний рух сторінок між RAM і swap. Однак оцінюй ці показники разом з іншими даними.

## 9. Memory Pressure — тиск на пам’ять

Memory Pressure виникає, коли системі складно забезпечити поточні потреби програм в оперативній пам’яті.

Наслідки можуть включати:

- активніше звільнення кешу;
- переміщення сторінок у swap;
- збільшення затримок;
- завершення процесів механізмом OOM killer.

### 9.1. Перевірка повідомлень про нестачу пам’яті

    journalctl -k -b | grep -Ei 'out of memory|oom|killed process'

Ця команда шукає в журналі ядра поточного завантаження повідомлення, пов’язані з OOM.

Альтернативно:

    dmesg | grep -Ei 'out of memory|oom|killed process'

Доступ до частини повідомлень може бути обмежений політиками системи.

### 9.2. Pressure Stall Information — PSI

На ядрах Linux із підтримкою PSI інформація про тиск ресурсів доступна у `/proc/pressure/`.

Перевірити доступні файли:

    ls /proc/pressure

Переглянути тиск на пам’ять:

    cat /proc/pressure/memory

Також можуть бути доступні:

    cat /proc/pressure/cpu

    cat /proc/pressure/io

PSI допомагає оцінити, скільки часу завдання втрачали через очікування ресурсів. Це корисніше для деяких діагностичних сценаріїв, ніж оцінка лише за кількістю вільної пам’яті.

Якщо `/proc/pressure/` відсутній, поточне ядро або середовище може не надавати PSI.

## 10. Перегляд використання пам’яті окремими процесами

### 10.1. Команда `ps`

Показати процеси з інформацією про пам’ять:

    ps aux

Показати PID, використання CPU, пам’яті та команду:

    ps -eo pid,comm,%cpu,%mem,rss,vsz --sort=-%mem | head

Поля:

- `PID` — ідентифікатор процесу.
- `COMM` — назва команди.
- `%CPU` — оцінка використання CPU.
- `%MEM` — частка фізичної пам’яті.
- `RSS` — резидентна пам’ять процесу, зазвичай у кілобайтах.
- `VSZ` — розмір віртуального адресного простору, зазвичай у кілобайтах.

**Важливо:** `VSZ` не означає, що процес реально використовує весь цей обсяг фізичної пам’яті.

RSS також не є ідеальним показником усього фактично спожитого ресурсу процесом: спільні сторінки можуть враховуватися в RSS кількох процесів.

### 10.2. Знайти процеси, які використовують найбільше RAM

    ps -eo pid,comm,%mem,rss --sort=-%mem | head -n 10

Команда виводить заголовок і до десяти рядків із найбільшими значеннями `%MEM`.

### 10.3. Знайти процеси, які використовують найбільше CPU

    ps -eo pid,comm,%cpu --sort=-%cpu | head -n 10

Це миттєвий знімок статистики, а не безперервний моніторинг.

Для спостереження в реальному часі краще використовувати `top` або `htop`.

## 11. Моніторинг ресурсів через `htop`

`htop` — інтерактивний інструмент для перегляду процесів та системних ресурсів.

Запуск:

    htop

Якщо команда відсутня в Ubuntu:

    sudo apt update
    sudo apt install htop

У верхній частині вікна зазвичай можна побачити:

- індикатори завантаження CPU;
- використання RAM;
- використання swap;
- Load Average;
- час роботи системи.

У списку процесів можуть відображатися:

- PID;
- користувач;
- пріоритет;
- використання CPU;
- використання пам’яті;
- час роботи процесу;
- команда запуску.

Корисні клавіші можуть відрізнятися залежно від конфігурації:

- `F3` — пошук процесу;
- `F4` — фільтр;
- `F5` — дерево процесів;
- `F6` — вибір способу сортування;
- `F9` — надсилання сигналу процесу;
- `F10` — вихід.

**Важливо:** не завершуй системні процеси лише тому, що вони використовують багато пам’яті або CPU. Спочатку з’ясуй, для чого вони потрібні.

## 12. Статистика ресурсів через `vmstat`

`vmstat` показує статистику процесів, пам’яті, swap, введення-виведення та CPU.

    vmstat

Оновлювати статистику кожні дві секунди:

    vmstat 2

Зробити п’ять вимірювань з інтервалом у дві секунди:

    vmstat 2 5

Основні поля:

- `r` — кількість процесів, готових до виконання;
- `b` — кількість процесів у стані очікування;
- `swpd` — використаний swap;
- `free` — вільна пам’ять;
- `si` — швидкість зчитування зі swap;
- `so` — швидкість запису в swap;
- `bi` — блоки, зчитані з пристроїв;
- `bo` — блоки, записані на пристрої;
- `in` — переривання за секунду;
- `cs` — перемикання контексту за секунду;
- `us` — час CPU у користувацькому просторі;
- `sy` — час CPU в ядрі;
- `id` — час простою CPU;
- `wa` — час очікування введення-виведення.

Перший рядок може відображати середні значення з моменту запуску системи. Наступні рядки показують статистику за відповідні інтервали.

### На що звертати увагу?

- Велике `r` може означати чергу процесів, готових до виконання.
- Постійно значні `si` та `so` можуть вказувати на активний рух сторінок через swap.
- Високе `wa` може свідчити про очікування операцій введення-виведення.
- Значне `cs` саме по собі не доводить наявність проблеми: контекстні перемикання нормальні для багатозадачної системи.

Не роби висновків за одним показником. Порівнюй `vmstat` із `top`, `free -h` і журналами системи.

## 13. Статистика окремих процесів — `pidstat`

`pidstat` входить до пакета `sysstat` у багатьох Debian/Ubuntu-системах.

Встановлення:

    sudo apt update
    sudo apt install sysstat

Показати статистику CPU процесів:

    pidstat

Оновлювати статистику щосекунди:

    pidstat 1

Показати статистику пам’яті процесів:

    pidstat -r 1

Показати статистику введення-виведення процесів:

    pidstat -d 1

Показати статистику CPU за всіма процесорами:

    pidstat -u -I 1

Параметри:

- `-u` — CPU.
- `-r` — пам’ять.
- `-d` — введення-виведення.
- `-I` — нормалізація використання CPU з урахуванням кількості процесорів, якщо підтримується поточною версією.

`pidstat` корисний, коли потрібно визначити, який процес створює навантаження протягом певного періоду.

## 14. Історична статистика — `sar`

`sar` також входить до пакета `sysstat`. Залежно від конфігурації системи він може збирати та зберігати статистику ресурсів для подальшого аналізу.

Переглянути статистику CPU:

    sar -u 1 5

Переглянути статистику пам’яті:

    sar -r 1 5

Переглянути статистику swap:

    sar -S 1 5

Ці приклади показують п’ять вимірювань з інтервалом у секунду.

Щоб переглядати історичні дані, має бути налаштоване їх збирання та зберігання. Якщо `sysstat` раніше не збирав статистику, дані за минулі періоди можуть бути відсутні.

## 15. CPU-bound та Memory-bound задачі

### 15.1. CPU-bound

**CPU-bound** — завдання, продуктивність якого переважно обмежена швидкістю обчислень.

Приклади:

- обробка великих масивів;
- складні математичні обчислення;
- стиснення даних;
- кодування відео;
- деякі алгоритми обробки зображень.

Можливі ознаки:

- високий CPU Usage;
- невеликий час простою CPU;
- відносно невеликий вплив очікування диска.

### 15.2. Memory-bound

**Memory-bound** — завдання, продуктивність якого значною мірою залежить від доступу до пам’яті, пропускної здатності пам’яті або затримок доступу до неї.

Можливі ознаки:

- великі обсяги даних;
- активне використання RAM;
- часті промахи кешу процесора;
- зниження продуктивності через обмежену пропускну здатність пам’яті.

Не кожна програма, яка використовує багато RAM, є memory-bound. Вона може бути обмежена CPU, диском або мережею.

### 15.3. I/O-bound

**I/O-bound** — завдання, продуктивність якого переважно обмежена операціями введення-виведення.

Приклади:

- читання великих файлів із повільного диска;
- інтенсивна робота з базою даних;
- очікування мережевих відповідей;
- масові файлові операції.

Можливі ознаки:

- значне очікування введення-виведення;
- процеси, що перебувають у стані очікування;
- високі затримки диска;
- CPU може залишатися частково незавантаженим.

**Запам’ятай:** високий CPU Usage, високе використання RAM і високе очікування I/O — різні ситуації, які потребують різних способів діагностики.

## 16. Як діагностувати повільну систему

Коли Linux працює повільно, не варто відразу завершувати процеси або змінювати системні налаштування.

Спочатку збери інформацію.

### Крок 1. Перевір Load Average

    uptime

### Крок 2. Перевір CPU та процеси

    top

Знайди процеси з високим CPU Usage.

### Крок 3. Перевір оперативну пам’ять

    free -h

Зверни увагу на `available`, а також на використання swap.

### Крок 4. Перевір статистику пам’яті та I/O

    vmstat 1 5

Подивись на `r`, `b`, `si`, `so`, `wa`.

### Крок 5. Знайди процеси з найбільшим використанням RAM

    ps -eo pid,comm,%mem,rss --sort=-%mem | head -n 10

### Крок 6. Знайди процеси з найбільшим використанням CPU

    ps -eo pid,comm,%cpu --sort=-%cpu | head -n 10

### Крок 7. Перевір повідомлення ядра

    journalctl -k -b | grep -Ei 'oom|out of memory|killed process'

### Крок 8. Перевір, чи не обмежений процес

Якщо процес працює в контейнері або під системним менеджером, він може мати обмеження CPU чи пам’яті.

Для systemd-сервісу можна переглянути його властивості через `systemctl show`, якщо відома назва сервісу.

Наприклад:

    systemctl show nginx -p CPUQuota -p MemoryMax

Заміни `nginx` на назву потрібного сервісу. Порожнє або спеціальне значення властивості не завжди означає, що ресурсів достатньо: потрібно враховувати конфігурацію сервісу, його батьківські cgroup та обмеження середовища.

## 18. Типові помилки

### Помилка 1. Вважати, що низький `free` означає нестачу RAM

Linux активно використовує вільну пам’ять для кешу.

Перевір:

    free -h

Зверни увагу на `available`, використання swap і поведінку системи.

### Помилка 2. Вважати, що Swap завжди є проблемою

Використання swap саме по собі не свідчить про несправність.

Перевір:

    free -h
    vmstat 1 5

Важливі не лише обсяг використаного swap, а й активність переміщення сторінок та загальна продуктивність.

### Помилка 3. Вважати Load Average відсотком CPU

Load Average не є відсотком завантаження процесора.

Перевір:

    uptime
    top

### Помилка 4. Робити висновки за одним вимірюванням

Один знімок `ps` або `free` не завжди показує причину проблеми.

Використовуй інструменти, які дозволяють спостерігати за змінами протягом певного часу:

    top
    vmstat 1 5
    pidstat 1

### Помилка 5. Завершувати процес лише через високе використання RAM

Високе використання пам’яті може бути нормальним для конкретної програми.

Перед завершенням процесу з’ясуй:

- що це за процес;
- яку функцію він виконує;
- чи є ознаки витоку пам’яті;
- чи впливає він на доступність ресурсів;
- чи можна безпечно його перезапустити.

### Помилка 6. Плутати RSS і VSZ

- `RSS` — пам’ять процесу, яка наразі перебуває у фізичній RAM.
- `VSZ` — розмір його віртуального адресного простору.

VSZ не дорівнює реальному використанню фізичної пам’яті.

### Помилка 7. Вважати високий CPU Usage єдиною причиною повільної системи

Система може гальмувати через:

- нестачу RAM;
- активний swap;
- повільний диск;
- мережеві затримки;
- блокування процесів;
- надмірне очікування введення-виведення.

Перевіряй ресурси комплексно.

## 23. Висновок

CPU та RAM — ключові ресурси, від яких залежить продуктивність Linux-системи.

Для щоденної роботи достатньо добре знати `top`, `free -h`, `uptime`, `ps` і `vmstat`. Вони допомагають швидко визначити, які процеси використовують ресурси та чи є ознаки перевантаження.

Для глибшої діагностики використовуй `pidstat`, `mpstat`, `sar`, `/proc/meminfo`, PSI та системні журнали.

**Головний принцип:** не роби висновків за одним числом. Порівнюй CPU Usage, Load Average, доступну пам’ять, активність swap і стан процесів, щоб знайти справжню причину проблеми.
