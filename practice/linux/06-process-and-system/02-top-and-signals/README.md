# 02. top and htop

`top` та `htop` — це інтерактивні інструменти Linux для моніторингу процесів і системних ресурсів у реальному часі.

Вони дозволяють спостерігати за роботою системи, бачити активні процеси та визначати, які програми використовують найбільше CPU і RAM.

Інструменти використовуються, коли потрібно:

- переглянути поточне навантаження на CPU;
- перевірити використання оперативної пам'яті;
- знайти процес, який споживає багато ресурсів;
- спостерігати за зміною навантаження в реальному часі;
- визначити кількість запущених процесів;
- перевірити стан процесів;
- знайти процес, який уповільнює систему;
- відсортувати процеси за CPU або пам'яттю;
- переглянути процеси конкретного користувача;
- надіслати сигнал процесу;
- діагностувати проблеми з Node.js, PostgreSQL та іншими програмами.

Основні команди:

    top
    htop
    uptime
    free
    ps
    pgrep
    kill

`top` зазвичай доступний у стандартній системі Linux.

`htop` — зручніший інтерактивний інструмент із кольоровим інтерфейсом, індикаторами ресурсів і зручнішою навігацією. Він може потребувати окремого встановлення.

## Що потрібно пам'ятати

• `top` показує процеси та стан системи з регулярним оновленням інформації.

• `htop` надає подібні можливості, але зазвичай має зручніший інтерактивний інтерфейс.

• `top` зазвичай уже встановлений у Linux, а `htop` може потребувати встановлення.

• `%CPU` показує оцінку використання процесора процесом.

• `%MEM` показує частку фізичної пам'яті, яку використовує процес.

• `VIRT` — обсяг віртуального адресного простору процесу.

• `RES` — обсяг фізичної пам'яті, що перебуває в RAM і пов'язана з процесом.

• `SHR` — оцінка обсягу спільної пам'яті процесу.

• `load average` — показник системного навантаження, а не прямий відсоток використання CPU.

• Високий `load average` не завжди означає, що процесор повністю завантажений.

• Кількість CPU cores важлива для інтерпретації `load average`.

• Пам'ять Linux використовується не лише програмами, а й кешем та буферами.

• Вільна пам'ять (`free`) і доступна пам'ять (`available`) — різні показники.

• Swap — простір на диску, який система може використовувати як доповнення до RAM.

• Сам факт використання swap не означає несправність системи.

• `top` та `htop` дозволяють спостерігати за процесами в реальному часі, а `ps` переважно показує одноразовий знімок.

• Перед завершенням процесу потрібно перевірити PID, користувача та команду.

• Інструменти моніторингу допомагають виявляти симптоми проблеми, але не завжди пояснюють її першопричину.

# System Monitoring

System monitoring — це спостереження за станом операційної системи та використанням її ресурсів.

Основні ресурси:

    CPU
        → виконання інструкцій програм

    RAM
        → оперативна пам'ять

    Swap
        → простір на диску для сторінок пам'яті

    Processes
        → запущені процеси

    Load average
        → показник системного навантаження

Для швидкого моніторингу можна використовувати:

    top

Для інтерактивного перегляду:

    htop

Для окремої перевірки пам'яті:

    free -h

Для перегляду часу роботи системи та load average:

    uptime

Ці команди доповнюють одна одну.

---

# top

`top` — інтерактивна команда Linux для перегляду системних показників і процесів.

Запуск:

    top

Після запуску відкривається екран, який регулярно оновлюється.

Зазвичай він містить:

    загальну інформацію про систему
        ↓
    load average
        ↓
    кількість процесів
        ↓
    CPU usage
        ↓
    memory usage
        ↓
    список процесів

На відміну від `ps`, `top` не завершується відразу після виведення результату.

Він продовжує оновлювати інформацію, поки ти не вийдеш із програми.

Вихід:

    q

# Інформація у верхній частині top

У верхній частині `top` зазвичай відображаються:

    uptime
    load average
    tasks
    CPU usage
    memory usage
    swap usage

Точний вигляд залежить від версії `top` і налаштувань.

---

## Uptime

`uptime` показує, скільки часу система працює без перезавантаження.

Наприклад, у `top` можна побачити:

    up 2 days, 4:15

Це означає, що система працює приблизно 2 дні та 4 години 15 хвилин.

Окрема команда:

    uptime

Приклад результату:

    20:30:10 up 2 days, 4:15, 1 user, load average: 0.30, 0.25, 0.20

Тут:

    20:30:10 → поточний час системи
    up       → час роботи системи
    1 user   → кількість користувацьких сеансів
    load average → середнє навантаження

Кількість користувачів у цьому рядку не обов'язково дорівнює кількості фізичних людей за комп'ютерами.

---

# Load Average

`load average` — це показник середнього системного навантаження за певний період.

У Linux зазвичай відображаються три значення:

    load average: 0.30, 0.25, 0.20

Вони відповідають періодам:

    1 minute
    5 minutes
    15 minutes

Тобто:

    0.30 → середнє навантаження за 1 хвилину
    0.25 → середнє навантаження за 5 хвилин
    0.20 → середнє навантаження за 15 хвилин

Load average враховує процеси, які виконуються або готові до виконання, а також процеси в певних станах непереривного очікування.

Тому це не просто кількість процесів, що зараз використовують CPU.

---

## Як інтерпретувати load average

Уявімо, що комп'ютер має 4 логічні CPU.

Якщо:

    load average: 1.00, 0.80, 0.70

це зазвичай відповідає відносно невеликому середньому навантаженню для системи з 4 логічними CPU.

Якщо:

    load average: 4.00, 3.80, 3.50

це може означати, що процеси в середньому активно використовують доступні обчислювальні ресурси або очікують виконання.

Якщо:

    load average: 8.00, 7.50, 7.00

для системи з 4 логічними CPU це може свідчити про суттєве навантаження або накопичення процесів, які очікують на ресурси.

Але ці значення потрібно інтерпретувати разом з іншими показниками.

Важливо враховувати:

- кількість логічних CPU;
- завантаження кожного CPU;
- кількість процесів, які очікують на виконання;
- стан дискової підсистеми;
- наявність процесів у стані `D`;
- використання пам'яті та swap.

Load average не є прямим відсотком CPU usage.

---

## Перевірка кількості CPU

Команда:

    nproc

Показує кількість доступних процесорних одиниць обчислення, які бачить команда.

Додаткова інформація:

    lscpu

Наприклад:

    nproc

Результат:

    4

Це умовний приклад.

Якщо система має 4 доступні логічні CPU, load average близько 4 може вказувати на середнє навантаження, еквівалентне можливостям цих CPU. Але причину потрібно перевіряти окремо.

# Tasks у top

У верхній частині `top` може відображатися рядок:

    Tasks: 180 total, 1 running, 179 sleeping, 0 stopped, 0 zombie

Це умовний приклад.

Показники означають:

    total    → загальна кількість процесів
    running  → процеси, які виконуються або готові до виконання
    sleeping → процеси, що очікують
    stopped  → зупинені процеси
    zombie   → завершені процеси, статус яких ще не забрано

Кількість процесів змінюється залежно від того, які програми запущені.

Не потрібно прагнути до того, щоб усі процеси були в стані `running`.

Багато процесів нормально перебувають в очікуванні.

---

# CPU Usage у top

`top` показує, як використовуються процесорні ресурси.

Приклад рядка:

    %Cpu(s): 12.0 us, 3.0 sy, 0.0 ni, 83.0 id, 1.0 wa, 0.0 hi, 1.0 si, 0.0 st

Це умовні дані.

Основні значення:

    us → user
    sy → system
    ni → nice
    id → idle
    wa → iowait
    hi → hardware interrupts
    si → software interrupts
    st → steal time

---

## us — User

`us` показує час CPU, витрачений на виконання коду в користувацькому просторі.

Наприклад:

    us = 12.0%

Це означає, що приблизно 12% відповідного облікового інтервалу CPU було витрачено на роботу в user space.

---

## sy — System

`sy` показує час CPU, витрачений на роботу ядра Linux.

Наприклад:

    sy = 3.0%

Високе значення може бути пов'язане з інтенсивною системною роботою, але саме по собі не вказує на конкретну проблему.

---

## ni — Nice

`ni` показує час CPU, витрачений на виконання процесів зі зміненими значеннями nice.

Nice впливає на пріоритет планування процесу.

Детальніше nice та пріоритети розглядаються в темі про керування процесами.

---

## id — Idle

`id` показує частку часу, коли CPU був незайнятий.

Наприклад:

    id = 83.0%

Це означає, що процесор мав значний обсяг незайнятого часу протягом відповідного інтервалу.

Високий idle зазвичай означає, що CPU не є повністю завантаженим.

---

## wa — I/O Wait

`wa` — час, коли CPU був незайнятий, поки система очікувала завершення операцій введення-виведення.

Наприклад, це може бути пов'язано з диском.

Але:

    wa > 0

не доводить, що саме диск є причиною проблеми.

Потрібно перевірити інші показники та стан процесів.

---

## hi та si

    hi → hardware interrupts
    si → software interrupts

Ці показники пов'язані з обробкою апаратних і програмних переривань.

На початковому рівні достатньо знати, що вони відображають частину системної роботи CPU.

---

## st — Steal Time

`st` важливий насамперед у віртуалізованих середовищах.

Він показує час CPU, який гостьова операційна система хотіла використати, але який не був наданий їй гіпервізором.

На звичайному фізичному комп'ютері цей показник часто дорівнює нулю.

---

# Memory Usage у top

`top` також показує використання пам'яті.

У сучасних версіях procps-ng рядок може виглядати приблизно так:

    MiB Mem : 7900.0 total, 1200.0 free, 4100.0 used, 2600.0 buff/cache
    MiB Swap: 2048.0 total, 2048.0 free, 0.0 used

Це умовний приклад. Конкретні поля та спосіб представлення залежать від версії.

Основні поняття:

    total     → загальний обсяг пам'яті
    free      → повністю вільна пам'ять
    used      → пам'ять, віднесена до використаної
    buff/cache → буфери та кеш
    swap      → використання swap

У Linux вільна RAM часто використовується для кешування файлів.

Це нормально: кеш може бути звільнений системою, коли пам'ять потрібна програмам.

Тому невелике значення `free` саме по собі не означає, що пам'ять закінчується.

Для оцінки доступної пам'яті корисно також використовувати:

    free -h

# Process List у top

Нижче системної інформації відображається список процесів.

Типові колонки:

    PID USER PR NI VIRT RES SHR S %CPU %MEM TIME+ COMMAND

Пояснення:

    PID     → ідентифікатор процесу
    USER    → власник процесу
    PR      → планувальний пріоритет у форматі top
    NI      → nice value
    VIRT    → віртуальний обсяг пам'яті
    RES     → фізична пам'ять
    SHR     → спільна пам'ять
    S       → стан процесу
    %CPU    → використання CPU
    %MEM    → використання RAM
    TIME+   → накопичений CPU time
    COMMAND → назва або команда процесу

Набір колонок може змінюватися залежно від налаштувань.

---

# PR — Priority

`PR` — значення, пов'язане з пріоритетом планування процесу.

Linux використовує різні класи планування, тому значення PR не завжди можна інтерпретувати за простим правилом.

Для звичайних процесів, які використовують стандартну політику планування, часто можна побачити зв'язок між PR та NI.

На початковому рівні достатньо знати:

    PR → пріоритет планування, який показує top
    NI → nice value процесу

Не слід змінювати пріоритети процесів без розуміння наслідків.

---

# NI — Nice Value

`NI` — значення nice, яке впливає на відносний пріоритет звичайних процесів.

Типовий діапазон:

    -20 → вищий пріоритет
      0 → стандартне значення
     19 → нижчий пріоритет

Це стосується звичайної політики планування Linux.

Значення nice впливає на те, як планувальник розподіляє CPU між конкуруючими процесами.

Для початкового ознайомлення можна запустити процес із нижчим пріоритетом:

    nice -n 10 command

Наприклад:

    nice -n 10 node script.js

Команда запустить Node.js зі зміненим nice value, якщо це підтримується та дозволено системою.

Детальніше:

    man nice
    man renice

---

# VIRT, RES та SHR

Ці поля описують різні аспекти пам'яті процесу.

## VIRT

`VIRT` — віртуальний обсяг пам'яті процесу.

Він може включати:

- сторінки, що перебувають у RAM;
- відображені у пам'ять файли;
- виділену, але ще не використану пам'ять;
- сторінки, які не перебувають у фізичній RAM.

Тому VIRT може бути значно більшим за RES.

## RES

`RES` — обсяг фізичної пам'яті, пов'язаної з процесом, яка зараз перебуває в RAM.

Це корисніший показник для приблизного розуміння фізичного резидентного набору пам'яті процесу.

Проте RES може включати спільні сторінки.

## SHR

`SHR` — оцінка пам'яті, яка може бути спільною з іншими процесами.

Наприклад, спільними можуть бути сторінки бібліотек.

Не слід механічно підсумовувати RES або SHR усіх процесів і вважати результат точним обсягом зайнятої системної пам'яті.

---

# Основні клавіші top

Під час роботи `top` можна використовувати клавіші для зміни відображення.

    q → вихід
    h → довідка
    k → надіслати сигнал процесу
    r → змінити nice value процесу
    P → сортування за CPU
    M → сортування за пам'яттю
    T → сортування за CPU time
    N → сортування за PID
    1 → показувати окремі CPU, якщо підтримується поточним режимом
    c → перемикання між назвою команди та командним рядком
    V → деревоподібний режим у версіях, які його підтримують
    W → зберегти налаштування користувача в підтримуваних версіях

Поведінка деяких клавіш залежить від версії та режиму `top`.

Якщо не впевнений у клавішах, натисни:

    h

# Сортування в top

За замовчуванням процеси часто сортуються за використанням CPU.

Можна змінювати поле сортування.

## За CPU

Натисни:

    P

## За пам'яттю

Натисни:

    M

## За CPU time

Натисни:

    T

## За PID

Натисни:

    N

Це допомагає швидко знаходити процеси, які споживають найбільше ресурсів або працюють тривалий час.

# Фільтрація процесів у top

У `top` доступні інтерактивні можливості фільтрації.

У багатьох версіях можна використовувати:

    u

для вибору процесів певного користувача.

Залежно від версії та режиму інтерфейсу доступні й інші фільтри.

Для пошуку за назвою іноді простіше скористатися іншими командами в окремому терміналі:

    pgrep -af node

або:

    ps aux | grep '[n]ode'

Не потрібно запам'ятовувати всі функції фільтрації `top` на початковому етапі.

# htop

`htop` — інтерактивний інструмент моніторингу процесів і системних ресурсів.

Запуск:

    htop

Зазвичай інтерфейс містить:

    індикатори CPU
    індикатори RAM і swap
    load average
    uptime
    список процесів
    інтерактивне меню

Переваги `htop`:

- зручніша навігація;
- кольорове відображення ресурсів;
- можливість швидко вибирати процеси;
- зручне сортування;
- перегляд дерева процесів;
- інтерактивне надсилання сигналів;
- налаштування видимих колонок;
- підтримка прокручування списку процесів.

Наявність конкретних можливостей залежить від версії `htop` та її конфігурації.

---

# Встановлення htop в Ubuntu

Перевірити, чи встановлений `htop`:

    htop --version

Якщо команда не знайдена, можна встановити пакет:

    sudo apt update
    sudo apt install htop

Після встановлення:

    htop

Для виходу:

    q

Або скористайся відповідною клавішею виходу, яку показує нижня панель інтерфейсу.

---

# Інтерфейс htop

У верхній частині `htop` зазвичай розташовані індикатори ресурсів.

Наприклад:

    CPU  [||||||||        ]
    Mem  [||||||||||      ]
    Swp  [                ]

Це схематичне зображення.

Зазвичай інтерфейс показує:

    CPU → навантаження процесорів
    Mem → використання фізичної пам'яті
    Swp → використання swap
    Load average → системне навантаження
    Uptime → час роботи системи

Нижче відображається список процесів.

Важливо: кольори та значення індикаторів залежать від версії та налаштувань. Не слід робити висновок про конкретний тип пам'яті лише за кольором, не перевіривши легенду інтерфейсу.

---

# Основні колонки htop

Залежно від налаштувань можуть відображатися:

    PID
    USER
    PRI
    NI
    VIRT
    RES
    SHR
    S
    CPU%
    MEM%
    TIME+
    Command

Основні значення:

    PID     → ідентифікатор процесу
    USER    → власник процесу
    PRI     → інформація про пріоритет
    NI      → nice value
    VIRT    → віртуальна пам'ять
    RES     → резидентна фізична пам'ять
    SHR     → спільна пам'ять
    S       → стан процесу
    CPU%    → використання CPU
    MEM%    → частка RAM
    TIME+   → накопичений CPU time
    Command → команда

Набір полів може змінюватися у налаштуваннях `htop`.

# Основні клавіші htop

Найважливіші клавіші:

    F1 → Help
    F2 → Setup
    F3 → Search
    F4 → Filter
    F5 → Tree
    F6 → SortBy
    F7 → зменшити nice value, якщо дозволено
    F8 → збільшити nice value
    F9 → Kill
    F10 → Quit

У деяких терміналах функціональні клавіші можуть працювати інакше або перехоплюватися середовищем.

Тоді можна використовувати альтернативні клавіші, зазначені в нижній панелі `htop`.

---

## F1 — Help

Відкриває довідку `htop`.

Корисно, коли потрібно перевірити призначення клавіш.

## F2 — Setup

Дозволяє налаштовувати інтерфейс.

Залежно від версії можна змінювати:

- видимі колонки;
- індикатори;
- кольори;
- параметри відображення;
- інші налаштування.

## F3 — Search

Дозволяє шукати процеси за текстом.

Наприклад:

    node

Це зручно для пошуку Node.js-процесів у довгому списку.

## F4 — Filter

Дозволяє відфільтрувати процеси за текстом.

Наприклад, можна ввести:

    postgres

Тоді інтерфейс показуватиме відповідні процеси.

Точна поведінка фільтра залежить від версії.

## F5 — Tree

Перемикає деревоподібне відображення процесів.

Це допомагає зрозуміти:

    parent process
        ↓
    child process
        ↓
    child process

## F6 — SortBy

Дозволяє вибрати поле сортування.

Наприклад:

    CPU%
    MEM%
    PID
    TIME+

Доступні поля залежать від версії та конфігурації.

## F9 — Kill

Відкриває меню надсилання сигналу вибраному процесу.

Перед підтвердженням перевір:

    PID
    USER
    Command

Не надсилай сигнал процесу, якщо не впевнений, що вибрав правильний рядок.

## F10 — Quit

Завершує роботу `htop`.

Альтернативно часто працює:

    q

---

# Сортування в htop

У `htop` можна сортувати процеси за різними полями.

Наприклад:

    CPU% → хто використовує найбільше CPU
    MEM% → хто використовує найбільше RAM
    PID  → сортування за ідентифікатором
    TIME+ → процеси з найбільшим накопиченим CPU time

Натисни:

    F6

Потім вибери потрібне поле.

Це зручніше, ніж вручну обробляти великий список процесів.

---

# Дерево процесів у htop

Натисни:

    F5

Процеси будуть відображатися в деревоподібному вигляді, якщо режим підтримується поточною версією.

Наприклад:

    systemd
        └── terminal
              └── bash
                    └── node server.js

Це умовний приклад.

Дерево допомагає зрозуміти, які процеси були створені іншими процесами.

Це особливо корисно для:

- серверів розробки;
- дочірніх процесів;
- скриптів автоматизації;
- системних служб;
- діагностики процесів, що залишилися після завершення роботи термінала.

---

# htop і керування процесами

`htop` дозволяє надсилати сигнали процесам.

Порядок дій:

    1. Запустити htop.
    2. Знайти потрібний процес.
    3. Перевірити PID та команду.
    4. Вибрати процес.
    5. Натиснути F9.
    6. Вибрати відповідний сигнал.
    7. Підтвердити дію.

Для звичайного завершення процесу часто використовують:

    SIGTERM

Для примусового завершення:

    SIGKILL

`SIGKILL` не дає процесу можливості виконати звичайне очищення ресурсів.

Тому спочатку надавай перевагу коректному завершенню.

Не завершуй системні процеси без розуміння їхнього призначення.

# top vs htop

Обидва інструменти призначені для моніторингу системи та процесів.

| Можливість | `top` | `htop` |
|---|---|---|
| Моніторинг у реальному часі | Так | Так |
| Список процесів | Так | Так |
| CPU usage | Так | Так |
| Memory usage | Так | Так |
| Load average | Так | Так |
| Сортування процесів | Так | Так |
| Інтерактивний пошук | Залежить від версії та режиму | Зручніший пошук |
| Дерево процесів | Підтримується в багатьох версіях | Зручний режим дерева |
| Керування сигналами | Так | Так |
| Кольоровий інтерфейс | Залежить від налаштувань | Зазвичай так |
| Потреба у встановленні | Зазвичай не потрібна | Часто потрібно встановити |
| Налаштування інтерфейсу | Так | Так, зручне інтерактивне меню |

Основний принцип:

    top
        → стандартний інструмент моніторингу

    htop
        → інтерактивна альтернатива з розширеною навігацією

Обидва інструменти корисні. Важливо навчитися розуміти показники, а не лише користуватися зручним інтерфейсом.

# top / htop vs ps

Ці інструменти доповнюють один одного.

## ps

    ps aux

Показує знімок процесів.

Корисний для:

- командних сценаріїв;
- пошуку процесів;
- фільтрації через `grep`;
- отримання інформації в скриптах;
- швидкої перевірки PID.

## top

    top

Показує процеси та ресурси з регулярним оновленням.

Корисний для:

- спостереження за CPU;
- спостереження за RAM;
- визначення процесів із високим навантаженням;
- діагностики проблем у реальному часі.

## htop

    htop

Надає подібні можливості з інтерактивною навігацією.

Корисний для:

- швидкого пошуку процесу;
- сортування;
- перегляду дерева;
- керування сигналами;
- інтерактивного дослідження системи.

Можна запам'ятати так:

    ps    → знімок процесів
    top   → моніторинг у реальному часі
    htop  → інтерактивний моніторинг

# free — перевірка пам'яті

Команда `free` показує використання оперативної пам'яті та swap.

Запуск:

    free

Зручний формат:

    free -h

Параметр `-h` означає human-readable format.

Приклад результату:

    total   used   free   shared  buff/cache  available
    7.7Gi   3.8Gi  1.2Gi  250Mi   2.7Gi       3.4Gi

Це умовні значення.

Основні колонки:

    total      → загальний обсяг
    used       → використана пам'ять
    free       → повністю вільна пам'ять
    shared     → спільна пам'ять
    buff/cache → буфери та кеш
    available  → приблизний обсяг пам'яті, доступний програмам без активного використання swap

`available` часто корисніший для оцінювання запасу RAM, ніж просто `free`.

---

# Swap

Swap — це простір на диску, який Linux може використовувати для зберігання сторінок пам'яті, що не перебувають у фізичній RAM.

Переглянути swap:

    free -h

Або:

    swapon --show

Приклад:

    NAME      TYPE SIZE USED PRIO
    /swapfile file   2G   0B   -2

Це умовний приклад.

Використання swap не обов'язково означає проблему.

Але якщо система активно переміщує сторінки між RAM і swap, продуктивність може погіршуватися.

Для оцінки ситуації перевіряй:

    RAM usage
    available memory
    swap usage
    CPU usage
    load average
    disk activity

Не роби висновок лише за одним показником.

---

# CPU Usage vs Load Average

Це два різні показники.

## CPU usage

Показує, наскільки зайняті процесорні ресурси.

Наприклад:

    CPU usage = 90%

Це означає високу активність CPU протягом відповідного інтервалу.

## Load average

Показує середнє навантаження системи за певний час.

Наприклад:

    load average: 5.00, 4.50, 4.00

Це не означає 500% CPU usage.

Load average потрібно інтерпретувати з урахуванням кількості CPU та процесів, які очікують на ресурси.

Високий load average при невисокому CPU usage може бути пов'язаний, наприклад, із процесами в стані непереривного очікування.

---

# Чому система може працювати повільно

Якщо комп'ютер уповільнився, можливі різні причини:

    1. Високе використання CPU.
    2. Нестача доступної RAM.
    3. Активне використання swap.
    4. Очікування дискових операцій.
    5. Процеси, що зависли або довго очікують.
    6. Високе системне навантаження.
    7. Проблеми конкретної програми.
    8. Фонові оновлення або інші системні завдання.

Початкова діагностика:

    top

Знайди процеси з високим CPU usage.

Потім перевір:

    free -h

Оціни доступну RAM та swap.

Далі:

    ps -eo pid,ppid,stat,%cpu,%mem,cmd --sort=-%cpu

Перевір, які процеси споживають найбільше CPU.

Якщо причина неочевидна, не потрібно відразу завершувати процеси. Спочатку визнач, чи це нормальна робота програми, чи ознака проблеми.

# Практичний сценарій: діагностика повільного Node.js-сервера

Уявімо, що ти запускаєш Express або NestJS, але система стала працювати повільно.

## Крок 1 — запусти моніторинг

    top

Перевір:

    CPU usage
    load average
    memory usage
    swap usage

## Крок 2 — знайди процес Node.js

У другому терміналі:

    pgrep -af node

Перевір командний рядок і PID потрібного процесу.

## Крок 3 — перевір використання ресурсів

    ps -p PID -o pid,ppid,user,stat,%cpu,%mem,rss,etime,cmd

Заміни `PID` на реальний числовий ідентифікатор.

## Крок 4 — перевір загальну пам'ять

    free -h

Особливо зверни увагу на:

    available
    swap used

## Крок 5 — спостерігай за змінами

    htop

Перевір, чи стабільно процес використовує CPU або навантаження постійно зростає.

## Крок 6 — зроби висновок

Можливі ситуації:

    високий CPU
        → можлива інтенсивна обробка або нескінченний цикл

    низький available memory
        → можлива нестача RAM

    значне використання swap
        → можлива нестача фізичної пам'яті

    процес у стані S
        → може нормально очікувати на подію

    процес у стані D
        → можлива проблема з операцією введення-виведення

Це лише початкові ознаки. Для остаточного висновку потрібна додаткова діагностика.

# Практичний сценарій: знайти процес, що споживає багато CPU

Крок 1. Запусти:

    top

Крок 2. Натисни:

    P

Крок 3. Знайди процес із високим `%CPU`.

Крок 4. Перевір:

    PID
    USER
    COMMAND

Крок 5. Отримай додаткову інформацію:

    ps -p PID -o pid,ppid,user,stat,%cpu,%mem,etime,cmd

Крок 6. Визнач, чи процес справді працює неправильно.

Високе CPU usage може бути нормальним, наприклад, під час компіляції або обробки великого обсягу даних.

Не завершуй процес автоматично лише через високе навантаження.

---

# Практичний сценарій: знайти процес, що використовує багато RAM

Крок 1. Запусти:

    htop

Крок 2. Натисни:

    F6

Крок 3. Вибери сортування за `MEM%`, якщо це поле доступне.

Крок 4. Перевір процеси з найбільшими значеннями.

Крок 5. Запусти:

    free -h

Крок 6. Порівняй використання пам'яті процесами із загальним станом RAM.

Важливо: процес із великим VIRT не обов'язково використовує такий самий обсяг фізичної пам'яті.

Перевіряй RES, MEM% та загальну доступну пам'ять.

# Типові помилки

## ❌ Вважати load average відсотком CPU

    load average: 4.00

Це не означає 400% CPU usage.

Load average відображає середнє системне навантаження, яке потрібно інтерпретувати з урахуванням кількості CPU та станів процесів.

---

## ❌ Вважати, що високе load average завжди означає високий CPU usage

Load average може враховувати процеси, які перебувають у певних станах непереривного очікування.

Тому потрібно перевіряти CPU, стан процесів та інші ресурси.

---

## ❌ Вважати малий free показником нестачі RAM

Linux використовує пам'ять для кешу та буферів.

Перевір:

    free -h

Особливо зверни увагу на:

    available

# Головне

• `top` та `htop` допомагають спостерігати за процесами й системними ресурсами в реальному часі.

• `top` зазвичай доступний у Linux за замовчуванням, а `htop` може потребувати встановлення.

• `ps` показує переважно одноразовий знімок процесів, тоді як `top` і `htop` регулярно оновлюють інформацію.

• CPU usage показує використання процесорних ресурсів, а load average відображає середнє системне навантаження.

• Load average зазвичай відображається за 1, 5 та 15 хвилин.

• Для правильного розуміння load average потрібно враховувати кількість доступних CPU та стани процесів.

• `us`, `sy`, `id` та `wa` описують різні аспекти використання CPU.

• VIRT — це віртуальний адресний простір, RES — резидентна фізична пам'ять, SHR — оцінка спільної пам'яті.

• Невелика кількість вільної RAM не обов'язково означає нестачу пам'яті. Перевіряй `available` через `free -h`.

• Swap є механізмом керування пам'яттю, і сам факт його використання не означає проблему.

• `top` дозволяє сортувати процеси за CPU, пам'яттю та іншими показниками.

• `htop` спрощує пошук процесів, сортування, перегляд дерева та надсилання сигналів.

• Високе використання CPU або RAM є приводом для дослідження, але не автоматичною причиною завершувати процес.

• Перед надсиланням сигналу завжди перевіряй PID, користувача та команду.

• Основний алгоритм діагностики:

    CPU → перевірити навантаження
    RAM → перевірити available memory
    Swap → перевірити використання
    Process → знайти винуватця
    PID → підтвердити потрібний процес
    Cause → встановити причину
    Action → виконати обґрунтовану дію

• Для розробника особливо корисно вміти знаходити процеси Node.js, перевіряти їхнє навантаження та відрізняти проблеми CPU від проблем пам'яті.
