# System Information — Інформація про систему Linux

> Шпаргалка з отримання інформації про операційну систему Linux, ядро, процесор, оперативну пам’ять, апаратне забезпечення, час роботи системи та системні ресурси.

---

## 1. Що таке System Information?

**System Information** — це відомості про поточну операційну систему, її апаратне забезпечення, ядро, ресурси та стан роботи.

У Linux є багато команд, які допомагають дізнатися:

- ✔ Назву та версію операційної системи.
- ✔ Версію ядра Linux.
- ✔ Архітектуру процесора.
- ✔ Модель CPU та кількість ядер.
- ✔ Обсяг оперативної пам’яті.
- ✔ Час роботи системи.
- ✔ Поточну дату й час.
- ✔ Ім’я комп’ютера.
- ✔ Інформацію про BIOS, диски, USB та інші пристрої.
- ✔ Завантаження системи та використання ресурсів.

Ці команди особливо корисні під час налаштування Linux, пошуку несправностей, адміністрування серверів і розробки програм.

## 3. Інформація про операційну систему

### 3.1. `/etc/os-release`

Файл `/etc/os-release` містить основні відомості про Linux-дистрибутив.

    cat /etc/os-release

Приклад результату:

    PRETTY_NAME="Ubuntu 26.04 LTS"
    NAME="Ubuntu"
    VERSION_ID="26.04"
    VERSION="26.04 LTS"
    ID=ubuntu
    ID_LIKE=debian

Зверни увагу: конкретні значення залежать від встановленого дистрибутива.

Основні поля:

- `NAME` — назва дистрибутива.
- `PRETTY_NAME` — зрозуміла людині назва.
- `VERSION` — назва та номер версії.
- `VERSION_ID` — ідентифікатор версії.
- `ID` — короткий ідентифікатор дистрибутива.
- `ID_LIKE` — споріднені сімейства дистрибутивів, якщо зазначені.

Показати тільки потрібні поля:

    grep -E '^(NAME|VERSION|VERSION_ID|PRETTY_NAME)=' /etc/os-release

**Запам’ятай:** `/etc/os-release` — один із найзручніших способів програмно визначити дистрибутив Linux.

### 3.2. Команда `uname`

`uname` виводить інформацію про ядро та систему.

    uname

Типовий результат:

    Linux

Показати ім’я ядра:

    uname -s

Показати ім’я комп’ютера:

    uname -n

Показати версію ядра:

    uname -r

Показати повну інформацію:

    uname -a

Приклад:

    Linux my-computer 6.14.0-generic #14-Ubuntu SMP x86_64 GNU/Linux

Основні параметри:

| Параметр | Значення |
|---|---|
| `-s` | Назва ядра |
| `-n` | Ім’я вузла (hostname) |
| `-r` | Версія ядра |
| `-v` | Інформація про збірку ядра |
| `-m` | Машинна архітектура |
| `-p` | Тип процесора, якщо підтримується |
| `-i` | Апаратна платформа, якщо підтримується |
| `-o` | Назва операційної системи |
| `-a` | Уся доступна інформація |

**Важливо:** `uname -r` показує версію ядра Linux, а не версію Ubuntu чи іншого дистрибутива.

### 3.3. `hostnamectl`

Команда `hostnamectl` показує ім’я комп’ютера та доступні відомості про систему.

    hostnamectl

У результаті можуть відображатися:

- Static hostname — постійне ім’я комп’ютера.
- Operating System — операційна система.
- Kernel — версія ядра.
- Architecture — архітектура.
- Virtualization — відомості про віртуалізацію, якщо визначені.

Показати лише ім’я:

    hostnamectl --static

Звичайна команда для перегляду імені комп’ютера:

    hostname

Зміна hostname потребує адміністративних прав. Не змінюй його без потреби на навчальній або робочій системі.

## 4. Архітектура системи

Архітектура визначає, для якої процесорної платформи створені ядро та програми.

### 4.1. Дізнатися архітектуру

    uname -m

Типові результати:

    x86_64

    aarch64

Зазвичай:

- `x86_64` — 64-бітна архітектура x86, поширена на комп’ютерах Intel і AMD.
- `aarch64` — 64-бітна архітектура ARM.
- `i386`, `i686` — 32-бітні варіанти x86.

### 4.2. Архітектура пакетів Debian/Ubuntu

    dpkg --print-architecture

Приклад:

    amd64

Тут `amd64` — назва архітектури пакетів Debian/Ubuntu, яка відповідає 64-бітній архітектурі x86, незалежно від того, процесор Intel чи AMD.

Переглянути також архітектуру ядра:

    uname -m

**Запам’ятай:** `uname -m` показує архітектуру системи, а `dpkg --print-architecture` — архітектуру пакетів у Debian/Ubuntu.

## 5. Інформація про процесор — CPU

### 5.1. Команда `lscpu`

`lscpu` показує основні характеристики процесора.

    lscpu

У результаті можна побачити:

- Architecture — архітектура.
- CPU(s) — кількість логічних процесорів.
- Thread(s) per core — кількість потоків на ядро.
- Core(s) per socket — кількість ядер на процесор.
- Socket(s) — кількість фізичних процесорів у системі.
- Model name — модель процесора.
- CPU MHz — частота, якщо наведена.
- Virtualization — підтримка або наявність віртуалізації.

Приклад окремих полів:

    Architecture:             x86_64
    CPU(s):                   4
    Thread(s) per core:       2
    Core(s) per socket:       2
    Socket(s):                1

Це лише приклад: кількість логічних процесорів і фізичних ядер може відрізнятися.

### 5.2. Кількість доступних CPU

    nproc

Команда показує кількість процесорних одиниць, доступних поточному процесу. У деяких середовищах, наприклад контейнерах, це значення може відрізнятися від загальної кількості логічних CPU в системі.

Інші варіанти:

    nproc --all

Переглянути інформацію про CPU через системний файл:

    cat /proc/cpuinfo

Показати назви моделей процесорів:

    grep -m 1 "model name" /proc/cpuinfo

**Запам’ятай:**

- `lscpu` — зручний загальний огляд CPU.
- `nproc` — кількість доступних процесорних одиниць.
- `/proc/cpuinfo` — детальніші відомості про процесори, які надає ядро.

## 6. Оперативна пам’ять — RAM

### 6.1. Команда `free`

`free` показує використання оперативної пам’яті та swap.

    free

Зручний варіант у мегабайтах або гігабайтах:

    free -h

Приклад:

    total        used        free      shared  buff/cache   available
    Mem:           7.6Gi       2.1Gi       1.8Gi       200Mi       3.7Gi       5.0Gi
    Swap:          2.0Gi          0B       2.0Gi

Цифри наведені лише для прикладу.

Основні колонки:

- `total` — загальний обсяг пам’яті, доступний Linux.
- `used` — використана пам’ять за методикою команди.
- `free` — пам’ять, яка зараз не використовується.
- `shared` — пам’ять, пов’язана зі спільним використанням.
- `buff/cache` — буфери та кеш.
- `available` — приблизний обсяг пам’яті, який можна використати без активного звернення до swap.

**Важливо:** мале значення `free` саме по собі не означає нестачу RAM. Linux використовує вільну пам’ять для кешування. Для оцінки доступного ресурсу звертай увагу на `available`.

### 6.2. Оновлення інформації

    free -h -s 2

Команда оновлює статистику кожні дві секунди. Зупинити — `Ctrl + C`.

Показати пам’ять у мегабайтах:

    free -m

Показати пам’ять у гігабайтах:

    free -g

### 6.3. Файл `/proc/meminfo`

Детальніші дані про пам’ять:

    cat /proc/meminfo

Показати тільки найважливіші поля:

    grep -E '^(MemTotal|MemFree|MemAvailable|Buffers|Cached|SwapTotal|SwapFree):' /proc/meminfo

Основні поля:

- `MemTotal` — загальний обсяг RAM, видимий ядру.
- `MemFree` — вільна пам’ять.
- `MemAvailable` — оцінка доступної пам’яті.
- `Buffers` — буфери.
- `Cached` — кеш.
- `SwapTotal` — загальний обсяг swap.
- `SwapFree` — вільний swap.

### 6.4. Команда `lsmem`

    lsmem

Команда показує інформацію про діапазони фізичної пам’яті, які розпізнає система. Вона не замінює `free` для оцінки поточного використання RAM.

## 7. Час роботи системи — Uptime

### 7.1. Команда `uptime`

    uptime

Приклад:

    20:45:10 up 3 days, 4:12, 2 users, load average: 0.30, 0.45, 0.40

Значення:

- `20:45:10` — поточний час.
- `up 3 days, 4:12` — система працює три дні й чотири години дванадцять хвилин.
- `2 users` — кількість облікових сесій користувачів, які враховує система.
- `load average` — середнє навантаження за 1, 5 і 15 хвилин.

Компактний формат:

    uptime -p

Приклад:

    up 3 days, 4 hours, 12 minutes

Час останнього запуску системи:

    uptime -s

### 7.2. Що таке Load Average?

**Load Average** — це середнє навантаження системи. У Linux воно враховує процеси, які виконуються або очікують на виконання CPU, а також процеси в певних станах очікування, зокрема незворотного очікування введення-виведення.

Наприклад:

    load average: 0.30, 0.45, 0.40

Ці числа відповідають середньому навантаженню за:

1. Останню 1 хвилину.
2. Останні 5 хвилин.
3. Останні 15 хвилин.

Як приблизно оцінювати значення:

- На системі з 4 логічними CPU навантаження близько `4.0` може відповідати повному завантаженню процесорів, якщо навантаження переважно CPU-залежне.
- Значення вище кількості CPU може означати чергу процесів, але також може бути пов’язане з очікуванням введення-виведення.
- Значення нижче кількості CPU не гарантує, що система працює без проблем.

**Запам’ятай:** Load Average — це не відсоток використання CPU. Для поточного завантаження процесора використовуй `top` або `htop`.

## 8. Дата, час і часовий пояс

### 8.1. Команда `date`

    date

Показати дату у власному форматі:

    date +"%Y-%m-%d"

Приклад:

    2026-10-18

Показати дату й час:

    date +"%Y-%m-%d %H:%M:%S"

Основні символи формату:

| Символ | Значення |
|---|---|
| `%Y` | Рік |
| `%m` | Місяць |
| `%d` | День |
| `%H` | Година у форматі 00–23 |
| `%M` | Хвилини |
| `%S` | Секунди |
| `%A` | Повна назва дня тижня |
| `%B` | Повна назва місяця |

### 8.2. Команда `timedatectl`

    timedatectl

Показати доступні часові пояси:

    timedatectl list-timezones

Знайти часові пояси, пов’язані з Києвом:

    timedatectl list-timezones | grep Kyiv

У багатьох сучасних системах використовується часовий пояс `Europe/Kyiv`.

Переглянути статус синхронізації часу:

    timedatectl status

**Важливо:** не змінюй системний час або часовий пояс без потреби. На серверах неправильний час може спричиняти проблеми з журналами, сертифікатами, завданнями за розкладом і мережевими сервісами.

## 9. Апаратне забезпечення

### 9.1. Команда `lshw`

`lshw` показує детальну інформацію про апаратне забезпечення.

    sudo lshw

Зручний скорочений огляд:

    sudo lshw -short

Показати інформацію про CPU:

    sudo lshw -class processor

Показати інформацію про пам’ять:

    sudo lshw -class memory

Показати інформацію про мережеві пристрої:

    sudo lshw -class network

**Примітка:** `lshw` може бути не встановлений за замовчуванням. У Ubuntu його можна встановити так:

    sudo apt update
    sudo apt install lshw

Використовуй `sudo` лише тоді, коли команда справді потребує підвищених прав.

### 9.2. Команда `lspci`

`lspci` показує пристрої, підключені через PCI/PCI Express: відеокарти, мережеві контролери, аудіоконтролери та інші пристрої.

    lspci

Детальніший список:

    lspci -v

Показати інформацію про графічний адаптер:

    lspci | grep -Ei 'vga|3d|display'

Показати мережеві контролери:

    lspci | grep -i network

### 9.3. Команда `lsusb`

`lsusb` показує USB-пристрої.

    lsusb

Детальніший список:

    lsusb -v

Оскільки `lsusb -v` може виводити багато інформації, зазвичай достатньо почати з `lsusb`.

### 9.4. Команда `dmidecode`

`dmidecode` читає дані DMI/SMBIOS, якщо вони доступні. Це може бути інформація про BIOS, виробника, модель комп’ютера, системну плату та пам’ять.

    sudo dmidecode

Показати інформацію про BIOS:

    sudo dmidecode -t bios

Показати інформацію про систему:

    sudo dmidecode -t system

Показати інформацію про системну плату:

    sudo dmidecode -t baseboard

Показати відомості про модулі пам’яті:

    sudo dmidecode -t memory

На віртуальних машинах або деякому обладнанні частина даних може бути відсутня чи неповна.

## 10. Системні файли `/proc` і `/sys`

Linux надає багато відомостей про ядро та пристрої через спеціальні файлові системи.

### 10.1. Що таке `/proc`?

`/proc` — віртуальна файлова система, яка надає інформацію про процеси та стан ядра.

Це не звичайний каталог із файлами, збереженими на диску. Багато його даних формуються ядром під час читання.

Корисні файли:

| Файл | Призначення |
|---|---|
| `/proc/cpuinfo` | Інформація про процесор |
| `/proc/meminfo` | Інформація про пам’ять |
| `/proc/uptime` | Час роботи системи та час простою CPU |
| `/proc/loadavg` | Load Average та деякі відомості про процеси |
| `/proc/version` | Інформація про версію ядра |
| `/proc/cmdline` | Параметри запуску ядра |
| `/proc/mounts` | Поточні точки монтування |
| `/proc/1/` | Інформація про процес із PID 1 |

Приклади:

    cat /proc/version

    cat /proc/uptime

    cat /proc/loadavg

    cat /proc/cmdline

Значення у `/proc/uptime` подаються в секундах. Перше число — час роботи системи, друге — сумарний час простою CPU, виражений у специфічному форматі ядра.

### 10.2. Що таке `/sys`?

`/sys` — віртуальна файлова система `sysfs`, яка надає інформацію про пристрої, драйвери, ядро та системні об’єкти.

Переглянути вміст:

    ls /sys

Приклад:

    ls /sys/class

Переглянути пристрої:

    ls /sys/devices

**Важливо:** не записуй значення у файли `/sys` навмання. Деякі з них керують реальними параметрами пристроїв або ядра.

## 11. Повідомлення ядра — `dmesg`

Команда `dmesg` показує повідомлення, які надає ядро Linux. Вони допомагають досліджувати виявлення обладнання, драйвери, помилки та проблеми під час запуску.

    dmesg

Показати час у читабельнішому форматі, якщо підтримується:

    dmesg -T

Показати останні повідомлення:

    dmesg | tail -n 30

Знайти повідомлення про помилки:

    dmesg --level=err

Знайти повідомлення про USB:

    dmesg | grep -i usb

Знайти повідомлення про відео або графіку:

    dmesg | grep -Ei 'drm|gpu|graphics|video'

Деякі системи обмежують доступ до повідомлень ядра для звичайних користувачів. Якщо команда повертає помилку доступу, це не обов’язково означає проблему з системою.

Для перегляду журналів запуску системи також використовують:

    journalctl -k

Показати повідомлення ядра поточного завантаження:

    journalctl -k -b

**Запам’ятай:**

- `dmesg` — буфер повідомлень ядра.
- `journalctl -k` — повідомлення ядра в системному журналі systemd, якщо journald доступний.

## 12. Поточний стан системи

### 12.1. Команда `top`

    top

`top` показує процеси та змінні показники використання ресурсів у реальному часі.

У верхній частині зазвичай можна побачити:

- Час роботи системи.
- Load Average.
- Кількість процесів.
- Використання CPU.
- Використання пам’яті.
- Список процесів.

Корисні клавіші в `top`:

- `q` — вихід.
- `P` — сортування за використанням CPU.
- `M` — сортування за використанням пам’яті.
- `1` — показати CPU окремо, якщо підтримується.

### 12.2. Команда `htop`

    htop

`htop` — інтерактивний переглядач процесів із зручнішим інтерфейсом, ніж `top`.

Якщо команда відсутня, в Ubuntu можна встановити її:

    sudo apt update
    sudo apt install htop

### 12.3. Команда `vmstat`

`vmstat` показує статистику процесів, пам’яті, swap, введення-виведення та CPU.

    vmstat

Оновлювати статистику кожні дві секунди:

    vmstat 2

Показати п’ять оновлень із двосекундним інтервалом:

    vmstat 2 5

Основні поля залежать від формату виводу, але зазвичай включають:

- `r` — процеси, готові до виконання.
- `b` — процеси в очікуванні.
- `swpd` — використаний swap.
- `free` — вільна пам’ять.
- `si`, `so` — переміщення даних через swap.
- `us`, `sy`, `id`, `wa` — показники часу CPU.

Перший рядок статистики `vmstat` часто відображає середні значення з моменту запуску системи, а наступні — показники за відповідні інтервали.

## 13. Інформація про диски та файлові системи

Хоча докладніше диски розглядаються в темі Storage and Archives, кілька команд корисні і для загального огляду системи.

### 13.1. Команда `lsblk`

    lsblk

Показує блокові пристрої: диски, розділи та деякі інші пристрої зберігання.

Зручний формат:

    lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

Основні поля:

- `NAME` — назва пристрою.
- `SIZE` — розмір.
- `TYPE` — тип пристрою.
- `FSTYPE` — тип файлової системи, якщо визначений.
- `MOUNTPOINTS` — точки монтування.

### 13.2. Команда `df`

    df -h

Показує використання простору змонтованими файловими системами.

### 13.3. Команда `du`

    du -sh ~/projects

Показує приблизний обсяг простору, зайнятого каталогом `~/projects`.

**Різниця:**

- `lsblk` — які блокові пристрої та розділи є в системі.
- `df` — скільки місця зайнято й доступно у файлових системах.
- `du` — скільки місця займають файли й каталоги.

## 16. Інформація про завантаження системи

### 16.1. Команда `systemd-analyze`

У системах із systemd можна переглянути загальний час завантаження:

    systemd-analyze

Приклад:

    Startup finished in 3.2s (firmware) + 2.1s (loader) + 4.8s (kernel) + 12.0s (userspace) = 22.1s

Це умовний приклад. На різних системах формат і доступність окремих показників відрізняються.

Переглянути служби, які найбільше впливають на час запуску:

    systemd-analyze blame

Переглянути критичний ланцюжок завантаження:

    systemd-analyze critical-chain

**Важливо:** `systemd-analyze blame` показує час запуску окремих служб, але це не завжди означає, що служба затримує завантаження на весь наведений час. Частина служб запускається паралельно.

### 16.2. Журнали поточного запуску

    journalctl -b

Показати повідомлення поточного завантаження з пріоритетом помилки:

    journalctl -b -p err

Показати попереднє завантаження, якщо його журнали збережені:

    journalctl -b -1

Ці команди корисні для дослідження проблем, які виникають під час запуску системи.

## 18. Практичний приклад: короткий системний звіт

Можна об’єднати декілька команд у послідовність, щоб отримати короткий звіт.

    echo "=== OPERATING SYSTEM ==="
    cat /etc/os-release

    echo
    echo "=== KERNEL ==="
    uname -r

    echo
    echo "=== ARCHITECTURE ==="
    uname -m

    echo
    echo "=== CPU ==="
    lscpu

    echo
    echo "=== MEMORY ==="
    free -h

    echo
    echo "=== UPTIME ==="
    uptime

    echo
    echo "=== STORAGE ==="
    lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS

Це приклад для термінала Bash. Команди виконуються послідовно, а `echo` додає заголовки для зручного читання.

### Варіант: короткий звіт без зайвих деталей

    echo "OS: $(. /etc/os-release && echo "$PRETTY_NAME")"
    echo "Kernel: $(uname -r)"
    echo "Architecture: $(uname -m)"
    echo "CPU units available: $(nproc)"
    echo
    free -h
    echo
    uptime

Тут використовуються:

- `$(...)` — підстановка результату команди.
- `.` — читання змінних із файлу в поточному Bash-середовищі.
- `&&` — виконання наступної команди, якщо попередня завершилася успішно.

Файл `/etc/os-release` призначений для опису дистрибутива; його можна читати таким способом у звичайному навчальному сценарії.

## 20. Типові помилки

### Помилка 1. Плутати версію ядра та версію Ubuntu

    uname -r

Ця команда показує версію ядра, а не повну версію дистрибутива.

Для дистрибутива використовуй:

    cat /etc/os-release

### Помилка 2. Вважати, що вся пам’ять у `used` недоступна

Linux використовує вільну RAM для кешування.

Для оцінки пам’яті, доступної програмам, дивись:

    free -h

Особливу увагу звертай на колонку `available`.

### Помилка 3. Плутати Load Average із відсотком CPU

Load Average — не відсоток завантаження процесора.

Для моніторингу CPU використовуй:

    top

Або:

    htop

### Помилка 4. Вважати, що `nproc` завжди дорівнює кількості фізичних ядер

`nproc` показує кількість процесорних одиниць, доступних процесу. Це не обов’язково кількість фізичних ядер.

Для докладнішого аналізу:

    lscpu

### Помилка 5. Використовувати `sudo` для кожної команди

Більшість команд перегляду системної інформації працюють без адміністративних прав.

Починай зі звичайного користувача. Використовуй `sudo` лише за потреби.

### Помилка 6. Вважати, що всі команди доступні на кожному дистрибутиві

Наприклад, `lshw`, `htop` або `dmidecode` можуть бути не встановлені.

Перевір наявність команди:

    command -v lshw

Якщо команда нічого не вивела, найімовірніше, виконуваний файл не знайдений у `PATH`.

### Помилка 7. Очікувати однакових результатів на фізичному комп’ютері та у віртуальній машині

Віртуальні машини, контейнери та фізичні комп’ютери можуть показувати різні значення CPU, пам’яті, пристроїв і системної інформації.

**Головний принцип:** спочатку збери факти про систему, потім зістав їх між собою і лише після цього роби висновки про причину проблеми.
