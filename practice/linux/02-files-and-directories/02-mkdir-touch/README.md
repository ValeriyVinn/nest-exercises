# 02. mkdir, touch

`mkdir` та `touch` — це основні команди Linux для створення директорій і файлів.

Вони використовуються під час організації файлової структури, створення навчальних матеріалів, налаштування проєктів і роботи з кодом у Bash-терміналі.

Основні команди:

    mkdir     — створити директорію
    touch     — створити порожній файл або оновити часові мітки наявного файлу

Також важливо знати:

    mkdir -p  — створити вкладені директорії разом із батьківськими
    mkdir -v  — показати повідомлення про створення директорії
    touch -c  — не створювати файл, якщо він не існує
    touch -a  — оновити час останнього доступу
    touch -m  — оновити час останньої модифікації
    touch -t  — встановити часові мітки за вказаним часом

## Що потрібно пам'ятати

• `mkdir` створює директорії.

• `touch` створює порожній файл, якщо він не існує.

• Якщо файл уже існує, звичайний `touch` не стирає його вміст.

• `mkdir name` створює директорію в поточному робочому каталозі.

• `mkdir -p path/to/dir` дозволяє створити відразу декілька рівнів вкладених директорій.

• Без `-p` команда `mkdir` не створить вкладену директорію, якщо її батьківська директорія не існує.

• `touch file.txt` створює порожній файл або оновлює часові мітки наявного файлу.

• `touch` не є текстовим редактором і не призначений для запису вмісту у файл.

• Для створення кількох файлів однією командою можна передати декілька імен.

• Для створення декількох директорій можна передати декілька аргументів команді `mkdir`.

• Шляхи можуть бути абсолютними або відносними.

• Якщо шлях не починається з `/`, він зазвичай інтерпретується відносно поточної робочої директорії.

• Linux розрізняє великі та малі літери в іменах.

• `mkdir -p` зручно використовувати в навчальних проєктах, скриптах і під час автоматизованого створення структури каталогів.

• `touch` змінює часові мітки, навіть якщо файл уже містить дані. Саме тому не слід сприймати його лише як команду створення файлів.

• Права доступу до нових об'єктів залежать від параметрів команди, системного `umask` і правил файлової системи.

# mkdir

`mkdir` — make directory.

Команда створює директорію.

Синтаксис:

    mkdir [OPTIONS] DIRECTORY

Де:

    OPTIONS     — необов'язкові параметри
    DIRECTORY   — ім'я або шлях директорії, яку потрібно створити

Наприклад:

    mkdir practice

Команда створить директорію `practice` у поточній робочій директорії.

Перевірити результат:

    ls

Або:

    ls -l

Щоб дізнатися поточне розташування:

    pwd

---

# Створення однієї директорії

Приклад:

    mkdir linux

Після виконання команди в поточній директорії з'явиться каталог:

    linux/

Перевірка:

    ls

Можливий результат:

    linux

Якщо директорія з такою назвою вже існує, команда зазвичай повідомить про помилку.

Наприклад:

    mkdir linux

Можливе повідомлення:

    mkdir: cannot create directory 'linux': File exists

Це означає, що створити ще одну директорію з тим самим ім'ям у цьому місці не вдалося.

---

# Створення кількох директорій

Команда `mkdir` може приймати декілька аргументів.

Наприклад:

    mkdir html css javascript

Буде створено три окремі директорії:

    html/
    css/
    javascript/

Інший приклад:

    mkdir 01-basics 02-arrays 03-functions

Результат:

    01-basics/
    02-arrays/
    03-functions/

Це зручно під час організації навчальних матеріалів.

Важливо: усі три директорії створюються в поточному каталозі, якщо для них не вказано інші шляхи.

---

# mkdir -p

`mkdir -p` — створення директорій разом із відсутніми батьківськими директоріями.

Параметр `-p` означає `parents`.

Синтаксис:

    mkdir -p PATH

Наприклад:

    mkdir -p practice/linux/02-files-and-directories/02-mkdir-touch

Якщо директорій `practice`, `linux`, `02-files-and-directories` або `02-mkdir-touch` ще немає, команда створить необхідні рівні.

Приблизна структура:

    practice/
    └── linux/
        └── 02-files-and-directories/
            └── 02-mkdir-touch/

Це одна з найкорисніших можливостей `mkdir`.

## mkdir без -p

Припустимо, директорії `courses` не існує.

Команда:

    mkdir courses/linux

не зможе створити `linux`, якщо батьківська директорія `courses` відсутня.

Можлива помилка:

    mkdir: cannot create directory 'courses/linux': No such file or directory

## mkdir з -p

Команда:

    mkdir -p courses/linux

створить:

    courses/
    └── linux/

Параметр `-p` дозволяє створювати вкладені директорії за один виклик.

---

# mkdir -p та наявні директорії

`mkdir -p` зручна тим, що не повідомляє про помилку лише через те, що потрібна директорія вже існує.

Наприклад:

    mkdir -p practice/linux

Якщо шлях уже створено, команда зазвичай завершиться без помилки.

Це корисно у скриптах, коли потрібно гарантувати існування певної структури каталогів.

Наприклад:

    mkdir -p logs
    mkdir -p uploads
    mkdir -p backups

Повторне виконання цих команд не призведе до помилки лише через наявність відповідних директорій.

Важливо: це не означає, що `mkdir -p` виправляє будь-яку проблему з шляхом. Помилки прав доступу, конфлікти з файлами та інші проблеми все одно можливі.

---

# mkdir -v

`-v` — verbose.

Параметр показує повідомлення про створення директорій.

Приклад:

    mkdir -v projects

Можливий результат:

    mkdir: created directory 'projects'

Для вкладеної структури:

    mkdir -pv courses/linux/javascript

Команда покаже, які директорії було створено.

Наприклад:

    mkdir: created directory 'courses'
    mkdir: created directory 'courses/linux'
    mkdir: created directory 'courses/linux/javascript'

Фактичний вивід залежить від того, які директорії вже існували.

`-v` корисний для навчання, перевірки результатів і налагодження Bash-скриптів.

---

# mkdir -m

`-m` — mode.

Дозволяє задати права доступу для нової директорії.

Синтаксис:

    mkdir -m MODE DIRECTORY

Наприклад:

    mkdir -m 755 public

Права `755` у звичайній системі Unix означають:

    власник — читання, запис, виконання
    група   — читання, виконання
    інші    — читання, виконання

Детально права доступу розглядатимуться в розділі:

    05-permissions-and-ownership

Важливо: для `mkdir -m` заданий режим застосовується до створюваних директорій, але реальний результат залежить від підтримки файлової системи та особливостей системи. Не слід плутати цей параметр із `umask`, який впливає на звичайне створення об'єктів.

---

# mkdir з абсолютним шляхом

Абсолютний шлях починається з `/`.

Наприклад:

    mkdir -p /home/taubu/projects/linux-practice

Команда створить директорію за вказаним абсолютним шляхом, якщо це дозволяють права доступу.

Можна створити структуру всередині домашньої директорії:

    mkdir -p ~/projects/linux-practice

Символ `~` розгортається Bash до домашньої директорії користувача.

Для поточного користувача це може бути:

    /home/taubu/projects/linux-practice

Перевірка:

    ls ~/projects

---

# mkdir з відносним шляхом

Відносний шлях визначається від поточної робочої директорії.

Наприклад, якщо ти перебуваєш у:

    /home/taubu/projects/nest-exercises

Команда:

    mkdir practice/linux-test

створить директорію:

    /home/taubu/projects/nest-exercises/practice/linux-test

за умови, що `practice` вже існує.

Якщо батьківського каталогу немає, можна використати:

    mkdir -p practice/linux-test

Відносні шляхи особливо зручні під час роботи всередині Git-репозиторію.

# Створення структури навчального курсу

Припустимо, потрібно створити директорії Linux-курсу:

    practice/
    └── linux/
        ├── 01-linux-fundamentals/
        ├── 02-files-and-directories/
        │   ├── 01-pwd-ls-cd/
        │   ├── 02-mkdir-touch/
        │   └── 03-cp-mv-rm/
        └── 03-file-content-and-search/

Можна створити структуру за допомогою однієї команди:

    mkdir -p practice/linux/01-linux-fundamentals \
        practice/linux/02-files-and-directories/01-pwd-ls-cd \
        practice/linux/02-files-and-directories/02-mkdir-touch \
        practice/linux/02-files-and-directories/03-cp-mv-rm \
        practice/linux/03-file-content-and-search

Зворотна скісна риска `\` наприкінці рядка дозволяє продовжити команду на наступному рядку в Bash.

Цей варіант корисний для читабельності.

Але якщо ти вже перебуваєш у директорії `practice/linux`, достатньо:

    mkdir -p 01-linux-fundamentals \
        02-files-and-directories/01-pwd-ls-cd \
        02-files-and-directories/02-mkdir-touch \
        02-files-and-directories/03-cp-mv-rm \
        03-file-content-and-search

Перед створенням структури завжди перевіряй:

    pwd

Це допомагає уникнути випадкового створення каталогів не в тому місці.

# Brace Expansion

Brace expansion — розгортання фігурних дужок у Bash.

Цей механізм дозволяє створювати групи імен без ручного повторення спільної частини.

Наприклад:

    mkdir -p practice/linux/{01-linux-fundamentals,02-files-and-directories,03-file-content-and-search}

Bash розгорне вираз приблизно в такі шляхи:

    practice/linux/01-linux-fundamentals
    practice/linux/02-files-and-directories
    practice/linux/03-file-content-and-search

Інший приклад:

    mkdir -p practice/linux/02-files-and-directories/{01-pwd-ls-cd,02-mkdir-touch,03-cp-mv-rm}

Результат:

    practice/linux/02-files-and-directories/
    ├── 01-pwd-ls-cd/
    ├── 02-mkdir-touch/
    └── 03-cp-mv-rm/

Можна також використовувати діапазони:

    mkdir -p lesson-{01..05}

Буде створено:

    lesson-01/
    lesson-02/
    lesson-03/
    lesson-04/
    lesson-05/

Ще один приклад:

    mkdir -p section-{1..3}/examples

Створить:

    section-1/
    ├── examples/
    section-2/
    ├── examples/
    section-3/
    └── examples/

Brace expansion виконується оболонкою Bash до запуску команди `mkdir`.

Це зручний інструмент, але на початковому етапі можна спокійно створювати директорії звичайними командами.

# touch

`touch` — команда для створення порожнього файлу, якщо він не існує, або оновлення його часових міток, якщо файл уже існує.

Синтаксис:

    touch [OPTIONS] FILE

Приклад:

    touch README.md

Якщо `README.md` не існує, буде створено порожній файл.

Перевірка:

    ls -l

Можливий результат:

    -rw-r--r-- 1 taubu taubu 0 Oct 16 18:00 README.md

Розмір `0` означає, що файл порожній.

Важливо: `touch` не додає текст у файл.

Щоб записати вміст, використовують текстовий редактор або інші інструменти.

Наприклад:

    code README.md

Якщо встановлено VS Code і команда `code` доступна в терміналі, файл відкриється в редакторі.

---

# Створення одного файлу

Приклад:

    touch notes.txt

Буде створено порожній файл:

    notes.txt

Інший приклад:

    touch README.md

Або:

    touch app.js

Можна створювати файли різних типів:

    touch index.html
    touch styles.css
    touch script.js

Команда не перевіряє, чи відповідає розширення вмісту файлу. Розширення є частиною імені, а не гарантією формату.

---

# Створення кількох файлів

`touch` може приймати декілька імен за один виклик.

Наприклад:

    touch README.md index.html styles.css script.js

Буде створено чотири порожні файли:

    README.md
    index.html
    styles.css
    script.js

Це зручно для швидкого створення базової структури навчального прикладу.

Наприклад, для HTML/CSS/JavaScript:

    mkdir -p practice/demo

    touch practice/demo/index.html \
        practice/demo/styles.css \
        practice/demo/script.js

Результат:

    practice/
    └── demo/
        ├── index.html
        ├── styles.css
        └── script.js

---

# touch з відносним шляхом

Припустимо, ти перебуваєш у директорії:

    ~/projects/nest-exercises/practice/linux

Команда:

    touch README.md

створить файл:

    ~/projects/nest-exercises/practice/linux/README.md

А команда:

    touch 02-files-and-directories/README.md

створить файл:

    ~/projects/nest-exercises/practice/linux/02-files-and-directories/README.md

за умови, що директорія `02-files-and-directories` уже існує.

Якщо батьківська директорія не існує, `touch` не створить її автоматично.

Наприклад:

    touch new-course/README.md

не спрацює, якщо `new-course` ще не існує.

Правильний порядок:

    mkdir -p new-course
    touch new-course/README.md

Або однією командою:

    mkdir -p new-course && touch new-course/README.md

Оператор `&&` означає, що друга команда виконується лише тоді, коли перша завершилася успішно.

---

# touch та наявний файл

Якщо файл уже існує, команда:

    touch README.md

не видаляє і не перезаписує його текст.

Вона оновлює часові мітки відповідно до поведінки `touch`.

Наприклад, файл містить:

    # Linux Notes

    Це мої навчальні нотатки.

Після:

    touch README.md

текст залишиться незмінним.

Однак змінитися може час останнього доступу (`atime`) та час останньої модифікації (`mtime`).

Тому не варто використовувати `touch` бездумно, якщо часові мітки файлів мають значення для системи складання, синхронізації чи автоматизації.

---

# touch -c

`-c` — no create.

Цей параметр забороняє створювати файл, якщо він не існує.

Приклад:

    touch -c missing.txt

Якщо `missing.txt` не існує, команда не створить його.

Якщо файл уже існує, `touch -c` усе ще може оновити його часові мітки.

Це корисно, коли потрібно оновлювати часові мітки тільки наявних файлів, не створюючи нових.

---

# touch -a

`-a` — змінити час останнього доступу (`atime`).

Приклад:

    touch -a README.md

Команда оновлює час останнього доступу до файлу, не призначаючи навмисно новий час модифікації.

Фактична поведінка часових міток може залежати від файлової системи та її параметрів монтування.

Для початкового рівня достатньо пам'ятати:

    touch -a FILE

— оновити access time наявного файлу.

---

# touch -m

`-m` — змінити час останньої модифікації (`mtime`).

Приклад:

    touch -m README.md

Команда оновлює час останньої модифікації файлу.

Це не означає, що його текстовий вміст змінюється.

Наприклад:

    touch -m package.json

може оновити `mtime` файлу `package.json`, хоча його JSON-вміст залишиться тим самим.

У деяких процесах автоматичного складання та синхронізації час модифікації використовується для визначення того, чи потрібно повторно обробляти файл.

---

# touch -t

`-t` дозволяє встановити часові мітки за заданим часом.

Синтаксис:

    touch -t [[CC]YY]MMDDhhmm[.ss] FILE

Наприклад:

    touch -t 202610161200 README.md

Цей запис задає дату й час 16 жовтня 2026 року, 12:00 за локальним часом, якщо формат інтерпретується стандартним GNU `touch`.

Тут:

    2026 — рік
    10   — місяць
    16   — день
    12   — година
    00   — хвилини

Можна вказати секунди:

    touch -t 202610161200.30 README.md

Тоді час буде 12:00:30.

Формат параметра `-t` не є найзручнішим для щоденного використання, тому на початковому етапі достатньо знати про його існування.

---

# Створення директорії та файлу разом

Часто потрібно створити директорію та файл усередині неї.

Наприклад:

    mkdir notes
    touch notes/README.md

Результат:

    notes/
    └── README.md

Якщо директорія може ще не існувати:

    mkdir -p notes
    touch notes/README.md

Або:

    mkdir -p notes && touch notes/README.md

У другому варіанті `touch` виконається лише після успішного створення директорії.

# Створення вкладеної структури з файлами

Припустимо, потрібно створити структуру:

    linux/
    └── 02-files-and-directories/
        └── 02-mkdir-touch/
            ├── README.md
            ├── examples.txt
            └── practice.sh

Команди:

    mkdir -p linux/02-files-and-directories/02-mkdir-touch

    touch linux/02-files-and-directories/02-mkdir-touch/README.md

    touch linux/02-files-and-directories/02-mkdir-touch/examples.txt

    touch linux/02-files-and-directories/02-mkdir-touch/{README.md,examples.txt,practice.sh}

Тут Bash спочатку розгортає фігурні дужки, а потім запускає `touch` з трьома шляхами.

# mkdir та touch: відмінності

| Команда | Призначення |
|---|---|
| `mkdir notes` | Створити директорію |
| `mkdir -p a/b/c` | Створити вкладені директорії |
| `mkdir -v notes` | Показати повідомлення про створення |
| `touch notes.txt` | Створити файл або оновити часові мітки |
| `touch a.txt b.txt` | Створити або оновити два файли |
| `touch -c missing.txt` | Не створювати відсутній файл |
| `touch -a notes.txt` | Оновити час останнього доступу |
| `touch -m notes.txt` | Оновити час останньої модифікації |

Головна відмінність:

    mkdir → створення директорій
    touch → створення файлів та оновлення часових міток

# Безпека та обережність

`mkdir` і `touch` зазвичай не є небезпечними командами, але важливо розуміти їхню поведінку.

## 1. Перевіряй поточну директорію

Перед створенням структури виконай:

    pwd

Це допомагає переконатися, що файли створюються в потрібному місці.

## 2. Не плутай директорію та файл

Команда:

    mkdir README.md

створить директорію з назвою `README.md`, а не текстовий файл.

Для створення файлу:

    touch README.md

## 3. Не очікуй, що touch створить батьківські директорії

Команда:

    touch a/b/c.txt

не створить директорії `a` і `b`.

Спочатку:

    mkdir -p a/b

Потім:

    touch a/b/c.txt

## 4. Не використовуй touch для запису тексту

Команда:

    touch README.md

не додасть до файлу текст.

Для редагування використовуй VS Code або інший текстовий редактор.

## 5. Пам'ятай про часові мітки

Якщо файл уже існує, `touch` оновлює часові мітки.

Не слід вважати його командою, яка нічого не змінює в наявному файлі.

## 6. Не створюй зайві директорії через помилки в шляхах

Наприклад:

    mkdir -p ~/projects/nest-exercises/practice/linuxx

Створить директорію `linuxx`, якщо це дозволено, хоча ти міг мати на увазі `linux`.

Перевіряй імена та шляхи.

# Типові помилки

## Помилка 1 — створення вкладеної директорії без -p

    mkdir courses/linux

Якщо `courses` не існує, команда завершиться помилкою.

Правильно:

    mkdir -p courses/linux

---

## Помилка 2 — повторне створення директорії

    mkdir notes

Якщо `notes` уже існує, команда повідомить про помилку.

Якщо потрібно, щоб наявність директорії не спричиняла помилку:

    mkdir -p notes

---

## Помилка 3 — спроба створити файл у відсутній директорії

    touch notes/README.md

Якщо `notes` не існує, команда не зможе створити файл.

Правильно:

    mkdir -p notes
    touch notes/README.md

---

## Помилка 4 — очікування, що touch очистить файл

    touch README.md

Якщо файл уже містить текст, його вміст не буде очищено.

`touch` оновлює часові мітки, а не очищає файл.

---

## Помилка 5 — плутанина між mkdir і touch

    mkdir index.html

створює директорію.

    touch index.html

створює звичайний файл, якщо він не існує.

Назва `index.html` сама по собі не визначає, який тип об'єкта буде створено: це визначає команда.

---

## Помилка 6 — неправильний відносний шлях

    touch linux/README.md

Команда створить файл відносно поточної директорії.

Якщо ти перебуваєш не там, де очікував, файл може з'явитися в іншому місці.

Перевір:

    pwd

---

## Помилка 7 — плутанина між регістром символів

    touch Readme.md
    touch README.md

Це можуть бути два різні файли.

Linux розрізняє великі та малі літери.

---

## Помилка 8 — забуті лапки в іменах із пробілами

Для створення директорії `My Notes`:

    mkdir "My Notes"

Для створення файлу `My Notes.md`:

    touch "My Notes.md"

---

## Помилка 9 — очікування, що mkdir створить файл

    mkdir notes.txt

Це створює директорію `notes.txt`.

Якщо потрібен файл:

    touch notes.txt

---

## Помилка 10 — неправильне розуміння mkdir -p

Команда:

    mkdir -p a/b/c

створює директорії, якщо вони відсутні.

Вона не створює файли всередині цих директорій.

Для файлу:

    touch a/b/c/README.md

# Головне

• `mkdir` створює директорії.

• `touch` створює порожні файли, якщо вони ще не існують.

• Якщо файл уже існує, `touch` не стирає його вміст.

• `mkdir -p` дозволяє створювати вкладені директорії за один виклик.

• `mkdir -v` показує повідомлення про створення директорій.

• `mkdir -m` дозволяє задати права доступу під час створення директорії.

• `touch -c` не створює файл, якщо він відсутній.

• `touch -a` та `touch -m` дозволяють окремо оновлювати часові мітки.

• Абсолютний шлях починається з `/`, а відносний залежить від поточної робочої директорії.

• `mkdir` не створює текстові файли, а `touch` не створює відсутні батьківські директорії.

• Для створення структури спочатку можна використати `mkdir -p`, а потім `touch`.

• Bash brace expansion допомагає швидко створювати групи директорій і файлів.

• Перед створенням об'єктів варто перевірити поточну директорію через `pwd`.

• Після створення корисно перевірити результат за допомогою `ls -la`.

• `mkdir` і `touch` змінюють файлову систему, але не додають файли до Git автоматично.

• Основна модель роботи:

    pwd
      ↓
    перевірити поточну директорію
      ↓
    mkdir -p
      ↓
    створити потрібну структуру каталогів
      ↓
    touch
      ↓
    створити порожні файли
      ↓
    ls -la
      ↓
    перевірити результат
      ↓
    редактор коду
      ↓
    наповнити файли вмістом

• Ці команди є основою організації файлів і директорій у Linux. Їх варто впевнено опанувати перед переходом до копіювання, переміщення та видалення файлів у наступній темі `03-cp-mv-rm`.
