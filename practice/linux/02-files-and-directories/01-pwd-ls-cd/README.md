# 01. pwd, ls, cd

`pwd`, `ls` та `cd` — це основні команди Linux для навігації файловою системою.

Вони дозволяють визначити поточну директорію, переглядати файли та каталоги, переходити між ними й орієнтуватися у структурі файлової системи.

Ці команди використовуються практично щодня під час роботи в Linux, Bash-терміналі, VS Code, Git, Node.js та інших інструментах розробника.

Основні команди:

    pwd     — вивести поточну робочу директорію
    ls      — переглянути вміст директорії
    cd      — перейти до іншої директорії

Також важливо знати:

    .       — поточна директорія
    ..      — батьківська директорія
    ~       — домашня директорія поточного користувача
    /       — коренева директорія файлової системи
    -       — попередня робоча директорія для cd
    *       — шаблон, який відповідає послідовності символів
    /       — роздільник компонентів шляху

## Що потрібно пам'ятати

• `pwd` показує абсолютний шлях до поточної робочої директорії.

• `ls` виводить список файлів і директорій.

• `cd` змінює поточну робочу директорію.

• Linux використовує єдину ієрархію файлової системи, яка починається з `/`.

• `/` — корінь усієї файлової системи, а не домашня директорія користувача.

• `~` позначає домашню директорію поточного користувача.

• `.` позначає поточну директорію.

• `..` позначає батьківську директорію.

• `cd ..` переходить на один рівень вище.

• `cd ../..` переходить на два рівні вище.

• Абсолютний шлях починається з `/`.

• Відносний шлях обчислюється від поточної робочої директорії.

• `ls -l` показує детальну інформацію про об'єкти.

• `ls -a` показує також приховані файли.

• `ls -la` поєднує обидва варіанти.

• `cd -` повертає до попередньої робочої директорії.

• Linux розрізняє великі та малі літери в іменах файлів і директорій.

• Натискання `Tab` допомагає доповнювати імена файлів і директорій.

• `pwd` показує поточну директорію оболонки, а не обов'язково директорію, відкриту у графічному файловому менеджері.

# Linux Filesystem

Файлова система Linux організована у вигляді дерева.

На відміну від Windows, де зазвичай використовуються окремі літери дисків, наприклад `C:\` або `D:\`, у Linux файлові системи об'єднуються в єдину ієрархію, яка починається з кореня `/`.

Приклад структури:

    /
    ├── bin
    ├── boot
    ├── dev
    ├── etc
    ├── home
    │   ├── taubu
    │   │   ├── projects
    │   │   │   ├── nest-exercises
    │   │   │   └── next-exercises
    │   │   ├── Downloads
    │   │   └── Documents
    │   └── another-user
    ├── media
    ├── mnt
    ├── opt
    ├── proc
    ├── root
    ├── run
    ├── srv
    ├── tmp
    ├── usr
    └── var

Це приблизна структура. Конкретний набір директорій і спосіб їх організації можуть відрізнятися залежно від дистрибутива та налаштувань системи.

Основні директорії:

    /           — коренева директорія файлової системи
    /home       — домашні директорії звичайних користувачів
    /root       — домашня директорія користувача root
    /etc        — системні конфігураційні файли
    /usr        — більшість встановлених програм, бібліотек і ресурсів
    /var        — змінні дані, журнали, кеші та інші системні дані
    /tmp        — тимчасові файли
    /dev        — файли пристроїв
    /proc       — віртуальна файлова система з інформацією про процеси та ядро
    /sys        — інформація про пристрої та ядро
    /boot       — файли, необхідні для завантаження системи
    /media      — типове місце автоматичного монтування знімних носіїв
    /mnt        — типове місце для тимчасового монтування файлових систем
    /opt        — додаткове програмне забезпечення

Не потрібно одразу запам'ятовувати всі директорії. Для початку достатньо розуміти структуру `/`, `/home`, `/etc`, `/usr`, `/var` і `/tmp`.

# pwd

`pwd` — print working directory.

Команда показує поточну робочу директорію.

Синтаксис:

    pwd

Приклад:

    taubu@taubu-lap:~$ pwd
    /home/taubu

Це означає, що поточна робоча директорія:

    /home/taubu

Якщо перейти до проєктів:

    cd ~/projects

і виконати:

    pwd

отримаємо приблизно:

    /home/taubu/projects

Якщо перейти до репозиторію:

    cd ~/projects/nest-exercises

команда:

    pwd

покаже:

    /home/taubu/projects/nest-exercises

---

## Навіщо потрібна pwd

`pwd` особливо корисна, коли:

- відкрито кілька терміналів;
- незрозуміло, у якій директорії ти перебуваєш;
- потрібно перевірити шлях перед видаленням файлів;
- потрібно запустити програму з правильної директорії;
- потрібно виконати Git-команди в конкретному репозиторії;
- потрібно знайти шлях до файлу або проєкту.

Практичний приклад:

    cd ~/projects/nest-exercises/practice/linux

    pwd

Результат:

    /home/taubu/projects/nest-exercises/practice/linux

Тепер можна перевірити вміст директорії:

    ls

---

## pwd -L та pwd -P

Існують два варіанти виведення шляху.

### pwd -L

Показує логічний шлях, який зберігає оболонка. Якщо шлях містить символічні посилання, вони можуть залишатися у виведеному шляху.

    pwd -L

### pwd -P

Показує фізичний шлях, розкриваючи символічні посилання в компонентах шляху.

    pwd -P

Для звичайної навігації зазвичай достатньо:

    pwd

# ls

`ls` — list.

Команда показує вміст директорії.

Синтаксис:

    ls [OPTIONS] [PATH]

Де:

    OPTIONS — параметри команди
    PATH    — директорія або шлях, вміст якого потрібно переглянути

Приклад:

    ls

Можливий результат:

    Desktop  Documents  Downloads  Music  Pictures  projects

Команда без аргументів показує вміст поточної робочої директорії.

---

## ls із зазначенням директорії

Можна переглядати вміст будь-якої директорії, не переходячи до неї.

Наприклад:

    ls ~/projects

Переглянути вміст репозиторію:

    ls ~/projects/nest-exercises

Переглянути вміст каталогу Linux:

    ls ~/projects/nest-exercises/practice/linux

Важливо:

    ls PATH

не змінює поточну робочу директорію.

Для переходу потрібно використовувати `cd`.

---

# ls -l

`ls -l` — long listing format.

Показує розширену інформацію про файли та директорії.

Приклад:

    ls -l

Можливий результат:

    drwxr-xr-x  3 taubu taubu 4096 Oct 16 17:00 projects
    drwxr-xr-x  2 taubu taubu 4096 Oct 16 16:30 Documents
    -rw-r--r--  1 taubu taubu  250 Oct 16 17:10 notes.txt

Розглянемо структуру рядка:

    -rw-r--r--  1 taubu taubu  250 Oct 16 17:10 notes.txt
    │           │ │     │      │   │           │
    │           │ │     │      │   │           └── ім'я
    │           │ │     │      │   └── дата зміни
    │           │ │     │      └── розмір у байтах
    │           │ │     └── група-власник
    │           │ └── власник
    │           └── кількість hard links
    └── тип об'єкта та права доступу

Детально права доступу розглядатимуться в розділі:

    05-permissions-and-ownership

Зараз достатньо розуміти, що `ls -l` показує більше інформації, ніж звичайний `ls`.

---

# ls -a

`ls -a` — all.

Показує всі записи директорії, включно з прихованими файлами.

У Linux імена, які починаються з крапки, зазвичай вважаються прихованими.

Наприклад:

    ls -a

Можливий результат:

    .
    ..
    .bashrc
    .profile
    .gitconfig
    .ssh
    Documents
    Downloads
    projects

Пояснення:

    .       — поточна директорія
    ..      — батьківська директорія
    .bashrc — файл конфігурації Bash
    .profile — файл налаштування середовища користувача
    .ssh    — директорія конфігурації SSH та ключів
    .gitconfig — глобальна конфігурація Git

Не всі приховані файли обов'язково присутні в кожній системі.

---

# ls -la

`ls -la` поєднує два параметри:

    -l — long listing
    -a — all

Приклад:

    ls -la

Команда показує детальну інформацію про звичайні та приховані файли.

Це одна з найкорисніших команд для перевірки структури проєкту.

Наприклад, у репозиторії можна побачити:

    .
    ..
    .git
    .gitignore
    .vscode
    README.md
    package.json
    practice
    src

Це допомагає перевірити наявність:

    .git       — службові дані Git-репозиторію
    .gitignore — правила ігнорування файлів Git
    package.json — конфігурація Node.js-проєкту
    README.md  — документація

Зверни увагу: звичайний `ls` не показує приховані записи.

# Інші корисні параметри ls

## ls -h

Сам по собі `-h` зазвичай не використовується для зручного перегляду розмірів у списку. Найчастіше його поєднують із `-l`.

    ls -lh

Розмір файлів показується у зручнішому вигляді:

    1.2K
    4.0K
    15M

Приклад:

    ls -lh

---

## ls -R

`-R` — recursive.

Показує вміст директорії та вкладених директорій рекурсивно.

    ls -R

Наприклад:

    ls -R practice/linux

Це може бути корисно для огляду невеликої структури каталогів.

Але в великих проєктах результат може бути дуже довгим.

---

## ls -t

Сортує записи за часом останньої зміни, починаючи з найновіших.

    ls -t

Зручно, коли потрібно швидко знайти файли, які нещодавно змінювалися.

---

## ls -r

Змінює порядок сортування на зворотний.

    ls -r

У поєднанні з `-t`:

    ls -tr

зазвичай показує найстаріші записи першими, а найновіші — останніми.

---

## ls -S

Сортує файли за розміром, від найбільших до найменших.

    ls -S

Для зручнішого відображення розмірів:

    ls -lhS

---

## ls -d

Показує саму директорію як об'єкт, а не її вміст.

    ls -d */

Наприклад, команда:

    ls -d */

покаже піддиректорії поточного каталогу, використовуючи шаблон `*/`.

Для прихованих директорій потрібен окремий шаблон або інший підхід.

---

## ls --color=auto

У багатьох дистрибутивах Linux кольори виводу налаштовуються автоматично.

Можна явно вказати:

    ls --color=auto

Кольори можуть допомагати розрізняти типи об'єктів, але їхнє значення залежить від конфігурації термінала.

---

# Комбінування параметрів ls

Параметри можна комбінувати.

Приклади:

    ls -la
    ls -lh
    ls -lah
    ls -lt
    ls -ltr
    ls -lhS
    ls -R

Найважливіші команди для щоденної роботи:

    ls       — звичайний список
    ls -l    — детальний список
    ls -a    — включно з прихованими записами
    ls -la   — детальний список із прихованими записами
    ls -lh   — детальний список зі зручними розмірами
    ls -lt   — сортування за часом зміни

# cd

`cd` — change directory.

Команда змінює поточну робочу директорію оболонки.

Синтаксис:

    cd [PATH]

Приклад:

    cd ~/projects

Після цього поточною робочою директорією стане:

    /home/taubu/projects

Перевірити можна командою:

    pwd

---

# cd ~

`~` позначає домашню директорію поточного користувача.

Наприклад, для користувача `taubu`:

    ~

відповідає:

    /home/taubu

Команди:

    cd ~
    cd
    cd "$HOME"

у звичайному Bash-контексті без додаткових аргументів переводять до домашньої директорії.

Поточну домашню директорію можна переглянути так:

    echo "$HOME"

Можливий результат:

    /home/taubu

`$HOME` — змінна середовища, у якій зберігається шлях до домашньої директорії користувача.

---

# cd /

Перехід до кореневої директорії файлової системи.

    cd /

Перевірка:

    pwd

Результат:

    /

Переглянути вміст кореня:

    ls /

Можливий результат:

    bin  boot  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  sys  tmp  usr  var

Це не означає, що користувач перебуває в домашній директорії.

Корінь `/` і домашня директорія `~` — різні місця.

---

# cd ..

`..` означає батьківську директорію.

Приклад:

    pwd

    /home/taubu/projects/nest-exercises

Виконуємо:

    cd ..

Тепер:

    pwd

    /home/taubu/projects

Можна підніматися на кілька рівнів.

    cd ../..

Якщо початковий шлях:

    /home/taubu/projects/nest-exercises

то після `cd ../..` результатом буде:

    /home/taubu

Ще один приклад:

    cd ../../..

Із початкової директорії:

    /home/taubu/projects/nest-exercises

можна перейти до:

    /home

Кожен компонент `..` означає перехід на один рівень вище від поточної точки навігації.

---

# cd .

`.` позначає поточну директорію.

Команда:

    cd .

залишає тебе в тій самій директорії.

Це не дуже корисно для звичайної навігації, але позначення `.` часто використовується в інших командах.

Наприклад:

    ls .

означає показати вміст поточної директорії.

А команда:

    ls ..

показує вміст батьківської директорії.

Порівняння:

    ls .      — вміст поточної директорії
    ls ..     — вміст батьківської директорії
    ls /      — вміст кореневої директорії
    ls ~      — вміст домашньої директорії

---

# cd -

`cd -` повертає до попередньої робочої директорії.

Приклад:

    cd ~/projects

Поточна директорія:

    /home/taubu/projects

Тепер переходимо в інше місце:

    cd /etc

Поточна директорія:

    /etc

Повернення:

    cd -

Термінал повідомить про перехід до попередньої директорії, наприклад:

    /home/taubu/projects

Повторне виконання:

    cd -

знову перемкне між цими двома директоріями.

Це зручно, коли потрібно тимчасово перейти в інше місце, а потім повернутися назад.

---

# Абсолютний шлях

Absolute path — абсолютний шлях.

Абсолютний шлях починається з `/` і визначає розташування об'єкта від кореня файлової системи.

Приклади:

    /home/taubu
    /home/taubu/projects
    /home/taubu/projects/nest-exercises
    /etc
    /var/log

Наприклад:

    cd /home/taubu/projects/nest-exercises

Команда працюватиме незалежно від того, у якій директорії ти перебував до її виконання, якщо вказаний шлях існує і доступний.

Важливо:

    /home/taubu/projects

— абсолютний шлях.

    home/taubu/projects

— не абсолютний шлях, оскільки не починається з `/`.

---

# Відносний шлях

Relative path — відносний шлях.

Відносний шлях визначається від поточної робочої директорії.

Наприклад, якщо поточна директорія:

    /home/taubu/projects

і в ній є директорія:

    nest-exercises

можна виконати:

    cd nest-exercises

Результат:

    /home/taubu/projects/nest-exercises

Абсолютний варіант:

    cd /home/taubu/projects/nest-exercises

Відносний варіант:

    cd nest-exercises

Обидва варіанти ведуть до одного місця, якщо поточна директорія відповідає очікуваному розташуванню.

---

# Absolute Path vs Relative Path

Абсолютний шлях:

    /home/taubu/projects/nest-exercises/practice/linux

Відносний шлях, якщо ти вже перебуваєш у `nest-exercises`:

    practice/linux

Відносний шлях, якщо ти перебуваєш у `practice`:

    linux

# Навігація від поточної директорії

Не обов'язково щоразу вказувати повний шлях.

Якщо ти перебуваєш у:

    ~/projects/nest-exercises/practice/linux

можна виконати:

    cd 02-files-and-directories

Далі:

    cd 01-pwd-ls-cd

Повернутися до `linux`:

    cd ../..

Пояснення:

    01-pwd-ls-cd
        ↓
    02-files-and-directories
        ↓
    linux

Дві команди `..` означають два переходи на рівень вище.

Важливо: відносний шлях має сенс тільки щодо поточної робочої директорії.

# Перегляд батьківської директорії без переходу

Щоб подивитися вміст батьківської директорії, необов'язково виконувати `cd ..`.

Достатньо:

    ls ..

Наприклад, якщо поточна директорія:

    ~/projects/nest-exercises/practice/linux/02-files-and-directories

команда:

    ls ..

покаже вміст:

    ~/projects/nest-exercises/practice/linux

Можна переглядати й глибші рівні:

    ls ../..
    ls ../../..

Це корисно, коли потрібно перевірити структуру сусідніх директорій, не змінюючи поточного розташування.

# Перегляд директорій і файлів за шляхом

`ls` приймає шлях до конкретного об'єкта.

Наприклад:

    ls ~/projects/nest-exercises/practice/linux

Переглянути конкретний файл:

    ls ~/projects/nest-exercises/README.md

Показати детальну інформацію про файл:

    ls -l ~/projects/nest-exercises/README.md

Переглянути приховані записи в конкретній директорії:

    ls -la ~/projects/nest-exercises

Якщо вказаний шлях не існує, Linux повідомить про помилку.

Наприклад:

    ls nonexistent-directory

Можливий результат:

    ls: cannot access 'nonexistent-directory': No such file or directory

У такому разі перевір:

    pwd
    ls
    ls ..

Можливо, ти перебуваєш не в тій директорії або помилився в назві.

# Регістр символів у Linux

Linux розрізняє великі та малі літери в іменах файлів і директорій.

Наприклад:

    Documents
    documents
    DOCUMENTS

можуть бути трьома різними іменами.

Якщо існує директорія:

    projects

команда:

    cd Projects

може завершитися помилкою, оскільки `Projects` і `projects` — різні імена.

Правильно:

    cd projects

Тому важливо точно вводити назви директорій і файлів.

# Пробіли в іменах директорій

У Linux імена файлів та директорій можуть містити пробіли.

Наприклад:

    My Documents

Для переходу можна використати лапки:

    cd "My Documents"

Або екранувати пробіл зворотною скісною рискою:

    cd My\ Documents

Якщо шлях містить пробіли, без лапок або екранування оболонка може сприйняти його як кілька окремих аргументів.

Наприклад:

    cd My Documents

не означає автоматично перейти до однієї директорії з назвою `My Documents`.

# Tab Completion

Tab completion — автоматичне доповнення команд, шляхів та імен.

Це одна з найкорисніших можливостей Bash.

Припустимо, є директорія:

    nest-exercises

Можна почати вводити:

    cd nest

і натиснути `Tab`.

Якщо ім'я однозначне, Bash доповнить його:

    cd nest-exercises

Якщо існує кілька варіантів, повторне натискання `Tab` може показати доступні варіанти.

Tab completion допомагає:

- швидше вводити довгі шляхи;
- уникати помилок у назвах;
- працювати з вкладеними директоріями;
- зменшувати кількість ручного введення.

Для розробника, який регулярно працює з Git-репозиторіями, це дуже корисна звичка.

# Command History

Bash зберігає історію введених команд.

Основні клавіші:

    ↑ — попередня команда
    ↓ — наступна команда

Наприклад, якщо раніше виконував:

    cd ~/projects/nest-exercises/practice/linux

можна натиснути стрілку вгору, щоб відновити команду, не вводячи її заново.

Історія особливо корисна для довгих шляхів.

Також можна переглянути історію:

    history

Для пошуку раніше введених команд зручно використовувати:

    Ctrl + R

Після натискання `Ctrl + R` почни вводити частину команди, наприклад:

    cd ~/projects

Bash шукатиме відповідні записи в історії.

# Символи та шаблони шляхів

Bash підтримує шаблони, які допомагають вибирати групи файлів і директорій.

## *

`*` відповідає послідовності символів, включно з порожньою послідовністю.

Наприклад:

    ls *.md

Покаже файли з розширенням `.md` у поточній директорії, якщо такі файли є.

Приклад:

    ls 0*

може показати записи, назви яких починаються з `0`.

Шаблони розгортаються оболонкою до запуску команди.

Важливо: звичайний шаблон `*` не збігається з іменами, що починаються з крапки, якщо спеціальна поведінка оболонки не налаштована інакше.

---

## ?

`?` відповідає одному символу.

Наприклад:

    ls file?.txt

може відповідати:

    file1.txt
    file2.txt

але не відповідає:

    file10.txt

оскільки після `file` у шаблоні допускається лише один символ перед `.txt`.

---

## [ ]

Квадратні дужки дозволяють вказати один символ із набору.

Наприклад:

    ls file[123].txt

може відповідати:

    file1.txt
    file2.txt
    file3.txt

Ці шаблони корисні під час роботи з файлами, але для базової навігації достатньо знати про їх існування.

---

# Символічні посилання та шляхи

Symbolic link — символічне посилання на інший файл або директорію.

Воно дозволяє звертатися до об'єкта через інше ім'я або шлях.

Наприклад:

    /home/taubu/project-link -> /home/taubu/projects/nest-exercises

Якщо `project-link` є символічним посиланням на директорію, можна перейти до неї:

    cd ~/project-link

Для перегляду посилань у списку:

    ls -l

Символічні посилання докладніше розглядатимуться в інших розділах Linux.

Важливо пам'ятати, що логічний шлях, який показує `pwd`, і фізичний шлях, який показує `pwd -P`, можуть відрізнятися через символічні посилання.

# Типові помилки

## Помилка 1 — не перевіряти поточну директорію

Команда:

    cd practice/linux

може завершитися помилкою, якщо ти перебуваєш не в корені репозиторію.

Перед переходом можна перевірити:

    pwd

або використати абсолютний шлях:

    cd ~/projects/nest-exercises/practice/linux

---

## Помилка 2 — плутати / та ~

    / — корінь файлової системи
    ~ — домашня директорія користувача

Команда:

    cd /

переводить до кореня.

Команда:

    cd ~

переводить до домашньої директорії.

Це різні місця.

---

## Помилка 3 — забувати про регістр символів

Якщо директорія називається:

    Documents

команда:

    cd documents

може не спрацювати.

Використовуй точне ім'я.

---

## Помилка 4 — неправильно використовувати ..

Команда:

    cd ..

переходить на один рівень вище.

Команда:

    cd ../..

переходить на два рівні вище.

Кількість компонентів `..` визначає кількість переходів.

---

## Помилка 5 — очікувати, що ls змінить директорію

Команда:

    ls /etc

лише показує вміст `/etc`.

Вона не переводить до `/etc`.

Для переходу використовуй:

    cd /etc

---

## Помилка 6 — забувати про приховані файли

Звичайна команда:

    ls

не показує приховані записи, імена яких починаються з крапки.

Використовуй:

    ls -a

або:

    ls -la

---

## Помилка 7 — плутати абсолютний і відносний шлях

Абсолютний:

    /home/taubu/projects

Відносний:

    projects

Відносний шлях `projects` працює тільки тоді, коли в поточній директорії є відповідний об'єкт.

---

## Помилка 8 — неправильно вводити шляхи з пробілами

Неправильно для директорії `My Documents`:

    cd My Documents

Правильно:

    cd "My Documents"

або:

    cd My\ Documents

---

## Помилка 9 — сприймати . і .. як звичайні назви директорій

    .  — поточна директорія
    .. — батьківська директорія

Це спеціальні позначення, які використовуються для навігації.

---

## Помилка 10 — забувати про Tab completion

Замість ручного введення довгого шляху можна почати вводити його та натиснути `Tab`.

Наприклад:

    cd ~/projects/nest

Після доповнення:

    cd ~/projects/nest-exercises

Це зменшує кількість помилок і пришвидшує роботу.

# Головне

• `pwd` відповідає на запитання: «Де я зараз?»

• `ls` відповідає на запитання: «Що знаходиться в цій директорії?»

• `cd` відповідає на запитання: «Як перейти до іншої директорії?»

• `/` — корінь файлової системи.

• `~` — домашня директорія користувача.

• `.` — поточна директорія.

• `..` — батьківська директорія.

• `cd -` перемикає між поточною та попередньою робочими директоріями.

• Абсолютний шлях починається з `/`.

• Відносний шлях залежить від поточного розташування.

• `ls -la` — одна з найкорисніших команд для огляду директорії.

• `ls PATH` дозволяє переглядати інші директорії без переходу до них.

• Linux розрізняє великі та малі літери в іменах файлів і директорій.

• `Tab` допомагає швидше вводити шляхи та зменшує кількість помилок.

• `Ctrl + R` допомагає знаходити раніше введені команди.

• Перед роботою з файлами корисно перевірити поточну директорію через `pwd`.

• Для повсякденної роботи розробника важливо впевнено переходити між домашньою директорією, проєктами, Git-репозиторіями та системними каталогами.

• Основна модель навігації:

    pwd
      ↓
    визначити поточну директорію
      ↓
    ls
      ↓
    переглянути її вміст
      ↓
    cd PATH
      ↓
    перейти до потрібної директорії
      ↓
    pwd
      ↓
    перевірити результат

• Ці три команди є фундаментом роботи в Linux-терміналі. Їх варто довести до автоматизму, перш ніж переходити до створення, копіювання, переміщення та видалення файлів.
