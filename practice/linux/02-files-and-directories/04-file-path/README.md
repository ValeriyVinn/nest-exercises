# 📌 1. Що таке файловий шлях

**Файловий шлях (file path)** — це адреса, яка вказує, де розташований файл або директорія у файловій системі.

Наприклад:

    /home/taubu/projects/nest-exercises/README.md

Цей шлях указує на файл `README.md`, який розташований у директорії `nest-exercises`.

Інший приклад:

    documents/linux/README.md

Це відносний шлях до файла `README.md`.

Шлях може бути:

- абсолютним;
- відносним.

Щоб правильно працювати з Linux, потрібно розуміти різницю між ними.

## ✔ Приклади

Переглянути поточну директорію:

    pwd

Переглянути вміст поточної директорії:

    ls

Переглянути вміст конкретної директорії:

    ls /home/taubu/projects

Перейти до директорії за абсолютним шляхом:

    cd /home/taubu/projects

Перейти до вкладеної директорії відносно поточного розташування:

    cd documents/linux

## 🎯 Що потрібно запам'ятати

- Шлях указує на розташування файла або директорії.
- Абсолютний шлях починається з `/`.
- Відносний шлях залежить від поточної директорії.
- Символ `.` означає поточну директорію.
- Символ `..` означає батьківську директорію.
- Символ `~` зазвичай позначає домашню директорію користувача.
- Linux розрізняє великі та малі літери в назвах шляхів.

# 📌 2. Основні поняття

## 2.1. Коренева директорія `/`

У Linux усі файли та директорії належать до єдиної ієрархії, яка починається з кореневої директорії `/`.

Приклад:

    /
    ├── home/
    │   └── taubu/
    │       ├── projects/
    │       └── Documents/
    ├── etc/
    ├── usr/
    ├── var/
    └── tmp/

Основні директорії:

| Шлях | Призначення |
|---|---|
| `/` | Корінь файлової системи |
| `/home` | Домашні директорії звичайних користувачів |
| `/root` | Домашня директорія адміністратора `root` |
| `/etc` | Системні конфігураційні файли |
| `/usr` | Багато програм, бібліотек і ресурсів системи |
| `/var` | Змінні дані, наприклад журнали |
| `/tmp` | Тимчасові файли |
| `/dev` | Файли пристроїв |
| `/mnt` | Типове місце для тимчасового монтування файлових систем |
| `/media` | Типове місце монтування знімних носіїв |

Це стандартні приклади, але фактична структура залежить від системи та її налаштувань.

## 2.2. Директорія `/home`

У домашніх директоріях зберігаються особисті файли користувачів.

Наприклад:

    /home/taubu/

Тут можуть бути:

    /home/taubu/projects/
    /home/taubu/Documents/
    /home/taubu/Downloads/
    /home/taubu/.config/

У твоїй Ubuntu навчальні проєкти можуть розташовуватися приблизно так:

    /home/taubu/projects/nest-exercises/

Не потрібно щоразу вводити весь шлях: можна використовувати `~`.

## 2.3. Роздільник шляхів `/`

У Linux символ `/` розділяє компоненти шляху.

Наприклад:

    /home/taubu/projects/README.md

Компоненти:

- `/` — коренева директорія;
- `home` — директорія всередині кореня;
- `taubu` — домашня директорія користувача;
- `projects` — директорія проєктів;
- `README.md` — файл.

На відміну від Windows, у Linux стандартним роздільником шляхів є `/`, а не `\`.

Приклад Windows:

    C:\Users\Valer\projects\README.md

Приклад Linux:

    /home/taubu/projects/README.md

## 2.4. Регістр символів

У Linux назви зазвичай чутливі до регістру.

Це різні шляхи:

    README.md
    Readme.md
    readme.md

Так само:

    projects/
    Projects/

можуть бути двома різними директоріями.

Тому завжди перевіряй точне написання назв.

## 2.5. Файл і директорія — не одне й те саме

Шлях може вказувати на файл:

    /home/taubu/projects/README.md

Або на директорію:

    /home/taubu/projects/

Для перевірки конкретного шляху використовуй:

    ls -ld /home/taubu/projects

Опція `-d` дозволяє показати саму директорію, а не її вміст.

# 📌 3. Абсолютні шляхи

## 3.1. Що таке абсолютний шлях

**Абсолютний шлях (absolute path)** — це повний шлях, який починається з кореневої директорії `/`.

Наприклад:

    /home/taubu/projects/nest-exercises

Інший приклад:

    /etc/hosts

Абсолютний шлях не залежить від поточної директорії термінала.

Якщо ти перебуваєш у:

    /home/taubu/projects

то команда:

    ls /etc

все одно перегляне директорію `/etc`.

## 3.2. Приклади абсолютних шляхів

Домашня директорія користувача:

    /home/taubu

Директорія проєктів:

    /home/taubu/projects

Репозиторій:

    /home/taubu/projects/nest-exercises

Файл README:

    /home/taubu/projects/nest-exercises/README.md

Системний файл:

    /etc/hostname

## 3.3. Використання абсолютного шляху з cd

    cd /home/taubu/projects

Перейти до репозиторію:

    cd /home/taubu/projects/nest-exercises

Перейти до системної директорії:

    cd /etc

## 3.4. Використання абсолютного шляху з ls

Переглянути домашню директорію:

    ls /home/taubu

Переглянути проєкти:

    ls /home/taubu/projects

Переглянути вкладену директорію:

    ls /home/taubu/projects/nest-exercises/practice/linux

## 3.5. Використання абсолютного шляху з mkdir

Створити директорію:

    mkdir /home/taubu/projects/test-folder

Це спрацює, якщо батьківська директорія існує та користувач має потрібні права.

Створити вкладені директорії:

    mkdir -p /home/taubu/projects/test-folder/linux/files

Опція `-p` створює відсутні батьківські директорії.

## 3.6. Переваги абсолютних шляхів

- Вони однозначно вказують на розташування.
- Не залежать від поточної директорії.
- Зручні в документації та сценаріях, коли потрібне конкретне розташування.
- Допомагають уникати плутанини під час роботи з різними директоріями.

## 3.7. Недоліки абсолютних шляхів

Абсолютні шляхи можуть бути довгими.

Наприклад:

    /home/taubu/projects/nest-exercises/practice/linux/02-files-and-directories/README.md

Для щоденної роботи зручніше використовувати відносні шляхи або `~`, якщо це доречно.

# 📌 4. Відносні шляхи

## 4.1. Що таке відносний шлях

**Відносний шлях (relative path)** — це шлях, який визначається відносно поточної директорії.

Він не починається з `/`.

Приклад:

    documents/notes.txt

Щоб правильно інтерпретувати цей шлях, потрібно знати, де саме ти перебуваєш.

## 4.2. Приклад структури

Припустимо, маємо:

    /home/taubu/projects/
    ├── README.md
    ├── notes.txt
    └── documents/
        ├── report.txt
        └── lessons/
            └── linux.md

Якщо поточна директорія:

    /home/taubu/projects

то відносний шлях до `notes.txt`:

    notes.txt

Відносний шлях до `report.txt`:

    documents/report.txt

Відносний шлях до `linux.md`:

    documents/lessons/linux.md

## 4.3. Перехід до вкладеної директорії

Якщо ти перебуваєш у:

    /home/taubu/projects

виконай:

    cd documents

Після цього поточна директорія:

    /home/taubu/projects/documents

Щоб перейти до `lessons`:

    cd lessons

Відносний шлях починається від поточного місця.

## 4.4. Перехід на кілька рівнів углиб

З директорії:

    /home/taubu/projects

можна перейти до:

    /home/taubu/projects/documents/lessons

однією командою:

    cd documents/lessons

Не потрібно виконувати `cd` окремо для кожної директорії.

## 4.5. Перехід до батьківської директорії

Для цього використовують `..`.

Якщо ти перебуваєш у:

    /home/taubu/projects/documents

виконай:

    cd ..

Після цього опинишся в:

    /home/taubu/projects

Щоб піднятися ще на один рівень:

    cd ../..

Результат:

    /home/taubu

Кожна частина `..` означає перехід на один рівень угору.

## 4.6. Перехід до сусідньої директорії

Припустимо, структура така:

    projects/
    ├── nest-exercises/
    └── next-exercises/

Якщо ти перебуваєш у:

    projects/nest-exercises

можна перейти до сусіднього репозиторію:

    cd ../next-exercises

Пояснення:

- `..` — піднятися до `projects`;
- `next-exercises` — увійти до сусідньої директорії.

## 4.7. Відносний шлях до файла в батьківській директорії

Якщо поточна директорія:

    /home/taubu/projects/documents

а потрібний файл лежить у:

    /home/taubu/projects/notes.txt

виконай:

    cat ../notes.txt

Або скопіюй його:

    cp ../notes.txt .

Тут `.` означає поточну директорію.

## 4.8. Коли використовувати відносні шляхи

Відносні шляхи зручні, коли:

- ти працюєш усередині проєкту;
- файли розташовані поруч;
- структура директорій добре відома;
- потрібно писати коротші команди;
- створюєш README та навчальні приклади, які мають бути зрозумілими в межах проєкту.

Наприклад, усередині репозиторію:

    cp README.md README.backup.md

або:

    ls practice/linux

# 📌 5. Спеціальні позначення шляхів

У Linux є кілька важливих позначень, які потрібно добре запам'ятати.

| Позначення | Значення |
|---|---|
| `/` | Коренева директорія |
| `.` | Поточна директорія |
| `..` | Батьківська директорія |
| `~` | Домашня директорія поточного користувача в Bash |
| `-` | У команді `cd -` — попередня робоча директорія |
| `./` | Шлях від поточної директорії |
| `../` | Шлях від батьківської директорії |

## 5.1. Поточна директорія — `.`

Символ `.` означає директорію, у якій ти перебуваєш.

Приклад:

    pwd

    /home/taubu/projects

Команда:

    ls .

переглядає поточну директорію.

Команда:

    cp notes.txt .

копіює `notes.txt` до поточної директорії.

Однак якщо файл уже перебуває в цій директорії, така команда не має практичної користі й може завершитися повідомленням про те, що джерело та призначення — той самий файл.

## 5.2. Явний шлях `./`

`./` означає, що шлях починається від поточної директорії.

Наприклад:

    ./notes.txt

У багатьох командах це еквівалентно:

    notes.txt

Але `./` має особливе значення під час запуску виконуваних файлів.

Наприклад, якщо в поточній директорії є виконуваний скрипт `script.sh`, його можна запустити так:

    ./script.sh

Shell не обов'язково шукає виконувані файли в поточній директорії автоматично.

## 5.3. Батьківська директорія — `..`

Позначення `..` указує на один рівень вище.

Переглянути вміст батьківської директорії:

    ls ..

Перейти до батьківської директорії:

    cd ..

Переглянути директорію на два рівні вище:

    ls ../..

Скопіювати файл із батьківської директорії:

    cp ../notes.txt .

## 5.4. Кілька рівнів угору

Приклад поточного розташування:

    /home/taubu/projects/nest-exercises/practice/linux/02-files-and-directories

Шлях:

    ../../..

означає піднятися на три рівні вгору.

Результат:

    /home/taubu/projects/nest-exercises/practice

Щоб побачити результат переходу, можна виконати:

    cd ../../..

    pwd

## 5.5. Попередня директорія — `cd -`

Команда:

    cd -

повертає до попередньої робочої директорії.

Приклад:

    cd /etc

    cd /home/taubu/projects

    cd -

Після останньої команди ти повернешся до `/etc`.

Повторне виконання:

    cd -

поверне до `/home/taubu/projects`.

Це зручно, коли потрібно швидко перемикатися між двома місцями.

## 5.6. Коренева директорія — `/`

Перейти до кореня файлової системи:

    cd /

Переглянути його вміст:

    ls

Повернутися до домашньої директорії:

    cd ~

Не плутай `/` і `~`:

- `/` — корінь усієї файлової системи;
- `~` — домашня директорія поточного користувача.

# 📌 6. Домашня директорія та символ тильди

## 6.1. Що означає `~`

У Bash символ `~` на початку слова зазвичай позначає домашню директорію поточного користувача.

Наприклад, для користувача `taubu`:

    ~

зазвичай відповідає:

    /home/taubu

Тому:

    cd ~

перейде до домашньої директорії.

## 6.2. Шлях до проєктів через `~`

Замість:

    cd /home/taubu/projects

можна написати:

    cd ~/projects

А замість:

    ls /home/taubu/projects/nest-exercises

використати:

    ls ~/projects/nest-exercises

Це робить команди коротшими.

## 6.3. Створення директорії в домашньому каталозі

    mkdir ~/linux-practice

Створює директорію `linux-practice` у домашній директорії.

Створити вкладену структуру:

    mkdir -p ~/linux-practice/files/documents

Перевірити результат:

    ls -R ~/linux-practice

## 6.4. Важлива особливість тильди

Shell розпізнає `~` як домашню директорію, коли він стоїть у відповідній позиції, наприклад на початку слова.

Працює:

    cd ~/projects

А ось так писати не слід, якщо ти очікуєш автоматичної підстановки домашнього шляху:

    cd "~"/projects

Лапки заважають звичайній підстановці `~` у Bash у цьому контексті.

Найпростіше запам'ятати:

    cd ~
    cd ~/projects

## 6.5. Домашня директорія іншого користувача

У Bash можна використовувати форму:

    ~username

Наприклад:

    ls ~root

Вона може посилатися на домашню директорію користувача `root`, зазвичай `/root`.

Доступ до файлів усе одно залежить від прав користувача.

## 6.6. Змінна `$HOME`

Змінна середовища `$HOME` містить шлях до домашньої директорії поточного користувача.

Переглянути її:

    echo "$HOME"

Приклад результату:

    /home/taubu

Можна використати її в команді:

    cd "$HOME/projects"

Для звичайної роботи часто зручніше `~/projects`, а `$HOME` особливо корисний у скриптах.

# 📌 7. Робота з вкладеними директоріями

## 7.1. Як читати складний шлях

Розглянемо шлях:

    ~/projects/nest-exercises/practice/linux/02-files-and-directories/04-file-paths/README.md

Його можна розкласти так:

    ~
    └── projects/
        └── nest-exercises/
            └── practice/
                └── linux/
                    └── 02-files-and-directories/
                        └── 04-file-paths/
                            └── README.md

Кожен наступний компонент указує на вкладену директорію або файл.

# 📌 8. Шляхи з пробілами та спеціальними символами

## 8.1. Пробіли в назвах

У Linux назви файлів і директорій можуть містити пробіли.

Наприклад:

    My Documents/

Щоб перейти до такої директорії, можна використати лапки:

    cd "My Documents"

Або екранувати пробіл:

    cd My\ Documents

Для початківця найпростіше використовувати лапки.

## 8.2. Абсолютний шлях із пробілами

    cd "/home/taubu/My Documents"

Або:

    ls "/home/taubu/My Documents"

Лапки допомагають shell сприймати шлях як один аргумент.

## 8.3. Відносний шлях із пробілами

    cd "My Documents/Linux Notes"

Тут шлях містить дві вкладені директорії.

## 8.4. Використання лапок із cp, mv і rm

Копіювання:

    cp "my notes.txt" "my notes backup.txt"

Переміщення:

    mv "old report.txt" "new report.txt"

Видалення:

    rm -i "temporary notes.txt"

Правило просте: якщо шлях містить пробіли, обрамляй його подвійними лапками або екрануй пробіли.

## 8.5. Символи `*` і `?`

Ці символи shell використовує в шаблонах імен файлів.

`*` відповідає будь-якій послідовності символів:

    ls *.txt

`?` відповідає одному символу:

    ls file?.txt

Наприклад:

    file1.txt
    file2.txt
    fileA.txt

можуть відповідати шаблону `file?.txt`.

Не плутай ці шаблони зі звичайними символами в назві шляху.

## 8.6. Квадратні дужки в шаблонах

Квадратні дужки можуть задавати набір допустимих символів.

    ls file[12].txt

Такий шаблон може відповідати:

    file1.txt
    file2.txt

Але не `file3.txt`.

Це механізм підстановки shell, а не спеціальна властивість файлової системи.

# 📌 9. Використання шляхів із командами Linux

Шляхи використовуються майже в усіх командах роботи з файлами.

## 9.1. Команда pwd

Показує абсолютний шлях поточної робочої директорії.

    pwd

Приклад результату:

    /home/taubu/projects

## 9.2. Команда ls

Переглянути поточну директорію:

    ls

Переглянути конкретну директорію:

    ls ~/projects

Переглянути конкретний файл:

    ls -l ~/projects/README.md

Переглянути приховані файли:

    ls -la ~/projects

## 9.3. Команда cd

Перейти до абсолютного шляху:

    cd /etc

Перейти до відносного шляху:

    cd projects

Перейти до домашньої директорії:

    cd ~

Піднятися на рівень вище:

    cd ..

Повернутися до попередньої директорії:

    cd -

## 9.4. Команда mkdir

Створити директорію в поточному місці:

    mkdir documents

Створити директорію за абсолютним шляхом:

    mkdir ~/linux-practice

Створити вкладені директорії:

    mkdir -p ~/linux-practice/files/paths

## 9.5. Команда touch

Створити файл у поточній директорії:

    touch notes.txt

Створити файл у вкладеній директорії:

    touch documents/notes.txt

Це спрацює, якщо `documents/` уже існує.

Створити файл за абсолютним шляхом:

    touch ~/linux-practice/files/notes.txt

## 9.6. Команда cp

Скопіювати файл у поточній директорії:

    cp ~/projects/README.md .

Скопіювати файл за абсолютним шляхом:

    cp ~/projects/README.md ~/linux-practice/README.md

Скопіювати директорію:

    cp -r ~/projects/example ~/linux-practice/example-copy

## 9.7. Команда mv

Перейменувати файл:

    mv notes.txt notes-backup.txt

Перемістити файл:

    mv notes.txt documents/

Перемістити файл за абсолютним шляхом:

    mv ~/linux-practice/notes.txt ~/linux-practice/files/

## 9.8. Команда rm

Видалити файл:

    rm -i notes.txt

Видалити файл за абсолютним шляхом:

    rm -i ~/linux-practice/notes.txt

Видалити директорію разом із вмістом:

    rm -ri ~/linux-practice/old-files

Перед використанням рекурсивного видалення обов'язково перевіряй шлях.

## 9.9. Команда cat

Прочитати файл у поточній директорії:

    cat README.md

Прочитати файл за абсолютним шляхом:

    cat ~/projects/nest-exercises/README.md

Прочитати файл у вкладеній директорії:

    cat practice/linux/README.md

Файл має існувати, а користувач повинен мати права на читання.

# 📌 10. Типові помилки

## ❌ Помилка 1. Плутанина між `/` і `~`

`/` — коренева директорія всієї файлової системи.

`~` — домашня директорія користувача.

Команда:

    cd /

перейде до кореня.

Команда:

    cd ~

перейде до домашньої директорії.

## ❌ Помилка 2. Використання неправильного відносного шляху

Припустимо, ти перебуваєш у:

    /home/taubu/projects/nest-exercises/practice

Команда:

    cd linux

спрацює лише тоді, коли `linux` є піддиректорією поточної директорії.

Якщо директорія розташована в іншому місці, потрібно вказати правильний шлях.

Перевір:

    pwd

    ls

## ❌ Помилка 3. Забутий перехід на рівень вище

Якщо потрібний файл лежить у батьківській директорії, а ти перебуваєш усередині вкладеної, потрібно використати `..`.

Наприклад:

    cat ../README.md

Без `..` команда шукатиме файл у поточній директорії.

## ❌ Помилка 4. Неправильний регістр

Команда:

    cd Documents

не обов'язково працюватиме, якщо директорія називається:

    documents

У Linux ці назви можуть бути різними.

Перевір назву через:

    ls

## ❌ Помилка 5. Пробіли без лапок

Неправильно:

    cd My Documents

Shell сприйме `My` і `Documents` як різні аргументи.

Правильно:

    cd "My Documents"

## ❌ Помилка 6. Використання Windows-шляху в Linux

Windows:

    C:\Users\Valer\projects

Linux:

    /home/taubu/projects

Не використовуй Windows-шлях безпосередньо в командах Linux, якщо він не належить до спеціального середовища доступу до Windows-файлів, наприклад WSL.

## ❌ Помилка 7. Відносний шлях сприймається як абсолютний

Шлях:

    documents/notes.txt

не вказує на одне незмінне місце. Його значення залежить від поточної директорії.

Щоб побачити поточне розташування:

    pwd

## ❌ Помилка 8. Очікування, що `..` означає домашню директорію

`..` означає батьківську директорію, а не домашню.

Якщо поточний шлях:

    /home/taubu/projects

то:

    cd ..

перейде до:

    /home/taubu

У цьому конкретному випадку це домашня директорія, але в іншому місці результат буде іншим.

## ❌ Помилка 9. Директорія не існує

Команда:

    cd documents

завершиться помилкою, якщо директорії `documents` немає в поточному місці.

Перевір:

    ls -la

Або перейди за правильним абсолютним шляхом.

## ❌ Помилка 10. Шлях існує, але доступ заборонений

Повідомлення `Permission denied` означає, що операцію заборонено через права доступу або інші обмеження.

Перевір:

    ls -ld /path/to/directory

Не намагайся автоматично розв'язувати кожну таку проблему через `sudo`: спочатку з'ясуй причину.

# 📌 14. Мінішпаргалка

## Основні команди

    pwd

Показати поточну директорію.

    ls

Переглянути вміст поточної директорії.

    ls -la

Показати всі файли, включно з прихованими.

    cd ~

Перейти до домашньої директорії.

    cd /

Перейти до кореневої директорії.

    cd ..

Перейти до батьківської директорії.

    cd ../..

Піднятися на два рівні вгору.

    cd -

Повернутися до попередньої робочої директорії.

## Абсолютні шляхи

    cd /home/taubu/projects

Перейти за абсолютним шляхом.

    ls /etc

Переглянути вміст `/etc`.

    cat /home/taubu/projects/README.md

Прочитати файл за абсолютним шляхом.

## Відносні шляхи

    cd documents

Перейти до піддиректорії `documents`, якщо вона існує.

    cd documents/linux

Перейти до вкладеної директорії.

    cd ../next-exercises

Перейти до сусідньої директорії, якщо вона існує.

    cat ../README.md

Прочитати файл у батьківській директорії.

    cp ../notes.txt .

Скопіювати файл із батьківської директорії в поточну.

## Домашня директорія

    ~

Домашня директорія в Bash.

    ~/projects

Директорія `projects` у домашньому каталозі.

    echo "$HOME"

Показати значення змінної домашньої директорії.

    cd "$HOME/projects"

Перейти до каталогу проєктів через змінну `$HOME`.

## Пробіли в шляхах

    cd "My Documents"

Перейти до директорії з пробілом у назві.

    ls "/home/taubu/My Documents"

Переглянути директорію з пробілом у шляху.

    cp "my notes.txt" "backup notes.txt"

Скопіювати файл, назва якого містить пробіл.

Чи існує ця директорія та які її основні атрибути?

    ls -l /path/to/file

# 📌 15. Головне, що потрібно запам'ятати

✔ **Абсолютний шлях** починається з `/` і не залежить від поточної директорії.

✔ **Відносний шлях** обчислюється від поточної директорії.

✔ `/` — коренева директорія файлової системи.

✔ `.` — поточна директорія.

✔ `..` — батьківська директорія.

✔ `~` — домашня директорія користувача в Bash.

✔ `cd -` — повернення до попередньої робочої директорії.

✔ `pwd` — команда для перевірки поточного розташування.

✔ `ls -la` — команда для перегляду файлів, включно з прихованими.

✔ Linux розрізняє великі та малі літери в назвах файлів і директорій.

✔ Для шляхів із пробілами використовуй лапки або екранування.

✔ Відносний шлях потрібно завжди розглядати в контексті поточної директорії.

✔ Перед видаленням або переміщенням файлів перевіряй шлях.
