# 07. File Types — типи файлів у Linux

## 📌 Вступ

У Linux майже все представлено як файл або файловий об'єкт. Проте не всі об'єкти є звичайними файлами: у системі є директорії, символічні посилання, спеціальні файли пристроїв, канали та сокети.

Щоб правильно працювати з файловою системою Linux, потрібно навчитися:

- визначати тип файлу;
- розрізняти розширення і реальний тип файлу;
- використовувати команди `file`, `stat`, `ls -l` і `ls -F`;
- розуміти звичайні файли, директорії та посилання;
- розпізнавати спеціальні файли Linux;
- перевіряти виконувані файли й типи текстових даних.

**Головна ідея:** розширення імені не визначає справжній тип файлу. Наприклад, файл `photo.jpg` може містити звичайний текст, а не зображення.

---

## 1. Основні типи файлів у Linux

У Linux використовуються такі основні типи файлових об'єктів:

| Тип | Позначення в `ls -l` | Призначення |
|---|---|---|
| Звичайний файл | `-` | Текст, код, зображення, архіви та інші дані |
| Директорія | `d` | Містить записи про файли та піддиректорії |
| Символічне посилання | `l` | Посилається на інший шлях |
| Символьний пристрій | `c` | Надає доступ до пристрою через потік даних |
| Блоковий пристрій | `b` | Надає доступ до пристрою блоками даних |
| Іменований канал (FIFO) | `p` | Передає дані між процесами |
| Сокет | `s` | Забезпечує обмін даними між процесами |

Ці позначення можна побачити за допомогою:

    ls -l

Наприклад:

    -rw-r--r-- 1 user user 1200 Oct 16 12:00 notes.txt
    drwxr-xr-x 2 user user 4096 Oct 16 12:00 documents
    lrwxrwxrwx 1 user user   10 Oct 16 12:00 latest -> notes.txt

Перший символ у першій колонці показує тип об'єкта:

- `-` — звичайний файл;
- `d` — директорія;
- `l` — символічне посилання.

Решта символів у цій колонці описують права доступу.

## 2. Звичайні файли — regular files

### 2.1. Що це таке

Звичайний файл (`regular file`) містить дані.

Це можуть бути:

- текстові документи;
- вихідний код;
- конфігураційні файли;
- зображення;
- аудіо та відео;
- архіви;
- виконувані програми;
- бази даних.

Приклади:

    README.md
    package.json
    server.js
    styles.css
    photo.jpg
    archive.zip

Усі вони можуть бути звичайними файлами, хоча вміст у них різний.

### 2.2. Як визначити звичайний файл

    ls -l README.md

Якщо перший символ у рядку — `-`, це звичайний файл.

Перевірити тип за допомогою `file`:

    file README.md

Приклад результату:

    README.md: Unicode text, UTF-8 text

Результат залежить від реального вмісту файлу.

### 2.3. Пошук лише звичайних файлів

    find . -type f

Знайти лише файли JavaScript:

    find . -type f -name "*.js"

Знайти файли Markdown:

    find . -type f -name "*.md"

**Запам'ятай:** `-type f` у `find` означає звичайний файл, а не будь-який файловий об'єкт.

## 3. Директорії — directories

### 3.1. Що таке директорія

Директорія — це спеціальний тип файлового об'єкта, який містить записи про імена файлів та інші об'єкти файлової системи.

У повсякденній роботі директорії використовують для організації проєктів і даних.

Приклад структури:

    nest-exercises/
    ├── package.json
    ├── README.md
    ├── practice/
    │   └── linux/
    │       ├── README.md
    │       └── 02-files-and-directories/
    └── src/

Тут `nest-exercises`, `practice`, `linux`, `02-files-and-directories` і `src` — директорії.

### 3.2. Як визначити директорію

    ls -ld practice

Опція `-d` показує саму директорію, а не її вміст.

Звичайний список:

    ls -l

Знайти всі директорії в поточному каталозі та його підкаталогах:

    find . -type d

Знайти директорії з назвою `src`:

    find . -type d -name "src"

### 3.3. Чим директорія відрізняється від звичайного файлу

- Звичайний файл зберігає дані.
- Директорія організовує імена об'єктів файлової системи.
- Для роботи з директоріями часто використовують `cd`, `mkdir`, `rmdir` і `ls`.

Не намагайся редагувати директорію так, ніби це звичайний текстовий файл.

## 4. Символічні посилання — symbolic links

### 4.1. Що таке символічне посилання

Символічне посилання (`symlink`) — це окремий файловий об'єкт, який зберігає шлях до іншого об'єкта.

Воно працює подібно до ярлика, але є частиною файлової системи Linux.

Створити тестову директорію та файл:

    mkdir -p ~/linux-file-types
    cd ~/linux-file-types
    echo "Hello Linux" > original.txt

Створити символічне посилання:

    ln -s original.txt shortcut.txt

Переглянути:

    ls -l

Приклад результату:

    -rw-r--r-- 1 user user 12 Oct 16 12:00 original.txt
    lrwxrwxrwx 1 user user 12 Oct 16 12:01 shortcut.txt -> original.txt

Позначення `l` на початку рядка вказує на символічне посилання.

### 4.2. Як прочитати посилання

    cat shortcut.txt

Якщо посилання веде до доступного звичайного файлу, команда покаже його вміст.

Перевірити тип:

    file shortcut.txt

Перевірити сам об'єкт посилання:

    ls -l shortcut.txt

### 4.3. Символічне посилання та ціль — не одне й те саме

Перевірити, чи є об'єкт символічним посиланням:

    test -L shortcut.txt && echo "Це symlink"

Перевірити, чи доступна ціль посилання:

    test -e shortcut.txt && echo "Ціль існує"

Якщо ціль видалити, посилання може залишитися, але стати неробочим.

Приклад:

    rm original.txt
    ls -l shortcut.txt
    test -L shortcut.txt && echo "Посилання існує"
    test -e shortcut.txt && echo "Ціль доступна"

Перша перевірка може бути успішною, а друга — ні.

### 4.4. Символічні та жорсткі посилання

У Linux існують також жорсткі посилання (`hard links`).

- Символічне посилання зберігає шлях до іншого об'єкта.
- Жорстке посилання — це ще одне ім'я того самого inode.

Для початкового вивчення достатньо добре зрозуміти символічні посилання. Жорсткі посилання можна вивчити окремо.

## 5. Спеціальні файли пристроїв

У Linux пристрої можуть бути представлені спеціальними файлами, найчастіше в директорії `/dev`.

### 5.1. Символьні пристрої — character devices

Символьні пристрої позначаються літерою `c`.

Вони забезпечують доступ до пристроїв через послідовний потік даних.

Приклади шляхів:

    /dev/tty
    /dev/null
    /dev/zero

Перевірити тип:

    ls -l /dev/null

Приклад початку рядка:

    crw-rw-rw-

Літера `c` означає символьний пристрій.

### 5.2. Блокові пристрої — block devices

Блокові пристрої позначаються літерою `b`.

Вони працюють із даними блоками та часто пов'язані з накопичувачами й розділами дисків.

Приклади назв:

    /dev/sda
    /dev/sda1
    /dev/nvme0n1

Наявність і назви пристроїв залежать від комп'ютера.

Переглянути блокові пристрої:

    lsblk

Перевірити тип конкретного пристрою, якщо він існує:

    ls -l /dev/sda

На сучасних системах диск може мати назву на кшталт `/dev/nvme0n1`, а не `/dev/sda`.

**Застереження:** не записуй дані безпосередньо в пристрої з `/dev`, якщо не розумієш наслідків. Неправильні операції можуть знищити дані.

## 6. Канали — pipes і FIFO

### 6.1. Що таке канал

Канал дає змогу передавати дані між процесами.

У командному рядку найчастіше використовується анонімний канал через символ `|`.

Наприклад:

    ls -l | less

Тут результат `ls -l` передається команді `less`.

Інший приклад:

    cat README.md | grep "Linux"

Це передає вміст файла команді `grep`, яка шукає рядки зі словом `Linux`.

Для простого пошуку часто зручніше писати так:

    grep "Linux" README.md

### 6.2. Іменований канал — FIFO

FIFO — це спеціальний файловий об'єкт, який дає змогу процесам обмінюватися даними через ім'я в файловій системі.

Створити FIFO:

    mkfifo mypipe

Перевірити тип:

    ls -l mypipe

На початку рядка буде `p`.

Видалити тестовий FIFO:

    rm mypipe

**Важливо:** FIFO — не звичайний текстовий файл. Операції читання та запису можуть очікувати на інший процес, який працюватиме з каналом.

## 7. Сокети — sockets

### 7.1. Що таке сокет

Сокет — це механізм обміну даними між процесами.

Він може використовуватися для:

- взаємодії між локальними процесами;
- серверних застосунків;
- мережевого обміну;
- системних служб.

У Linux існують різні типи сокетів. У файловій системі можна зустріти Unix domain sockets.

### 7.2. Як розпізнати сокет

Якщо сокет представлений як файловий об'єкт, у `ls -l` він позначається літерою `s`.

Приклад умовного рядка:

    srwxr-xr-x 1 user user 0 Oct 16 12:00 app.sock

Знайти сокети в доступній частині файлової системи:

    find . -type s

Переглянути мережеві сокети можна також командою:

    ss -l

Для розширеного перегляду слухаючих TCP- і UDP-портів:

    ss -lntup

Деяка інформація про процеси може вимагати додаткових дозволів.

**Запам'ятай:** не кожен мережевий сокет обов'язково має шлях у файловій системі.

## 8. Команда `file` — визначення реального типу

### 8.1. Для чого потрібна `file`

Команда `file` аналізує вміст або характеристики об'єкта й намагається визначити його тип.

Синтаксис:

    file назва_файлу

Приклади:

    file README.md
    file package.json
    file server.js
    file photo.jpg
    file archive.zip

Можливі результати:

    README.md: Unicode text, UTF-8 text
    package.json: JSON text data
    server.js: JavaScript source, Unicode text, UTF-8 text
    photo.jpg: JPEG image data
    archive.zip: Zip archive data

Це приклади можливих результатів. Точне формулювання залежить від версії `file` та вмісту файлу.

### 8.2. Розширення не гарантує тип

Припустимо, створюємо файл:

    echo "Це звичайний текст" > photo.jpg

Тепер перевіримо:

    file photo.jpg

Команда, найімовірніше, визначить його як текст, а не як JPEG-зображення.

Чому?

Тому що назва `photo.jpg` — лише ім'я. Сам вміст не є справжнім JPEG-зображенням.

### 8.3. Перевірка кількох файлів

    file *

Це передає команді `file` об'єкти, назви яких розгорнув Bash у поточній директорії.

Щоб включити приховані файли, можна явно передати потрібні шляхи або використати інший спосіб пошуку.

Перевірити всі звичайні файли в поточному дереві:

    find . -type f -exec file {} +

Це зручно, але на великому проєкті може вивести багато інформації.

### 8.4. Визначення текстового кодування

    file README.md

Команда може повідомити, що текст має кодування UTF-8.

Проте `file` не є універсальним інструментом для точної перевірки всіх можливих кодувань. Для спеціалізованих завдань можуть знадобитися інші інструменти.

## 9. Команда `stat` — інформація про файловий об'єкт

### 9.1. Що показує `stat`

`stat` показує детальну інформацію про файл або директорію:

- тип;
- розмір;
- права доступу;
- власника та групу;
- inode;
- кількість жорстких посилань;
- часові характеристики.

Приклад:

    stat README.md

Вивід залежить від системи, але може містити поля на кшталт:

    File: README.md
    Size: 1200
    Access: (0644/-rw-r--r--)
    Uid: (...)
    Gid: (...)
    Access: ...
    Modify: ...
    Change: ...

### 9.2. Що таке inode

Inode — це структура файлової системи, яка зберігає метадані об'єкта, наприклад права доступу, власника та посилання на дані.

Назва файлу не є самим inode. Директорія пов'язує ім'я з відповідним файловим об'єктом.

Переглянути inode:

    ls -i README.md

Або:

    stat README.md

### 9.3. Часові поля

У `stat` зазвичай можна побачити:

- `Access` — час останнього доступу;
- `Modify` — час останньої зміни вмісту;
- `Change` — час останньої зміни метаданих inode.

`Change` не означає дату створення файла.

Не слід плутати ці поля з часом створення. Наявність інформації про створення залежить від файлової системи та її підтримки.

### 9.4. Коротка інформація

    stat -c "%F %s bytes %n" README.md

Тут:

- `%F` — тип об'єкта;
- `%s` — розмір у байтах;
- `%n` — назва.

Приклад результату:

    regular file 1200 bytes README.md

## 10. Команда `ls -l` — тип і права доступу

### 10.1. Основний формат

    ls -l

Приклад:

    -rw-r--r-- 1 user user 1200 Oct 16 12:00 README.md

Основні частини:

    -rw-r--r--

- перший символ `-` — тип об'єкта;
- `rw-` — права власника;
- `r--` — права групи;
- `r--` — права інших користувачів.

Далі йдуть кількість жорстких посилань, власник, група, розмір, дата й ім'я.

Детально права доступу вивчатимуться в окремій темі.

### 10.2. Символи типів

Приклади перших символів:

    -    звичайний файл
    d    директорія
    l    символічне посилання
    c    символьний пристрій
    b    блоковий пристрій
    p    FIFO
    s    сокет

### 10.3. Показати типи у зручнішому форматі

    ls -F

Ця команда додає до назв спеціальні символи:

- `/` — директорія;
- `*` — файл із відповідними дозволами на виконання;
- `@` — символічне посилання;
- `|` — FIFO;
- `=` — сокет.

Приклад умовного виводу:

    documents/
    script.sh*
    shortcut@
    mypipe|

Точний набір позначень залежить від типу об'єкта й налаштувань `ls`.

**Важливо:** символ `*` у `ls -F` означає наявність дозволів на виконання, а не обов'язково те, що файл є програмою потрібного формату.

## 11. Виконувані файли та скрипти

### 11.1. Виконуваний файл — не окремий базовий тип

У Linux виконуваність не є окремим типом файлового об'єкта в тому самому сенсі, що `-`, `d` або `l`.

Звичайний файл може мати дозвіл на виконання, але це не гарантує, що його вміст можна запустити.

Наприклад:

    ls -l script.sh

Можна побачити права:

    -rwxr-xr-x

Літери `x` означають право виконання для відповідної категорії користувачів.

### 11.2. Перевірити тип скрипту

Створити тестовий скрипт:

    printf '#!/bin/bash\necho "Hello Linux"\n' > hello.sh

Перевірити:

    file hello.sh

Додати право виконання власнику:

    chmod u+x hello.sh

Запустити:

    ./hello.sh

Результат:

    Hello Linux

### 11.3. Чому розширення `.sh` недостатньо

Файл із назвою `hello.sh` не обов'язково є коректним Bash-скриптом.

Він може:

- містити звичайний текст;
- мати синтаксичні помилки;
- не мати правильного інтерпретатора;
- не мати права виконання.

Перевіряй вміст, права та інтерпретатор, а не лише розширення.

## 12. Текстові та бінарні файли

### 12.1. Текстові файли

Текстові файли містять дані, які можна інтерпретувати як текст у певному кодуванні.

Приклади:

    README.md
    package.json
    server.js
    styles.css
    .gitignore

Для перегляду використовують:

    cat README.md

Для перегляду з прокручуванням:

    less README.md

Для початку файла:

    head README.md

Для кінця файла:

    tail README.md

### 12.2. Бінарні файли

Бінарні файли містять дані, які не призначені для звичайного читання як текст.

Приклади:

- зображення;
- архіви;
- аудіо;
- відео;
- деякі виконувані програми;
- скомпільовані файли.

Визначити тип:

    file photo.jpg
    file archive.zip

Не варто відкривати невідомі бінарні файли командою `cat`: це може вивести багато нечитабельних символів у термінал.

### 12.3. Текст і бінарні дані — не окремі типи `ls -l`

Позначення `-` у `ls -l` показує, що це звичайний файл.

Він може бути текстовим або бінарним. Для попереднього визначення вмісту використовуй `file`.

---

## 13. Спеціальні шляхи: `/dev/null`, `/dev/zero`, `/dev/tty`

У Linux є спеціальні об'єкти, які поводяться не як звичайні файли.

### 13.1. `/dev/null`

`/dev/null` відкидає записані в нього дані.

Наприклад:

    echo "Цей текст не буде показаний" > /dev/null

Перенаправити повідомлення про помилки в `/dev/null`:

    find /root -name "*.txt" 2>/dev/null

Тут `2>/dev/null` перенаправляє потік помилок, а не звичайний вивід.

### 13.2. `/dev/zero`

`/dev/zero` надає потік нульових байтів під час читання.

Перевірити його тип:

    ls -l /dev/zero
    file /dev/zero

Не потрібно читати його без обмежень: потік може бути нескінченним.

### 13.3. `/dev/tty`

`/dev/tty` позначає термінал, пов'язаний із поточним процесом, якщо такий є.

Перевірити:

    ls -l /dev/tty

Ці об'єкти корисні для розуміння того, що в Linux файлові інтерфейси використовуються не лише для звичайних документів.

## 14. Файли, які починаються з крапки

У Linux назви, що починаються з крапки, зазвичай вважаються прихованими для стандартного відображення `ls`.

Приклади:

    .bashrc
    .profile
    .gitignore
    .env
    .config/

Проте прихованість не є окремим типом файлового об'єкта.

### Переглянути приховані файли

    ls -a

Показати докладну інформацію:

    ls -la

Знайти приховані звичайні файли:

    find . -type f -name ".*"

Знайти приховані директорії:

    find . -type d -name ".*"

**Запам'ятай:** прихований файл може бути звичайним файлом, директорією або символічним посиланням.

## 15. Практична лабораторна робота

Створимо окрему директорію, щоб безпечно дослідити різні типи об'єктів.

### Крок 1. Створити робочу директорію

    mkdir -p ~/linux-file-types
    cd ~/linux-file-types

### Крок 2. Створити звичайний текстовий файл

    echo "Hello Linux" > notes.txt

Перевірити:

    ls -l notes.txt
    file notes.txt
    stat notes.txt

### Крок 3. Створити директорію

    mkdir documents

Перевірити:

    ls -ld documents
    file documents

### Крок 4. Створити символічне посилання

    ln -s notes.txt notes-link.txt

Перевірити:

    ls -l notes-link.txt
    file notes-link.txt
    cat notes-link.txt

### Крок 5. Створити скрипт

    printf '#!/bin/bash\necho "Linux practice"\n' > hello.sh

Перевірити тип:

    file hello.sh

Додати право виконання:

    chmod u+x hello.sh

Запустити:

    ./hello.sh

### Крок 6. Переглянути всі об'єкти

    ls -la
    ls -lF
    find . -maxdepth 2
    find . -type f
    find . -type d
    find . -type l

### Крок 7. Порівняти типи

    file notes.txt documents notes-link.txt hello.sh

Зверни увагу на різницю між:

- звичайним текстовим файлом;
- директорією;
- символічним посиланням;
- скриптом із правом виконання.

### Крок 8. Очистити тестову директорію

Якщо більше не потрібні тестові дані, можна видалити створену директорію:

    cd ~
    rm -r ~/linux-file-types

**Увага:** `rm -r` видаляє директорію разом із її вмістом. Перед виконанням переконайся, що шлях правильний.

## 16. Типові помилки

### Помилка 1. Визначати тип лише за розширенням

Файл `photo.jpg` не обов'язково є зображенням.

Перевіряй:

    file photo.jpg

### Помилка 2. Плутати звичайний файл і виконуваний файл

Виконуваність залежить від дозволів і формату вмісту, а не тільки від назви.

Перевіряй:

    ls -l script.sh
    file script.sh

### Помилка 3. Вважати символічне посилання цільовим файлом

Посилання та його ціль — різні об'єкти.

Перевіряй:

    ls -l shortcut.txt
    test -L shortcut.txt && echo "Це посилання"
    test -e shortcut.txt && echo "Ціль доступна"

### Помилка 4. Плутати тип об'єкта і права доступу

У рядку:

    -rwxr-xr-x

- перший `-` — тип звичайного файла;
- `rwxr-xr-x` — права доступу.

### Помилка 5. Вважати, що прихований файл має особливий тип

Назва `.env` може належати звичайному файлу. Крапка на початку імені лише впливає на стандартне відображення.

### Помилка 6. Використовувати `cat` для будь-якого файла

Для бінарних даних краще почати з:

    file filename

Для текстових файлів використовуй:

    less filename

### Помилка 7. Вважати `ctime` часом створення

`ctime` означає час останньої зміни метаданих inode. Це не обов'язково дата створення.

## 19. Що потрібно запам'ятати

✔ У Linux існують звичайні файли, директорії, символічні посилання та спеціальні файлові об'єкти.

✔ Перший символ у виводі `ls -l` показує тип об'єкта.

✔ `file` аналізує вміст і допомагає визначити реальний формат.

✔ `stat` показує метадані, розмір, права та часові характеристики.

✔ `-type f`, `-type d` і `-type l` у `find` дозволяють шукати відповідно звичайні файли, директорії та символічні посилання.

✔ Розширення `.js`, `.jpg`, `.zip` або `.sh` саме по собі не гарантує формат файла.

✔ Право виконання не є окремим типом файла.

✔ Символічне посилання може залишатися після видалення цілі.

✔ `/dev` містить багато спеціальних файлових об'єктів для роботи з пристроями та системними механізмами.

✔ Прихованість файла через крапку на початку імені не є окремим типом.

## 20. Головний принцип

**Тип файла, його вміст і права доступу — це різні характеристики.**

Для перевірки використовуй:

    ls -l filename
    file filename
    stat filename

А для пошуку об'єктів певного типу:

    find . -type f
    find . -type d
    find . -type l

Коли навчишся розрізняти ці характеристики, буде значно простіше працювати з файлами, скриптами, посиланнями та системними каталогами Linux.
