# 📌 1. Що таке приховані файли

**Приховані файли (hidden files)** — це файли, назви яких у Linux починаються з крапки `.`.

Наприклад:

    .bashrc
    .profile
    .gitignore
    .env
    .config/

Звичайна команда `ls` за замовчуванням не показує такі файли.

    ls

А команда:

    ls -a

показує приховані файли та директорії також.

## ✔ Приклад

Припустимо, у домашній директорії є такі файли:

    Documents/
    Downloads/
    projects/
    .bashrc
    .profile
    .config/

Виконуємо:

    ls

Можемо побачити:

    Documents  Downloads  projects

Тепер виконуємо:

    ls -a

Побачимо приблизно:

    .  ..  .bashrc  .config  .profile  Documents  Downloads  projects

Порядок елементів може відрізнятися.

## 🎯 Що потрібно запам'ятати

- Приховані файли зазвичай починаються з крапки.
- `ls` за замовчуванням їх не показує.
- `ls -a` показує всі записи, включно з `.` і `..`.
- `ls -A` показує приховані записи, але не включає спеціальні записи `.` і `..`.
- Прихований файл не є автоматично захищеним або секретним.
- Крапка на початку назви — це звичайна домовленість Unix/Linux, а не механізм безпеки.

# 📌 2. Як Linux визначає приховані файли

## 2.1. Крапка на початку назви

У Linux прихованість файла зазвичай визначається назвою.

Приховані:

    .bashrc
    .gitignore
    .env
    .config/

Не приховані:

    bashrc
    gitignore
    env
    config/

Зверни увагу: файл `.env` прихований, а файл `env` — ні.

## 2.2. Прихованість не залежить від розширення

Прихованими можуть бути файли з різними назвами та розширеннями:

    .config
    .config.json
    .notes.txt
    .backup.tar.gz

Головна умова — крапка на початку назви.

Файл:

    notes.txt

не стане прихованим лише тому, що має розширення `.txt`.

## 2.3. Приховані директорії

Прихованими можуть бути не лише файли, а й директорії.

Наприклад:

    .config/
    .cache/
    .local/
    .ssh/
    .git/

Звичайний `ls` не показуватиме їх без відповідних опцій.

Щоб переглянути приховані директорії:

    ls -a

## 2.4. `.` і `..` — спеціальні записи

Коли виконуєш:

    ls -a

часто побачиш:

    .
    ..

Це спеціальні записи:

- `.` — поточна директорія;
- `..` — батьківська директорія.

Вони не є звичайними прихованими файлами, створеними користувачем.

Щоб побачити приховані записи без `.` і `..`, використовуй:

    ls -A

## 2.5. Прихований файл не обов'язково є системним

Наприклад:

    .my-notes

може бути звичайним текстовим файлом, створеним користувачем.

А:

    .git/

зазвичай містить службові дані Git-репозиторію.

Обидва елементи приховані через крапку на початку назви, але призначення в них різне.

# 📌 3. Перегляд прихованих файлів

## 3.1. Команда `ls -a`

Опція `-a` означає all.

    ls -a

Показує всі записи в поточній директорії, включно з прихованими, `.` і `..`.

Для домашньої директорії:

    ls -a ~

Для конкретного проєкту:

    ls -a ~/projects/nest-exercises

## 3.2. Команда `ls -A`

    ls -A

Показує приховані записи, але не показує `.` і `..`.

Це часто зручніше, коли потрібно побачити вміст директорії без спеціальних записів.

Порівняй:

    ls -a

    ls -A

## 3.3. Команда `ls -la`

Опції можна комбінувати.

    ls -la

Тут:

- `-l` — довгий формат списку;
- `-a` — показувати всі записи.

Результат може містити:

    drwxr-xr-x  5 taubu taubu 4096 Oct 16 17:00 .
    drwxr-xr-x 10 taubu taubu 4096 Oct 16 16:00 ..
    -rw-r--r--  1 taubu taubu  220 Oct 16 16:00 .bashrc
    drwx------  3 taubu taubu 4096 Oct 16 16:30 .config

Це умовний приклад: права, власник, розміри й дати залежать від системи.

## 3.4. Що показує довгий формат

У рядку:

    -rw-r--r-- 1 taubu taubu 220 Oct 16 16:00 .bashrc

можна побачити:

- тип об'єкта та права доступу;
- кількість жорстких посилань;
- власника;
- групу;
- розмір;
- дату й час останньої модифікації;
- назву файла.

Докладніше права доступу розглядатимуться в темі про permissions.

## 3.5. Перегляд конкретного прихованого файла

    ls -l .bashrc

Перегляд прихованої директорії:

    ls -ld .config

Перегляд її вмісту:

    ls -la .config/

Різниця:

- `ls -ld .config` показує саму директорію;
- `ls -la .config/` показує її вміст.

## 3.6. Пошук прихованих файлів за назвою

Можна використати `find`.

Знайти приховані записи безпосередньо в поточній директорії:

    find . -maxdepth 1 -name '.*' -print

Знайти приховані записи рекурсивно:

    find . -name '.*' -print

У другому прикладі команда може показати також записи `.` і `..` для директорій. Щоб виключити їх із результату:

    find . -name '.*' ! -name '.' ! -name '..' -print

`find` корисний, коли потрібно шукати приховані файли у великій структурі директорій.

# 📌 4. Створення прихованих файлів і директорій

## 4.1. Створення прихованого файла

Щоб створити порожній прихований файл, можна використати `touch`.

    touch .notes

Перевір результат:

    ls -a

Можеш побачити:

    .  ..  .notes

Якщо файл уже існує, `touch` зазвичай оновить час його модифікації, а не видалить його вміст.

## 4.2. Створення прихованого файла з текстом

Використовуй перенаправлення:

    echo "My private notes" > .notes

Команда створить файл `.notes` або перезапише його вміст.

**Увага:** оператор `>` перезаписує наявний файл.

Щоб додати текст у кінець файла, використовуй:

    echo "Another note" >> .notes

Оператор `>>` додає дані в кінець файла.

## 4.3. Створення прихованої директорії

    mkdir .my-folder

Перевір:

    ls -a

Можеш побачити:

    .  ..  .my-folder

Створити вкладені директорії:

    mkdir -p .my-folder/documents/notes

Опція `-p` створює відсутні батьківські директорії.

## 4.4. Створення конфігураційного файла

Наприклад, файл `.myconfig`:

    touch .myconfig

Відкрити його у текстовому редакторі VS Code:

    code .myconfig

Якщо команда `code` доступна в терміналі, відкриється файл у VS Code.

## 4.5. Створення прихованого файла в іншій директорії

    touch ~/projects/nest-exercises/.my-notes

Перевір:

    ls -la ~/projects/nest-exercises

Якщо шлях до проєкту правильний, у списку буде `.my-notes`.

## 4.6. Чи можна створити прихований файл без `touch`?

Так.

Наприклад:

    > .notes

Це створить порожній файл `.notes`, якщо його ще немає, або очистить наявний файл.

Безпечніший варіант, якщо потрібно створити файл лише тоді, коли його ще немає:

    touch .notes

Пам'ятай: `touch` не очищає вміст наявного файла, але оновлює його часові мітки.

# 📌 5. Перейменування та видалення

Приховані файли можна перейменовувати й видаляти так само, як звичайні. Головне — правильно вказати назву.

## 5.1. Перейменування файла

Перейменувати звичайний файл на прихований:

    mv notes.txt .notes

Перейменувати прихований файл на звичайний:

    mv .notes notes.txt

Перейменувати один прихований файл на інший:

    mv .old-config .new-config

## 5.2. Видалення прихованого файла

    rm -i .notes

Опція `-i` запитає підтвердження.

Якщо файл непотрібний і ти впевнений у його назві, його можна видалити звичайною командою `rm`.

## 5.3. Видалення прихованої директорії

Порожню директорію можна видалити командою:

    rmdir .my-folder

Непорожню директорію можна видалити рекурсивно:

    rm -ri .my-folder

Перед видаленням перевір вміст:

    ls -la .my-folder

## 5.4. Чому `rm *` не видаляє приховані файли

Команда:

    rm *

у звичайному Bash за типових налаштувань охоплює неприховані імена, але не файли, назви яких починаються з крапки.

Наприклад, вона може видалити:

    notes.txt
    report.txt

але не:

    .notes
    .gitignore

Це стандартна поведінка підстановки шаблонів shell.

**Не намагайся виправляти це командою на кшталт `rm -rf .*`.** Такий шаблон може охоплювати небажані шляхи, зокрема `..`, залежно від шаблону й поведінки shell. Для видалення прихованих файлів краще спочатку переглянути їх через `ls -la`, а потім указати конкретні назви.

# 📌 6. Копіювання прихованих файлів

## 6.1. Копіювання одного прихованого файла

    cp .notes .notes-backup

Створить копію `.notes` під назвою `.notes-backup`.

Обидва файли залишаться в поточній директорії.

## 6.2. Копіювання прихованого файла до іншої директорії

    cp .gitignore backup/

Скопіює `.gitignore` до директорії `backup/`, якщо вона існує.

## 6.3. Копіювання прихованої директорії

    cp -a .config .config-backup

Створить архівну копію директорії `.config` під назвою `.config-backup`.

Опція `-a` допомагає зберегти структуру й атрибути.

## 6.4. Копіювання всіх файлів директорії разом із прихованими

У Bash звичайна команда:

    cp -r project/* project-backup/

не охоплює приховані файли, що лежать безпосередньо в `project/`.

Наприклад, файл `.gitignore` може не потрапити до копії.

Якщо потрібно скопіювати всю директорію разом із прихованими файлами, найпростіше скопіювати саму директорію:

    cp -a project project-backup

Якщо директорія призначення вже існує, поведінка буде залежати від її структури, тому перевір результат після копіювання.

## 6.5. Чому важливо зберігати приховані файли

У програмних проєктах приховані файли можуть містити важливу конфігурацію.

Наприклад:

    .gitignore
    .npmrc
    .editorconfig
    .env.example

Якщо під час копіювання проєкту пропустити такі файли, проєкт може працювати не так, як очікується.

# 📌 7. Приховані файли в Linux-проєктах

У розробці програмного забезпечення приховані файли часто використовуються для конфігурації інструментів і керування проєктом.

## 7.1. Файл `.bashrc`

Шлях:

    ~/.bashrc

Це конфігураційний файл Bash, який зазвичай використовується для налаштування інтерактивних оболонок.

У ньому можуть бути:

- псевдоніми команд;
- налаштування prompt;
- змінні середовища;
- інші команди налаштування оболонки.

Переглянути файл:

    cat ~/.bashrc

Відкрити в редакторі:

    code ~/.bashrc

Змінюй системні налаштування обережно та бажано створюй резервну копію перед редагуванням.

## 7.2. Директорія `.config`

Шлях:

    ~/.config/

У ній багато програм зберігають налаштування користувача.

Переглянути:

    ls -la ~/.config

## 7.3. Директорія `.cache`

Шлях:

    ~/.cache/

Тут програми часто зберігають кеш.

Переглянути вміст:

    ls -la ~/.cache

Не видаляй увесь кеш автоматично: деякі програми можуть потребувати повторного завантаження або створення даних.

## 7.4. Директорія `.ssh`

Шлях:

    ~/.ssh/

У ній можуть міститися SSH-ключі та конфігурація SSH.

Переглянути список файлів:

    ls -la ~/.ssh

Наприклад, там можуть бути:

    config
    id_ed25519
    id_ed25519.pub
    known_hosts

Назви залежать від конфігурації користувача.

**Важливо:** приватні SSH-ключі, наприклад `id_ed25519`, не можна передавати іншим людям або публікувати в репозиторії.

Файл із розширенням `.pub` зазвичай є відкритим ключем, який призначений для поширення відповідно до правил SSH.

## 7.5. Директорія `.git`

У Git-репозиторії директорія `.git` зазвичай містить внутрішні дані Git.

Переглянути її:

    ls -la .git

Якщо команда `ls` не показує `.git`, переконайся, що ти перебуваєш у корені репозиторію.

Перевірити:

    git status

Не видаляй `.git` без розуміння наслідків: це може позбавити локальну директорію історії та метаданих Git-репозиторію.

## 7.6. Файл `.gitignore`

Файл `.gitignore` визначає, які файли й директорії Git має ігнорувати під час звичайного пошуку змін для відстеження.

Наприклад, у JavaScript-проєкті він може містити:

    node_modules/
    .next/
    dist/
    .env

Переглянути:

    cat .gitignore

**Важливо:** `.gitignore` не видаляє файли й не перестає відстежувати файли, які вже були додані до Git. Він впливає на файли, які Git ще не відстежує.

## 7.7. Файл `.env`

Файл `.env` часто використовують для локальних змінних середовища.

Наприклад:

    DATABASE_URL=postgresql://localhost:5432/example
    API_PORT=3000

Такий файл може містити секрети: паролі, токени, ключі доступу.

Тому:

- не додавай справжній `.env` до публічного репозиторію;
- додай `.env` до `.gitignore`, якщо це відповідає структурі проєкту;
- використовуй `.env.example` для демонстрації потрібних назв змінних без секретних значень;
- не вважай файл безпечним лише тому, що він прихований.

# 📌 8. Приховані файли та безпека

## 8.1. Прихований не означає захищений

Назва:

    .passwords.txt

не робить файл безпечним.

Будь-який користувач, який має відповідні права доступу, може спробувати прочитати його.

Прихованість — це спосіб організації файлів, а не контроль доступу.

## 8.2. Перевірка прав доступу

Переглянути права прихованого файла:

    ls -l .env

Переглянути права прихованої директорії:

    ls -ld .ssh

Приклад:

    -rw------- 1 taubu taubu 120 Oct 16 17:00 .env

У цьому умовному прикладі файл доступний для читання й запису лише власнику.

Фактичні права потрібно перевіряти у своїй системі.

## 8.3. Не публікуй секрети

Небезпечні приклади даних у репозиторії:

    DB_PASSWORD=real-password
    API_TOKEN=real-secret-token

Не розміщуй справжні паролі, токени або приватні ключі в публічних файлах.

Навіть якщо файл називається `.env` і його не видно через звичайний `ls`, він усе одно може потрапити до Git або бути прочитаний іншим користувачем із відповідними правами.

## 8.4. Резервна копія конфігурації

Перед редагуванням важливого прихованого файла можна створити копію:

    cp -i ~/.bashrc ~/.bashrc.backup

Після цього редагуй оригінал.

Зверни увагу: `.bashrc.backup` також буде прихованим, оскільки його назва починається з крапки.

# 📌 9. Шаблони та приховані файли

## 9.1. Чому `*` не охоплює приховані файли

У Bash за звичайних налаштувань шаблон:

    *

не відповідає іменам, що починаються з крапки.

Наприклад, у директорії є:

    README.md
    app.js
    .gitignore
    .env

Команда:

    ls *

зазвичай покаже `README.md` та `app.js`, але не `.gitignore` і `.env`.

Щоб переглянути все, використовуй:

    ls -la

## 9.2. Шаблон `.*`

Шаблон:

    .*

може відповідати прихованим іменам, але також має особливості, пов'язані зі спеціальними записами `.` і `..`.

Тому не використовуй його бездумно з командами видалення.

Наприклад, уникай:

    rm -rf .*

Для пошуку прихованих файлів краще використовувати:

    find . -maxdepth 1 -name '.*' -print

Ця команда виводить приховані записи безпосередньо в поточній директорії. За потреби результат можна додатково відфільтрувати.

## 9.3. Копіювання звичайних і прихованих файлів

Команда:

    cp -r source/* destination/

зазвичай копіює неприховані записи, що відповідають `source/*`.

Щоб скопіювати всю директорію разом із прихованими файлами:

    cp -a source destination

Це зазвичай зрозуміліший і надійніший підхід, якщо потрібна повна копія директорії.

# 📌 10. Типові помилки

## ❌ Помилка 1. Звичайний `ls` не показує `.env`

Команда:

    ls

не показує приховані файли за замовчуванням.

Правильно:

    ls -a

Або:

    ls -la

## ❌ Помилка 2. Файл не знаходиться через неправильну назву

Наприклад, команда:

    cat env

не прочитає файл `.env`, тому що це різні назви.

Правильно:

    cat .env

## ❌ Помилка 3. Вважаєш прихований файл захищеним

Назва `.secret` не обмежує доступ до файла.

Перевіряй права:

    ls -l .secret

Для секретних даних використовуй належні права доступу та безпечне зберігання.

## ❌ Помилка 4. `cp *` пропускає приховані файли

Команда:

    cp -r source/* destination/

не охоплює приховані записи за звичайних налаштувань Bash.

Для копіювання всієї директорії:

    cp -a source destination

## ❌ Помилка 5. Видалення через `rm -rf .*`

Не використовуй цю команду:

    rm -rf .*

Шаблон може охопити не ті записи, які ти очікуєш, і спричинити небажане видалення.

Спочатку переглянь список:

    ls -la

Потім працюй із конкретними назвами.

## ❌ Помилка 6. Випадково перезаписаний файл через `>`

Команда:

    echo "new content" > .notes

перезапише вміст `.notes`, якщо файл уже існує.

Якщо потрібно додати текст:

    echo "additional content" >> .notes

Якщо потрібно просто створити файл або оновити його часові мітки без очищення вмісту:

    touch .notes

## ❌ Помилка 7. Випадково видалена директорія `.git`

Директорія `.git` містить внутрішні дані Git-репозиторію.

Не видаляй її як звичайний непотрібний каталог без розуміння наслідків.

Перевір поточний репозиторій:

    git status

## ❌ Помилка 8. Секрети потрапили до Git

Якщо `.env` уже відстежується Git, додавання його до `.gitignore` не припинить відстеження автоматично.

Перевір:

    git status

Якщо потрібно припинити відстежувати файл, але залишити його на диску, для відповідного репозиторію можна використати:

    git rm --cached .env

Перед виконанням перевір стан репозиторію та переконайся, що розумієш наслідки команди.

Якщо секрет уже потрапив до публічного репозиторію, простого видалення файла недостатньо: секрет може залишитися в історії Git. Такий секрет потрібно вважати скомпрометованим і замінити.

Команда знайде приховані записи у вкладених директоріях, крім спеціальних записів `.` і `..`.

## 11.7. Практика з Git

Перейди до репозиторію:

## 11.8. Безпечне видалення навчальних файлів

Працюй лише з навчальними даними, які не шкода втратити.

# 📌 14. Мінішпаргалка

## Перегляд

    ls

Показати звичайні файли.

    ls -a

Показати всі записи, включно з `.` і `..`.

    ls -A

Показати приховані записи без `.` і `..`.

    ls -la

Показати всі записи в довгому форматі.

    ls -ld .config

Показати саму приховану директорію.

    ls -la .config/

Показати вміст прихованої директорії.

## Створення

    touch .notes

Створити прихований файл.

    mkdir .private

Створити приховану директорію.

    mkdir -p .private/documents/notes

Створити вкладені приховані директорії.

## Перейменування та копіювання

    mv notes.txt .notes.txt

Зробити файл прихованим через перейменування.

    mv .notes.txt notes.txt

Перейменувати прихований файл на звичайний.

    cp .notes .notes-backup

Скопіювати прихований файл.

    cp -a .config .config-backup

Скопіювати приховану директорію зі збереженням атрибутів.

## Видалення

    rm -i .notes

Видалити прихований файл із підтвердженням.

    rmdir .empty-folder

Видалити порожню приховану директорію.

    rm -ri .private

Видалити приховану директорію разом із вмістом із підтвердженням.

## Пошук

    find . -maxdepth 1 -name '.*' -print

Знайти приховані записи безпосередньо в поточній директорії.

    find . -name '.*' ! -name '.' ! -name '..' -print

Знайти приховані записи рекурсивно, виключивши `.` і `..`.

## Важливі приховані файли

    ~/.bashrc

Конфігурація Bash.

    ~/.config/

Налаштування багатьох програм.

    ~/.cache/

Кеш багатьох програм.

    ~/.ssh/

SSH-конфігурація та ключі.

    .git/

Внутрішні дані Git-репозиторію.

    .gitignore

Правила ігнорування файлів Git.

    .env

Файл змінних середовища, який може містити секрети.
