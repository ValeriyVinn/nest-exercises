# 03. Terminal and Shell — Термінал і командна оболонка

Термінал і shell — основні інструменти роботи в Linux. Вони дають змогу керувати файлами, запускати програми, працювати з процесами, налаштовувати систему та автоматизувати завдання за допомогою команд.

Для backend-розробника знання термінала необхідне під час роботи з Node.js, npm, Git, PostgreSQL, SSH, серверами та розгортанням застосунків.

## 1. Що таке термінал і shell?

Це пов'язані, але різні поняття.

### 1.1. Terminal — термінал

**Термінал** — це інтерфейс, у якому ти вводиш команди та бачиш їхній результат.

У сучасному Linux термінал зазвичай є графічною програмою, яка відкриває текстовий інтерфейс для взаємодії із shell.

Приклади термінальних програм:

- GNOME Terminal;
- Konsole;
- Xfce Terminal;
- Tilix;
- Alacritty.

У Ubuntu можна відкрити термінал через меню програм або комбінацією клавіш `Ctrl + Alt + T` (залежно від налаштувань робочого середовища).

Приклад команди в терміналі:

    pwd

Результат може бути таким:

    /home/taubu/projects

Команда `pwd` показує поточну робочу директорію.

### 1.2. Shell — командна оболонка

**Shell** — це програма, яка приймає команди, інтерпретує їх і запускає відповідні програми.

Shell також підтримує змінні, умови, цикли, функції, перенаправлення введення та виведення, конвеєри команд і сценарії.

Популярні shell:

| Shell | Опис |
|---|---|
| Bash | Bash — поширена оболонка Linux, зручна для командного рядка та Bash-скриптів |
| Zsh | Розширена оболонка з гнучким налаштуванням і доповненням команд |
| Fish | Оболонка з дружнім інтерактивним інтерфейсом |
| Dash | Легка POSIX-сумісна оболонка, яку часто використовують для системних сценаріїв |
| Sh | Назва традиційної Unix-оболонки та сумісного командного інтерфейсу; конкретна реалізація залежить від системи |

У твоєму Ubuntu типовою інтерактивною оболонкою, найімовірніше, є Bash. Перевірити це можна командами нижче.

    echo "$SHELL"

Приклад результату:

    /bin/bash

Це показує оболонку, зазначену як оболонка входу користувача. Щоб перевірити саме поточний процес shell, можна виконати:

    ps -p $$ -o comm=

Приклад результату:

    bash

**Запам'ятай:**
- Terminal — вікно або програма для роботи з командним рядком.
- Shell — програма, яка обробляє команди.
- Bash — один із різновидів shell.
- Команди виконуються не «терміналом», а програмами, які запускає shell.

## 2. Як працює взаємодія з командним рядком

Зазвичай процес виглядає так:

    Користувач вводить команду
            ↓
    Terminal передає введення shell
            ↓
    Shell розбирає команду
            ↓
    Shell виконує вбудовану команду
    або запускає зовнішню програму
            ↓
    Програма повертає результат
            ↓
    Результат відображається в терміналі

Наприклад:

    ls -la

Shell розбирає команду, знаходить програму `ls`, передає їй аргументи `-la`, а програма показує вміст поточної директорії.

Не кожна команда є окремою програмою. Деякі команди, наприклад `cd`, є вбудованими командами shell.

Перевірити тип команди можна так:

    type cd
    type ls
    type pwd

Можливий результат:

    cd is a shell builtin
    ls is /usr/bin/ls
    pwd is a shell builtin

Точний результат залежить від системи та налаштувань.

## 3. Що таке командний рядок (CLI)?

**CLI (Command-Line Interface)** — текстовий інтерфейс для керування програмами та системою за допомогою команд.

CLI є альтернативою або доповненням до графічного інтерфейсу (GUI).

### GUI — Graphical User Interface

Графічний інтерфейс використовує вікна, меню, кнопки та значки.

Приклади:
- відкривання папок у файловому менеджері;
- встановлення програм через графічний центр програм;
- переміщення файлів мишею.

### CLI — Command-Line Interface

Командний інтерфейс використовує текстові команди.

Приклади:

    pwd
    ls
    cd projects
    mkdir demo
    touch README.md

### Чому розробнику потрібен CLI?

За допомогою командного рядка можна:

- швидко переміщуватися між директоріями;
- створювати, копіювати та видаляти файли;
- запускати Node.js і npm;
- керувати Git-репозиторіями;
- працювати з базами даних;
- встановлювати та оновлювати програми;
- переглядати процеси й системні журнали;
- підключатися до віддалених серверів через SSH;
- запускати сценарії автоматизації.

**Важливо:** графічний інтерфейс і CLI не конкурують між собою. У повсякденній роботі розробник часто використовує обидва.

## 4. Як читати командний рядок

Коли ти відкриваєш термінал, зазвичай бачиш запрошення shell — **prompt**.

Наприклад:

    taubu@taubu-lap:~/projects$

Розберемо його складові:

| Частина | Значення |
|---|---|
| `taubu` | Ім'я користувача |
| `@` | Роздільник між користувачем і комп'ютером |
| `taubu-lap` | Ім'я комп'ютера (hostname) |
| `:` | Роздільник |
| `~/projects` | Поточна директорія |
| `$` | Типовий символ запрошення звичайного користувача |

Символ `~` означає домашню директорію поточного користувача.

Наприклад:

    ~
    ~/projects
    ~/projects/nest-exercises

Це скорочені форми шляхів:

    /home/taubu
    /home/taubu/projects
    /home/taubu/projects/nest-exercises

### 4.1. Символи `$` і `#`

У традиційному оформленні prompt:

- `$` зазвичай позначає звичайного користувача;
- `#` зазвичай позначає користувача root.

Наприклад:

    taubu@taubu-lap:~$

    root@server:~#

Це лише поширена домовленість оформлення prompt, а не універсальна гарантія прав користувача.

**Не потрібно постійно працювати від root.** Для адміністративних операцій в Ubuntu зазвичай використовують `sudo`.

### 4.2. Командний рядок — це не частина команди

Якщо бачиш:

    taubu@taubu-lap:~/projects$ pwd

Вводити потрібно лише:

    pwd

Сам prompt вводити не потрібно.

## 5. Основна структура команди

Багато команд мають таку структуру:

    command [options] [arguments]

Де:

- `command` — назва команди;
- `options` — параметри, які змінюють поведінку команди;
- `arguments` — об'єкти, з якими працює команда: файли, директорії, назви пакетів тощо;
- квадратні дужки в описах означають необов'язкові елементи — їх не потрібно вводити буквально.

Приклад:

    ls -l /home/taubu

Розбір:

- `ls` — команда;
- `-l` — параметр, який виводить детальний список;
- `/home/taubu` — аргумент, шлях до директорії.

Ще приклади:

    pwd
    ls -a
    mkdir practice
    cp notes.txt backup.txt
    mv old.txt new.txt

### 5.1. Короткі та довгі параметри

Параметри часто мають коротку та довгу форму.

    ls -a
    ls --all

Обидві команди показують приховані файли разом зі звичайними.

Інший приклад:

    ls -l
    ls --format=long

Не кожна команда має однакові варіанти параметрів. Завжди перевіряй довідку конкретної команди.

### 5.2. Кілька коротких параметрів

Деякі короткі параметри можна об'єднувати.

    ls -l -a
    ls -la
    ls -al

У цьому прикладі всі варіанти виводять детальний список із прихованими файлами.

Однак об'єднувати параметри можна не завжди: це залежить від синтаксису конкретної програми.

### 5.3. Аргументи з пробілами

Якщо назва файлу або директорії містить пробіли, використовуй лапки.

    mkdir "my project"
    cd "my project"
    touch "my notes.txt"

Без лапок shell зазвичай сприйме частини назви як окремі аргументи.

Також можна екранувати пробіли символом `\`:

    mkdir my\ project

Для початку простіше використовувати лапки.

## 6. Як shell знаходить команди

Коли ти вводиш:

    ls

Shell має визначити, що саме потрібно запустити.

Зазвичай це відбувається одним із двох способів:

1. Shell розпізнає вбудовану команду, наприклад `cd`.
2. Shell шукає зовнішню програму у директоріях, перелічених у змінній середовища `PATH`.

### 6.1. Що таке PATH?

`PATH` — змінна середовища, яка містить список директорій, де shell шукає виконувані програми.

Переглянути її:

    echo "$PATH"

Результат може бути приблизно таким:

    /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Двокрапка `:` розділяє директорії.

Якщо програма встановлена в одній із цих директорій, її часто можна запускати просто за назвою.

    node --version
    npm --version
    git --version

Якщо shell не знаходить програму, ти можеш отримати помилку:

    command not found

Це не завжди означає, що програми взагалі немає. Можливо, вона не встановлена, не входить до `PATH` або назву введено неправильно.

### 6.2. Де знаходиться програма?

Використовуй:

    command -v node
    command -v npm
    command -v git

Приклад результату:

    /home/taubu/.nvm/versions/node/v24.21.0/bin/node

Точний шлях залежить від способу встановлення.

Для пошуку зовнішньої програми також можна використати:

    which node

Проте `command -v` зручніша для загальної перевірки, оскільки працює з вбудованими командами shell і зовнішніми програмами.

### 6.3. Запуск програми з поточної директорії

У Linux поточна директорія зазвичай не додається до `PATH` автоматично.

Якщо в поточній директорії є виконуваний файл `script.sh`, запуск може виглядати так:

    ./script.sh

Тут `./` означає «у поточній директорії».

Не варто додавати поточну директорію до `PATH` без розуміння наслідків для безпеки.

## 7. Змінні shell

Змінна — це ім'я, якому присвоєно значення.

Приклад:

    project="nest-exercises"
    echo "$project"

Результат:

    nest-exercises

У Bash під час присвоєння значення не можна ставити пробіли навколо `=`.

Правильно:

    name="Valeriy"

Неправильно:

    name = "Valeriy"

У другому випадку Bash спробує сприйняти `name` як команду.

### 7.1. Виведення значення

    city="Vinnytsia"
    echo "$city"

Для виведення значення змінної використовують `$`:

    echo "$HOME"
    echo "$USER"
    echo "$SHELL"
    echo "$PATH"

Типові змінні середовища:

| Змінна | Значення |
|---|---|
| `HOME` | Домашня директорія користувача |
| `USER` | Ім'я користувача в типовій конфігурації |
| `SHELL` | Оболонка входу користувача |
| `PATH` | Директорії пошуку виконуваних програм |
| `PWD` | Поточна робоча директорія |
| `OLDPWD` | Попередня робоча директорія після відповідного переходу |

### 7.2. Змінна та змінна середовища — не те саме

Звичайна змінна Bash доступна в поточній оболонці.

Змінну середовища можна передати дочірнім процесам.

Приклад:

    project="demo"
    export APP_ENV="development"

Команда `export` позначає змінну для передавання дочірнім процесам.

Перевірити:

    echo "$APP_ENV"
    printenv APP_ENV

Можна також передати змінну лише на час запуску однієї команди:

    APP_ENV=development node app.js

Це поширений спосіб передавати конфігурацію застосункам, зокрема Node.js.

## 8. Поточна директорія та команди переходу

Термінал завжди має поточну робочу директорію.

Перевірити її:

    pwd

Переглянути вміст:

    ls
    ls -l
    ls -la

Перейти до іншої директорії:

    cd projects
    cd nest-exercises
    cd ..

Основні позначення шляхів:

| Позначення | Значення |
|---|---|
| `.` | Поточна директорія |
| `..` | Батьківська директорія |
| `~` | Домашня директорія |
| `/` | Корінь файлової системи |
| `-` у `cd -` | Повернення до попередньої робочої директорії |

Приклади:

    cd ~
    cd /
    cd ..
    cd -
    cd ~/projects/nest-exercises

### Абсолютний і відносний шлях

Абсолютний шлях починається з `/`.

    /home/taubu/projects/nest-exercises

Відносний шлях указується відносно поточної директорії.

    projects/nest-exercises

Якщо ти перебуваєш у `/home/taubu`, обидва шляхи ведуть до тієї самої директорії.

**Запам'ятай:** `cd` змінює поточну директорію самого shell. Саме тому `cd` є вбудованою командою, а не просто окремою програмою.

## 9. Вбудовані команди та зовнішні програми

У Linux команди можуть бути різних типів.

### 9.1. Вбудовані команди shell

Вбудовані команди виконуються самою оболонкою.

Приклади:

    cd
    echo
    export
    alias
    type
    read

Їхня поведінка часто пов'язана зі станом поточного shell.

Наприклад, окрема зовнішня програма не могла б звичайним способом змінити поточну директорію батьківського shell, тому `cd` виконується всередині нього.

### 9.2. Зовнішні програми

Це окремі виконувані файли.

Приклади:

    ls
    cat
    grep
    find
    mkdir
    cp
    mv
    git
    node

Більшість стандартних утиліт Linux — зовнішні програми, хоча реалізація залежить від системи.

### 9.3. Як перевірити тип команди?

    type cd
    type ls
    type git

Для додаткової інформації:

    command -V cd
    command -V ls

Не потрібно запам'ятовувати, які команди вбудовані. Достатньо знати, як перевірити це самостійно.

## 10. Як shell обробляє команди

Shell — це не лише засіб запуску програм. Він також має власний синтаксис.

### 10.1. Кілька команд в одному рядку

Символ `;` розділяє команди. Наступна команда виконується незалежно від коду завершення попередньої.

    pwd; ls; whoami

Символ `&&` виконує наступну команду лише тоді, коли попередня завершилася успішно.

    mkdir practice && cd practice

Символ `||` виконує наступну команду, якщо попередня завершилася з помилкою.

    cd unknown-directory || echo "Directory not found"

Важливо: shell орієнтується на код завершення команди, а не на те, чи виглядає її текстовий результат правильним.

### 10.2. Код завершення

У Linux програми зазвичай повертають код завершення:

- `0` — успішне виконання;
- ненульове значення — помилка або інший стан, визначений програмою.

Перевірити код останньої команди в Bash:

    echo "$?"

Наприклад:

    true
    echo "$?"

Результат:

    0

Інший приклад:

    false
    echo "$?"

Результат:

    1

Команди `true` і `false` — прості вбудовані команди Bash, корисні для навчання.

Зверни увагу: `echo "$?"` показує код завершення саме попередньої команди. Якщо між ними запустити іншу команду, значення зміниться.

### 10.3. Перенаправлення виведення

Символ `>` записує стандартне виведення у файл, замінюючи його попередній вміст.

    echo "Hello Linux" > message.txt

Символ `>>` додає виведення в кінець файлу.

    echo "Second line" >> message.txt

Прочитати файл:

    cat message.txt

Перенаправити повідомлення про помилки:

    ls missing-file 2> error.log

Основні потоки:

| Позначення | Значення |
|---|---|
| `stdin` | Стандартне введення, файловий дескриптор `0` |
| `stdout` | Стандартне виведення, файловий дескриптор `1` |
| `stderr` | Стандартне виведення помилок, файловий дескриптор `2` |
| `>` | Перенаправлення стандартного виведення |
| `>>` | Додавання стандартного виведення в кінець файлу |
| `2>` | Перенаправлення стандартного потоку помилок |

### 10.4. Конвеєр (pipe)

Символ `|` передає стандартне виведення однієї команди на стандартне введення іншої.

    ls -la | less

Тут список передається програмі `less`, яка дозволяє переглядати його посторінково.

Інший приклад:

    cat /etc/os-release | grep PRETTY_NAME

Команда `grep` відбирає рядки, які містять `PRETTY_NAME`.

У цьому простому прикладі `cat` можна не використовувати:

    grep PRETTY_NAME /etc/os-release

**Запам'ятай:** конвеєр поєднує команди так, щоб результат однієї міг стати вхідними даними іншої.

## 11. Інтерактивна робота із shell

Коли ти працюєш у терміналі, shell допомагає вводити команди швидше.

### 11.1. Автодоповнення — Tab

Клавіша `Tab` допомагає доповнювати:

- назви команд;
- назви файлів;
- назви директорій;
- деякі аргументи команд.

Наприклад, якщо існує директорія `nest-exercises`, можна почати вводити:

    cd nest<Tab>

Якщо є лише один відповідний варіант, shell може доповнити назву автоматично. Якщо варіантів декілька, повторне натискання `Tab` може показати список можливостей.

Автодоповнення залежить від shell, налаштувань і встановлених пакетів. У різних системах поведінка може відрізнятися.

### 11.2. Історія команд

Shell зберігає історію введених команд.

Переглянути історію:

    history

Повторно виконати попередню команду можна клавішею `↑`, а для переходу вперед по історії — `↓`.

У Bash можна шукати команду за текстом через:

    Ctrl + R

Введи частину команди, щоб знайти відповідний запис. Повторне натискання `Ctrl + R` переходить до попередніх збігів.

Запуск команди з історії за її номером:

    !123

Це виконає команду з номером `123` у списку історії. Використовуй цей механізм уважно, особливо якщо команда може змінювати або видаляти дані.

### 11.3. Редагування поточного рядка

Корисні комбінації клавіш Bash:

| Комбінація | Дія |
|---|---|
| `Ctrl + A` | Перейти на початок рядка |
| `Ctrl + E` | Перейти в кінець рядка |
| `Ctrl + U` | Видалити текст від курсора до початку рядка |
| `Ctrl + K` | Видалити текст від курсора до кінця рядка |
| `Ctrl + W` | Видалити слово перед курсором |
| `Alt + B` | Переміститися на слово назад |
| `Alt + F` | Переміститися на слово вперед |
| `Ctrl + L` | Очистити видиму область термінала |

На деяких клавіатурах або в окремих терміналах комбінації з `Alt` можуть працювати інакше.

### 11.4. Переривання та призупинення команди

`Ctrl + C` зазвичай надсилає поточному процесу сигнал переривання `SIGINT`.

Наприклад, якщо програма зависла або ти запустив команду, яку хочеш зупинити, спробуй:

    Ctrl + C

`Ctrl + Z` зазвичай призупиняє поточне завдання в інтерактивному shell, надсилаючи сигнал `SIGTSTP`.

Це не те саме, що завершення програми: призупинене завдання можна відновити.

Команди для роботи із завданнями:

    jobs
    fg
    bg

- `jobs` — показує завдання, якими керує поточний shell;
- `fg` — повертає завдання на передній план;
- `bg` — відновлює призупинене завдання у фоновому режимі, якщо це можливо.

### 11.5. Очищення термінала

    clear

Або:

    Ctrl + L

Ці дії очищають видиму область термінала, але не обов'язково видаляють історію команд.

## 12. Права доступу та виконання команд

Не кожну команду можна виконати без відповідних прав.

Наприклад, звичайний користувач може не мати дозволу змінювати системні файли.

В Ubuntu для адміністративних операцій часто використовують `sudo`.

Приклад:

    sudo apt update

Команда попросить пароль користувача, якщо цього вимагає конфігурація.

Під час введення пароля символи можуть не відображатися. Це нормальна поведінка термінала: введи пароль і натисни `Enter`.

### 12.1. Не запускай усе через sudo

Не потрібно додавати `sudo` до кожної команди.

Наприклад, для перегляду домашньої директорії зазвичай достатньо:

    ls -la ~

А ось для деяких системних змін потрібні підвищені права.

**Правило:** запускай із `sudo` лише ті команди, яким справді потрібні адміністративні привілеї.

### 12.2. Особлива обережність із командами

Перед виконанням незнайомої команди:

1. Перевір, що саме вона робить.
2. Переглянь її довідку.
3. Переконайся, що правильно вказав шлях.
4. Особливо уважно перевір команди з `sudo`, перенаправленням `>` і видаленням файлів.
5. Не копіюй сліпо команди з інтернету, якщо не розумієш їхньої дії.

Наприклад, перенаправлення:

    command > file.txt

може замінити вміст `file.txt`. Це не просто виведення тексту на екран.

## 13. Які shell налаштування використовують

У Bash користувацькі налаштування часто зберігаються у файлах домашньої директорії.

Основні файли:

| Файл | Призначення |
|---|---|
| `~/.bashrc` | Налаштування інтерактивного Bash |
| `~/.profile` | Налаштування середовища під час входу; використання залежить від конфігурації |
| `~/.bash_profile` | Один із можливих файлів налаштування Bash під час входу |
| `~/.bash_history` | Файл з історією команд Bash у типовій конфігурації |

Переглянути вміст:

    cat ~/.bashrc

Для довгих файлів зручніше:

    less ~/.bashrc

Не змінюй конфігураційні файли навмання. Помилка в `~/.bashrc` може спричинити проблеми під час відкривання інтерактивного Bash.

### 13.1. Аліаси (aliases)

Аліас — це коротке ім'я для команди або набору параметрів.

Приклад:

    alias ll='ls -lah'

Тепер команда:

    ll

виконуватиме відповідний виклик `ls` у поточному shell.

Переглянути визначені аліаси:

    alias

Видалити аліас у поточній оболонці:

    unalias ll

Щоб зберегти аліас для наступних інтерактивних сесій Bash, його часто додають у `~/.bashrc`.

Приклад рядка у `~/.bashrc`:

    alias ll='ls -lah'

Після редагування можна перечитати файл у поточному shell:

    source ~/.bashrc

Аліаси призначені переважно для інтерактивного використання. Для складніших повторюваних завдань краще створювати функції або окремі скрипти.

## 14. Shell і термінал у роботі backend-розробника

Під час розробки ти регулярно використовуватимеш командний рядок.

### 14.1. Перевірка середовища

    pwd
    whoami
    hostname
    echo "$SHELL"
    node --version
    npm --version
    git --version

Ці команди допомагають перевірити поточну директорію, користувача, ім'я комп'ютера, оболонку та версії інструментів.

### 14.2. Робота з проєктом

    cd ~/projects
    ls
    cd nest-exercises
    pwd
    git status

Такий порядок допомагає переконатися, що ти перебуваєш у правильному репозиторії.

### 14.3. Запуск Node.js

    node --version
    npm --version

Якщо в поточній директорії є Node.js-проєкт із відповідним `package.json`, залежності можна встановити командою:

    npm install

Якщо `package.json` містить сценарій `dev`, його часто запускають так:

    npm run dev

Назви сценаріїв залежать від конкретного проєкту. Перед запуском можна переглянути `package.json`.

### 14.4. Передавання результатів команд

Можна записати результат команди у файл:

    git status > git-status.txt

Або додати новий результат у кінець файлу:

    date >> command-log.txt

Для пошуку рядків у результаті:

    history | grep npm

Це приклади того, як shell поєднує різні програми в один робочий процес.

## 15. Типові помилки початківця

### Помилка 1. Плутати terminal і shell

**Неправильно:** вважати, що термінал і Bash — одна й та сама програма.

**Правильно:** термінал надає інтерфейс, а shell обробляє команди.

### Помилка 2. Вводити prompt разом із командою

Якщо бачиш:

    taubu@taubu-lap:~/projects$

вводити потрібно лише саму команду, наприклад `pwd`.

### Помилка 3. Ставити пробіли навколо `=` у змінній

Неправильно:

    project = "demo"

Правильно:

    project="demo"

### Помилка 4. Не враховувати пробіли в назвах

Неправильно:

    cd my project

Правильно:

    cd "my project"

### Помилка 5. Не розуміти різницю між `>` і `>>`

    echo "New content" > notes.txt

замінює попередній вміст файла.

    echo "Additional content" >> notes.txt

додає текст у кінець файла.

### Помилка 6. Вважати, що `Ctrl + Z` завершує програму

`Ctrl + Z` зазвичай призупиняє поточне завдання. Для звичайного переривання команди використовують `Ctrl + C`.

### Помилка 7. Вважати, що будь-яка команда є окремою програмою

`cd` — вбудована команда Bash. `ls` зазвичай є зовнішньою програмою.

Перевіряти тип можна через:

    type cd
    type ls

### Помилка 8. Використовувати sudo без потреби

Не додавай `sudo` автоматично до всіх команд. Підвищені привілеї потрібні лише для відповідних адміністративних операцій.

### Помилка 9. Вважати, що PATH містить усі директорії

Shell шукає зовнішні програми у директоріях із `PATH`. Поточна директорія зазвичай не включена до нього автоматично.

Для запуску виконуваного файла з поточної директорії використовуй `./ім'я-файла`, якщо це відповідає його типу та правам доступу.

## 16. Практика

Мета практики — навчитися впевнено користуватися терміналом і розуміти базову поведінку Bash.

### Вправа 1. Дослідження середовища

Виконай команди:

    pwd
    whoami
    hostname
    echo "$SHELL"
    echo "$HOME"
    echo "$PATH"

Завдання:

- визнач свою поточну директорію;
- дізнайся ім'я користувача;
- перевір оболонку входу;
- знайди домашню директорію;
- подивись, які директорії входять до `PATH`.

### Вправа 2. Перевірка типів команд

Виконай:

    type cd
    type pwd
    type ls
    type git

Завдання:

- визнач, які команди вбудовані;
- перевір, де розташовані зовнішні програми;
- поясни, чому `cd` має бути вбудованою командою shell.

### Вправа 3. Робота зі змінними

Виконай:

    project="linux-practice"
    echo "$project"

    export APP_ENV="development"
    printenv APP_ENV

Завдання:

- створи звичайну змінну;
- виведи її значення;
- створи змінну середовища;
- перевір її значення через `printenv`.

### Вправа 4. Кілька команд в одному рядку

Виконай:

    pwd; whoami; hostname

Потім:

    true && echo "Success"

І нарешті:

    false || echo "Previous command failed"

Завдання:

- поясни різницю між `;`, `&&` і `||`;
- перевір код завершення команди через `echo "$?"`.

### Вправа 5. Перенаправлення

Створи файл і запиши в нього текст:

    echo "First line" > practice.txt
    echo "Second line" >> practice.txt
    cat practice.txt

Завдання:

- поясни різницю між `>` і `>>`;
- перевір, що обидва рядки збереглися;
- не використовуй `sudo`, оскільки для цієї вправи достатньо прав звичайного користувача.

### Вправа 6. Конвеєр команд

Виконай:

    grep PRETTY_NAME /etc/os-release

Потім:

    cat /etc/os-release | grep PRETTY_NAME

Завдання:

- порівняй результати;
- поясни, як працює `|`;
- подумай, чому в першому прикладі `cat` не потрібен.

### Вправа 7. Історія та навігація

1. Виконай декілька команд.
2. Натисни `↑`, щоб повернутися до попередньої команди.
3. Натисни `Ctrl + R` і знайди команду, яку вводив раніше.
4. Використай `Ctrl + L` для очищення видимої області термінала.
5. Перевір, чи залишилася історія доступною.

### Вправа 8. Мінісценарій для backend-розробника

Перейди до свого репозиторію:

    cd ~/projects/nest-exercises

Перевір середовище:

    pwd
    git status
    node --version
    npm --version

Завдання:

- переконайся, що ти перебуваєш у правильному репозиторії;
- перевір доступність Node.js та npm;
- поясни, яка програма виконує кожну команду;
- не запускай встановлення залежностей або інші зміни, якщо вони не потрібні для цієї вправи.

## 17. Рівні засвоєння теми

### Core — базовий рівень

Ти повинен уміти:

- пояснити різницю між terminal, shell і CLI;
- розуміти призначення Bash;
- читати prompt і визначати поточну директорію;
- запускати прості команди;
- користуватися `Tab`, історією команд і `Ctrl + C`;
- розуміти, що означають аргументи та параметри.

### Junior — практичний рівень

Ти повинен уміти:

- розрізняти вбудовані команди й зовнішні програми;
- перевіряти тип команди через `type`;
- розуміти призначення `PATH`;
- створювати змінні та змінні середовища;
- використовувати `;`, `&&` і `||`;
- розуміти коди завершення;
- застосовувати перенаправлення та конвеєри;
- запускати Node.js-проєкти з термінала.

### Middle — впевнена робота

Ти повинен уміти:

- розуміти базові правила обробки команд shell;
- використовувати змінні середовища для конфігурації застосунків;
- налаштовувати аліаси;
- розуміти роботу інтерактивних завдань і команд `jobs`, `fg`, `bg`;
- знаходити причини помилок `command not found`;
- розуміти, як `PATH` впливає на запуск програм;
- використовувати shell для автоматизації робочих процесів.

### Senior — поглиблений рівень

Ти повинен розуміти:

- відмінності між Bash, POSIX shell та іншими оболонками;
- як shell обробляє команди, розширення змінних і перенаправлення;
- різницю між стандартними потоками та файловими дескрипторами;
- як коди завершення впливають на сценарії автоматизації;
- як організувати безпечне середовище для виконання скриптів;
- як діагностувати проблеми з конфігурацією shell і змінними середовища.

Ці рівні — орієнтир для навчання, а не офіційна класифікація посад.

| Перечитати налаштування Bash | `source ~/.bashrc` |

## 20. Головне, що потрібно запам'ятати

- **Terminal** — програма, у якій ти працюєш із командним рядком.
- **Shell** — оболонка, яка обробляє команди та запускає програми.
- **Bash** — поширена оболонка Linux, яка також підтримує змінні, умови, цикли та скрипти.
- **CLI** — спосіб взаємодії з програмами через текстові команди.
- Команда часто має структуру `command [options] [arguments]`.
- `PATH` визначає, у яких директоріях shell шукає зовнішні програми.
- `type` допомагає визначити тип команди, а `command -v` — знайти її або перевірити, чи доступна вона.
- Змінні середовища дають змогу передавати конфігурацію програмам.
- `;`, `&&` і `||` визначають, як поєднуються команди.
- `>`, `>>` і `|` допомагають перенаправляти та поєднувати виведення.
- `Ctrl + C` зазвичай перериває процес, а `Ctrl + Z` призупиняє завдання.
- `sudo` потрібно використовувати лише тоді, коли справді потрібні адміністративні права.

**Мета цього розділу:** навчитися впевнено працювати в терміналі, розуміти, як shell запускає команди, і підготувати основу для наступних тем — Bash, файлової системи, прав доступу, процесів, пакетного менеджера та автоматизації завдань у Linux.
