# 05. Man Pages and Help — Довідка та документація Linux

У Linux є вбудована система документації, яка допомагає дізнаватися, як працюють команди, які параметри вони підтримують, які аргументи приймають і як правильно їх використовувати.

Не потрібно запам'ятовувати всі команди та їхні параметри. Важливіше навчитися самостійно знаходити потрібну інформацію за допомогою `man`, `--help`, `help`, `apropos`, `whatis` та інших інструментів.

Для backend-розробника це особливо корисно під час роботи з Bash, Git, Node.js, npm, PostgreSQL, SSH, системними сервісами й серверним середовищем.

## 1. Навіщо потрібна документація Linux?

У Linux існують сотні команд і тисячі параметрів. Навіть досвідчені розробники регулярно звертаються до документації.

Довідка допомагає:

- дізнатися призначення команди;
- переглянути доступні параметри;
- зрозуміти формат аргументів;
- знайти приклади використання;
- перевірити особливості роботи команди;
- розібратися з кодами завершення;
- знайти альтернативні способи виконання завдання;
- уникнути помилок під час роботи з файлами та системою.

Наприклад, ти знаєш, що команда `cp` копіює файли, але не пам'ятаєш, як скопіювати цілу директорію.

Замість пошуку в інтернеті можна виконати:

    cp --help

Або відкрити докладну документацію:

    man cp

**Головний принцип:** не обов'язково пам'ятати всі параметри. Потрібно знати, де знайти їхній опис.

## 2. Основні способи отримати довідку

У Linux є декілька основних інструментів документації.

| Команда | Призначення |
|---|---|
| `man` | Відкриває сторінку документації команди або системного компонента |
| `--help` | Часто показує коротку довідку програми |
| `help` | Показує довідку про вбудовані команди Bash |
| `apropos` | Шукає сторінки документації за ключовими словами |
| `whatis` | Показує короткий опис команди або сторінки документації |
| `info` | Відкриває документацію у форматі GNU Info, якщо вона доступна |
| `type` | Допомагає визначити тип команди |
| `command -v` | Перевіряє, як shell знаходить команду |
| `whereis` | Шукає пов'язані з програмою виконувані файли, джерела та сторінки документації |

Ці інструменти мають різне призначення. Не кожна команда підтримує всі способи отримання довідки.

## 3. Команда `man` — основна система документації

`man` означає **manual** — посібник або довідкова сторінка.

Це один із найважливіших інструментів Linux для отримання докладної інформації про команди та системні компоненти.

### 3.1. Відкриття сторінки документації

Загальний синтаксис:

    man command

Приклади:

    man ls
    man cp
    man grep
    man bash
    man ssh

Команда відкриває сторінку документації у програмі перегляду тексту, зазвичай `less`.

Наприклад:

    man ls

Ти побачиш опис команди `ls`, її синтаксис, параметри та інші відомості.

### 3.2. Як вийти з `man`

Щоб закрити сторінку документації, натисни:

    q

Це стандартна команда виходу з переглядача `less`, який зазвичай використовується для `man`.

### 3.3. Навігація всередині `man`

Основні клавіші:

| Клавіша | Дія |
|---|---|
| `↑` | Переміщення на один рядок угору |
| `↓` | Переміщення на один рядок униз |
| `Space` | Перехід на наступну сторінку |
| `b` | Перехід на попередню сторінку |
| `g` | Перехід на початок документа |
| `G` | Перехід у кінець документа |
| `/word` | Пошук слова |
| `n` | Перехід до наступного збігу |
| `N` | Перехід до попереднього збігу |
| `q` | Вихід |

Наприклад, щоб знайти в документації `ls` опис параметра `--all`:

    man ls

Після відкриття документа введи:

    /--all

Натисни `Enter`, щоб виконати пошук, а потім `n`, щоб перейти до наступного збігу.

**Порада:** не обов'язково читати всю сторінку від початку до кінця. Знайди потрібний розділ за допомогою пошуку.

## 4. Структура сторінки `man`

Більшість сторінок документації мають стандартні розділи.

### 4.1. NAME

Коротка назва та призначення команди.

Наприклад, для `ls` цей розділ повідомляє, що команда показує вміст директорій.

### 4.2. SYNOPSIS

Синтаксис команди.

Тут показано, як записувати команду, які параметри вона підтримує та які аргументи приймає.

Наприклад, умовна схема:

    command [OPTION]... [FILE]...

Означає:

- `command` — назва команди;
- `[OPTION]` — необов'язковий параметр;
- `...` — елемент може повторюватися;
- `[FILE]` — необов'язковий аргумент, наприклад назва файла.

Квадратні дужки в документації зазвичай позначають необов'язкові елементи. Їх не потрібно вводити буквально.

### 4.3. DESCRIPTION

Докладний опис призначення команди та її поведінки.

Цей розділ допомагає зрозуміти, що саме робить програма.

### 4.4. OPTIONS

Список параметрів команди.

Наприклад, у документації `ls` можна знайти опис параметрів для прихованих файлів, детального списку та формату відображення розмірів.

### 4.5. EXAMPLES

Приклади використання, якщо автор документації їх додав.

Не кожна сторінка `man` містить цей розділ.

### 4.6. FILES

Файли, які використовує команда або пов'язаний із нею компонент.

### 4.7. SEE ALSO

Посилання на інші сторінки документації, пов'язані команди або системні компоненти.

**Запам'ятай:** для швидкої роботи зазвичай достатньо переглянути `NAME`, `SYNOPSIS`, `DESCRIPTION` та потрібні параметри в `OPTIONS`.

## 5. Розділи документації `man`

Сторінки `man` поділяються на розділи. Номер розділу допомагає розрізняти різні значення однакової назви.

Основні розділи:

| Номер | Призначення |
|---|---|
| `1` | Команди користувача та виконувані програми |
| `2` | Системні виклики ядра |
| `3` | Бібліотечні функції |
| `4` | Спеціальні файли та пристрої |
| `5` | Формати файлів і конфігурацій |
| `6` | Ігри та розважальні програми |
| `7` | Оглядові матеріали, домовленості та різні теми |
| `8` | Системне адміністрування та команди для адміністратора |

Наявність конкретної сторінки залежить від установлених пакетів і дистрибутива.

### 5.1. Як указати номер розділу

Загальний синтаксис:

    man SECTION NAME

Наприклад:

    man 1 printf
    man 3 printf

`printf` у розділі `1` — команда користувача.

`printf` у розділі `3` — бібліотечна функція, якщо відповідна сторінка встановлена.

Назва однакова, але документація описує різні інтерфейси.

### 5.2. Приклади інших розділів

    man 2 open
    man 5 passwd
    man 8 ip

Ці приклади демонструють вибір розділу. Доступність конкретних сторінок залежить від системи.

Наприклад:

- `man 2 open` — документація системного виклику `open`;
- `man 5 passwd` — документація формату файла `passwd`;
- `man 8 ip` — документація системної утиліти `ip`.

### 5.3. Як дізнатися, який розділ доступний

Виконай:

    man -f printf

Ця команда намагається показати короткі описи відповідних сторінок документації.

Також можна використати:

    whatis printf

Щоб переглянути всі знайдені сторінки з назвою `printf`, спробуй:

    man -a printf

Опція `-a` дозволяє переглянути всі знайдені сторінки з такою назвою, якщо вони доступні.

## 6. Коротка довідка через `--help`

Багато програм підтримують параметр `--help`.

Він зазвичай показує коротку довідку без відкриття повної сторінки `man`.

Приклади:

    ls --help
    cp --help
    mv --help
    grep --help
    mkdir --help

### 6.1. Коли краще використовувати `--help`

Використовуй його, коли потрібно:

- швидко пригадати параметр;
- перевірити синтаксис;
- знайти назву потрібної опції;
- побачити короткий перелік можливостей команди.

Наприклад:

    cp --help

Дозволяє знайти інформацію про копіювання файлів і директорій.

### 6.2. Обмеження `--help`

Не кожна програма підтримує `--help`.

Інші програми можуть використовувати:

    command -h

Проте `-h` не є універсальним параметром довідки. У деяких програмах він має інше значення.

Наприклад, для `ls` параметр `-h` означає зручне відображення розмірів у відповідних форматах виведення.

Тому не варто без перевірки замінювати `--help` на `-h`.

### 6.3. `--help` чи `man`?

| Критерій | `--help` | `man` |
|---|---|---|
| Швидкість | Зазвичай швидко показує коротку довідку | Потрібно відкрити сторінку |
| Детальність | Часто стислий опис | Часто докладна документація |
| Приклади | Залежить від програми | Залежить від сторінки |
| Наявність | Не всі програми підтримують | Не для кожної програми є встановлена сторінка |
| Пошук | Можна комбінувати з іншими командами | Є вбудований пошук у переглядачі |

Для повсякденної роботи корисно знати обидва способи.

## 7. Команда `help` — довідка Bash

`help` використовується для отримання довідки про вбудовані команди Bash.

Приклади:

    help
    help cd
    help export
    help alias
    help read

Наприклад:

    help cd

Показує синтаксис і опис вбудованої команди `cd`.

### 7.1. Чому `help` потрібен окремо?

Деякі команди виконуються самим Bash, а не окремою зовнішньою програмою.

Наприклад:

    cd
    export
    alias
    read

Для них `help` може бути зручнішим за `man`.

Спробуй:

    type cd
    help cd

Команда `type` покаже, що `cd` є вбудованою командою Bash, а `help cd` відкриє її довідку.

### 7.2. Відмінність між `help` і `man`

- `help` — передусім довідка про вбудовані команди Bash.
- `man` — загальна система сторінок документації Linux.
- `--help` — коротка довідка, яку реалізує сама програма.

Ці інструменти доповнюють один одного.

## 8. Команда `apropos` — пошук за ключовими словами

Іноді ти знаєш, що потрібно зробити, але не знаєш назви відповідної команди.

Наприклад, потрібно знайти інструмент для пошуку тексту у файлах.

Для цього існує:

    apropos keyword

Приклади:

    apropos directory
    apropos search
    apropos network
    apropos process

Команда шукає ключові слова в коротких описах сторінок документації.

### 8.1. Приклад пошуку

Припустімо, ти хочеш знайти команди, пов'язані з директоріями.

Виконай:

    apropos directory

Результат може містити назви команд і короткі описи їхнього призначення.

Конкретний список залежить від установленої документації та локальної бази пошуку.

### 8.2. Альтернативний синтаксис

    man -k directory

Це альтернативний спосіб виконати пошук за ключовим словом у базі описів сторінок `man`.

### 8.3. Якщо `apropos` нічого не знаходить

Причини можуть бути такими:

- ключове слово не відповідає описам сторінок;
- відповідна документація не встановлена;
- база пошуку документації не налаштована або не оновлена.

Не роби висновок, що потрібної команди не існує, лише тому, що `apropos` не повернув результат.

## 9. Команда `whatis` — короткий опис

`whatis` показує короткий опис сторінки документації за її назвою.

Приклад:

    whatis ls

Інші приклади:

    whatis grep
    whatis mkdir
    whatis ssh

Команда корисна, коли ти вже знаєш назву програми, але хочеш швидко пригадати її призначення.

### 9.1. Відмінність від `apropos`

`whatis` шукає короткий опис за конкретною назвою.

`apropos` шукає за ключовими словами в описах сторінок.

Порівняй:

    whatis grep
    apropos search

Перша команда шукає опис `grep`, а друга — документацію, пов'язану з пошуком.

### 9.2. Чому `whatis` може не працювати?

Якщо команда нічого не знаходить, можливо:

- сторінка не встановлена;
- база описів недоступна або застаріла;
- назва не відповідає доступній сторінці.

У такому разі можна спробувати:

    man grep
    grep --help

## 10. Документація GNU Info — команда `info`

Деякі програми GNU мають документацію у форматі Info.

Відкрити її можна командою:

    info

Для конкретної теми:

    info coreutils
    info bash

Наявність відповідної документації залежить від установлених пакетів.

### 10.1. Коли потрібен `info`?

`info` може містити докладну документацію, розбиту на вузли та розділи, між якими можна переходити.

Це корисно для деяких GNU-інструментів, наприклад Coreutils і Bash.

### 10.2. Чи потрібно вивчати `info` одразу?

На початковому етапі достатньо знати, що такий інструмент існує.

Насамперед навчися користуватися:

    command --help
    man command
    help command

До `info` можна звертатися, коли інші джерела не дають достатньої інформації.

## 11. Команди `type`, `command -v` і `whereis`

Іноді проблема полягає не в синтаксисі, а в тому, що незрозуміло, яку саме програму запускає shell.

### 11.1. `type`

Показує, як shell інтерпретує назву команди.

    type cd
    type ls
    type git

Можна побачити, що команда є вбудованою, зовнішньою програмою, аліасом або має інший тип, залежно від ситуації.

### 11.2. `command -v`

Перевіряє, як поточний shell знаходить команду.

    command -v node
    command -v npm
    command -v git

Приклад результату:

    /home/taubu/.nvm/versions/node/v24.21.0/bin/node

Це приклад можливого шляху, якщо Node.js установлено через NVM.

Якщо команда недоступна, результат залежить від shell і контексту виклику.

### 11.3. `whereis`

Шукає пов'язані з програмою файли, зокрема виконуваний файл, вихідний код або сторінки документації, якщо вони є в стандартних місцях пошуку.

    whereis ls
    whereis bash
    whereis ssh

`whereis` не є універсальним пошуком усіх файлів у системі. Він шукає в обмеженому наборі місць.

### 11.4. Порівняння

| Команда | Основне завдання |
|---|---|
| `type` | Визначити, як shell трактує команду |
| `command -v` | Перевірити доступність команди або її розташування |
| `whereis` | Знайти типові файли, пов'язані з програмою |
| `man` | Прочитати документацію |
| `--help` | Переглянути коротку довідку |

## 12. Пошук у документації через `grep`

Можна поєднувати команди документації з іншими інструментами Linux.

Наприклад:

    ls --help | grep all

Команда передає текст довідки `ls` до `grep`, який відбирає рядки зі словом `all`.

Інший приклад:

    ls --help | grep -i human

Параметр `-i` для `grep` означає пошук без урахування регістру літер.

Можна також шукати потрібні параметри в довідці інших програм:

    cp --help | grep recursive

Це корисно, коли довідка довга й потрібно знайти конкретний параметр.

Важливо розуміти: пошук через `grep` знаходить рядки з відповідним текстом, але не пояснює весь контекст. Якщо результат незрозумілий, відкрий повну довідку.

## 13. Документація команд і конфігураційних файлів

У Linux документація стосується не лише команд.

Можна шукати інформацію про:

- формати конфігураційних файлів;
- системні виклики;
- бібліотечні функції;
- мережеві протоколи;
- системні служби;
- формати журналів;
- правила налаштування системи.

Наприклад:

    man 5 crontab
    man 5 hosts
    man 5 fstab

Це приклади сторінок, що описують формати файлів або конфігураційні домовленості. Доступність залежить від системи.

### 13.1. Чому важливий розділ 5?

Розділ `5` містить документацію про формати файлів і конфігурацій.

Це особливо корисно, коли потрібно не просто запустити команду, а зрозуміти, як правильно налаштувати Linux.

Наприклад, документація `fstab` допомагає розібратися з конфігурацією файлових систем, а `hosts` — із локальними відповідностями між іменами вузлів та IP-адресами.

**Увага:** перед редагуванням системних конфігураційних файлів потрібно розуміти наслідки змін. Для початку краще лише читати документацію.

## 14. Якщо документація не відкривається

Не всі системи мають однаковий набір сторінок `man`, а деякі мінімальні інсталяції містять лише частину документації.

Якщо команда:

    man some-command

не знаходить сторінку, це не обов'язково означає, що сама команда відсутня.

Перевір послідовно.

### Крок 1. Перевір наявність програми

    command -v some-command

Якщо шлях знайдено, команда доступна в поточному shell.

### Крок 2. Спробуй коротку довідку

    some-command --help

Це працює лише тоді, коли програма підтримує такий параметр.

### Крок 3. Перевір `man`

    man some-command

Якщо документації немає, можливо, відповідний пакет документації не встановлено.

### Крок 4. Перевір інші інструменти

    type some-command
    whatis some-command
    apropos some-command

Не всі вони обов'язково повернуть результат.

### Крок 5. Перевір доступні пакети

В Ubuntu та інших Debian-подібних системах документація може постачатися окремим пакетом.

Загальний приклад пошуку пакета:

    apt search manpages

Не потрібно встановлювати всі знайдені пакети без потреби. Спочатку визнач, яка саме документація відсутня.

## 15. Встановлення документації в Ubuntu

В Ubuntu багато програм уже мають доступну довідку, але набір сторінок залежить від установлених пакетів.

### 15.1. Перевірка `man`

    man --version

Ця команда перевіряє версію програми `man`, якщо вона підтримує такий параметр.

Також можна спробувати:

    man ls

Якщо сторінка відкрилася, система має відповідну документацію для `ls`.

### 15.2. Пошук пакетів документації

У Debian/Ubuntu для пошуку пакетів можна використовувати:

    apt search manpages

У назвах пакетів можуть бути загальні сторінки документації, довідка GNU або документація окремих програм.

### 15.3. Встановлення пакетів

Якщо ти визначив, який пакет потрібен, установити його можна через `apt`.

    sudo apt install package-name

`package-name` у цьому прикладі — умовне позначення. Перед установленням потрібно підставити реальну назву пакета.

Для звичайної роботи не потрібно встановлювати додаткові пакети, якщо наявної документації достатньо.

## 16. Як ефективно читати документацію

Не завжди потрібно читати всю сторінку. Використовуй послідовний підхід.

### Крок 1. Визнач, що потрібно зробити

Наприклад, скопіювати директорію разом із вмістом.

### Крок 2. Переглянь коротку довідку

    cp --help

### Крок 3. Знайди потрібний параметр

У довідці знайди інформацію про рекурсивне копіювання.

### Крок 4. За потреби відкрий `man`

    man cp

### Крок 5. Знайди відповідний розділ

У `man` натисни `/`, введи ключове слово, наприклад `recursive`, і натисни `Enter`.

### Крок 6. Перевір синтаксис

Перед виконанням команди переконайся, що правильно вказав джерело, призначення та потрібні параметри.

### Крок 7. Виконай команду на безпечному прикладі

Для навчання краще використовувати тестову директорію з файлами, які не шкода змінити або видалити.

Цей підхід допомагає навчитися знаходити інформацію самостійно, а не просто копіювати готові команди.

## 17. Приклад: як знайти потрібний параметр

Припустімо, потрібно скопіювати директорію з усім її вмістом.

Ти знаєш команду `cp`, але не пам'ятаєш параметр.

Спочатку:

    cp --help

Знайди в довідці параметр, який відповідає за рекурсивне копіювання.

Потім перевір докладну документацію:

    man cp

Знайди слово:

    /recursive

Приклад команди для копіювання директорії:

    cp -r source-directory backup-directory

У цьому прикладі:

- `cp` — команда копіювання;
- `-r` — параметр рекурсивного копіювання;
- `source-directory` — вихідна директорія;
- `backup-directory` — директорія призначення.

Для навчання краще спочатку створити тестову структуру й перевірити результат.

## 18. Приклад: як дослідити незнайому команду

Припустімо, ти зустрів команду `chmod` і хочеш дізнатися, що вона робить.

### Крок 1. Перевір коротку довідку

    chmod --help

### Крок 2. Відкрий документацію

    man chmod

### Крок 3. Знайди синтаксис

У розділі `SYNOPSIS` перевір, які аргументи приймає команда.

### Крок 4. Знайди опис параметрів

Переглянь `DESCRIPTION` та `OPTIONS`.

### Крок 5. Вивчи приклади

Якщо документація містить приклади, перевір, як вони співвідносяться із синтаксисом.

Команда `chmod` змінює права доступу до файлів і директорій. Під час навчання не варто експериментувати з правами системних файлів: спочатку використовуй тестові файли у власній домашній директорії.

## 19. Типові помилки початківця

### Помилка 1. Вважати, що потрібно запам'ятати всі параметри

**Неправильно:** намагатися вивчити напам'ять повний синтаксис кожної команди.

**Правильно:** знати базові команди та вміти швидко знаходити їхню документацію.

### Помилка 2. Використовувати `-h` як універсальну довідку

`-h` може означати різні речі в різних програмах.

Спочатку перевіряй:

    command --help

Якщо програма не підтримує `--help`, шукай інший спосіб отримати довідку.

### Помилка 3. Не знати про вбудовані команди Bash

Для вбудованих команд зручно використовувати:

    help cd
    help export

### Помилка 4. Читати лише коротку довідку

`--help` може не пояснювати всі особливості команди.

Для докладнішої інформації спробуй:

    man command

### Помилка 5. Плутати `apropos` і `whatis`

- `apropos` — пошук за ключовими словами.
- `whatis` — короткий опис конкретної назви.

### Помилка 6. Вважати, що відсутність сторінки `man` означає відсутність програми

Програма може бути встановлена без відповідного пакета документації.

Перевір:

    command -v program-name

### Помилка 7. Не користуватися пошуком усередині `man`

Замість читання всього документа можна відкрити сторінку й знайти потрібне слово через `/`.

### Помилка 8. Виконувати команду, не перевіривши її призначення

Перед використанням незнайомої команди особливо важливо з'ясувати, чи змінює вона файли, права доступу або системні налаштування.

## 20. Практика

Мета практики — навчитися самостійно знаходити потрібну інформацію в документації Linux.

### Вправа 1. Відкрий сторінки `man`

Виконай:

    man ls
    man cp
    man grep
    man mkdir

Для кожної сторінки знайди:

- `NAME`;
- `SYNOPSIS`;
- `DESCRIPTION`;
- потрібні параметри в `OPTIONS`.

Закривай сторінку клавішею `q`.

### Вправа 2. Порівняй `man` і `--help`

Виконай:

    ls --help
    man ls

Завдання:

- порівняй структуру довідки;
- знайди параметр `-a`;
- знайди параметр `-l`;
- визнач, який спосіб зручніший для швидкого пошуку, а який — для докладнішого читання.

### Вправа 3. Довідка Bash

Виконай:

    type cd
    help cd
    help export
    help alias

Завдання:

- визнач, які команди є вбудованими;
- знайди їхній синтаксис;
- поясни, чому для `cd` корисно знати команду `help`.

### Вправа 4. Пошук за ключовим словом

Виконай:

    apropos directory
    man -k directory

Завдання:

- порівняй результати;
- знайди кілька команд, пов'язаних із директоріями;
- вибери одну команду й відкрий її сторінку `man`.

Якщо результатів немає, перевір доступність документації або спробуй інше ключове слово.

### Вправа 5. Короткий опис

Виконай:

    whatis ls
    whatis grep
    whatis mkdir

Завдання:

- прочитай короткі описи;
- поясни, чим `whatis` відрізняється від `man`;
- спробуй знайти сторінку для іншої відомої команди.

### Вправа 6. Пошук у документації

Відкрий:

    man cp

Потім знайди слово:

    /recursive

Завдання:

- перейди до наступного збігу клавішею `n`;
- знайди опис рекурсивного копіювання;
- поясни, як знайдений параметр впливає на поведінку команди.

### Вправа 7. Дослідження незнайомої команди

Обери одну команду:

    chmod
    chown
    find
    sort
    uniq

Для обраної команди:

1. Виконай `command --help`, якщо цей спосіб підтримується.
2. Відкрий `man`.
3. Знайди призначення команди.
4. Випиши три корисні параметри.
5. Знайди приклад використання або склади власний безпечний приклад.
6. Поясни, які аргументи потрібні команді.

### Вправа 8. Документація для backend-розробника

Перевір довідку інструментів, які ти використовуєш:

    git --help
    npm --help
    node --help

Не всі інструменти використовують однаковий формат довідки. У Git і npm також існують підкоманди з окремою документацією.

Спробуй:

    git help status
    npm help run

Завдання:

- знайди інформацію про перевірку стану Git;
- знайди інформацію про запуск npm-сценаріїв;
- поясни, як довідка допомагає працювати без постійного пошуку готових команд.

## 21. Рівні засвоєння теми

### Core — базовий рівень

Ти повинен уміти:

- відкривати `man`;
- користуватися `--help`;
- знаходити потрібний параметр;
- переміщатися сторінкою документації;
- шукати текст через `/`;
- виходити з переглядача клавішею `q`.

### Junior — практичний рівень

Ти повинен уміти:

- розрізняти `man`, `help` і `--help`;
- використовувати `apropos` і `whatis`;
- знаходити потрібний розділ документації;
- перевіряти доступність команди через `command -v`;
- читати `SYNOPSIS`, `DESCRIPTION` та `OPTIONS`;
- самостійно досліджувати команди Linux.

### Middle — впевнена робота

Ти повинен уміти:

- швидко знаходити потрібні параметри в довгій документації;
- розрізняти документацію команд, системних викликів і форматів файлів;
- досліджувати причини відсутності сторінок документації;
- знаходити довідку для складних інструментів;
- використовувати конвеєри для пошуку інформації у виведенні довідки;
- оцінювати, чи достатньо короткої довідки для безпечного виконання команди.

### Senior — поглиблений рівень

Ти повинен розуміти:

- організацію розділів `man`;
- відмінності між документацією програм, системних викликів і бібліотек;
- зв'язок між програмою, її пакетом і пакетом документації;
- особливості документації різних дистрибутивів;
- способи знаходження першоджерел інформації про системні інструменти;
- як використовувати документацію для діагностики складних проблем.

Ці рівні є навчальним орієнтиром, а не офіційною класифікацією посад.

## 24. Головне, що потрібно запам'ятати

- `man` — основний інструмент для читання сторінок документації Linux.
- `--help` — швидкий спосіб переглянути довідку багатьох програм.
- `help` використовується для вбудованих команд Bash.
- `apropos` допомагає знайти команди за ключовими словами.
- `whatis` показує короткий опис сторінки документації.
- `info` надає документацію в окремому форматі GNU Info.
- `type` допомагає зрозуміти, як shell інтерпретує назву команди.
- `command -v` допомагає перевірити доступність команди.
- Сторінки `man` поділяються на розділи, які описують різні типи системних компонентів.
- Пошук через `/` допомагає швидко знаходити потрібний параметр у довгому документі.
- Відсутність сторінки `man` не означає, що програма не встановлена.
- Документація потрібна не лише для навчання, а й для щоденної роботи розробника.

**Мета цього розділу:** навчитися самостійно знаходити, читати та використовувати документацію Linux, щоб упевнено працювати з командами й переходити до наступних тем курсу без необхідності запам'ятовувати всі параметри напам'ять.
