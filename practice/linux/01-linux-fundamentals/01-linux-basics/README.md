## 01. Linux Basics

Linux Basics (основи Linux) — це базові поняття про операційну систему Linux, її призначення, архітектуру, основні компоненти та принципи роботи.

Linux використовується для:

- розробки програмного забезпечення;
- роботи серверів і вебзастосунків;
- розгортання Node.js, Express та NestJS-проєктів;
- роботи з базами даних PostgreSQL;
- автоматизації завдань за допомогою Bash;
- адміністрування серверів;
- роботи з контейнерами та Docker;
- управління файлами, процесами, користувачами й мережами;
- розміщення застосунків у хмарній інфраструктурі.

Linux особливо важливий для backend-розробника, оскільки значна частина серверної інфраструктури працює на Linux.

У цьому розділі вивчаються фундаментальні поняття. Практична робота з командами, файлами, каталогами, правами доступу та процесами розглядатиметься в наступних розділах курсу.

### Що потрібно пам'ятати

• Linux — це насамперед ядро операційної системи, а не назва одного конкретного дистрибутива.

• Linux kernel керує апаратними ресурсами, пам'яттю, процесами, пристроями та взаємодією між програмами й обладнанням.

• GNU — проєкт, який розробляє вільне програмне забезпечення, зокрема багато командних утиліт, що використовуються в Linux-системах.

• GNU/Linux — назва повної операційної системи, побудованої на Linux kernel та інших програмних компонентах. У повсякденному спілкуванні її часто називають просто Linux.

• Linux distribution — готова система, яка об'єднує ядро, системні утиліти, пакетний менеджер, бібліотеки та інше програмне забезпечення.

• Ubuntu, Debian, Fedora, Linux Mint і Arch Linux — приклади Linux-дистрибутивів.

• Terminal — програма, через яку користувач взаємодіє із системою за допомогою текстового інтерфейсу.

• Shell — програма, яка інтерпретує команди користувача. Приклад — Bash.

• CLI — інтерфейс, у якому користувач вводить текстові команди.

• GUI — графічний інтерфейс із вікнами, меню, кнопками та іншими візуальними елементами.

• Root — обліковий запис суперкористувача, який має широкі адміністративні повноваження.

• Process — екземпляр запущеної програми.

• File system — спосіб організації та зберігання файлів і каталогів.

• Package manager — інструмент для встановлення, оновлення та видалення програм.

• Linux широко використовується на серверах, у хмарних середовищах, вбудованих пристроях і системах розробки.

• Для backend-розробника важливо не лише знати команди, а й розуміти, як працюють операційна система, процеси, користувачі, файлові системи та мережа.

# Operating System (OS)

Operating System (операційна система) — системне програмне забезпечення, яке керує апаратними ресурсами комп'ютера та забезпечує середовище для виконання програм.

Приклади операційних систем:

    Linux
    Windows
    macOS
    Android
    iOS

Операційна система координує роботу:

    CPU
    RAM
    Storage
    Network interfaces
    Input/output devices
    Running applications

Наприклад, коли запускається Node.js-застосунок, операційна система допомагає:

    1. Завантажити виконуваний файл і потрібні бібліотеки.
    2. Створити процес.
    3. Виділити процесу пам'ять.
    4. Надати процесу доступ до необхідних ресурсів.
    5. Забезпечити роботу з файлами та мережею.
    6. Керувати виконанням процесу.

Основні функції операційної системи:

- Process management — керування процесами.
- Memory management — керування оперативною пам'яттю.
- File system management — організація файлів і каталогів.
- Device management — взаємодія з апаратними пристроями.
- Security and access control — контроль доступу.
- Networking — підтримка мережевої взаємодії.
- Resource allocation — розподіл ресурсів між програмами.

# Linux

Linux — це операційна система у звичному широкому розумінні, а технічно — її ядро (kernel).

Linux kernel було створено Лінусом Торвальдсом у 1991 році.

Linux є open-source software: його вихідний код доступний для вивчення, зміни та поширення відповідно до умов ліцензії.

Linux використовується на:

    Personal computers
    Servers
    Cloud infrastructure
    Supercomputers
    Embedded devices
    Routers
    Internet of Things (IoT) devices
    Android devices

Linux популярний у backend-розробці, тому що забезпечує:

- стабільне серверне середовище;
- гнучке налаштування;
- потужні командні інструменти;
- автоматизацію через shell scripting;
- керування користувачами та дозволами;
- підтримку багатьох мов програмування;
- підтримку серверів і мережевих служб;
- сумісність із великою кількістю інструментів розробки.

Наприклад, типовий backend-проєкт може використовувати:

    Linux
      ↓
    Node.js
      ↓
    NestJS
      ↓
    PostgreSQL
      ↓
    Nginx
      ↓
    Internet

Це лише один із можливих варіантів архітектури. Компоненти та їхнє розташування можуть відрізнятися залежно від проєкту.

# Linux Kernel

Kernel (ядро) — центральна частина операційної системи, яка керує ресурсами комп'ютера та забезпечує взаємодію програм з апаратним забезпеченням.

Linux kernel відповідає за:

    Process scheduling
    Memory management
    Device drivers
    File system support
    Networking
    System calls
    Security mechanisms

Приклад взаємодії:

    Node.js application
            ↓
    Standard libraries / runtime
            ↓
    System calls
            ↓
    Linux kernel
            ↓
    Hardware

Наприклад, коли програма читає файл, вона не повинна безпосередньо керувати фізичним накопичувачем. Вона використовує системні інтерфейси, а ядро забезпечує доступ до файлу та необхідні операції з пристроєм.

Важливо розуміти:

- Kernel — не те саме, що shell.
- Kernel — не те саме, що terminal.
- Kernel — не те саме, що distribution.
- Bash не є частиною Linux kernel.
- Node.js не є частиною Linux kernel.

Це різні компоненти системи.

# GNU

GNU — проєкт зі створення вільної операційної системи та програмного забезпечення, який започаткував Річард Столмен у 1983 році.

Багато GNU-інструментів використовуються в Linux-системах.

Приклади:

    bash
    coreutils
    grep
    sed
    awk
    gcc
    make

Ці інструменти виконують різні завдання:

- `bash` — командна оболонка.
- `ls` — перегляд вмісту каталогів.
- `cp` — копіювання файлів.
- `mv` — переміщення та перейменування.
- `grep` — пошук тексту за шаблоном.
- `sed` — обробка тексту.
- `awk` — обробка структурованих текстових даних.
- `gcc` — компілятор GNU для мов програмування, зокрема C і C++.

Багато класичних команд Linux походять із GNU Coreutils, але не всі команди в Linux-системах є GNU-утилітами.

Наприклад, в Ubuntu типовою оболонкою часто є Bash, а значна частина базових команд надається GNU Coreutils.

---

# GNU/Linux

GNU/Linux — операційна система, яка використовує Linux kernel разом із системними бібліотеками, утилітами та іншими компонентами.

Спрощена схема:

    Linux kernel
         +
    System libraries
         +
    System utilities
         +
    Shell
         +
    Package management
         +
    Other software
         ↓
    GNU/Linux system

Сучасні дистрибутиви можуть містити GNU-компоненти, інші реалізації системних утиліт, додаткові бібліотеки та програмне забезпечення.

Тому не кожну Linux-систему правильно описувати як систему, що складається виключно з GNU-компонентів.

У повсякденній роботі назви Linux і GNU/Linux часто використовуються як взаємозамінні.

# Open Source

Open-source software — програмне забезпечення, вихідний код якого доступний відповідно до ліцензії, що дозволяє його використання, вивчення, зміну та поширення.

Linux kernel розповсюджується за ліцензією GNU GPL версії 2 з додатковими умовами для окремих компонентів.

Переваги open-source software:

- можливість перевіряти вихідний код;
- незалежне створення змін;
- спільна розробка;
- прозорість багатьох технічних рішень;
- можливість адаптації до різних потреб;
- широкий вибір інструментів.

Важливо:

    Open source ≠ завжди безкоштовний сервіс.
    Open source ≠ відсутність ліцензійних умов.
    Open source ≠ відсутність відповідальності за безпеку.

Програмне забезпечення з відкритим кодом може мати різні ліцензії, умови використання та моделі комерційного розповсюдження.

    SSD

    Keyboard

# Kernel Space vs User Space

Linux розділяє виконання коду на дві основні області привілеїв.

## Kernel Space

Kernel space — привілейований простір виконання ядра.

Тут працює код Linux kernel, який має доступ до механізмів керування апаратними ресурсами відповідно до архітектури та прав ядра.

Основні завдання:

    Process scheduling
    Memory management
    Device drivers
    Networking
    Low-level file system operations

## User Space

User space — простір, у якому виконуються звичайні програми та більшість системних служб.

Приклади:

    Bash
    Node.js
    PostgreSQL
    Firefox
    VS Code

Звичайна програма не має необмеженого прямого доступу до ресурсів ядра.

Для виконання привілейованих операцій вона використовує системні виклики та механізми, які надає операційна система.

Спрощена схема:

    User Space
    ┌──────────────────────┐
    │ Bash                 │
    │ Node.js              │
    │ PostgreSQL           │
    │ Other applications   │
    └──────────┬───────────┘
               │
         System calls
               │
    ┌──────────▼───────────┐
    │ Linux Kernel         │
    │ Process management   │
    │ Memory management    │
    │ Device drivers       │
    │ Networking           │
    └──────────┬───────────┘
               │
            Hardware

Це спрощена модель: системні бібліотеки та інші компоненти можуть брати участь у взаємодії між програмами й ядром.

# System Calls

System call (системний виклик) — механізм, за допомогою якого програма запитує в ядра виконання певної операції.

Приклади системних викликів Linux:

    openat()
    read()
    write()
    close()
    fork()
    execve()
    mmap()
    socket()

Призначення:

- `openat()` — відкриття або створення файлу відносно каталогу чи іншого заданого контексту.
- `read()` — читання даних із файлового дескриптора.
- `write()` — запис даних у файловий дескриптор.
- `close()` — закриття файлового дескриптора.
- `fork()` — створення нового процесу на основі поточного.
- `execve()` — запуск іншої програми в поточному процесі.
- `mmap()` — відображення ділянки файлу або пам'яті у віртуальний адресний простір.
- `socket()` — створення мережевого або іншого комунікаційного сокета.

Не кожна взаємодія програми з бібліотекою безпосередньо спричиняє системний виклик. Бібліотеки можуть виконувати частину роботи самостійно.

Для початкового рівня достатньо запам'ятати:

    Application
         ↓
    System call interface
         ↓
    Kernel
         ↓
    Resource or operation

Детальніше системні виклики розглядатимуться під час вивчення процесів, файлових операцій і мережі.

# Process

Process (процес) — екземпляр програми, що виконується в операційній системі.

Наприклад, коли запускається команда:

    node server.js

операційна система створює процес для виконання Node.js із відповідним файлом.

Процес має власний контекст виконання, ідентифікатор та інші ресурси, потрібні для роботи.

Основні поняття:

    PID — Process ID
    PPID — Parent Process ID
    Process state
    CPU time
    Memory usage
    Open file descriptors

Приклади програм, які можуть працювати як процеси:

    node server.js
    postgres
    nginx
    bash
    firefox

Одна програма може створювати декілька процесів. Також одна програма може виконувати багато завдань у межах одного процесу, наприклад через потоки або асинхронну модель виконання.

Процеси та керування ними детально вивчатимуться в розділі:

    06-processes-and-system

# Memory Management

Memory management — керування оперативною пам'яттю та адресними просторами процесів.

Linux kernel відповідає за:

- розподіл і звільнення пам'яті;
- ізоляцію адресних просторів процесів;
- керування віртуальною пам'яттю;
- відображення файлів у пам'ять;
- використання механізмів кешування;
- реагування на нестачу пам'яті.

Основні поняття:

    RAM
    Virtual memory
    Virtual address space
    Physical memory
    Page
    Page table
    Swap
    Memory allocation

Важливо:

• Віртуальна пам'ять не тотожна фізичній оперативній пам'яті.

• Кожен звичайний процес має власний віртуальний адресний простір, який ізолюється від інших процесів за допомогою механізмів апаратури та ядра.

• Swap — механізм використання накопичувача як додаткового ресурсу для підтримки віртуальної пам'яті. Він не є повноцінною заміною RAM.

• Linux використовує вільну пам'ять також для кешування, тому сама по собі невелика кількість вільної RAM не обов'язково означає проблему.

# File System

File system (файлова система) — спосіб організації та зберігання файлів, каталогів і пов'язаних із ними метаданих.

Linux використовує єдину ієрархію каталогів, коренем якої є:

    /

Цей символ називається root directory — кореневий каталог.

Приклад структури:

    /
    ├── bin
    ├── boot
    ├── dev
    ├── etc
    ├── home
    ├── lib
    ├── media
    ├── mnt
    ├── opt
    ├── proc
    ├── root
    ├── run
    ├── srv
    ├── sys
    ├── tmp
    ├── usr
    └── var

Призначення основних каталогів:

- `/` — корінь файлової ієрархії.
- `/home` — домашні каталоги звичайних користувачів.
- `/root` — домашній каталог користувача root.
- `/etc` — системні конфігураційні файли.
- `/var` — дані, що змінюються під час роботи системи, наприклад журнали.
- `/tmp` — тимчасові файли.
- `/usr` — значна частина програм, бібліотек і ресурсів користувацького простору.
- `/bin` — базові виконувані програми; у сучасних дистрибутивах цей каталог часто є посиланням на `/usr/bin`.
- `/sbin` — системні утиліти; у сучасних дистрибутивах цей каталог часто є посиланням на `/usr/sbin`.
- `/boot` — файли, необхідні для завантаження системи.
- `/dev` — інтерфейси до пристроїв, представлені у вигляді спеціальних файлів.
- `/proc` — віртуальна файлова система з інформацією про процеси та ядро.
- `/sys` — віртуальна файлова система для представлення інформації про пристрої та ядро.
- `/run` — тимчасові дані стану системи, зазвичай доступні протягом поточного завантаження.
- `/media` — типове місце автоматичного монтування знімних носіїв.
- `/mnt` — типове місце для тимчасового монтування файлових систем.
- `/opt` — додаткове програмне забезпечення, яке встановлюється окремими пакетами або постачальниками.
- `/srv` — дані, які надаються системою через служби.

Не кожен каталог обов'язково має бути окремою фізичною файловою системою. У Linux різні файлові системи можуть монтуватися в різні точки єдиної ієрархії.

Детальніше каталоги, шляхи, пошук і робота з файлами вивчатимуться в розділах:

    03-file-content-and-search

# Everything Is a File

У Linux часто кажуть: "Everything is a file" — «Усе є файлом».

Це корисна модель для розуміння Unix-подібних систем, але не буквальне правило без винятків.

У Linux багато ресурсів доступні через файлові інтерфейси:

    Regular files
    Directories
    Device files
    Pipes
    Sockets
    /proc entries
    /sys entries

Приклади:

    /etc/hosts
    /dev/null
    /dev/zero
    /proc/cpuinfo
    /proc/meminfo

Команда для перегляду інформації про процесор:

    cat /proc/cpuinfo

Команда для перегляду інформації про пам'ять:

    cat /proc/meminfo

Файл `/proc/cpuinfo` зазвичай не є звичайним файлом, збереженим на диску. Він надає динамічну інформацію через віртуальну файлову систему `/proc`.

Приклад перенаправлення даних у спеціальний пристрій:

    echo "Hello" > /dev/null

Вивід команди буде спрямовано до `/dev/null`, де дані відкидаються.

Цей принцип дозволяє використовувати спільні механізми роботи з багатьма різними ресурсами.

# User and Root

Linux підтримує користувачів і групи, які використовуються для керування доступом до ресурсів системи.

Основні поняття:

    User
    Group
    UID
    GID
    Root
    Superuser
    Permissions
    Ownership

Root — спеціальний обліковий запис із UID 0, який має широкі адміністративні повноваження.

Звичайний користувач має обмежені права відповідно до налаштувань системи.

Наприклад:

    regular user
         ↓
    limited permissions

    root
         ↓
    broad administrative privileges

У Ubuntu для виконання адміністративних команд зазвичай використовується `sudo`.

Наприклад:

    sudo apt update

Ця команда запускає `apt update` з адміністративними повноваженнями, якщо користувач має відповідні права sudo.

Важливо:

• Root — це не назва каталогу `/`, хоча слово root використовується в обох випадках.

• `/` — кореневий каталог файлової системи.

• `root` — ім'я суперкористувача та його домашнього каталогу за замовчуванням `/root`.

• Не потрібно запускати всі команди через `sudo`.

• Адміністративні права слід використовувати лише тоді, коли вони потрібні.

• Зайві права можуть призвести до випадкового пошкодження системних файлів або неправильного налаштування системи.

Детальніше користувачі, групи, права доступу та власники вивчатимуться в розділі:

    05-permissions-and-ownership

# Shell

Shell — програма, яка забезпечує взаємодію користувача з операційною системою через командний інтерфейс.

Приклади shell:

    Bash
    Zsh
    Fish
    Dash
    Ksh

Shell дозволяє:

- запускати команди;
- передавати аргументи програмам;
- використовувати змінні;
- виконувати перенаправлення введення та виведення;
- об'єднувати команди через pipes;
- створювати цикли й умовні конструкції;

Деякі команди, наприклад `cd`, часто є вбудованими командами shell, оскільки мають змінювати стан поточної оболонки.

# Package Manager

Package manager — інструмент для встановлення, оновлення, налаштування та видалення програмних пакетів.

В Ubuntu типовим інструментом керування пакетами Debian є APT.

Приклади:

    sudo apt update
    sudo apt upgrade
    sudo apt install curl
    sudo apt remove curl

Призначення команд:

- `apt update` — оновлює локальну інформацію про доступні пакети.
- `apt upgrade` — оновлює встановлені пакети відповідно до доступних оновлень і правил APT.
- `apt install` — встановлює пакети.
- `apt remove` — видаляє пакети, зазвичай залишаючи системні конфігураційні файли, якщо вони не видаляються окремо.

    Package
        ↓
    Package manager
        ↓
    Package repository

Package — пакет програмного забезпечення.

Package manager — інструмент для керування пакетами.

Package repository — джерело, з якого пакетний менеджер отримує пакети та метадані.

У різних дистрибутивах використовуються різні пакетні менеджери.

# Boot Process

Boot process — послідовність дій, під час яких комп'ютер запускається та завантажує операційну систему.

Спрощена схема:

    Power on
        ↓
    Firmware (BIOS / UEFI)
        ↓
    Bootloader
        ↓
    Linux kernel
        ↓
    Initial userspace
        ↓
    systemd or another init system
        ↓
    System services
        ↓
    Login / graphical session

Основні етапи:

1. Firmware ініціалізує апаратне забезпечення та передає керування завантажувачу.
2. Bootloader завантажує ядро та необхідні компоненти.
3. Linux kernel ініціалізує основні підсистеми.
4. Запускається початкове користувацьке середовище, яке допомагає підготувати систему до роботи.
5. Запускається init system, наприклад systemd.
6. Запускаються потрібні служби.
7. Система переходить до відповідного режиму роботи, наприклад текстового входу або графічного робочого середовища.

Реальний процес завантаження залежить від конфігурації системи, апаратної платформи та використовуваних інструментів.

На цьому етапі достатньо розуміти загальну послідовність.

Детальніше завантаження системи та діагностика розглядатимуться під час вивчення процесів і системних служб.

# POSIX

POSIX (Portable Operating System Interface) — набір стандартів, які визначають спільні інтерфейси та поведінку для сумісності Unix-подібних операційних систем.

POSIX охоплює, зокрема:

    Shell and utilities
    File operations
    Process control
    Signals
    Threads
    System interfaces

POSIX важливий тому, що допомагає створювати програми та скрипти, які можуть працювати на різних сумісних системах із меншими змінами.

Однак Linux не є повністю тотожним POSIX, і не кожна можливість Linux обов'язково входить до POSIX.

Наприклад:

- Bash підтримує POSIX-сумісний режим, але також має власні розширення.
- POSIX shell-скрипти можуть бути переносимішими між різними Unix-подібними системами.
- Linux надає додаткові інтерфейси, яких немає в POSIX.

Для початкового рівня достатньо знати, що POSIX визначає важливі стандартизовані інтерфейси, а Linux реалізує багато з них та має власні розширення.

# Linux Architecture

Архітектура Linux-системи — це організація компонентів, які разом забезпечують роботу операційної системи та програм.

Спрощена схема:

    User
      ↓
    Terminal / GUI
      ↓
    Shell / Applications
      ↓
    Libraries / Runtime
      ↓
    System calls
      ↓
    Linux kernel
      ↓
    Hardware

Приклад для backend-розробника:

    Developer
       ↓
    VS Code Terminal
       ↓
    Bash
       ↓
    npm run start
       ↓
    Node.js / NestJS process
       ↓
    Linux kernel
       ↓
    CPU / RAM / Storage / Network

Що відбувається:

1. Розробник вводить команду в терміналі.
2. Bash обробляє команду та запускає відповідну програму.
3. Node.js виконує JavaScript-код.
4. Застосунок може читати файли, використовувати пам'ять і працювати з мережею.
5. Для операцій, що потребують послуг ядра, процес використовує системні інтерфейси.
6. Linux kernel керує відповідними ресурсами.

Ця схема спрощена: між програмою та ядром можуть працювати різні бібліотеки, runtime-компоненти й системні служби.

Головне — розуміти, що Linux kernel, shell, terminal, Node.js і NestJS виконують різні функції.

# Linux Command Structure

Команда Linux часто має таку структуру:

    command [options] [arguments]

Де:

    command   → назва програми або вбудованої команди
    options   → параметри поведінки
    arguments → об'єкти, над якими виконується дія

Приклад:

    ls -l /home/taubu

Тут:

    ls             → command
    -l             → option
    /home/taubu    → argument

Параметри можуть мати коротку або довгу форму.

Приклад:

    ls -a
    ls --all

У багатьох командах ці варіанти еквівалентні, але конкретні правила залежать від самої програми.

Важливо: не всі команди мають однаковий синтаксис. Значення параметрів визначається документацією конкретної команди.

Детальніше структура команд розглядатиметься в розділі:

    01-linux-fundamentals/04-command-structure

# Linux Environment

Environment (оточення) — набір параметрів, які програми можуть отримувати під час запуску.

Приклади змінних оточення:

    HOME
    USER
    PATH
    SHELL
    LANG
    TERM

Подивитися значення окремої змінної можна так:

    echo "$HOME"

Або:

    printenv HOME

Подивитися значення `PATH`:

    echo "$PATH"

`PATH` містить список каталогів, у яких shell шукає виконувані програми, коли команда вказана без повного шляху.

Наприклад, команда:

    node --version

працює без зазначення повного шляху до Node.js, якщо виконуваний файл доступний через `PATH` або інший механізм пошуку команд.

Важливо:

• Змінні оточення можуть впливати на поведінку програм.

• Кожен процес отримує власне оточення під час запуску.

• Дочірній процес може успадкувати оточення батьківського процесу.

• Зміна змінної в одному процесі зазвичай не змінює оточення вже запущених незалежних процесів.

Детальніше змінні, shell і Bash розглядатимуться в наступних розділах курсу.

# Linux and Windows

Linux і Windows — різні операційні системи, які мають різні системні архітектури та інструменти адміністрування.

Основні відмінності:

| Характеристика | Linux | Windows |
|---|---|---|
| Типова файлова ієрархія | Єдине дерево від `/` | Диски на зразок `C:` |
| Основний командний інструментарій | Bash, coreutils та інші утиліти | PowerShell, CMD |
| Типові системні конфігурації | `/etc` та інші системні каталоги | Реєстр, системні каталоги та конфігураційні файли |
| Типові пакетні менеджери | APT, DNF, pacman тощо | WinGet та інші засоби |
| Права доступу | Unix-подібна модель власників і дозволів | ACL та інші механізми Windows |
| Типові серверні інструменти | SSH, systemd, Nginx та інші | PowerShell, Windows Services та інші |

Це загальне порівняння: в обох системах є додаткові інструменти, різні моделі безпеки та різні способи адміністрування.

Приклад шляхів:

    Linux:
    /home/taubu/projects/nest-exercises

    Windows:
    C:\Users\valer\projects\nest-exercises

У Linux прямий слеш `/` використовується для розділення компонентів шляху.

У Windows традиційно використовують зворотний слеш `\`.

Важливо: регістр літер у назвах файлів у Linux зазвичай має значення.

Наприклад:

    README.md
    readme.md

У типовій Linux-файловій системі це можуть бути два різні файли.

# Типові помилки початківців

❌ **Вважати Linux і Ubuntu одним і тим самим.**

Ubuntu — це дистрибутив, побудований на Linux kernel та інших програмних компонентах.

---

❌ **Плутати kernel, shell і terminal.**

    Kernel   → керує ресурсами системи
    Shell    → інтерпретує команди
    Terminal → забезпечує текстовий інтерфейс

---

❌ **Вважати, що Bash є ядром Linux.**

Bash — командна оболонка, яка працює в користувацькому просторі.

---

❌ **Вважати, що всі Linux-дистрибутиви використовують APT.**

Ubuntu та Debian використовують APT, тоді як інші дистрибутиви можуть використовувати DNF, pacman, apk або інші інструменти.

---

❌ **Вважати, що Linux працює лише в терміналі.**

Linux може використовуватися як із графічним інтерфейсом, так і без нього.

---

❌ **Виконувати всі команди через `sudo`.**

    sudo command

Не потрібно використовувати `sudo`, якщо команда не вимагає адміністративних прав.

---

❌ **Плутати `/` і `/root`.**

    /       → кореневий каталог файлової системи
    /root   → домашній каталог користувача root

---

❌ **Вважати, що все в Linux буквально є звичайним файлом.**

Це корисна концепція Unix-подібних систем, але існують також інші інтерфейси та об'єкти ядра.

---

❌ **Вважати, що Linux і GNU — одне й те саме.**

Linux — ядро, а GNU — проєкт, який створив багато програмних компонентів, що використовуються в Linux-системах.

---

❌ **Вважати, що сервер обов'язково має мати GUI.**

Багато серверів працюють без графічного середовища та адмініструються через SSH і CLI.

---

❌ **Ігнорувати регістр літер у назвах файлів.**

    config.js
    Config.js

У типовій Linux-файловій системі це різні назви.

# Практичні завдання

## Завдання 1 — визначити дистрибутив

- версію;
- ідентифікатор дистрибутива.

## Завдання 2 — перевірити ядро

Виконай:

    uname -a

Знайди у виводі:

- назву системи;
- ім'я хоста;
- версію ядра;
- архітектуру.

Пам'ятай, що точний формат виводу залежить від системи.

---

## Завдання 3 — перевірити користувача

Виконай:

    whoami

Потім:

    echo "$HOME"

Визнач:

- ім'я поточного користувача;
- його домашній каталог.

---

## Завдання 4 — перевірити поточний каталог

Виконай:

    pwd

Потім:

    cd ~
    pwd

Порівняй результати.

---

## Завдання 5 — переглянути каталоги

Виконай:

    ls /
    ls /home
    ls -la ~

Зверни увагу на:

- кореневий каталог;
- домашні каталоги користувачів;
- приховані файли.

---

## Завдання 6 — перевірити середовище

Виконай:

    echo "$SHELL"
    echo "$PATH"
    printenv HOME

Поясни призначення кожної змінної.

Врахуй, що `$SHELL` зазвичай показує оболонку користувача за замовчуванням, а не обов'язково оболонку, яка виконується в поточному терміналі.

---

## Завдання 7 — перевірити інструменти розробки

Виконай:

    node --version
    npm --version
    git --version

Переконайся, що основні інструменти доступні.

Якщо команда не знайдена, це може означати, що програму не встановлено або її шлях не доступний через `PATH`.

---

## Завдання 8 — знайти інформацію про пам'ять

Виконай:

    cat /proc/meminfo

Знайди рядки:

    MemTotal
    MemFree
    MemAvailable
    SwapTotal
    SwapFree

Поясни різницю між фізичною пам'яттю, доступною пам'яттю та swap.

---

## Завдання 9 — знайти інформацію про процесор

Виконай:

    cat /proc/cpuinfo

Зверни увагу на:

    processor
    vendor_id
    model name

Доступні поля залежать від архітектури процесора.

---

    uname -r
    uname -m
    cat /etc/os-release

Поясни, чим відрізняються:

    Kernel version
    Machine architecture
    Distribution version

# Головне

• Linux — ядро операційної системи, а Ubuntu — дистрибутив, який використовує це ядро.

• Linux kernel керує процесами, пам'яттю, пристроями, мережею та іншими ресурсами системи.

• GNU надає багато програмних компонентів, які використовуються в Linux-системах.

• Shell інтерпретує команди, а terminal забезпечує текстовий інтерфейс для взаємодії з shell.

• CLI особливо важливий для адміністрування серверів і backend-розробки.

• Файлова система Linux має єдину ієрархію каталогів, коренем якої є `/`.

• `/home` містить домашні каталоги звичайних користувачів, а `/root` — домашній каталог суперкористувача.

• Root має широкі адміністративні повноваження, тому `sudo` слід використовувати обдумано.

• Process — запущений екземпляр програми.

• System calls забезпечують контрольований доступ програм до можливостей ядра.

• Linux широко використовується для розробки, запуску та розгортання серверних застосунків.

• Для backend-розробника Linux допомагає розуміти, як працюють Node.js, NestJS, PostgreSQL, мережеві служби та серверна інфраструктура.

• Основні команди для початку:

    pwd
    ls
    cd
    whoami
    uname
    cat
    man

• Важливо не просто запам'ятовувати команди, а розуміти, який компонент системи виконує кожну дію.

• Основна модель Linux:

    User
      ↓
    Terminal / GUI
      ↓
    Shell / Applications
      ↓
    System interfaces
      ↓
    Linux kernel
      ↓
    Hardware

• Розпочинай із базових понять, одразу перевіряй їх у власному Ubuntu-терміналі та переходь до наступних тем поступово.
