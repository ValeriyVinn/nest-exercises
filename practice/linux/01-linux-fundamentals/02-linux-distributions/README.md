## 02. Linux Distributions

Linux Distributions (дистрибутиви Linux) — це готові операційні системи, побудовані на Linux kernel та доповнені системними утилітами, бібліотеками, пакетним менеджером, конфігураціями й іншими програмними компонентами.

Linux kernel — це ядро системи, а Linux distribution — повне програмне середовище, яке користувач встановлює та використовує.

Дистрибутиви створюються для різних завдань:

- повсякденна робота на персональному комп'ютері;
- навчання Linux і системному адмініструванню;
- backend-розробка;
- робота серверів;
- хмарна інфраструктура;
- контейнери та Docker;
- кібербезпека;
- вбудовані системи;
- робота на старому або малопотужному обладнанні.

Популярні Linux-дистрибутиви:

    Ubuntu
    Debian
    Linux Mint
    Fedora
    Arch Linux
    openSUSE
    Rocky Linux
    AlmaLinux
    Alpine Linux

Для backend-розробника важливо розуміти, чим відрізняються дистрибутиви, як вони встановлюють програмне забезпечення, як отримують оновлення та чому сервер може використовувати інший дистрибутив, ніж локальний комп'ютер розробника.

У цьому розділі розглядаються основні сімейства дистрибутивів, пакетні менеджери, моделі оновлення, версії систем і критерії вибору Linux для навчання та розробки.

### Що потрібно пам'ятати

• Linux distribution — це не лише ядро Linux, а повна система з програмними компонентами та інструментами керування.

• Ubuntu, Debian, Fedora, Arch Linux та Alpine Linux — різні дистрибутиви, які використовують Linux kernel, але відрізняються пакетною системою, конфігурацією, моделлю оновлення та цільовою аудиторією.

• Ubuntu базується на Debian і використовує пакети `.deb` та пакетний менеджер APT.

• Debian відомий широким вибором програмного забезпечення та кількома гілками випусків, зокрема Stable, Testing і Unstable.

• Fedora використовує пакети RPM та пакетний менеджер DNF.

• RHEL — комерційний дистрибутив Red Hat для корпоративного використання. Rocky Linux та AlmaLinux є окремими корпоративними дистрибутивами, сумісними з RHEL на рівні, визначеному їхніми проєктами.

• Arch Linux використовує `pacman` і модель rolling release.

• openSUSE має різні варіанти, зокрема Leap і Tumbleweed, які відрізняються моделлю випуску.

• Alpine Linux орієнтований на компактність і використовує пакетний менеджер `apk`.

• Пакетний менеджер допомагає встановлювати, оновлювати та видаляти програми й керувати залежностями.

• `.deb` і `.rpm` — формати пакетів, а APT, DNF і pacman — інструменти керування пакетами.

• LTS означає Long-Term Support — триваліший період підтримки певного випуску. Конкретні строки залежать від дистрибутива, версії та умов підтримки.

• Rolling release — модель, у якій система отримує оновлення без необхідності переходити між окремими великими версіями за традиційною схемою.

• Fixed release — модель, у якій основні версії системи випускаються окремими релізами.

• Server distribution не обов'язково є окремою операційною системою: часто це звичайний дистрибутив, встановлений із серверним набором компонентів.

• Для навчання Linux і backend-розробки не потрібно встановлювати всі дистрибутиви. Достатньо добре освоїти один, а потім навчитися розпізнавати відмінності між іншими.

• Для роботи з Node.js, NestJS, PostgreSQL і Git знання Ubuntu дає хорошу основу для переходу до інших Linux-середовищ.

# What Is a Linux Distribution?

Linux distribution — це набір програмних компонентів, зібраних і налаштованих так, щоб користувач міг установити та використовувати операційну систему.

Типовий дистрибутив містить:

    Linux kernel
         +
    System libraries
         +
    System utilities
         +
    Package manager
         +
    Package repositories
         +
    Init system
         +
    Configuration files
         +
    Applications
         ↓
    Linux distribution

Залежно від дистрибутива до складу також можуть входити графічне середовище, браузер, офісні програми, серверні служби та інші компоненти.

Наприклад, Ubuntu Desktop зазвичай містить графічне середовище, а мінімальна серверна інсталяція може обходитися без повноцінного desktop environment.

Важливо розрізняти:

    Linux kernel
        → ядро

    GNU/Linux system
        → операційна система на базі Linux та системних компонентів

    Linux distribution
        → конкретна збірка системи з визначеним набором програм,
          конфігурацією та способом оновлення

# Debian Family

До Debian family належать:

    Debian
    Ubuntu
    Linux Mint
    Pop!_OS
    Raspberry Pi OS

Ці дистрибутиви мають різний ступінь спорідненості та різне призначення. Наприклад, Ubuntu базується на Debian, Linux Mint має редакції з різною програмною основою, а Raspberry Pi OS призначена насамперед для пристроїв Raspberry Pi.

Типові технології:

    Package format: .deb
    Low-level package tool: dpkg
    High-level package manager: APT

APT працює з репозиторіями та допомагає керувати залежностями пакетів.

Приклад:

    sudo apt update
    sudo apt install curl
    sudo apt upgrade

Призначення команд:

- `apt update` — оновлює локальні індекси доступних пакетів.
- `apt install curl` — встановлює пакет `curl` та необхідні залежності.
- `apt upgrade` — оновлює встановлені пакети відповідно до доступних оновлень і правил APT.

Команда `apt update` не оновлює всі встановлені програми. Вона оновлює інформацію про пакети.

## Debian

Debian — один із найважливіших Linux-дистрибутивів, на якому базуються інші системи, зокрема Ubuntu.

Характерні особливості:

- широка програмна база;
- розвинена система пакетів;
- кілька гілок випусків;
- акцент на стабільності у Stable;
- використання APT і DPKG.

Основні гілки Debian:

    Stable
    Testing
    Unstable (кодова назва — Sid)

Stable призначена для систем, у яких важливі передбачуваність і стабільність.

Testing використовується для підготовки майбутнього стабільного випуску.

Unstable містить активніші зміни пакетів і не призначена для тих самих сценаріїв, що Debian Stable.

Назви та стан конкретних випусків змінюються з часом.

## Ubuntu

Ubuntu — популярний дистрибутив на базі Debian, який використовується на персональних комп'ютерах, серверах і в хмарній інфраструктурі.

Характерні особливості:

- зручність встановлення та початкового налаштування;
- APT і пакети `.deb`;
- регулярні випуски;
- LTS-випуски з тривалішою підтримкою;
- широка документація;
- велика кількість навчальних матеріалів.

Ubuntu має редакції для різних сценаріїв, зокрема Desktop і Server.

На локальному комп'ютері можна працювати з Ubuntu Desktop, а на сервері використовувати Ubuntu Server.

Основні команди:

    sudo apt update
    sudo apt install git
    sudo apt upgrade

Для backend-розробника Ubuntu — зручна основна система, оскільки на ній можна встановлювати Node.js, npm, Git, PostgreSQL, редактори коду та інші інструменти.

## Linux Mint

Linux Mint — дистрибутив, орієнтований насамперед на зручну роботу на персональному комп'ютері.

Він має графічні середовища та інструменти, які полегшують повсякденне використання Linux.

Основні особливості:

- орієнтація на desktop;
- зручне графічне середовище;
- пакетна база, пов'язана з Ubuntu або Debian залежно від редакції;
- доступ до широкого набору програмного забезпечення.

Для backend-розробки Linux Mint також підходить, якщо доступні потрібні версії інструментів.

# Red Hat Family

До Red Hat family та споріднених RPM-дистрибутивів належать:

    Red Hat Enterprise Linux (RHEL)
    Fedora
    Rocky Linux
    AlmaLinux

Вони використовують RPM-пакети, а сучасні системи цього сімейства зазвичай застосовують DNF для керування програмним забезпеченням.

Типові технології:

    Package format: .rpm
    Package manager: DNF
    Low-level package tools: RPM

Приклади команд:

    sudo dnf check-update
    sudo dnf install git
    sudo dnf upgrade

Точна поведінка команд залежить від версії DNF і конкретного дистрибутива. Наприклад, команда перевірки оновлень може повертати спеціальний код завершення, коли доступні оновлення.

## Fedora

Fedora — дистрибутив, який розвивається у співпраці з ширшою екосистемою Red Hat.

Особливості:

- відносно нові версії програмного забезпечення;
- використання RPM і DNF;
- кілька офіційних редакцій та варіантів;
- підтримка сучасних технологій Linux;
- регулярні випуски.

Fedora може бути корисною для розробників, які хочуть працювати з актуальними інструментами та вивчати RPM-екосистему.

## Red Hat Enterprise Linux (RHEL)

RHEL — корпоративний Linux-дистрибутив, який розробляє Red Hat.

Використовується в середовищах, де важливі:

- корпоративна підтримка;
- передбачуваний життєвий цикл;
- сертифікації та сумісність;
- керування оновленнями;
- інструменти корпоративного адміністрування.

RHEL має власні умови доступу до програмного забезпечення та підтримки. Це комерційний продукт, хоча існують безкоштовні варіанти використання за певними умовами.

## Rocky Linux

Rocky Linux — корпоративний Linux-дистрибутив, створений як сумісна альтернатива RHEL.

Його використовують для серверних систем, лабораторних середовищ і навчання адміністрування RPM-систем.

## AlmaLinux

AlmaLinux — незалежний корпоративний Linux-дистрибутив, орієнтований на сумісність із RHEL.

Rocky Linux та AlmaLinux мають власні процеси розробки й випуску. Не слід вважати їх одним і тим самим дистрибутивом.

# Arch Family

Arch Linux — дистрибутив, орієнтований на гнучкість і налаштування системи користувачем.

Основні особливості:

- rolling release;
- пакетний менеджер `pacman`;
- мінімалістичний підхід до початкової системи;
- велика кількість доступних пакетів;
- необхідність розуміти процес налаштування системи.

Приклади команд:

    sudo pacman -Syu
    sudo pacman -S git
    pacman -Q

Призначення:

- `pacman -Syu` — синхронізує бази пакетів і виконує повне оновлення системи.
- `pacman -S git` — встановлює пакет `git`.
- `pacman -Q` — показує встановлені пакети.

У rolling-release системах важливо уважно стежити за оновленнями та рекомендаціями розробників.

Arch Linux може бути корисним для глибшого вивчення Linux, але для першого знайомства з командним рядком не обов'язково починати саме з нього.

# SUSE Family

До екосистеми SUSE належать:

    openSUSE
    SUSE Linux Enterprise Server (SLES)

Для керування пакетами в openSUSE використовується Zypper, який працює з RPM-пакетами.

Приклади:

    sudo zypper refresh
    sudo zypper install git
    sudo zypper update

Призначення:

- `zypper refresh` — оновлює метадані репозиторіїв.
- `zypper install git` — встановлює Git.
- `zypper update` — оновлює встановлені пакети відповідно до доступних оновлень.

openSUSE має різні моделі випуску.

    openSUSE Leap
        → fixed-release модель

    openSUSE Tumbleweed
        → rolling-release модель

Конкретні особливості та життєвий цикл залежать від актуального стану проєкту.

SUSE Linux Enterprise Server орієнтований на корпоративні серверні середовища та має окрему модель підтримки.

# Alpine Linux

Alpine Linux — компактний Linux-дистрибутив, який часто використовують у контейнерах та мінімальних серверних середовищах.

Основні особливості:

- невеликий базовий розмір;
- пакетний менеджер `apk`;
- мінімалістичний набір компонентів;
- використання musl libc замість glibc у стандартній системі;
- використання BusyBox для багатьох базових утиліт.

Приклади команд:

    apk update
    apk add curl
    apk info

Призначення:

- `apk update` — оновлює індекси репозиторіїв.
- `apk add curl` — встановлює пакет `curl`.
- `apk info` — показує інформацію про пакети.

Alpine часто використовується як основа контейнерних образів, але компактність не означає, що він завжди є найкращим варіантом.

Важливі відмінності:

- деякі програми очікують glibc;
- окремі нативні Node.js-модулі можуть вимагати додаткових залежностей;
- інструменти діагностики можуть відрізнятися;
- мінімальний образ може потребувати додаткового налаштування.

Наприклад, якщо Node.js-застосунок використовує нативні залежності, необхідно перевіряти сумісність цих залежностей із середовищем Alpine.

# Package Formats

Формат пакета визначає, як програмне забезпечення та пов'язані метадані упаковані для встановлення.

Найвідоміші формати:

    .deb
    .rpm

## DEB

`.deb` — формат пакетів, який використовується Debian та багатьма похідними дистрибутивами.

Приклади систем:

    Debian
    Ubuntu
    Linux Mint

Низькорівневий інструмент:

    dpkg

Високорівневий пакетний менеджер:

    apt

APT допомагає встановлювати пакети з репозиторіїв і розв'язувати залежності.

## RPM

`.rpm` — формат пакетів, який використовується Fedora, RHEL, Rocky Linux, AlmaLinux та іншими RPM-дистрибутивами.

Низькорівневий інструмент:

    rpm

Високорівневий пакетний менеджер:

    dnf

DNF працює з репозиторіями, залежностями та встановленими пакетами.

## Важлива різниця

    .deb → package format
    APT  → package manager

    .rpm → package format
    DNF  → package manager

Формат пакета і пакетний менеджер — різні поняття.

Не варто намагатися встановлювати випадкові пакети з іншого сімейства дистрибутивів без перевірки сумісності.

# Package Managers

Package manager — програма для керування програмними пакетами.

Основні пакетні менеджери:

| Дистрибутив або сімейство | Пакетний менеджер | Формат пакетів |
|---|---|---|
| Debian | APT / DPKG | `.deb` |
| Ubuntu | APT / DPKG | `.deb` |
| Linux Mint | APT / DPKG | `.deb` |
| Fedora | DNF / RPM | `.rpm` |
| RHEL | DNF / RPM | `.rpm` |
| Rocky Linux | DNF / RPM | `.rpm` |
| AlmaLinux | DNF / RPM | `.rpm` |
| Arch Linux | pacman | власна система пакетів Arch |
| openSUSE | Zypper / RPM | `.rpm` |
| Alpine Linux | apk | формат пакетів Alpine |

Пакетний менеджер допомагає:

- знаходити пакети;
- встановлювати програми;
- видаляти програми;
- оновлювати програмне забезпечення;
- перевіряти встановлені пакети;
- керувати залежностями;
- отримувати пакети з репозиторіїв.

Для backend-розробника це важливо під час встановлення системних бібліотек, інструментів розробки, Git, компіляторів та інших системних залежностей.

# Package Repositories

Repository (репозиторій пакетів) — джерело, з якого пакетний менеджер отримує інформацію про пакети та саме програмне забезпечення.

Репозиторій може містити:

    Package metadata
    Package versions
    Dependencies
    Download locations
    Repository signatures

Спрощена схема:

    Package manager
          ↓
    Package repository
          ↓
    Package metadata
          ↓
    Package download
          ↓
    Installation

Наприклад, в Ubuntu команда:

    sudo apt update

оновлює локальні індекси пакетів, використовуючи налаштовані репозиторії.

Після цього можна виконати:

    sudo apt install curl

APT знайде потрібний пакет у доступних джерелах, перевірить залежності та запропонує встановлення.

Важливо:

• Репозиторії можуть бути офіційними, сторонніми або локальними.

• Додавати сторонні репозиторії потрібно обережно.

• Репозиторій може містити інші версії пакетів, ніж ті, що доступні в основних джерелах дистрибутива.

• Для безпеки важливі підписи пакетів, довіра до джерела та своєчасне встановлення оновлень.

# Dependencies

Dependency (залежність) — програмний компонент, який потрібний іншій програмі для роботи.

Наприклад, застосунок може залежати від:

    Shared libraries
    Runtime
    System packages
    Node.js packages
    Native libraries

Пакетний менеджер Linux зазвичай автоматично встановлює системні залежності, якщо вони доступні та правильно описані в метаданих пакетів.

У Node.js також є власна система залежностей:

    package.json
         ↓
    npm
         ↓
    node_modules

Важливо розрізняти:

    Linux system packages
        → системні програми та бібліотеки

    npm packages
        → JavaScript-пакети проєкту

Наприклад, Git можна встановити через APT:

    sudo apt install git

А JavaScript-бібліотеку можна додати через npm:

    npm install express

Це два різні рівні керування залежностями.

# Release Models

Модель випуску визначає, як дистрибутив отримує нові версії програмного забезпечення та як користувач переходить між версіями системи.

Основні моделі:

    Fixed release
    Rolling release
    Long-Term Support (LTS)

## Fixed Release

Fixed release — модель, у якій основні версії системи випускаються окремо.

Наприклад:

    Release A
       ↓
    Updates for Release A
       ↓
    Upgrade to Release B

У межах конкретного випуску дистрибутив може підтримувати визначений набір версій системних компонентів, випускаючи оновлення безпеки та виправлення.

Приклади дистрибутивів із fixed-release моделлю:

    Debian Stable
    Ubuntu
    Fedora
    openSUSE Leap

У різних дистрибутивів різна тривалість підтримки та різні правила оновлення.

## Rolling Release

Rolling release — модель, у якій система отримує нові версії пакетів постійним потоком оновлень.

Спрощена схема:

    Installed system
          ↓
    Regular updates
          ↓
    New package versions
          ↓
    Updated system

Приклади:

    Arch Linux
    openSUSE Tumbleweed

Переваги:

- доступ до новіших версій програм;
- відсутність необхідності переходити між великими релізами за традиційною схемою;
- можливість швидше отримувати нові функції.

Можливі складнощі:

- потреба регулярно встановлювати оновлення;
- необхідність стежити за змінами;
- можливі проблеми сумісності після оновлення.

Rolling release не означає, що система автоматично оновлюється без участі користувача. Спосіб встановлення оновлень залежить від конфігурації.

## LTS — Long-Term Support

LTS — випуск із тривалішим періодом підтримки.

Ubuntu має LTS-випуски, які широко використовуються на робочих комп'ютерах і серверах.

Переваги LTS:

- передбачуваніший життєвий цикл;
- триваліша підтримка;
- зручність для довгострокових середовищ;
- менша потреба часто переходити на новий основний випуск.

Важливо:

• LTS не означає повну відсутність змін.

• Програми та бібліотеки можуть отримувати виправлення безпеки.

• Для деяких пакетів і компонентів умови підтримки можуть відрізнятися.

• Точні строки підтримки залежать від версії та конкретної політики дистрибутива.

# Ubuntu Releases

Ubuntu випускає нові версії за визначеним циклом.

Назва версії зазвичай містить рік і місяць випуску.

Наприклад:

    Ubuntu 24.04 LTS
    Ubuntu 26.04 LTS

У цих прикладах:

    24 → рік 2024
    04 → квітень

    26 → рік 2026
    04 → квітень

LTS-випуски призначені для тривалішого використання та підтримки.

Між ними також виходять проміжні випуски з коротшим періодом підтримки.

Перед оновленням важливо перевірити:

    Current release
    Target release
    Supported upgrade path
    Available disk space
    Backup status
    Third-party repositories
    Application compatibility

Не потрібно встановлювати кожну нову версію Ubuntu одразу після її появи.

Для навчання та роботи варто вибирати підтримуваний випуск, який сумісний із потрібними інструментами.

# Check Your Distribution

У Linux є кілька способів дізнатися, який дистрибутив установлено.

## /etc/os-release

Основна команда:

    cat /etc/os-release

Приклад виводу:

    NAME="Ubuntu"
    VERSION="..."
    ID=ubuntu
    ID_LIKE=debian

Значення `VERSION` залежить від установленого випуску.

Основні поля:

    NAME      → назва системи
    VERSION   → версія дистрибутива
    ID        → ідентифікатор дистрибутива
    ID_LIKE   → спорідненість із іншими дистрибутивами

`ID_LIKE` може бути відсутнім або містити кілька значень.

## lsb_release

Якщо команда встановлена, можна виконати:

    lsb_release -a

Вона може показати:

    Distributor ID
    Description
    Release
    Codename

У деяких мінімальних системах `lsb_release` не встановлена за замовчуванням.

## uname

Команда:

    uname -a

показує інформацію про ядро та систему, але не є основним способом визначення версії дистрибутива.

Важливо розрізняти:

    Distribution version
        → версія дистрибутива

    Kernel version
        → версія ядра Linux

Ці версії не обов'язково збігаються за номером.

# Check Package Manager

Щоб визначити, який пакетний менеджер використовується, можна перевірити доступні команди.

Наприклад:

    command -v apt
    command -v dnf
    command -v pacman
    command -v zypper
    command -v apk

Якщо команда повертає шлях, відповідний виконуваний файл доступний через механізм пошуку команд shell.

Наприклад:

    /usr/bin/apt

Але наявність команди сама по собі не завжди визначає дистрибутив: інструмент може бути встановлений додатково.

Надійніше спочатку перевірити:

    cat /etc/os-release

а потім використовувати пакетний менеджер, який відповідає цій системі.

---

# Kernel Version vs Distribution Version

Версія ядра Linux і версія дистрибутива — різні характеристики.

Приклад:

    Distribution:
    Ubuntu 24.04 LTS

    Kernel:
    6.x.y

Тут `6.x.y` — умовне позначення версії ядра, а не конкретна рекомендована версія для цього випуску.

Дізнатися версію ядра:

    uname -r

Дізнатися версію дистрибутива:

    cat /etc/os-release

Дистрибутив може оновлювати ядро в межах свого циклу підтримки. Також версія ядра може залежати від апаратної платформи, налаштувань і встановлених пакетів.

Не слід робити висновок про версію Ubuntu лише за результатом `uname -r`.

# Desktop vs Server Distributions

Дистрибутиви та редакції Linux можуть бути орієнтовані на робочий стіл або сервери.

## Desktop-oriented

Приклади:

    Ubuntu Desktop
    Linux Mint
    Fedora Workstation

Зазвичай містять:

- графічне середовище;
- графічні інструменти налаштування;
- програми для повсякденної роботи;
- підтримку мультимедіа та периферійних пристроїв.

## Server-oriented

Приклади:

    Ubuntu Server
    Debian minimal installation
    RHEL
    Rocky Linux
    AlmaLinux

Типові сценарії:

- запуск вебзастосунків;
- робота баз даних;
- розміщення мережевих служб;
- адміністрування віддалених систем;
- робота в хмарній інфраструктурі.

Серверні інсталяції часто обходяться без графічного середовища, але це не обов'язкова умова.

Один і той самий дистрибутив може використовуватися як на desktop, так і на server.

# Minimal Installation

Minimal installation — встановлення системи з невеликою кількістю компонентів.

Переваги:

- менше зайвого програмного забезпечення;
- менша кількість компонентів для обслуговування;
- можливість самостійно вибрати потрібні інструменти;
- зручність для спеціалізованих серверів і контейнерів.

Недоліки:

- може бракувати звичних інструментів;
- додаткові пакети потрібно встановлювати вручну;
- діагностика може вимагати більше знань.

Наприклад, у мінімальній системі можуть бути відсутні окремі утиліти для діагностики мережі або редактори тексту.

Не слід припускати, що будь-яка команда, доступна в Ubuntu Desktop, обов'язково буде доступна на мінімальному сервері.

# Live Environment and ISO Image

ISO image — файл образу диска, який використовується для встановлення або запуску операційної системи.

Наприклад:

    ubuntu-desktop.iso
    debian.iso

ISO-образ можна записати на USB-накопичувач і завантажити комп'ютер із нього.

Live environment — середовище, яке дозволяє запустити Linux без повного встановлення на внутрішній накопичувач.

Це корисно для:

- перевірки сумісності обладнання;
- ознайомлення з дистрибутивом;
- діагностики системи;
- відновлення даних;
- встановлення операційної системи.

Live-система може працювати з USB-накопичувача та використовувати оперативну пам'ять для частини тимчасових даних.

Зміни в такому середовищі не обов'язково зберігатимуться після перезавантаження.

# Architecture and Compatibility

Під час вибору дистрибутива важливо враховувати архітектуру обладнання.

Поширені архітектури:

    x86_64
    aarch64
    ARM

`x86_64` — поширена 64-бітна архітектура процесорів, сумісних з x86.

`aarch64` — 64-бітна архітектура ARM.

Архітектура впливає на:

- доступні образи операційної системи;
- сумісність пакетів;
- підтримку обладнання;
- можливість запуску певних програм;
- доступність деяких бінарних залежностей.

Перевірити архітектуру:

    uname -m

Приклади можливого виводу:

    x86_64
    aarch64

Під час вибору системи потрібно перевіряти не лише архітектуру процесора, а й підтримку конкретного пристрою та його драйверів.

# Distribution Choice for Backend Development

Для backend-розробки важливі не лише особливості дистрибутива, а й доступність потрібних інструментів.

Типовий стек:

    Linux
    Node.js
    npm
    Git
    PostgreSQL
    VS Code
    Bash
    SSH

Основні критерії вибору:

- стабільність системи;
- сумісність із Node.js;
- доступність PostgreSQL;
- наявність документації;
- зручність керування пакетами;
- підтримка обладнання;
- доступність оновлень безпеки;
- схожість із цільовим серверним середовищем.

## Ubuntu

Підходить для:

- навчання Linux;
- локальної розробки;
- роботи з Node.js та NestJS;
- роботи з PostgreSQL;
- вивчення серверного адміністрування;
- роботи з багатьма популярними інструментами.

## Debian

Підходить для:

- стабільних серверних середовищ;
- навчання адміністрування;
- розміщення застосунків;
- систем, у яких важлива передбачуваність.

## Fedora

Підходить для:

- знайомства з RPM-екосистемою;
- роботи з актуальними версіями програм;
- вивчення сучасних Linux-технологій.

## Arch Linux

Підходить для:

- глибшого вивчення Linux;
- ручного налаштування системи;
- дослідження роботи пакетного менеджера та компонентів.

## Alpine Linux

Підходить для:

- компактних контейнерів;
- мінімалістичних середовищ;
- спеціалізованих систем, де важливий розмір образу.

Однак для Node.js-проєктів необхідно перевіряти сумісність нативних залежностей.

# Why Learn One Distribution First?

На початку навчання краще вибрати один основний дистрибутив і добре опанувати його.

Причини:

- однакова базова система для практики;
- менше плутанини з пакетними менеджерами;
- простіше повторювати команди;
- легше накопичувати практичний досвід;
- більше часу на вивчення Linux, а не на перевстановлення систем.

Після освоєння базових принципів можна вивчати відмінності інших дистрибутивів.

Наприклад:

    Ubuntu
       ↓
    Linux commands
       ↓
    Files and permissions
       ↓
    Processes and services
       ↓
    Networking
       ↓
    SSH and deployment
       ↓
    Differences between distributions

Важливо навчитися розрізняти універсальні принципи Linux і специфічні інструменти конкретного дистрибутива.

# Ubuntu on Local PC and Linux on Server

Локальна система розробника й віддалений сервер можуть використовувати різні дистрибутиви.

Наприклад:

    Local development:
    Ubuntu Desktop

    Production server:
    Debian

    Container:
    Alpine Linux

Це не обов'язково проблема.

Node.js-застосунок може працювати в різних Linux-середовищах, якщо дотримані вимоги до runtime, системних бібліотек, архітектури та конфігурації.

Проте слід перевіряти:

- версію Node.js;
- версії npm-пакетів;
- системні бібліотеки;
- наявність нативних модулів;
- змінні оточення;
- права доступу;
- мережеві налаштування;
- доступність потрібних програм.

Для зменшення відмінностей між середовищами використовують автоматизацію розгортання, lock-файли, CI/CD і контейнери.

Docker та контейнеризація розглядатимуться в подальших темах курсу.

# End of Life (EOL)

End of Life — завершення періоду підтримки певного випуску або продукту.

Після завершення підтримки система може більше не отримувати звичайні виправлення безпеки.

Це створює ризики:

- відомі вразливості можуть залишатися невиправленими;
- програмне забезпечення може перестати отримувати оновлення;
- сумісність із новими інструментами може погіршитися;
- підтримка з боку постачальників може бути обмеженою.

Перед використанням дистрибутива варто перевіряти:

    Distribution version
    Release date
    Support period
    Security update policy
    Upgrade path

Для серверів особливо важливо використовувати підтримувані випуски.

Не слід плутати завершення стандартної підтримки із завершенням усіх можливих варіантів розширеної підтримки. У деяких дистрибутивах можуть існувати окремі програми розширеного обслуговування.

# Типові помилки

❌ **Вважати, що всі Linux-дистрибутиви однакові.**

Вони мають спільну основу, але можуть суттєво відрізнятися пакетними менеджерами, моделями оновлення, конфігурацією та доступним програмним забезпеченням.

---

❌ **Плутати Linux kernel і дистрибутив.**

    Linux kernel → ядро

    Ubuntu → повний дистрибутив на основі Linux kernel

---

❌ **Плутати APT і DPKG.**

    APT  → високорівневе керування пакетами та залежностями

    DPKG → низькорівнева робота з Debian-пакетами

---

❌ **Плутати DNF і RPM.**

    DNF → пакетний менеджер

    RPM → формат пакетів та інструмент роботи з RPM-пакетами

---

❌ **Використовувати команди одного дистрибутива на іншому без перевірки.**

    Ubuntu → apt

    Fedora → dnf

    Arch Linux → pacman

    openSUSE → zypper

    Alpine Linux → apk

---

❌ **Вважати, що `apt update` оновлює всі програми.**

Команда оновлює локальні індекси пакетів.

Для оновлення встановлених пакетів у звичайному сценарії використовують:

    sudo apt upgrade

---

❌ **Вважати rolling release повністю автоматичним оновленням.**

Rolling release описує модель розвитку дистрибутива, а не обов'язково автоматичне встановлення кожного оновлення.

---

❌ **Вважати LTS незмінною системою.**

LTS-системи отримують виправлення та оновлення в межах визначеної політики підтримки.

---

❌ **Встановлювати пакети з випадкових джерел.**

Невідомі репозиторії та пакети можуть містити небезпечний код або спричиняти конфлікти залежностей.

---

❌ **Вважати, що мінімальний образ завжди найкращий для Docker.**

Компактність образу важлива, але потрібно також враховувати сумісність бібліотек, безпеку, підтримку та зручність діагностики.

---

❌ **Оцінювати сумісність лише за номером версії ядра.**

Для запуску застосунку також важливі архітектура, бібліотеки, runtime, залежності та конфігурація середовища.

---

❌ **Використовувати непідтримуваний дистрибутив на сервері без обґрунтованої причини.**

Слід перевіряти термін підтримки й планувати оновлення системи.

---

# Practical Examples

## Приклад 1 — визначити дистрибутив

    cat /etc/os-release

Завдання:

- знайти назву дистрибутива;
- визначити версію;
- знайти поле `ID`;
- перевірити, чи присутнє поле `ID_LIKE`.

---

## Приклад 2 — визначити версію ядра

    uname -r

Поясни, чому ця команда не замінює `/etc/os-release`.

---

## Приклад 3 — перевірити архітектуру

    uname -m

Визнач, чи використовує система `x86_64`, `aarch64` або іншу архітектуру.

---

## Приклад 4 — перевірити APT

На Ubuntu виконай:

    apt --version

Потім:

    apt list --installed

Друга команда виведе список установлених пакетів. Він може бути довгим.

Щоб перевірити конкретний пакет, наприклад Git:

    apt list --installed git

Для детальнішої інформації можна використати:

    apt show git

---

## Приклад 5 — перевірити джерела пакетів

На Ubuntu можна подивитися основні файли конфігурації APT:

    ls /etc/apt/

Серед них можуть бути:

    sources.list
    sources.list.d/

Сучасні Ubuntu-системи можуть використовувати файли формату `.sources` у каталозі `sources.list.d`, тому не всі репозиторії обов'язково описані в одному `sources.list`.

---

## Приклад 6 — порівняти пакетні менеджери

Знайди документацію для команд:

    apt
    dnf
    pacman
    zypper
    apk

Для кожної визнач:

- як встановлюється пакет;
- як оновлюються індекси;
- як оновлюється система;
- як перевіряється список установлених пакетів.

Не запускай команди пакетних менеджерів, призначені для іншого дистрибутива, без відповідного середовища.

---

## Приклад 7 — перевірити інформацію про пакет

На Ubuntu:

    apt show curl

Знайди:

    Package
    Version
    Depends
    Description

Поясни, що означають ці поля.

## Приклад 9 — перевірити підтримку

Вибери один дистрибутив, наприклад Ubuntu.

Знайди:

- період стандартної підтримки;
- чи є розширена підтримка;

Для цього завдання користуйся офіційною документацією відповідного проєкту.

# Головне

• Linux distribution — це готова операційна система на базі Linux kernel та інших програмних компонентів.

• Ubuntu базується на Debian і є зручним варіантом для навчання Linux та backend-розробки.

• Debian, Ubuntu, Fedora, Arch Linux, openSUSE та Alpine Linux відрізняються своїми інструментами й моделями оновлення.

• Debian та Ubuntu використовують пакети `.deb` і APT.

• Fedora, RHEL, Rocky Linux, AlmaLinux та openSUSE використовують RPM-екосистему, хоча конкретні інструменти керування пакетами відрізняються.

• Arch Linux використовує pacman, а Alpine Linux — apk.

• Пакетний менеджер допомагає встановлювати, оновлювати та видаляти програми й керувати залежностями.

• Fixed release означає окремі випуски, а rolling release — постійний потік оновлень.

• LTS означає триваліший період підтримки певного випуску.

• Версія ядра Linux не тотожна версії дистрибутива.

• Для перевірки дистрибутива використовуй:

    cat /etc/os-release

• Для перевірки ядра використовуй:

    uname -r

• Для перевірки архітектури використовуй:

    uname -m

• Перед використанням системи на сервері перевіряй термін підтримки та сумісність із потрібним програмним забезпеченням.

• Не потрібно вивчати всі дистрибутиви одночасно. Спочатку добре опануй Ubuntu, а потім порівнюй інші системи.

• Для backend-розробника важливо розуміти як Linux загалом, так і специфічні особливості середовища, у якому запускається застосунок.
