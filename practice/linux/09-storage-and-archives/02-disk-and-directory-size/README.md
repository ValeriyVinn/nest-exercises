# 02. Disk and Directory Size

Disk and directory size (розмір диска та директорій) — це тема про визначення розміру файлів, каталогів і файлових систем у Linux, пошук великих файлів, аналіз використання дискового простору та контроль ресурсів.

Ці навички допомагають:

- визначати розмір окремого файлу або директорії;
- знаходити каталоги, які займають найбільше місця;
- порівнювати розміри проєктів;
- знаходити великі файли;
- перевіряти розмір `node_modules`, `.git`, `.next`, `dist` та інших каталогів;
- розуміти різницю між логічним розміром файлу та реально зайнятим дисковим простором;
- готувати проєкти до архівування та резервного копіювання;
- знаходити причини швидкого заповнення диска.

Основні команди та інструменти:

    ls -lh
    stat
    du
    du -sh
    du -ah
    du -h --max-depth=1
    find
    sort
    head
    wc
    numfmt

### Що потрібно пам'ятати

• `ls -lh file` показує розмір файлу у зручному форматі.

• `ls -lh` показує інформацію про елементи директорії, але не обчислює сумарний розмір її вмісту.

• `ls -lSh` сортує елементи за розміром у спадному порядку.

• `stat file` показує детальну інформацію про файл, зокрема його логічний розмір і кількість виділених блоків.

• `du -sh directory/` показує підсумковий розмір директорії з урахуванням використаного дискового простору.

• `du -ah directory/` показує розміри файлів і директорій рекурсивно.

• `du -h --max-depth=1 directory/` допомагає порівнювати розміри безпосередніх піддиректорій.

• `du --apparent-size` показує логічний розмір файлів, а не лише простір, фактично виділений для їхнього зберігання.

• `find` дозволяє знаходити файли за типом, розміром, назвою та іншими критеріями.

• `find -type f` шукає звичайні файли.

• `find -size +100M` шукає файли, розмір яких перевищує 100 MiB у GNU `find`.

• `sort -hr` сортує розміри від найбільшого до найменшого.

• `head -n 10` показує перші десять рядків.

• Приховані файли та директорії починаються з крапки, наприклад `.git` і `.cache`.

• Розмір директорії залежить від її вмісту та способу підрахунку.

• Логічний розмір файлу може відрізнятися від реально зайнятого дискового простору.

• Символічні посилання та жорсткі посилання мають особливості, які потрібно враховувати під час підрахунку.

# File Size

File size — розмір файлу.

У Linux розмір звичайного файлу зазвичай вимірюється в байтах.

Наприклад:

    README.md  → 4096 bytes
    image.png  → 250000 bytes
    archive.tar.gz → 15000000 bytes

Для відображення розміру використовуються команди:

    ls -lh
    stat
    du -h

Важливо розрізняти:

    logical size
        → логічний розмір файлу

    allocated size
        → простір, фактично виділений для файлу у файловій системі

Для звичайних файлів ці значення можуть бути близькими, але вони не обов'язково збігаються.

---

# Bytes and Units

Основна одиниця вимірювання розміру файлу — byte.

    1 byte = 8 bits

У Linux часто використовуються такі одиниці:

    B  → bytes
    K  → KiB у багатьох GNU-утилітах
    M  → MiB у багатьох GNU-утилітах
    G  → GiB у багатьох GNU-утилітах
    T  → TiB у багатьох GNU-утилітах

Двійкові одиниці:

    1 KiB = 1024 bytes
    1 MiB = 1024 KiB
    1 GiB = 1024 MiB
    1 TiB = 1024 GiB

Десяткові одиниці:

    1 kB = 1000 bytes
    1 MB = 1000 kB
    1 GB = 1000 MB
    1 TB = 1000 GB

Наприклад:

    1024 bytes = 1 KiB
    1048576 bytes = 1 MiB
    1073741824 bytes = 1 GiB

Для швидкого читання розмірів зручно використовувати параметр:

    -h

Він означає:

    human-readable

# ls -lh

`ls` — команда для перегляду вмісту директорій.

Параметри:

    -l → long listing format
    -h → human-readable sizes

Приклад:

    ls -lh

Результат може виглядати так:

    -rw-r--r-- 1 user user 4.0K Oct 18 10:00 README.md
    -rw-r--r-- 1 user user  15M Oct 18 10:05 archive.tar.gz
    -rw-r--r-- 1 user user 250K Oct 18 10:10 image.png

Колонки:

    permissions
    links
    owner
    group
    size
    modification time
    name

Наприклад:

    -rw-r--r-- 1 user user 4.0K Oct 18 10:00 README.md

Розмір файлу:

    4.0K

### Важливо

`ls -lh` показує розмір кожного елемента, але не обчислює загальний розмір усіх файлів усередині директорії.

Наприклад:

    ls -lh ~/projects

показує елементи `projects`, але не сумарний розмір усіх проєктів.

Для цього використовують:

    du -sh ~/projects

---

# ls -lS

Параметр `-S` сортує звичайний список файлів за розміром у спадному порядку.

    ls -lS

Найбільші файли будуть на початку списку.

Для зручного відображення:

    ls -lhS

Приклад:

    ls -lhS ~/projects/nest-exercises

Це допомагає швидко порівняти розміри елементів однієї директорії.

### Зворотне сортування

    ls -lhSr

Параметр `-r` змінює порядок сортування на зворотний.

Тепер найменші елементи будуть на початку.

### Обмеження

`ls -lhS` не шукає найбільші файли рекурсивно в усіх піддиректоріях.

Для рекурсивного пошуку краще використовувати:

    find
    du
    sort

---

# ls -la

Параметр `-a` включає приховані елементи.

    ls -la

Приклад:

    .
    ..
    .git
    .gitignore
    .next
    README.md
    package.json
    src

У Linux імена, що починаються з крапки, зазвичай вважаються прихованими.

Для перегляду розмірів:

    ls -lah

Важливо:

• `ls -lah` показує приховані елементи.

• Розмір директорії у списку не дорівнює сумарному розміру всього її вмісту.

• Щоб перевірити розмір прихованої директорії, можна використати `du`.

Наприклад:

    du -sh .git
    du -sh .next

# stat

`stat` показує детальну інформацію про файл або директорію.

Синтаксис:

    stat FILE

Приклад:

    stat README.md

Результат може містити:

    File: README.md
    Size: 4096
    Blocks: 8
    IO Block: 4096
    regular file

Точний формат залежить від системи.

Основні поля:

    File
        → ім'я або шлях

    Size
        → логічний розмір у байтах

    Blocks
        → кількість виділених блоків у форматі, який використовує система

    IO Block
        → рекомендований розмір блока для операцій введення-виведення

    File type
        → тип файлу

    Access
        → права доступу

    Modify
        → час останньої зміни вмісту

    Change
        → час останньої зміни метаданих inode

    Birth
        → час створення, якщо файлова система та система підтримують його відображення

### Перевірити розмір файлу

    stat README.md

### Перевірити розмір директорії

    stat src

Зверни увагу: `stat src` показує розмір самої директорії як файлового об'єкта, а не сумарний розмір файлів усередині неї.

Для сумарного розміру:

    du -sh src

---

# stat — форматований вивід

Параметр `-c` у GNU `stat` дозволяє задати формат результату.

Наприклад:

    stat -c '%n %s bytes' README.md

Результат:

    README.md 4096 bytes

Тут:

    %n → ім'я файлу
    %s → логічний розмір у байтах

Щоб показати кількість блоків:

    stat -c '%n: %s bytes, %b blocks' README.md

Тут:

    %b → кількість виділених блоків

Для точного аналізу потрібно враховувати, що інтерпретація виділеного простору залежить від файлової системи та її особливостей.

# Directory Size

Directory size — розмір директорії.

Під час роботи з Linux важливо розрізняти два поняття:

    size of directory entry
        → розмір самої директорії як об'єкта файлової системи

    total disk usage of directory
        → простір, який займають файли та піддиректорії всередині неї

Для більшості практичних задач розробника потрібен другий варіант.

Наприклад:

    du -sh ~/projects/nest-exercises

Команда показує підсумковий розмір проєкту.

---

# du -sh

`du -sh DIRECTORY` — основна команда для перевірки загального розміру директорії.

Синтаксис:

    du -sh PATH

Параметри:

    -s → summary
    -h → human-readable

Приклад:

    du -sh ~/projects/nest-exercises

Умовний результат:

    1.4G    /home/user/projects/nest-exercises

Перевірка іншого проєкту:

    du -sh ~/projects/next-exercises

Перевірка домашньої директорії:

    du -sh ~

Перевірка поточної директорії:

    du -sh .

Перевірка батьківської директорії:

    du -sh ..

### Коли використовувати

• Коли потрібно швидко дізнатися розмір проєкту.

• Коли потрібно перевірити розмір резервної копії.

• Коли потрібно порівняти розміри директорій.

• Коли потрібно оцінити обсяг даних перед архівуванням.

---

# du -ah

`du -ah` показує розміри файлів і директорій рекурсивно.

    du -ah ~/projects/nest-exercises

Команда може вивести багато рядків.

Наприклад:

    4.0K    ~/projects/nest-exercises/README.md
    8.0K    ~/projects/nest-exercises/package.json
    24K     ~/projects/nest-exercises/src/app
    120M    ~/projects/nest-exercises/node_modules
    1.4G    ~/projects/nest-exercises

Значення наведені лише для прикладу.

Щоб побачити найбільші результати:

    du -ah ~/projects/nest-exercises | sort -hr | head -n 10

Це покаже десять найбільших рядків у відсортованому списку.

Важливо: до результатів можуть потрапляти як файли, так і директорії, а отже один і той самий вміст може бути представлений на різних рівнях дерева. Не слід складати всі показані значення, оскільки це призведе до подвійного підрахунку.

---

# du --max-depth

Параметр `--max-depth` обмежує глибину відображення директорій.

Наприклад:

    du -h --max-depth=1 ~/projects

Показує розміри безпосередніх піддиректорій та загальний підсумок `~/projects`.

Приклад:

    1.4G    /home/user/projects/nest-exercises
    900M    /home/user/projects/next-exercises
    200M    /home/user/projects/demo
    2.5G    /home/user/projects

Значення умовні.

Інші рівні:

    du -h --max-depth=0 ~/projects
    du -h --max-depth=1 ~/projects
    du -h --max-depth=2 ~/projects

Пояснення:

    0 → лише підсумок заданого каталогу
    1 → каталог та безпосередні підкаталоги
    2 → ще один рівень вкладеності

Короткий варіант у GNU `du`:

    du -h -d 1 ~/projects

# Пошук найбільших директорій

Щоб побачити, які піддиректорії займають найбільше місця:

    du -h --max-depth=1 ~/projects | sort -hr

Щоб обмежити результат десятьма рядками:

    du -h --max-depth=1 ~/projects | sort -hr | head -n 10

Для конкретного проєкту:

    du -h --max-depth=1 ~/projects/nest-exercises | sort -hr

Цей спосіб особливо корисний для проєктів, у яких можуть бути:

    node_modules/
    .git/
    .next/
    dist/
    build/
    public/
    src/

Не всі ці директорії обов'язково існують у кожному проєкті.

# Hidden Directories

Приховані директорії в Linux зазвичай починаються з крапки.

Приклади:

    .git/
    .next/
    .cache/
    .config/
    .local/

У проєктах вони можуть займати значний обсяг дискового простору.

### Перевірити .git

    du -sh .git

### Перевірити .next

    du -sh .next

### Перевірити .cache

    du -sh ~/.cache

### Показати розміри видимих і прихованих елементів поточного каталогу

Для звичайних файлів та директорій можна використати:

    du -sh .[^.]* *

Однак цей шаблон не є універсальним для всіх можливих імен та ситуацій.

Для простого навчального сценарію краще перевіряти важливі приховані каталоги окремо:

    du -sh .git
    du -sh .next
    du -sh .cache

Якщо директорія відсутня, `du` повідомить про помилку.

# Apparent Size

Apparent size — логічний розмір файлу, тобто розмір його вмісту, який бачить програма.

Для перевірки використовують:

    du --apparent-size -h FILE

Наприклад:

    du --apparent-size -h image.iso

Для директорії:

    du --apparent-size -sh ~/projects/nest-exercises

Звичайний `du` зазвичай показує простір, виділений для зберігання даних.

`du --apparent-size` показує логічний розмір.

Ці значення можуть відрізнятися.

### Коли це важливо

• Під час роботи з великими файлами.

• Під час аналізу sparse files.

• Під час порівняння логічного розміру даних із фактично зайнятим простором.

• Під час оцінювання розміру файлів перед передаванням або архівуванням.

---

# Sparse Files

Sparse file — файл, у якому частина логічного простору не має відповідних фізично виділених блоків даних.

Наприклад, програма може створити файл із логічним розміром 1 GiB, але фактично записати в нього лише невелику частину даних.

Тоді:

    logical size → 1 GiB
    allocated size → може бути значно меншим

Перевірити логічний розмір:

    stat -c '%n: %s bytes' sparse-file.img

Перевірити оцінку використаного простору:

    du -h sparse-file.img

Перевірити логічний розмір через `du`:

    du --apparent-size -h sparse-file.img

Значення залежать від способу створення файлу та підтримки sparse files файловою системою.

Важливо: копіювання або архівування sparse file може змінити співвідношення між логічним розміром та фактично зайнятим простором.

# find

`find` — команда для пошуку файлів і директорій за заданими критеріями.

Синтаксис:

    find PATH [EXPRESSION]

Наприклад:

    find ~/projects -type f

Знайти всі звичайні файли всередині `~/projects`.

Основні параметри:

    -type f → звичайні файли
    -type d → директорії
    -name   → пошук за шаблоном імені
    -iname  → пошук за шаблоном без урахування регістру
    -size   → пошук за розміром
    -maxdepth → обмеження глибини пошуку

`find` обходить дерево каталогів рекурсивно, якщо глибина не обмежена.

---

# find -type f

Щоб знайти тільки звичайні файли:

    find ~/projects -type f

Приклад:

    /home/user/projects/demo/README.md
    /home/user/projects/demo/package.json
    /home/user/projects/demo/src/app.js

Для подальшого аналізу можна передати результат іншій команді.

Наприклад:

    find ~/projects -type f | head -n 20

Покаже перші двадцять знайдених шляхів.

Зверни увагу: порядок результатів `find` не обов'язково буде відсортований за назвою або розміром.

---

# find -type d

Щоб знайти тільки директорії:

    find ~/projects -type d

Приклад:

    /home/user/projects
    /home/user/projects/demo
    /home/user/projects/demo/src

Це корисно для пошуку певних каталогів.

Наприклад, усіх директорій `node_modules`:

    find ~/projects -type d -name node_modules

Або всіх директорій `.git`:

    find ~/projects -type d -name .git

Великий каталог проєктів може містити багато результатів.

# find -name

Параметр `-name` дозволяє шукати файли та директорії за шаблоном імені.

Наприклад:

    find ~/projects -type f -name "*.log"

Знайти файли з розширенням `.log`.

Знайти архіви ZIP:

    find ~/projects -type f -name "*.zip"

Знайти архіви TAR.GZ:

    find ~/projects -type f -name "*.tar.gz"

Знайти файли README:

    find ~/projects -type f -name "README.md"

Знайти файли резервних копій із певним розширенням:

    find ~/backups -type f -name "*.bak"

Важливо: шаблон у лапках передається команді `find`, а не розгортається оболонкою до запуску команди.

# find -size

Параметр `-size` дозволяє шукати файли за розміром.

Приклади:

    find ~/projects -type f -size +100M
    find ~/projects -type f -size -10M
    find ~/projects -type f -size 50M

У GNU `find` суфікси `M` і `G` для `-size` означають одиниці по 1024, а округлення розміру відбувається до блоків по 1 KiB.

Основні приклади:

    -size +100M
        → файли, розмір яких перевищує 100 MiB

    -size -10M
        → файли, розмір яких менший за 10 MiB

    -size 50M
        → файли, розмір яких після округлення до одиниць по 1 MiB дорівнює 50 MiB

Для точного розуміння меж `find -size` варто враховувати одиниці вимірювання та правила округлення.

# Знайти файли понад 100 MiB

Практичний приклад:

    find ~/projects -type f -size +100M

Команда знаходить звичайні файли, логічний розмір яких перевищує зазначену межу.

Результат може містити:

    великі архіви
    ISO-образи
    відеофайли
    дампи баз даних
    великі файли журналів
    інші великі файли

Це лише можливі приклади, а не гарантія того, що такі файли будуть знайдені.

Щоб шукати у всій системі, можна використовувати кореневий каталог:

    sudo find / -type f -size +100M

Але така команда може працювати довго та виводити повідомлення про відсутність доступу.

Починай із конкретної директорії, наприклад `~/projects`.

---

# find із сортуванням

Щоб знайти файли, а потім переглянути їхні розміри, можна поєднати `find`, `du`, `sort` і `head`.

Наприклад:

    find ~/projects -type f -exec du -h {} + | sort -hr | head -n 10

Що відбувається:

    find
        → знаходить звичайні файли

    -exec du -h {} +
        → передає знайдені шляхи команді du групами

    sort -hr
        → сортує результати за розміром

    head -n 10
        → показує перші десять рядків

Це зручний варіант для пошуку великих файлів.

Важливо: `du` оцінює виділений дисковий простір, а не обов'язково логічний розмір файлу. Якщо потрібно досліджувати саме логічні розміри, використовуй `stat` або `du --apparent-size`.

# find та du: різні задачі

`find` шукає файли за критеріями.

`du` оцінює використання дискового простору.

Приклад пошуку великих файлів:

    find ~/projects -type f -size +100M

Приклад оцінювання розміру директорій:

    du -h --max-depth=1 ~/projects

Приклад пошуку файлів із відображенням розміру:

    find ~/projects -type f -exec du -h {} + | sort -hr | head -n 10

Для діагностики часто потрібно використовувати обидва інструменти.

---

# wc -l

`wc` — команда для підрахунку рядків, слів і байтів.

Параметр `-l` рахує рядки.

    find ~/projects -type f | wc -l

Це дозволяє оцінити кількість знайдених файлів.

Приклад:

    find ~/projects -type f -name "*.log" | wc -l

Показує кількість знайдених лог-файлів.

Важливо: цей спосіб підрахунку через текстовий потік може бути ненадійним для імен файлів із символами нового рядка. Для звичайних навчальних сценаріїв він зручний, але для складних автоматизованих задач варто використовувати безпечніші методи обробки шляхів.

---

# numfmt

`numfmt` — утиліта GNU Coreutils для форматування числових значень.

Наприклад:

    numfmt --to=iec 1048576

Результат:

    1.0M

Зручний варіант для перетворення числових байтів у читабельні одиниці:

    numfmt --to=iec-i 1073741824

Результат:

    1.0 Gi

Залежно від параметрів та версії утиліти формат може відрізнятися.

`numfmt` корисний у Bash-скриптах, коли потрібно форматувати числові розміри.

Для звичайної ручної перевірки файлів найчастіше достатньо:

    ls -lh
    du -sh

# Пошук найбільших файлів у проєкті

Для проєкту `nest-exercises` можна виконати:

    find ~/projects/nest-exercises -type f -exec du -h {} + | sort -hr | head -n 10

Це дозволяє визначити, які файли займають найбільше виділеного дискового простору.

Для пошуку файлів, логічний розмір яких перевищує 50 MiB:

    find ~/projects/nest-exercises -type f -size +50M

Якщо потрібно перевірити лише файли з певним розширенням:

    find ~/projects/nest-exercises -type f -name "*.log" -size +10M

Це корисно, якщо великі журнали займають значну частину диска.

# Пошук найбільших директорій у проєкті

Почни з першого рівня:

    du -h --max-depth=1 ~/projects/nest-exercises | sort -hr

Якщо потрібно дослідити конкретну директорію:

    du -h --max-depth=1 ~/projects/nest-exercises/node_modules | sort -hr

Або:

    du -h --max-depth=1 ~/projects/nest-exercises/.git | sort -hr

Якщо каталог відсутній, команда повідомить про помилку.

Не потрібно відразу видаляти найбільшу директорію. Спочатку з'ясуй, що вона містить і чи потрібна вона проєкту.

# Порівняння розмірів проєктів

Щоб порівняти розміри кількох проєктів:

    du -sh ~/projects/next-exercises ~/projects/nest-exercises

Для всіх видимих елементів у `~/projects`:

    du -sh ~/projects/*

Ця команда не охоплює приховані імена, які не збігаються з шаблоном `*`.

Для сортування:

    du -sh ~/projects/* | sort -hr

Результат показує розміри елементів, які відповідають шаблону.

Якщо потрібно врахувати приховані директорії, перевір їх окремо.

# Directory Size та Git

Директорія `.git` містить службові дані Git, зокрема об'єкти, історію комітів, посилання та інші метадані репозиторію.

Перевірити розмір:

    du -sh .git

Перевірити розмір репозиторію:

    du -sh .

Порівняти:

    du -sh .git .

Зверни увагу: під час порівняння `.git` та всього репозиторію другий результат уже включає `.git`.

Тому не потрібно складати ці два значення.

Велика директорія `.git` може бути пов'язана з історією репозиторію, великими об'єктами або іншими даними Git.

Не видаляй `.git`, якщо потрібно зберегти локальний репозиторій, історію комітів і налаштування Git.

---

# Directory Size та Node.js

У Node.js-проєктах значний простір можуть займати:

    node_modules/
    .next/
    dist/
    build/
    coverage/
    .cache/

Перевірка `node_modules`:

    du -sh node_modules

Перевірка `.next`:

    du -sh .next

Перевірка `dist`:

    du -sh dist

Перевірка `coverage`:

    du -sh coverage

Якщо потрібно оцінити основні піддиректорії проєкту:

    du -h --max-depth=1 . | sort -hr

### Важливо

• `node_modules` часто можна відновити за допомогою пакетного менеджера, якщо збережені `package.json` та відповідний lock-файл.

• `.next` зазвичай містить результати роботи Next.js, але перед видаленням потрібно переконатися, що сервер розробки або інші процеси не використовують ці файли.

• `dist` та `build` можуть містити результати компіляції, необхідні для розгортання.

• Не можна автоматично вважати всі великі директорії непотрібними.

# Directory Size та PostgreSQL

У проєктах із базами даних потрібно уважно ставитися до розміру каталогів, де зберігаються дані PostgreSQL.

Розмір бази даних та розмір усієї директорії з файлами PostgreSQL — різні поняття.

Файли бази даних не слід видаляти вручну для звільнення місця.

Для загальної діагностики можна перевірити доступний простір:

    df -h

Для власних файлів проєкту:

    du -sh ~/projects

Якщо потрібно дослідити розмір даних PostgreSQL, краще використовувати інструменти PostgreSQL, а не видаляти файли з каталогу даних.

Наприклад, у `psql` можна виконати:

    SELECT pg_size_pretty(pg_database_size('educational'));

Цей SQL-запит показує розмір бази даних `educational`.

Щоб отримати розмір усіх баз даних:

    SELECT
        datname,
        pg_size_pretty(pg_database_size(datname)) AS size
    FROM pg_database
    ORDER BY pg_database_size(datname) DESC;

Ці запити належать до інструментів PostgreSQL, а не до команд Linux.

# Визначення розміру перед архівуванням

Перед створенням архіву корисно оцінити розмір директорії.

Наприклад:

    du -sh ~/projects/nest-exercises

Після цього можна створити архів у наступних темах:

    tar
    gzip
    zip

Розмір вихідної директорії не обов'язково дорівнює розміру архіву.

Причини:

    compression
    archive metadata
    sparse files
    excluded files
    file format

Наприклад, текстові файли можуть добре стискатися, а вже стиснені зображення або архіви часто стискаються значно гірше.

Перед створенням резервної копії також потрібно перевірити вільний простір:

    df -h

Особливо важливо перевірити файлову систему, на якій буде зберігатися архів.

# Перевірка розміру та вільного місця

Розмір директорії та доступний простір файлової системи — різні показники.

Наприклад:

    du -sh ~/projects
    df -h ~/projects

Перша команда оцінює розмір директорії `projects`.

Друга показує використання файлової системи, на якій розташована ця директорія.

Це допомагає зрозуміти:

    скільки місця займають проєкти;
    скільки простору доступно;
    чи вистачить місця для резервної копії;
    чи потрібно шукати великі файли.

# Типові помилки

## 1. Плутати розмір директорії з розміром її запису

❌ Використовувати `ls -ld directory` як спосіб дізнатися сумарний розмір її вмісту.

Правильно:

    du -sh directory

`ls -ld` показує інформацію про саму директорію, а не про весь її вміст.

---

## 2. Плутати логічний розмір із виділеним простором

`stat` може показувати логічний розмір файлу, який відрізняється від простору, виділеного файловою системою.

Для порівняння:

    stat file.img
    du -h file.img
    du --apparent-size -h file.img

---

## 3. Вважати, що ls -lh показує всі файли рекурсивно

Команда:

    ls -lh

показує елементи поточної директорії.

Для рекурсивного пошуку використовуй:

    find
    du -ah

---

## 4. Забувати про приховані каталоги

Шаблон:

    *

не охоплює приховані імена за стандартного налаштування Bash.

Тому для перевірки `.git` або `.next` використовуй:

    du -sh .git
    du -sh .next

---

## 5. Шукати великі файли без обмеження директорії

Команда:

    sudo find / -type f -size +100M

може працювати довго.

Для початку краще:

    find ~/projects -type f -size +100M

---

## 6. Неправильно розуміти find -size

Команда:

    find . -type f -size +100M

у GNU `find` шукає файли більші за 100 MiB за правилами округлення, які використовуються параметром `-size`.

Для аналізу логічного розміру та фактично зайнятого простору використовуй відповідні інструменти окремо.

---

## 7. Складати всі результати du -ah

Вивід `du -ah` містить як файли, так і директорії, які включають ці файли.

Якщо скласти всі числа, частина простору буде врахована кілька разів.

---

## 8. Видаляти великі файли без перевірки

Великий файл може бути:

    database file
    backup
    system log
    application dependency
    archive
    virtual machine image

Перед видаленням потрібно визначити призначення файлу.

---

## 9. Ігнорувати права доступу

Під час пошуку `find` або виконання `du` можуть виникати помилки доступу.

Не завжди потрібно запускати команду з `sudo`.

Почни з директорій, до яких маєш доступ.

---

## 10. Вважати, що розмір проєкту дорівнює розміру архіву

Розмір архіву залежить від алгоритму стиснення, типу файлів і правил включення даних.

Для оцінювання вихідного каталогу використовуй:

    du -sh directory

Для перевірки створеного архіву:

    ls -lh archive.tar.gz

# Основні правила

    ls -lh
        → показати розміри елементів директорії

    ls -lhS
        → відсортувати елементи за розміром

    stat FILE
        → отримати детальну інформацію про файл

    du -sh DIR
        → оцінити сумарний розмір директорії

    du -ah DIR
        → переглянути розміри файлів і директорій

    du --max-depth=1 DIR
        → порівняти розміри піддиректорій

    find DIR -type f
        → знайти звичайні файли

    find DIR -type f -size +100M
        → знайти файли понад 100 MiB

    sort -hr
        → сортувати розміри за спаданням

    head -n 10
        → показати перші десять результатів

    df -h
        → перевірити доступний простір файлових систем

---

# Головне

• `ls -lh` показує розмір окремих елементів, але не сумарний розмір дерева каталогів.

• `stat` надає детальні метадані файлу, включно з логічним розміром.

• `du -sh DIR` — основна команда для оцінювання загального розміру директорії.

• `du -ah DIR` допомагає дослідити розміри файлів і директорій.

• `du --max-depth=1 DIR` допомагає визначити, які піддиректорії займають найбільше місця.

• `find` дозволяє шукати файли за розміром, типом та іменем.

• `sort -hr` і `head` дозволяють швидко отримати список найбільших результатів.

• Логічний розмір файлу не завжди дорівнює фактично зайнятому дисковому простору.

• Приховані каталоги `.git`, `.next` та `.cache` можуть займати значний обсяг.

• Не можна бездумно складати всі значення з `du -ah`, оскільки розміри піддиректорій уже включені до розмірів батьківських директорій.

• Перед створенням резервної копії варто перевірити розмір вихідної директорії та доступний простір на файловій системі.

• Для повсякденної роботи розробника корисно знати:

    ls -lh
    stat
    du -sh
    du -h --max-depth=1
    find
    sort -hr
    head -n 10
    df -h

• Основна модель роботи:

    визначити задачу
        ↓
    перевірити розмір файлу або директорії
        ↓
    du / stat / ls
        ↓
    знайти найбільші файли та піддиректорії
        ↓
    find / sort / head
        ↓
    оцінити використання диска
        ↓
    df -h
        ↓
    безпечно звільнити простір за потреби

• Правильне визначення розмірів файлів і директорій допомагає контролювати дисковий простір, знаходити зайві дані та готувати проєкти до архівування й резервного копіювання.
