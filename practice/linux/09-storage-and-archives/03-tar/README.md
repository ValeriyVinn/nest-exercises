# 03. TAR — архівування файлів і директорій

`tar` (Tape Archive) — це стандартна Linux-утиліта для об'єднання файлів і директорій в один архів, перегляду його вмісту, додавання файлів та розпакування.

`tar` сам по собі зазвичай **об'єднує файли без стиснення**. Для зменшення розміру архіву його часто використовують разом із `gzip`, `bzip2` або `xz`.

## 1. Для чого потрібен TAR

`tar` використовують, щоб:

- ✔ об'єднати багато файлів в один архів;
- ✔ заархівувати цілу директорію зі структурою вкладених файлів;
- ✔ зберегти структуру проєкту під час перенесення;
- ✔ створювати резервні копії;
- ✔ переглядати вміст архіву без розпакування;
- ✔ розпаковувати архіви;
- ✔ зберігати права доступу та інші атрибути файлів;
- ✔ створювати стиснені архіви `.tar.gz`, `.tar.bz2`, `.tar.xz`.

Наприклад, у проєкті можуть бути сотні файлів:

    nest-exercises/
    ├── package.json
    ├── README.md
    ├── practice/
    │   └── linux/
    └── src/

Замість копіювання кожного файлу окремо можна створити один архів:

    nest-exercises.tar

Або стиснений архів:

    nest-exercises.tar.gz

## 2. Основна команда `tar`

Загальний синтаксис:

    tar [ОПЦІЇ] [АРХІВ] [ФАЙЛИ_АБО_ДИРЕКТОРІЇ]

Найчастіше використовуються такі операції:

| Опція | Значення |
|---|---|
| `-c` | Create — створити архів |
| `-x` | Extract — розпакувати архів |
| `-t` | List — переглянути вміст архіву |
| `-f` | File — вказати ім'я файлу архіву |
| `-v` | Verbose — показувати оброблювані файли |
| `-z` | Використовувати gzip |
| `-j` | Використовувати bzip2 |
| `-J` | Використовувати xz |
| `-C` | Змінити директорію перед виконанням операції |
| `-p` | Під час розпакування зберігати права доступу, якщо це дозволено |
| `--exclude` | Виключити файли або директорії за шаблоном |
| `-k` | Не перезаписувати наявні файли під час розпакування |
| `--overwrite` | Дозволити перезапис наявних файлів під час розпакування |

**Що потрібно пам'ятати:**

- `-c` — створити архів.
- `-x` — витягнути файли з архіву.
- `-t` — переглянути вміст.
- `-f` — наступний аргумент є назвою архіву.
- `-v` — показувати список оброблюваних файлів.
- `-z`, `-j`, `-J` — використовувати певний алгоритм стиснення.

Порядок деяких опцій можна змінювати, але назву архіву та список файлів потрібно вказувати в правильному порядку.

## 3. Створення архіву `.tar`

### 3.1. Архівування одного файлу

Створимо архів із файлу `README.md`:

    tar -cf readme.tar README.md

Пояснення:

- `-c` — створити архів;
- `-f readme.tar` — назва архіву;
- `README.md` — файл, який додаємо.

Перевіримо результат:

    ls -lh readme.tar

### 3.2. Архівування кількох файлів

    tar -cf documents.tar README.md package.json package-lock.json

В архів потраплять три зазначені файли.

Щоб додати інші файли, потрібно вказати їх у команді під час створення архіву.

### 3.3. Архівування директорії

    tar -cf project.tar project/

Команда створить `project.tar`, що міститиме директорію `project/` разом із її файлами та вкладеними директоріями.

Наприклад:

    project/
    ├── README.md
    ├── package.json
    └── src/
        ├── app.js
        └── styles.css

Після архівування структура збережеться всередині `project.tar`.

### 3.4. Створення архіву з відображенням файлів

    tar -cvf project.tar project/

Опція `-v` показує файли, які додаються до архіву.

Це зручно для великих директорій, коли потрібно бачити, що саме архівується.

### 3.5. Архівування поточної директорії

Перебуваючи всередині директорії проєкту:

    tar -cf ../project.tar .

Архів буде створений на один рівень вище.

Крапка `.` означає поточну директорію та її вміст, включно з прихованими файлами, доступними для читання.

**Важливо:** якщо архів створюється всередині директорії, яку архівуємо, він може потрапити до власного вмісту під час обробки. Краще зберігати архів поза цією директорією.

## 4. Перегляд вмісту архіву

### 4.1. Переглянути список файлів

    tar -tf project.tar

Команда покаже назви файлів і директорій, що містяться в архіві, без розпакування.

### 4.2. Переглянути список із додатковою інформацією

    tar -tvf project.tar

Опція `-v` виводить детальнішу інформацію, зокрема тип запису, права доступу, власника, розмір і дату.

### 4.3. Перевірити архів перед розпакуванням

    tar -tf project.tar

Переконайся, що структура архіву відповідає очікуваній і в ньому немає небажаних шляхів.

Це особливо важливо, якщо архів завантажено з інтернету або отримано від іншої людини.

## 5. Розпакування `.tar`

### 5.1. Розпакувати архів у поточну директорію

    tar -xf project.tar

Команда витягне файли з архіву в поточну директорію.

Якщо архів містить директорію `project/`, вона буде створена або доповнена в поточному місці.

### 5.2. Розпакувати з відображенням файлів

    tar -xvf project.tar

Опція `-v` показує файли, які розпаковуються.

### 5.3. Розпакувати в конкретну директорію

Спочатку створимо директорію:

    mkdir -p extracted

Потім розпакуємо архів:

    tar -xf project.tar -C extracted/

Опція `-C` вказує директорію, у якій потрібно виконати операцію.

**Важливо:** директорія після `-C` має існувати. Сам `tar` зазвичай не створює її автоматично.

### 5.4. Розпакувати один файл з архіву

Припустімо, архів містить `project/README.md`.

    tar -xf project.tar project/README.md

Буде витягнуто лише зазначений файл.

Шлях потрібно вказувати так, як він записаний усередині архіву. Перевірити його можна командою:

    tar -tf project.tar

### 5.5. Розпакувати одну директорію

    tar -xf project.tar project/src/

Ця команда намагається витягнути записи, що відповідають зазначеному шляху. Якщо потрібні файли всередині директорії, переконайся за допомогою `tar -tf`, як саме вони записані в архіві.

## 6. Формат `.tar` і стиснення

Файл `.tar` — це архів, але не обов'язково стиснений архів.

Наприклад:

    project.tar

об'єднує файли, але зазвичай не зменшує їхній сумарний розмір.

Щоб стиснути архів, використовують алгоритми на кшталт gzip, bzip2 або xz.

| Розширення | Формат | Опція `tar` |
|---|---|---|
| `.tar` | Архів без додаткового стиснення | — |
| `.tar.gz` | TAR + gzip | `-z` |
| `.tgz` | Інша поширена назва TAR + gzip | `-z` |
| `.tar.bz2` | TAR + bzip2 | `-j` |
| `.tar.xz` | TAR + xz | `-J` |

Докладніше про самі алгоритми стиснення буде в темі `04-gzip-and-zip`.

## 7. Створення стиснених архівів

### 7.1. Створити `.tar.gz`

    tar -czf project.tar.gz project/

Пояснення:

- `-c` — створити архів;
- `-z` — стиснути за допомогою gzip;
- `-f` — указати ім'я архіву.

Це один із найпоширеніших форматів для перенесення файлів у Linux.

### 7.2. Створити `.tgz`

    tar -czf project.tgz project/

`.tgz` — скорочене розширення для архіву TAR, стисненого gzip.

За призначенням воно відповідає `.tar.gz`.

### 7.3. Створити `.tar.bz2`

    tar -cjf project.tar.bz2 project/

Опція `-j` використовує bzip2.

### 7.4. Створити `.tar.xz`

    tar -cJf project.tar.xz project/

Опція `-J` використовує xz.

### 7.5. Порівняти розміри архівів

Після створення різних форматів можна перевірити їхній розмір:

    ls -lh project.tar project.tar.gz project.tar.bz2 project.tar.xz

Результат залежить від вмісту. Текстові файли часто добре стискаються, а вже стиснені зображення, відео та архіви можуть зменшитися незначно.

## 8. Перегляд і розпакування стиснених архівів

### 8.1. Переглянути `.tar.gz`

    tar -tzf project.tar.gz

Опція `-z` указує, що архів стиснений gzip.

### 8.2. Розпакувати `.tar.gz`

    tar -xzf project.tar.gz

### 8.3. Розпакувати `.tar.bz2`

    tar -xjf project.tar.bz2

Переглянути вміст:

    tar -tjf project.tar.bz2

### 8.4. Розпакувати `.tar.xz`

    tar -xJf project.tar.xz

Переглянути вміст:

    tar -tJf project.tar.xz

### 8.5. Розпакувати стиснений архів у певну директорію

    mkdir -p backup-restore
    tar -xzf project.tar.gz -C backup-restore/

Опції `-z`, `-j` і `-J` визначають алгоритм стиснення, а `-C` — місце розпакування.

## 9. Керування шляхами всередині архіву

### 9.1. Чому важливо, звідки запускати `tar`

Припустімо, структура така:

    ~/projects/
    └── nest-exercises/
        ├── package.json
        ├── README.md
        └── practice/

Якщо виконати:

    cd ~/projects
    tar -cf nest-exercises.tar nest-exercises/

у архіві буде шлях, що починається з `nest-exercises/`.

Це зазвичай зручно, оскільки після розпакування файли опиняться в окремій директорії.

### 9.2. Використання `-C` під час створення архіву

    tar -cf nest-exercises.tar -C ~/projects nest-exercises/

Опція `-C` дозволяє перейти до зазначеної директорії перед обробкою наступних шляхів.

У цьому прикладі архів міститиме `nest-exercises/`, але шлях не включатиме повний шлях домашньої директорії.

### 9.3. Архівувати лише вміст директорії

Якщо потрібно, щоб у корені архіву були самі файли проєкту, а не додаткова директорія верхнього рівня:

    tar -cf project-content.tar -C ~/projects/nest-exercises .

У цьому випадку вміст `nest-exercises/` записується відносно кореня архіву.

Переглянь результат:

    tar -tf project-content.tar

**Порада:** перед створенням архіву виріши, що саме має з'явитися після розпакування: окрема директорія проєкту чи одразу його вміст.

## 10. Виключення файлів і директорій

Не завжди потрібно додавати до архіву всі файли проєкту.

Наприклад, у JavaScript-проєкті зазвичай можна не включати `node_modules/`, якщо залежності можна відновити командою `npm install`.

### 10.1. Виключити одну директорію

    tar -czf project.tar.gz --exclude='node_modules' project/

Шаблон `--exclude` не додає до архіву відповідні записи.

### 10.2. Виключити кілька директорій

    tar -czf project.tar.gz \
        --exclude='node_modules' \
        --exclude='.next' \
        --exclude='.git' \
        project/

Символ `\` у кінці рядка дозволяє продовжити команду на наступному рядку Bash.

У цьому прикладі виключаються залежності, згенеровані файли Next.js і службова директорія Git.

### 10.3. Виключити файли за шаблоном

Наприклад, не додавати файли журналів із розширенням `.log`:

    tar -czf project.tar.gz --exclude='*.log' project/

Шаблони виключення потрібно перевіряти на реальному вмісті архіву, особливо якщо вони складні або містять вкладені шляхи.

### 10.4. Перевірити, що саме потрапило до архіву

    tar -tzf project.tar.gz

Переконайся, що потрібні файли присутні, а зайві директорії виключені.

**Важливо:** не виключай автоматично файли лише через їхній розмір. Конфігурації, `.env.example`, міграції бази даних та інші файли можуть бути потрібними для відновлення проєкту. Справжні секрети, навпаки, не слід включати до архіву без належного захисту.

## 11. Додавання файлів до наявного архіву

Звичайний TAR-архів без стиснення підтримує додавання файлів.

### 11.1. Додати файл до `.tar`

    tar -rf project.tar notes.md

Опція `-r` додає файл до наявного архіву.

### 11.2. Додати декілька файлів

    tar -rf project.tar notes.md todo.txt

### 11.3. Важливе обмеження

Опція `-r` призначена для звичайних TAR-архівів, а не для стиснених архівів на кшталт `.tar.gz`, `.tar.bz2` чи `.tar.xz`.

Щоб оновити стиснений архів, зазвичай потрібно створити його заново з потрібним набором файлів.

Для практики:

    tar -tf project.tar

Після додавання перевір, що нові файли з'явилися в списку.

## 12. Оновлення файлів у TAR-архіві

Опція `-u` додає до архіву файли, які новіші за відповідні файли в архіві, або яких там ще немає.

    tar -uf project.tar README.md

Ця команда працює з несжатим TAR-архівом.

Щоб перевірити вміст:

    tar -tvf project.tar

Важливо розуміти: TAR не є повноцінною системою керування версіями. Для історії змін коду використовуй Git, а для резервних копій — відповідний процес резервування.

## 13. Вилучення файлів з архіву

З TAR-архіву можна витягнути окремий файл, не розпаковуючи все.

### 13.1. Витягнути файл

    tar -xf project.tar project/README.md

### 13.2. Витягнути декілька файлів

    tar -xf project.tar project/README.md project/package.json

### 13.3. Не перезаписувати наявні файли

    tar -xkf project.tar

Опція `-k` наказує не перезаписувати файли, які вже існують.

Це корисно, якщо потрібно уникнути випадкового перезапису локальних даних.

### 13.4. Обережно з перезаписуванням

За замовчуванням розпакування може перезаписати наявні файли. Перед розпакуванням у важливу директорію перевір вміст архіву:

    tar -tf project.tar

Для незнайомих архівів краще створити окрему директорію й розпаковувати туди.

## 14. Збереження прав доступу та атрибутів

TAR може зберігати інформацію про права доступу, власника, групу, часові мітки та інші атрибути.

### 14.1. Перегляд прав у архіві

    tar -tvf project.tar

У виводі можна побачити права на кшталт:

    -rw-r--r-- ...
    drwxr-xr-x ...

### 14.2. Відновлення прав доступу

Звичайне розпакування відновлює права доступу з урахуванням обмежень поточного користувача та системи.

Опція `-p` просить зберегти права доступу під час розпакування:

    tar -xpf project.tar

Не запускай таку команду з `sudo` без потреби.

### 14.3. Власник і група

Звичайний користувач не може довільно встановлювати власника файлів. Під час відновлення резервних копій системи можуть знадобитися права адміністратора та додаткові опції, наприклад:

    sudo tar --same-owner -xpf system-backup.tar -C /restore/

Використовуй такі команди лише тоді, коли справді потрібно відновлювати системні файли та їхні власники. Для звичайного навчального проєкту це зазвичай не потрібно.

## 15. Архівування проєкту для резервної копії

Розглянемо практичний приклад для `nest-exercises`.

### 15.1. Перейти до батьківської директорії

    cd ~/projects

### 15.2. Створити стиснений архів

    tar -czf nest-exercises-backup.tar.gz \
        --exclude='nest-exercises/node_modules' \
        --exclude='nest-exercises/.next' \
        --exclude='nest-exercises/.git' \
        nest-exercises/

Це створить архів із проєктом, але виключить зазначені директорії.

Пам'ятай: `.git` містить історію Git. Якщо хочеш зберегти локальний репозиторій разом з історією, не виключай його бездумно.

### 15.3. Перевірити архів

    tar -tzf nest-exercises-backup.tar.gz

### 15.4. Перевірити розмір

    ls -lh nest-exercises-backup.tar.gz

### 15.5. Відновити в окрему директорію

    mkdir -p ~/restore-test
    tar -xzf nest-exercises-backup.tar.gz -C ~/restore-test/

### 15.6. Переконатися, що файли відновлені

    ls -la ~/restore-test/nest-exercises/

Це простий спосіб перевірити, чи архів придатний до використання.

**Головне правило резервного копіювання:** створення архіву ще не доводить, що резервна копія працює. Перевіряй, чи її можна прочитати й відновити.

## 16. Архівування з абсолютними та відносними шляхами

### 16.1. Відносний шлях

    tar -cf project.tar project/

Відносні шляхи зазвичай зручніші: після розпакування архів не намагається відтворити повний шлях до початкової директорії.

### 16.2. Абсолютні шляхи

Якщо передати абсолютний шлях, GNU tar зазвичай прибирає початковий `/` під час запису до архіву та попереджає про це.

Наприклад:

    tar -cf project.tar /home/user/project/

Однак не варто покладатися на таку поведінку як на спосіб захисту. Перед розпакуванням незнайомого архіву переглянь його вміст і шляхи.

### 16.3. Чому не слід бездумно використовувати `sudo tar`

Архівування всієї файлової системи або розпакування системного архіву з правами адміністратора може вплинути на важливі файли.

Для навчання і резервного копіювання власних проєктів працюй у своїй домашній директорії без `sudo`, якщо адміністративні права не потрібні.

## 17. Безпечне розпакування

Архів може містити не лише звичайні файли, а й символічні посилання або шляхи, що виходять за межі очікуваної директорії.

Перед розпакуванням невідомого архіву:

1. Переглянь список файлів.
2. Перевір, чи шляхи не ведуть до несподіваних місць.
3. Розпаковуй спочатку в окрему порожню директорію.
4. Не запускай невідомі скрипти з архіву автоматично.
5. Не використовуй `sudo`, якщо це не потрібно.

Приклад:

    mkdir -p ~/tmp/archive-check
    tar -tf downloaded-archive.tar
    tar -xf downloaded-archive.tar -C ~/tmp/archive-check/

Перевіряй вміст перед відкриттям або виконанням файлів.

## 18. Типові помилки

### Помилка 1. Забули `-f`

Неправильно:

    tar -cf project.tar project/

Правильно:

    tar -cf project.tar project/

У цьому прикладі команда вже правильна: `-f` указує ім'я архіву. Без `-f` TAR може використовувати стандартний потік, а команда поводитиметься не так, як очікувалося.

### Помилка 2. Переплутали `-c` і `-x`

- `-c` створює архів.
- `-x` розпаковує архів.

Створити:

    tar -cf project.tar project/

Розпакувати:

    tar -xf project.tar

### Помилка 3. Очікують стиснення від `.tar`

    tar -cf project.tar project/

Ця команда зазвичай лише об'єднує файли. Щоб використати gzip:

    tar -czf project.tar.gz project/

### Помилка 4. Неправильно вказали шлях до файлу

Якщо файл записаний у архіві як `project/README.md`, команда з шляхом `README.md` може його не знайти.

Спочатку перевір:

    tar -tf project.tar

Потім використай точний шлях із результату.

### Помилка 5. Архів розпакувався не туди

Поточна директорія визначає, де з'являться розпаковані файли, якщо не використано `-C`.

Перевір:

    pwd

Або явно задай місце:

    mkdir -p extracted
    tar -xf project.tar -C extracted/

### Помилка 6. Архів включає зайві директорії

У JavaScript-проєкті це можуть бути `node_modules/`, `.next/` або інші згенеровані файли.

Використовуй `--exclude`, коли це доречно:

    tar -czf project.tar.gz \
        --exclude='project/node_modules' \
        project/

Після створення перевір вміст:

    tar -tzf project.tar.gz

### Помилка 7. Архів перезаписав локальні файли

Перед розпакуванням перевір його вміст або використовуй окрему директорію. Для захисту від перезаписування наявних файлів є опція `-k`.

    tar -xkf project.tar

### Помилка 8. Вважають, що архів автоматично зашифрований

TAR не шифрує вміст. Навіть `.tar.gz` зазвичай можна прочитати без пароля.

Якщо архів містить конфіденційні дані, потрібне окреме шифрування та безпечне зберігання ключа.

## 19. Корисні команди для щоденної роботи

Переглянути вміст звичайного архіву:

    tar -tf archive.tar

Переглянути вміст gzip-архіву:

    tar -tzf archive.tar.gz

Створити архів:

    tar -cf archive.tar folder/

Створити стиснений архів:

    tar -czf archive.tar.gz folder/

Розпакувати архів:

    tar -xf archive.tar

Розпакувати стиснений архів:

    tar -xzf archive.tar.gz

Розпакувати в конкретну директорію:

    tar -xf archive.tar -C destination/

Додати файл до несжатого TAR:

    tar -rf archive.tar file.txt

Показати детальний список:

    tar -tvf archive.tar

Виключити директорію:

    tar -czf archive.tar.gz --exclude='folder/cache' folder/

## 20. Практика

### Вправа 1. Створення простого архіву

Створи тестову структуру:

    mkdir -p ~/tar-practice/project/src
    cd ~/tar-practice/project

    touch README.md package.json src/app.js

Створи архів:

    tar -cf project.tar README.md package.json src/

Перевір вміст:

    tar -tf project.tar

**Завдання:** поясни, чому архів містить і файли, і директорію `src/`.

### Вправа 2. Стиснення

Створи gzip-архів:

    tar -czf project.tar.gz README.md package.json src/

Порівняй розміри:

    ls -lh project.tar project.tar.gz

**Завдання:** поясни, чому розміри можуть відрізнятися незначно, якщо файли порожні.

### Вправа 3. Розпакування в інше місце

    mkdir -p ~/tar-practice/restored
    tar -xf project.tar -C ~/tar-practice/restored/

Перевір результат:

    find ~/tar-practice/restored -maxdepth 3 -print

**Завдання:** визнач, де опинилися файли після розпакування.

### Вправа 4. Витягування одного файлу

Переглянь вміст архіву:

    tar -tf project.tar

Витягни лише `README.md`:

    mkdir -p ~/tar-practice/single-file
    tar -xf project.tar README.md -C ~/tar-practice/single-file/

Перевір:

    ls -la ~/tar-practice/single-file/

**Завдання:** поясни, чому не потрібно розпаковувати весь архів.

### Вправа 5. Виключення директорії

Створи директорію, яку не потрібно включати до архіву:

    mkdir -p cache
    touch cache/temp.txt

Створи архів із виключенням `cache`:

    tar -czf project-clean.tar.gz \
        --exclude='project/cache' \
        project/

Якщо ти перебуваєш усередині `project/`, зручніше виконати команду з батьківської директорії, як у прикладі, або відповідно змінити шляхи.

Перевір результат:

    tar -tzf project-clean.tar.gz

**Завдання:** переконайся, що `cache/` не потрапила до архіву.

## 22. Що потрібно пам'ятати

- `tar` об'єднує файли й директорії в один архів.
- `-c` створює архів.
- `-x` розпаковує архів.
- `-t` показує вміст архіву.
- `-f` задає ім'я файлу архіву.
- `-v` виводить список оброблюваних файлів.
- `.tar` зазвичай не означає стиснення.
- `-z` використовує gzip, `-j` — bzip2, `-J` — xz.
- `-C` задає директорію для виконання операції.
- `--exclude` дозволяє виключати непотрібні файли.
- `-r` і `-u` призначені для роботи з несжатими TAR-архівами.
- Перед розпакуванням невідомого архіву переглядай його вміст.
- Не плутай архівування, стиснення, шифрування та резервне копіювання.

## 23. Шлях вивчення TAR

### Core — базовий рівень

- Створювати `.tar`.
- Переглядати вміст за допомогою `tar -tf`.
- Розпаковувати архіви за допомогою `tar -xf`.
- Розуміти опції `-c`, `-x`, `-t`, `-f`, `-v`.

### Junior — практичний рівень

- Створювати `.tar.gz`, `.tar.bz2`, `.tar.xz`.
- Розпаковувати архіви в конкретну директорію.
- Витягувати окремі файли.
- Виключати `node_modules/`, `.next/` та інші непотрібні директорії.
- Перевіряти вміст і розмір архіву.
- Створювати резервні копії навчальних проєктів.

### Middle — поглиблений рівень

- Керувати шляхами всередині архіву за допомогою `-C`.
- Розуміти збереження прав доступу, власників і часових міток.
- Безпечно відновлювати файли з резервних копій.
- Розуміти обмеження додавання файлів до стиснених архівів.
- Перевіряти відновлення резервної копії на практиці.

### Senior — системний рівень

- Планувати резервне копіювання систем і серверів.
- Враховувати права доступу, власників, символічні посилання та точки монтування.
- Організовувати ротацію та перевірку резервних копій.
- Визначати, які дані потрібно архівувати, а які можна відновити з інших джерел.
- Захищати конфіденційні резервні копії шифруванням і контролем доступу.

## 24. Мінішпаргалка

    # Створити TAR
    tar -cf archive.tar folder/

    # Створити TAR із виведенням файлів
    tar -cvf archive.tar folder/

    # Переглянути вміст TAR
    tar -tf archive.tar

    # Переглянути детальний список
    tar -tvf archive.tar

    # Розпакувати TAR
    tar -xf archive.tar

    # Розпакувати TAR в іншу директорію
    tar -xf archive.tar -C destination/

    # Створити TAR.GZ
    tar -czf archive.tar.gz folder/

    # Переглянути TAR.GZ
    tar -tzf archive.tar.gz

    # Розпакувати TAR.GZ
    tar -xzf archive.tar.gz

    # Створити TAR.BZ2
    tar -cjf archive.tar.bz2 folder/

    # Розпакувати TAR.BZ2
    tar -xjf archive.tar.bz2

    # Створити TAR.XZ
    tar -cJf archive.tar.xz folder/

    # Розпакувати TAR.XZ
    tar -xJf archive.tar.xz

    # Виключити директорію
    tar -czf archive.tar.gz \
        --exclude='folder/node_modules' \
        folder/

    # Додати файл до звичайного TAR
    tar -rf archive.tar file.txt

    # Перевірити розмір архіву
    ls -lh archive.tar*

## Головне

`tar` — базовий інструмент Linux для архівування файлів і директорій. Він допомагає об'єднувати файли, переносити проєкти та створювати резервні копії.

Для повсякденної роботи достатньо впевнено знати чотири операції:

    tar -cf archive.tar folder/      # створити
    tar -tf archive.tar              # переглянути
    tar -xf archive.tar              # розпакувати
    tar -czf archive.tar.gz folder/  # створити стиснений архів

Перед відновленням завжди перевіряй вміст архіву та місце розпакування. А якщо архів використовується як резервна копія — періодично перевіряй, чи можна з нього відновити потрібні файли.
