# 01. Disk Usage — df та du

`df` та `du` — це команди Linux, які використовуються для перевірки використання дискового простору.

Вони допомагають визначити:

- скільки вільного місця залишилося на файлових системах;
- скільки місця займають файли та директорії;
- які директорії займають найбільше простору;
- чи вистачає місця для проєктів, пакетів та резервних копій;
- де можуть накопичуватися великі файли;
- чи потрібно звільнити дисковий простір.

Основні команди:

    df
    du
    df -h
    du -h
    du -sh
    du -h --max-depth=1

### Що потрібно пам'ятати

• `df` показує використання дискового простору файловими системами.

• `du` показує, скільки дискового простору займають файли та директорії.

• `df -h` — найзручніший спосіб швидко перевірити вільне місце на дисках.

• `du -sh directory/` показує загальний розмір директорії.

• `du -h --max-depth=1 directory/` показує розміри директорії та її безпосередніх піддиректорій.

• `du -ah directory/` показує розміри окремих файлів і директорій.

• Параметр `-h` означає human-readable: розміри відображаються у KB, MB, GB тощо.

• Параметр `-s` означає summary: показати підсумковий розмір без детального переліку вмісту.

• Параметр `-a` означає all: включити до результатів окремі файли.

• Параметр `-T` у `df` показує тип файлової системи.

• Параметр `-i` у `df` показує використання inode, а не обсяг дискового простору в байтах.

• `df` і `du` можуть показувати різні результати, оскільки вимірюють різні аспекти використання диска.

• Для пошуку великих директорій зручно поєднувати `du`, `sort` і `head`.

• Не слід видаляти системні файли лише тому, що вони займають багато місця.

---

# Disk Space

Disk space — дисковий простір, доступний для зберігання файлів, програм, баз даних та інших даних.

Наприклад, на диску є файлова система обсягом приблизно 100 GB.

Умовно:

    Total:      100 GB
    Used:        65 GB
    Available:   35 GB

Тут:

    Total     → загальний обсяг
    Used      → використаний простір
    Available → доступний простір

У Linux дисковий простір зазвичай перевіряють командами:

    df -h
    du -sh

Важливо розуміти, що це різні вимірювання.

---

# Filesystem

Filesystem — файлова система, яка визначає спосіб організації та зберігання файлів на пристрої або в іншому сховищі.

Приклади файлових систем:

    ext4
    XFS
    Btrfs
    FAT32
    exFAT
    NTFS

У Linux файлова система може бути змонтована в певну точку дерева каталогів.

Наприклад:

    /
    /home
    /boot
    /mnt/data

Коренева файлова система:

    /

містить основну структуру Linux.

Домашня директорія користувача може розташовуватися тут:

    /home/username

Але `/home` не обов'язково є окремою файловою системою. Це залежить від конфігурації комп'ютера.

---

# df

`df` — команда для перевірки використання дискового простору файловими системами.

Назва походить від:

    disk free

Базовий синтаксис:

    df [OPTIONS] [FILE...]

Наприклад:

    df

Команда показує інформацію про змонтовані файлові системи.

Типовий результат:

    Filesystem      1K-blocks      Used Available Use% Mounted on
    /dev/sda2       100000000 65000000  35000000  66% /
    /dev/sda1          500000    80000    420000  17% /boot

Це умовний приклад. Реальні пристрої, значення та назви файлових систем залежатимуть від комп'ютера.

Основні колонки:

    Filesystem → пристрій або джерело файлової системи
    1K-blocks  → загальний обсяг у блоках по 1 KiB
    Used       → використаний простір
    Available  → доступний простір
    Use%       → відсоток використання
    Mounted on → точка монтування

---

# df -h

`df -h` — найпоширеніший спосіб перевірки дискового простору.

Параметр `-h` означає human-readable.

Команда:

    df -h

Приклад результату:

    Filesystem      Size  Used Avail Use% Mounted on
    /dev/sda2        95G   62G   29G  69% /
    /dev/sda1       512M   80M  432M  16% /boot

Тут:

    Size  → загальний обсяг
    Used  → використаний простір
    Avail → доступний простір
    Use%  → відсоток використання

Розміри відображаються у зручному для читання форматі.

Наприклад:

    512M
    29G
    1.5T

### Коли використовувати df -h

• Перед установленням великих програм.

• Перед створенням резервної копії.

• Коли потрібно перевірити, чому не вистачає місця.

• Під час роботи з PostgreSQL та іншими базами даних.

• Під час розробки й розгортання Node.js-проєктів.

• Коли потрібно перевірити стан файлової системи.

---

# df -H

`df -H` також показує розміри у зрозумілому форматі, але використовує десяткові одиниці.

    df -H

Основна відмінність:

    -h → степені 1024
    -H → степені 1000

Приблизно:

    1 KiB = 1024 bytes
    1 MiB = 1024 KiB
    1 GiB = 1024 MiB

Десяткові одиниці:

    1 kB = 1000 bytes
    1 MB = 1000 kB
    1 GB = 1000 MB

У результатах `df -h` Linux зазвичай використовує позначення `K`, `M`, `G`, `T`, хоча фактична база розрахунку для параметра `-h` дорівнює 1024.

Для повсякденної роботи достатньо пам'ятати:

    df -h → стандартний вибір
    df -H → десяткові одиниці

---

# df -T

Параметр `-T` додає тип файлової системи.

    df -T

Приклад:

    Filesystem     Type   Size  Used Avail Use% Mounted on
    /dev/sda2      ext4    95G   62G   29G  69% /
    /dev/sda1      vfat   512M   80M  432M  16% /boot

Тут:

    ext4 → файлова система ext4
    vfat → файлова система сімейства FAT

Комбінація параметрів:

    df -hT

Дозволяє одночасно побачити тип файлової системи та використання простору.

---

# df -i

`df -i` показує використання inode.

    df -i

Inode — структура файлової системи, яка містить метадані файлу або директорії.

Залежно від файлової системи inode містить або пов'язує такі відомості:

    file type
    permissions
    owner
    group
    file size
    timestamps
    references to data blocks

Назва файлу та його шлях зберігаються в структурі директорії, а не як частина самого inode.

Приклад результату:

    Filesystem      Inodes   IUsed   IFree IUse% Mounted on
    /dev/sda2      6000000  500000 5500000    9% /

Основні колонки:

    Inodes → загальна кількість inode
    IUsed  → використані inode
    IFree  → вільні inode
    IUse%  → відсоток використання inode

### Навіщо перевіряти inode

Іноді на диску ще достатньо вільного простору, але створення нових файлів неможливе через вичерпання доступних inode.

Це може трапитися, коли система містить величезну кількість невеликих файлів.

Наприклад:

    df -h
    df -i

Перша команда перевіряє простір, друга — inode.

Важливо: спосіб виділення inode залежить від файлової системи. У деяких файлових системах їхня кількість не є фіксованою так, як у традиційних конфігураціях ext4.

---

# df для конкретної директорії

`df` може показати файлову систему, на якій розташована певна директорія.

Наприклад:

    df -h /home

Або:

    df -h ~/projects

Це корисно, якщо потрібно з'ясувати, на якій файловій системі зберігаються проєкти.

Наприклад:

    df -h ~/projects/nest-exercises

Команда покаже використання тієї файлової системи, до якої належить зазначений шлях.

Важливо:

    df -h directory/

не показує сумарний розмір саме цієї директорії.

Для цього використовується `du`.

---

# df -hT /

Щоб перевірити кореневу файлову систему:

    df -hT /

Ця команда показує:

    filesystem
    filesystem type
    total size
    used space
    available space
    usage percentage
    mount point

Коренева файлова система монтується в:

    /

Вона зазвичай містить системні файли та директорії Linux.

---

# du

`du` — команда для оцінювання дискового простору, який займають файли та директорії.

Назва походить від:

    disk usage

Базовий синтаксис:

    du [OPTIONS] [FILE...]

Приклад:

    du ~/projects

Команда показує розмір директорії та її піддиректорій.

Результат може бути досить великим, якщо директорія містить багато файлів.

Для зручнішого перегляду використовують:

    du -h ~/projects

---

# du -h

Параметр `-h` показує розміри у форматі human-readable.

    du -h ~/projects

Приклад результату:

    120K    /home/user/projects/demo/src
    340K    /home/user/projects/demo
    1.2G    /home/user/projects/nest-exercises
    2.4G    /home/user/projects

Це умовний приклад.

Результат залежить від вмісту директорій.

Команда показує використання дискового простору для директорій, які вона обходить.

Без параметра `-s` результат може містити багато рядків.

---

# du -s

Параметр `-s` означає summary.

Він показує підсумковий розмір кожного зазначеного шляху, не виводячи окремий результат для кожної піддиректорії.

Наприклад:

    du -s ~/projects

Приклад:

    2516582    /home/user/projects

Числові значення без `-h` зазвичай відображаються в блоках по 1 KiB у GNU `du`.

Зручніший варіант:

    du -sh ~/projects

---

# du -sh

`du -sh` — одна з найкорисніших команд для повсякденної роботи.

Синтаксис:

    du -sh PATH

Наприклад:

    du -sh ~/projects

Результат:

    2.4G    /home/user/projects

Перевірка конкретного проєкту:

    du -sh ~/projects/nest-exercises

Перевірка каталогу `node_modules`:

    du -sh ~/projects/nest-exercises/node_modules

Перевірка каталогу `.git`:

    du -sh ~/projects/nest-exercises/.git

Перевірка директорії резервних копій:

    du -sh ~/backups

Зверни увагу: назви директорій у цих прикладах потрібно замінити, якщо твоя структура відрізняється.

### Коли використовувати du -sh

• Коли потрібно дізнатися розмір проєкту.

• Коли потрібно перевірити, скільки займає `node_modules`.

• Коли потрібно оцінити розмір архіву або резервної копії.

• Коли потрібно порівняти розміри кількох директорій.

• Коли потрібно швидко перевірити, чи не займає якась директорія надто багато місця.

---

# du -a

Параметр `-a` означає all.

Він включає до результату окремі файли, а не лише директорії.

Наприклад:

    du -ah ~/projects/demo

Приклад результату:

    4.0K    /home/user/projects/demo/package.json
    8.0K    /home/user/projects/demo/README.md
    16K     /home/user/projects/demo/src/app.js
    32K     /home/user/projects/demo/src
    60K     /home/user/projects/demo

Це умовний приклад.

Команда допомагає знайти великі файли та директорії.

Але для великих дерев каталогів вивід може бути дуже довгим.

---

# du --max-depth

Параметр `--max-depth=N` обмежує глибину відображення директорій.

Наприклад:

    du -h --max-depth=1 ~/projects

Команда показує загальний розмір `~/projects` і розміри її безпосередніх піддиректорій.

Умовний результат:

    1.2G    /home/user/projects/nest-exercises
    800M    /home/user/projects/next-exercises
    400M    /home/user/projects/other
    2.4G    /home/user/projects

Глибина:

    --max-depth=0 → лише зазначений каталог
    --max-depth=1 → каталог і його безпосередні підкаталоги
    --max-depth=2 → ще один рівень вкладеності

Наприклад:

    du -h --max-depth=1 ~/projects/nest-exercises

Це зручно для пошуку піддиректорій, які займають найбільше місця.

### Короткий варіант

У GNU `du` також можна використовувати:

    du -h -d 1 ~/projects

Параметр `-d` є короткою формою `--max-depth`.

---

# du -sh *

Команда показує розміри елементів поточної директорії.

    du -sh *

Наприклад, якщо поточна директорія містить:

    README.md
    src/
    node_modules/
    package.json

результат може бути таким:

    4.0K    README.md
    120M    node_modules
    4.0K    package.json
    240K    src

Це умовні значення.

Символ `*` — шаблон оболонки Bash, який зазвичай розгортається у список видимих імен поточної директорії.

Важливо:

• Приховані елементи на кшталт `.git` за стандартного налаштування Bash не включаються до `*`.

• Якщо приховані директорії потрібно перевірити окремо, можна виконати:

    du -sh .git

• Якщо директорія містить багато елементів, команда може вивести багато рядків.

• `du -sh *` не означає «показати всі файли в усіх вкладених директоріях окремо». Для детального обходу використовується `du -ah`.

---

# Пошук великих директорій

Для пошуку директорій, які займають найбільше місця, можна використовувати:

    du -h --max-depth=1 ~/projects

Але результати не обов'язково будуть відсортовані за розміром.

Для сортування використовують `sort`.

---

# sort

`sort` — команда для сортування текстових рядків.

Звичайне сортування:

    sort file.txt

Числове сортування:

    sort -n file.txt

Сортування чисел у зворотному порядку:

    sort -nr file.txt

Для розмірів, які містять суфікси на кшталт `K`, `M`, `G`, GNU `sort` має параметр `-h`.

    sort -h

Наприклад:

    printf "10M\n2G\n500K\n100M\n" | sort -h

Результат:

    500K
    10M
    100M
    2G

Для сортування за спаданням:

    printf "10M\n2G\n500K\n100M\n" | sort -hr

Результат:

    2G
    100M
    10M
    500K

---

# Пошук найбільших директорій через du і sort

Команда:

    du -h --max-depth=1 ~/projects | sort -h

Сортує результати за розміром від меншого до більшого.

Щоб показати найбільші директорії першими:

    du -h --max-depth=1 ~/projects | sort -hr

Це корисний шаблон для діагностики дискового простору.

---

# head

`head` показує початок текстового потоку або файлу.

За замовчуванням:

    head file.txt

показує перші 10 рядків.

Параметр `-n` задає кількість рядків.

    head -n 5 file.txt

Показує перші п'ять рядків.

Команда:

    du -h --max-depth=1 ~/projects | sort -hr | head -n 5

Показує п'ять найбільших результатів серед директорій і загального каталогу `~/projects`.

Якщо потрібно дослідити тільки піддиректорії конкретного проєкту:

    du -h --max-depth=1 ~/projects/nest-exercises | sort -hr | head -n 10

---

# Pipes

Pipe — механізм передавання стандартного виводу однієї команди на стандартний ввід іншої.

Символ:

    |

Приклад:

    du -h --max-depth=1 ~/projects | sort -hr

Логіка:

    du
      ↓
    список розмірів
      ↓
    sort -hr
      ↓
    відсортований список

З `head`:

    du -h --max-depth=1 ~/projects | sort -hr | head -n 5

Логіка:

    du
      ↓
    sort -hr
      ↓
    head -n 5
      ↓
    п'ять найбільших результатів

Pipe дозволяє будувати складніші команди з простих інструментів.

# df vs du

Це одна з найважливіших відмінностей у темі керування дисковим простором.

## df

Показує використання файлової системи.

    df -h

Відповідає на запитання:

    Скільки простору використано на файловій системі?
    Скільки простору ще доступно?

## du

Оцінює використання простору файлами та директоріями.

    du -sh ~/projects

Відповідає на запитання:

    Скільки місця займає цей проєкт?
    Яка директорія займає найбільше місця?
    Який розмір node_modules?

### Порівняння

| Команда | Що показує | Приклад використання |
|---|---|---|
| `df -h` | Використання файлових систем | Перевірити вільне місце |
| `df -hT` | Простір і тип файлової системи | Дослідити змонтовані файлові системи |
| `df -i` | Використання inode | Перевірити вичерпання inode |
| `du -sh DIR` | Підсумковий розмір директорії | Оцінити розмір проєкту |
| `du -ah DIR` | Розміри файлів і директорій | Знайти великі файли |
| `du -h --max-depth=1 DIR` | Розміри директорії та її піддиректорій | Знайти великі піддиректорії |

# Чому df та du показують різні значення

Результати `df` та `du` не завжди збігаються.

Це нормально.

Основні причини:

## 1. Метадані файлової системи

Файлова система використовує частину простору для власних структур та метаданих.

Це не завжди відображається як звичайні файли, які можна підрахувати через `du`.

## 2. Видалені, але відкриті файли

Процес може продовжувати використовувати файл після того, як його ім'я було видалено з директорії.

Наприклад:

    процес відкрив великий лог-файл
    ↓
    файл видалили
    ↓
    процес продовжує тримати файл відкритим
    ↓
    простір ще не звільнений

У такому випадку `df` може показувати використаний простір, який не пояснюється звичайним обходом директорій через `du`.

На системах із відповідними інструментами можна перевірити:

    sudo lsof +L1

Ця команда шукає відкриті файли, кількість жорстких посилань на які менша за 1. Вона може вимагати встановлення `lsof` та відповідних прав доступу.

## 3. Жорсткі посилання

Hard links — кілька імен, що посилаються на один і той самий inode.

Це може впливати на підрахунок простору.

`du` зазвичай не рахує один і той самий файл повторно в межах одного обходу файлової системи, якщо не задано іншу поведінку.

## 4. Монтування файлових систем

Інша файлова система може бути змонтована всередині каталогу.

Наприклад:

    /
    └── home/
        └── user/
            └── projects/

Якщо частина дерева розташована на іншій файловій системі, результати залежать від того, яку саме файлову систему перевіряємо та чи дозволений перехід через точки монтування.

У `du` параметр `-x` обмежує обхід однією файловою системою.

    du -x -h --max-depth=1 /

Це може бути корисно для дослідження використання простору кореневої файлової системи.

## 5. Розріджені файли

Sparse files — файли, логічний розмір яких може бути більшим за обсяг реально виділених для даних блоків.

Звичайний розмір файлу та реально зайнятий простір можуть відрізнятися.

GNU `du` за замовчуванням зазвичай враховує фактично виділений простір, тоді як логічний розмір можна оцінити окремо.

# Доступний простір та зарезервовані блоки

У Linux доступний простір не завжди дорівнює простій різниці між загальним та використаним обсягом.

Наприклад, у файловій системі ext4 частина блоків може бути зарезервована для привілейованих процесів.

Це допомагає системі продовжувати працювати, коли вільного простору залишається мало.

Тому у результатах:

    df -h

значення `Avail` може бути меншим за арифметичну різницю:

    Size - Used

Не слід вважати це помилкою.

---

# Перевірка дискового простору перед роботою з проєктами

Під час розробки JavaScript-проєктів дисковий простір можуть займати:

    node_modules/
    .git/
    .next/
    dist/
    build/
    logs/
    backups/

Не кожен проєкт містить усі ці директорії.

### Перевірити вільне місце

    df -h

### Перевірити каталог проєктів

    du -sh ~/projects

### Перевірити конкретний проєкт

    du -sh ~/projects/nest-exercises

### Перевірити основні піддиректорії

    du -h --max-depth=1 ~/projects/nest-exercises

### Знайти найбільші піддиректорії

    du -h --max-depth=1 ~/projects/nest-exercises | sort -hr | head -n 10

### Перевірити node_modules

    du -sh ~/projects/nest-exercises/node_modules

Якщо директорії не існує, `du` повідомить про помилку. Це не означає, що з файловою системою щось не так.

# Перевірка системних директорій

Щоб дослідити використання простору кореневої файлової системи:

    df -h /

Щоб оцінити розміри основних системних директорій:

    sudo du -x -h --max-depth=1 / | sort -hr

Тут:

    sudo       → виконує команду з підвищеними правами
    du         → оцінює використання простору
    -x         → не переходить на інші файлові системи
    -h         → human-readable
    --max-depth=1 → показує лише один рівень вкладеності
    sort -hr   → сортує за розміром від більшого до меншого

Важливо:

• Для звичайного користувача спочатку краще спробувати `du` без `sudo`.

• `sudo` може показати більше даних, але використовувати його потрібно лише тоді, коли це справді необхідно.

• Не видаляй системні файли лише через їхній розмір.

• Перед видаленням потрібно з'ясувати призначення файлів і перевірити, чи не використовуються вони системою або програмами.

---

# Помилки доступу

Під час виконання `du` можуть з'являтися повідомлення:

    Permission denied

Це означає, що користувач не має необхідних прав для читання певної директорії або отримання інформації про її вміст.

Наприклад:

    du -sh /root

Звичайний користувач, як правило, не має доступу до всього вмісту `/root`.

Якщо потрібно оцінити директорію, до якої немає доступу, можна використати `sudo`, якщо маєш відповідні права.

    sudo du -sh /root

Але не варто автоматично запускати кожну команду з `sudo`.

Для звичайних проєктів:

    du -sh ~/projects

зазвичай достатньо прав поточного користувача.

---

# Перенаправлення помилок

У Bash:

    2>/dev/null

перенаправляє стандартний потік помилок у спеціальний пристрій `/dev/null`.

Наприклад:

    du -ah ~/projects 2>/dev/null

Це приховує повідомлення про помилки, наприклад деякі повідомлення про відсутність доступу.

Важливо розуміти:

• Команда не отримує додаткових прав.

• Помилки не виправляються.

• Приховані повідомлення можуть містити важливу інформацію.

Тому під час навчання краще спочатку бачити помилки, а не приховувати їх.

Якщо потрібно переглянути тільки успішно прочитані результати, перенаправлення помилок може бути доречним.

    df -i

    df -h /

Після цього:

    sudo du -x -h --max-depth=1 / | sort -hr

Перша команда показує використання файлової системи, друга допомагає оцінити розміри каталогів у її межах.

Результати не обов'язково збігатимуться через метадані, відкриті видалені файли та інші особливості файлової системи.

# Типові помилки

## 1. Плутати df і du

❌ Використовувати `du`, щоб перевірити загальний доступний простір файлової системи.

Правильно:

    df -h

Для розміру конкретної директорії:

    du -sh ~/projects

---

## 2. Забувати параметр -h

Без `-h` результати можуть бути менш зручними для читання.

    du -s ~/projects

Зручніше:

    du -sh ~/projects

---

## 3. Використовувати du без обмеження глибини на великій директорії

Команда:

    du -h /

може вивести дуже багато рядків і довго виконуватися.

Для початкової діагностики зручніше:

    du -h --max-depth=1 /

Для кореневої файлової системи без переходу на інші файлові системи:

    du -x -h --max-depth=1 /

---

## 4. Вважати, що df -h показує розмір поточної директорії

Команда:

    df -h .

показує використання файлової системи, на якій розташована поточна директорія.

Щоб отримати розмір самої директорії:

    du -sh .

---

## 5. Вважати, що du завжди покаже той самий обсяг, що й df

Це не так.

Причини можуть включати:

    filesystem metadata
    deleted but open files
    hard links
    mounted filesystems
    sparse files
    reserved blocks

---

## 6. Ігнорувати inode

Навіть якщо є вільний дисковий простір, кількість доступних inode може бути вичерпана.

Для перевірки:

    df -i

---

## 7. Використовувати sudo без потреби

Не кожна команда потребує підвищених прав.

Спочатку спробуй:

    du -sh ~/projects

Якщо доступу недостатньо, з'ясуй причину та лише за необхідності використовуй `sudo`.

---

## 8. Видаляти файли тільки через їхній розмір

Великий файл не обов'язково є непотрібним.

Перед видаленням потрібно з'ясувати:

    що це за файл;
    яка програма його використовує;
    чи потрібен він для роботи системи;
    чи існує резервна копія;
    чи можна безпечно відновити дані.

---

## 9. Забувати про приховані директорії

Шаблон:

    *

не охоплює приховані імена на кшталт:

    .git
    .next
    .cache

Перевіряти їх потрібно окремо або використовувати інший відповідний спосіб пошуку.

---

## 10. Плутати логічний розмір файлу та реально зайнятий простір

Для звичайних файлів ці значення можуть бути близькими, але для sparse files вони можуть істотно відрізнятися.

Тому під час аналізу використання простору потрібно враховувати, що саме вимірюється.

    du -h --max-depth=1 ~/projects

Показати розміри піддиректорій першого рівня.

## sort -hr

    sort -hr

Відсортувати числові значення у зворотному порядку, враховуючи розміри із суфіксами.

## head -n 5

    head -n 5

Показати перші п'ять рядків.

## Пошук найбільших директорій

    du -h --max-depth=1 ~/projects | sort -hr | head -n 10

Показати десять найбільших результатів.

---

# Основні правила

    df -h
        → перевірити вільне місце на файлових системах

    df -hT
        → перевірити типи файлових систем

    df -i
        → перевірити використання inode

    du -sh DIR
        → дізнатися розмір директорії

    du -ah DIR
        → переглянути розміри файлів і директорій

    du -h --max-depth=1 DIR
        → оцінити розміри піддиректорій

    sort -hr
        → сортувати розміри від більшого до меншого

    head -n 10
        → показати перші десять результатів

---

# Головне

• `df` показує використання файлових систем, а `du` оцінює простір, зайнятий файлами та директоріями.

• `df -h` — основна команда для перевірки вільного місця.

• `du -sh DIR` — основна команда для перевірки розміру директорії.

• `df -i` допомагає виявити проблеми з вичерпанням inode.

• `du -h --max-depth=1 DIR` допомагає знайти великі піддиректорії.

• `sort -hr` разом із `head` дозволяє швидко знайти найбільші результати.

• Pipe `|` передає вивід однієї команди іншій.

• `df` та `du` можуть показувати різні значення через особливості файлової системи, відкриті видалені файли, hard links та інші чинники.

• Для перевірки дискового простору проєктів корисно регулярно використовувати:

    df -h
    du -sh ~/projects
    du -h --max-depth=1 ~/projects | sort -hr

• Для перевірки конкретного JavaScript-проєкту:

    du -sh ~/projects/nest-exercises
    du -h --max-depth=1 ~/projects/nest-exercises | sort -hr

• Перед видаленням великих файлів потрібно з'ясувати їхнє призначення.

• Основна модель роботи:

    df
      ↓
    перевірити файлову систему
      ↓
    du
      ↓
    знайти каталоги, які займають місце
      ↓
    sort
      ↓
    відсортувати за розміром
      ↓
    head
      ↓
    переглянути найбільші результати

• Правильне використання `df` та `du` допомагає контролювати дисковий простір, своєчасно виявляти проблеми та підтримувати Linux-систему в робочому стані.
