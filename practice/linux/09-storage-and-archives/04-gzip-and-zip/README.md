# 04. GZIP AND ZIP — стиснення файлів та архіви

`gzip` і `zip` — це інструменти Linux для стиснення файлів і зменшення обсягу даних, які потрібно зберігати або передавати.

Вони мають різне призначення:

- `gzip` — стискає окремі файли, зазвичай створюючи файли з розширенням `.gz`.
- `gunzip` — розпаковує файли `.gz`.
- `zip` — створює ZIP-архіви, які можуть містити багато файлів і директорій.
- `unzip` — переглядає та розпаковує ZIP-архіви.

Для роботи з TAR-архівами також можна використовувати стиснення через `gzip`, створюючи файли `.tar.gz`.

## 1. Для чого потрібні gzip і zip

Їх використовують, щоб:

- ✔ зменшувати розмір файлів;
- ✔ передавати файли через мережу;
- ✔ створювати архіви з багатьох файлів;
- ✔ зберігати резервні копії;
- ✔ розпаковувати завантажені архіви;
- ✔ працювати з форматами, які підтримують Linux, Windows та інші операційні системи.

Наприклад, звичайний текстовий файл може займати кілька мегабайтів. Після стиснення він може стати значно меншим.

Однак результат залежить від типу даних. Текст зазвичай стискається добре, а вже стиснені файли, наприклад JPEG або MP4, часто майже не зменшуються.

## 2. GZIP: стиснення одного файлу

### 2.1. Створити стиснений файл

Загальний синтаксис:

    gzip FILE

Приклад:

    gzip report.txt

Зазвичай після виконання команди:

- створюється `report.txt.gz`;
- початковий `report.txt` видаляється.

**Важливо:** `gzip` за замовчуванням замінює початковий файл його стисненою версією. Якщо потрібно зберегти оригінал, використовуй опцію `-k`.

### 2.2. Стиснути файл і зберегти оригінал

    gzip -k report.txt

Результат:

    report.txt
    report.txt.gz

Опція `-k` означає `--keep` — залишити початковий файл.

Це зручно, коли хочеш порівняти оригінал зі стисненою копією.

### 2.3. Стиснути файл із відображенням результату

    gzip -v report.txt

Опція `-v` показує інформацію про стиснення, зокрема коефіцієнт або відсоток зміни розміру.

Щоб одночасно зберегти оригінал:

    gzip -kv report.txt

### 2.4. Перевірити розмір файлів

    ls -lh report.txt report.txt.gz

Команда `ls -lh` покаже розміри в зручному форматі.

Для порівняння розмірів важливо пам'ятати: стиснення не гарантує зменшення кожного файлу. Для дуже маленьких файлів службова інформація формату може зробити результат майже таким самим або навіть трохи більшим.

## 3. Розпакування GZIP

### 3.1. Розпакувати файл `.gz`

Загальний синтаксис:

    gunzip FILE.gz

Приклад:

    gunzip report.txt.gz

Зазвичай після виконання команди:

- створюється `report.txt`;
- файл `report.txt.gz` видаляється.

### 3.2. Розпакувати, зберігши стиснений файл

    gunzip -k report.txt.gz

Опція `-k` залишає `.gz` на місці.

### 3.3. Використати gzip для розпакування

Команда `gzip` також уміє розпаковувати файли за допомогою опції `-d`:

    gzip -d report.txt.gz

Це еквівалентно звичайному використанню `gunzip`.

Щоб залишити стиснений файл:

    gzip -dk report.txt.gz

### 3.4. Перевірити цілісність GZIP-файлу

    gzip -t report.txt.gz

Якщо помилок немає, команда зазвичай завершується без повідомлення.

Щоб отримати повідомлення про результат:

    gzip -tv report.txt.gz

Це перевіряє, чи можна прочитати стиснений потік і чи відповідають дані контрольній сумі.

**Важливо:** успішна перевірка цілісності не гарантує, що вміст файлу є безпечним або правильним для твоєї програми.

## 4. Рівні стиснення GZIP

GZIP підтримує різні рівні стиснення.

| Опція | Значення |
|---|---|
| `-1` | Швидше стиснення, зазвичай менше зменшення розміру |
| `-6` | Стандартний баланс швидкості та розміру |
| `-9` | Максимальні зусилля стиснення, зазвичай повільніше |
| `-v` | Показувати інформацію про стиснення |
| `-k` | Зберігати початковий файл |
| `-d` | Розпаковувати |
| `-t` | Перевіряти цілісність |
| `-c` | Виводити результат у стандартний потік |

Приклади:

    gzip -1 -k report.txt
    gzip -6 -k report.txt
    gzip -9 -k report.txt

Для повсякденної роботи зазвичай достатньо стандартного рівня.

**Потрібно пам'ятати:** максимальний рівень стиснення не завжди дає суттєво менший файл. Результат залежить від вмісту та характеристик даних.

## 5. GZIP і стандартні потоки

GZIP можна використовувати разом із перенаправленням і конвеєрами Bash.

### 5.1. Стиснути дані у файл через стандартний потік

    gzip -c report.txt > report.txt.gz

Опція `-c` виводить стиснені дані в стандартний потік, а `>` записує їх у файл.

На відміну від звичайного `gzip report.txt`, цей спосіб не видаляє початковий файл.

### 5.2. Розпакувати у стандартний потік

    gzip -dc report.txt.gz

Команда виводить розпакований вміст у термінал.

Щоб записати його в інший файл:

    gzip -dc report.txt.gz > restored-report.txt

### 5.3. Перенаправлення не змінює початковий файл автоматично

У команді:

    gzip -c report.txt > report.txt.gz

файл `report.txt` зберігається, оскільки `gzip` виводить результат у стандартний потік, а не замінює оригінал.

Обережно використовуй `>`: якщо файл призначення вже існує, оболонка зазвичай перезапише його.

## 6. ZIP: архівування багатьох файлів

На відміну від звичайного `gzip`, ZIP може зберігати багато файлів і директорій в одному архіві.

Загальний синтаксис:

    zip [ОПЦІЇ] ARCHIVE.zip FILES

### 6.1. Створити ZIP-архів з одного файлу

    zip documents.zip report.txt

Буде створено `documents.zip`, який міститиме `report.txt`.

### 6.2. Додати декілька файлів

    zip documents.zip report.txt notes.txt README.md

Усі зазначені файли потраплять до одного архіву.

### 6.3. Архівувати директорію рекурсивно

    zip -r project.zip project/

Опція `-r` означає рекурсивний обхід директорій.

Наприклад, якщо структура така:

    project/
    ├── README.md
    ├── package.json
    └── src/
        ├── app.js
        └── styles.css

то `zip -r project.zip project/` включить файли та вкладені директорії.

Без `-r` ZIP зазвичай не обійде всю структуру директорій рекурсивно.

### 6.4. Перевірити розмір архіву

    ls -lh project.zip

### 6.5. Переглянути вміст ZIP

    unzip -l project.zip

Ця команда покаже список файлів, їхні розміри та іншу інформацію, не розпаковуючи архів.

## 7. Розпакування ZIP

### 7.1. Розпакувати в поточну директорію

    unzip project.zip

Файли буде витягнуто в поточну директорію.

Якщо в архіві є директорія `project/`, вона буде створена або доповнена.

### 7.2. Розпакувати в конкретну директорію

Спочатку створимо директорію:

    mkdir -p extracted

Потім розпакуємо архів:

    unzip project.zip -d extracted/

Опція `-d` указує директорію призначення.

### 7.3. Розпакувати лише один файл

    unzip project.zip README.md

Назва має відповідати шляху файлу всередині архіву.

Перевір список:

    unzip -l project.zip

Якщо файл записаний як `project/README.md`, використовуй саме цей шлях:

    unzip project.zip project/README.md

### 7.4. Перевірити ZIP-архів

    unzip -t project.zip

Команда перевіряє цілісність записів архіву.

Для більш докладного виводу:

    unzip -tv project.zip

### 7.5. Поведінка під час перезаписування файлів

Якщо файл із такою самою назвою вже існує, `unzip` може запитати, чи потрібно його перезаписати.

Основні опції:

| Опція | Значення |
|---|---|
| `-n` | Не перезаписувати наявні файли |
| `-o` | Перезаписувати без запитань |
| `-d DIR` | Розпакувати в директорію `DIR` |
| `-l` | Показати список файлів |
| `-t` | Перевірити архів |

Приклади:

    unzip -n project.zip
    unzip -o project.zip

**Обережно:** `-o` може без підтвердження замінити локальні файли. Не використовуй цю опцію без потреби.

## 8. Додавання файлів до ZIP-архіву

ZIP дозволяє додавати файли до вже наявного архіву.

### 8.1. Додати один файл

    zip project.zip notes.txt

Якщо архів уже існує, команда зазвичай додає файл або оновлює його запис.

### 8.2. Додати директорію

    zip -r project.zip docs/

### 8.3. Оновити файли в архіві

    zip -u project.zip README.md

Опція `-u` додає нові файли або оновлює записи для файлів, які змінилися після попереднього архівування.

### 8.4. Видалити файл із ZIP-архіву

    zip -d project.zip notes.txt

Це видаляє запис `notes.txt` з архіву, але не видаляє початковий файл із файлової системи.

Якщо файл міститься всередині директорії архіву, потрібно вказати його шлях, наприклад:

    zip -d project.zip project/notes.txt

Перед виконанням перевір фактичний шлях:

    unzip -l project.zip

## 9. Стиснення та формати: GZIP, ZIP і TAR

Ці інструменти мають різне призначення.

| Формат або інструмент | Що робить | Типовий результат |
|---|---|---|
| `gzip` | Стискає один файл | `file.gz` |
| `gunzip` | Розпаковує GZIP | Початковий файл |
| `zip` | Архівує та стискає файли | `archive.zip` |
| `unzip` | Переглядає та розпаковує ZIP | Файли й директорії |
| `tar` | Об'єднує файли в архів | `archive.tar` |
| `tar -czf` | Створює TAR і стискає через GZIP | `archive.tar.gz` |

### 9.1. Чому `.gz` — не те саме, що `.zip`

`report.txt.gz` зазвичай містить стиснений потік одного файлу.

`documents.zip` може містити багато файлів і директорій, а також інформацію про кожен запис.

Тому для передачі набору файлів часто зручний ZIP, а для стиснення текстових файлів або журналів — GZIP.

### 9.2. Чому `.tar.gz` — це два формати разом

Спочатку TAR об'єднує файли в один потік архіву, а потім GZIP стискає цей потік.

    tar -czf project.tar.gz project/

У зворотному напрямку:

    tar -xzf project.tar.gz

Це поширений формат у Linux, особливо для вихідного коду, пакетів і резервних копій.

## 10. Приклади для Linux-проєктів

### 10.1. Стиснути лог-файл

Припустімо, є файл `application.log`.

    gzip -k application.log

Після виконання залишаться обидва файли:

    application.log
    application.log.gz

Це корисно для зберігання старих логів, які рідко переглядаються.

### 10.2. Архівувати навчальний проєкт у ZIP

    cd ~/projects
    zip -r nest-exercises.zip nest-exercises/

Перевірити архів:

    unzip -l nest-exercises.zip

### 10.3. Не включати залежності Node.js

Для JavaScript-проєкту часто немає потреби зберігати `node_modules/`, якщо залежності можна відновити.

    cd ~/projects

    zip -r nest-exercises.zip nest-exercises/ \
        -x 'nest-exercises/node_modules/*' \
           'nest-exercises/.next/*'

Опція `-x` виключає записи, що відповідають указаним шаблонам.

Для вкладених директорій і складніших шаблонів перевір результат через `unzip -l`.

**Важливо:** `.git` містить історію Git. Якщо архів повинен бути повною копією репозиторію, не виключай `.git` бездумно.

### 10.4. Створити GZIP-архів логів

    gzip -k *.log

Команда обробить файли, що відповідають шаблону `*.log` у поточній директорії, залишаючи оригінали завдяки `-k`.

Якщо таких файлів немає, поведінка залежатиме від налаштувань оболонки та команди; перевір вміст директорії перед виконанням.

### 10.5. Розпакувати ZIP у тестову директорію

    mkdir -p ~/restore-test
    unzip nest-exercises.zip -d ~/restore-test/

Перевір відновлені файли:

    ls -la ~/restore-test/
    find ~/restore-test -maxdepth 3 -type f

Це допоможе переконатися, що архів містить очікувану структуру.

## 11. Приховані файли та директорії

У Linux імена, що починаються з крапки, вважаються прихованими, наприклад:

    .git/
    .env
    .gitignore

Під час архівування конкретної директорії рекурсивними командами `zip -r` або `tar` такі файли зазвичай включаються, якщо їх не виключено.

Але шаблон оболонки `*` зазвичай не охоплює приховані файли.

Наприклад:

    zip backup.zip project/*

Ця команда може не включити приховані файли в корені `project/`.

Надійніший варіант для архівування директорії разом із її прихованими файлами:

    zip -r backup.zip project/

Перед архівуванням перевір, чи справді потрібні приховані дані. Зокрема, `.env` може містити паролі, токени або інші секрети, які не можна передавати без захисту.

## 12. ZIP із паролем

ZIP підтримує традиційне парольне шифрування, але його рівень захисту залежить від реалізації та методу шифрування.

Приклад створення архіву з паролем:

    zip -e private.zip private.txt

Команда попросить увести пароль.

Для архіву з кількома файлами:

    zip -er private.zip private-folder/

**Застереження:**

- Не передавай пароль відкритим текстом у командному рядку, якщо його можуть побачити інші користувачі через список процесів або історію команд.
- Традиційне ZIP-шифрування слабке. Не покладайся на нього для захисту важливих конфіденційних даних.
- Якщо потрібен сильний захист, використовуй сучасний формат шифрування з перевіреною реалізацією та зберігай пароль окремо від архіву.

Саме стиснення через GZIP не забезпечує шифрування.

## 13. Типові помилки

### Помилка 1. Очікують, що GZIP створить архів директорії

Неправильно:

    gzip project/

`gzip` призначений для стиснення файлів, а не для рекурсивного архівування директорій.

Правильно — створити TAR і стиснути його через GZIP:

    tar -czf project.tar.gz project/

### Помилка 2. Забули `-r` для ZIP

Команда:

    zip project.zip project/

не є надійним способом рекурсивно додати всю директорію.

Правильно:

    zip -r project.zip project/

### Помилка 3. Втратили початковий файл після GZIP

Команда:

    gzip report.txt

зазвичай видаляє `report.txt` після успішного стиснення.

Якщо потрібно залишити оригінал:

    gzip -k report.txt

### Помилка 4. Переплутали GZIP та ZIP

- `.gz` — зазвичай стиснений потік одного файлу.
- `.zip` — архів, який може містити багато файлів.
- `.tar.gz` — TAR-архів, стиснений GZIP.

Для кожного формату використовуй відповідний інструмент.

### Помилка 5. Перезаписали локальні файли під час розпакування

Команда:

    unzip -o archive.zip

перезаписує наявні файли без запитань.

Якщо потрібно уникнути перезаписування:

    unzip -n archive.zip

Ще безпечніше спочатку розпаковувати в окрему директорію.

### Помилка 6. Вважають, що архів захищений від сторонніх

ZIP і GZIP самі по собі не гарантують конфіденційність.

Якщо архів містить паролі, токени, приватні ключі чи персональні дані, не передавай його незахищеним каналом.

### Помилка 7. Архів створено, але його не перевірили

Перевірка GZIP:

    gzip -t archive.gz

Перевірка ZIP:

    unzip -t archive.zip

Перегляд ZIP:

    unzip -l archive.zip

Перевірка допомагає виявити пошкодження, але для резервних копій також потрібно тестувати реальне відновлення.

## 14. Корисні команди для щоденної роботи

    # Стиснути файл
    gzip report.txt

    # Стиснути файл, залишивши оригінал
    gzip -k report.txt

    # Розпакувати GZIP
    gunzip report.txt.gz

    # Розпакувати GZIP, залишивши архів
    gunzip -k report.txt.gz

    # Перевірити GZIP
    gzip -t report.txt.gz

    # Стиснути в стандартний потік
    gzip -c report.txt > report.txt.gz

    # Створити ZIP
    zip documents.zip report.txt notes.txt

    # Архівувати директорію
    zip -r project.zip project/

    # Переглянути вміст ZIP
    unzip -l project.zip

    # Перевірити ZIP
    unzip -t project.zip

    # Розпакувати ZIP
    unzip project.zip

    # Розпакувати ZIP в іншу директорію
    unzip project.zip -d extracted/

    # Витягнути один файл із ZIP
    unzip project.zip project/README.md

    # Додати файл до ZIP
    zip project.zip notes.txt

    # Видалити запис із ZIP
    zip -d project.zip notes.txt

    # Створити TAR.GZ
    tar -czf project.tar.gz project/

    # Переглянути TAR.GZ
    tar -tzf project.tar.gz

    # Розпакувати TAR.GZ
    tar -xzf project.tar.gz

## 15. Практика

### Вправа 1. GZIP

Створи тестовий файл:

    mkdir -p ~/compression-practice
    cd ~/compression-practice

    printf 'Linux compression practice\n' > report.txt

Стисни його, зберігши оригінал:

    gzip -k report.txt

Перевір результат:

    ls -lh report.txt report.txt.gz
    gzip -t report.txt.gz

**Завдання:** поясни, чому команда `gzip -k` залишає два файли.

### Вправа 2. Розпакування GZIP

    gunzip -k report.txt.gz

Перевір вміст:

    cat report.txt

**Завдання:** поясни, чим відрізняються `gunzip report.txt.gz` і `gunzip -k report.txt.gz`.

### Вправа 3. ZIP

Створи декілька файлів:

    mkdir -p project/src
    printf 'Project README\n' > project/README.md
    printf '{"name":"demo"}\n' > project/package.json
    printf 'console.log("Hello");\n' > project/src/app.js

Створи архів:

    zip -r project.zip project/

Переглянь його:

    unzip -l project.zip

**Завдання:** визнач, які файли та директорії потрапили до архіву.

### Вправа 4. Розпакування ZIP

    mkdir -p restored
    unzip project.zip -d restored/

Перевір результат:

    find restored -maxdepth 4 -print

**Завдання:** поясни, як опція `-d` впливає на місце розпакування.

### Вправа 5. Порівняння форматів

Створи два архіви:

    tar -czf project.tar.gz project/
    zip -r project.zip project/

Порівняй розміри:

    ls -lh project.tar.gz project.zip

Перевір їхній вміст:

    tar -tzf project.tar.gz
    unzip -l project.zip

**Завдання:** поясни різницю між `.tar.gz` та `.zip`.

## 17. Що потрібно пам'ятати

- `gzip` стискає файли та зазвичай створює `.gz`.
- `gunzip` розпаковує `.gz`.
- `gzip -k` зберігає початковий файл.
- `gzip -t` перевіряє цілісність стисненого файлу.
- `zip` створює архіви, які можуть містити багато файлів.
- `zip -r` рекурсивно додає директорії.
- `unzip -l` показує список файлів у ZIP.
- `unzip -t` перевіряє цілісність ZIP.
- `unzip -d` задає директорію призначення.
- `zip -d` видаляє запис із ZIP-архіву.
- `.tar.gz` — це TAR, стиснений GZIP.
- Стиснення не дорівнює шифруванню.
- Перед розпакуванням невідомих архівів перевіряй їхній вміст.
- Для резервних копій важливо не лише створити архів, а й перевірити можливість відновлення.

## 18. Шлях вивчення GZIP і ZIP

### Core — базовий рівень

- Стискати файли через `gzip`.
- Розпаковувати їх через `gunzip`.
- Створювати ZIP-архіви через `zip`.
- Розпаковувати ZIP через `unzip`.
- Переглядати вміст архівів.
- Розуміти різницю між стисненням та архівуванням.

### Junior — практичний рівень

- Створювати ZIP-архіви цілих проєктів.
- Виключати непотрібні файли.
- Розпаковувати архіви в окремі директорії.
- Перевіряти цілісність архівів.
- Порівнювати розміри різних форматів.
- Використовувати `.tar.gz` для резервних копій.

### Middle — поглиблений рівень

- Використовувати стандартні потоки та перенаправлення.
- Обирати формат відповідно до задачі.
- Планувати резервні копії з урахуванням конфігурацій і залежностей.
- Безпечно відновлювати файли.
- Розуміти обмеження шифрування та захисту архівів.

### Senior — системний рівень

- Організовувати стиснення та ротацію журналів.
- Визначати політику резервного копіювання.
- Автоматизувати створення та перевірку архівів.
- Захищати конфіденційні резервні копії.
- Тестувати процедури відновлення.

## Головне

Для повсякденної роботи в Linux достатньо впевнено знати такі команди:

    gzip -k file.txt             # стиснути, зберегти оригінал
    gunzip -k file.txt.gz        # розпакувати, зберегти архів
    gzip -t file.txt.gz          # перевірити GZIP

    zip -r archive.zip folder/   # створити ZIP
    unzip -l archive.zip         # переглянути ZIP
    unzip -t archive.zip         # перевірити ZIP
    unzip archive.zip -d out/    # розпакувати в out/

А якщо потрібно об'єднати директорію проєкту в один стиснений архів Linux, використовуй:

    tar -czf project.tar.gz project/

Пам'ятай: **GZIP стискає, ZIP архівує та стискає, а TAR об'єднує файли в архів і може працювати разом із GZIP.**
