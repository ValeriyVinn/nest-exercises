# 05. Repositories

Репозиторії Linux — це сервери або локальні джерела, у яких зберігаються пакети програм, їхні версії та метадані. За допомогою репозиторіїв APT може знаходити програми, завантажувати їх, перевіряти залежності та встановлювати оновлення.

В Ubuntu репозиторії є основним джерелом програмного забезпечення для менеджера пакетів APT.

Розуміння репозиторіїв допомагає з'ясувати:

- Звідки система отримує пакети.
- Чому певна програма доступна або недоступна.
- Чим відрізняються офіційні репозиторії Ubuntu від сторонніх.
- Де налаштовуються джерела пакетів.
- Як перевірити, з якого джерела встановлюється пакет.
- Як безпечно додавати або вимикати сторонні джерела.

## 1. Що потрібно знати

✔ **Repository** — джерело пакетів і метаданих, доступне через мережу або локальну файлову систему.

✔ **APT** — інструмент для пошуку, встановлення, оновлення та видалення пакетів.

✔ **Package index** — локальний список доступних пакетів і відомостей про їхні версії.

✔ `sudo apt update` — завантажує актуальні списки пакетів із налаштованих джерел.

✔ `apt-cache policy package-name` — показує доступні версії пакета та джерела, з яких вони можуть надходити.

✔ `/etc/apt/sources.list` — традиційний файл налаштування джерел APT, якщо він використовується системою.

✔ `/etc/apt/sources.list.d/` — каталог для додаткових файлів джерел пакетів.

✔ `.list` і `.sources` — формати файлів налаштування джерел APT.

✔ Офіційні репозиторії Ubuntu містять пакети, які підтримуються відповідно до політики Ubuntu.

✔ Сторонні репозиторії можуть надавати додаткові програми або інші версії пакетів.

✔ Перед додаванням стороннього джерела потрібно перевірити його походження, підтримку та спосіб перевірки підписів.

## 2. Як працюють репозиторії

APT не переглядає всі сервери інтернету щоразу, коли ти шукаєш пакет. Він використовує налаштовані джерела та локальні списки пакетів.

Загальна схема:

    1. У системі налаштовані джерела пакетів.
    2. apt update звертається до цих джерел.
    3. APT завантажує актуальні метадані.
    4. apt search шукає пакети в локальних списках.
    5. apt install завантажує потрібні пакети з доступних джерел.
    6. APT перевіряє залежності та автентичність пакетів
       відповідно до налаштувань системи.

Наприклад:

    sudo apt update
    apt search curl
    apt-cache policy curl
    sudo apt install curl

Перша команда оновлює списки пакетів. Друга шукає пакет. Третя показує доступні версії та джерела. Четверта встановлює пакет.

**Важливо:** `apt update` не оновлює встановлені програми. Вона оновлює інформацію про пакети з налаштованих репозиторіїв.

## 3. Основні компоненти репозиторію

Репозиторій зазвичай містить не лише файли програм, а й метадані, які описують доступні пакети.

Основні компоненти:

- **Packages metadata** — інформація про назви пакетів, версії, залежності та інші властивості.
- **Package files** — архіви пакетів, наприклад `.deb`.
- **Release metadata** — інформація про стан репозиторію та його індекси.
- **Signatures** — цифрові підписи, які допомагають перевірити автентичність метаданих.

APT використовує ці дані, щоб визначити доступні пакети, їхні версії та залежності.

### Приклад

Припустимо, репозиторій містить:

    curl      8.5.0
    nano      7.2
    git       2.x

Після виконання:

    sudo apt update

APT оновлює локальну інформацію про ці пакети.

Потім можна виконати:

    apt show curl
    apt-cache policy curl

Щоб перевірити інформацію про конкретний пакет.

Наведені версії є умовними прикладами, а не актуальними версіями для конкретного випуску Ubuntu.

## 4. Основні офіційні компоненти Ubuntu

В Ubuntu офіційні репозиторії традиційно поділяються на компоненти, зокрема `main`, `restricted`, `universe` і `multiverse`.

Вони відрізняються характером програмного забезпечення та політикою підтримки.

### `main`

Містить основне програмне забезпечення Ubuntu, яке підтримується відповідно до політики дистрибутива.

Цей компонент важливий для базової роботи системи.

### `restricted`

Містить певне програмне забезпечення з обмеженнями щодо ліцензування або розповсюдження, наприклад деякі драйвери обладнання.

### `universe`

Містить широкий набір програм із відкритим кодом, підтримка яких може відрізнятися від підтримки пакетів у `main`.

Не слід автоматично вважати, що кожен пакет із `universe` має такий самий рівень підтримки, як пакети `main`.

### `multiverse`

Містить програмне забезпечення, на яке можуть поширюватися обмеження щодо ліцензування або розповсюдження.

Перед використанням таких пакетів варто перевірити відповідні умови.

### Як запам'ятати

    main        — основний компонент Ubuntu.
    restricted  — певне програмне забезпечення з обмеженнями.
    universe    — широкий набір додаткових програм.
    multiverse  — програми з певними ліцензійними
                  або іншими обмеженнями.

Ці назви — компоненти репозиторіїв, а не окремі команди.

Доступність компонентів і конкретних пакетів залежить від випуску Ubuntu та налаштувань системи.

## 5. Що таке випуск Ubuntu в джерелі пакетів

Під час налаштування джерел APT часто зустрічаються назви випусків Ubuntu, наприклад `noble` або `jammy`.

Це кодові назви випусків Ubuntu:

- `jammy` — Ubuntu 22.04 LTS.
- `noble` — Ubuntu 24.04 LTS.

Кодові назви допомагають APT визначати, для якого випуску системи призначені пакети.

Умовний приклад рядка джерела:

    deb http://archive.ubuntu.com/ubuntu noble main universe

У цьому прикладі:

- `deb` — джерело бінарних пакетів.
- `http://archive.ubuntu.com/ubuntu` — адреса репозиторію.
- `noble` — кодова назва випуску.
- `main universe` — компоненти репозиторію.

**Увага:** цей рядок наведено лише для пояснення формату. Не додавай його навмання до системи. Використовуй джерела, які відповідають саме твоєму випуску Ubuntu.

Не можна бездумно змішувати репозиторії різних випусків: це може призвести до конфліктів версій і залежностей.

## 6. Де зберігаються налаштування репозиторіїв

Основні шляхи:

    /etc/apt/sources.list
    /etc/apt/sources.list.d/

Перший шлях — традиційний файл джерел APT. У сучасних системах він може бути відсутнім, порожнім або використовуватися не як основне місце налаштування.

Другий шлях — каталог для додаткових файлів джерел.

У ньому можуть бути файли з розширеннями:

    *.list
    *.sources

Сучасний формат `.sources` використовує структуровані поля. Його часто називають форматом deb822.

### Переглянути каталог джерел

    ls -la /etc/apt/sources.list.d/

### Перевірити традиційний файл, якщо він існує

    cat /etc/apt/sources.list

Якщо файл відсутній, це не обов'язково означає проблему. Джерела можуть бути налаштовані через файли в `/etc/apt/sources.list.d/`.

### Переглянути файли `.list`

    grep -R --include='*.list' '^[[:space:]]*deb ' \
      /etc/apt/sources.list.d/

Ця команда шукає рядки, що починаються з `deb`, у файлах `.list` цього каталогу.

Вона не охоплює всі можливі формати джерел, тому для повної перевірки потрібно переглядати також файли `.sources`.

## 7. Формат `.list`

Файл `.list` використовує однорядковий формат джерел APT.

Умовний приклад:

    deb https://example.org/ubuntu noble main

Структура:

    deb URL SUITE COMPONENTS

Де:

- `deb` — джерело бінарних пакетів.
- `URL` — адреса репозиторію.
- `SUITE` — випуск або інша назва набору пакетів.
- `COMPONENTS` — компоненти репозиторію.

У старих або спеціалізованих конфігураціях можуть також використовуватися джерела вихідних пакетів із позначенням `deb-src`.

### Приклад `deb-src`

    deb-src https://example.org/ubuntu noble main

Таке джерело призначене для отримання вихідних пакетів, а не звичайних готових бінарних пакетів.

Не додавай приклад з `example.org` до робочої конфігурації: це демонстрація синтаксису.

## 8. Формат `.sources`

У сучасному APT можна використовувати формат deb822 із розширенням `.sources`.

Умовний приклад:

    Types: deb
    URIs: https://example.org/ubuntu
    Suites: noble
    Components: main universe
    Enabled: yes

Основні поля:

- `Types` — типи пакетів, наприклад `deb` або `deb-src`.
- `URIs` — адреси джерел.
- `Suites` — випуски або набори пакетів.
- `Components` — компоненти репозиторію.
- `Enabled` — чи активне джерело, якщо це поле використовується.

У `.sources` можна також задавати параметри ключів підпису та інші властивості джерела.

**Важливо:** це умовний приклад формату. Не використовуй його як готове джерело без перевірки адреси, випуску, компонентів і ключів підпису.

## 9. Як переглянути налаштовані репозиторії

Для початку переглянь список файлів:

    ls -la /etc/apt/sources.list.d/

Потім переглянь конкретний файл `.list`:

    cat /etc/apt/sources.list.d/example.list

Або файл `.sources`:

    cat /etc/apt/sources.list.d/example.sources

Назви `example.list` і `example.sources` тут умовні. Підстав реальні назви файлів зі своєї системи.

Якщо потрібно переглянути всі файли з цього каталогу:

    grep -R -n '' /etc/apt/sources.list.d/

Ця команда виводить вміст файлів із зазначенням шляхів і номерів рядків. Якщо файлів багато, вивід може бути довгим.

Для перегляду лише назв файлів:

    find /etc/apt/sources.list.d/ -maxdepth 1 -type f

### На що звернути увагу

- Чи відповідає випуск джерела твоїй версії Ubuntu.
- Чи походить адреса з офіційного або довіреного джерела.
- Чи не налаштовано дубльовані джерела.
- Чи немає джерел старих випусків, які більше не потрібні.
- Чи зрозуміло, який репозиторій надає пакет.

Не редагуй файли лише тому, що їхній вміст здається незнайомим. Спочатку з'ясуй призначення кожного джерела.

## 10. Як перевірити версію Ubuntu

Перед дослідженням репозиторіїв корисно дізнатися, який випуск системи використовується.

    cat /etc/os-release

Серед полів зазвичай є:

    NAME="Ubuntu"
    VERSION="..."
    VERSION_CODENAME=...

Це лише приклад формату виводу.

Кодова назва випуску може допомогти перевірити, чи відповідають налаштовані джерела поточній системі.

Також можна використати:

    lsb_release -a

Ця команда доступна, якщо відповідний інструмент установлений.

**Правило:** перед додаванням або зміною джерела пакетів перевір кодову назву свого випуску. Не копіюй рядки з інструкцій для іншої версії Ubuntu без перевірки сумісності.

## 11. Як перевірити джерело конкретного пакета

Щоб з'ясувати, звідки APT може встановити пакет, використовуй:

    apt-cache policy curl

Команда показує:

- установлену версію;
- версію-кандидата;
- список доступних версій;
- пріоритети та джерела пакетів.

Приклад умовного фрагмента:

    curl:
      Installed: 8.5.0
      Candidate: 8.5.1
      Version table:
         8.5.1 500
            500 http://archive.ubuntu.com/ubuntu ...
     *** 8.5.0 100
            100 /var/lib/dpkg/status

Це допомагає зрозуміти, яка версія встановлена і яка доступна з поточних джерел.

Якщо пакет доступний у кількох репозиторіях, APT враховує версії та пріоритети під час вибору кандидата.

### Перевірити метадані пакета

    apt show curl

Команда покаже опис, версію та інші властивості пакета.

Однак `apt show` не завжди дозволяє однозначно визначити походження конкретного встановленого файла. Для дослідження джерел версій краще використовувати `apt-cache policy`.

## 12. Що таке сторонній репозиторій

Сторонній репозиторій — це джерело пакетів, яке не є одним із базових офіційних джерел Ubuntu.

Його можуть підтримувати:

- розробники певної програми;
- компанія, яка поширює програмне забезпечення;
- спільнота;
- сторонній постачальник пакетів.

Такі репозиторії іноді потрібні, коли програми немає в стандартних джерелах Ubuntu або потрібна інша версія.

Проте сторонній репозиторій створює додаткові ризики:

- пакет може не відповідати твоєму випуску Ubuntu;
- оновлення можуть припинитися;
- залежності можуть конфліктувати з офіційними пакетами;
- джерело може містити ненадійні або шкідливі пакети.

### Перед додаванням стороннього джерела

Перевір:

1. Чи є репозиторій на офіційному сайті розробника.
2. Чи підтримує він твій випуск Ubuntu.
3. Чи описано спосіб перевірки підписів.
4. Чи є інструкції з видалення джерела.
5. Чи не можна встановити потрібну програму з офіційних репозиторіїв Ubuntu.

**Не додавай репозиторій лише тому, що знайшов команду в дописі на форумі.** Спочатку перевір її джерело та призначення.

## 13. Ключі підпису та безпека репозиторіїв

APT використовує криптографічні підписи для перевірки автентичності метаданих репозиторіїв.

Це допомагає переконатися, що отримана інформація про пакети походить від джерела, яке має відповідний ключ підпису.

Для сторонніх джерел важливо правильно налаштовувати ключі та обмежувати їхню область використання.

### Сучасний підхід

Для окремих сторонніх репозиторіїв часто використовують файл ключа в каталозі:

    /etc/apt/keyrings/

А в конфігурації джерела — параметр `Signed-By`, який вказує, який ключ використовувати для перевірки цього джерела.

Наприклад, умовний рядок `.list` може виглядати так:

    deb [signed-by=/etc/apt/keyrings/vendor.gpg] \
      https://example.org/apt stable main

Це лише приклад синтаксису. Адреса, назва випуску та файл ключа не є готовими значеннями для реальної системи.

### Чого не варто робити

Не вимикай перевірку підписів, щоб обійти помилку репозиторію.

Не використовуй застарілі інструкції, які пропонують без перевірки довіряти всім джерелам або глобально додавати сторонні ключі.

Якщо APT повідомляє про помилку підпису, перевір офіційні інструкції постачальника, адресу джерела, термін дії ключа та налаштування `Signed-By`.

## 14. Що таке `apt-key`

`apt-key` — застарілий механізм керування ключами довіри APT.

У старих інструкціях можна зустріти команди на кшталт:

    sudo apt-key add keyfile

Для сучасних налаштувань сторонніх репозиторіїв цей підхід зазвичай не рекомендується.

Замість глобального додавання ключів застарілим способом використовують окремі keyring-файли та параметр `Signed-By`, якщо це підтримується відповідною конфігурацією джерела.

**Запам'ятай:** не копіюй стару інструкцію з `apt-key` без перевірки, чи не існує сучаснішого рекомендованого способу.

## 15. Як додати сторонній репозиторій

Порядок дій залежить від конкретного постачальника. Не існує однієї універсальної команди, яка безпечно додає будь-який репозиторій.

Загальний процес:

    1. Знайти офіційну інструкцію розробника.
    2. Перевірити сумісність із випуском Ubuntu.
    3. Завантажити ключ підпису рекомендованим способом.
    4. Зберегти ключ у відповідному keyring-файлі.
    5. Створити файл джерела .list або .sources.
    6. Перевірити вміст конфігурації.
    7. Виконати sudo apt update.
    8. Перевірити apt-cache policy потрібного пакета.
    9. Лише після перевірки встановити програму.

### Переглянути джерела після додавання

    ls -la /etc/apt/sources.list.d/

### Оновити списки пакетів

    sudo apt update

Якщо APT повідомляє про помилки підпису або недоступне джерело, не ігноруй їх. Спочатку виправ конфігурацію.

### Перевірити пакет

    apt-cache policy package-name

Заміни `package-name` реальною назвою пакета.

**Важливо:** не додавай випадкові репозиторії лише для того, щоб отримати новішу версію пакета. Сторонні джерела можуть змінювати залежності та впливати на стабільність системи.

## 16. Як вимкнути сторонній репозиторій

Якщо стороннє джерело більше не потрібне, його можна вимкнути або видалити з конфігурації.

Спочатку знайди відповідний файл:

    ls -la /etc/apt/sources.list.d/

Потім переглянь його вміст:

    cat /etc/apt/sources.list.d/vendor.sources

Назва `vendor.sources` наведена як приклад. Використовуй фактичну назву файла.

### Вимкнення в `.sources`

У форматі deb822 джерело може містити поле:

    Enabled: no

Якщо формат і конфігурація це підтримують, так можна вимкнути відповідний запис.

Перед редагуванням створи резервну копію файла.

    sudo cp /etc/apt/sources.list.d/vendor.sources \
      /etc/apt/sources.list.d/vendor.sources.bak

Потім редагуй файл обережно, використовуючи текстовий редактор із відповідними правами.

### Вимкнення в `.list`

У файлах `.list` рядок джерела можна закоментувати, додавши на початку `#`.

Приклад:

    # deb https://example.org/apt stable main

Це умовний приклад.

Після зміни конфігурації онови списки пакетів:

    sudo apt update

Якщо джерело більше не потрібне, його файл можна видалити, але спочатку переконайся, що він не містить інших важливих записів.

**Важливо:** вимкнення репозиторію не видаляє програми, які були встановлені з нього. Воно лише змінює доступні джерела для подальших операцій APT.

## 17. Як видалити стороннє джерело

Перед видаленням перевір, який саме файл відповідає за репозиторій.

Наприклад:

    ls -la /etc/apt/sources.list.d/

Потім перевір його вміст:

    cat /etc/apt/sources.list.d/vendor.list

Якщо ти точно встановив, що файл містить лише непотрібне джерело, його можна видалити:

    sudo rm /etc/apt/sources.list.d/vendor.list

Це приклад команди: не запускай її, доки не перевіриш реальну назву та вміст файла.

Після видалення:

    sudo apt update

### Важливе розрізнення

Видалення файла джерела:

- припиняє використання цього джерела APT;
- не видаляє автоматично встановлені з нього програми;
- не повертає автоматично попередні версії пакетів;
- не гарантує, що всі залежності сторонніх пакетів будуть усунені.

Якщо потрібно видалити саму програму, це окрема операція:

    sudo apt remove package-name

Перед видаленням перевір список пакетів, які APT планує змінити.

## 18. Помилки під час роботи з репозиторіями

### 18.1. `Unable to locate package`

Приклад:

    E: Unable to locate package package-name

Можливі причини:

- помилка в назві пакета;
- списки пакетів застаріли;
- пакет відсутній у налаштованих репозиторіях;
- необхідний компонент репозиторію не ввімкнений;
- програма поширюється через іншу систему встановлення.

Що перевірити:

    sudo apt update
    apt search package-name
    apt-cache policy package-name

Не додавай сторонній репозиторій, доки не перевіриш, чи справді пакет відсутній в офіційних джерелах.

### 18.2. `404 Not Found`

Приклад:

    Failed to fetch ...
    404 Not Found

Можливі причини:

- неправильна адреса джерела;
- застаріла конфігурація;
- помилка в назві випуску або компонента;
- джерело більше не містить очікуваних файлів.

Перевір конфігурацію:

    ls -la /etc/apt/sources.list.d/
    cat /etc/apt/sources.list

Якщо `sources.list` відсутній, перевір файли в `sources.list.d`.

Не замінюй кодову назву Ubuntu навмання. Спочатку перевір випуск системи:

    cat /etc/os-release

### 18.3. `NO_PUBKEY`

APT може повідомляти, що не має потрібного відкритого ключа для перевірки підпису репозиторію.

Можливі причини:

- ключ не встановлено;
- ключ змінився або втратив чинність;
- джерело неправильно налаштоване;
- інструкція постачальника застаріла.

Правильний підхід:

    1. Визначити, якому репозиторію належить помилка.
    2. Перевірити офіційну документацію постачальника.
    3. Відновити ключ за рекомендованою процедурою.
    4. Перевірити налаштування Signed-By.
    5. Повторити sudo apt update.

Не обходь помилку вимкненням перевірки підписів.

### 18.4. `The repository ... does not have a Release file`

Це може означати, що джерело неправильно налаштоване, не підтримує вказаний випуск або більше не публікує потрібні метадані.

Перевір:

- URL репозиторію;
- назву випуску;
- підтримувану версію Ubuntu;
- офіційні інструкції постачальника.

Не намагайся примусово використовувати джерело, призначене для іншого випуску Ubuntu.

### 18.5. Дубльовані джерела

APT може попереджати, що одне джерело налаштоване кілька разів.

Знайди відповідні файли:

    grep -R -n 'example.org' /etc/apt/

Заміни `example.org` адресою, яку згадує повідомлення APT.

Перевір результати та визнач, які записи дублюються. Не видаляй файли навмання: один файл може містити кілька різних джерел.

## 19. Практика в терміналі

Виконуй вправи послідовно. На цьому етапі достатньо переглядати налаштування — змінювати репозиторії для навчання не обов'язково.

### Вправа 1. Дізнатися випуск Ubuntu

    cat /etc/os-release

Завдання:

- Знайди назву системи.
- Знайди версію.
- Знайди `VERSION_CODENAME`, якщо це поле присутнє.
- Поясни, чому кодова назва важлива для репозиторіїв.

### Вправа 2. Переглянути файли джерел

    ls -la /etc/apt/sources.list.d/

Завдання:

- Переглянь назви файлів.
- Визнач, які мають розширення `.list`.
- Визнач, які мають розширення `.sources`.

### Вправа 3. Переглянути вміст джерел

    grep -R -n '' /etc/apt/sources.list.d/

Завдання:

- Знайди адреси репозиторіїв.
- Знайди назви випусків.
- Знайди компоненти, якщо вони зазначені.
- Не публікуй вивід без перевірки, чи не містить він приватних адрес або внутрішніх налаштувань.

### Вправа 4. Оновити списки пакетів

    sudo apt update

Завдання:

- Зверни увагу, які джерела використовує APT.
- Перевір, чи є помилки підпису або доступності.
- Поясни, чому ця команда не встановлює оновлення програм.

### Вправа 5. Перевірити джерела конкретного пакета

    apt-cache policy curl

Завдання:

- Знайди встановлену версію.
- Знайди версію-кандидата.
- Переглянь джерела доступних версій.
- Поясни, як ця інформація допомагає досліджувати репозиторії.

### Вправа 6. Знайти помилку в умовній конфігурації

Припустимо, твоя система використовує один випуск Ubuntu, а сторонній репозиторій налаштований для іншого.

Завдання:

- Поясни, чому таке налаштування може бути небезпечним.
- Назви команду, яка допоможе перевірити випуск системи.
- Назви команду, яка допоможе переглянути джерела пакета.
- Опиши, що потрібно перевірити перед виправленням конфігурації.

Не змінюй реальні файли системи лише заради виконання цієї вправи.

## 20. Мінішпаргалка

    # Перевірити випуск Ubuntu
    cat /etc/os-release

    # Переглянути традиційний файл джерел
    cat /etc/apt/sources.list

    # Переглянути додаткові файли джерел
    ls -la /etc/apt/sources.list.d/

    # Переглянути вміст файлів у каталозі джерел
    grep -R -n '' /etc/apt/sources.list.d/

    # Оновити локальні списки пакетів
    sudo apt update

    # Знайти пакет
    apt search keyword

    # Перевірити доступні версії та джерела пакета
    apt-cache policy package-name

    # Переглянути інформацію про пакет
    apt show package-name

    # Перевірити, які джерела згадують певну адресу
    grep -R -n 'example.org' /etc/apt/

    # Переглянути Snap-пакети
    snap list

    # Переглянути Flatpak-програми
    flatpak list

    # Переглянути довідку APT
    apt --help

## 21. Що потрібно пам'ятати

- Репозиторій — це джерело пакетів і метаданих.
- APT використовує локальні списки пакетів, які оновлюються командою `sudo apt update`.
- Офіційні компоненти Ubuntu включають `main`, `restricted`, `universe` і `multiverse`.
- Кодова назва випуску допомагає визначити, для якої версії Ubuntu призначений репозиторій.
- Джерела APT можуть налаштовуватися у `/etc/apt/sources.list` і `/etc/apt/sources.list.d/`.
- Файли `.list` використовують однорядковий формат, а `.sources` — структурований формат deb822.
- `apt-cache policy` допомагає дослідити доступні версії та їхні джерела.
- Сторонній репозиторій може надати додаткові програми, але також створює ризики сумісності та безпеки.
- Ключі підпису потрібні для перевірки автентичності метаданих репозиторіїв.
- `apt-key` є застарілим механізмом; для сучасних сторонніх джерел зазвичай використовують окремі keyring-файли та `Signed-By`.
- Вимкнення джерела не видаляє програми, які вже були з нього встановлені.
- Перед зміною репозиторіїв потрібно перевірити випуск Ubuntu, адресу джерела, компоненти та ключі підпису.
- Не змішуй репозиторії різних випусків Ubuntu без чіткого розуміння наслідків.

## 23. Рівні засвоєння теми

### Core — базовий рівень

- Розуміти, що таке репозиторій.
- Знати призначення `sudo apt update`.
- Уміти переглядати файли джерел APT.
- Розрізняти офіційні та сторонні репозиторії.
- Знати основні компоненти репозиторіїв Ubuntu.

### Junior — практичний рівень

- Перевіряти випуск Ubuntu через `/etc/os-release`.
- Переглядати `.list` і `.sources`.
- Використовувати `apt-cache policy` для дослідження джерел пакетів.
- Розуміти базові помилки репозиторіїв.
- Безпечно перевіряти сторонні джерела перед їхнім додаванням.

### Middle — поглиблений рівень

- Розуміти роль Release-метаданих і підписів.
- Аналізувати конфігурацію джерел і ключів підпису.
- Досліджувати помилки доступності та автентичності репозиторіїв.
- Розуміти вплив сторонніх джерел на залежності пакетів.
- Визначати причини дубльованих або несумісних джерел.

### Senior — системне розуміння

- Аналізувати конфігурацію APT у системах зі складними джерелами пакетів.
- Розуміти механізми довіри та перевірки підписів.
- Оцінювати ризики використання сторонніх репозиторіїв.
- Планувати зміни джерел пакетів із можливістю відновлення.
- Діагностувати проблеми, пов'язані з версіями, залежностями та походженням пакетів.

---

**Головна думка:** репозиторії визначають, звідки Ubuntu отримує пакети та їхні версії. Перед встановленням програми перевіряй її джерело, а перед зміною конфігурації — випуск Ubuntu, адресу репозиторію та налаштування підписів. Використовуй офіційні або перевірені джерела й не вимикай перевірки безпеки заради швидкого усунення помилки.
