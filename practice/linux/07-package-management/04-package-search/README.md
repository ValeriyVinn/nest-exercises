# 04. Package Search

Пошук пакетів у Linux — це процес знаходження програм у репозиторіях, перевірки їхніх версій, перегляду опису, залежностей і визначення того, які файли належать установленому пакету.

В Ubuntu для пошуку та дослідження пакетів використовуються `apt`, `apt-cache` і `dpkg`.

Ці інструменти допомагають відповісти на практичні запитання:

- Як знайти пакет за назвою або призначенням?
- Як перевірити, чи встановлена програма?
- Як дізнатися, яку версію можна встановити?
- Як переглянути опис пакета та його залежності?
- Як знайти пакет, якому належить певний файл?
- Як дізнатися, які файли встановлює пакет?

## 1. Що потрібно знати

✔ `apt search` — шукає пакети за назвою та описом.

✔ `apt show` — показує інформацію про пакет.

✔ `apt list` — виводить список пакетів, зокрема встановлених або доступних для оновлення.

✔ `apt-cache search` — шукає пакети в локальних списках APT.

✔ `apt-cache show` — показує метадані пакета.

✔ `apt-cache policy` — показує встановлену версію, версію-кандидата та джерела пакета.

✔ `dpkg -s` — показує стан установленого пакета.

✔ `dpkg -l` — виводить список пакетів і їхні статуси.

✔ `dpkg -L` — показує файли, установлені конкретним пакетом.

✔ `dpkg -S` — допомагає визначити, якому встановленому пакету належить файл.

✔ `command -v` — перевіряє, чи доступна команда в поточному середовищі оболонки.

✔ Для пошуку в репозиторіях потрібні локальні списки пакетів, які зазвичай оновлюють командою `sudo apt update`.

## 2. Як працює пошук пакетів

APT використовує локальну інформацію про пакети з налаштованих репозиторіїв.

Загальна схема роботи:

    1. Оновити списки пакетів.
    2. Знайти пакет за назвою або ключовими словами.
    3. Переглянути його опис і версії.
    4. Перевірити, чи встановлений пакет.
    5. За потреби встановити його.

Приклад:

    sudo apt update
    apt search text editor
    apt show nano
    apt-cache policy nano

Команда `sudo apt update` не встановлює програми. Вона оновлює локальні списки пакетів, які використовуються для пошуку та визначення доступних версій.

**Важливо:** `apt search` шукає пакети в доступних локальних списках APT, а не виконує повнотекстовий пошук по всьому інтернету.

## 3. Команда `apt search`

`apt search` шукає пакети за заданими ключовими словами.

Синтаксис:

    apt search keyword

Наприклад, знайти текстові редактори:

    apt search editor

Знайти графічні редактори зображень:

    apt search image editor

Знайти засоби роботи з Git:

    apt search git

Команда може показувати назву пакета, короткий опис і позначку стану.

Приклад умовного виводу:

    nano/stable 7.x amd64
      small, friendly text editor

    vim/stable 9.x amd64
      Vi IMproved - enhanced vi editor

Назви випусків, версії та описи залежать від дистрибутива й репозиторіїв.

### Що важливо пам'ятати

`apt search` шукає за назвою та описом пакета. Тому результатів може бути багато.

Якщо потрібен конкретний пакет, краще перевірити його окремо:

    apt show nano

Якщо ти не знаєш точної назви, починай із загального пошуку:

    apt search browser
    apt search music player
    apt search database client

Зверни увагу: пошукові слова не обов'язково мають збігатися з назвою пакета. Програма, яку користувач називає одним словом, може мати іншу офіційну назву пакета.

## 4. Пошук за точнішою назвою

Якщо відома назва програми або її частина, пошук можна звузити.

Наприклад:

    apt search '^nano$'

Тут використовуються регулярні вирази:

- `^` — початок рядка;
- `$` — кінець рядка.

Такий шаблон допомагає знайти пакет, назва якого точно дорівнює `nano`.

Порівняй:

    apt search nano
    # Може знайти nano та пакети,
    # у назві чи описі яких згадується nano.

    apt search '^nano$'
    # Шукає точну назву nano.

Пам'ятай, що `apt search` використовує регулярні вирази, тому спеціальні символи можуть впливати на результати.

## 5. Команда `apt show`

`apt show` показує докладні метадані пакета.

Синтаксис:

    apt show package-name

Приклад:

    apt show curl

Зазвичай можна побачити такі поля:

- `Package` — назва пакета.
- `Version` — версія пакета.
- `Architecture` — архітектура.
- `Maintainer` — відповідальний за пакет.
- `Depends` — залежності.
- `Description` — опис.
- `Homepage` — домашня сторінка проєкту, якщо вказана.

Приклад умовного виводу:

    Package: curl
    Version: 8.x
    Architecture: amd64
    Depends: libc6, libcurl4
    Description: command line tool for transferring data

Це скорочений приклад. Реальний список полів може бути довшим.

### Для чого використовувати `apt show`

Команда корисна, коли потрібно:

- зрозуміти призначення програми;
- перевірити назву пакета;
- подивитися доступні метадані;
- ознайомитися із залежностями;
- знайти домашню сторінку проєкту.

**Важливо:** `apt show package-name` може показати інформацію про версію, доступну в репозиторіях, навіть якщо пакет не встановлений.

Щоб перевірити стан установленого пакета, використовуй `dpkg -s`.

## 6. Команда `apt list`

`apt list` показує пакети з інформації, доступної APT.

### 6.1. Переглянути пакети, що мають назву

    apt list 'curl*'

Шаблон із `*` може охоплювати назви, що починаються з `curl`.

Кавички важливі: вони передають шаблон команді `apt`, а не дозволяють оболонці передчасно розгорнути його у список файлів поточного каталогу.

### 6.2. Переглянути встановлені пакети

    apt list --installed

Команда може вивести дуже довгий список.

Для пошуку певної назви можна використати `grep`:

    apt list --installed | grep curl

Це текстовий пошук у виводі. Він може знаходити не лише точну назву пакета, а й інші рядки, що містять `curl`.

### 6.3. Переглянути пакети, доступні для оновлення

    apt list --upgradable

Команда показує пакети, для яких доступні новіші версії порівняно з установленими.

Щоб результати були актуальними, перед пошуком оновлень зазвичай виконують:

    sudo apt update

### 6.4. Обмеження `apt list`

`apt list` зручний для швидкого перегляду, але для перевірки конкретного пакета краще застосовувати спеціалізовані команди:

    apt show curl
    dpkg -s curl
    apt-cache policy curl

Кожна з них відповідає на своє запитання.

## 7. Команда `apt-cache search`

`apt-cache search` виконує пошук у локальному кеші метаданих APT.

Синтаксис:

    apt-cache search keyword

Приклади:

    apt-cache search editor
    apt-cache search database
    apt-cache search audio

Зазвичай команда показує назву пакета та короткий опис.

### Відмінність від `apt search`

Для повсякденної роботи обидві команди корисні:

    apt search editor
    apt-cache search editor

`apt` надає зручний для користувача інтерфейс, а `apt-cache` є спеціалізованим інструментом роботи з кешем метаданих APT.

Якщо ти тільки починаєш вивчати Linux, достатньо спочатку запам'ятати `apt search`.

## 8. Команда `apt-cache show`

`apt-cache show` показує метадані пакета з локального кешу APT.

    apt-cache show curl

Це корисно, коли потрібно подивитися інформацію про пакет без його встановлення.

Залежно від налаштувань і доступних версій команда може показати кілька записів.

Для звичайного перегляду інформації можна використовувати коротший варіант:

    apt show curl

**Не плутай:** обидві команди показують інформацію про пакети, але не доводять, що пакет уже встановлений у системі.

## 9. Команда `apt-cache policy`

`apt-cache policy` допомагає з'ясувати, які версії пакета доступні та яка версія буде кандидатом для встановлення.

Синтаксис:

    apt-cache policy package-name

Приклад:

    apt-cache policy curl

Умовний вивід:

    curl:
      Installed: 8.5.0
      Candidate: 8.5.1
      Version table:
         8.5.1 500
            500 http://archive.ubuntu.com/ubuntu ...
     *** 8.5.0 100
            100 /var/lib/dpkg/status

Пояснення:

- `Installed` — версія, яка зараз установлена.
- `Candidate` — версія, яку APT вибрав би для встановлення за поточних умов.
- `Version table` — доступні версії та інформація про їхні джерела.

Якщо пакет не встановлений, значення `Installed` може бути `(none)`.

Якщо `Candidate` дорівнює `(none)`, APT не має кандидата для встановлення з поточних джерел.

### Коли ця команда особливо корисна

- Коли потрібно перевірити версію пакета.
- Коли доступна не та версія, яку ти очікував.
- Коли пакет не знаходиться в репозиторіях.
- Коли потрібно дослідити джерела пакетів.

## 10. Команда `dpkg -s`

`dpkg -s` показує стан конкретного пакета в базі даних `dpkg`.

Синтаксис:

    dpkg -s package-name

Приклад:

    dpkg -s curl

Серед полів можна знайти:

    Package: curl
    Status: install ok installed
    Version: 8.x
    Architecture: amd64

Пояснення:

- `Package` — назва пакета.
- `Status` — поточний стан.
- `Version` — встановлена версія.
- `Architecture` — архітектура пакета.

Ключовий рядок:

    Status: install ok installed

Він означає, що пакет позначений як установлений.

Якщо пакета немає в базі даних `dpkg`, команда повідомить, що пакет не знайдений.

### Чим `dpkg -s` відрізняється від `apt show`

    apt show curl
    # Інформація про пакет із метаданих APT.

    dpkg -s curl
    # Стан пакета в локальній базі dpkg.

Перша команда допомагає досліджувати пакет, доступний через APT. Друга — перевіряти його локальний стан.

## 11. Команда `dpkg -l`

`dpkg -l` виводить список пакетів і їхніх статусів.

Переглянути весь список:

    dpkg -l

Оскільки список може бути великим, зручніше переглядати його через `less`:

    dpkg -l | less

Знайти конкретний пакет:

    dpkg -l curl

Приклад умовного рядка:

    ii  curl  8.x  amd64  command line tool for transferring data

### Що означають статуси

У виводі `dpkg -l` використовуються кілька символів стану. Найважливіші для початківця:

- `ii` — пакет бажано встановити, і він установлений.
- `rc` — пакет видалений, але його конфігураційні файли можуть залишатися.
- `un` — пакет не встановлений; такий запис може траплятися у відповідних списках статусів.

У форматі `dpkg -l` перші два символи позначають бажаний стан і фактичний стан. Можливі й інші комбінації, пов'язані з незавершеними операціями або помилками.

Якщо під час дослідження бачиш незвичний статус, не роби висновків лише за одним символом — перевір пакет докладніше за допомогою `dpkg -s`.

## 12. Команда `dpkg -L`

`dpkg -L` показує файли, які належать установленому пакету.

Синтаксис:

    dpkg -L package-name

Приклад:

    dpkg -L curl

У виводі можуть бути шляхи до:

- виконуваних файлів;
- документації;
- конфігураційних файлів;
- довідкових сторінок;
- інших файлів, установлених пакетом.

Щоб знайти виконувані файли в результатах:

    dpkg -L curl | grep '/bin/'

Це допомагає зрозуміти, які файли встановлює пакет і де вони розташовані.

**Важливо:** `dpkg -L` показує файли, зареєстровані за встановленим пакетом у базі `dpkg`. Він не є загальним пошуком файлів на всьому диску.

## 13. Команда `dpkg -S`

`dpkg -S` допомагає визначити, якому встановленому пакету належить конкретний файл.

Синтаксис:

    dpkg -S /path/to/file

Наприклад:

    dpkg -S /usr/bin/curl

Команда може повернути результат на зразок:

    curl: /usr/bin/curl

Це означає, що файл `/usr/bin/curl` належить пакету `curl`.

### Коли це корисно

- Коли ти знайшов незнайомий системний файл.
- Коли потрібно з'ясувати, яка програма встановила файл.
- Коли досліджуєш структуру файлової системи.
- Коли потрібно визначити пакет, пов'язаний із певною командою.

### Обмеження

`dpkg -S` шукає серед файлів, зареєстрованих у базі пакетів `dpkg`.

Якщо файл створила програма вручну, він належить Snap-пакету або був установлений іншим способом, команда може нічого не знайти.

Для файлів, які не належать пакетам APT/`dpkg`, можуть знадобитися інші інструменти.

## 14. Команда `command -v`

Іноді потрібно перевірити не пакет, а саму команду, яку можна запустити в терміналі.

Для цього зручно використовувати:

    command -v curl

Якщо команда доступна через `PATH`, оболонка виведе її шлях або відповідне визначення.

Наприклад:

    /usr/bin/curl

Якщо результату немає, це може означати, що команда не доступна в поточному середовищі оболонки.

Але це **не завжди доводить, що пакет не встановлений**. Наприклад:

- пакет може не містити виконуваної команди;
- команда може бути розташована поза `PATH`;
- назва команди може відрізнятися від назви пакета;
- програма може бути встановлена через Snap, Flatpak або інший механізм.

### Приклад: назва пакета й назва команди

Назва пакета не завжди збігається з назвою виконуваного файла.

Тому корисно поєднувати команди:

    apt search keyword
    apt show package-name
    dpkg -s package-name
    dpkg -L package-name
    command -v command-name

Так можна пройти шлях від пошуку програми до перевірки її файлів і доступної команди.

## 15. Пошук за допомогою `grep`

`grep` допомагає шукати текст у виводі інших команд.

Наприклад, знайти пакети, пов'язані з Python:

    apt list --installed | grep python

Знайти записи про певний пакет:

    dpkg -l | grep curl

Знайти файл пакета серед його файлів:

    dpkg -L curl | grep bin

### Що робить конструкція `|`

Символ `|` називається конвеєром, або pipe.

Він передає стандартний вивід першої команди на стандартний ввід другої.

Приклад:

    dpkg -L curl | grep bin

Послідовність:

    1. dpkg -L curl виводить список файлів пакета.
    2. Символ | передає цей список далі.
    3. grep bin залишає рядки, що містять bin.

Тема конвеєрів докладніше розглядається в розділі `03-file-content-and-search`.

### Важливе застереження

Пошук через `grep` не завжди означає точний збіг назви пакета.

Наприклад:

    dpkg -l | grep curl

може знайти не лише пакет `curl`, а й інші пакети, у назвах або описах яких є цей текст.

Якщо потрібен конкретний пакет, використовуй:

    dpkg -s curl
    dpkg -l curl

## 16. Пошук файлів через `find`

Якщо потрібно знайти файл у файловій системі, можна використовувати `find`.

Наприклад:

    find /usr/bin -name 'curl'

Пошук файлів за частиною назви:

    find /usr/bin -name '*python*'

Це пошук файлів у вказаному каталозі, а не пошук пакетів у репозиторіях.

Порівняй:

    apt search python
    # Пошук пакетів у списках APT.

    find /usr/bin -name '*python*'
    # Пошук файлів у каталозі /usr/bin.

    dpkg -S /usr/bin/python3
    # Пошук пакета, якому належить цей файл,
    # якщо файл зареєстрований у базі dpkg.

Це три різні завдання, для яких використовуються різні інструменти.

## 17. Як знайти пакет для потрібної програми

Уявімо, що ти хочеш установити програму для роботи із зображеннями, але не знаєш назви пакета.

### Крок 1. Виконати пошук

    apt search image editor

Переглянь назви пакетів та описи.

### Крок 2. Перевірити знайдений пакет

    apt show package-name

Заміни `package-name` реальною назвою пакета з результатів пошуку.

### Крок 3. Перевірити версії та джерела

    apt-cache policy package-name

Переконайся, що пакет доступний із потрібного репозиторію.

### Крок 4. Перевірити, чи пакет уже встановлений

    dpkg -s package-name

Якщо пакет не встановлений, команда повідомить про це.

### Крок 5. За потреби встановити пакет

    sudo apt install package-name

Перед підтвердженням перевір, які залежності та додаткові пакети APT пропонує встановити.

**Запам'ятай:** пошук пакета сам по собі нічого не встановлює. `apt search`, `apt show` та `apt-cache policy` призначені для дослідження пакетів.

## 18. Де шукати програми, яких немає в APT

Не всі програми в Ubuntu встановлюються через APT.

Можливі способи встановлення:

- APT/`dpkg` — системні пакети з репозиторіїв.
- Snap — пакети, що керуються системою Snap.
- Flatpak — програми, що керуються Flatpak.
- Офіційні інсталятори розробника.
- Інші системи встановлення, наприклад менеджери мов або середовищ розробки.

Перевірити встановлені Snap-пакети:

    snap list

Якщо команда `snap` доступна, вона покаже список пакетів, установлених через Snap.

Перевірити Flatpak-програми:

    flatpak list

Ця команда працюватиме, якщо Flatpak встановлений і доступний у системі.

**Важливо:** відсутність програми в `apt search` не означає, що її неможливо встановити в Ubuntu. Вона може бути доступна через інший механізм встановлення.

Водночас не варто встановлювати невідомі пакети з випадкових сайтів. Перевіряй джерело, розробника та спосіб оновлення програми.

## 19. Типові помилки початківців

### Помилка 1. Плутати пошук пакета з пошуком команди

Неправильне припущення:

    apt search curl
    # Отже, команда curl обов'язково доступна.

Пошук може знайти пакет, який ще не встановлений.

Перевір:

    dpkg -s curl
    command -v curl

Перша команда перевіряє стан пакета, друга — доступність команди.

### Помилка 2. Вважати, що `apt show` доводить факт встановлення

Команда:

    apt show curl

може показати опис і версію доступного пакета, навіть якщо його немає в системі.

Для перевірки встановлення використовуй:

    dpkg -s curl

### Помилка 3. Очікувати від `dpkg -L` пошуку по всьому диску

Команда:

    dpkg -L curl

показує файли, зареєстровані за пакетом `curl`.

Для пошуку файлів у каталозі використовуй `find`.

### Помилка 4. Вважати, що `dpkg -S` знайде будь-який файл

Команда:

    dpkg -S /path/to/file

не гарантує знаходження файлів, створених вручну або встановлених іншим менеджером пакетів.

### Помилка 5. Забувати оновлювати списки пакетів

Якщо пакет не знаходиться або показує неочікувану версію, спочатку онови списки:

    sudo apt update

Після цього повтори пошук.

### Помилка 6. Не перевіряти точну назву пакета

Пошукові результати можуть містити багато схожих назв.

Перед встановленням перевір:

    apt show package-name
    apt-cache policy package-name

Переконайся, що це саме та програма, яка тобі потрібна.

### Помилка 7. Вважати, що будь-яка програма встановлена через APT

Програма може бути встановлена через Snap, Flatpak або іншим способом.

Для додаткової перевірки використовуй відповідний інструмент, наприклад:

    snap list
    flatpak list

Ці команди не замінюють APT, а допомагають досліджувати інші системи керування програмами.

## 20. Практика в терміналі

Виконуй вправи по черзі. Для навчання краще використовувати вже знайомі пакети, наприклад `curl`, `nano` або `bash`.

### Вправа 1. Пошук пакета

    apt search editor

Завдання:

- Переглянь результати.
- Знайди назви кількох текстових редакторів.
- Прочитай їхні короткі описи.
- Поясни, чому пошук може повертати багато результатів.

### Вправа 2. Перегляд опису пакета

    apt show nano

Завдання:

- Знайди поле `Package`.
- Знайди поле `Version`.
- Переглянь `Description`.
- Знайди інформацію про залежності, якщо вона є.

### Вправа 3. Перевірка доступних версій

    apt-cache policy curl

Завдання:

- Знайди поле `Installed`.
- Знайди поле `Candidate`.
- Поясни, що означає кожне поле.
- Зверни увагу на джерела доступних версій.

### Вправа 4. Перевірка встановленого пакета

    dpkg -s curl

Завдання:

- Знайди рядок `Status`.
- Знайди встановлену версію.
- Переконайся, що `apt show` і `dpkg -s` відповідають на різні запитання.

Якщо `curl` не встановлений, вибери інший пакет, який уже є у твоїй системі.

### Вправа 5. Перегляд файлів пакета

    dpkg -L curl

Завдання:

- Переглянь список файлів.
- Знайди шляхи, які містять `/bin/`.
- Зверни увагу на каталоги документації.

### Вправа 6. Визначення власника файла

    dpkg -S /usr/bin/curl

Завдання:

- Прочитай назву пакета у відповіді.
- Поясни, як `dpkg -S` допомагає досліджувати файлову систему.
- Спробуй інший файл, який належить установленому пакету.

### Вправа 7. Пошук команди

    command -v curl

Завдання:

- Перевір, чи доступна команда.
- Запиши шлях, якщо він виведений.
- Поясни, чому відсутність шляху не завжди означає, що програма не встановлена.

### Вправа 8. Порівняння пошуку пакетів і файлів

    apt search python
    find /usr/bin -name '*python*'
    dpkg -S /usr/bin/python3

Завдання:

- Порівняй результати.
- Поясни, що саме шукає кожна команда.
- Визнач, чому їх не можна вважати взаємозамінними.

## 21. Мінішпаргалка

    # Пошук пакета за назвою або описом
    apt search keyword

    # Пошук точної назви пакета
    apt search '^package-name$'

    # Перегляд інформації про пакет
    apt show package-name

    # Список пакетів
    apt list

    # Список установлених пакетів
    apt list --installed

    # Список пакетів, доступних для оновлення
    apt list --upgradable

    # Пошук у локальних списках APT
    apt-cache search keyword

    # Перегляд метаданих пакета
    apt-cache show package-name

    # Перевірка версій і джерел пакета
    apt-cache policy package-name

    # Перевірка стану встановленого пакета
    dpkg -s package-name

    # Перегляд списку пакетів і статусів
    dpkg -l

    # Перегляд файлів установленого пакета
    dpkg -L package-name

    # Визначення пакета, якому належить файл
    dpkg -S /path/to/file

    # Перевірка доступності команди
    command -v command-name

    # Пошук тексту у виводі команди
    dpkg -l | grep keyword

    # Пошук файлів за назвою в каталозі
    find /usr/bin -name '*keyword*'

    # Перегляд установлених Snap-пакетів
    snap list

    # Перегляд установлених Flatpak-програм
    flatpak list

## 22. Що потрібно пам'ятати

- `apt search` допомагає знайти пакети за назвою та описом.
- `apt show` показує метадані пакета, але не гарантує, що пакет установлений.
- `apt list --installed` показує встановлені пакети.
- `apt list --upgradable` показує пакети, для яких доступні оновлення.
- `apt-cache policy` допомагає перевірити встановлену версію, кандидата та джерела.
- `dpkg -s` перевіряє стан конкретного пакета.
- `dpkg -l` показує список пакетів та їхні статуси.
- `dpkg -L` показує файли, зареєстровані за пакетом.
- `dpkg -S` допомагає визначити власника файла серед пакетів `dpkg`.
- `command -v` перевіряє доступність команди в поточному середовищі.
- `grep` фільтрує текстовий вивід, а `find` шукає файли у файловій системі.
- APT не охоплює автоматично всі програми, установлені через Snap, Flatpak або інші системи.
- Якщо пакет не знаходиться або інформація застаріла, спочатку виконай `sudo apt update`.

## 24. Рівні засвоєння теми

### Core — базовий рівень

- Розуміти, що таке пакет і репозиторій.
- Уміти шукати пакети через `apt search`.
- Уміти переглядати опис через `apt show`.
- Уміти перевіряти встановлення через `dpkg -s`.
- Знати призначення `apt list --installed`.

### Junior — практичний рівень

- Перевіряти версії пакетів за допомогою `apt-cache policy`.
- Переглядати файли пакетів через `dpkg -L`.
- Визначати власника файла через `dpkg -S`.
- Використовувати `grep` для пошуку в текстовому виводі.
- Розуміти різницю між назвою пакета та назвою команди.
- Відрізняти пакети APT від програм, установлених через Snap або Flatpak.

### Middle — поглиблений рівень

- Аналізувати версії пакетів і джерела їхнього отримання.
- Досліджувати залежності й метадані пакетів.
- З'ясовувати, чому пакет недоступний у поточних репозиторіях.
- Визначати походження системних файлів.
- Поєднувати `apt`, `dpkg`, `grep` і `find` для діагностики.

### Senior — системне розуміння

- Розуміти роль локальних списків APT та бази даних `dpkg`.
- Аналізувати джерела пакетів і доступні версії.
- Досліджувати складні випадки, коли програма встановлена не через APT.
- Розуміти обмеження пошуку за метаданими пакетів.
- Використовувати результати пошуку для діагностики проблем керування програмним забезпеченням.

---

**Головна думка:** для пошуку програм використовуй `apt search`, для дослідження пакета — `apt show` і `apt-cache policy`, для перевірки встановленого пакета — `dpkg -s`, для перегляду його файлів — `dpkg -L`, а для визначення власника файла — `dpkg -S`. Кожна команда відповідає на своє запитання, тому найкращий результат дає їхнє поєднання.
