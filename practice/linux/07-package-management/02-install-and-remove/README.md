# 02. Install and Remove Packages

Install and Remove Packages (встановлення та видалення пакетів) — це одна з основних операцій керування програмним забезпеченням у Linux.

В Ubuntu для встановлення та видалення програм зазвичай використовується APT (Advanced Package Tool).

APT дозволяє встановлювати програми з репозиторіїв, автоматично опрацьовувати залежності, видаляти пакети, очищати непотрібні залежності та перевіряти результат операцій.

Основні команди:

    sudo apt install package-name
    sudo apt remove package-name
    sudo apt purge package-name
    sudo apt autoremove
    sudo apt install --simulate package-name

Пакети також можна встановлювати з локальних `.deb`-файлів.

У цьому розділі розглядаються практичне встановлення, перевірка, видалення та очищення пакетів в Ubuntu.

### Що потрібно пам'ятати

• `sudo apt install package-name` встановлює пакет із доступних джерел.

• APT автоматично опрацьовує залежності та може встановити додаткові пакети.

• Перед підтвердженням встановлення потрібно перевірити список запланованих змін.

• `sudo apt remove package-name` видаляє пакет, зазвичай залишаючи його системні конфігураційні файли.

• `sudo apt purge package-name` видаляє пакет разом із системними конфігураційними файлами, які належать пакету.

• Видалення пакета не гарантує видалення всіх користувацьких даних програми.

• `sudo apt reinstall package-name` перевстановлює пакет, якщо він доступний у налаштованих джерелах.

• `sudo apt autoremove` видаляє автоматично встановлені залежності, які більше не потрібні за оцінкою APT.

• `sudo apt install --simulate package-name` дозволяє попередньо перевірити план встановлення без фактичного виконання операції.

• `dpkg -i package.deb` встановлює локальний `.deb`-пакет, але не розв'язує автоматично всі відсутні залежності через репозиторії.

• Для встановлення локального `.deb` часто зручніше використовувати `sudo apt install ./package.deb`.

• Після встановлення програми варто перевірити її версію або стан пакета.

• Не видаляй системні пакети, якщо не розумієш, які компоненти від них залежать.

• Перед використанням `apt autoremove` завжди перевіряй список пакетів, які пропонується видалити.

# Package Installation

Package installation (встановлення пакета) — це процес додавання програмного забезпечення до системи за допомогою пакетного менеджера.

У Ubuntu для цього найчастіше використовується команда:

    sudo apt install package-name

Наприклад, встановлення `tree`:

    sudo apt install tree

Пакет `tree` дозволяє відображати структуру каталогів у вигляді дерева.

Після встановлення можна виконати:

    tree

Приклад результату:

    .
    ├── documents
    │   ├── notes.txt
    │   └── report.txt
    └── projects
        └── app

Фактичний результат залежить від вмісту поточного каталогу.

---

# apt install

`apt install` — основна команда для встановлення пакетів із доступних джерел APT.

Синтаксис:

    sudo apt install package-name

Наприклад:

    sudo apt install curl

APT виконує приблизно такі дії:

    1. Перевіряє доступність пакета.
    2. Визначає потрібну версію.
    3. Аналізує залежності.
    4. Визначає додаткові пакети, якщо вони потрібні.
    5. Показує план операції.
    6. Після підтвердження завантажує пакети.
    7. Встановлює та налаштовує їх.

Для виконання операції APT зазвичай потребує прав адміністратора.

---

## Встановлення одного пакета

    sudo apt install git

Ця команда встановлює Git, якщо пакет доступний у налаштованих джерелах.

Перевірити результат:

    git --version

Приклад результату:

    git version 2.x.x

Номер версії залежить від установленого пакета.

---

## Встановлення декількох пакетів

APT дозволяє встановити кілька пакетів однією командою.

    sudo apt install git curl wget

У цьому прикладі встановлюються:

    git
        → система контролю версій

    curl
        → інструмент для передавання даних через URL

    wget
        → інструмент для завантаження файлів

Якщо один із пакетів уже встановлений, APT зазвичай повідомить про це та не встановлюватиме його повторно без необхідності.

---

## Встановлення конкретної версії

Якщо потрібна певна версія пакета, можна вказати її явно.

Синтаксис:

    sudo apt install package-name=version

Наприклад, умовна команда:

    sudo apt install package-name=1.2.3-1

Назва пакета та версія в прикладі умовні.

Щоб дізнатися доступні версії:

    apt-cache policy package-name

Встановити конкретну версію можна лише тоді, коли вона доступна з налаштованих джерел або іншим підтримуваним способом.

Після встановлення конкретної версії APT не обов'язково автоматично закріплює її від подальшого оновлення. Для керування оновленнями існують окремі механізми.

---

# Як працює встановлення пакета

Наприклад:

    sudo apt install curl

Спрощена схема:

    apt install curl
          ↓
    Find package
          ↓
    Check dependencies
          ↓
    Calculate required changes
          ↓
    Show installation plan
          ↓
    Confirm operation
          ↓
    Download packages
          ↓
    Unpack packages
          ↓
    Configure packages
          ↓
    Installation completed

Під час встановлення APT може повідомити, що додатково потрібно встановити інші пакети.

Це нормально: програма може залежати від бібліотек або інших компонентів системи.

Перед підтвердженням перевір:

    additional packages
    packages to be installed
    packages to be removed
    download size
    disk space requirements

Якщо система пропонує несподівано видалити важливі пакети, скасуй операцію та розберися в причині.

# Package Dependencies

Dependency (залежність) — це пакет або програмний компонент, необхідний для роботи іншого пакета.

Наприклад:

    Application
        ↓
    Library A
        ↓
    Library B

Якщо потрібних бібліотек немає в системі, APT може встановити їх автоматично.

Переглянути залежності пакета:

    apt depends curl

Переглянути інформацію про пакет:

    apt show curl

Якщо встановлення потребує додаткових пакетів, APT покаже їх перед підтвердженням.

Залежності можуть мати обмеження щодо версій або альтернативні варіанти. Тому не завжди достатньо просто скопіювати файли програми в системний каталог.

**Головне:** використання APT допомагає уникнути багатьох проблем із залежностями, які можуть виникнути під час ручного встановлення програм.

---

# Installation Simulation

Simulation — це попереднє моделювання операції без фактичного встановлення чи видалення пакетів.

Для моделювання встановлення:

    sudo apt install --simulate curl

Альтернативний короткий варіант:

    sudo apt -s install curl

APT показує заплановані дії, але не виконує звичайне встановлення пакетів.

Для моделювання видалення:

    sudo apt remove --simulate curl

Для моделювання видалення з конфігурацією:

    sudo apt purge --simulate curl

Симуляція корисна, коли потрібно перевірити:

    which packages will be installed
    which packages will be removed
    which dependencies are involved
    what changes APT plans to make

Симуляція не гарантує, що операція пізніше завершиться успішно: стан системи, репозиторіїв або доступність пакетів можуть змінитися.

---

# Перевірка встановлення

Після встановлення пакета потрібно переконатися, що він справді встановлений і працює.

Для цього можна використовувати декілька способів.

## Спосіб 1 — перевірити версію програми

Наприклад:

    git --version

Або:

    curl --version

Це зручно, коли програма підтримує параметр `--version`.

---

## Спосіб 2 — перевірити стан пакета

    dpkg -s git

Якщо пакет установлений, результат зазвичай міститиме поле:

    Status: install ok installed

Якщо пакет не встановлений, команда повідомить про відповідну помилку або відсутність пакета в базі.

---

## Спосіб 3 — переглянути встановлені пакети

    apt list --installed

Ця команда виводить список установлених пакетів.

Для перевірки конкретного пакета:

    dpkg -l git

У виводі `dpkg -l` стан пакета позначається спеціальними символами.

Наприклад, рядок зі станом `ii` зазвичай означає, що пакет вибраний для встановлення та успішно встановлений.

---

## Спосіб 4 — перевірити розташування виконуваного файла

    command -v git

Приклад результату:

    /usr/bin/git

Команда `command -v` показує, як оболонка знаходить команду.

Якщо результат порожній, це не завжди означає, що пакет не встановлений: виконуваний файл може мати іншу назву або не входити до `PATH`.

---

# apt remove

`apt remove` видаляє пакет із системи.

Синтаксис:

    sudo apt remove package-name

Приклад:

    sudo apt remove tree

APT покаже заплановані зміни та попросить підтвердження, якщо інтерактивне підтвердження не вимкнено.

Зазвичай команда видаляє програмні файли пакета, але залишає системні конфігураційні файли, які пакетний менеджер зберігає для можливого повторного використання.

Важливо розрізняти:

    package files
        → файли, встановлені пакетом

    system configuration files
        → системні конфігураційні файли пакета

    user data
        → дані користувача, які програма може зберігати окремо

Видалення пакета не гарантує автоматичного видалення всіх даних, які програма створила під час роботи.

---

# apt purge

`apt purge` видаляє пакет разом із системними конфігураційними файлами, які належать цьому пакету та керуються пакетним менеджером.

Синтаксис:

    sudo apt purge package-name

Приклад:

    sudo apt purge tree

Для звичайного пакета без значущої конфігурації різниця між `remove` та `purge` може бути непомітною.

Для серверних служб або програм із конфігураційними файлами ця різниця важливіша.

Порівняння:

    sudo apt remove package-name
        → видалити пакет
        → зазвичай залишити системну конфігурацію

    sudo apt purge package-name
        → видалити пакет
        → видалити також системну конфігурацію, якою керує пакетний менеджер

**Важливо:** `purge` не гарантує видалення користувацьких даних, файлів у домашньому каталозі або всіх файлів, які програма створила самостійно.

Перед видаленням важливих серверних програм потрібно перевірити, де зберігаються їхні дані та конфігурація.

---

# apt remove vs apt purge

Це одна з найважливіших відмінностей у керуванні пакетами.

| Команда | Призначення |
|---|---|
| `apt remove` | Видаляє пакет, зазвичай залишаючи системні конфігураційні файли |
| `apt purge` | Видаляє пакет разом із системними конфігураційними файлами, якими керує пакетний менеджер |

Приклад:

    sudo apt remove nginx

Якщо потрібно видалити пакет разом із системною конфігурацією:

    sudo apt purge nginx

Nginx у цьому прикладі наведено для демонстрації. Перед виконанням перевір, які зміни пропонує APT.

Якщо конфігурація потрібна для подальшого використання, `remove` може бути зручнішим.

Якщо пакет більше не потрібен і його системну конфігурацію також потрібно видалити, можна розглянути `purge`.

# Видалення залежностей

Під час встановлення програми APT може автоматично встановити додаткові пакети.

Після видалення програми деякі з цих пакетів можуть більше не бути потрібними.

Для їх очищення використовується:

    sudo apt autoremove

APT визначає пакети, які були автоматично встановлені як залежності та більше не потрібні за його обліком.

Перед підтвердженням перевір список пакетів.

Для попереднього моделювання:

    sudo apt autoremove --simulate

Важливо:

    apt remove
        → видаляє зазначений пакет

    apt autoremove
        → видаляє непотрібні автоматично встановлені залежності

Це не одна й та сама операція.

Не видаляй пакети вручну лише через те, що їхні назви незнайомі. Деякі системні компоненти можуть бути потрібними іншим програмам.

# Автоматично та вручну встановлені пакети

APT розрізняє пакети, встановлені вручну, та пакети, встановлені автоматично як залежності.

Manually installed package — пакет, який користувач або інший процес явно попросив установити.

Automatically installed package — пакет, який було встановлено для задоволення залежностей.

Наприклад:

    sudo apt install application-name

Якщо APT додатково встановлює бібліотеки для цієї програми, вони можуть бути позначені як автоматично встановлені залежності.

Переглянути автоматично встановлені пакети:

    apt-mark showauto

Переглянути вручну встановлені пакети:

    apt-mark showmanual

Позначити пакет як установлений вручну:

    sudo apt-mark manual package-name

Позначити пакет як автоматично встановлений:

    sudo apt-mark auto package-name

Будь обережним з останньою командою. Якщо пакет позначити як автоматичний і жоден інший пакет більше не потребуватиме його, APT може запропонувати видалити його під час `autoremove`.

Зазвичай немає потреби змінювати ці позначки без конкретної причини.

---

# apt reinstall

`apt reinstall` повторно встановлює пакет, який уже присутній у системі.

Синтаксис:

    sudo apt reinstall package-name

Приклад:

    sudo apt reinstall curl

Це може бути корисно, якщо потрібно відновити файли пакета або повторно виконати стандартну процедуру його встановлення.

Однак перевстановлення не є універсальним способом ремонту програми.

Воно не обов'язково відновить:

    user configuration
    user-created files
    application database
    manually modified files
    files not managed by the package

Для перевстановлення потрібен доступний пакет відповідної версії в налаштованих джерелах або інший підтримуваний спосіб отримання пакета.

---

# Встановлення локального .deb-пакета

Іноді програмне забезпечення надається не через стандартні репозиторії Ubuntu, а у вигляді локального `.deb`-файлу.

Наприклад:

    example-package.deb

Щоб встановити його через APT:

    sudo apt install ./example-package.deb

Префікс `./` вказує, що йдеться про файл у поточному каталозі.

Якщо файл розташований в іншому каталозі, можна вказати шлях до нього.

Наприклад:

    sudo apt install ~/Downloads/example-package.deb

APT може опрацювати залежності локального пакета через доступні репозиторії.

Перед встановленням перевір:

    1. Джерело файлу.
    2. Назву та призначення програми.
    3. Сумісність з архітектурою системи.
    4. Заплановані зміни.
    5. Репутацію постачальника.

Не встановлюй невідомі пакети лише тому, що вони мають розширення `.deb`.

---

# dpkg -i

`dpkg -i` встановлює локальний Debian-пакет.

Синтаксис:

    sudo dpkg -i package.deb

Цей спосіб безпосередньо передає файл пакета інструменту `dpkg`.

На відміну від APT, `dpkg` не виконує повне автоматичне розв'язання залежностей через репозиторії.

Якщо залежностей бракує, пакет може залишитися в некоректному або незавершеному стані.

У такому разі APT іноді може допомогти встановити відсутні залежності:

    sudo apt --fix-broken install

Перед підтвердженням перевір запропоновані зміни.

Для звичайного встановлення локальних `.deb`-пакетів часто зручніше починати з:

    sudo apt install ./package.deb

---

# dpkg -r та dpkg -P

Інструмент `dpkg` також дозволяє видаляти встановлені пакети.

## Видалення пакета

    sudo dpkg -r package-name

Команда видаляє пакет, але зазвичай залишає його конфігураційні файли.

## Видалення пакета з конфігурацією

    sudo dpkg -P package-name

Команда видаляє пакет разом із конфігураційними файлами, які контролює `dpkg`.

Порівняння:

    dpkg -r
        → remove

    dpkg -P
        → purge

На відміну від APT, `dpkg` не керує автоматичним видаленням непотрібних залежностей так, як це робить APT.

Тому для звичайної роботи в Ubuntu частіше використовують:

    sudo apt remove package-name

    sudo apt purge package-name

---

# apt --fix-broken install

Іноді встановлення пакета переривається або в системі виникають незадоволені залежності.

Для спроби виправити такі проблеми APT підтримує:

    sudo apt --fix-broken install

Короткий варіант:

    sudo apt -f install

APT аналізує стан залежностей і намагається визначити, які зміни потрібні для відновлення узгодженого стану пакетів.

Залежно від ситуації він може запропонувати встановити додаткові пакети або видалити конфліктні.

**Не підтверджуй операцію автоматично.** Спочатку перевір список змін, особливо якщо пропонується видалення важливих системних пакетів.

Ця команда не гарантує виправлення будь-якої проблеми з програмним забезпеченням.

---

# Package Status

Після встановлення або видалення пакет може перебувати в різному стані.

Для перевірки стану:

    dpkg -l package-name

Або:

    dpkg -s package-name

У виводі `dpkg -l` використовуються спеціальні позначки стану.

Приклад установленого пакета:

    ii  git  ...  amd64  fast, scalable, distributed revision control system

Точні версія та опис залежать від системи.

Найважливіше для початку:

    ii
        → пакет установлений

Інші стани можуть указувати на те, що пакет очікує на встановлення або видалення, перебуває в неповному стані чи має проблеми з налаштуванням.

Не роби висновків лише за назвою пакета: перевіряй фактичний стан і повідомлення пакетного менеджера.

---

# Перегляд файлів установленого пакета

Команда:

    dpkg -L package-name

показує файли, які пакетний менеджер обліковує як файли встановленого пакета.

Приклад:

    dpkg -L git

У результаті можуть бути показані:

    /usr/bin/git
    /usr/share/doc/git
    /usr/share/man/man1/git.1.gz

Наведені шляхи є прикладами; фактичний список залежить від пакета.

Ця команда корисна, коли потрібно з'ясувати, де розташовані виконувані файли, документація та інші компоненти програми.

Вона не обов'язково показує всі файли, які програма створила під час роботи.

---

# Визначення власника файлу

Команда:

    dpkg -S /path/to/file

дозволяє знайти пакет, якому належить файл.

Наприклад:

    dpkg -S /usr/bin/git

Якщо файл зареєстрований у базі `dpkg`, команда покаже відповідний пакет.

Це корисно, коли потрібно:

    identify which package provides a file
    find the package responsible for a command
    investigate installed system components
    determine which package should be reinstalled

Якщо файл створений вручну або програмою під час роботи, він може не належати жодному пакету.

---

# Очищення кешу пакетів

APT зберігає завантажені пакетні архіви в:

    /var/cache/apt/archives/

Для очищення кешу:

    sudo apt clean

Для видалення застарілих пакетних архівів:

    sudo apt autoclean

Ці команди звільняють місце на диску, але не видаляють установлені програми.

Порівняння:

    apt clean
        → видаляє завантажені пакетні архіви з кешу

    apt autoclean
        → видаляє застарілі пакетні архіви з кешу

Очищення кешу не є обов'язковим після кожного встановлення.

---

# Безпечне видалення пакетів

Перед видаленням пакета корисно виконати декілька перевірок.

## Крок 1 — перевірити встановлення

    dpkg -s package-name

## Крок 2 — переглянути залежності

    apt depends package-name

## Крок 3 — змоделювати видалення

    sudo apt remove --simulate package-name

## Крок 4 — перевірити список змін

Зверни увагу на:

    packages to be removed
    packages to be upgraded
    packages to be installed
    important system components

## Крок 5 — виконати видалення, якщо план зрозумілий

    sudo apt remove package-name

## Крок 6 — за потреби очистити непотрібні залежності

    sudo apt autoremove

Перед `autoremove` також перевір список пакетів, які буде видалено.

Особливо обережно потрібно працювати із системними бібліотеками, мережевими компонентами, графічним середовищем та пакетами, потрібними для завантаження системи.

# Практичний сценарій: встановити та видалити tree

Цей сценарій дозволяє безпечно потренуватися на невеликій консольній утиліті.

## Крок 1 — перевірити, чи встановлений пакет

    dpkg -s tree

Якщо пакет не встановлений, команда повідомить про це.

## Крок 2 — встановити пакет

    sudo apt install tree

## Крок 3 — перевірити встановлення

    tree --version

## Крок 4 — використати програму

    tree

## Крок 5 — змоделювати видалення

    sudo apt remove --simulate tree

## Крок 6 — видалити пакет

    sudo apt remove tree

## Крок 7 — перевірити результат

    dpkg -s tree

Після видалення пакет більше не повинен бути в стані `install ok installed`.

## Крок 8 — за потреби перевірити непотрібні залежності

    sudo apt autoremove --simulate

Якщо APT пропонує видалити непотрібні залежності, перевір список перед виконанням справжнього `autoremove`.

---

# Практичний сценарій: встановити кілька інструментів розробника

Для роботи в Linux розробнику часто потрібні базові інструменти.

Наприклад:

    sudo apt install git curl wget tree

Перед підтвердженням переглянь список пакетів.

Після встановлення перевір:

    git --version

    curl --version

    wget --version

    tree --version

Кожна команда повинна показати інформацію про встановлену програму.

Це приклад встановлення кількох незалежних інструментів однією командою.

Не потрібно встановлювати весь набір повторно, якщо потрібні пакети вже є в системі.

---

# Практичний сценарій: перевстановлення пакета

Припустімо, потрібно повторно встановити пакет `curl`.

Спочатку перевір його стан:

    dpkg -s curl

Потім перевстанови:

    sudo apt reinstall curl

Перевір результат:

    curl --version

Якщо проблема пов'язана не з файлами пакета, а з конфігурацією, мережею або зовнішніми сервісами, перевстановлення може не допомогти.

---

# Практичний сценарій: встановлення локального .deb

Припустімо, файл розташований у каталозі `Downloads`.

Перевір наявність файлу:

    ls -lh ~/Downloads/

Перейди до каталогу:

    cd ~/Downloads

Переглянь потрібний файл:

    ls -lh package.deb

Назва `package.deb` умовна.

За потреби перевір архітектуру системи:

    dpkg --print-architecture

Для перегляду вмісту архіву:

    dpkg-deb -c package.deb

Якщо джерело файлу перевірене та пакет сумісний із системою, встанови його:

    sudo apt install ./package.deb

Після встановлення перевір пакет через `dpkg -s` або відповідну команду програми.

---

# Типові помилки

❌ **Встановлювати пакет без перевірки плану операції.**

    sudo apt install package-name

Перед підтвердженням переглядай залежності, додаткові пакети та можливі видалення.

---

❌ **Плутати `remove` та `purge`.**

    sudo apt remove package-name

Зазвичай залишає системні конфігураційні файли.

    sudo apt purge package-name

Видаляє пакет разом із системною конфігурацією, якою керує пакетний менеджер.

---

❌ **Вважати, що `purge` видаляє абсолютно всі дані програми.**

Користувацькі файли та дані програми можуть зберігатися окремо.

---

❌ **Вважати, що `autoremove` видаляє всі непотрібні файли системи.**

`autoremove` призначений для автоматично встановлених пакетів, які більше не потрібні за обліком APT. Це не універсальний засіб очищення диска.

---

❌ **Встановлювати `.deb` через `dpkg -i` і не перевіряти залежності.**

    sudo dpkg -i package.deb

Якщо залежностей бракує, встановлення може потребувати додаткових дій.

---

❌ **Вважати, що перевстановлення видалить усі проблеми програми.**

    sudo apt reinstall package-name

Перевстановлення відновлює файли пакета, але не обов'язково виправляє проблеми конфігурації, користувацьких даних або зовнішніх залежностей.

---

❌ **Видаляти невідомі пакети через їхню назву.**

Спочатку перевір інформацію:

    apt show package-name

    apt depends package-name

    sudo apt remove --simulate package-name

---

❌ **Автоматично підтверджувати `autoremove`.**

    sudo apt autoremove

Перед підтвердженням перевір список пакетів, особливо якщо серед них є системні компоненти.

---

❌ **Вважати, що успішне встановлення гарантує працездатність програми.**

Пакет може бути встановлений, але сама програма може мати проблеми з конфігурацією, правами доступу або зовнішніми сервісами.

---

❌ **Використовувати `sudo` без необхідності.**

Перегляд інформації про пакет зазвичай не потребує прав адміністратора.

# Головне

• Для встановлення програм в Ubuntu зазвичай використовують APT.

• `apt install` встановлює пакет і розв'язує залежності через налаштовані джерела.

• Перед підтвердженням операції перевіряй список пакетів, які будуть установлені або видалені.

• `apt remove` видаляє пакет, зазвичай залишаючи системні конфігураційні файли.

• `apt purge` видаляє пакет разом із системними конфігураційними файлами, якими керує пакетний менеджер.

• Користувацькі дані можуть залишатися навіть після `purge`.

• `apt reinstall` повторно встановлює пакет, але не гарантує виправлення всіх проблем програми.

• `apt autoremove` очищає непотрібні автоматично встановлені залежності.

• `apt install --simulate` та `apt remove --simulate` дозволяють попередньо перевірити план операції.

• Для встановлення локального `.deb` часто зручно використовувати:

    sudo apt install ./package.deb

• `dpkg -i` встановлює локальний пакет, але не розв'язує автоматично всі залежності через репозиторії.

• `dpkg -s` дозволяє перевірити стан пакета.

• `dpkg -L` показує файли, які належать пакету.

• `dpkg -S` допомагає визначити пакет, якому належить файл.

• `sudo apt --fix-broken install` може допомогти відновити узгоджений стан залежностей.

• Не видаляй системні пакети, не перевіривши наслідки.

• Основний принцип роботи:

    Install
        → встановити пакет

    Remove
        → видалити пакет

    Purge
        → видалити пакет і системну конфігурацію

    Autoremove
        → прибрати непотрібні автоматичні залежності

    Verify
        → перевірити результат

• Для початку достатньо впевнено користуватися командами:

    sudo apt install
    sudo apt remove
    sudo apt purge
    sudo apt reinstall
    sudo apt autoremove
    sudo apt install --simulate
    dpkg -s
    dpkg -l
    dpkg -L
    dpkg -S
