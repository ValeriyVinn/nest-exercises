# 03. Update and Upgrade

Оновлення та модернізація пакетів у Linux — це процес отримання актуальної інформації про пакети з репозиторіїв, встановлення нових версій програм, оновлення системних компонентів і виправлення помилок безпеки.

В Ubuntu для керування пакетами використовується APT (Advanced Package Tool). Він працює з репозиторіями, перевіряє залежності та допомагає безпечно оновлювати встановлене програмне забезпечення.

## 1. Що потрібно знати

✔ `apt update` — оновлює локальний список доступних пакетів і версій.

✔ `apt upgrade` — встановлює доступні оновлення вже встановлених пакетів.

✔ `apt full-upgrade` — виконує повніше оновлення, за потреби встановлюючи або видаляючи пакети для розв'язання залежностей.

✔ `apt list --upgradable` — показує пакети, для яких доступні оновлення.

✔ `apt-cache policy package` — показує встановлену версію, доступного кандидата та джерела пакета.

✔ `sudo apt update` не оновлює самі програми — воно лише оновлює інформацію про пакети.

✔ Перед оновленням потрібно перевіряти, які пакети буде змінено або видалено.

✔ Регулярні оновлення допомагають отримувати виправлення безпеки та помилок.

## 2. Як працює оновлення пакетів

APT використовує інформацію з налаштованих репозиторіїв — серверів, на яких зберігаються пакети та їхні метадані.

Типовий процес оновлення:

    1. apt update
       Завантаження актуальних списків пакетів.

    2. apt list --upgradable
       Перевірка доступних оновлень.

    3. apt upgrade
       Встановлення оновлених версій пакетів.

    4. Перевірка результату
       Переконатися, що система працює належним чином.

Наприклад:

    sudo apt update
    apt list --upgradable
    sudo apt upgrade

**Важливо:** `apt update` та `apt upgrade` виконують різні завдання. Зазвичай перед встановленням оновлень потрібно спочатку оновити списки пакетів.

## 3. Команда `apt update`

Команда завантажує актуальну інформацію про доступні пакети з налаштованих репозиторіїв.

    sudo apt update

Що відбувається:

- APT звертається до репозиторіїв.
- Завантажує оновлені списки пакетів.
- Оновлює інформацію про доступні версії.
- Повідомляє про помилки, якщо певні джерела недоступні.

Приклад фрагмента виводу:

    Hit:1 http://archive.ubuntu.com/ubuntu ...
    Get:2 http://security.ubuntu.com/ubuntu ...
    Reading package lists... Done
    Building dependency tree... Done
    All packages are up to date.

Точний вивід залежить від системи, репозиторіїв і наявності оновлень.

### Що важливо пам'ятати

Команда:

    sudo apt update

**не встановлює оновлені версії програм.** Вона лише оновлює локальні списки доступних пакетів.

Наприклад, якщо у списку раніше була доступна версія `1.0`, а репозиторій тепер пропонує `1.1`, після `apt update` APT знатиме про нову версію. Щоб її встановити, потрібно виконати команду оновлення.

## 4. Перегляд доступних оновлень

Перед встановленням оновлень корисно перевірити, які пакети можна оновити.

    apt list --upgradable

Приклад виводу:

    Listing...
    curl/noble-updates 8.x amd64 [upgradable from: 8.y]
    package-example/noble-updates 2.0 amd64 [upgradable from: 1.9]

Це умовний приклад: назви, версії та позначення репозиторіїв залежать від системи.

Команда показує пакети, для яких доступні новіші версії порівняно з установленими.

### Перевірка конкретного пакета

    apt-cache policy curl

Команда показує інформацію про версії пакета, зокрема:

- установлену версію;
- версію-кандидата для встановлення;
- репозиторії, з яких доступні версії.

Приклад умовного виводу:

    curl:
      Installed: 8.5.0
      Candidate: 8.5.1
      Version table:
         8.5.1 500
            500 http://archive.ubuntu.com/ubuntu ...
     *** 8.5.0 100
            100 /var/lib/dpkg/status

Якщо `Installed` і `Candidate` відрізняються, доступна інша версія пакета. Однак це не означає, що її обов'язково потрібно встановлювати негайно: варто врахувати залежності та заплановані зміни.

## 5. Команда `apt upgrade`

Команда оновлює встановлені пакети до доступних новіших версій, не видаляючи встановлені пакети для розв'язання залежностей.

    sudo apt upgrade

Перед виконанням APT зазвичай показує:

- які пакети будуть оновлені;
- скільки пакетів буде встановлено або залишено без оновлення;
- скільки даних потрібно завантажити;
- скільки додаткового місця може знадобитися.

Приклад умовного повідомлення:

    The following packages will be upgraded:
      curl package-example

    Do you want to continue? [Y/n]

Щоб продовжити, введи `Y` або натисни `Enter`, якщо це відповідає запропонованому значенню за замовчуванням.

Якщо список змін незрозумілий, можна відповісти `n` і спочатку розібратися, що саме буде змінено.

### Чому деякі пакети можуть залишитися без оновлення

Звичайний `apt upgrade` не видаляє встановлені пакети, щоб задовольнити певні зміни залежностей.

Якщо оновлення потребує видалення чи заміни інших пакетів, APT може залишити такий пакет без оновлення.

Це не обов'язково означає помилку.

## 6. Команда `apt full-upgrade`

`full-upgrade` дозволяє APT змінювати склад установлених пакетів, якщо це потрібно для оновлення системи. Зокрема, команда може встановлювати додаткові пакети або видаляти наявні для розв'язання залежностей.

    sudo apt full-upgrade

Відмінність від звичайного оновлення:

    sudo apt upgrade
    # Оновлення без видалення встановлених пакетів
    # для розв'язання залежностей.

    sudo apt full-upgrade
    # Оновлення з можливістю встановлення
    # або видалення пакетів за потреби.

**Увага:** перед підтвердженням `full-upgrade` обов'язково перевіряй список пакетів, які APT пропонує видалити або встановити.

Якщо команда пропонує видалити важливі компоненти робочого середовища, мережі чи системи, не підтверджуй операцію, доки не з'ясуєш причину.

Для звичайного обслуговування Ubuntu часто достатньо `apt upgrade`. `full-upgrade` використовують тоді, коли потрібно розв'язати складніші зміни залежностей.

## 7. Рекомендована послідовність оновлення Ubuntu

Для звичайного оновлення пакетів використовуй такий порядок.

### Крок 1. Оновити списки пакетів

    sudo apt update

### Крок 2. Переглянути доступні оновлення

    apt list --upgradable

### Крок 3. Переглянути та встановити оновлення

    sudo apt upgrade

Перед підтвердженням прочитай список змін.

### Крок 4. Перевірити, чи залишилися оновлення

    apt list --upgradable

Якщо залишилися пакети без оновлення, перевір їхні версії та причини, через які APT їх пропускає.

### Крок 5. Перевірити помилки

Якщо під час оновлення з'явилися помилки, не запускай багато команд навмання. Спочатку прочитай повідомлення APT і визнач, чи пов'язана проблема з мережею, репозиторіями, залежностями або нестачею місця.

**Практичний приклад:**

    sudo apt update
    apt list --upgradable
    sudo apt upgrade

Цього достатньо для типового оновлення встановлених APT-пакетів.

## 8. Автоматичне підтвердження `-y`

Параметр `-y` автоматично відповідає «так» на запити підтвердження APT.

    sudo apt upgrade -y

Аналогічно:

    sudo apt install curl -y

Це зручно для сценаріїв автоматизації, але під час навчання краще спочатку використовувати команди без `-y`.

Так ти зможеш побачити список пакетів, які будуть оновлені, встановлені або видалені.

**Правило:** не використовуй `-y` бездумно з командами, що можуть змінити багато пакетів або видалити системні компоненти.

## 9. Команда `apt-get upgrade` та відмінність від `apt`

Для повсякденної роботи в терміналі Ubuntu можна використовувати `apt`:

    sudo apt update
    sudo apt upgrade

Також існує `apt-get`:

    sudo apt-get update
    sudo apt-get upgrade

Обидва інструменти працюють із системою пакетів APT, але мають деякі відмінності в інтерфейсі та призначенні.

- `apt` зручний для інтерактивної роботи користувача.
- `apt-get` традиційно часто використовують у скриптах і документації.
- Не варто вважати їх двома незалежними системами керування пакетами.

Для початкового вивчення Ubuntu достатньо добре знати `apt`.

## 10. Що робити, якщо оновлення не працює

### 10.1. Помилка мережі або недоступний сервер

Приклад повідомлення:

    Failed to fetch ...
    Could not connect to ...
    Temporary failure resolving ...

Можливі причини:

- немає підключення до інтернету;
- тимчасово недоступний сервер;
- помилка DNS;
- проксі або мережеві налаштування блокують з'єднання.

Що перевірити:

    ping -c 3 1.1.1.1

Ця команда перевіряє доступність IP-адреси, якщо мережа дозволяє ICMP-запити.

Для перевірки DNS:

    getent hosts archive.ubuntu.com

Якщо IP-адреса доступна, але ім'я сервера не розпізнається, можлива проблема з DNS.

Водночас відсутність відповіді на `ping` сама по собі не доводить, що інтернет не працює: ICMP-запити можуть блокуватися.

### 10.2. Пакет не знайдено

Приклад:

    E: Unable to locate package package-name

Можливі причини:

- помилка в назві пакета;
- локальні списки пакетів застаріли;
- пакет відсутній у підключених репозиторіях;
- пакет доступний через іншу систему встановлення, наприклад Snap або Flatpak.

Що спробувати:

    sudo apt update
    apt search package-name

Пошук:

    apt search curl

Перевіряй точну назву пакета перед встановленням.

### 10.3. Помилки залежностей

Іноді APT повідомляє про незадоволені залежності або незавершене встановлення.

Спочатку прочитай повідомлення про помилку та список пакетів, яких вона стосується.

Для діагностики можна перевірити:

    sudo apt check

Команда перевіряє залежності встановлених пакетів.

Якщо є пошкоджений або незавершений стан керування пакетами, іноді допомагає:

    sudo apt --fix-broken install

Ця команда намагається виправити проблеми залежностей. Вона може запропонувати встановити або видалити пакети, тому уважно перевіряй план операції перед підтвердженням.

Не запускай її автоматично при будь-якій помилці — спочатку з'ясуй причину.

### 10.4. Недостатньо місця на диску

Приклад повідомлення:

    No space left on device

Перевір вільне місце:

    df -h

Перевір розмір каталогів:

    du -sh /var/cache/apt/archives

APT зберігає завантажені архіви пакетів у кеші. Якщо потрібно звільнити місце, можна очистити цей кеш:

    sudo apt clean

Це видаляє завантажені архіви пакетів із кешу, але не видаляє встановлені програми.

Перед очищенням переконайся, що проблема справді пов'язана з місцем на диску.

## 11. Очищення після оновлення

Після встановлення оновлень можуть залишатися непотрібні залежності або кеш завантажених пакетів.

### `apt autoremove`

Видаляє пакети, які були автоматично встановлені як залежності та більше не потрібні іншим установленим пакетам.

    sudo apt autoremove

Перед підтвердженням переглянь список. Якщо серед пакетів є компоненти, призначення яких незрозуміле, не підтверджуй видалення, доки не перевіриш його.

### `apt clean`

Видаляє завантажені архіви пакетів із кешу APT.

    sudo apt clean

Встановлені програми залишаються на місці.

### `apt autoclean`

Видаляє з кешу архіви пакетів, які вже не можна завантажити з налаштованих репозиторіїв.

    sudo apt autoclean

### Порівняння

    sudo apt autoremove
    # Видаляє непотрібні автоматично встановлені пакети.

    sudo apt clean
    # Очищає кеш завантажених архівів пакетів.

    sudo apt autoclean
    # Очищає застарілі архіви пакетів у кеші.

Ці команди виконують різні завдання.

## 12. Оновлення ядра Linux

Ядро Linux — основний компонент операційної системи, який взаємодіє з обладнанням і керує системними ресурсами.

В Ubuntu оновлення ядра зазвичай надходять через системні пакети та встановлюються разом з іншими оновленнями, якщо вони доступні для поточної версії системи.

Перевірити версію запущеного ядра:

    uname -r

Приклад виводу:

    6.x.x-generic

Це лише приклад формату версії.

Перевірити пакети, пов'язані з ядром:

    dpkg -l 'linux-image*'

Після встановлення нового ядра для переходу на нього зазвичай потрібне перезавантаження.

    sudo reboot

**Важливо:** після оновлення ядра система не обов'язково одразу починає працювати на новій версії. Команда `uname -r` показує ядро, яке запущене зараз. Після перезавантаження перевір його ще раз.

Не видаляй вручну поточне або попереднє робоче ядро, не розуміючи наслідків. Попереднє ядро може бути корисним для відновлення системи.

## 13. Оновлення пакетів і оновлення версії Ubuntu — не одне й те саме

Це важлива відмінність.

### Оновлення пакетів

    sudo apt update
    sudo apt upgrade

Оновлює списки пакетів і встановлене програмне забезпечення в межах налаштованих репозиторіїв поточного випуску Ubuntu.

### Оновлення дистрибутива до нового випуску

Перехід, наприклад, з однієї версії Ubuntu на наступну — це окрема процедура.

Для Ubuntu існує спеціальний інструмент:

    do-release-upgrade

Не запускай його просто як частину звичайного оновлення пакетів. Перед переходом на новий випуск потрібно перевірити підтримуваний шлях оновлення, сумісність програм, резервні копії та вільне місце.

**Запам'ятай:**

- `apt upgrade` — оновлення встановлених пакетів.
- `apt full-upgrade` — оновлення з можливістю зміни складу пакетів для розв'язання залежностей.
- `do-release-upgrade` — інструмент для переходу на новий випуск Ubuntu.

## 14. Автоматичні оновлення безпеки

Ubuntu може встановлювати певні оновлення безпеки автоматично. Для цього використовуються механізми автоматичного оновлення, зокрема пакет `unattended-upgrades`.

Перевірити, чи встановлений пакет:

    dpkg -s unattended-upgrades

Перевірити стан відповідної служби:

    systemctl status unattended-upgrades

На різних конфігураціях системи служба може працювати або бути відсутньою. Сам факт встановлення пакета не гарантує, що автоматичне оновлення налаштоване саме так, як потрібно.

Щоб переглянути параметри автоматичних оновлень, можна вивчити конфігурацію:

    /etc/apt/apt.conf.d/

Наприклад, у цій директорії може бути файл:

    /etc/apt/apt.conf.d/20auto-upgrades

Не змінюй системну конфігурацію автоматичних оновлень без потреби. Спочатку з'ясуй, які налаштування вже використовуються.

## 15. Перегляд журналів APT

Якщо потрібно з'ясувати, які пакети встановлювалися або оновлювалися, можна переглянути журнали.

Історія операцій APT:

    less /var/log/apt/history.log

Журнал дій APT:

    less /var/log/apt/term.log

Журнал операцій низькорівневого менеджера пакетів `dpkg`:

    less /var/log/dpkg.log

Для пошуку конкретної назви пакета:

    grep 'curl' /var/log/dpkg.log

Ці журнали допомагають з'ясувати:

- коли виконувалися операції;
- які пакети встановлювалися або оновлювалися;
- чи були помилки під час виконання операцій.

Старі журнали можуть бути стиснуті або перенесені в архіви, тому поточний файл не обов'язково містить усю історію.

## 16. Безпека під час оновлення

Під час оновлення системи важливо дотримуватися кількох правил.

✔ Використовуй офіційні або перевірені репозиторії.

✔ Читай список пакетів, які APT планує встановити, оновити чи видалити.

✔ Не запускай команди з `sudo`, якщо не розумієш їхнього призначення.

✔ Не вимикай перевірки підписів пакетів заради встановлення оновлення.

✔ Не використовуй параметри на кшталт `--force-*` без чіткого розуміння наслідків.

✔ Для важливих даних роби резервні копії перед масштабними системними змінами.

✔ Після значних оновлень перевір працездатність системи.

Оновлення — важлива частина безпеки Linux, але необережні операції з пакетами також можуть призвести до проблем.

## 17. Типові помилки початківців

### Помилка 1. Очікувати, що `apt update` оновить програми

Неправильно:

    sudo apt update
    # Очікувати, що всі програми вже оновлено.

Правильно:

    sudo apt update
    sudo apt upgrade

Перша команда оновлює списки пакетів, друга встановлює доступні оновлення.

### Помилка 2. Виконувати `full-upgrade`, не читаючи список змін

Небезпечно:

    sudo apt full-upgrade -y

Чому це проблема: APT може запропонувати видалення пакетів для розв'язання залежностей, а `-y` прибирає звичайний запит підтвердження.

Краще спочатку виконати:

    sudo apt full-upgrade

Переглянути запропоновані зміни та підтверджувати їх лише тоді, коли вони зрозумілі.

### Помилка 3. Вважати, що будь-який пакет оновиться командою `apt upgrade`

Пакет може залишитися без оновлення через зміни залежностей, утримання версії або особливості репозиторіїв.

Перевір:

    apt list --upgradable
    apt-cache policy package-name

За потреби розберися, чому версія-кандидат не встановлюється.

### Помилка 4. Плутати оновлення пакетів із переходом на нову Ubuntu

Звичайне оновлення пакетів не означає автоматичний перехід на наступний випуск дистрибутива.

Для переходу на новий випуск існує окрема процедура.

### Помилка 5. Видаляти кеш, думаючи, що видаляються програми

Команда:

    sudo apt clean

не видаляє встановлені програми. Вона видаляє завантажені архіви пакетів із кешу APT.

### Помилка 6. Ігнорувати повідомлення про помилки

Якщо `apt update` повідомляє про недоступний репозиторій, не слід відразу вимикати перевірки безпеки або видаляти конфігураційні файли.

Спочатку перевір мережу, адресу репозиторію, ключі підпису та відповідність репозиторію версії Ubuntu.

## 18. Практика в терміналі

Виконай вправи по черзі. Не потрібно виконувати всі команди автоматично — читай результати кожного кроку.

### Вправа 1. Оновлення списків пакетів

    sudo apt update

Завдання:

- Знайди рядки, які повідомляють про завантаження даних.
- Зверни увагу на помилки, якщо вони є.
- Поясни своїми словами, що змінилося після команди.

### Вправа 2. Перегляд доступних оновлень

    apt list --upgradable

Завдання:

- Перевір, чи є пакети з доступними оновленнями.
- Вибери один пакет.
- Подивись його версії:

    apt-cache policy package-name

Заміни `package-name` реальною назвою пакета.

### Вправа 3. Перевірка стану пакета

    dpkg -s curl

Завдання:

- Знайди поле `Status`.
- Знайди встановлену версію.
- Поясни, чим ця інформація відрізняється від `apt-cache policy curl`.

Якщо `curl` не встановлений, спочатку перевір це за допомогою `command -v curl` або встанови пакет, якщо він потрібен для вправи.

### Вправа 4. Оновлення пакетів

    sudo apt upgrade

Завдання:

- Прочитай список пакетів.
- Зверни увагу на обсяг завантаження.
- Перед підтвердженням перевір, чи зрозумілі тобі всі запропоновані зміни.

### Вправа 5. Перевірка після оновлення

    apt list --upgradable
    sudo apt check

Завдання:

- Перевір, чи залишилися доступні оновлення.
- Перевір стан залежностей пакетів.
- Якщо є помилки, запиши їхній точний текст і досліди причину.

### Вправа 6. Перегляд журналу

    less /var/log/apt/history.log

Завдання:

- Знайди останні операції.
- Зверни увагу на назви пакетів і дати.
- Навчись виходити з `less` клавішею `q`.

## 19. Мінішпаргалка

    # Оновити списки пакетів
    sudo apt update

    # Переглянути доступні оновлення
    apt list --upgradable

    # Оновити встановлені пакети
    sudo apt upgrade

    # Повніше оновлення з можливістю зміни складу пакетів
    sudo apt full-upgrade

    # Перевірити версії та джерела пакета
    apt-cache policy package-name

    # Перевірити стан пакета
    dpkg -s package-name

    # Перевірити залежності
    sudo apt check

    # Спробувати виправити проблеми залежностей
    sudo apt --fix-broken install

    # Видалити непотрібні автоматично встановлені залежності
    sudo apt autoremove

    # Очистити кеш архівів пакетів
    sudo apt clean

    # Переглянути журнал операцій APT
    less /var/log/apt/history.log

    # Переглянути версію запущеного ядра
    uname -r

## 20. Що потрібно пам'ятати

- `apt update` оновлює списки пакетів, а не самі програми.
- `apt upgrade` встановлює доступні оновлення без видалення встановлених пакетів для розв'язання залежностей.
- `apt full-upgrade` може встановлювати й видаляти пакети, тому список змін потрібно перевіряти особливо уважно.
- `apt list --upgradable` показує пакети, для яких доступні оновлення.
- `apt-cache policy package-name` допомагає перевірити версії пакета та джерела.
- `apt clean` очищає кеш завантажених архівів, але не видаляє встановлені програми.
- `apt autoremove` видаляє автоматично встановлені залежності, які більше не потрібні.
- `uname -r` показує версію ядра, що працює зараз.
- Оновлення пакетів і перехід на новий випуск Ubuntu — різні операції.
- Перед підтвердженням системних змін потрібно читати список пакетів, які буде встановлено або видалено.

## 22. Рівні засвоєння теми

### Core — базовий рівень

- Розуміти, що таке пакети та репозиторії.
- Знати різницю між `apt update` і `apt upgrade`.
- Уміти переглядати доступні оновлення.
- Уміти безпечно запускати звичайне оновлення пакетів.
- Розуміти призначення `apt clean` і `apt autoremove`.

### Junior — практичний рівень

- Перевіряти доступну та встановлену версії пакета.
- Розуміти, чому деякі пакети можуть залишатися без оновлення.
- Читати повідомлення APT про залежності та помилки.
- Перевіряти журнали операцій.
- Відрізняти оновлення пакетів від переходу на новий випуск Ubuntu.

### Middle — поглиблений рівень

- Розуміти, як залежності впливають на план оновлення.
- Аналізувати джерела пакетів і версії-кандидати.
- Досліджувати проблеми з репозиторіями та залежностями.
- Розуміти механізм автоматичних оновлень безпеки.
- Оцінювати ризики системних змін перед їх підтвердженням.

### Senior — системне розуміння

- Аналізувати наслідки масштабного оновлення системи.
- Планувати оновлення з урахуванням резервних копій і відновлення.
- Розуміти взаємодію APT, `dpkg`, репозиторіїв і системних залежностей.
- Діагностувати проблеми оновлення за журналами та станом пакетів.
- Розрізняти оновлення програм, оновлення ядра та перехід на новий випуск дистрибутива.

---

**Головна думка:** спочатку онови списки пакетів (`apt update`), потім переглянь доступні зміни (`apt list --upgradable`) і лише після цього встановлюй оновлення (`apt upgrade`). Під час будь-яких системних операцій уважно читай повідомлення APT і не підтверджуй незрозуміле видалення пакетів.
