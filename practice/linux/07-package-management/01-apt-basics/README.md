# 01. APT Basics

APT (Advanced Package Tool) — це набір інструментів Linux для керування програмними пакетами в Debian-based дистрибутивах, зокрема Ubuntu.

APT дозволяє знаходити, встановлювати, оновлювати та видаляти програми, а також автоматично керувати залежностями між пакетами.

У Ubuntu APT використовується для встановлення системних утиліт, інструментів розробника, бібліотек та іншого програмного забезпечення.

APT працює з репозиторіями — джерелами, з яких система отримує інформацію про доступні пакети та завантажує їх.

Основні інструменти пакетного менеджменту:

    apt
    apt-get
    apt-cache
    dpkg

Для повсякденної роботи в Ubuntu зазвичай достатньо почати з `apt`.

### Що потрібно пам'ятати

• APT — інструмент керування пакетами в Ubuntu та інших Debian-based дистрибутивах.

• Пакет — це підготовлений для встановлення набір програмних файлів, метаданих та інструкцій.

• Репозиторій — джерело програмних пакетів і інформації про них.

• APT автоматично розв'язує залежності, необхідні для встановлення програм.

• `apt update` оновлює локальний індекс пакетів, але не встановлює оновлення програм.

• `apt upgrade` встановлює доступні оновлення вже встановлених пакетів.

• `apt install` встановлює пакет.

• `apt remove` видаляє пакет, зазвичай залишаючи його системні конфігураційні файли.

• `apt purge` видаляє пакет разом із системними конфігураційними файлами, які належать цьому пакету.

• `apt search` шукає пакети за назвою та описом.

• `apt show` показує інформацію про пакет.

• Для більшості операцій, які змінюють системні пакети, потрібні права адміністратора через `sudo`.

• APT та `dpkg` — не одне й те саме: APT керує пакетами та залежностями, а `dpkg` працює безпосередньо з Debian-пакетами.

• Перед встановленням або видаленням пакетів варто перевіряти, які саме зміни пропонує система.

# Package Management

Package management (керування пакетами) — це процес встановлення, оновлення, налаштування та видалення програмного забезпечення в операційній системі.

Замість ручного завантаження кожної програми, пошуку її бібліотек і копіювання файлів користувач може скористатися пакетним менеджером.

Наприклад, в Ubuntu можна встановити Git однією командою:

    sudo apt install git

APT знайде пакет у доступних джерелах, перевірить залежності та запропонує встановлення.

Після підтвердження система завантажить необхідні пакети та встановить їх.

---

# Package

Package (пакет) — це одиниця розповсюдження програмного забезпечення, підготовлена для встановлення пакетним менеджером.

Пакет може містити:

    executable files
    libraries
    configuration files
    documentation
    package metadata
    installation scripts

Наприклад, пакет Git містить програму Git та інші необхідні файли.

Переглянути інформацію про встановлений Git:

    git --version

Приклад результату:

    git version 2.x.x

Точна версія залежить від встановленого пакета.

Важливо розрізняти:

    package → пакет, яким керує пакетний менеджер
    program  → програма, якою користується людина
    process  → запущений екземпляр програми

Встановлення пакета не обов'язково означає, що програма автоматично запускається.

---

# Package Manager

Package manager — це інструмент, який керує програмними пакетами.

У Linux існують різні пакетні менеджери залежно від дистрибутива.

Приклади:

    APT      → Debian, Ubuntu
    DNF      → Fedora та інші RPM-based системи
    Zypper   → openSUSE
    Pacman   → Arch Linux

У цьому розділі ми вивчаємо APT, оскільки він використовується в Ubuntu.

Для встановлення пакета в Ubuntu зазвичай використовують:

    sudo apt install package-name

Для пошуку пакета:

    apt search package-name

Для перегляду інформації:

    apt show package-name

Назва `package-name` у прикладах — умовна. Замість неї потрібно вказувати реальну назву пакета.

---

# APT

APT розшифровується як Advanced Package Tool.

Це інструмент для керування пакетами в Debian-based системах.

APT дозволяє:

    install    → встановлювати пакети
    remove     → видаляти пакети
    purge      → видаляти пакети з конфігурацією
    update     → оновлювати індекс пакетів
    upgrade    → оновлювати встановлені пакети
    search     → шукати пакети
    show       → переглядати інформацію про пакети
    autoremove → видаляти непотрібні автоматично встановлені залежності

Приклади:

    sudo apt update

    sudo apt upgrade

    sudo apt install curl

    apt search nginx

    apt show git

    sudo apt remove curl

Команди `update`, `upgrade`, `install` та `remove` виконують різні завдання. Їх не слід плутати.

Детальніше вони розглядатимуться в наступних підрозділах `07-package-management`.

---

# Як працює APT

APT використовує інформацію про репозиторії та доступні пакети, щоб визначити, що можна встановити або оновити.

Спрощена схема:

    Repositories
          ↓
    Package indexes
          ↓
    APT resolves dependencies
          ↓
    Download packages
          ↓
    Install / upgrade / remove
          ↓
    Installed system

Наприклад, коли ти встановлюєш програму, APT може визначити, що їй потрібні додаткові бібліотеки.

Замість ручного пошуку кожної бібліотеки APT автоматично опрацьовує залежності.

---

# Repository

Repository (репозиторій) — це джерело пакетів та інформації про них.

APT використовує налаштовані джерела, щоб знаходити доступні пакети.

У репозиторіях містяться:

    package files
    package versions
    package metadata
    dependency information
    package indexes

Репозиторії можуть надаватися розробниками Ubuntu, іншими постачальниками програмного забезпечення або сторонніми проєктами.

APT не шукає довільні файли на всьому інтернеті. Він працює з налаштованими джерелами пакетів.

Подивитися налаштовані джерела можна у файлах:

    /etc/apt/sources.list

    /etc/apt/sources.list.d/

У сучасних версіях Ubuntu джерела також можуть зберігатися у файлах із розширенням `.sources`, наприклад:

    /etc/apt/sources.list.d/ubuntu.sources

Фактичний набір файлів залежить від версії Ubuntu та конфігурації системи.

Переглянути каталог додаткових джерел:

    ls -la /etc/apt/sources.list.d/

Переглянути традиційний файл джерел, якщо він існує:

    cat /etc/apt/sources.list

Якщо файл відсутній, це не обов'язково означає, що APT не має налаштованих репозиторіїв.

---

# Package Index

Package index — локальний індекс із відомостями про доступні пакети.

APT використовує його, щоб знати:

    package name
    package version
    package description
    package dependencies
    package source

Індекс допомагає APT знаходити потрібні пакети без необхідності завантажувати повний архів кожного пакета під час пошуку.

Локальні індекси APT зазвичай зберігаються в:

    /var/lib/apt/lists/

Переглянути їх:

    ls -lh /var/lib/apt/lists/

Важливо: наявність індексу не гарантує, що пакет досі доступний у репозиторії або що його версія є найновішою.

Щоб оновити локальні індекси:

    sudo apt update

# apt update

Команда `apt update` завантажує актуальну інформацію про пакети з налаштованих репозиторіїв та оновлює локальні індекси.

    sudo apt update

Що відбувається:

    1. APT читає налаштовані джерела.
    2. Звертається до репозиторіїв.
    3. Завантажує доступні індекси пакетів.
    4. Оновлює локальну інформацію про пакети.

Після цього APT може враховувати новіші версії пакетів, доступні в репозиторіях.

**Важливо:** `apt update` не встановлює нові версії програм.

Для встановлення доступних оновлень використовується інша команда:

    sudo apt upgrade

Типова послідовність:

    sudo apt update
    sudo apt upgrade

Це один із найважливіших шаблонів роботи з пакетами в Ubuntu.

---

# apt upgrade

Команда `apt upgrade` встановлює доступні оновлення вже встановлених пакетів, використовуючи актуальний індекс пакетів.

    sudo apt upgrade

APT аналізує доступні оновлення та показує, які пакети планує оновити.

Зазвичай система запитує підтвердження перед виконанням змін.

Якщо потрібно спочатку лише переглянути заплановані зміни:

    sudo apt upgrade --simulate

Або:

    sudo apt -s upgrade

Параметр `-s` означає simulation — моделювання операції без фактичного встановлення оновлень.

Для звичайної роботи часто достатньо:

    sudo apt update
    sudo apt upgrade

Докладніше про оновлення буде в підрозділі:

    03-update-and-upgrade

# apt install

Команда `apt install` встановлює пакет із доступних джерел.

Синтаксис:

    sudo apt install package-name

Приклад:

    sudo apt install curl

Що відбувається:

    1. APT знаходить пакет.
    2. Перевіряє залежності.
    3. Визначає додаткові пакети, якщо вони потрібні.
    4. Показує заплановані зміни.
    5. Після підтвердження завантажує та встановлює пакети.

Можна встановити декілька пакетів одночасно:

    sudo apt install curl wget git

Перед встановленням APT показує інформацію про операцію, зокрема пакети, які будуть встановлені, та обсяг завантаження.

Не варто автоматично підтверджувати операцію, якщо її склад незрозумілий.

---

# apt remove

Команда `apt remove` видаляє встановлений пакет.

Синтаксис:

    sudo apt remove package-name

Приклад:

    sudo apt remove curl

Зазвичай вона видаляє програмні файли пакета, але залишає системні конфігураційні файли, які пакетний менеджер зберігає для можливого повторного використання.

Поведінка щодо користувацьких даних залежить від конкретної програми. Не слід вважати, що видалення пакета завжди зберігає всі дані програми.

Для видалення пакета разом із системними конфігураційними файлами використовується:

    sudo apt purge package-name

Для видалення непотрібних автоматично встановлених залежностей:

    sudo apt autoremove

Ці команди мають різне призначення.

# apt search

Команда `apt search` шукає пакети за назвою та описом.

Синтаксис:

    apt search keyword

Приклад:

    apt search editor

Ще приклади:

    apt search python3

    apt search postgresql

    apt search nginx

Результати можуть містити:

    package name
    package version
    package description

Пошук відбувається за локальною інформацією APT, тому перед пошуком корисно оновити індекси:

    sudo apt update

Детальніше пошук пакетів розглядатиметься в підрозділі:

    04-package-search

# apt show

Команда `apt show` показує відомості про пакет.

Синтаксис:

    apt show package-name

Приклад:

    apt show git

Інформація може включати:

    Package
    Version
    Architecture
    Maintainer
    Depends
    Description
    Installed-Size

Залежно від пакета та джерела можуть бути доступні й інші поля.

Наприклад:

    apt show curl

За допомогою `apt show` можна попередньо перевірити, що саме являє собою пакет.

Не плутай цю команду з:

    apt list --installed

Перша показує відомості про пакет, а друга дозволяє переглянути встановлені пакети.

---

# apt list

Команда `apt list` виводить списки пакетів.

Переглянути встановлені пакети:

    apt list --installed

Переглянути пакети, для яких доступні оновлення:

    apt list --upgradable

Переглянути відповідність назві пакета:

    apt list 'git*'

Останній приклад використовує шаблон назви. Лапки не дозволяють Bash самостійно розгорнути `*` у список файлів поточного каталогу.

Результат `apt list` може бути довгим, тому іноді зручно використовувати `less`:

    apt list --installed | less

Для пошуку конкретного пакета серед установлених можна також скористатися:

    dpkg -l git

# apt vs apt-get

`apt` та `apt-get` належать до інструментів APT, але мають різні інтерфейси та призначення.

`apt` — зручний інтерфейс для інтерактивної роботи в терміналі.

`apt-get` — традиційний інтерфейс, який часто використовують у скриптах та автоматизованих сценаріях.

Приклади:

    sudo apt update

    sudo apt-get update

Обидві команди оновлюють індекси пакетів.

Встановлення пакета:

    sudo apt install git

    sudo apt-get install git

Обидві команди можуть встановити Git.

Основні відмінності:

    apt
        → зручний інтерфейс для користувача
        → повідомлення та вивід, орієнтовані на інтерактивну роботу

    apt-get
        → традиційний інтерфейс
        → часто використовується в автоматизації та скриптах

У повсякденній роботі в Ubuntu можна починати з `apt`.

У скриптах варто враховувати сумісність, стабільність виводу та параметри конкретної команди, а не механічно замінювати один інструмент іншим.

# apt-cache

`apt-cache` дозволяє працювати з інформацією, яку APT зберігає про пакети.

Наприклад:

    apt-cache search editor

    apt-cache show git

    apt-cache policy git

`apt-cache search` шукає пакети за назвою та описом.

`apt-cache show` показує відомості про пакет.

`apt-cache policy` допомагає переглянути встановлену версію, доступні версії та пріоритети джерел пакетів.

Наприклад:

    apt-cache policy git

Результат залежить від установленої версії Git, налаштованих репозиторіїв та локальних індексів.

`apt-cache` корисний, коли потрібно дослідити доступність пакета або зрозуміти, звідки APT планує його отримати.

---

# dpkg

`dpkg` — низькорівневий інструмент для роботи з Debian-пакетами формату `.deb`.

APT працює з репозиторіями та автоматично розв'язує залежності, тоді як `dpkg` безпосередньо встановлює, видаляє та перевіряє Debian-пакети.

Переглянути встановлені пакети:

    dpkg -l

Перевірити конкретний пакет:

    dpkg -l git

Переглянути файли, встановлені пакетом:

    dpkg -L git

Перевірити, якому пакету належить конкретний файл:

    dpkg -S /usr/bin/git

Переглянути інформацію про пакет:

    dpkg -s git

Переглянути вміст локального `.deb`-файлу без встановлення:

    dpkg-deb -c package.deb

Назва `package.deb` тут умовна.

Для звичайного встановлення програм із репозиторіїв Ubuntu зазвичай краще використовувати APT.

---

# APT vs dpkg

Це важлива відмінність.

APT:

    sudo apt install git

APT знаходить пакет у налаштованих джерелах, визначає залежності та керує встановленням.

dpkg:

    sudo dpkg -i package.deb

`dpkg -i` встановлює локальний `.deb`-пакет, але самостійно не розв'язує всі залежності шляхом пошуку та завантаження відсутніх пакетів із репозиторіїв.

Якщо після встановлення локального пакета виникли незадоволені залежності, для їх виправлення можна використати:

    sudo apt --fix-broken install

Перед виконанням потрібно перевірити запропоновані зміни.

Порівняння:

    apt
        → репозиторії
        → індекси пакетів
        → автоматичне розв'язання залежностей
        → встановлення та оновлення пакетів

    dpkg
        → безпосередня робота з Debian-пакетами
        → встановлення локальних .deb-файлів
        → перевірка стану встановлених пакетів
        → перегляд файлів пакета

# .deb Package

`.deb` — формат пакетів, який використовується Debian та Ubuntu.

Приклад назви:

    example-package_1.0.0_amd64.deb

Назва може містити:

    package name
    version
    architecture
    .deb extension

Наприклад, `amd64` зазвичай позначає архітектуру x86-64, яка використовується на багатьох сучасних комп'ютерах.

Подивитися архітектуру системи:

    dpkg --print-architecture

Приклад результату:

    amd64

Для встановлення локального `.deb`-файлу через APT можна використовувати:

    sudo apt install ./package.deb

Шлях `./package.deb` вказує на файл у поточному каталозі.

APT може опрацювати залежності такого пакета через доступні репозиторії.

Альтернативний спосіб:

    sudo dpkg -i package.deb

У цьому випадку залежності можуть потребувати окремого виправлення.

Завжди перевіряй походження локального пакета. Не встановлюй невідомі `.deb`-файли лише тому, що вони мають правильне розширення.

---

# Package Dependencies

Dependency (залежність) — це інший пакет або програмний компонент, який потрібен програмі для правильної роботи.

Наприклад:

    Application
        ↓
    Library A
        ↓
    Library B

Якщо програма потребує бібліотеку, якої немає в системі, пакетний менеджер може встановити її автоматично.

APT аналізує залежності та визначає, які пакети потрібно встановити або оновити.

Переглянути залежності пакета:

    apt depends git

Переглянути інформацію про залежності:

    apt show git

У виводі `apt show` можна побачити поле:

    Depends

Залежності можуть бути складнішими за простий список: пакет може залежати від певних версій інших пакетів або використовувати альтернативні залежності.

Тому встановлення програми вручну без урахування залежностей часто складніше, ніж використання APT.

---

# Package Metadata

Metadata (метадані) — це інформація про пакет, яка описує його властивості.

Метадані можуть містити:

    package name
    version
    architecture
    maintainer
    dependencies
    description
    package size
    repository information

Переглянути метадані:

    apt show git

Приклад окремих полів:

    Package: git
    Version: ...
    Architecture: ...
    Depends: ...
    Description: ...

Це схематичний приклад. Фактичні значення залежать від версії пакета у твоїх репозиторіях.

Метадані допомагають APT визначати, які пакети доступні, які залежності необхідні та яку версію можна встановити.

# Де APT зберігає інформацію

Основні каталоги та файли:

    /etc/apt/
        → конфігурація APT

    /etc/apt/sources.list
        → традиційний список джерел пакетів, якщо використовується

    /etc/apt/sources.list.d/
        → додаткові джерела пакетів

    /var/lib/apt/lists/
        → локальні індекси пакетів

    /var/cache/apt/archives/
        → кеш завантажених пакетних архівів

    /var/lib/dpkg/
        → база даних стану та метаданих установлених пакетів

Переглянути конфігурацію APT:

    ls -la /etc/apt/

Переглянути додаткові джерела:

    ls -la /etc/apt/sources.list.d/

Переглянути кеш пакетів:

    ls -lh /var/cache/apt/archives/

Переглянути базу даних dpkg:

    ls -la /var/lib/dpkg/

Не редагуй системні файли пакетного менеджера без розуміння наслідків. Неправильна конфігурація джерел може спричинити помилки оновлення або встановлення пакетів.

# sudo та APT

Більшість операцій, які змінюють установлені системні пакети, потребують прав адміністратора.

Для цього використовується `sudo`.

Приклади:

    sudo apt update

    sudo apt upgrade

    sudo apt install curl

    sudo apt remove curl

Для перегляду інформації про пакет зазвичай не потрібен `sudo`:

    apt show git

    apt search editor

    apt-cache policy git

Не запускай команди з `sudo` автоматично, якщо вони не потребують підвищених привілеїв.

`sudo` надає команді адміністративні права, тому важливо розуміти, які зміни вона виконує.

---

# Безпечна робота з APT

Перед встановленням або видаленням пакета перевіряй, які зміни пропонує APT.

Наприклад:

    sudo apt install curl

Перед підтвердженням перевір:

    packages to be installed
    packages to be removed
    additional dependencies
    download size
    disk space requirements

Для попереднього моделювання операції встановлення:

    sudo apt install --simulate curl

Для моделювання видалення:

    sudo apt remove --simulate curl

Симуляція дозволяє попередньо переглянути заплановані дії, але не замінює перевірку походження пакета та оцінку ризиків.

Не використовуй без розуміння команду на кшталт:

    sudo apt remove package-name

для системних пакетів, від яких залежать важливі компоненти Ubuntu.

Видалення деяких пакетів може спричинити видалення інших пакетів або порушити роботу середовища.

---

# apt autoremove

`apt autoremove` видаляє пакети, які були встановлені автоматично як залежності та більше не вважаються потрібними.

    sudo apt autoremove

Наприклад, ти встановив програму, якій потрібна додаткова бібліотека. Після видалення програми ця бібліотека може залишитися в системі, якщо більше нікому не потрібна.

APT може запропонувати її видалення.

Перед підтвердженням перевір список пакетів.

Важливо:

    apt remove
        → видаляє зазначений пакет

    apt purge
        → видаляє пакет із системними конфігураційними файлами

    apt autoremove
        → видаляє непотрібні автоматично встановлені залежності

Це різні операції.

---

# apt clean та apt autoclean

APT може зберігати завантажені `.deb`-файли в кеші:

    /var/cache/apt/archives/

Щоб очистити кеш завантажених пакетів:

    sudo apt clean

Ця команда видаляє завантажені пакетні архіви з кешу.

Для видалення застарілих пакетних архівів, які більше не можна завантажити з репозиторіїв, використовується:

    sudo apt autoclean

Важливо:

    apt clean
        → очищає кеш завантажених пакетів

    apt autoclean
        → очищає застарілі пакетні архіви з кешу

Ці команди не призначені для видалення встановлених програм.

Очищення кешу не є обов'язковою щоденною операцією.

    apt list --upgradable

    sudo apt upgrade

## Крок 4 — знайти потрібний пакет

    apt search git

## Крок 5 — переглянути інформацію

    apt show git

## Крок 6 — встановити пакет

    sudo apt install git

    git --version

    dpkg -l git

Це типовий навчальний сценарій. Не кожного разу потрібно виконувати всі кроки: послідовність залежить від задачі.

# Типові помилки

❌ Плутати `apt update` та `apt upgrade`.

    sudo apt update

Оновлює індекси пакетів.

    sudo apt upgrade

Встановлює доступні оновлення встановлених пакетів.

---

❌ Вважати, що `apt search` шукає всі програми в інтернеті.

APT шукає за локальною інформацією про пакети з налаштованих джерел.

Перед пошуком можна оновити індекси:

    sudo apt update

---

❌ Вважати, що `apt remove` завжди видаляє абсолютно всі файли програми.

`apt remove` зазвичай залишає системні конфігураційні файли пакета. Користувацькі дані програми також можуть зберігатися окремо.

---

❌ Плутати `apt` та `dpkg`.

    apt
        → керування пакетами та залежностями

    dpkg
        → безпосередня робота з Debian-пакетами

---

❌ Використовувати `dpkg -i` і забувати про залежності.

    sudo dpkg -i package.deb

Якщо необхідних залежностей немає, встановлення може потребувати додаткового виправлення.

---

❌ Встановлювати невідомі `.deb`-файли.

Перед встановленням перевіряй джерело пакета, його призначення та сумісність із системою.

---

❌ Бездумно погоджувати видалення пакетів.

Перед підтвердженням `apt remove`, `apt purge` або `apt autoremove` перевіряй список змін.

---

❌ Вважати, що всі команди APT потребують `sudo`.

Для пошуку та перегляду інформації зазвичай достатньо звичайного користувача.

---

❌ Редагувати репозиторії без розуміння конфігурації.

Неправильні адреси джерел або несумісні репозиторії можуть спричинити проблеми з оновленням системи.

# Головне

• APT — основний інструмент керування пакетами в Ubuntu.

• Пакети дозволяють стандартизовано встановлювати та видаляти програмне забезпечення.

• Репозиторії містять пакети та інформацію про них.

• Індекси APT містять локальну інформацію про доступні пакети.

• `sudo apt update` оновлює індекси, але не оновлює встановлені програми.

• `sudo apt upgrade` встановлює доступні оновлення.

• `sudo apt install package-name` встановлює пакет і опрацьовує його залежності.

• `sudo apt remove package-name` видаляє пакет, зазвичай залишаючи системні конфігураційні файли.

• `sudo apt purge package-name` видаляє пакет разом із системними конфігураційними файлами, які належать пакету.

• `apt search keyword` допомагає знаходити пакети.

• `apt show package-name` показує інформацію про пакет.

• `apt-cache policy package-name` допомагає досліджувати доступні версії та джерела.

• APT та `dpkg` виконують різні ролі.

• `.deb` — формат пакетів Debian та Ubuntu.

• Для локального `.deb`-файлу часто зручніше використовувати `sudo apt install ./package.deb`, оскільки APT може опрацювати залежності з налаштованих репозиторіїв.

• Перед видаленням пакетів перевіряй, які зміни пропонує система.

• Не встановлюй пакети з невідомих джерел.

• Для початку достатньо впевнено користуватися командами:

    sudo apt update
    sudo apt upgrade
    sudo apt install
    sudo apt remove
    sudo apt purge
    apt search
    apt show
    apt list --installed
    apt list --upgradable

• Основна модель роботи APT:

    Repository
        ↓
    Package index
        ↓
    Search / dependency resolution
        ↓
    Download
        ↓
    Install / upgrade / remove
