# 02. Bash Completion

Bash Completion (автодоповнення Bash) — це механізм оболонки Bash, який допомагає автоматично доповнювати команди, назви файлів, каталогів, параметрів та інших доступних елементів під час введення команд у терміналі.

Автодоповнення дозволяє швидше працювати з командним рядком, зменшує кількість помилок у назвах файлів і команд та полегшує навігацію великими проєктами.

Bash Completion використовується, коли потрібно:

- автоматично доповнювати назви файлів і каталогів;
- швидко переходити між каталогами проєкту;
- доповнювати назви системних команд;
- переглядати можливі варіанти введення;
- доповнювати параметри команд;
- працювати з Git-командами та їхніми підкомандами;
- швидше вводити команди Node.js та npm;
- використовувати автодоповнення в інтерактивному терміналі;
- налаштовувати власні правила доповнення;
- розуміти різницю між стандартним доповненням Bash і пакетом `bash-completion`.

Основні можливості та команди:

    Tab
    Tab Tab
    complete

## Що потрібно пам'ятати

• Bash Completion допомагає доповнювати команди, файли, каталоги та аргументи.

• Клавіша `Tab` — основний інструмент автодоповнення в Bash.

• Якщо введення можна однозначно доповнити, Bash зазвичай підставляє відповідну частину або повне ім'я.

• Якщо існує декілька варіантів, повторне натискання `Tab` може показати список доступних варіантів.

• Стандартне доповнення файлів і каталогів доступне в Bash без обов'язкового встановлення окремого пакета `bash-completion`.

• Пакет `bash-completion` розширює можливості автодоповнення для багатьох команд та їхніх параметрів.

• Поведінка доповнення залежить від оболонки, її налаштувань, встановлених пакетів і доступних правил completion.

• `complete` показує або встановлює правила програмованого доповнення Bash.

• `compgen` допомагає генерувати список можливих варіантів доповнення.

• `type` показує, як Bash інтерпретує назву команди.

• `command -v` допомагає перевірити, чи доступна команда в поточному середовищі.

• Файл `~/.bashrc` часто використовується для налаштування інтерактивної оболонки Bash.

• Зміни в `~/.bashrc` зазвичай застосовуються після відкриття нового інтерактивного Bash або після повторного завантаження конфігурації.

• `source ~/.bashrc` повторно виконує команди з файлу конфігурації в поточній оболонці.

• На Ubuntu пакет `bash-completion` можна встановити через `apt`.

• Автодоповнення не надає прав доступу до файлів і не змінює permissions.

• Bash Completion не є повноцінним пошуком по всій файловій системі: стандартне доповнення шляхів орієнтується на введений шлях і поточний контекст.

• Для розробника автодоповнення особливо корисне під час роботи з довгими шляхами до каталогів і файлами проєктів.

# Bash Completion

Bash Completion — загальна назва механізму доповнення введення в Bash.

Наприклад, ви хочете перейти до каталогу:

    ~/projects/nest-exercises

Замість введення всього шляху можна почати вводити:

    cd ~/projects/nest

Потім натиснути `Tab`.

Якщо назва однозначна, Bash може доповнити її:

    cd ~/projects/nest-exercises

Після цього можна натиснути `Enter`.

Важливо розрізняти два рівні:

    Basic completion
        ↓
    доповнення назв файлів і каталогів

    Programmable completion
        ↓
    доповнення команд, параметрів та аргументів
    за спеціальними правилами

Базове доповнення шляхів є стандартною можливістю Bash.

Розширене доповнення для Git, системних інструментів та інших команд часто забезпечується додатковими completion-правилами або пакетом `bash-completion`.

# Tab Completion

Tab Completion — доповнення введення за допомогою клавіші `Tab`.

Це найважливіша навичка для повсякденної роботи з Bash.

## Приклад 1 — доповнення каталогу

Припустимо, структура каталогів така:

    ~/projects/
    ├── nest-exercises/
    ├── next-exercises/
    └── python-exercises/

Введіть:

    cd ~/projects/nes

Натисніть `Tab`.

Якщо є лише один відповідний варіант, Bash може доповнити:

    cd ~/projects/nest-exercises/

Тепер натисніть `Enter`.

## Приклад 2 — кілька можливих варіантів

Припустимо, існують каталоги:

    nest-exercises/
    next-exercises/

Введіть:

    cd ~/projects/ne

Натисніть `Tab`.

Bash може доповнити спільну частину:

    cd ~/projects/n

Якщо продовження неоднозначне, натисніть `Tab` ще раз, щоб переглянути варіанти, якщо це передбачено налаштуваннями оболонки.

У такій ситуації можна ввести ще кілька символів:

    cd ~/projects/nest

і знову натиснути `Tab`.

## Приклад 3 — доповнення файла

Припустимо, у поточному каталозі є:

    README.md
    package.json
    server.js

Введіть:

    cat READ

Натисніть `Tab`.

Bash може доповнити команду до:

    cat README.md

## Приклад 4 — доповнення вкладеного шляху

Введіть:

    cd ~/projects/nest-exercises/practice/linux/12-dev

Натисніть `Tab`.

Якщо каталог має назву `12-developer-workflow`, Bash може доповнити шлях.

Результат:

    cd ~/projects/nest-exercises/practice/linux/12-developer-workflow

## Приклад 5 — доповнення імені команди

Введіть:

    git sta

Натисніть `Tab`.

У стандартній конфігурації Bash це не обов'язково доповнить `git status`, адже `status` — аргумент Git, а не окрема команда оболонки.

Для доповнення підкоманд Git зазвичай потрібні відповідні правила Git completion.

Це важлива відмінність між доповненням назв команд і доповненням аргументів програм.

# Одне натискання Tab

Коли ви натискаєте `Tab` один раз, Bash намагається доповнити поточне слово.

Наприклад:

    cd ~/projects/nest

Якщо відповідний каталог лише один, Bash може доповнити його до повного імені.

Інший приклад:

    ls /etc/hos

Можливе доповнення:

    ls /etc/hosts

Результат залежить від того, які файли існують і які правила доповнення активні.

Якщо введення неоднозначне, Bash може:

- доповнити лише спільну частину;
- залишити введення без змін;
- запропонувати варіанти після наступного натискання `Tab`.

---

# Два натискання Tab

Повторне натискання `Tab` часто використовується для перегляду доступних варіантів.

Наприклад:

    cd ~/projects/ne

Якщо існують:

    nest-exercises/
    next-exercises/

Bash може показати обидва варіанти.

Це допомагає зрозуміти, які назви відповідають уже введеному фрагменту.

Пам'ятайте:

    Tab
        ↓
    доповнити введення

    Tab Tab
        ↓
    доповнити або показати можливі варіанти

Точна поведінка залежить від конфігурації Bash та Readline.

---

# Filename Completion

Filename Completion — доповнення назв файлів.

Bash може доповнювати назви файлів у командах, які приймають шляхи як аргументи.

Наприклад:

    cat READ

Якщо існує файл `README.md`, Bash може доповнити назву.

Інший приклад:

    nano package

Якщо файл називається `package.json`, автодоповнення може допомогти ввести його назву.

Приклад із абсолютним шляхом:

    ls /etc/ssh/ss

Bash може доповнити назву до відповідного файла або каталогу, якщо є однозначний збіг.

Автодоповнення допомагає зменшити кількість помилок у назвах, але не перевіряє, чи є файл потрібним для конкретної задачі.

---

# Directory Completion

Directory Completion — доповнення назв каталогів.

Це особливо корисно для команди `cd`.

Наприклад:

    cd ~/projects/nest-exercises/practice/li

Після `Tab` Bash може доповнити шлях до:

    cd ~/projects/nest-exercises/practice/linux

Для переходу між вкладеними каталогами можна доповнювати шлях поступово:

    cd ~/projects/
    cd nest-exercises/
    cd practice/
    cd linux/

У реальній роботі можна не вводити кожну частину вручну:

    cd ~/projects/nest-exercises/practice/linux

Достатньо вводити короткі фрагменти й натискати `Tab`.

Важливо: якщо назви каталогів неоднозначні, потрібно уточнити введення.

---

# Command Completion

Command Completion — доповнення назв команд.

Bash може доповнювати назви доступних команд, зокрема програм, знайдених через `PATH`, а також деякі вбудовані команди оболонки.

Наприклад:

    sys

Після `Tab` можуть з'явитися варіанти команд, які починаються з `sys`.

Інший приклад:

    git

Якщо натиснути `Tab` після пробілу, Bash зазвичай спробує доповнити аргументи, а не назву `git` як команди.

Порівняйте:

    gi<Tab>

Доповнення назви команди.

    git <Tab>

Доповнення першого аргументу команди `git`.

Ці два випадки можуть використовувати різні правила.

---

# Argument Completion

Argument Completion — доповнення аргументів команди.

Аргументи — це значення, які передаються команді після її назви.

Наприклад:

    cd ~/projects

Тут `~/projects` — аргумент команди `cd`.

Для багатьох команд Bash може доповнювати шляхи в аргументах стандартними правилами.

Але для спеціальних аргументів потрібні відповідні completion-правила.

Наприклад:

    git checkout <Tab>

Автодоповнення гілок Git може працювати, якщо налаштоване Git completion.

Без відповідних правил Bash не обов'язково зможе запропонувати список гілок.

---

# Option Completion

Option Completion — доповнення параметрів команд.

Параметри часто починаються з дефіса:

    -l
    -a
    -h
    --help
    --version

Наприклад:

    ls -

Після натискання `Tab` результат залежить від доступних правил доповнення.

Деякі команди мають власні правила, які допомагають доповнювати параметри.

Наприклад, для команд із великою кількістю опцій автодоповнення може значно спростити роботу.

Однак не всі команди підтримують повне доповнення всіх параметрів.

---

# Programmable Completion

Programmable Completion — програмоване доповнення Bash.

Це механізм, який дозволяє налаштовувати правила доповнення для конкретних команд.

Наприклад, можна створити правило, яке після введення:

    deploy <Tab>

показуватиме доступні середовища:

    development
    staging
    production

Це лише концептуальний приклад. Щоб таке доповнення працювало, потрібно визначити функцію та зареєструвати її в Bash.

Програмоване доповнення може враховувати:

- поточну команду;
- попередні аргументи;
- поточне слово;
- позицію курсора;
- файли та каталоги;
- значення змінних;
- доступні підкоманди;
- результати інших команд.

Основні інструменти:

    complete
    compgen
    COMPREPLY
    COMP_WORDS
    COMP_CWORD

Для початкового рівня достатньо розуміти, що programmable completion дозволяє створювати власні правила автодоповнення.

---

# complete

`complete` — вбудована команда Bash для налаштування програмованого доповнення.

Переглянути доступні правила:

    complete -p

Ця команда показує визначені completion-специфікації.

Переглянути правила для конкретної команди:

    complete -p git

Результат залежить від того, чи зареєстровані відповідні правила.

Приклад простого правила для власної команди `deploy`:

    complete -W "development staging production" deploy

Тепер Bash має пропонувати слова:

    development
    staging
    production

після команди `deploy`, якщо це правило завантажене в поточній оболонці.

Наприклад:

    deploy sta

Після натискання `Tab` може бути доповнено:

    deploy staging

Це правило використовує фіксований список слів і підходить лише для демонстрації механізму.

Для складніших команд використовують completion-функції.

Видалити правило для команди:

    complete -r deploy

Видалення правила впливає на поточну оболонку, якщо воно не буде повторно завантажене з конфігурації.

---

# compgen

`compgen` — вбудована команда Bash, яка генерує список можливих варіантів доповнення.

Наприклад, показати доступні команди:

    compgen -c

Показати доступні вбудовані команди Bash:

    compgen -b

Показати змінні оболонки:

    compgen -v

Показати функції:

    compgen -A function

Показати команди, які починаються з `git`:

    compgen -c git

Можливий результат міститиме команди з таким префіксом, якщо вони доступні в середовищі.

Для простого доповнення фіксованого списку:

    compgen -W "development staging production" -- st

Результат:

    staging

Тут:

    -W
        → список слів для перевірки

    --
        → завершення списку опцій

    st
        → префікс для пошуку

`compgen` корисний під час написання власних completion-функцій і дослідження доступних варіантів.

# Completion Functions

Completion Function — функція Bash, яка формує варіанти автодоповнення для певної команди.

Функція може аналізувати введення та формувати список відповідних варіантів.

У програмованому доповненні часто використовуються:

    COMP_WORDS
    COMP_CWORD
    COMPREPLY

Їхні основні призначення:

    COMP_WORDS
        → масив слів поточного командного рядка

    COMP_CWORD
        → індекс поточного слова в COMP_WORDS

    COMPREPLY
        → масив запропонованих варіантів доповнення

Приклад простої функції для команди `deploy`:

    _deploy_completion() {
        local cur

        cur="${COMP_WORDS[COMP_CWORD]}"

        COMPREPLY=(
            $(compgen -W "development staging production" -- "$cur")
        )
    }

    complete -F _deploy_completion deploy

Після завантаження цього коду в інтерактивний Bash можна перевірити:

    deploy dev

Якщо доповнення налаштоване правильно, Bash запропонує:

    development

Важливо: цей приклад призначений для вивчення механізму. Для складних сценаріїв із пробілами та спеціальними символами в назвах краще використовувати обережнішу обробку масивів і стандартні helper-функції, якщо вони доступні.

---

# COMP_WORDS

`COMP_WORDS` — масив Bash, який містить слова поточного командного рядка під час виконання completion-функції.

Наприклад, для команди:

    deploy staging

під час доповнення аргументу `staging` масив може містити:

    COMP_WORDS[0] → deploy
    COMP_WORDS[1] → staging

Точне розбиття залежить від правил обробки введення та контексту.

`COMP_WORDS` використовується у функціях programmable completion.

У звичайному інтерактивному терміналі цей масив не призначений для постійного зберігання всіх команд користувача.

---

# COMP_CWORD

`COMP_CWORD` — індекс поточного слова в масиві `COMP_WORDS` під час виконання completion-функції.

Наприклад:

    COMP_WORDS[0] → deploy
    COMP_WORDS[1] → staging

Якщо курсор перебуває в аргументі `staging`, `COMP_CWORD` зазвичай дорівнює:

    1

Індекс починається з нуля.

Це дозволяє completion-функції визначити, яке слово зараз потрібно доповнювати.

---

# COMPREPLY

`COMPREPLY` — масив Bash, у який completion-функція записує можливі варіанти доповнення.

Наприклад:

    COMPREPLY=(
        development
        staging
        production
    )

Це фіксований список кандидатів.

У практичних completion-функціях список часто формується динамічно за допомогою `compgen`.

Приклад:

    COMPREPLY=(
        $(compgen -W "development staging production" -- "$cur")
    )

Якщо поточний префікс:

    pro

можливим результатом буде:

    production

Bash використовує `COMPREPLY`, щоб запропонувати користувачу відповідні варіанти.

# bash-completion

`bash-completion` — пакет, який надає розширену систему автодоповнення для Bash.

В Ubuntu його можна встановити через пакетний менеджер `apt`.

Оновити список пакетів:

    sudo apt update

Встановити пакет:

    sudo apt install bash-completion

Перевірити встановлення:

    dpkg -s bash-completion

Або:

    apt list --installed bash-completion

Після встановлення потрібно переконатися, що completion-функціональність завантажується в інтерактивному Bash.

На багатьох системах відповідна конфігурація вже інтегрована в системні файли Bash.

Типові шляхи можуть включати:

    /etc/bash_completion
    /usr/share/bash-completion/bash_completion
    /usr/share/bash-completion/completions/

Конкретні файли та розташування залежать від дистрибутива й версії пакета.

Важливо:

• Пакет не обов'язково потрібен для стандартного доповнення файлів і каталогів.

• Він корисний для розширеного доповнення багатьох команд.

• Після встановлення пакет може потребувати перезапуску оболонки або повторного завантаження відповідної конфігурації.

---

# Перевірка Bash Completion

Щоб перевірити, чи доступна команда Bash:

    echo "$BASH_VERSION"

Якщо змінна містить номер версії, поточна оболонка, імовірно, є Bash.

Перевірити, чи встановлений пакет:

    dpkg -s bash-completion

Перевірити, чи доступна команда `complete`:

    type complete

Можливий результат:

    complete is a shell builtin

Переглянути зареєстровані правила:

    complete -p

Перевірити конкретне правило:

    complete -p git

Якщо правило для `git` не знайдене, це не обов'язково означає, що Git не встановлений. Можливо, completion для Git не налаштований або не завантажений.

Перевірити Git:

    command -v git
    git --version

Перевірити, чи існує типовий файл пакетного доповнення:

    ls /usr/share/bash-completion/completions/

Перевірити конкретний файл, якщо він є:

    ls /usr/share/bash-completion/completions/git

Шлях залежить від системи, а наявність файлу сама по собі не гарантує, що правила вже завантажені в поточну оболонку.

# Налаштування ~/.bashrc

`~/.bashrc` — конфігураційний файл Bash, який зазвичай виконується під час запуску інтерактивної оболонки, що не є login shell.

У ньому можуть бути:

- aliases;
- shell functions;
- змінні середовища;
- налаштування prompt;
- правила completion;
- інші параметри інтерактивної роботи.

Переглянути файл:

    cat ~/.bashrc

Відкрити для редагування у VS Code:

    code ~/.bashrc

Або в термінальному редакторі:

    nano ~/.bashrc

Після змін можна повторно завантажити конфігурацію:

    source ~/.bashrc

Альтернативний синтаксис:

    . ~/.bashrc

Обидва варіанти виконують файл у поточній оболонці.

Важливо: `source ~/.bashrc` не встановлює відсутні пакети. Якщо команда або файл не існують, спочатку потрібно перевірити встановлення та налаштування.

---

# Як перевірити, чи Bash Completion завантажений

Спочатку перевірте оболонку:

    echo "$BASH_VERSION"

Потім перевірте команду:

    type complete

Перевірте правила:

    complete -p

Перевірте пакет:

    dpkg -s bash-completion

Якщо пакет встановлений, але доповнення команд не працює, перевірте конфігурацію системи та поточного користувача.

Наприклад:

    grep -n "bash_completion" ~/.bashrc

Ця команда шукає згадки `bash_completion` у файлі `~/.bashrc`.

Також можна переглянути системну конфігурацію:

    grep -n "bash_completion" /etc/bash.bashrc

На Ubuntu системне налаштування може бути інтегроване у `/etc/bash.bashrc`, але точний спосіб завантаження залежить від версії системи та встановлених пакетів.

Не потрібно бездумно додавати один і той самий блок ініціалізації в кілька файлів. Спочатку перевірте, чи налаштування вже існує.

# Власні правила автодоповнення

У Bash можна створювати власні completion-правила для команд, які ви використовуєте у своїх проєктах.

Наприклад, уявімо команду:

    deploy

Вона може приймати аргументи:

    development
    staging
    production

Найпростіше правило:

    complete -W "development staging production" deploy

Після цього Bash може доповнювати доступні значення для команди `deploy`.

Перевірити визначені правила:

    complete -p deploy

Видалити правило:

    complete -r deploy

Такі правила зберігаються лише в поточній оболонці, якщо їх не завантажувати з конфігураційного файла.

Для постійного використання правило можна додати до відповідної конфігурації Bash, наприклад `~/.bashrc`, якщо це доречно.

Не додавайте тестові правила до основної конфігурації без потреби. Спочатку перевірте їх у поточній оболонці.

# Типові помилки

❌ **Очікувати, що Tab завжди доповнюватиме будь-яку команду.**

Стандартне доповнення шляхів і програмоване доповнення аргументів — різні механізми.

---

❌ **Вважати, що `bash-completion` обов'язково потрібен для доповнення файлів.**

Базове доповнення файлів і каталогів уже є можливістю Bash.

---

❌ **Очікувати доповнення Git-підкоманд без відповідних правил.**

Наприклад:

    git sta<Tab>

може не доповнити `status`, якщо Git completion не налаштований.

---

❌ **Вважати, що встановлення пакета автоматично виправляє всі налаштування.**

Після встановлення можуть бути потрібні правильна конфігурація та перезапуск оболонки.

---

❌ **Не перевіряти, яка оболонка використовується.**

    echo "$BASH_VERSION"

Допомагає визначити, чи запущено Bash.

---

❌ **Редагувати конфігурацію, не перевіривши наявні налаштування.**

Спочатку перевірте:

    grep -n "bash_completion" ~/.bashrc

Не потрібно дублювати блоки ініціалізації без причини.

---

❌ **Плутати `complete` та `compgen`.**

    complete
    → налаштування правил доповнення

    compgen
    → генерація списку кандидатів

---

❌ **Очікувати, що `complete -p git` обов'язково покаже правила Git.**

Якщо правило не зареєстроване, команда може повідомити, що відповідного правила немає.

Це не доводить, що Git відсутній у системі.

---

❌ **Вважати, що автодоповнення перевіряє права доступу.**

Доповнення може показати ім'я файла або каталогу, але фактичний доступ залежить від permissions та інших механізмів безпеки.

---

❌ **Забувати про пробіли та спеціальні символи в назвах.**

Для складних шляхів Bash використовує власні правила екранування та лапок.

Під час створення власних completion-функцій потрібно враховувати ці особливості.

    Tab

        → розширені правила доповнення

# Головне

• Bash Completion допомагає швидше вводити команди, назви файлів, каталоги та аргументи.

• Клавіша `Tab` — головний інструмент автодоповнення.

• Стандартне доповнення файлів і каталогів доступне в Bash без окремого пакета.

• `bash-completion` додає розширені правила для багатьох команд.

• `complete` використовується для налаштування правил програмованого доповнення.

• `compgen` генерує можливі варіанти доповнення.

• `COMP_WORDS` містить слова поточного командного рядка в контексті completion-функції.

• `COMP_CWORD` указує на поточне слово.

• `COMPREPLY` містить варіанти, які пропонує completion-функція.

• Файл `~/.bashrc` часто використовується для налаштування інтерактивного Bash.

• `source ~/.bashrc` повторно завантажує налаштування в поточну оболонку.

• Git completion може доповнювати підкоманди, гілки та інші аргументи, якщо відповідні правила доступні.

• У VS Code автодоповнення залежить від оболонки, запущеної у вбудованому терміналі.

• Git Bash у Windows та Bash в Ubuntu можуть мати різні налаштування.

• Автодоповнення не замінює знання команд і не гарантує, що вибраний файл або аргумент підходить для конкретної операції.

• Основна модель Bash Completion:

    user input
        ↓
    press Tab
        ↓
    Bash examines current word
        ↓
    completion rules generate candidates
        ↓
    Bash completes input or displays options

• Для щоденної роботи розробника найважливіше — упевнено використовувати `Tab`, розуміти доповнення шляхів і вміти перевірити налаштування, якщо автодоповнення не працює.

• На початковому етапі достатньо освоїти стандартне доповнення, а програмоване доповнення вивчати поступово, коли виникне потреба автоматизувати роботу з власними CLI-командами.
