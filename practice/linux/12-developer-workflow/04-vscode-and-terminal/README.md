# VS Code and Terminal — VS Code та термінал у Linux

VS Code and Terminal — це робота з редактором Visual Studio Code та терміналом Linux для щоденної розробки. Термінал дає змогу керувати файлами, запускати команди, працювати з Git, Node.js, npm, PostgreSQL та запускати проєкти безпосередньо з редактора.

Мета цієї теми — навчитися налаштовувати VS Code в Ubuntu, відкривати проєкти, працювати з інтегрованим терміналом, використовувати Bash, запускати JavaScript / TypeScript-проєкти та ефективно переміщатися між файлами й каталогами.

---

## 1. Що потрібно знати

✔ VS Code — редактор коду з підтримкою розширень, термінала, Git та налагодження.

✔ Terminal — програма, у якій можна вводити команди й отримувати їхній результат.

✔ Shell — командна оболонка, яка інтерпретує введені команди. У цьому курсі основна оболонка — Bash.

✔ Integrated Terminal — термінал, вбудований у VS Code.

✔ Workspace — відкрита папка або набір папок, з якими ти працюєш у VS Code.

✔ Explorer — панель для перегляду файлів і каталогів проєкту.

✔ Command Palette — пошук і запуск команд VS Code через `Ctrl + Shift + P`.

✔ Settings — налаштування редактора та розширень.

✔ Extensions — розширення, які додають функціональність VS Code.

✔ Terminal Profile — конфігурація оболонки, яку VS Code запускає в інтегрованому терміналі.

✔ `code` — команда для відкриття VS Code з термінала.

✔ `settings.json` — файл налаштувань VS Code у форматі JSON.

✔ `tasks.json` — файл для налаштування повторюваних задач, наприклад запуску команд.

✔ `launch.json` — файл конфігурації налагодження, якщо потрібна спеціальна конфігурація.

✔ `cwd` — current working directory, тобто поточний робочий каталог процесу.

## 2. Перевірка встановленого VS Code

### 2.1. Перевірити версію

У терміналі Ubuntu:

    code --version

Якщо команда доступна, VS Code виведе версію програми та додаткові ідентифікатори збірки.

### 2.2. Знайти виконуваний файл

    command -v code

Команда показує, звідки оболонка запускає `code`.

Якщо результат порожній, це не обов'язково означає, що VS Code не встановлений. Можливо, команда `code` не додана до `PATH`.

### 2.3. Перевірити процес VS Code

    pgrep -a code

Команда показує процеси, назва яких відповідає `code`, якщо вони є.

### 2.4. Перевірити інформацію про систему

    uname -a
    cat /etc/os-release

Ці команди корисні, коли потрібно з'ясувати версію Linux або діагностувати проблему із запуском програми.

## 3. Відкриття проєкту з термінала

Для навчальних проєктів можна використовувати каталог:

    ~/projects

### 3.1. Перейти до каталогу проєктів

    cd ~/projects

Перевірити поточний каталог:

    pwd

Переглянути вміст:

    ls -la

### 3.2. Відкрити конкретний проєкт

Наприклад, відкрити проєкт `nest-exercises`:

    code ~/projects/nest-exercises

VS Code відкриє папку як workspace.

### 3.3. Відкрити поточний каталог

Якщо ти вже перебуваєш у корені проєкту:

    cd ~/projects/nest-exercises
    code .

Крапка `.` означає поточний каталог.

Це один із найзручніших способів роботи: спочатку переходиш у потрібний каталог через Bash, а потім відкриваєш його у VS Code.

### 3.4. Відкрити окремий файл

    code README.md

Відкриє файл у VS Code. Якщо файл ще не існує, редактор може відкрити новий документ із таким ім'ям, але сам файл буде створений на диску лише після збереження.

### 3.5. Відкрити файл у конкретному рядку

    code -g README.md:25

Редактор відкриє файл приблизно на 25-му рядку.

### 3.6. Відкрити проєкт у новому вікні

    code -n ~/projects/nest-exercises

Параметр `-n` просить відкрити нове вікно.

### 3.7. Відкрити файл у поточному вікні

    code -r README.md

Параметр `-r` просить повторно використати наявне вікно, якщо це можливо.

## 4. Основні способи роботи у VS Code

### 4.1. Explorer

Explorer показує структуру проєкту.

Наприклад:

    nest-exercises/
    ├── practice/
    │   └── linux/
    │       ├── README.md
    │       └── 12-developer-workflow/
    │           ├── 01-directory-navigation/
    │           ├── 02-bash-completion/
    │           ├── 03-git-from-terminal/
    │           └── 04-vscode-and-terminal/
    ├── src/
    ├── package.json
    └── README.md

Через Explorer можна відкривати файли, створювати каталоги, перейменовувати файли та переглядати структуру проєкту.

### 4.2. Command Palette

Відкрити Command Palette:

    Ctrl + Shift + P

У ній можна знайти команди для:

- відкриття налаштувань;
- зміни теми;
- керування терміналом;
- встановлення розширень;
- форматування коду;
- запуску налагодження;
- керування workspace.

Command Palette особливо корисна, якщо ти не пам'ятаєш клавіатурне скорочення.

### 4.3. Settings

Відкрити графічні налаштування:

    Ctrl + ,

Відкрити Command Palette та знайти:

    Preferences: Open User Settings (JSON)

Ця команда відкриває JSON-файл користувацьких налаштувань.

### 4.4. Перемикання панелей

Корисні комбінації:

| Дія | Linux |

| Settings | `Ctrl + ,` |

Примітка: комбінації можуть відрізнятися через власні налаштування, розкладку клавіатури або конфлікти з іншими програмами.

## 5. Integrated Terminal

Integrated Terminal дозволяє виконувати команди Linux без виходу з VS Code.

### 5.1. Відкрити термінал

Натисни:

    Ctrl + `

Або відкрий меню:

    Terminal → New Terminal

### 5.2. Перевірити поточну оболонку

    echo "$SHELL"

Це показує шлях до оболонки, визначеної для користувача. Але команда сама по собі не гарантує, що саме ця оболонка зараз виконується.

Для перевірки поточної оболонки:

    ps -p $$ -o comm=

Якщо результат:

    bash

то поточна оболонка — Bash.

### 5.3. Перевірити поточний каталог

    pwd

Термінал може відкриватися в корені workspace, але це залежить від конфігурації та способу відкриття проєкту.

### 5.4. Перейти до іншого каталогу

    cd ~/projects/nest-exercises

### 5.5. Виконати команду Linux

    ls -la

### 5.6. Виконати команду Node.js

    node --version

### 5.7. Виконати команду npm

    npm --version

### 5.8. Переглянути Git-статус

    git status

Усі ці команди виконуються так само, як у звичайному терміналі Ubuntu.

**Важливо:** інтегрований термінал — це не окрема система. Він запускає звичайну оболонку, доступну в твоєму середовищі.

## 6. Робота з кількома терміналами

Під час розробки часто потрібно запускати сервер і паралельно виконувати інші команди.

Наприклад, для Next.js:

- перший термінал — сервер розробки;
- другий термінал — Git, npm або інші команди;
- третій термінал — окремий backend чи база даних, якщо потрібно.

### 6.1. Створити новий термінал

У панелі Terminal натисни кнопку `+` або вибери:

    Terminal → New Terminal

### 6.2. Перемикатися між терміналами

Використовуй список терміналів у панелі Terminal.

У кожному терміналі можуть бути:

- власний поточний каталог;
- власна історія команд;
- власні запущені процеси;
- власне середовище оболонки.

### 6.3. Зупинити сервер

Якщо сервер запущений у поточному терміналі, натисни:

    Ctrl + C

Це зазвичай надсилає процесу сигнал переривання.

### 6.4. Не закривай термінал із сервером випадково

Якщо сервер працює у терміналі, закриття термінала може завершити серверний процес.

Для звичайної розробки зручно тримати сервер у виділеному терміналі, а інші команди запускати в окремому.

## 7. Налаштування Bash у VS Code

Якщо Ubuntu використовує Bash, інтегрований термінал зазвичай може запускати його автоматично.

### 7.1. Перевірити доступні оболонки

    cat /etc/shells

Цей файл містить перелік оболонок, дозволених системою для входу. Він не гарантує, що кожна з них встановлена або налаштована для VS Code.

### 7.2. Перевірити Bash

    bash --version

### 7.3. Перевірити налаштування профілю термінала

Відкрий Settings і знайди:

    Terminal › Integrated › Default Profile: Linux

Назва та розташування параметра можуть змінюватися між версіями VS Code.

Для Bash можна вибрати профіль `bash`, якщо він доступний.

### 7.4. Приклад налаштування профілю

У `settings.json` можна задати профіль Bash:

    {
        "terminal.integrated.profiles.linux": {
            "bash": {
                "path": "bash",
                "args": []
            }
        },
        "terminal.integrated.defaultProfile.linux": "bash"
    }

Не потрібно додавати цей фрагмент автоматично, якщо Bash уже працює правильно. Якщо відповідні параметри існують, об'єднай налаштування, а не створюй дублікати ключів.

### 7.5. Перевірити результат

Відкрий новий інтегрований термінал:

    echo "$SHELL"
    ps -p $$ -o comm=
    pwd

Якщо термінал використовує Bash, `ps` має показати `bash`.

## 8. Налаштування `settings.json`

VS Code зберігає налаштування у форматі JSON.

### 8.1. Відкрити User Settings JSON

Через Command Palette знайди:

    Preferences: Open User Settings (JSON)

### 8.2. Приклад базових налаштувань

    {
        "editor.fontSize": 14,
        "editor.tabSize": 2,
        "editor.insertSpaces": true,
        "editor.formatOnSave": true,
        "files.autoSave": "afterDelay",
        "files.autoSaveDelay": 1000,
        "terminal.integrated.defaultProfile.linux": "bash"
    }

Це приклад, а не обов'язковий набір налаштувань. Розмір шрифту, відступи й автозбереження можна змінювати відповідно до власних потреб.

**Увага:** `editor.formatOnSave` працюватиме лише тоді, коли для відповідної мови доступний форматувальник і він налаштований.

### 8.3. User Settings і Workspace Settings

**User Settings** діють для користувача в різних проєктах.

**Workspace Settings** діють лише для конкретного workspace.

Налаштування workspace зазвичай зберігаються в:

    .vscode/settings.json

Приклад структури:

    nest-exercises/
    ├── .vscode/
    │   └── settings.json
    ├── package.json
    └── src/

Не всі персональні налаштування варто зберігати в репозиторії. Налаштування форматування проєкту часто корисні для команди, а особисті вподобання можуть залишатися в User Settings.

## 9. Робота з файлами через термінал

Термінал корисний для швидкого створення файлів і каталогів.

### 9.1. Створити каталог

    mkdir -p practice/linux/12-developer-workflow/04-vscode-and-terminal

Параметр `-p` дозволяє створити також відсутні батьківські каталоги.

### 9.2. Перейти до каталогу

    cd practice/linux/12-developer-workflow/04-vscode-and-terminal

### 9.3. Створити порожній файл

    touch README.md

### 9.4. Відкрити файл у VS Code

    code README.md

### 9.5. Переглянути файл у терміналі

    cat README.md

Для довгого файла:

    less README.md

Вийти з `less`:

    q

### 9.6. Переглянути структуру каталогів

Якщо встановлено `tree`:

    tree practice/linux/12-developer-workflow

Якщо команда `tree` не встановлена, можна скористатися:

    find practice/linux/12-developer-workflow -maxdepth 2 -print

### 9.7. Відкрити поточний каталог у VS Code

    code .

Це зручно, якщо ти створив каталог через Bash і хочеш одразу працювати з ним у редакторі.

## 10. Bash-команди для щоденної роботи

### 10.1. Навігація

    pwd
    ls
    ls -la
    cd ..
    cd ~
    cd ~/projects/nest-exercises

### 10.2. Перегляд файлів

    cat README.md
    less README.md
    head -n 20 README.md
    tail -n 20 README.md

### 10.3. Пошук файлів

    find . -name "*.md"

Знайти всі файли `package.json` у поточному каталозі та його підкаталогах:

    find . -name "package.json"

### 10.4. Пошук тексту

Якщо встановлено `grep`:

    grep -n "TODO" README.md

Пошук у всіх Markdown-файлах:

    grep -Rni "TODO" --include="*.md" .

### 10.5. Автодоповнення

У Bash натисни `Tab`, щоб доповнити команду, назву файлу або шлях.

Наприклад, якщо структура така:

    src/app/react/

можна почати вводити:

    cd src/app/re

і натиснути `Tab`, якщо це дозволяє однозначно доповнити шлях.

Якщо є кілька варіантів, повторне натискання `Tab` може показати доступні варіанти залежно від налаштувань оболонки.

## 11. VS Code і Git

VS Code має інтеграцію з Git, тому багато операцій можна виконувати як через інтерфейс, так і через термінал.

### 11.1. Перевірити стан Git

    git status

### 11.2. Відкрити Source Control

Натисни:

    Ctrl + Shift + G

У цій панелі можна переглядати змінені файли, підготовлені зміни та створювати коміти.

### 11.3. Переглянути різницю у файлі

У Source Control вибери змінений файл. VS Code покаже diff — порівняння поточної версії з версією, яку Git використовує як базову для порівняння.

### 11.4. Виконати коміт у терміналі

    git add README.md
    git diff --staged
    git commit -m "Update VS Code terminal notes"

### 11.5. Відправити коміт

    git push

### 11.6. Коли використовувати інтерфейс, а коли термінал

Інтерфейс VS Code зручний для:

- перегляду змін у файлах;
- вибору окремих фрагментів для staging;
- перегляду історії та конфліктів;
- швидкого створення комітів.

Термінал зручний для:

- повторюваних команд;
- складних операцій із гілками;
- перевірки стану репозиторію;
- роботи з кількома проєктами;
- використання інструментів Linux, Node.js та npm.

Обидва способи працюють з тим самим Git-репозиторієм.

## 12. Запуск Node.js-проєктів із VS Code

Для JavaScript / TypeScript-розробки термінал використовується для запуску застосунків та інструментів.

### 12.1. Перевірити Node.js

    node --version

### 12.2. Перевірити npm

    npm --version

### 12.3. Перейти до проєкту

    cd ~/projects/nest-exercises

### 12.4. Перевірити `package.json`

    cat package.json

У цьому файлі зазвичай містяться метадані проєкту, залежності та npm-скрипти.

### 12.5. Встановити залежності

Якщо проєкт використовує npm і має `package-lock.json`:

    npm ci

`npm ci` встановлює залежності відповідно до lock-файла та зазвичай використовується для відтворюваного встановлення. Він може видалити наявний `node_modules`, а за невідповідності lock-файла `package.json` завершиться помилкою.

Для звичайного встановлення залежностей можна використовувати:

    npm install

### 12.6. Переглянути доступні скрипти

    npm run

Команда показує доступні npm-скрипти, якщо вони визначені в `package.json`.

### 12.7. Запустити проєкт

Наприклад, якщо є скрипт `dev`:

    npm run dev

Конкретна команда залежить від проєкту.

### 12.8. Зупинити застосунок

    Ctrl + C

### 12.9. Запустити сервер у першому терміналі, а команди виконувати в другому

Термінал 1:

    npm run dev

Термінал 2:

    git status

Так можна залишити сервер запущеним і паралельно працювати з Git або іншими файлами.

## 13. Робота з кількома проєктами

Під час навчання можна мати декілька репозиторіїв:

    ~/projects/
    ├── next-exercises/
    ├── nest-exercises/
    └── parish/

### 13.1. Відкрити Next.js-проєкт

    code ~/projects/next-exercises

### 13.2. Відкрити NestJS-проєкт

    code ~/projects/nest-exercises

### 13.3. Відкрити проєкт сайту

    code ~/projects/parish

Назви каталогів мають відповідати фактичній структурі на комп'ютері.

### 13.4. Відкрити кілька папок в одному workspace

VS Code підтримує multi-root workspace. Через меню File можна додати інші папки до поточного workspace.

Це зручно, якщо потрібно одночасно працювати з frontend і backend, але не завжди потрібно об'єднувати різні репозиторії. Для незалежних проєктів окремі вікна часто простіші.

### 13.5. Перевіряти, в якому проєкті працює термінал

    pwd
    git rev-parse --show-toplevel

Це допомагає уникнути випадкових команд у неправильному репозиторії.

## 14. Налаштування форматування та відступів

Для JavaScript / TypeScript важливо, щоб файли мали послідовне форматування.

### 14.1. Форматувати документ

    Shift + Alt + F

Комбінація запускає форматування поточного документа, якщо для мови доступний форматувальник.

### 14.2. Встановити форматувальник

Для JavaScript і TypeScript часто використовують Prettier. У командному проєкті краще встановлювати його як залежність розробки, якщо це відповідає правилам проєкту.

Приклад:

    npm install --save-dev prettier

Після встановлення можна додати npm-скрипт у `package.json`, наприклад:

    {
        "scripts": {
            "format": "prettier --write ."
        }
    }

Це лише приклад. Якщо `package.json` уже має секцію `scripts`, додай новий ключ у наявний об'єкт, не створюючи другу секцію `scripts`.

Запуск форматування:

    npm run format

Перед форматуванням усього репозиторію перевір конфігурацію, `.prettierignore` та правила проєкту.

### 14.3. Форматування при збереженні

У `settings.json` можна використовувати:

    {
        "editor.formatOnSave": true
    }

Якщо проєкт має власні правила форматування, варто зберігати їх у репозиторії, щоб різні комп'ютери форматували код однаково.

## 15. Налаштування автозбереження

VS Code підтримує автоматичне збереження файлів.

### 15.1. Увімкнути через налаштування

Відкрий Settings:

    Ctrl + ,

Знайди параметр:

    Files: Auto Save

Можна вибрати `afterDelay`, щоб збереження відбувалося після короткої затримки.

### 15.2. Через `settings.json`

    {
        "files.autoSave": "afterDelay",
        "files.autoSaveDelay": 1000
    }

`1000` означає приблизно одну секунду.

### 15.3. Що потрібно пам'ятати

Автозбереження:

- допомагає не втрачати незбережені зміни;
- може змінити файли без натискання `Ctrl + S`;
- не створює Git-коміт;
- не відправляє зміни на GitHub.

Навіть за ввімкненого автозбереження Git потрібно використовувати окремо.

## 16. Запуск команд через `tasks.json`

Якщо одна й та сама команда виконується регулярно, її можна оформити як задачу VS Code.

Файл зазвичай розташований тут:

    .vscode/tasks.json

Приклад задачі для npm-скрипту `dev`:

    {
        "version": "2.0.0",
        "tasks": [
            {
                "label": "Start development server",
                "type": "shell",
                "command": "npm",
                "args": ["run", "dev"],
                "problemMatcher": []
            }
        ]
    }

Запустити задачу можна через Command Palette:

    Tasks: Run Task

Потім вибери:

    Start development server

### Коли корисні tasks

- запуск серверів;
- виконання тестів;
- запуск форматування;
- збірка проєкту;
- повторювані команди для навчальних вправ.

**Важливо:** задача запускається в певному робочому каталозі. Якщо команда не знаходить `package.json`, перевір `cwd` та налаштування workspace.

## 17. Налагодження JavaScript у VS Code

VS Code підтримує налагодження JavaScript та Node.js.

### 17.1. Запуск програми з термінала

    node app.js

Це звичайний запуск програми без налагоджувача VS Code.

### 17.2. Запуск Node.js із режимом інспектора

    node --inspect app.js

Це вмикає інтерфейс інспектора для підключення налагоджувача. Порт інспектора не варто відкривати для недовірених мереж.

### 17.3. Встановити breakpoint

У VS Code натисни ліворуч від номера рядка у редакторі. Червона позначка означає breakpoint.

Коли програма виконується під налагоджувачем і доходить до цієї точки, виконання може зупинитися.

### 17.4. Відкрити Run and Debug

Натисни:

    Ctrl + Shift + D

Тут можна запускати та налаштовувати конфігурації налагодження.

### 17.5. Перевірити змінні

Коли виконання зупинено, можна переглядати:

- значення змінних;
- Call Stack;
- Watch expressions;
- локальне оточення;
- порядок виконання коду.

### 17.6. Коли потрібен `launch.json`

Для простих сценаріїв VS Code часто може запропонувати запуск без ручного налаштування. Для складніших сценаріїв можна створити:

    .vscode/launch.json

Конфігурація залежить від того, чи запускається браузерний JavaScript, Node.js, TypeScript або інший runtime.

## 18. VS Code та PostgreSQL

    psql --version

### 18.2. Підключитися до бази даних

## 19. Розширення VS Code

Розширення додають функції, яких немає в базовому редакторі.

Відкрити панель Extensions:

    Ctrl + Shift + X

Для JavaScript / TypeScript можуть бути корисними:

- Prettier — форматування коду;
- ESLint — аналіз JavaScript / TypeScript відповідно до правил проєкту;
- розширення для роботи з Git — якщо потрібні додаткові можливості;
- розширення для PostgreSQL — якщо зручно працювати з базою даних у редакторі.

Для Bash можна шукати розширення з підтримкою підсвічування синтаксису та перевірки shell-скриптів.

### 19.1. Переглянути встановлені розширення через CLI

    code --list-extensions

### 19.2. Встановити розширення через CLI

    code --install-extension dbaeumer.vscode-eslint

Це приклад встановлення розширення ESLint. Перед встановленням перевір його видавця та відповідність своєму робочому середовищу.

### 19.3. Видалити розширення

    code --uninstall-extension dbaeumer.vscode-eslint

### 19.4. Не встановлювати забагато розширень

Встановлюй лише те, що справді допомагає роботі. Велика кількість розширень може ускладнювати конфігурацію, збільшувати споживання ресурсів і створювати конфлікти.

## 20. Проблеми з терміналом VS Code

### Проблема 1. Термінал не відкривається

Спробуй:

1. Закрити поточний термінал.
2. Створити новий через `Terminal → New Terminal`.
3. Перевірити профіль термінала.
4. Перезапустити VS Code.

Також можна перевірити Bash у звичайному терміналі Ubuntu:

    bash --version

### Проблема 2. Команда `code` не знайдена

Перевір:

    command -v code
    code --version

Якщо команда відсутня, перевір спосіб встановлення VS Code та доступність CLI у `PATH`.

### Проблема 3. Термінал відкривається не в тому каталозі

Перевір:

    pwd

Перейди до потрібного каталогу:

    cd ~/projects/nest-exercises

Потім за потреби відкрий workspace:

    code .

### Проблема 4. `npm` або `node` не знайдено

Перевір:

    command -v node
    command -v npm
    node --version
    npm --version

Якщо Node.js встановлено через `nvm`, перевір, чи завантажується конфігурація `nvm` у поточній оболонці.

Для Bash можна переглянути:

    grep -n "NVM_DIR" ~/.bashrc

Не додавай нові рядки для `nvm` навмання: спочатку перевір наявну конфігурацію.

### Проблема 5. Команди працюють у звичайному терміналі, але не у VS Code

Можливі причини:

- VS Code запущено до зміни `PATH`;
- інтегрований термінал використовує іншу оболонку;
- конфігурація Bash не завантажується;
- `nvm` або інший менеджер версій ініціалізується не в тому файлі конфігурації.

Перевір:

    ps -p $$ -o comm=
    echo "$PATH"
    command -v node
    command -v npm

Після зміни змінних середовища або конфігурації оболонки закрий старий термінал і створи новий.

### Проблема 6. Автодоповнення не працює

Перевір:

    echo "$SHELL"
    ps -p $$ -o comm=

У Bash натисни `Tab` після початку назви команди або шляху.

Якщо не працює автодоповнення опцій Git або інших команд, перевір налаштування Bash completion. Підказки для файлів і спеціалізоване автодоповнення команд — не одне й те саме.

### Проблема 7. Термінал завис після запуску сервера

Можливо, сервер працює у foreground і займає термінал.

Щоб зупинити процес:

    Ctrl + C

Або створи новий термінал і продовжуй роботу там.

### Проблема 8. VS Code не бачить зміни файлів

Перевір:

    git status

Якщо Git бачить зміни, але редактор не оновився, спробуй повторно відкрити файл або перезавантажити вікно VS Code через Command Palette:

    Developer: Reload Window

## 21. Практична вправа

Мета: відкрити Linux-проєкт у VS Code, попрацювати з інтегрованим терміналом, створити файл, перевірити Git та зберегти зміни.

### Крок 1. Відкрити проєкт

    cd ~/projects/nest-exercises
    code .

### Крок 2. Відкрити інтегрований термінал

Натисни:

    Ctrl + `

### Крок 3. Перевірити каталог

    pwd

### Крок 4. Перевірити Git

    git status -sb

### Крок 5. Перейти до навчального каталогу

    cd practice/linux/12-developer-workflow/04-vscode-and-terminal

### Крок 6. Створити тестовий файл

    touch terminal-practice.md

### Крок 7. Відкрити файл

    code terminal-practice.md

### Крок 8. Додати текст у файл

    # Terminal Practice

    This file was created from the VS Code integrated terminal.

Збережи файл.

### Крок 9. Перевірити зміни

Повернися до кореня репозиторію:

    cd ~/projects/nest-exercises

Перевір статус:

    git status

### Крок 10. Підготувати файл до коміту

    git add practice/linux/12-developer-workflow/04-vscode-and-terminal/terminal-practice.md

Перевір підготовлені зміни:

    git diff --staged

### Крок 11. Створити коміт

    git commit -m "Add terminal practice file"

### Крок 12. Перевірити історію

    git log -5 --oneline

### Крок 13. Відправити зміни

    git push

Виконуй останню команду, якщо гілка налаштована для push і ти справді хочеш опублікувати цей коміт.

### Крок 14. Прибрати тестовий файл за потреби

Якщо файл був потрібен лише для вправи, видали його через VS Code або команду:

    rm practice/linux/12-developer-workflow/04-vscode-and-terminal/terminal-practice.md

Перевір результат:

    git status

Якщо файл уже був закомічений, видалення стане окремою зміною, яку потрібно додати та закомітити, якщо хочеш відобразити його видалення в історії.
