# 01. Directory Navigation

Directory Navigation (навігація каталогами) — це вміння переміщатися між каталогами Linux, визначати поточне розташування, знаходити потрібні директорії та швидко переходити до робочих проєктів через термінал.

Навігація каталогами є однією з базових навичок розробника, який працює в Linux, Bash, Git, Node.js, npm, PostgreSQL та інших інструментах командного рядка.

Навігація використовується, коли потрібно:

- визначити поточний каталог;
- перейти до іншого каталогу;
- повернутися до домашнього каталогу;
- перейти до кореня файлової системи;
- перейти до попереднього робочого каталогу;
- використовувати абсолютні та відносні шляхи;
- швидко переходити між каталогами проєкту;
- знаходити потрібні файли та директорії;
- працювати з пробілами в назвах каталогів;
- розуміти структуру файлової системи Linux;
- виконувати команди з потрібного каталогу;
- ефективно працювати з Git-репозиторіями та проєктами.

Основні команди навігації:

    pwd
    cd
    ls
    cd ..
    cd -
    cd ~
    cd /
    pushd
    popd
    dirs

Допоміжні команди та можливості:

    tree
    find
    realpath
    dirname
    basename
    Tab completion
    Bash history

## Що потрібно пам'ятати

• `pwd` показує поточний робочий каталог.

• `cd` змінює поточний робочий каталог.

• `ls` показує вміст каталогу.

• `cd ..` переходить до батьківського каталогу.

• `cd .` посилається на поточний каталог і зазвичай не змінює розташування.

• `cd ~` переходить до домашнього каталогу поточного користувача.

• `cd` без аргументів також переходить до домашнього каталогу.

• `cd /` переходить до кореня файлової системи.

• `cd -` повертає до попереднього робочого каталогу.

• Абсолютний шлях починається з `/`.

• Відносний шлях визначається відносно поточного робочого каталогу.

• `.` означає поточний каталог, а `..` — батьківський.

• `~` зазвичай позначає домашній каталог поточного користувача в Bash.

• Символ `/` використовується для розділення компонентів шляху.

• Linux розрізняє великі та малі літери в назвах файлів і каталогів.

• Пробіли в назвах потрібно правильно обробляти: використовувати лапки або екранування.

• Tab completion допомагає автоматично доповнювати назви каталогів і файлів.

• Поточний каталог впливає на те, як оболонка та програми інтерпретують відносні шляхи.

• Команда `cd` є вбудованою командою Bash, оскільки змінює робочий каталог самої оболонки.

• Перехід до каталогу не надає автоматично прав доступу до файлів усередині нього.

• Для роботи з проєктами корисно розрізняти домашній каталог, каталог проєктів і корінь конкретного репозиторію.

# Filesystem Navigation

Filesystem Navigation — навігація файловою системою Linux.

Файлова система організована у вигляді дерева каталогів.

На відміну від Windows, де диски часто позначаються літерами на кшталт `C:` або `D:`, у Linux каталоги та файлові системи організовані в єдиному дереві, коренем якого є `/`.

Спрощена структура:

    /
    ├── bin
    ├── boot
    ├── dev
    ├── etc
    ├── home
    │   ├── user
    │   │   ├── projects
    │   │   ├── Documents
    │   │   └── Downloads
    ├── lib
    ├── media
    ├── mnt
    ├── opt
    ├── proc
    ├── root
    ├── run
    ├── sbin
    ├── sys
    ├── tmp
    ├── usr
    └── var

Це спрощений приклад. У сучасних Linux-дистрибутивах деякі каталоги можуть бути символічними посиланнями на інші каталоги.

Основні каталоги:

    /       → корінь файлової системи
    /home   → домашні каталоги звичайних користувачів
    /root   → домашній каталог користувача root
    /etc    → системні конфігураційні файли
    /usr    → програми, бібліотеки та інші ресурси
    /var    → змінні дані, журнали та кеші
    /tmp    → тимчасові файли
    /dev    → файли пристроїв
    /proc   → віртуальна файлова система з інформацією про процеси та ядро
    /sys    → інтерфейс до інформації про ядро та пристрої

Наприклад, на Ubuntu домашній каталог користувача може мати такий шлях:

    /home/valer

А каталог проєктів:

    /home/valer/projects

Проєкт NestJS може розташовуватися тут:

    /home/valer/projects/nest-exercises

Щоб перейти до кореня файлової системи:

    cd /

Щоб перейти до домашнього каталогу:

    cd ~

Щоб перейти до каталогу проєктів:

    cd ~/projects

# Current Working Directory

Current Working Directory (CWD) — поточний робочий каталог процесу.

Це каталог, відносно якого інтерпретуються відносні шляхи під час виконання команд.

Для інтерактивного термінала поточний робочий каталог визначає, де саме ви перебуваєте у файловій системі.

Наприклад:

    pwd

Результат:

    /home/valer/projects

Це означає, що поточний робочий каталог:

    /home/valer/projects

Якщо виконати:

    ls

команда покаже вміст каталогу `/home/valer/projects`.

Якщо виконати:

    cd nest-exercises

поточний каталог зміниться на:

    /home/valer/projects/nest-exercises

Тепер команда:

    ls

покаже вміст каталогу `nest-exercises`.

Важливо розуміти:

    current working directory
        ↓
    relative path resolution
        ↓
    file or directory access

Наприклад, якщо поточний каталог:

    /home/valer/projects/nest-exercises

то шлях:

    practice/linux

відповідає:

    /home/valer/projects/nest-exercises/practice/linux

Поточний каталог належить конкретному процесу. Зміна каталогу в одному терміналі зазвичай не змінює каталог в іншому терміналі.

---

# pwd

`pwd` (print working directory) — команда для визначення поточного робочого каталогу.

Синтаксис:

    pwd

Приклад:

    pwd

Результат:

    /home/valer/projects/nest-exercises

Це абсолютний шлях до поточного каталогу.

---

## pwd -L

Опція `-L` показує логічний шлях, який враховує компоненти шляху та символічні посилання, якщо вони використовувалися для переходу.

    pwd -L

---

## pwd -P

Опція `-P` показує фізичний шлях без проходження через символічні посилання.

    pwd -P

Результат може відрізнятися від `pwd -L`, якщо ви перейшли до каталогу через symbolic link.

Наприклад, логічний шлях може містити:

    /home/valer/projects/current

а фізичний шлях відповідати:

    /home/valer/projects/nest-exercises

Це можливо, якщо `current` є символічним посиланням на `nest-exercises`.

На практиці:

    pwd      → показати поточний шлях
    pwd -L   → логічний шлях
    pwd -P   → фізичний шлях

У Bash `pwd` зазвичай є вбудованою командою оболонки.

---

# cd

`cd` (change directory) — команда для переходу до іншого робочого каталогу.

Синтаксис:

    cd [directory]

Наприклад:

    cd projects

Перехід до підкаталогу `projects`, якщо він існує в поточному каталозі.

Перехід за абсолютним шляхом:

    cd /home/valer/projects

Перехід за відносним шляхом:

    cd nest-exercises

Перехід до домашнього каталогу:

    cd ~

Перехід до кореня файлової системи:

    cd /

Якщо викликати `cd` без аргументів:

    cd

Bash перейде до домашнього каталогу користувача.

Перевірити результат можна командою:

    pwd

Важливо: `cd` змінює каталог поточної оболонки, а не запускає окрему програму для переходу.

---

# cd .

`.` — посилання на поточний каталог.

Наприклад:

    cd .

Ця команда зазвичай не змінює поточний каталог.

Інший приклад:

    ls .

Показує вміст поточного каталогу.

Порівняйте:

    ls
    ls .

У звичайній ситуації результат буде однаковим.

`.` часто зустрічається в шляхах:

    ./script.sh
    ./server.js
    ./node_modules

Наприклад:

    ./script.sh

Позначає файл `script.sh` у поточному каталозі.

Важливо: `.` у шляху не означає, що файл обов'язково можна виконати. Для цього потрібні відповідні права та коректний формат виконуваного файла.

---

# cd ..

`..` — посилання на батьківський каталог.

Наприклад, якщо поточний каталог:

    /home/valer/projects/nest-exercises

команда:

    cd ..

переведе вас до:

    /home/valer/projects

Ще один перехід:

    cd ..

Результат:

    /home/valer

Можна використовувати кілька рівнів:

    cd ../..

Якщо ви перебуваєте в:

    /home/valer/projects/nest-exercises/practice

то:

    cd ..

перейде до:

    /home/valer/projects/nest-exercises

А:

    cd ../..

перейде до:

    /home/valer/projects

А:

    cd ../../..

перейде до:

    /home/valer

Приклад із перевіркою:

    pwd
    cd ..
    pwd

Важливо:

    .    → поточний каталог
    ..   → батьківський каталог
    ../.. → на два рівні вище

---

# cd ~

`~` — скорочене позначення домашнього каталогу користувача в Bash.

Наприклад:

    cd ~

На Ubuntu це може привести до:

    /home/valer

Також можна використовувати:

    cd ~/projects

Перехід до:

    /home/valer/projects

Або:

    cd ~/projects/nest-exercises

Перехід до каталогу проєкту.

Корисні команди:

    cd ~
    pwd

    cd ~/projects
    pwd

    cd ~/projects/nest-exercises
    pwd

Важливо: у Bash `~` обробляється оболонкою. Це не звичайний символ, який Linux автоматично підставляє в кожному аргументі будь-якої програми.

Наприклад, лапки можуть змінити поведінку:

    cd "~/projects"

У цьому випадку Bash не виконає звичайне розгортання `~` усередині подвійних лапок, тому такий шлях може не існувати.

Правильно:

    cd ~/projects

Або:

    cd "$HOME/projects"

`$HOME` — змінна середовища, що зазвичай містить домашній каталог користувача.

---

# cd /

`/` — корінь файлової системи Linux.

Команда:

    cd /

переводить до кореневого каталогу.

Перевірка:

    pwd

Результат:

    /

Перегляд вмісту:

    ls

Детальніший перегляд:

    ls -la

Корінь `/` не слід плутати з домашнім каталогом користувача.

    /       → корінь усієї файлової системи
    /home   → каталоги звичайних користувачів
    /root   → домашній каталог root
    ~       → домашній каталог поточного користувача

Перехід до `/` сам по собі не надає адміністративних прав.

---

# cd -

`cd -` — перехід до попереднього робочого каталогу.

Ця команда особливо корисна, коли потрібно швидко перемикатися між двома каталогами.

Приклад:

    cd ~/projects
    cd ~/Downloads

Тепер поточний каталог:

    /home/valer/Downloads

Виконайте:

    cd -

Bash поверне вас до:

    /home/valer/projects

Повторне виконання:

    cd -

поверне до:

    /home/valer/Downloads

Приклад із перевіркою:

    cd ~/projects
    pwd

    cd ~/Downloads
    pwd

    cd -
    pwd

`cd -` зазвичай виводить шлях, до якого виконується перехід.

Важливо:

    cd .. → перехід до батьківського каталогу
    cd -  → повернення до попереднього каталогу

Це різні операції.

---

# Абсолютний шлях

Absolute Path — абсолютний шлях до файла або каталогу.

Абсолютний шлях починається з `/` і задає розташування від кореня файлової системи.

Наприклад:

    /home/valer/projects/nest-exercises
    /etc
    /var/log
    /usr/bin
    /home/valer/projects/nest-exercises/package.json

Припустимо, поточний каталог:

    /home/valer

Команда:

    cd /home/valer/projects/nest-exercises

переведе вас до каталогу проєкту незалежно від попереднього робочого каталогу, якщо шлях існує та доступний.

Абсолютний шлях зручно використовувати:

- у документації;
- у конфігураціях;
- у скриптах, де потрібне конкретне розташування;
- для перевірки фактичного шляху;
- під час роботи з каталогами за межами поточного проєкту.

Приклад:

    cd /etc
    pwd

Результат:

    /etc

Повернення до проєкту:

    cd /home/valer/projects/nest-exercises

---

# Відносний шлях

Relative Path — шлях, який визначається відносно поточного робочого каталогу або іншої базової директорії, заданої програмою.

Наприклад, поточний каталог:

    /home/valer/projects

Відносний шлях:

    nest-exercises

відповідає:

    /home/valer/projects/nest-exercises

Інший приклад:

    cd nest-exercises/practice

Якщо каталог існує, команда переведе до:

    /home/valer/projects/nest-exercises/practice

Порівняння:

    Absolute path:
    /home/valer/projects/nest-exercises

    Relative path:
    nest-exercises

Відносні шляхи зручні для роботи всередині проєкту, оскільки не завжди потрібно вказувати повне розташування.

Наприклад, якщо ви перебуваєте в корені репозиторію:

    nest-exercises/

то для переходу до каталогу Linux можна виконати:

    cd practice/linux

Якщо ви вже перебуваєте в:

    nest-exercises/practice

можна виконати:

    cd linux

Важливо: той самий відносний шлях може вказувати на різні місця залежно від поточного каталогу.

---

# Absolute Path vs Relative Path

Абсолютний і відносний шляхи вирішують одну задачу — вказують розташування файла або каталогу, але використовують різні початкові точки.

Абсолютний шлях:

    /home/valer/projects/nest-exercises/practice/linux

Відносний шлях із каталогу `nest-exercises`:

    practice/linux

Відносний шлях із каталогу `practice`:

    linux

Порівняння:

    /home/valer/projects/nest-exercises/practice/linux
    └── абсолютний шлях

    practice/linux
    └── відносний шлях від nest-exercises

    linux
    └── відносний шлях від practice

Правило:

    /path/to/directory → absolute path
    path/to/directory  → relative path

Абсолютний шлях починається з `/`.

Відносний шлях не починається з `/`.

Символ `~` — це спеціальне позначення домашнього каталогу в Bash, а не абсолютний шлях у буквальному вигляді.

# ls

`ls` — команда для перегляду вмісту каталогів.

Синтаксис:

    ls [options] [path]

Перегляд поточного каталогу:

    ls

Перегляд конкретного каталогу:

    ls /home/valer/projects

Перегляд підкаталогу:

    ls practice

Перегляд вмісту домашнього каталогу:

    ls ~

---

## ls -l

Опція `-l` показує детальну інформацію.

    ls -l

Приклад результату:

    drwxr-xr-x  3 valer valer 4096 Oct 19 10:00 practice
    -rw-r--r--  1 valer valer  250 Oct 19 10:00 README.md

У цьому виводі можна побачити:

    type and permissions
    number of hard links
    owner
    group
    size
    modification time
    name

Детальний формат корисний для перевірки прав, власника та розміру файлів.

---

## ls -a

Опція `-a` показує всі записи, включно з прихованими файлами та каталогами.

    ls -a

У Linux імена, які починаються з `.`, зазвичай вважаються прихованими.

Приклади:

    .git
    .gitignore
    .env
    .bashrc
    .profile

Це звичайні файли та каталоги з іменами, що починаються з крапки. Їх приховування є домовленістю інтерфейсу, а не окремим механізмом прав доступу.

---

## ls -la

Комбінація `-l` та `-a`:

    ls -la

Показує детальну інформацію про всі записи, включно з прихованими.

Це одна з найкорисніших команд для перевірки каталогу проєкту.

---

## ls -lh

Опція `-h` показує розміри у зручному для читання форматі, наприклад `K`, `M` або `G`, у поєднанні з довгим форматом.

    ls -lh

Можна поєднати опції:

    ls -lah

## ls із шляхом

Перегляд конкретної директорії без переходу до неї:

    ls ~/projects/nest-exercises/practice/linux

Перегляд лише каталогів не забезпечується звичайним `ls` автоматично, але можна використати:

    ls -d */

Ця команда показує каталоги без рекурсивного перегляду їхнього вмісту. Результат залежить від наявності каталогів, що відповідають шаблону в поточній директорії.

Для перегляду структури глибше можна використовувати `tree`.

# Hidden Files and Directories

Hidden Files — приховані файли та каталоги.

У Linux ім'я, яке починається з крапки, зазвичай не відображається звичайною командою `ls`.

Наприклад:

    .git
    .gitignore
    .env
    .bashrc
    .config

Перегляд:

    ls -a

Детальний перегляд:

    ls -la

Для розробника приховані файли особливо важливі.

Приклади в проєкті Node.js:

    .git/
    .gitignore
    .env
    .env.example
    .npmrc

Важливо:

- `.git` містить службові дані Git-репозиторію.
- `.gitignore` задає правила ігнорування файлів Git.
- `.env` часто містить змінні середовища.
- `.env.example` може містити приклад потрібних змінних без секретних значень.
- Прихований файл не є автоматично захищеним від читання.

Не публікуйте паролі, токени та інші секрети в репозиторіях.

# Navigation in a Developer Project

Під час розробки важливо розуміти структуру проєкту та вміти переходити між його частинами.

Наприклад, структура `nest-exercises`:

    nest-exercises/
    ├── practice/
    │   ├── linux/
    │   │   ├── README.md
    │   │   ├── 01-linux-fundamentals/
    │   │   ├── 02-files-and-directories/
    │   │   ├── 11-bash-scripting/
    │   │   └── 12-developer-workflow/
    │   └── server/
    ├── package.json
    └── README.md

Перехід до кореня проєкту:

    cd ~/projects/nest-exercises

Перегляд файлів:

    ls -la

Перехід до Linux:

    cd practice/linux

Перегляд розділів:

    ls

Перехід до developer workflow:

    cd 12-developer-workflow

Перегляд вмісту:

    ls -la

Повернення до каталогу `linux`:

    cd ..

Повернення до кореня проєкту:

    cd ../..

Перевірка:

    pwd

Важливо: якщо команда має виконуватися з кореня проєкту, перед її запуском переконайтеся, що ви перебуваєте саме там.

Наприклад, `npm install` зазвичай потрібно запускати в каталозі, де розташований відповідний `package.json`.

# Directory Tree

`tree` — команда для відображення структури каталогів у вигляді дерева.

Приклад:

    tree

Можливий результат:

    .
    ├── README.md
    ├── package.json
    ├── practice
    │   ├── linux
    │   │   ├── README.md
    │   │   └── 12-developer-workflow
    │   └── server
    └── src

Перегляд лише верхнього рівня та одного рівня вкладеності:

    tree -L 2

Перегляд конкретного каталогу:

    tree practice/linux

Перегляд лише каталогів:

    tree -d

Перегляд із обмеженням глибини:

    tree -L 3 practice/linux

`tree` може бути не встановлений у системі.

В Ubuntu його можна встановити так:

    sudo apt update
    sudo apt install tree

Після встановлення:

    tree -L 2

Якщо встановлювати додаткову програму не потрібно, можна скористатися `ls` або `find`.

# find

`find` — команда для пошуку файлів і каталогів у файловій системі.

Хоча `find` належить до інструментів пошуку, він корисний і для вивчення структури каталогів.

Загальний синтаксис:

    find [path] [expression]

Переглянути записи в поточному каталозі та його підкаталогах:

    find .

Знайти всі каталоги в поточній директорії та нижче:

    find . -type d

Знайти всі звичайні файли:

    find . -type f

Знайти каталоги з назвою `linux`:

    find . -type d -name "linux"

Знайти файли `README.md`:

    find . -type f -name "README.md"

Знайти всі каталоги на першому рівні:

    find . -maxdepth 1 -type d

Знайти файли з розширенням `.md`:

    find . -type f -name "*.md"

Важливо: шаблони на кшталт `"*.md"` потрібно брати в лапки, щоб їх обробила команда `find`, а не Bash до запуску команди.

# realpath

`realpath` — команда для отримання абсолютного шляху до файла або каталогу з розв'язанням компонентів шляху та символічних посилань.

Приклад:

    realpath .

Можливий результат:

    /home/valer/projects/nest-exercises

Отримати абсолютний шлях до каталогу:

    realpath practice/linux

Це корисно, якщо потрібно побачити, куди фактично веде відносний шлях.

Наприклад, поточний каталог:

    /home/valer/projects/nest-exercises

Команда:

    realpath practice/linux

поверне абсолютний шлях до `practice/linux`, якщо він існує.

Зверніть увагу: поведінка щодо шляхів, які ще не існують, залежить від реалізації `realpath` та її опцій.

---

# dirname

`dirname` — команда для отримання каталогу, що міститься в шляху.

Наприклад:

    dirname /home/valer/projects/nest-exercises/package.json

Результат:

    /home/valer/projects/nest-exercises

Ще приклад:

    dirname /home/valer/projects/nest-exercises/practice/linux/README.md

Результат:

    /home/valer/projects/nest-exercises/practice/linux

Команда не переходить до каталогу. Вона лише обробляє рядок шляху.

# basename

`basename` — команда для отримання останнього компонента шляху.

Приклад:

    basename /home/valer/projects/nest-exercises/package.json

Результат:

    package.json

Інший приклад:

    basename /home/valer/projects/nest-exercises/practice/linux

Результат:

    linux

Порівняння:

    dirname /home/valer/projects/nest-exercises/package.json
    → /home/valer/projects/nest-exercises

    basename /home/valer/projects/nest-exercises/package.json
    → package.json

Ці команди зручні у Bash-скриптах, коли потрібно розділити шлях на каталог та ім'я.

# Directory Names with Spaces

Назви каталогів можуть містити пробіли.

Наприклад:

    My Projects
    Node Exercises
    Linux Practice

Якщо назва містить пробіл, її потрібно правильно передати команді.

## Подвійні лапки

    cd "My Projects"

## Одинарні лапки

    cd 'My Projects'

## Екранування пробілу

    cd My\ Projects

Усі три варіанти можуть використовуватися для переходу до каталогу `My Projects`.

Неправильно:

    cd My Projects

У цьому випадку Bash передасть `My` та `Projects` як окремі аргументи, а `cd` не сприйматиме їх як одну назву каталогу.

Те саме стосується інших команд:

    ls "My Projects"
    find "My Projects" -type f

У практичній роботі з проєктами бажано уникати зайвих пробілів у назвах директорій, якщо вони не потрібні.

# Tab Completion

Tab Completion — автоматичне доповнення команд, імен файлів та каталогів у терміналі.

У Bash для цього використовується клавіша `Tab`.

Наприклад, ви перебуваєте в:

    /home/valer/projects

і хочете перейти до:

    nest-exercises

Почніть вводити:

    cd nest

Натисніть `Tab`.

Якщо збіг однозначний, Bash може доповнити команду:

    cd nest-exercises

Якщо існує кілька варіантів, Bash може не доповнити назву відразу. Натисніть `Tab` повторно, щоб переглянути можливі варіанти, якщо така поведінка налаштована у вашій оболонці.

Приклад:

    cd ~/projects/nest-exercises/practice/linux/12-developer-workflow/

Можна вводити шлях частинами та доповнювати назви через `Tab`.

Переваги:

- менше ручного введення;
- менше помилок у назвах;
- швидша навігація;
- зручна робота з довгими шляхами;
- швидкий доступ до файлів і каталогів.

Важливо: Tab completion залежить від налаштувань оболонки. Для простого доповнення шляхів не завжди потрібен окремий пакет `bash-completion`.

# Bash History

Bash History — історія команд, які вводилися в оболонці.

Основна команда:

    history

Показати останні команди:

    history

Пошук у виводі історії:

    history | grep "cd"

Так можна знайти попередні команди переходу між каталогами.

Для повторного використання команд зручно натискати стрілки:

    ↑ → попередня команда
    ↓ → наступна команда в історії

Пошук назад у Bash:

    Ctrl + R

Наприклад, натисніть `Ctrl + R` і почніть вводити:

    cd ~/projects

Bash спробує знайти відповідну команду в історії.

Це допомагає швидко повертатися до довгих команд переходу, не вводячи їх повторно.

# pushd

`pushd` — команда Bash для переходу до каталогу зі збереженням попереднього каталогу в стеку директорій.

Синтаксис:

    pushd [directory]

Приклад:

    cd ~/projects
    pushd ~/Downloads

Команда перейде до `~/Downloads`, а попередній каталог буде збережено в стеку.

Переглянути стек можна командою:

    dirs

Результат залежить від поточного стану стеку.

`pushd` корисний, коли потрібно тимчасово перейти до іншого каталогу, а потім повернутися до попереднього.

---

# popd

`popd` — команда Bash для видалення верхнього каталогу зі стеку директорій і переходу до наступного каталогу в стеку.

Приклад:

    cd ~/projects
    pushd ~/Downloads

Тепер виконайте:

    popd

Bash поверне вас до каталогу, з якого було виконано `pushd`, та видалить відповідний запис зі стеку.

Перевірка:

    pwd
    dirs

Порівняння:

    cd -
    → перемикання між поточним і попереднім каталогами

    pushd
    → робота зі стеком каталогів і перехід

    popd
    → видалення верхнього запису зі стеку та перехід

Для звичайної щоденної навігації часто достатньо `cd`, `cd ..` та `cd -`. `pushd` і `popd` корисніші в складніших сценаріях.

---

# Directory Stack

Directory Stack — стек каталогів, який підтримується Bash.

Основні команди:

    dirs
    pushd
    popd

Перегляд стеку:

    dirs

Додавання каталогу до стеку та перехід:

    pushd ~/Downloads

Повернення до попереднього каталогу зі стеку:

    popd

Спрощена модель:

    pushd directory
        ↓
    save previous directory
        ↓
    change directory
        ↓
    popd
        ↓
    return to saved directory

Стек каталогів може бути корисним, якщо потрібно тимчасово переходити між кількома директоріями.

Для базової навігації достатньо розуміти призначення цих команд без глибокого вивчення всіх можливостей Bash.

# Symbolic Links

Symbolic Link (символічне посилання) — спеціальний тип файлової системи, який вказує на інший шлях.

Наприклад, посилання:

    /home/valer/projects/current

може вказувати на:

    /home/valer/projects/nest-exercises

Якщо `current` є символічним посиланням на каталог проєкту, можна виконати:

    cd ~/projects/current

Перевірити поточний шлях:

    pwd

Порівняти логічний та фізичний шлях:

    pwd -L
    pwd -P

Переглянути інформацію про посилання:

    ls -l ~/projects/current

Символічні посилання дозволяють звертатися до каталогу через інше ім'я.

Важливо:

- посилання не є копією каталогу;
- ціль посилання може бути переміщена або видалена;
- посилання може стати неробочим;
- фізичний шлях може відрізнятися від логічного;
- доступ до цілі залежить від прав та стану файлової системи.

# PATH Environment Variable

`PATH` — змінна середовища, що містить список каталогів, у яких оболонка шукає виконувані команди, якщо команда задана без шляху.

Переглянути значення:

    echo "$PATH"

Приклад умовного значення:

    /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Каталоги розділяються двокрапками `:`.

Якщо виконати:

    node --version

Bash шукає виконуваний файл `node` у каталогах, указаних у `PATH`, відповідно до правил пошуку команд.

Перевірити розташування команди:

    command -v node

Інші приклади:

    command -v npm
    command -v git
    command -v code

Важливо не плутати:

    PATH
    → пошук виконуваних команд

    current working directory
    → база для інтерпретації відносних шляхів

Зміна робочого каталогу не змінює `PATH` автоматично.

Для запуску скрипта з поточного каталогу можна вказати шлях явно:

    ./script.sh

Це не те саме, що:

    script.sh

У другому випадку Bash зазвичай шукає команду через `PATH`, а не обов'язково в поточному каталозі.

# Navigation and Permissions

Для переходу до каталогу недостатньо знати його шлях — користувач повинен мати необхідні права доступу.

Наприклад:

    cd /root

Звичайний користувач зазвичай не може перейти до домашнього каталогу `root`, якщо права доступу цього не дозволяють.

Для пошуку або доступу до файлів у каталозі важливі права на відповідні каталоги.

Для каталогів:

    r → перегляд списку імен за відповідних умов доступу
    w → зміна записів каталогу за відповідних умов доступу
    x → пошук і доступ до елементів каталогу за відомими іменами

Права доступу детально розглядаються в розділі:

    05-permissions-and-ownership

Якщо отримано помилку:

    Permission denied

це означає, що поточна операція заборонена через права доступу або інші механізми контролю доступу.

Не варто автоматично використовувати `sudo` для кожної такої помилки. Спочатку потрібно зрозуміти, до якого каталогу ви звертаєтеся та чи справді потрібні адміністративні права.

# Navigation Errors

Під час навігації найчастіше виникають помилки, пов'язані з неправильним шляхом або поточним каталогом.

## No such file or directory

Приклад:

    cd nest-exercise

Помилка:

    bash: cd: nest-exercise: No such file or directory

Можливі причини:

- неправильна назва каталогу;
- помилка в написанні;
- каталог розташований в іншому місці;
- ви перебуваєте не в тому каталозі;
- регістр літер відрізняється.

Перевірка:

    pwd
    ls

Пошук потрібного каталогу:

    find ~/projects -type d -name "nest-exercises"

---

## Permission denied

Приклад:

    cd /root

Можлива причина — відсутність прав доступу.

Перевірка:

    ls -ld /root

Права доступу та власники розглядаються в розділі:

    05-permissions-and-ownership

---

## Not a directory

Якщо спробувати перейти до звичайного файла:

    cd package.json

Bash повідомить, що це не каталог.

Перевірка:

    ls -l package.json

Перехід через `cd` можливий лише до каталогу або до шляху, який веде до каталогу.

    cd documents

може завершитися помилкою, оскільки `Documents` і `documents` — різні імена в Linux.

Перевірка:

# Practical Examples

    pwd

    /home/valer/projects

## Приклад 2 — переглянути вміст каталогу

# Типові помилки

❌ **Не перевіряти поточний каталог перед виконанням команди.**

Наприклад:

    pwd
    ls

Корисно перевіряти каталог, якщо ви не впевнені, де перебуваєте.

---

❌ **Плутати абсолютний та відносний шляхи.**

    /home/valer/projects
    projects

Перший шлях абсолютний, а другий залежить від поточного каталогу.

---

❌ **Вважати `cd ..` і `cd -` однаковими командами.**

    cd .. → батьківський каталог
    cd -  → попередній каталог

---

❌ **Вважати `~` коренем файлової системи.**

    ~ → домашній каталог користувача
    / → корінь файлової системи

---

❌ **Не враховувати регістр літер.**

    Linux
    linux
    LINUX

Це можуть бути три різні назви.

---

❌ **Не брати назву каталогу з пробілами в лапки.**

    cd "My Projects"

---

❌ **Використовувати відносний шлях, не знаючи поточного каталогу.**

Перед переходом можна виконати:

    pwd

---

❌ **Вважати, що приховані файли не існують.**

Звичайна команда:

    ls

не показує всі записи.

Використовуйте:

    ls -a

---

❌ **Плутати поточний каталог із `PATH`.**

    pwd
    echo "$PATH"

Перша команда показує поточний каталог, а друга — список каталогів пошуку виконуваних команд.

---

❌ **Вважати, що `cd` працює з файлами так само, як із каталогами.**

    cd package.json

не працюватиме, якщо `package.json` — звичайний файл.

---

❌ **Вважати, що перехід до каталогу автоматично надає права доступу.**

Навігація та permissions — різні поняття.

# Головне

• Навігація каталогами — базова навичка роботи в Linux-терміналі.

• `pwd` показує поточний робочий каталог.

• `cd` змінює поточний робочий каталог.

• `ls` показує вміст каталогу.

• `cd ..` переходить до батьківського каталогу.

• `cd -` повертає до попереднього робочого каталогу.

• `cd ~` переходить до домашнього каталогу.

• `/` — корінь файлової системи, а `~` — домашній каталог користувача.

• `.` означає поточний каталог, а `..` — батьківський.

• Абсолютний шлях починається з `/`.

• Відносний шлях залежить від поточного робочого каталогу.

• Linux розрізняє великі та малі літери в назвах.

• Для перегляду прихованих файлів використовуйте `ls -a`.

• Для вивчення структури каталогів корисні `tree` та `find`.

• `realpath` допомагає отримати абсолютний шлях.

• `dirname` повертає каталог із заданого шляху, а `basename` — останній компонент.

• Tab completion дозволяє швидше вводити шляхи та зменшує кількість помилок.

• `pushd` і `popd` дають змогу працювати зі стеком каталогів.

• `PATH` відповідає за пошук виконуваних команд, а не за визначення поточного каталогу.

• Для навігації до каталогу потрібні відповідні права доступу.

• У розробці важливо розуміти, де розташований корінь проєкту та звідки запускаються команди.

• Перед виконанням важливих команд корисно перевіряти:

    pwd
    ls -la

• Для переходу до конкретного проєкту зручно використовувати абсолютний шлях:

    cd ~/projects/nest-exercises

• Для навігації всередині проєкту зручно використовувати відносні шляхи:

    cd practice/linux

• Основна модель навігації:

    current directory
          ↓
    choose path
          ↓
    execute cd
          ↓
    new current directory
          ↓
    verify with pwd

• Головна практична навичка — завжди розуміти, де ви перебуваєте, куди переходите та відносно якого каталогу інтерпретується ваш шлях.
