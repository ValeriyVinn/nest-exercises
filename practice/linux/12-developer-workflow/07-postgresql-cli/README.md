# PostgreSQL CLI — робота з PostgreSQL через термінал

PostgreSQL CLI — це набір командних інструментів для роботи з PostgreSQL без графічного інтерфейсу.

За допомогою термінала можна підключатися до сервера PostgreSQL, створювати бази даних і таблиці, виконувати SQL-запити, перевіряти дані, керувати ролями та діагностувати проблеми з підключенням.

Для Full Stack Developer робота з PostgreSQL через CLI особливо корисна під час розробки Node.js, Express, NestJS і Next.js застосунків.

---

## 1. Основні інструменти PostgreSQL CLI

### 1.1. `psql`

`psql` — інтерактивний термінальний клієнт PostgreSQL.

Він дозволяє:
- ✔ Підключатися до сервера PostgreSQL.
- ✔ Вибирати базу даних.
- ✔ Виконувати SQL-запити.
- ✔ Створювати таблиці та індекси.
- ✔ Переглядати структуру бази даних.
- ✔ Керувати ролями й правами доступу.
- ✔ Виконувати SQL-файли.
- ✔ Експортувати та імпортувати дані.

Приклад:

    psql -U postgres -d postgres

Після успішного підключення з'явиться запрошення приблизно такого вигляду:

    postgres=#

Це означає, що ти перебуваєш усередині інтерактивного клієнта `psql`.

### 1.2. `pg_isready`

Перевіряє, чи приймає сервер PostgreSQL підключення.

    pg_isready

Приклад відповіді:

    /var/run/postgresql:5432 - accepting connections

Це означає, що сервер приймає підключення за вказаною адресою.

Важливо: `pg_isready` перевіряє готовність сервера приймати з'єднання, але не підтверджує, що конкретний користувач має правильний пароль або права доступу до потрібної бази даних.

### 1.3. `createdb`

Створює базу даних.

    createdb -U postgres my_database

Ця команда є оболонкою над SQL-командою `CREATE DATABASE`.

### 1.4. `dropdb`

Видаляє базу даних.

    dropdb -U postgres my_database

**Увага:** команда видаляє базу даних. Переконайся, що в ній немає потрібних даних і ти підключений до правильного сервера.

### 1.5. `pg_dump`

Створює логічну резервну копію бази даних.

    pg_dump -U postgres -d my_database -f backup.sql

### 1.6. `pg_restore`

Відновлює базу даних із резервної копії, створеної у спеціальному форматі `pg_dump`.

    pg_restore -U postgres -d my_database backup.dump

На відміну від звичайного текстового SQL-файлу, файл спеціального формату можна створити, наприклад, за допомогою параметра `-Fc`.

    pg_dump -U postgres -d my_database -Fc -f backup.dump

## 2. Перевірка встановлення PostgreSQL

Перед підключенням потрібно переконатися, що необхідні інструменти доступні в терміналі.

### 2.1. Перевірити версію клієнта

    psql --version

Приклад:

    psql (PostgreSQL) 18.6

Ця команда показує версію клієнта `psql`, а не обов'язково версію сервера, до якого ти підключаєшся.

### 2.2. Перевірити розташування команд

    which psql
    which pg_isready
    which pg_dump

Альтернативний спосіб:

    command -v psql
    command -v pg_isready

`command -v` показує, яку команду Bash знайде у своєму середовищі.

### 2.3. Перевірити готовність сервера

    pg_isready

Якщо сервер приймає підключення, результат міститиме:

    accepting connections

Якщо сервер не запущений або недоступний, можливі повідомлення про відмову в підключенні чи відсутність відповіді.

### 2.4. Перевірити службу PostgreSQL в Ubuntu

    systemctl status postgresql

Запустити службу:

    sudo systemctl start postgresql

Перезапустити службу:

    sudo systemctl restart postgresql

Перевірити, чи служба автоматично запускається під час завантаження системи:

    systemctl is-enabled postgresql

У деяких конфігураціях Ubuntu служба `postgresql` керує одним або кількома кластерами PostgreSQL. Стан загальної служби не завжди пояснює, який саме кластер працює.

Для додаткової перевірки в Debian/Ubuntu можна використати:

    pg_lsclusters

Ця команда показує встановлені кластери PostgreSQL, їхні версії, порти та стани.

## 3. Підключення до PostgreSQL

### 3.1. Основний синтаксис `psql`

    psql -h HOST -p PORT -U USERNAME -d DATABASE

Параметри:

- `-h` — адреса сервера.
- `-p` — порт PostgreSQL.
- `-U` — ім'я ролі PostgreSQL.
- `-d` — назва бази даних.

Типовий порт PostgreSQL — `5432`, але він може бути змінений.

### 3.2. Підключення до локальної бази

    psql -U postgres -d postgres

Тут:
- `postgres` після `-U` — ім'я ролі.
- `postgres` після `-d` — назва бази даних.

Це два окремі параметри, хоча значення в прикладі однакові.

### 3.3. Підключення із зазначенням адреси та порту

    psql -h localhost -p 5432 -U postgres -d my_database

Якщо сервер працює на іншому порту, вкажи фактичний порт.

### 3.4. Підключення до локальної бази за назвою

Якщо налаштована автентифікація дозволяє поточному системному користувачеві підключатися до однойменної ролі PostgreSQL, можна використати:

    psql -d my_database

Якщо ім'я користувача PostgreSQL відрізняється від імені системного користувача, вкажи `-U`.

### 3.5. Підключення під системним користувачем `postgres`

У багатьох локальних інсталяціях Ubuntu адміністративний доступ до PostgreSQL налаштований через автентифікацію `peer`.

Тоді можна виконати:

    sudo -u postgres psql

Ця команда запускає `psql` від імені системного користувача `postgres`.

Вона не є універсальною для всіх серверів: спосіб автентифікації залежить від конфігурації PostgreSQL.

### 3.6. Підключення до віддаленого сервера

    psql -h db.example.com -p 5432 -U app_user -d app_database

Для віддаленого сервера можуть бути потрібні пароль, налаштований доступ за мережею, правила `pg_hba.conf` і параметри TLS.

Не вказуй пароль безпосередньо в командному рядку, оскільки він може потрапити в історію команд або бути видимим у списку процесів.

## 4. Основні команди всередині `psql`

Команди `psql`, які починаються з `\`, називаються метакомандами. Вони не є SQL-командами.

### 4.1. Показати список баз даних

    \l

Альтернативний варіант:

    \list

### 4.2. Підключитися до іншої бази

    \c my_database

Або:

    \connect my_database

Для підключення до іншої бази даних потрібна відповідна доступність і права.

### 4.3. Показати таблиці

    \dt

Показати таблиці у всіх схемах, доступних у поточній базі:

    \dt *.*

### 4.4. Показати схеми

    \dn

Схема — це логічний простір імен, у якому розміщуються таблиці, представлення та інші об'єкти бази даних.

Наприклад, типова схема — `public`.

### 4.5. Показати структуру таблиці

    \d users

Детальніший варіант:

    \d+ users

Команда показує стовпці, типи даних, індекси та іншу інформацію про таблицю.

### 4.6. Показати ролі

    \du

Або:

    \dg

### 4.7. Показати поточне підключення

    \conninfo

### 4.8. Показати історію команд

    \s

Ця команда показує історію команд `psql` поточного сеансу, якщо вона доступна.

### 4.9. Очистити екран

    \! clear

Це запускає системну команду `clear` через оболонку.

### 4.10. Вийти з `psql`

    \q

Це завершує роботу інтерактивного клієнта.

## 5. Корисні SQL-запити для перевірки

Метакоманди `psql` починаються з `\`, а SQL-команди зазвичай завершуються крапкою з комою `;`.

### 5.1. Перевірити поточну базу даних

    SELECT current_database();

### 5.2. Перевірити поточного користувача

    SELECT current_user;

### 5.3. Перевірити версію сервера

    SELECT version();

### 5.4. Перевірити порт сервера

    SHOW port;

### 5.5. Переглянути поточні налаштування

    SHOW search_path;

`search_path` визначає, у яких схемах PostgreSQL шукає об'єкти, якщо назву схеми не вказано явно.

### 5.6. Переглянути бази даних через SQL

    SELECT datname
    FROM pg_database
    ORDER BY datname;

### 5.7. Переглянути таблиці у схемі `public`

    SELECT table_name
    FROM information_schema.tables
    WHERE table_schema = 'public'
      AND table_type = 'BASE TABLE'
    ORDER BY table_name;

### 5.8. Переглянути стовпці таблиці

    SELECT
        column_name,
        data_type,
        is_nullable
    FROM information_schema.columns
    WHERE table_schema = 'public'
      AND table_name = 'users'
    ORDER BY ordinal_position;

## 6. Створення бази даних через CLI

### 6.1. Створити базу через `psql`

Підключись до адміністративної бази:

    psql -U postgres -d postgres

Виконай SQL:

    CREATE DATABASE my_database;

Перевір:

    \l

### 6.2. Створити базу командою `createdb`

    createdb -U postgres my_database

Обидва способи створюють базу даних, але перший працює всередині `psql`, а другий запускається безпосередньо з термінала.

### 6.3. Створити базу з власником

У `psql`:

    CREATE DATABASE my_database OWNER app_user;

Роль `app_user` має існувати до створення бази.

### 6.4. Видалити базу

У `psql`:

    DROP DATABASE my_database;

Або з термінала:

    dropdb -U postgres my_database

**Увага:** видалення бази даних є руйнівною операцією. Перед виконанням перевір назву бази, сервер і наявність резервної копії.

Не можна видалити базу, до якої ти зараз підключений. Спочатку переключись на іншу базу, наприклад `postgres`.

## 7. Робота з таблицями через CLI

### 7.1. Створити таблицю

Підключись до потрібної бази:

    psql -U postgres -d my_database

Створи таблицю:

    CREATE TABLE users (
        id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        name TEXT NOT NULL,
        email TEXT UNIQUE,
        created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

### 7.2. Перевірити структуру

    \d users

### 7.3. Додати дані

    INSERT INTO users (name, email)
    VALUES ('Olena', 'olena@example.com');

### 7.4. Переглянути дані

    SELECT * FROM users;

### 7.5. Вибрати окремі стовпці

    SELECT id, name, email
    FROM users
    ORDER BY id;

### 7.6. Оновити дані

    UPDATE users
    SET name = 'Olena Kovalenko'
    WHERE id = 1;

Перед `UPDATE` переконайся, що умова `WHERE` відповідає потрібним рядкам.

### 7.7. Видалити рядок

    DELETE FROM users
    WHERE id = 1;

Без `WHERE` команда може видалити всі рядки таблиці.

### 7.8. Видалити таблицю

    DROP TABLE users;

**Увага:** `DROP TABLE` видаляє саму таблицю та її дані. Використовуй цю команду лише тоді, коли справді потрібно видалити об'єкт.

## 8. Виконання SQL-файлів

У реальних проєктах SQL-запити часто зберігають у файлах.

### 8.1. Створити SQL-файл

Наприклад, `schema.sql`:

    CREATE TABLE IF NOT EXISTS colors (
        id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        name TEXT NOT NULL UNIQUE,
        hex VARCHAR(7) NOT NULL
    );

### 8.2. Виконати файл через `psql`

    psql -U postgres -d my_database -f schema.sql

Параметр `-f` вказує файл, який потрібно виконати.

### 8.3. Виконати файл із зупинкою при помилці

    psql -v ON_ERROR_STOP=1 -U postgres -d my_database -f schema.sql

Параметр `ON_ERROR_STOP=1` змушує `psql` припинити виконання сценарію після SQL-помилки.

Це корисно для навчальних скриптів, міграцій і автоматизованих процесів.

### 8.4. Виконати короткий SQL-запит із термінала

    psql -U postgres -d my_database -c "SELECT current_database();"

Параметр `-c` виконує переданий SQL-запит і завершує клієнт після виконання команди.

### 8.5. Виконати файл у поточному сеансі

Якщо ти вже всередині `psql`:

    \i schema.sql

Шлях до файлу інтерпретується відносно поточної робочої директорії процесу `psql`, а не обов'язково відносно директорії, де розташована база даних.

## 9. Резервне копіювання та відновлення

Резервні копії потрібні, щоб відновити дані після помилки, втрати файлів або невдалого оновлення.

### 9.1. Створити SQL-дамп

    pg_dump -U postgres -d my_database -f backup.sql

Це створює текстовий SQL-файл.

### 9.2. Відновити SQL-дамп

Спочатку створи порожню базу:

    createdb -U postgres my_database_restored

Потім виконай дамп:

    psql -U postgres -d my_database_restored -f backup.sql

### 9.3. Створити дамп у custom-форматі

    pg_dump -U postgres -d my_database -Fc -f backup.dump

Цей формат призначений для використання з `pg_restore` і підтримує гнучкіший вибір об'єктів під час відновлення.

### 9.4. Відновити custom-дамп

    createdb -U postgres my_database_restored

    pg_restore -U postgres -d my_database_restored backup.dump

### 9.5. Перевірити резервну копію

Наявність файлу ще не гарантує, що його можна успішно відновити.

Перевір розмір:

    ls -lh backup.sql

Для custom-формату можна переглянути зміст:

    pg_restore --list backup.dump

Найнадійніша перевірка — пробне відновлення в окрему тестову базу.

**Важливо:** дамп може містити конфіденційні дані. Зберігай його в захищеному місці та не додавай до публічного Git-репозиторію.

## 10. Ролі та права доступу

У PostgreSQL ролі визначають, хто може підключатися до сервера та які дії виконувати.

### 10.1. Переглянути ролі

У `psql`:

    \du

### 10.2. Створити роль із можливістю входу

    CREATE ROLE app_user WITH LOGIN;

### 10.3. Задати пароль

    \password app_user

Метакоманда `\password` дозволяє задати пароль інтерактивно, не вставляючи його безпосередньо в SQL-команду.

### 10.4. Створити базу для застосунку

    CREATE DATABASE app_database OWNER app_user;

### 10.5. Надати право підключення до бази

    GRANT CONNECT ON DATABASE app_database TO app_user;

Право власника бази та інші привілеї залежать від того, як саме створено об'єкти. Якщо роль не є власником, можуть знадобитися окремі дозволи на схеми, таблиці та послідовності.

### 10.6. Переглянути права в `psql`

    \l

Для прав на таблиці:

    \dp

### 10.7. Принцип мінімальних привілеїв

Для застосунку краще використовувати окрему роль, яка має лише необхідні права.

Не використовуй суперкористувача `postgres` для звичайного підключення вебзастосунку.

## 11. Змінні середовища для підключення

Щоб не повторювати параметри підключення, можна використовувати змінні середовища, які підтримує `libpq` — бібліотека клієнтського підключення PostgreSQL.

Наприклад:

    export PGHOST=localhost
    export PGPORT=5432
    export PGUSER=app_user
    export PGDATABASE=app_database

Після цього можна виконати:

    psql

Клієнт використає задані значення за замовчуванням, якщо їх не перевизначено параметрами командного рядка.

### 11.1. Вказати змінні лише для однієї команди

    PGHOST=localhost PGPORT=5432 PGUSER=app_user PGDATABASE=app_database psql

Це не зберігає змінні в поточній оболонці після виконання команди.

### 11.2. Перевірити значення

    printenv PGHOST
    printenv PGPORT
    printenv PGUSER
    printenv PGDATABASE

Не виводь секрети у спільному терміналі або публічних логах.

### 11.3. Пароль підключення

Не записуй пароль у команду такого вигляду:

    psql postgresql://app_user:my_password@localhost/app_database

Пароль у командному рядку може залишитися в історії оболонки або бути видимим іншим процесам.

Для інтерактивного підключення краще дозволити клієнту запросити пароль. Для автоматизації використовуй відповідний захищений механізм, наприклад файл `.pgpass` із належними правами або сховище секретів.

### 11.4. Файл `.pgpass`

На Linux типовий шлях:

    ~/.pgpass

Приклад структури рядка:

    hostname:port:database:username:password

Наприклад, для локального сервера:

    localhost:5432:app_database:app_user:REPLACE_WITH_PASSWORD

Заміни прикладове значення на справжній пароль локально, не публікуючи його.

Захисти файл:

    chmod 600 ~/.pgpass

PostgreSQL може ігнорувати `.pgpass`, якщо його права доступу занадто відкриті.

**Не додавай `.pgpass` до Git.**

## 12. Підключення до PostgreSQL із Node.js-проєкту

У розробці часто потрібно перевірити, чи доступна база для застосунку.

### 12.1. Перевірити підключення через `psql`

    psql -h localhost -p 5432 -U app_user -d app_database

Якщо підключення успішне, виконай:

    SELECT current_database(), current_user;

Це дозволяє перевірити, до якої бази та під якою роллю ти підключився.

### 12.2. Використовувати `.env` у Node.js

Приклад `.env`:

    DATABASE_URL=postgresql://app_user:REPLACE_WITH_PASSWORD@localhost:5432/app_database

Не зберігай справжній пароль у публічному файлі або Git-репозиторії.

Запуск Node.js із завантаженням змінних:

    node --env-file=.env server.js

### 12.3. Перевірити змінну в Node.js

    if (!process.env.DATABASE_URL) {
      throw new Error("DATABASE_URL is required");
    }

    console.log("DATABASE_URL is configured");

Не виводь саме значення URL, оскільки воно може містити пароль.

### 12.4. Перевірити підключення за допомогою `pg`

Якщо проєкт використовує пакет `pg`, приклад перевірки:

    import pg from "pg";

    const { Client } = pg;

    const connectionString = process.env.DATABASE_URL;

    if (!connectionString) {
      throw new Error("DATABASE_URL is required");
    }

    const client = new Client({
      connectionString,
    });

    try {
      await client.connect();

      const result = await client.query(
        "SELECT current_database(), current_user"
      );

      console.log("Database connection successful");
      console.log(result.rows[0]);
    } finally {
      await client.end();
    }

Цей приклад передбачає, що пакет `pg` установлено, `.env` завантажується під час запуску Node.js, а проєкт налаштовано на ES Modules.

## 13. Діагностика типових помилок

### Помилка 1. `psql: command not found`

Можливі причини:

- клієнт PostgreSQL не встановлено;
- каталог із програмою відсутній у `PATH`;
- встановлено сервер, але клієнтські інструменти недоступні.

Перевір:

    command -v psql
    psql --version

В Ubuntu клієнт можна встановити окремо:

    sudo apt update
    sudo apt install postgresql-client

Це встановлює клієнтські інструменти й не обов'язково встановлює локальний сервер.

### Помилка 2. `connection refused`

Можливі причини:

- сервер не запущений;
- неправильний порт;
- неправильна адреса;
- сервер не слухає потрібний інтерфейс.

Перевір:

    pg_isready -h localhost -p 5432

Для локальної інсталяції Ubuntu:

    systemctl status postgresql
    pg_lsclusters

### Помилка 3. `password authentication failed`

Можливі причини:

- неправильний пароль;
- неправильне ім'я ролі;
- сервер використовує інший механізм автентифікації;
- підключення здійснюється не до того сервера.

Перевір адресу, порт, ім'я ролі та спосіб автентифікації. Не змінюй конфігурацію сервера навмання.

### Помилка 4. `database does not exist`

Перевір список баз даних:

    psql -U postgres -d postgres

Усередині `psql`:

    \l

Переконайся, що назва бази вказана правильно.

### Помилка 5. `role does not exist`

Переглянь ролі:

    \du

Якщо роль справді відсутня, її може створити адміністратор PostgreSQL:

    CREATE ROLE app_user WITH LOGIN;

Створюй ролі лише з потрібними правами.

### Помилка 6. `permission denied`

Причина — у ролі недостатньо прав на базу, схему, таблицю або інший об'єкт.

Перевір:

    \conninfo
    \du
    \dp

Також переконайся, що працюєш із правильною базою та схемою.

### Помилка 7. `no pg_hba.conf entry`

Сервер не знайшов відповідного правила автентифікації для цього підключення.

Адміністратору потрібно перевірити правила в `pg_hba.conf`, адресу клієнта, назву бази, роль і потрібний метод автентифікації.

Не розв'язуй проблему відкриттям доступу для всіх адрес без належного обмеження.

### Помилка 8. Команда SQL не виконується в `psql`

Перевір, чи завершив ти SQL-команду крапкою з комою:

    SELECT current_database();

Якщо запрошення змінилося на продовження команди, наприклад `postgres-#`, можливо, SQL-команда ще не завершена.

Щоб перервати поточне введення:

    Ctrl + C

### Помилка 9. `pg_dump` не може підключитися

Перевір ті самі параметри, що й для `psql`:

- адресу;
- порт;
- ім'я ролі;
- базу даних;
- автентифікацію;
- доступність сервера.

Також перевір версію клієнтських інструментів:

    pg_dump --version

## 15. Мініпрактика: створення навчальної бази

Мета — навчитися підключатися до PostgreSQL, створювати базу, таблицю та перевіряти результат.

### Крок 1. Перевір сервер

    pg_isready

### Крок 2. Підключись до адміністративної бази

    psql -U postgres -d postgres

Якщо локальна Ubuntu використовує `peer`-автентифікацію для системного користувача `postgres`, можна виконати:

    sudo -u postgres psql

### Крок 3. Створи навчальну базу

    CREATE DATABASE cli_practice;

### Крок 4. Підключись до неї

    \c cli_practice

### Крок 5. Створи таблицю

    CREATE TABLE colors (
        id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
        name TEXT NOT NULL UNIQUE,
        hex VARCHAR(7) NOT NULL
    );

### Крок 6. Додай дані

    INSERT INTO colors (name, hex)
    VALUES
        ('red', '#FF0000'),
        ('lime', '#00FF00'),
        ('blue', '#0000FF');

### Крок 7. Перевір таблицю

    \dt
    \d colors
    SELECT * FROM colors ORDER BY id;

### Крок 8. Перевір підключення

    \conninfo
    SELECT current_database(), current_user;

### Крок 9. Створи резервну копію

Вийди з `psql`:

    \q

У терміналі виконай:

    pg_dump -U postgres -d cli_practice -f cli_practice.sql

### Крок 10. Перевір файл

    ls -lh cli_practice.sql

Ця вправа знайомить із базовим циклом роботи: підключення → створення об'єктів → додавання даних → перевірка → резервне копіювання.

## 19. Що потрібно запам'ятати

- `psql` — основний інтерактивний клієнт PostgreSQL.
- `pg_isready` перевіряє готовність сервера приймати підключення.
- `-h`, `-p`, `-U` і `-d` визначають адресу, порт, роль і базу даних.
- Метакоманди `psql` починаються з `\`, а SQL-команди зазвичай завершуються `;`.
- `\l`, `\dt`, `\d`, `\du` і `\q` — базові команди щоденної роботи.
- `pg_dump` створює логічну резервну копію, а `pg_restore` відновлює копії у відповідних форматах.
- Для Node.js можна використовувати `DATABASE_URL` або змінні `PGHOST`, `PGPORT`, `PGUSER` і `PGDATABASE`.
- Не передавай паролі відкритим текстом у командному рядку та не зберігай їх у Git.
- Застосунки повинні використовувати ролі з мінімально необхідними правами.
- Резервну копію потрібно не лише створити, а й перевірити відновленням.

**Головна ідея:** PostgreSQL CLI дає змогу керувати базами даних, перевіряти підключення, виконувати SQL і створювати резервні копії без графічного інтерфейсу.
