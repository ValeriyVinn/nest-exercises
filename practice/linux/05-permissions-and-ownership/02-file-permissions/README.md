# 02. File Permissions

File Permissions (права доступу до файлів і каталогів) — це механізм Linux, який визначає, які операції дозволено виконувати користувачам і групам над файлами та каталогами.

Linux використовує права доступу, щоб контролювати:

- хто може читати файл;
- хто може змінювати його вміст;
- хто може виконувати файл як програму;
- хто може переглядати вміст каталогу;
- хто може створювати, видаляти та перейменовувати файли в каталозі;
- як доступ розподіляється між власником, групою та іншими користувачами;
- як обмежувати доступ до системних файлів і ресурсів.

### Що потрібно пам'ятати

• Linux має три основні класи користувачів для стандартних прав доступу: owner, group та others.

• `r` означає read — читання.

• `w` означає write — запис або зміну.

• `x` означає execute — виконання для файлів або пошук і доступ до об'єктів за іменами для каталогів.

• Для файлів і каталогів значення `r`, `w` та `x` відрізняються.

• Власник файлу не обов'язково має всі дозволи: це залежить від установлених прав.

• Група-власник файлу не обов'язково збігається з основною групою користувача, який створив файл.

• `others` — усі користувачі, які не належать до класу власника і не отримують права через клас групи в стандартній моделі permissions.

• `ls -l` показує права доступу, власника, групу-власника та інші відомості про файли.

• `stat` показує детальнішу інформацію про файл, зокрема числовий режим доступу.

• Права доступу можна задавати символічно (`u+rwx`) або числово (`755`).

• У числовому записі `r = 4`, `w = 2`, `x = 1`.

• `755` означає `rwxr-xr-x`.

• `644` означає `rw-r--r--`.

• Для каталогів право `x` необхідне, щоб проходити через каталог і звертатися до об'єктів усередині за відомими іменами.

• Право `r` на каталог дозволяє читати список його імен, але для повноцінного доступу до записів зазвичай також потрібне `x`.

• Право `w` на каталог у поєднанні з `x` дозволяє створювати, видаляти та перейменовувати записи каталогу за умови, що інші механізми доступу це дозволяють.

• Право `w` на файл саме по собі не гарантує можливості його змінити, якщо доступ до файлу обмежується ACL, атрибутами, політиками безпеки або іншими механізмами.

• `chmod` змінює стандартні біти прав доступу.

• `chown` змінює власника та, за потреби, групу-власника.

• `chgrp` змінює групу-власника.

• `umask` впливає на стандартні права, з якими створюються нові файли й каталоги.

• Спеціальні біти SUID, SGID і sticky bit змінюють окремі аспекти поведінки файлів і каталогів.

• Права доступу — це не те саме, що власність на файл.

• Доступ до ресурсу може додатково контролюватися ACL, Linux capabilities, SELinux, AppArmor та іншими механізмами.

# File Permissions

File permissions — це права, які визначають, які операції дозволені над конкретним файлом або каталогом.

Наприклад:

    -rw-r--r--

Це рядок прав доступу, який можна побачити після виконання:

    ls -l

Він складається з кількох частин:

    - rw- r-- r--
    │  │   │   │
    │  │   │   └── others
    │  │   └────── group
    │  └────────── owner
    └───────────── file type

У цьому прикладі:

    -       → звичайний файл
    rw-     → власник може читати та змінювати файл
    r--     → група може читати файл
    r--     → інші користувачі можуть читати файл

Перший символ визначає тип об'єкта, а наступні дев'ять символів представляють три набори прав доступу.

---

# Permission Classes

У стандартній моделі Unix permissions права поділяються на три класи.

    owner
    group
    others

## Owner

Owner — користувач, який є власником файлу або каталогу.

Наприклад:

    -rw------- 1 taubu taubu 100 Oct 18 20:00 secret.txt

Тут:

    taubu → owner

Для класу власника встановлено:

    rw-

Власник може читати й змінювати файл, але не має права виконання за цим набором прав.

Важливо: право власника не визначається автоматично його основною групою.

## Group

Group — група-власник файлу або каталогу.

У прикладі:

    -rw-r----- 1 taubu developers 100 Oct 18 20:00 project.txt

Тут:

    taubu       → owner
    developers  → group owner

Для класу групи встановлено:

    r--

Користувачі, які відповідають класу групи та мають потрібне членство в ній, можуть читати файл відповідно до цих стандартних дозволів.

## Others

Others — клас користувачів, які не відповідають класу власника або класу групи для перевірки стандартних дозволів.

Наприклад:

    -rw-r--r--

Розшифрування:

    owner  → rw-
    group  → r--
    others → r--

Інші користувачі можуть читати файл, але не можуть змінювати його за цими стандартними правами.

---

# Read (r)

`r` означає read — читання.

Для звичайного файлу:

    r → читати вміст файлу

Приклад:

    cat notes.txt

Якщо користувач має право читання, команда може показати вміст файлу за умови, що доступ не обмежується іншими механізмами.

Приклад прав:

    -r--r--r--

Це означає, що всі три класи мають право читання.

Для каталогу:

    r → читати список імен записів каталогу

Наприклад:

    ls directory/

Для перегляду списку імен зазвичай потрібне право `r` на каталог.

Однак для доступу до самих об'єктів і проходження через шлях можуть знадобитися додаткові дозволи `x`.

Важливо:

    file r → читати вміст файлу
    dir r  → читати список імен у каталозі

Це різні операції.

---

# Write (w)

`w` означає write — запис або зміну.

Для звичайного файлу:

    w → змінювати вміст файлу

Наприклад:

    echo "Hello" > notes.txt

Якщо користувач має право запису у файл, він може змінювати його вміст, якщо це не заборонено іншими механізмами.

Для каталогу:

    w → змінювати записи каталогу

Це може включати:

    створення файлів;
    створення підкаталогів;
    видалення записів;
    перейменування записів.

Для більшості таких операцій над записами каталогу потрібні одночасно:

    w + x

Наприклад, для створення файлу:

    touch directory/new.txt

користувачеві зазвичай потрібні права запису та проходження до каталогу.

Важливо:

Право запису до каталогу не означає автоматичного права запису до вмісту кожного файлу в ньому.

Можна мати дозвіл змінювати записи каталогу, але не мати дозволу редагувати певний файл усередині.

---

# Execute (x)

`x` означає execute — виконання для звичайного файлу або пошук і проходження через каталог.

## Для файлу

Для звичайного виконуваного файлу:

    x → дозвіл на виконання

Наприклад:

    ./script.sh

Щоб запустити скрипт безпосередньо через шлях, користувачеві потрібен дозвіл на виконання та доступ до потрібних компонентів шляху.

Для скрипту також мають значення:

    коректний інтерпретатор;
    доступність інтерпретатора;
    права доступу до файлу;
    політики безпеки;
    спосіб запуску.

Важливо: право `x` не означає, що файл обов'язково є програмою, яку система може виконати.

## Для каталогу

Для каталогу:

    x → search / traverse

Це означає можливість проходити через каталог під час доступу до об'єктів за їхніми іменами.

Наприклад:

    cd directory/

Для переходу в каталог потрібне право `x` на нього, а також відповідні права на компоненти шляху.

Якщо користувач знає ім'я файлу, право `x` на каталог може дозволити звернутися до цього файлу навіть без права читання списку імен каталогу — за умови, що інші необхідні дозволи наявні.

Важливо:

    file x → виконання
    dir x  → пошук і проходження

# Permissions: File vs Directory

Це одна з найважливіших тем Linux.

| Permission | Для файлу | Для каталогу |
|---|---|---|
| `r` | Читати вміст | Читати список імен |
| `w` | Змінювати вміст | Змінювати записи каталогу |
| `x` | Виконувати файл | Проходити через каталог і шукати об'єкти |

## Приклад 1 — каталог із правом r

    dr--r--r-- directory/

Такий набір прав дозволяє читати список імен відповідно до класу користувача, але без `x` доступ до об'єктів усередині через цей каталог зазвичай буде неможливим.

## Приклад 2 — каталог із правом x

    d--x--x--x directory/

За наявності `x` користувач може проходити через каталог і звертатися до об'єктів за відомими іменами, якщо має інші необхідні дозволи.

Однак без `r` він не може звичайним способом прочитати список імен каталогу.

## Приклад 3 — каталог із rwx

    drwxr-xr-x directory/

Це поширений набір прав для каталогу.

    owner  → rwx
    group  → r-x
    others → r-x

Власник може читати список імен, створювати та видаляти записи й проходити через каталог.

Група та інші користувачі можуть читати список імен і проходити через каталог, але не можуть змінювати його записи за стандартними дозволами.

# ls -l

`ls -l` — основна команда для перегляду прав доступу, власника та групи-власника.

Команда:

    ls -l

Приклад результату:

    -rw-r--r-- 1 taubu taubu 120 Oct 18 20:00 notes.txt
    drwxr-xr-x 2 taubu developers 4096 Oct 18 20:05 projects

Розглянемо перший рядок:

    -rw-r--r-- 1 taubu taubu 120 Oct 18 20:00 notes.txt

Поля:

    -rw-r--r-- → тип об'єкта та права доступу
    1          → кількість жорстких посилань
    taubu      → власник
    taubu      → група-власник
    120        → розмір у байтах
    Oct 18     → дата зміни
    20:00      → час зміни
    notes.txt  → ім'я файлу

Для каталогу:

    drwxr-xr-x 2 taubu developers 4096 Oct 18 20:05 projects

Перший символ:

    d → directory

Далі:

    rwxr-xr-x → permissions

## Показати приховані файли

    ls -la

Параметр `-a` показує також імена, що починаються з крапки.

## Показати права конкретного файлу

    ls -l notes.txt

## Показати числовий UID і GID

    ls -ln

У цьому випадку замість імен власника та групи показуються числові ідентифікатори.

---

# File Type у ls -l

Перший символ у рядку `ls -l` визначає тип файлового об'єкта.

Основні типи:

    - → regular file
    d → directory
    l → symbolic link
    c → character device
    b → block device
    p → named pipe
    s → socket

Приклади:

    -rw-r--r-- notes.txt
    drwxr-xr-x projects/
    lrwxrwxrwx link -> notes.txt

Важливо:

Перший символ не входить до дев'яти стандартних бітів `rwx`.

Наприклад:

    -rw-r--r--

Тут:

    -       → file type
    rw-     → owner
    r--     → group
    r--     → others

---

# Permission String

Permission string — рядок, який відображає тип об'єкта та стандартні права доступу.

Наприклад:

    -rwxr-xr--

Розділимо його:

    - rwx r-x r--
    │  │   │   │
    │  │   │   └── others
    │  │   └────── group
    │  └────────── owner
    └───────────── file type

Розшифрування:

    owner:
        rwx → read, write, execute

    group:
        r-x → read, execute

    others:
        r-- → read

Власник має всі три права.

Група може читати та виконувати, але не змінювати файл.

Інші користувачі можуть лише читати файл.

---

# Permission Bits

Permission bits — біти, які визначають стандартні права доступу.

Для кожного з трьох класів використовуються три основні біти:

    r → read
    w → write
    x → execute

Загальна структура:

    owner  → rwx
    group  → rwx
    others → rwx

Усього:

    3 classes × 3 permissions = 9 permission bits

Наприклад:

    rwxr-xr--

Це дев'ять символів прав:

    rwx → owner
    r-x → group
    r-- → others

Окрім цих дев'яти бітів, у Unix-подібних системах існують спеціальні біти:

    SUID
    SGID
    sticky bit

Вони розглядаються окремо.

---

# Symbolic Permissions

Symbolic permissions — текстове подання прав доступу за допомогою символів `r`, `w` та `x`.

Приклади:

    rwx
    r-x
    rw-
    r--
    --x
    ---

Розшифрування:

    rwx → читання, запис, виконання
    r-x → читання, виконання
    rw- → читання, запис
    r-- → лише читання
    --x → лише виконання
    --- → жодного з трьох дозволів

Повні рядки:

    -rwxr-xr-x
    -rw-r--r--
    -rw-------
    drwxr-xr-x

Перший символ може визначати тип об'єкта.

Символічний спосіб подання дозволів зручний для читання результатів `ls -l`.

Він також використовується в командах `chmod`.

Наприклад:

    chmod u+x script.sh

Тут:

    u → user / owner
    + → додати
    x → execute

---

# Numeric Permissions

Numeric permissions — числове подання прав доступу.

Використовуються три основні значення:

    r = 4
    w = 2
    x = 1

Щоб отримати число для певного класу, потрібно скласти значення потрібних дозволів.

Приклади:

    rwx = 4 + 2 + 1 = 7
    rw- = 4 + 2     = 6
    r-x = 4 + 1     = 5
    r-- = 4         = 4
    -wx = 2 + 1     = 3
    -w- = 2         = 2
    --x = 1         = 1
    --- = 0

Число визначає набір дозволів для одного класу.

Три цифри відповідають:

    owner
    group
    others

Наприклад:

    755

означає:

    owner  → 7 → rwx
    group  → 5 → r-x
    others → 5 → r-x

Отже:

    755 = rwxr-xr-x

---

# Octal Notation

Octal notation — вісімковий запис прав доступу.

Він використовує цифри:

    0
    1
    2
    3
    4
    5
    6
    7

Кожна цифра представляє комбінацію трьох бітів:

    r = 4
    w = 2
    x = 1

Приклади:

    0 → ---
    1 → --x
    2 → -w-
    3 → -wx
    4 → r--
    5 → r-x
    6 → rw-
    7 → rwx

Три цифри:

    644
    755
    700
    600
    775

представляють права owner, group та others.

Важливо: числові дозволи записують не як звичайні десяткові значення, а як вісімкову комбінацію бітів.

У командах `chmod` звичайний запис `755` означає відповідні біти прав доступу.

# Common Permission Modes

Найпоширеніші набори прав:

| Mode | Symbolic | Типове застосування |
|---|---|---|
| `777` | `rwxrwxrwx` | Усі три класи мають усі стандартні дозволи |
| `755` | `rwxr-xr-x` | Виконувані файли або каталоги з публічним читанням |
| `750` | `rwxr-x---` | Власник має повний доступ, група — читання та виконання |
| `700` | `rwx------` | Доступ лише власнику |
| `666` | `rw-rw-rw-` | Усі три класи мають читання та запис |
| `644` | `rw-r--r--` | Власник може змінювати, інші — читати |
| `640` | `rw-r-----` | Власник може читати й змінювати, група — читати |
| `600` | `rw-------` | Читання та запис лише власнику |
| `444` | `r--r--r--` | Усі три класи можуть читати |
| `400` | `r--------` | Читання лише власнику |

Ці значення описують стандартні біти доступу. Реальний доступ також може залежати від ACL, атрибутів, політик безпеки та інших умов.

## 755

    chmod 755 script.sh

Права:

    owner  → rwx
    group  → r-x
    others → r-x

## 644

    chmod 644 notes.txt

Права:

    owner  → rw-
    group  → r--
    others → r--

## 700

    chmod 700 private-directory

Права:

    owner  → rwx
    group  → ---
    others → ---

## 600

    chmod 600 secret.txt

Права:

    owner  → rw-
    group  → ---
    others → ---

## Важливо про 777

Не встановлюй `777` автоматично, коли виникає проблема з доступом.

    chmod 777 file.txt

надає всім трьом класам стандартні права читання, запису та виконання.

Для звичайних файлів це може створити небезпечну конфігурацію, а для каталогів дозволити іншим користувачам змінювати записи каталогу.

Краще визначити конкретну причину відмови в доступі й надати лише потрібні права.

# Permissions для файлів

Розглянемо типові приклади.

## Read-only file

    -r--r--r--

Власник, група та інші користувачі можуть читати файл.

За цими стандартними правами жоден із трьох класів не має права запису або виконання.

## Private file

    -rw-------

Власник може читати й змінювати файл.

Група та інші користувачі не мають стандартних дозволів.

## Executable file

    -rwxr-xr-x

Власник може читати, змінювати й виконувати файл.

Група та інші користувачі можуть читати та виконувати його.

## File without permissions

    ----------

Жоден із трьох класів не має стандартних дозволів `rwx`.

Однак власність, спеціальні біти, ACL, привілеї процесу та інші механізми можуть впливати на фактичний доступ.

---

# Permissions для каталогів

Каталоги мають особливе значення для файлової системи.

## Каталог 755

    drwxr-xr-x

Власник:

    rwx

Група:

    r-x

Інші:

    r-x

Це поширений варіант для каталогів, які можуть переглядати та використовувати інші користувачі.

## Каталог 700

    drwx------

Власник:

    rwx

Група:

    ---

Інші:

    ---

Такий каталог обмежує стандартний доступ до власника.

## Каталог 750

    drwxr-x---

Власник має повний доступ.

Група може читати список імен і проходити через каталог.

Інші користувачі не мають стандартних дозволів.

## Чому x важливий для каталогу

Приклад:

    /home/taubu/projects/app

Щоб отримати доступ до файлу `app`, процес повинен мати потрібні права проходження через компоненти шляху.

Навіть якщо файл має:

    -rw-r--r--

доступ до нього може бути неможливим, якщо користувач не має права `x` на один із каталогів шляху.

Важливо:

    file permissions
        +
    directory permissions
        ↓
    access to a path

# Перевірка доступу до файлу

Припустімо, є файл:

    notes.txt

Переглянути його права:

    ls -l notes.txt

Приклад:

    -rw-r----- 1 taubu developers 120 Oct 18 20:00 notes.txt

Розшифрування:

    owner: taubu
    group: developers

    owner permissions:
        rw-

    group permissions:
        r--

    others permissions:
        ---

Це означає:

    owner  → може читати й змінювати файл
    group  → може читати файл
    others → не мають стандартних дозволів

Проте для доступу до файлу потрібно також мати право проходження через каталоги шляху.

---

# Перевірка через stat

`stat` показує детальні відомості про файл або каталог.

Команда:

    stat notes.txt

Приклад результату:

    File: notes.txt
    Size: 120
    Access: (0640/-rw-r-----)  Uid: (1000/taubu)  Gid: (2000/developers)

У цьому прикладі:

    0640          → числові права
    -rw-r-----    → символічні права
    1000          → UID власника
    taubu         → ім'я власника
    2000          → GID групи-власника
    developers    → назва групи-власника

Реальний результат залежить від системи та версії `stat`.

## Короткий формат

    stat -c '%A %a %U %G %n' notes.txt

Поля:

    %A → символічні права
    %a → числові права
    %U → ім'я власника
    %G → назва групи
    %n → ім'я файлу

Це зручно для практики.

# Permission Inheritance

Permission inheritance — умовна назва для механізмів, які впливають на права нових файлів і каталогів.

У стандартній моделі Linux права нового об'єкта визначаються:

    початковим режимом створення;
    umask;
    спеціальними властивостями батьківського каталогу;
    файловою системою та додатковими механізмами доступу.

Права звичайного файлу не копіюються автоматично з батьківського каталогу як є.

Наприклад:

    mkdir projects
    touch projects/notes.txt

Режими доступу нових об'єктів залежать від `umask` і параметрів створення.

Окремі механізми, наприклад setgid на каталозі, можуть впливати на групу-власника нових об'єктів.

ACL за наявності відповідних налаштувань можуть впливати на права нових файлів і каталогів.

Докладніше:

    04-chown-chgrp
    06-umask

# File Ownership vs Permissions

Власність і права доступу — різні характеристики файлу.

Наприклад:

    -rw-r----- 1 taubu developers 120 Oct 18 20:00 notes.txt

Власність:

    owner: taubu
    group: developers

Права:

    owner: rw-
    group: r--
    others: ---

Зміна прав:

    chmod 640 notes.txt

Зміна власника:

    sudo chown anotheruser notes.txt

Зміна групи-власника:

    sudo chgrp anothergroup notes.txt

Команди виконують різні завдання.

    chmod → змінює permissions
    chown → змінює owner та, за потреби, group
    chgrp → змінює group owner

Докладніше:

    03-chmod
    04-chown-chgrp

# Permission Denied

`Permission denied` — повідомлення, яке часто виникає, коли процес не має потрібних прав доступу.

Наприклад:

    cat secret.txt

Можливий результат:

    cat: secret.txt: Permission denied

Причини можуть включати:

    відсутність права читання файлу;
    відсутність права проходження через каталог;
    невідповідність класу власника або групи;
    обмеження ACL;
    системні політики безпеки;
    обмеження файлової системи.

## Як досліджувати проблему

Крок 1. Перевірити поточного користувача:

    whoami
    id

Крок 2. Перевірити права файлу:

    ls -l secret.txt

Крок 3. Перевірити шлях до файлу:

    namei -l /path/to/secret.txt

`namei -l` може показати права кожного компонента шляху.

Крок 4. Перевірити ACL, якщо утиліта доступна:

    getfacl secret.txt

Крок 5. Визначити, якого дозволу бракує.

Не потрібно відразу виконувати:

    chmod 777 secret.txt

Краще виправити конкретну причину відмови в доступі.

# Access Control

Access control — механізм контролю доступу до ресурсів.

У стандартній моделі Unix permissions використовуються:

    owner
    group
    others

Система порівнює ідентифікатори процесу з власником і групою-власником об'єкта та перевіряє відповідні права.

Спрощена модель:

    process credentials
        ↓
    owner / group / others
        ↓
    permission bits
        ↓
    allow or deny operation

Це спрощене пояснення. Фактична перевірка може включати ACL, capabilities, політики безпеки та інші механізми.

## Least Privilege

Least privilege — принцип найменших привілеїв.

Він означає, що користувач або процес повинен отримувати лише ті права, які потрібні для його завдання.

Наприклад:

    приватний файл → 600
    звичайний текстовий файл → 644
    приватний каталог → 700
    каталог для спільної групи → 750 або 770 залежно від задачі

Це типові приклади, а не універсальні правила для кожного сценарію.

---

# ACL — Access Control Lists

ACL (Access Control Lists) — списки контролю доступу, які дозволяють задавати додаткові права для конкретних користувачів і груп.

Стандартні permissions мають три класи:

    owner
    group
    others

ACL дозволяє додатково визначати доступ, наприклад, для окремого користувача, який не є власником файлу.

Переглянути ACL:

    getfacl notes.txt

Задати ACL для користувача:

    setfacl -m u:student:r notes.txt

У цьому прикладі користувач `student` отримує право читання відповідно до ACL.

Перевірити:

    getfacl notes.txt

Важливо:

    chmod
        → стандартні біти прав доступу

    setfacl
        → ACL

ACL можуть впливати на фактичний доступ, навіть якщо стандартний рядок прав не дає повної картини.

Наявність і поведінка ACL залежать від файлової системи та її конфігурації.

Для початкового рівня достатньо знати, що ACL розширює стандартну модель permissions.

---

# Special Permissions

Окрім стандартних прав `rwx`, Linux підтримує спеціальні біти.

Основні:

    SUID
    SGID
    sticky bit

Вони впливають на поведінку виконуваних файлів і каталогів.

Перевірити їх можна через:

    ls -l
    stat

У символічному поданні спеціальні біти можуть відображатися через:

    s
    S
    t
    T

Залежно від того, чи встановлено відповідний `x`, використовуються великі або малі літери.

## SUID

SUID (Set User ID) для виконуваного файлу може спричиняти виконання програми з ефективним UID власника файлу, якщо файлову систему та інші механізми налаштовано відповідним чином.

Приклад символічного відображення:

    -rwsr-xr-x

Тут `s` з'являється в позиції `x` власника.

SUID має значення для безпеки й потребує обережного використання.

## SGID

SGID (Set Group ID) має різну поведінку залежно від типу об'єкта.

Для виконуваного файлу він може впливати на ефективний GID процесу.

Для каталогу він зазвичай забезпечує успадкування групи-власника новими файлами й підкаталогами, створеними в ньому, залежно від системи та файлової системи.

Приклад каталогу:

    drwxr-sr-x

Літера `s` у позиції групового `x` показує встановлений SGID.

## Sticky Bit

Sticky bit найчастіше зустрічається на каталогах, у яких багато користувачів можуть створювати файли.

Наприклад:

    drwxrwxrwt

Типовий приклад:

    /tmp

У каталозі зі sticky bit видалення або перейменування записів зазвичай обмежується власником запису, власником каталогу або процесом із відповідними привілеями.

Sticky bit не означає, що файли в каталозі стають незмінними.

# Типові помилки

## 1. Плутати права файлу та каталогу

Для файлу:

    r → читати вміст
    w → змінювати вміст
    x → виконувати

Для каталогу:

    r → читати список імен
    w → змінювати записи каталогу
    x → проходити через каталог і шукати об'єкти

---

## 2. Вважати, що 755 означає повний доступ для всіх

    chmod 755 file.txt

означає:

    owner  → rwx
    group  → r-x
    others → r-x

Лише власник має право запису за цими стандартними дозволами.

---

## 3. Плутати 644 та 755

    644 → rw-r--r--
    755 → rwxr-xr-x

`644` не надає права виконання.

`755` надає право виконання всім трьом класам.

---

## 4. Вважати, що право x на каталог дозволяє бачити його вміст

`x` на каталозі дозволяє проходження та пошук за іменами.

Для читання списку імен зазвичай потрібне `r`.

---

## 5. Вважати, що право w на файл дозволяє видаляти його

Видалення файлу зазвичай залежить від прав на батьківський каталог, а не лише від права запису у файл.

Наприклад, файл може бути доступним лише для читання, але його запис у каталозі може бути видалений користувачем, який має потрібні права на каталог, якщо інші механізми не забороняють цю операцію.

Sticky bit може додатково обмежувати видалення.

---

## 6. Використовувати chmod 777 як універсальне рішення

    chmod 777 file.txt

Це може надати непотрібний доступ іншим користувачам.

Краще з'ясувати, який саме дозвіл потрібен.

---

## 7. Плутати owner і group

У рядку:

    -rw-r----- 1 taubu developers 120 Oct 18 20:00 notes.txt

    taubu       → owner
    developers  → group owner

Власник і група-власник — різні атрибути.

---

## 8. Вважати, що ls -l показує всю інформацію про доступ

`ls -l` показує тип об'єкта та стандартні права, але не повністю розкриває всі механізми доступу.

Для детальнішої перевірки можуть знадобитися:

    stat
    getfacl
    namei -l

---

## 9. Ігнорувати права каталогів у шляху

Файл може мати правильні дозволи, але доступ до нього все одно буде неможливим через відсутність `x` на одному з каталогів шляху.

Перевіряй усі компоненти шляху.

---

## 10. Вважати, що власник завжди має rwx

Власник може мати будь-яку комбінацію стандартних дозволів.

Наприклад:

    -r--------
    -rw-------
    --x------

Власність сама по собі не означає, що всі дозволи встановлено.

# Головне

• File permissions визначають, які стандартні операції дозволені над файлами та каталогами.

• Основні класи доступу:

    owner
    group
    others

• Основні права:

    r → read
    w → write
    x → execute

• Для звичайного файлу `r` означає читання вмісту, `w` — його зміну, а `x` — виконання.

• Для каталогу `r` означає читання списку імен, `w` — зміну записів, а `x` — пошук і проходження через каталог.

• `ls -l` показує тип об'єкта та стандартні права доступу.

• `stat` дозволяє детальніше дослідити права, власника й групу-власника.

• Числові дозволи використовують значення:

    r = 4
    w = 2
    x = 1

• `755` означає `rwxr-xr-x`.

• `644` означає `rw-r--r--`.

• `700` означає `rwx------`.

• `600` означає `rw-------`.

• Власність і права доступу — різні характеристики.

• `chmod` змінює стандартні біти прав доступу.

• `chown` змінює власника та, за потреби, групу-власника.

• `chgrp` змінює групу-власника.

• `umask` впливає на стандартні дозволи нових файлів і каталогів.

• SUID, SGID та sticky bit змінюють окремі аспекти поведінки файлових об'єктів.

• ACL можуть надавати додаткові правила доступу.

• Відсутність прав на каталог у шляху може блокувати доступ до файлу навіть тоді, коли сам файл має відповідні дозволи.

• `Permission denied` потрібно досліджувати, а не автоматично виправляти через `chmod 777`.

• Найкращий підхід — надавати лише ті права, які справді необхідні.

• Основна модель стандартних прав доступу:

    File / Directory
          ↓
    Owner + Group Owner
          ↓
    Owner / Group / Others
          ↓
    Read + Write + Execute
          ↓
    Permission Check
          ↓
    Allow or Deny

• **Головна мета вивчення file permissions — навчитися читати права доступу, розуміти їхню поведінку для файлів і каталогів та безпечно визначати, кому які дозволи потрібні.**
