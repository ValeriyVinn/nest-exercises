# 05. sudo — виконання команд із підвищеними привілеями в Linux

`sudo` (superuser do) — команда Linux, яка дозволяє уповноваженому користувачу виконувати команди з привілеями іншого користувача, зазвичай `root`.

У Linux звичайні користувачі мають обмежені права. Це допомагає захищати системні файли, налаштування операційної системи та дані інших користувачів.

За допомогою `sudo` можна виконувати адміністративні операції, не входячи постійно в систему під обліковим записом `root`.

## 1. Коли потрібен sudo

Команду `sudo` використовують, коли потрібно:

- встановити програму;
- оновити системні пакети;
- змінити системні налаштування;
- керувати системними службами;
- читати файли, доступ до яких обмежено;
- змінювати власника системних файлів;
- виконувати адміністративні операції з користувачами та групами;
- редагувати певні системні конфігураційні файли.

Приклади:

    sudo apt update
    sudo apt install curl
    sudo systemctl status ssh
    sudo chown root:root example.conf
    sudo less /var/log/auth.log

Останній приклад залежить від дистрибутива та наявності відповідного файлу журналу.

**Основне правило:** використовуйте `sudo` лише тоді, коли команда справді потребує підвищених привілеїв.

---

## 2. Основний синтаксис sudo

Загальний синтаксис:

    sudo [OPTIONS] COMMAND

Де:

- `sudo` — команда запуску з підвищеними привілеями;
- `OPTIONS` — додаткові параметри;
- `COMMAND` — команда, яку потрібно виконати.

Приклад:

    sudo apt update

Команда `apt update` запускається з привілеями адміністратора, оскільки оновлення системної інформації про пакети потребує відповідних повноважень.

Інший приклад:

    sudo systemctl restart nginx

Команда намагається перезапустити службу `nginx`. Вона спрацює лише тоді, коли служба існує та користувач має дозвіл виконати цю адміністративну дію.

### 2.1. Як працює sudo

Типовий процес:

1. Користувач вводить команду з `sudo`.
2. Система перевіряє, чи має користувач дозвіл на її виконання.
3. За потреби система просить пароль користувача.
4. Якщо перевірка успішна, команда виконується з відповідними привілеями.
5. Результат команди відображається в терміналі.

У стандартній конфігурації `sudo` зазвичай запитує пароль поточного користувача, а не пароль `root`.

Успішна автентифікація не означає, що користувачеві дозволено будь-яку команду. Дозволи визначаються конфігурацією `sudo`.

---

## 3. Перевірка поточного користувача

Перед адміністративними діями корисно з'ясувати, під яким користувачем працює термінал.

### 3.1. Команда whoami

    whoami

Приклад результату:

    valer

Команда показує ім'я поточного користувача.

### 3.2. Команда id

    id

Приклад результату:

    uid=1000(valer) gid=1000(valer) groups=1000(valer),27(sudo)

Результат містить:

- `uid` — ідентифікатор користувача;
- `gid` — ідентифікатор основної групи;
- `groups` — групи, до яких належить користувач.

У цьому прикладі користувач входить до групи `sudo`. Назви адміністративних груп залежать від дистрибутива та конфігурації системи.

### 3.3. Перевірити, чи доступна команда sudo

    sudo -V

Команда показує інформацію про встановлену версію `sudo` та її конфігурацію.

Якщо `sudo` не встановлено або команда недоступна, спосіб отримання адміністративних привілеїв залежить від дистрибутива й налаштувань системи.

---

## 4. Запуск команди з sudo

Без `sudo` команда може не мати доступу до системних ресурсів.

Наприклад:

    apt update

Звичайний користувач може отримати повідомлення про недостатні привілеї.

Правильний варіант для систем, які використовують `apt`:

    sudo apt update

Ще приклад:

    touch /etc/example.txt

Звичайний користувач зазвичай не може створювати файли в `/etc`.

Команда:

    sudo touch /etc/example.txt

може створити файл, якщо користувач має відповідні адміністративні повноваження. Проте для навчання краще не створювати зайвих файлів у системних каталогах.

### 4.1. sudo не потрібен для кожної команди

Зазвичай не потрібно використовувати `sudo` для:

    pwd
    ls
    cd
    mkdir ~/projects/test
    touch ~/projects/test/README.md
    node --version
    npm --version
    git status

Ці команди зазвичай виконуються з правами звичайного користувача, якщо вони працюють із доступними йому ресурсами.

---

## 5. Пароль і повторна автентифікація

Під час першого використання `sudo` система може попросити пароль.

Приклад:

    sudo apt update

Термінал може показати:

    [sudo] password for valer:

Потрібно ввести пароль поточного користувача.

### 5.1. Чому пароль не відображається

Під час введення пароля в терміналі символи зазвичай не показуються — навіть зірочки.

Це нормальна поведінка.

Введіть пароль і натисніть `Enter`.

### 5.2. Чому пароль не запитують щоразу

`sudo` зазвичай кешує результат успішної автентифікації на певний час.

Тому наступна команда може виконатися без повторного введення пароля.

Тривалість кешування залежить від конфігурації системи.

### 5.3. Очистити кеш автентифікації

    sudo -k

Команда робить кеш автентифікації недійсним для поточного сеансу `sudo`. Наступна команда, яка потребує автентифікації, зазвичай знову попросить пароль.

Щоб перевірити доступ до `sudo`, можна використати:

    sudo -v

Команда перевіряє або поновлює облікові дані `sudo`, не виконуючи окремої адміністративної команди.

---

## 6. Перевірка дозволів sudo

Не кожен користувач Linux може використовувати `sudo`.

Перевірити доступ можна командою:

    sudo -l

Вона показує команди, які поточному користувачеві дозволено виконувати через `sudo`, відповідно до чинної конфігурації.

Можливі ситуації:

- користувач має широкі адміністративні дозволи;
- користувач може виконувати лише певні команди;
- користувач не має дозволу використовувати `sudo`;
- система просить пароль або повідомляє про помилку автентифікації.

Приклад повідомлення про відсутність дозволу:

    valer is not in the sudoers file.

Це означає, що користувач не має необхідного дозволу відповідно до конфігурації `sudo`.

Не намагайтеся обходити це обмеження. Якщо адміністративні повноваження потрібні для законної роботи, зверніться до адміністратора системи або використайте дозволений спосіб керування обліковим записом.

---

## 7. sudo та root

`root` — спеціальний користувач Linux із широкими адміністративними привілеями.

Звичайний користувач має обмежений доступ до системи. `sudo` дозволяє виконувати окремі команди з іншими привілеями, якщо це дозволено конфігурацією.

### 7.1. Виконати команду від root

    sudo whoami

Очікуваний результат у типовій конфігурації:

    root

Команда `whoami` показує ефективного користувача, від імені якого виконується процес.

### 7.2. Запустити оболонку root

    sudo -i

Ця команда відкриває інтерактивну оболонку з привілеями `root`, якщо користувач має відповідний дозвіл.

Після цього команди виконуються з адміністративними привілеями, доки ви не завершите оболонку.

Вийти:

    exit

**Застереження:** у такій оболонці звичайна помилка може вплинути на всю систему. Для більшості завдань безпечніше використовувати `sudo` перед конкретною командою.

### 7.3. Різниця між sudo command і sudo -i

| Команда | Що відбувається |
|---|---|
| `sudo apt update` | Запускається одна команда з підвищеними привілеями |
| `sudo whoami` | `whoami` виконується з привілеями `root` у типовій конфігурації |
| `sudo -i` | Відкривається інтерактивна оболонка root |
| `exit` | Завершує поточну оболонку |

## 8. Виконання кількох команд

Якщо потрібно виконати кілька адміністративних команд, краще явно розділяти їх і розуміти, яка саме команда отримує підвищені привілеї.

Наприклад:

    sudo apt update
    sudo apt upgrade

Перша команда оновлює списки доступних пакетів, друга встановлює доступні оновлення пакетів.

Не варто бездумно об'єднувати багато адміністративних операцій в один рядок: це ускладнює перевірку результатів і пошук помилок.

### 8.1. Важливо: sudo не поширюється автоматично на весь рядок

Розглянемо:

    sudo command1 && command2

Тут `sudo` застосовується до `command1`. Команда `command2` запускається вже без окремого `sudo`, якщо її не запускає інший привілейований процес.

Якщо обидві команди потребують підвищених привілеїв, краще написати:

    sudo command1
    sudo command2

Це зрозуміліше та дозволяє перевірити результат кожної команди окремо.

Якщо необхідно виконати кілька команд у межах одного привілейованого процесу, спосіб слід обирати обережно, враховуючи, які саме команди запускаються.

## 9. Типова проблема: sudo не допомагає перенаправленню

У Linux символи перенаправлення, наприклад `>` і `>>`, обробляє оболонка, а не сама команда `sudo`.

Припустимо, потрібно записати текст у системний файл:

    echo "example" > /etc/example.conf

Звичайний користувач зазвичай не має права записувати в `/etc/example.conf`.

Спроба:

    sudo echo "example" > /etc/example.conf

може завершитися помилкою. Причина: оболонка відкриває файл для перенаправлення до того, як запускається команда `sudo echo`.

### 9.1. Використання tee

Для контрольованого запису можна використати `tee`:

    echo "example" | sudo tee /etc/example.conf

Команда `tee` сама запускається через `sudo`, тому відкриває файл із відповідними привілеями.

Щоб дописати рядок у кінець файлу:

    echo "example" | sudo tee -a /etc/example.conf

Параметр `-a` означає додавання до кінця файлу, а не повну заміну його вмісту.

**Обережно:** перша команда з `tee` може перезаписати наявний файл. Не використовуйте ці приклади для реальних системних конфігурацій без перевірки шляху та наслідків.

Для редагування системного текстового файлу зазвичай зручніше використати відповідний редактор із підвищеними привілеями, якщо це дозволено політикою системи.

## 10. sudo та керування файлами

Команда `sudo` може знадобитися для роботи з файлами, які належать `root` або іншому користувачу.

### 10.1. Переглянути системний файл

    sudo less /etc/hosts

`less` відкриває файл для перегляду. Вийти можна клавішею `q`.

### 10.2. Перевірити власника файлу

    ls -l /etc/hosts

### 10.3. Змінити власника

Зміна власника системного файлу може порушити роботу системи, тому не робіть цього без конкретної причини.

Синтаксичний приклад:

    sudo chown root:root example.conf

Команда змінює власника та групу на `root`, якщо це дозволено і відповідні облікові записи існують.

### 10.4. Не використовуйте sudo для власного проєкту без потреби

Якщо файли вашого навчального проєкту раптом вимагають `sudo` для звичайного редагування, перевірте їхню власність:

    ls -l
    ls -ld .

Якщо файли належать `root`, з'ясуйте, чому вони були створені з такими правами, перш ніж змінювати власника.

---

## 11. sudo та встановлення програм

У дистрибутивах на основі Debian і Ubuntu `sudo` часто використовується разом із `apt`.

Оновити список пакетів:

    sudo apt update

Встановити програму:

    sudo apt install curl

Оновити встановлені пакети:

    sudo apt upgrade

Знайти інформацію про пакет:

    apt show curl

Для перегляду інформації про пакет зазвичай не потрібні адміністративні привілеї, якщо доступні локальні метадані.

Перед підтвердженням встановлення або оновлення перегляньте список пакетів, які система збирається встановити, оновити або видалити.

Не запускайте команди встановлення програм із випадкових інструкцій, якщо не розумієте, що саме вони роблять.

---

## 12. sudo та системні служби

У системах із `systemd` команда `systemctl` використовується для керування службами.

Перевірити стан служби:

    systemctl status ssh

Якщо для перегляду або керування конкретною службою потрібні додаткові привілеї:

    sudo systemctl status ssh

Перезапустити службу:

    sudo systemctl restart ssh

Зупинити службу:

    sudo systemctl stop ssh

Увімкнути автоматичний запуск служби:

    sudo systemctl enable ssh

Не всі системи мають однакові служби або однакові назви пакетів. Наприклад, назва служби SSH може відрізнятися залежно від дистрибутива.

**Застереження:** зупинка або перезапуск мережевої служби може перервати підключення, особливо якщо ви працюєте віддалено через SSH.

## 13. Безпека під час використання sudo

Адміністративні привілеї дають змогу виконувати операції, які можуть вплинути на всю систему.

Перед виконанням команди перевірте:

1. Чи розумієте ви призначення команди?
2. Чи правильно вказаний шлях?
3. Чи дійсно потрібні підвищені привілеї?
4. Чи може команда видалити або перезаписати дані?
5. Чи не вплине вона на інших користувачів або служби?
6. Чи є резервна копія важливих даних, якщо операція ризикована?

### 13.1. Не запускайте невідомі команди через sudo

Уникайте сліпого копіювання команд на кшталт:

    curl https://example.com/script.sh | sudo bash

Така конструкція передає завантажений текст безпосередньо оболонці з підвищеними привілеями.

Навіть якщо джерело виглядає знайомим, спочатку перевірте офіційну документацію та вміст скрипту. Якщо можливо, завантажте його, перегляньте, перевірте походження та лише потім вирішуйте, чи варто виконувати.

### 13.2. Не використовуйте sudo для кожної команди

Не варто перетворювати всі команди на:

    sudo mkdir ...
    sudo touch ...
    sudo git ...
    sudo npm ...

Для файлів у власному домашньому каталозі зазвичай достатньо прав звичайного користувача.

Особливо небажано без потреби запускати `git`, `npm` або інструменти розробки з підвищеними привілеями: це може створювати файли з неочікуваним власником і призводити до подальших проблем із доступом.

### 13.3. Перевіряйте команди перед виконанням

Перед небезпечною файловою операцією спочатку перевірте шлях:

    pwd
    ls -ld /шлях/до/каталогу

Не виконуйте руйнівні команди з `sudo`, якщо не впевнені, де саме вони будуть застосовані.

## 14. Типові помилки sudo

### Помилка 1. sudo: command not found

Приклад:

    sudo: command not found

Можливі причини:

- `sudo` не встановлено;
- команда недоступна в `PATH`;
- використовується мінімальна система з іншим способом адміністрування.

Не встановлюйте пакети навмання, якщо ще не з'ясували, який спосіб керування системою доступний.

### Помилка 2. user is not in the sudoers file

Приклад:

    valer is not in the sudoers file.

Поточному користувачеві не дозволено використовувати `sudo` відповідно до конфігурації.

Потрібно звернутися до адміністратора або скористатися дозволеним способом отримання потрібних привілеїв.

### Помилка 3. Sorry, try again

Це повідомлення зазвичай означає, що введений пароль не пройшов перевірку.

Переконайтеся, що:

- вводите пароль правильного користувача;
- не переплутали розкладку клавіатури;
- не ввели зайвих символів;
- використовуєте актуальний пароль облікового запису.

### Помилка 4. Permission denied навіть із sudo

Можливі причини:

- команда не має відповідних дозволів у конфігурації `sudo`;
- файлова система змонтована з обмеженнями;
- операцію блокує інший механізм безпеки;
- проблема пов'язана не з правами користувача, а з параметрами самої операції.

Перевірте:

    sudo -l
    ls -l /шлях/до/файлу
    stat /шлях/до/файлу

Не намагайтеся автоматично виправляти помилку командою `chmod 777`.

### Помилка 5. Забули sudo для адміністративної команди

Наприклад:

    apt update

Якщо команда повідомляє про недостатні привілеї, у системі Ubuntu можна використати:

    sudo apt update

Але спочатку переконайтеся, що саме цій операції потрібні адміністративні права.

### Помилка 6. sudo не допомогло перенаправленню

Приклад:

    sudo echo "text" > /etc/example.conf

Проблема полягає в тому, що перенаправлення обробляє звичайна оболонка.

Для контрольованого запису використовуйте відповідний спосіб, наприклад:

    echo "text" | sudo tee /etc/example.conf

## 15. Корисні параметри sudo

| Команда | Призначення |
|---|---|
| `sudo COMMAND` | Виконати команду з дозволеними підвищеними привілеями |
| `sudo -l` | Переглянути дозволені команди |
| `sudo -v` | Перевірити або поновити кеш автентифікації |
| `sudo -k` | Зробити кеш автентифікації недійсним |
| `sudo -i` | Запустити інтерактивну оболонку root |
| `sudo -u USER COMMAND` | Виконати команду від імені іншого користувача, якщо дозволено |
| `sudo -H COMMAND` | У певних конфігураціях задати домашній каталог цільового користувача для відповідного середовища |

### 15.1. Виконати команду від імені іншого користувача

Наприклад:

    sudo -u www-data whoami

Якщо така операція дозволена, результатом буде:

    www-data

Це корисно для перевірки того, як команда поводиться від імені сервісного користувача.

Не всі користувачі мають дозвіл виконувати команди від імені будь-якого іншого облікового запису.

### 15.2. Навіщо потрібен sudo -H

    sudo -H COMMAND

Параметр `-H` просить `sudo` налаштувати змінну `HOME` для цільового користувача відповідно до його домашнього каталогу.

Це не означає, що будь-яка команда автоматично стане безпечною або що користувач отримає додаткові дозволи поза правилами `sudo`.

## 16. Практичні завдання

Виконуйте завдання у власному навчальному середовищі. Не змінюйте системні файли без конкретної потреби.

### Завдання 1. Перевірити користувача

    whoami
    id

Запишіть ім'я користувача, UID, основну групу та додаткові групи.

### Завдання 2. Перевірити дозволи sudo

    sudo -l

З'ясуйте, які адміністративні операції дозволені вашому користувачеві.

### Завдання 3. Перевірити роботу sudo

    sudo whoami

У типовій конфігурації з дозволом на використання `sudo` команда покаже:

    root

Поясніть, чим цей результат відрізняється від звичайного `whoami`.

### Завдання 4. Очистити кеш автентифікації

    sudo -k
    sudo -v

Зверніть увагу, чи запитує система пароль під час поновлення облікових даних.

### Завдання 5. Створити каталог без sudo

    mkdir -p ~/linux-practice/sudo
    touch ~/linux-practice/sudo/README.md
    ls -l ~/linux-practice/sudo/

Переконайтеся, що звичайні файли у вашому навчальному каталозі не потребують адміністративних привілеїв.

### Завдання 6. Переглянути системний файл

    sudo less /etc/hosts

Перегляньте вміст і вийдіть клавішею `q`.

### Завдання 7. Перевірити різницю між sudo та звичайною командою

    whoami
    sudo whoami

Поясніть, чому результати можуть відрізнятися.

### Завдання 8. Перевірити службу

Якщо у вашій системі є служба SSH:

    systemctl status ssh

Якщо команда потребує підвищених привілеїв:

    sudo systemctl status ssh

Порівняйте результати та з'ясуйте, чи встановлено відповідну службу.

## 17. Що потрібно пам'ятати

- `sudo` дозволяє виконувати команди з іншими привілеями, зазвичай `root`.
- Для використання `sudo` потрібен відповідний дозвіл у конфігурації системи.
- Зазвичай `sudo` запитує пароль поточного користувача.
- Кеш автентифікації може дозволяти повторні команди без нового запиту пароля.
- `sudo -l` показує дозволені команди.
- `sudo -k` робить кеш автентифікації недійсним.
- `sudo -i` відкриває інтерактивну оболонку root.
- Не потрібно використовувати `sudo` для кожної команди.
- Перенаправлення `>` обробляє оболонка, тому `sudo echo ... > file` може не працювати.
- Для контрольованого запису в захищений файл можна використовувати `sudo tee`.
- Не запускайте невідомі скрипти через `sudo`.
- Не запускайте `git`, `npm` або інші інструменти розробки з підвищеними привілеями без необхідності.
- Якщо виникла помилка доступу, спочатку визначте її причину.
- Адміністративні команди можуть впливати на всю систему.

## 19. Шлях навчання

### Core — базовий рівень

- Розуміти призначення `sudo`.
- Виконувати одну адміністративну команду.
- Розрізняти звичайного користувача та `root`.
- Перевіряти власні дозволи через `sudo -l`.
- Розуміти, чому пароль не відображається під час введення.

### Junior — практичний рівень

- Використовувати `sudo` для оновлення системи та встановлення програм.
- Переглядати системні файли з обмеженим доступом.
- Перевіряти та керувати службами через `systemctl`.
- Розуміти поведінку перенаправлення `>` і команди `tee`.
- Діагностувати типові помилки автентифікації та дозволів.

### Middle — поглиблений рівень

- Розуміти принцип найменших привілеїв.
- Перевіряти дозволи користувача в конфігурації `sudo`.
- Використовувати `sudo -u` для роботи з сервісними користувачами.
- Аналізувати ризики адміністративних скриптів.
- Розуміти наслідки запуску інструментів розробки від `root`.

### Senior — системний рівень

- Проєктувати політики адміністративного доступу.
- Надавати користувачам лише необхідні дозволи.
- Аналізувати журнали та події використання `sudo`.
- Автоматизувати адміністративні операції без надмірного розширення привілеїв.
- Враховувати безпеку системних служб, контейнерів і серверних середовищ.

## 20. Мінішпаргалка

    # Перевірити поточного користувача
    whoami
    id

    # Переглянути дозволи sudo
    sudo -l

    # Виконати адміністративну команду
    sudo apt update

    # Перевірити версію sudo
    sudo -V

    # Перевірити або поновити облікові дані
    sudo -v

    # Очистити кеш автентифікації
    sudo -k

    # Запустити інтерактивну оболонку root
    sudo -i

    # Вийти з оболонки root
    exit

    # Виконати команду від імені іншого користувача
    sudo -u www-data whoami

    # Переглянути системний файл
    sudo less /etc/hosts

    # Записати текст у файл із підвищеними привілеями
    echo "example" | sudo tee /etc/example.conf

    # Дописати текст у кінець файлу
    echo "example" | sudo tee -a /etc/example.conf

    # Перевірити стан служби
    sudo systemctl status ssh

    # Пам'ятай:
    # sudo — виконання команди з дозволеними привілеями
    # root  — привілейований користувач
    # sudo -l — перевірка дозволених команд
    # sudo -k — очищення кешу автентифікації
    # sudo -i — інтерактивна оболонка root
    # tee — запис даних у файл через потік введення

## Висновок

`sudo` — важливий інструмент адміністрування Linux. Він дозволяє виконувати необхідні системні операції без постійної роботи під `root`.

Для розробника особливо важливо розуміти, коли потрібні адміністративні привілеї, як перевірити власні дозволи та чому не варто запускати звичайні інструменти розробки через `sudo` без потреби.

**Головне правило:** використовуйте найменший необхідний рівень привілеїв, перевіряйте команди перед запуском і не виконуйте незрозумілі адміністративні операції навмання.
