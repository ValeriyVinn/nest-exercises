# 01. Users and Groups

Users and Groups (користувачі та групи) — це базовий механізм Linux для ідентифікації користувачів і керування доступом до файлів, каталогів та системних ресурсів.

Linux використовує систему користувачів і груп, щоб визначати:

- хто володіє файлом або каталогом;
- хто може читати, змінювати та виконувати файли;
- до яких груп належить користувач;
- які дозволи користувач отримує через групове членство;
- хто має адміністративні права;
- які процеси виконуються від імені певного користувача.

Основні поняття Linux:

    user
    group
    UID
    GID
    username
    primary group
    supplementary groups
    root
    /etc/passwd
    /etc/shadow
    /etc/group
    /etc/gshadow
    id
    whoami
    groups
    useradd
    usermod
    userdel
    groupadd

    getent
    sudo

### Що потрібно пам'ятати

• Кожен користувач Linux має унікальний UID у межах системи.

• Кожна група має GID.

• Ім'я користувача — це зрозумілий людині ідентифікатор, а UID — числовий ідентифікатор, який використовує система.

• Користувач може входити до кількох груп.

• Primary group — основна група користувача.

• Supplementary groups — додаткові групи, членом яких є користувач.

• `root` — спеціальний суперкористувач із широкими адміністративними повноваженнями.

• Звичайний користувач не повинен постійно працювати з адміністративними правами.

• `/etc/passwd` містить облікові записи користувачів та їхні основні атрибути.

• `/etc/shadow` містить захищену інформацію про паролі та їхні параметри старіння.

• `/etc/group` містить інформацію про групи.

• `/etc/gshadow` містить захищену інформацію про групи та керування ними.

• `whoami` показує ім'я ефективного користувача поточного процесу.

• `id` показує UID, GID і групи поточного або вказаного користувача.

• `groups` показує групи користувача.

• `getent` дозволяє отримувати записи з системних баз облікових записів.

• `useradd` створює користувачів.

• `usermod` змінює параметри користувачів.

• `userdel` видаляє облікові записи користувачів.

• `groupadd` створює групи.

• `groupmod` змінює параметри груп.

• `groupdel` видаляє групи.

• Зміни членства в групах зазвичай набувають чинності для нових сеансів входу користувача.

• Користувач, який уже працює в терміналі, може не бачити нові групи у своєму поточному сеансі.

• Наявність користувача в групі сама по собі не гарантує доступу до файлу: потрібно також перевіряти права доступу та інші механізми контролю.

• Для адміністративних операцій використовують `sudo`, якщо це дозволено конфігурацією системи.

• Принцип least privilege означає надання лише тих прав, які необхідні для виконання завдання.

# User

User (користувач) — це обліковий запис, від імені якого Linux виконує процеси та перевіряє права доступу до системних ресурсів.

Користувач може бути:

    regular user
    system user
    root user

Наприклад:

    taubu

Це ім'я користувача в системі.

Користувач має певні атрибути:

    username
    UID
    primary GID
    home directory
    login shell

Типовий запис користувача містить ці атрибути у відповідних системних базах.

---

# Username

Username — ім'я облікового запису користувача.

Наприклад:

    taubu
    valer
    postgres
    root

Ім'я використовується в командах для звернення до конкретного користувача.

Наприклад:

    id taubu

Команда показує ідентифікатори користувача `taubu` та інформацію про його групи.

Важливо:

    username → ім'я користувача
    UID      → числовий ідентифікатор користувача

Це різні поняття.

---

# UID

UID (User ID) — числовий ідентифікатор користувача в Linux.

Кожен обліковий запис має UID, який система використовує для ідентифікації користувача.

Перевірити UID:

    id -u

Приклад результату:

    1000

Перевірити UID конкретного користувача:

    id -u taubu

Приклад результату:

    1000

Це лише приклад. Реальний UID залежить від конфігурації системи.

Отримати повну інформацію:

    id taubu

Приклад результату:

    uid=1000(taubu) gid=1000(taubu) groups=1000(taubu),27(sudo)

У цьому прикладі:

    uid=1000(taubu)  → UID і username
    gid=1000(taubu)  → основний GID і назва групи
    groups=...       → групи користувача

---

# Group

Group (група) — це набір користувачів, яким можна спільно надавати права доступу до файлів, каталогів та інших ресурсів.

Наприклад:

    developers
    students
    teachers
    sudo

Групи спрощують керування дозволами.

Замість того щоб налаштовувати доступ для кожного користувача окремо, можна призначити потрібну групу власником файлів і надати їй відповідні дозволи.

Наприклад:

    owner: root
    group: developers
    permissions: rwxrwx---

Це означає, що:

    owner       → має rwx
    group       → має rwx
    others      → не мають дозволів

Докладніше про права доступу буде в розділах:

    02-file-permissions
    03-chmod
    04-chown-chgrp

---

# GID

GID (Group ID) — числовий ідентифікатор групи.

Як UID ідентифікує користувача, так GID ідентифікує групу.

Перевірити основний GID поточного користувача:

    id -g

Перевірити назву основної групи:

    id -gn

Перевірити GID конкретної групи:

    getent group sudo

Приклад результату:

    sudo:x:27:taubu

Тут:

    sudo  → назва групи
    x     → поле пароля групи
    27    → GID
    taubu → учасник групи, зазначений у списку

Число `27` наведено лише для прикладу. GID може відрізнятися в різних системах.

---

# Primary Group

Primary group — основна група користувача.

Кожен користувач має основний GID.

Основна група зазвичай визначається полем GID у записі користувача в `/etc/passwd`.

Перевірити:

    id -gn

Або:

    id taubu

Приклад:

    uid=1000(taubu) gid=1000(taubu) groups=1000(taubu),27(sudo)

Тут:

    gid=1000(taubu)

Це основна група користувача.

Primary group часто використовується як група-власник для нових файлів, які створює користувач. Однак остаточна група файлу може залежати від каталогу, його setgid-біта та інших налаштувань.

Наприклад:

    touch example.txt
    ls -l example.txt

Можливий результат:

    -rw-rw-r-- 1 taubu taubu 0 Oct 18 20:00 example.txt

Тут:

    taubu → власник файлу
    taubu → група-власник файлу

Це типовий приклад, а не гарантований результат для кожної системи.

---

# Supplementary Groups

Supplementary groups — додаткові групи, до яких належить користувач.

Користувач може входити до кількох груп одночасно.

Наприклад:

    taubu
        ├── taubu
        ├── sudo
        └── developers

Умовно:

    primary group:
        taubu

    supplementary groups:
        sudo
        developers

Перевірити групи:

    groups

Або:

    groups taubu

Переглянути UID, GID та всі групи:

    id taubu

Додаткові групи можуть надавати доступ до певних ресурсів.

Наприклад, якщо каталог належить групі `developers` і має відповідні дозволи, члени цієї групи можуть отримати доступ до нього.

Важливо:

    membership in group
        ↓
    group permissions
        ↓
    access to resource

Членство в групі не означає автоматичного доступу до всіх файлів.

---

# User IDs: Real та Effective

Linux використовує кілька ідентифікаторів користувача для визначення того, від чийого імені працює процес.

Основні поняття:

    RUID → Real User ID
    EUID → Effective User ID

Також існують saved user ID та filesystem user ID, які мають значення в певних сценаріях.

## Real User ID (RUID)

RUID — ідентифікатор, пов'язаний із користувачем, який запустив процес.

## Effective User ID (EUID)

EUID — ідентифікатор, який зазвичай використовується під час перевірки прав доступу процесу до системних ресурсів.

Перевірити ефективного користувача:

    whoami

Перевірити UID поточного процесу:

    id -u

Для звичайного термінального сеансу ці значення часто відповідають одному користувачу.

Однак вони можуть відрізнятися, наприклад, у процесах із підвищеними привілеями.

Важливо пам'ятати:

    RUID → хто пов'язаний із запуском процесу
    EUID → від чийого імені процес зазвичай перевіряє права

Для початкового рівня достатньо розуміти призначення цих ідентифікаторів.

---

# Root

`root` — спеціальний суперкористувач Linux, який має широкі адміністративні повноваження.

Зазвичай:

    username: root
    UID: 0

Перевірити:

    id root

Приклад результату:

    uid=0(root) gid=0(root) groups=0(root)

UID `0` має особливе значення в Linux: процеси з відповідними привілеями можуть виконувати операції, недоступні звичайним користувачам.

Користувач root може, зокрема:

    змінювати системні файли;
    керувати користувачами та групами;
    встановлювати системні пакети;
    змінювати права доступу;
    керувати службами;
    змінювати системну конфігурацію.

Проте конкретні можливості процесу можуть додатково обмежуватися capabilities, просторами імен, політиками безпеки та іншими механізмами.

## Перевірка root

    whoami

Якщо команда виводить:

    root

поточний ефективний користувач має ім'я `root`.

Інша перевірка:

    id -u

Результат:

    0

## Root та sudo

Звичайний користувач може отримувати адміністративні привілеї для окремих команд через `sudo`, якщо це дозволено системною конфігурацією.

Наприклад:

    sudo apt update

У цьому випадку команда виконується з адміністративними привілеями.

Не потрібно постійно працювати від імені root.

Правильний принцип:

    regular user
        ↓
    sudo для необхідних адміністративних операцій

Це зменшує ризик випадково пошкодити систему.

Докладніше:

    05-sudo

# Regular User

Regular user — звичайний користувач системи.

Такий користувач зазвичай працює зі своїми файлами, запускає програми, редагує код і виконує повсякденні завдання.

Приклади:

    taubu
    valer

Звичайний користувач зазвичай має:

    username
    UID
    primary group
    home directory
    login shell

Його можливості залежать від прав доступу, членства в групах і системної конфігурації.

Приклад домашнього каталогу:

    /home/taubu

Перевірити домашній каталог поточного користувача:

    echo "$HOME"

Перевірити обліковий запис:

    id

Важливо: звичайний користувач також може бути членом адміністративної групи або мати дозвіл на використання `sudo`.

---

# System User

System user — обліковий запис, який використовується для роботи системних служб, програм і фонових процесів.

Приклади:

    postgres
    www-data
    nobody

Конкретні системні користувачі залежать від установлених пакетів і конфігурації Linux.

Наприклад, сервер PostgreSQL часто працює від імені користувача:

    postgres

Перевірити:

    id postgres

Системні користувачі можуть мати:

    окремий UID;
    окрему основну групу;
    спеціальний домашній каталог;
    shell, який не призначений для інтерактивного входу.

Наприклад, у системі може використовуватися:

    /usr/sbin/nologin

Це обмежує звичайний інтерактивний вхід через цей shell, але не заважає виконанню службових процесів від імені відповідного користувача.

Не всі системні користувачі обов'язково мають однакові UID або однакові налаштування.

---

# Home Directory

Home directory — домашній каталог користувача.

У ньому зазвичай зберігаються особисті файли, налаштування програм, SSH-ключі та інші дані користувача.

Типові шляхи:

    /home/taubu
    /home/valer
    /root

Для звичайного користувача домашній каталог часто розташований у `/home`.

Для root типовим домашнім каталогом є:

    /root

Перевірити домашній каталог:

    echo "$HOME"

Переглянути каталог:

    ls -la "$HOME"

Перевірити домашній каталог конкретного користувача:

    getent passwd taubu

Приклад результату:

    taubu:x:1000:1000:User:/home/taubu:/bin/bash

У цьому прикладі:

    /home/taubu → home directory

Шлях залежить від конфігурації системи.

---

# Login Shell

Login shell — командна оболонка, яка призначена користувачеві для входу в систему.

Приклади:

    /bin/bash
    /bin/sh
    /usr/bin/zsh
    /usr/sbin/nologin

Перевірити shell поточного процесу:

    echo "$SHELL"

Перевірити запис користувача:

    getent passwd taubu

Приклад:

    taubu:x:1000:1000:User:/home/taubu:/bin/bash

Останнє поле:

    /bin/bash

Це shell, указаний в обліковому записі.

Важливо розрізняти:

    $SHELL
        → shell, зазначений у середовищі поточного сеансу

    поле shell у /etc/passwd
        → shell, налаштований для облікового запису

Ці значення не завжди збігаються.

---

# /etc/passwd

`/etc/passwd` — системний файл, який містить записи облікових записів користувачів.

Переглянути файл:

    cat /etc/passwd

Оскільки файл містить багато записів, зручніше використовувати:

    less /etc/passwd

Знайти конкретного користувача:

    getent passwd taubu

Приклад запису:

    taubu:x:1000:1000:User:/home/taubu:/bin/bash

Запис містить сім полів, розділених двокрапками:

    username:password:UID:GID:GECOS:home_directory:shell

Розглянемо їх.

    taubu       → username
    x           → поле пароля
    1000        → UID
    1000        → основний GID
    User        → GECOS / інформаційне поле
    /home/taubu → home directory
    /bin/bash   → login shell

## Поле password

У сучасних системах поле часто містить:

    x

Це означає, що парольні дані зберігаються окремо, зазвичай у `/etc/shadow`.

Не потрібно плутати `x` із самим паролем.

## GECOS

GECOS — інформаційне поле, яке може містити ім'я користувача, контактну інформацію або інші описові дані.

## Важливо

`/etc/passwd` не є файлом, де зазвичай зберігаються відкриті паролі користувачів.

Звичайні користувачі часто можуть читати цей файл, оскільки системним програмам потрібна інформація про облікові записи.

Не редагуй його вручну без необхідності.

Для керування обліковими записами використовуй відповідні команди.

# /etc/shadow

`/etc/shadow` — системний файл, який містить захищені парольні дані та параметри старіння паролів.

Переглянути його вміст зазвичай може root або користувач із відповідними привілеями.

Наприклад:

    sudo less /etc/shadow

Не публікуй вміст цього файлу та не копіюй його в загальнодоступні місця.

Запис у файлі зазвичай має дев'ять полів:

    username:password:last_change:min:max:warn:inactive:expire:reserved

Поля:

    username   → ім'я користувача
    password   → парольний хеш або спеціальне позначення
    last_change → дата останньої зміни пароля в днях від початку Unix epoch
    min        → мінімальний інтервал між змінами пароля
    max        → максимальний термін дії пароля
    warn       → кількість днів попередження до завершення терміну
    inactive   → період неактивності після завершення терміну дії пароля
    expire     → дата завершення дії облікового запису в днях від початку Unix epoch
    reserved   → зарезервоване поле

Не всі поля обов'язково заповнені.

## Основне правило

    /etc/passwd
        → загальна інформація про користувача

    /etc/shadow
        → захищені парольні дані та параметри старіння

Для встановлення або зміни пароля використовуй:

    passwd

Наприклад, зміна власного пароля:

    passwd

Зміна пароля іншого користувача з адміністративними правами:

    sudo passwd username

Заміни `username` реальним ім'ям потрібного облікового запису.

# /etc/group

`/etc/group` — системний файл, який містить записи груп.

Переглянути:

    cat /etc/group

Знайти конкретну групу:

    getent group sudo

Приклад:

    developers:x:2000:taubu,valer

Запис має чотири поля:

    group_name:password:GID:members

У цьому прикладі:

    developers     → назва групи
    x              → поле пароля групи
    2000           → GID
    taubu,valer    → список додаткових учасників

Важливо: список учасників у `/etc/group` показує членів групи, перелічених у цьому полі. Він не обов'язково містить усіх користувачів, для яких ця група є основною.

Щоб перевірити членство конкретного користувача, краще використовувати:

    id taubu

Або:

    groups taubu

# /etc/gshadow

`/etc/gshadow` — захищений системний файл, який містить додаткову інформацію про групи.

Зокрема, він може містити:

    назву групи;
    парольне поле;
    адміністраторів групи;
    список учасників групи.

Перегляд із відповідними привілеями:

    sudo less /etc/gshadow

Для звичайного навчання достатньо пам'ятати:

    /etc/group
        → загальна інформація про групи

    /etc/gshadow
        → захищена інформація про групи

Не редагуй ці файли вручну без чіткого розуміння наслідків.

# NSS та getent

Linux може отримувати інформацію про користувачів і групи не лише з локальних файлів.

Для цього використовується NSS (Name Service Switch), який визначає джерела системної інформації.

Джерелами можуть бути:

    локальні файли;
    LDAP;
    інші налаштовані служби каталогів.

Тому для перевірки облікових записів часто краще використовувати `getent`, а не читати лише локальні файли.

Приклади:

    getent passwd
    getent passwd taubu
    getent group
    getent group sudo

Отримати запис користувача:

    getent passwd taubu

Отримати запис групи:

    getent group developers

Якщо запис не знайдено, команда зазвичай нічого не виводить і повертає ненульовий код завершення.

Важливо:

    /etc/passwd
        → локальний файл користувачів

    getent passwd
        → користувачі, доступні через налаштовані NSS-джерела

Якщо виконати:

Важливо:

    whoami
        → ефективне ім'я користувача

Команда не показує повний список груп або всі атрибути облікового запису.

Для цього використовуй:

# id

`id` — одна з найважливіших команд для перевірки користувачів і груп.

Показати інформацію про поточного користувача:

    id

Приклад:

    uid=1000(taubu) gid=1000(taubu) groups=1000(taubu),27(sudo)

Показати інформацію про конкретного користувача:

    id taubu

Показати UID:

    id -u

Показати GID основної групи:

    id -g

Показати назву основної групи:

    id -gn

Показати всі групи у вигляді числових GID:

    id -G

Показати всі групи за назвами:

    id -Gn

## Швидке запам'ятовування

    id       → UID, GID, groups
    id -u    → UID
    id -g    → primary GID
    id -G    → усі GID
    id -gn   → назва primary group
    id -Gn   → назви всіх груп

# groups

`groups` показує групи, до яких належить користувач.

Поточний користувач:

    groups

Конкретний користувач:

    groups taubu

Приклад результату:

    taubu sudo developers

Важливо: результат для поточного процесу може відрізнятися від результату для нового сеансу після зміни членства в групах.

Для більш детальної інформації використовуй:

    id

# useradd

`useradd` створює новий обліковий запис користувача.

Команда зазвичай потребує адміністративних привілеїв.

Створити користувача:

    sudo useradd username

Заміни `username` потрібним ім'ям.

Увага: поведінка команди щодо створення домашнього каталогу залежить від параметрів і конфігурації системи.

Створити користувача з домашнім каталогом:

    sudo useradd -m username

Вказати основну групу:

    sudo useradd -m -g developers username

Вказати shell:

    sudo useradd -m -s /bin/bash username

Створити користувача з домашнім каталогом і shell:

    sudo useradd -m -s /bin/bash username

Встановити пароль:

    sudo passwd username

Перевірити обліковий запис:

    id username

Перевірити запис користувача:

    getent passwd username

## Важливо

Команда `useradd` створює обліковий запис, але не в усіх конфігураціях автоматично виконує всі кроки, необхідні для повноцінного інтерактивного входу.

Залежно від системи можуть знадобитися:

    встановлення пароля;
    налаштування груп;
    перевірка домашнього каталогу;
    перевірка shell.

---

# usermod

`usermod` змінює параметри наявного користувача.

Додати користувача до додаткової групи:

    sudo usermod -aG developers username

Тут:

    -a → append, додати до наявного списку груп
    -G → задати список додаткових груп

Це важлива команда.

## Чому потрібен -aG

Правильно:

    sudo usermod -aG developers username

Команда додає користувача до групи `developers`, зберігаючи наявне членство в додаткових групах.

Небезпечний для випадкового використання варіант:

    sudo usermod -G developers username

Без `-a` параметр `-G` задає новий список додаткових груп. Інші групи, яких немає у вказаному списку, можуть бути видалені зі списку членства користувача.

Перевірити результат:

    id username

## Змінити основну групу

    sudo usermod -g developers username

Тут:

    -g → primary group

## Змінити login shell

    sudo usermod -s /bin/bash username

## Змінити домашній каталог

    sudo usermod -d /home/newname username

Ця команда змінює шлях домашнього каталогу в записі користувача, але сама по собі не обов'язково переносить наявні файли.

Щоб також перемістити домашній каталог, застосовують відповідний параметр `-m` після перевірки ситуації:

    sudo usermod -d /home/newname -m username

Перед такими змінами потрібно переконатися, що новий шлях не конфліктує з наявними файлами.

---

# userdel

`userdel` видаляє обліковий запис користувача.

Видалити обліковий запис:

    sudo userdel username

Видалити обліковий запис разом із домашнім каталогом і поштовим каталогом, якщо він існує:

    sudo userdel -r username

Увага: `-r` може видалити дані користувача.

Перед видаленням облікового запису перевір:

    чи потрібні його файли;
    чи працюють від його імені процеси;
    чи належать йому файли поза домашнім каталогом;
    чи використовують його інші служби.

Перевірити наявність користувача:

    getent passwd username

Після видалення запис може бути відсутнім, якщо обліковий запис більше не доступний через NSS.

# groupadd

`groupadd` створює нову групу.

Приклад:

    sudo groupadd developers

Перевірити:

    getent group developers

Можливий результат:

    developers:x:2000:

GID `2000` наведено для прикладу.

Створити групу з явно заданим GID:

    sudo groupadd -g 2500 developers

Вказувати конкретний GID потрібно лише тоді, коли це справді необхідно та не створює конфліктів.

Для звичайного навчання достатньо:

    sudo groupadd developers

# groupmod

`groupmod` змінює параметри наявної групи.

Перейменувати групу:

    sudo groupmod -n developers-backend developers

Тут:

    -n → new name

Перевірити:

    getent group developers-backend

Змінити GID групи:

    sudo groupmod -g 2500 developers-backend

Змінювати GID потрібно обережно, оскільки файли на диску можуть продовжувати містити старий числовий GID у метаданих.

Перейменування групи або зміна GID не означає, що всі файли, пов'язані з нею, автоматично отримають потрібну нову конфігурацію власності.

# groupdel

`groupdel` видаляє групу.

Приклад:

    sudo groupdel developers

Перед видаленням потрібно перевірити, чи використовується група іншими обліковими записами або системними ресурсами.

Не можна безпечно видаляти основну групу користувача, поки вона використовується як його primary group.

Перевірити групу:

    getent group developers

Перевірити членство користувача:

    id username

# passwd

`passwd` використовується для встановлення або зміни пароля.

Змінити власний пароль:

    passwd

Змінити пароль іншого користувача з адміністративними правами:

    sudo passwd username

Заблокувати пароль облікового запису:

    sudo passwd -l username

Розблокувати пароль:

    sudo passwd -u username

Важливо: блокування пароля не обов'язково блокує всі можливі способи входу в систему. Доступ через SSH-ключі або інші механізми автентифікації може залежати від окремих налаштувань.

Для керування строком дії пароля та пов'язаними параметрами існують інші інструменти, зокрема `chage`.

Не плутай блокування пароля з повним блокуванням облікового запису.

# su

`su` дозволяє перейти до іншого користувача.

Наприклад:

    su username

У цьому випадку виконується перехід до користувача `username`, якщо автентифікація та політики системи це дозволяють.

Перейти до root із завантаженням його login environment:

    su -

У багатьох системах Ubuntu root-акаунт може бути заблокований для звичайного входу за паролем. Тому `su -` не завжди доступний для адміністративного переходу.

Для адміністративних команд в Ubuntu зазвичай використовують:

    sudo command

Для запуску інтерактивної оболонки з адміністративними привілеями:

    sudo -i

Використовуй адміністративну оболонку лише тоді, коли вона справді потрібна.

# sudo

`sudo` дозволяє виконувати команди з привілеями іншого користувача, зазвичай root.

Приклад:

    sudo apt update

Перевірити, які команди дозволені поточному користувачеві:

    sudo -l

Успішне використання `sudo` залежить від системної конфігурації та правил доступу.

На багатьох системах Ubuntu користувачі адміністративної групи `sudo` можуть отримувати відповідні привілеї.

Перевірити членство:

    groups

Або:

    id

Важливо:

    sudo → контрольоване підвищення привілеїв
    root → суперкористувач
    regular user → звичайний користувач

Докладніше:

    05-sudo

# Створення користувача: практичний сценарій

Припустімо, потрібно створити користувача `student01` і додати його до групи `developers`.

## Крок 1. Створити групу

    sudo groupadd developers

Якщо група вже існує, не потрібно створювати її повторно.

Перевірка:

    getent group developers

## Крок 2. Створити користувача

    sudo useradd -m -s /bin/bash student01

Тут:

    -m        → створити домашній каталог
    -s        → задати login shell
    /bin/bash → Bash

## Крок 3. Встановити пароль

    sudo passwd student01

Введи пароль у відповідь на запит термінала.

## Крок 4. Додати до групи

    sudo usermod -aG developers student01

## Крок 5. Перевірити користувача

    id student01

## Крок 6. Перевірити групу

    getent group developers

## Крок 7. Перевірити запис користувача

    getent passwd student01

У результаті потрібно переконатися, що:

    обліковий запис існує;
    домашній каталог створено;
    shell налаштовано;
    користувач входить до потрібної групи.

Це базовий практичний сценарій керування користувачами й групами.

# Практична робота з поточним користувачем

Для початку не потрібно створювати нові облікові записи або змінювати систему.

Виконай команди:

    whoami

    id

    id -u

    id -g

    id -gn

    groups

    echo "$HOME"

    echo "$SHELL"

Потім перевір системні записи:

    getent passwd "$(whoami)"

    getent group "$(id -gn)"

Переглянь інформацію про root:

    id root

Переглянь записи користувачів:

    getent passwd

Переглянь записи груп:

    getent group

Зверни увагу на:

    username;
    UID;
    primary GID;
    supplementary groups;
    home directory;
    login shell.

Це дозволить зрозуміти, як Linux ідентифікує поточного користувача.

# Типові помилки

## 1. Плутати username та UID

Неправильно:

    username = 1000

Правильно розуміти:

    username → ім'я облікового запису
    UID      → числовий ідентифікатор

UID може бути різним у різних системах.

---

## 2. Плутати group name та GID

    developers → назва групи
    2000       → приклад GID

Назва групи та її числовий ідентифікатор — різні речі.

---

## 3. Вважати, що користувач має лише одну групу

Користувач має одну primary group, але може входити до багатьох supplementary groups.

Перевірка:

    id username

---

## 4. Забути параметр -a у usermod -aG

Небезпечний для випадкового використання приклад:

    sudo usermod -G developers username

Ця команда може замінити наявний список додаткових груп.

Для додавання користувача до нової групи зазвичай використовують:

    sudo usermod -aG developers username

---

## 5. Очікувати, що зміни груп одразу з'являться в поточному сеансі

Після зміни членства в групах поточний процес може продовжувати використовувати старі групові ідентифікатори.

Перевірка після повторного входу:

    id

У деяких ситуаціях нове членство можна застосувати до окремого сеансу за допомогою відповідних інструментів, але для початкового рівня найпростіше повторно увійти в систему.

---

## 6. Вважати, що /etc/passwd містить відкриті паролі

У сучасних системах парольні дані зазвичай зберігаються в `/etc/shadow`.

    /etc/passwd → атрибути користувачів
    /etc/shadow → захищені парольні дані

---

## 7. Вважати, що /etc/group містить усіх учасників групи в кожному випадку

Поле учасників у `/etc/group` не обов'язково перелічує користувачів, для яких ця група є основною.

Для перевірки конкретного користувача використовуй:

    id username

---

## 8. Видаляти користувача без перевірки його файлів

Команда:

    sudo userdel -r username

може видалити домашній каталог і поштові дані користувача.

Перед видаленням потрібно перевірити, чи не містить каталог потрібних файлів.

---

## 9. Працювати постійно від root

Постійна робота з адміністративними привілеями підвищує ризик помилок.

Для повсякденних завдань використовуй звичайного користувача, а `sudo` — лише коли це необхідно.

---

## 10. Вважати, що група автоматично надає всі права

Членство в групі лише бере участь у механізмі перевірки доступу.

Потрібно також враховувати:

    власника файлу;
    групу-власника;
    permissions;
    ACL;
    атрибути файлу;
    системні політики безпеки.

# Головне

• Linux ідентифікує користувачів за UID, а групи — за GID.

• Username та назва групи потрібні для зручного звернення до облікових записів.

• Кожен користувач має основну групу та може мати додаткові групи.

• Root — спеціальний суперкористувач, UID якого зазвичай дорівнює `0`.

• Системні користувачі часто використовуються для запуску служб і фонових процесів.

• `/etc/passwd` містить основні атрибути облікових записів користувачів.

• `/etc/shadow` містить захищені парольні дані та параметри старіння паролів.

• `/etc/group` містить інформацію про групи.

• `/etc/gshadow` містить захищену інформацію про групи.

• `getent` дозволяє отримувати інформацію з налаштованих системних джерел облікових записів.

• `whoami` показує ефективне ім'я поточного користувача.

• `id` показує UID, GID та групи.

• `groups` показує групи користувача.

• `useradd` створює користувачів.

• `usermod` змінює параметри користувачів.

• `userdel` видаляє користувачів.

• `groupadd` створює групи.

• `groupmod` змінює параметри груп.

• `groupdel` видаляє групи.

• `passwd` використовується для зміни пароля.

• `sudo` дозволяє виконувати дозволені адміністративні команди.

• Під час додавання користувача до додаткової групи зазвичай потрібно використовувати:

    sudo usermod -aG groupname username

• Після зміни членства в групах може знадобитися новий сеанс входу.

• Членство в групі не гарантує автоматичного доступу до файлу: потрібно враховувати права доступу та інші механізми контролю.

• Не варто постійно працювати від імені root.

• Принцип least privilege означає надання лише необхідних привілеїв.

• Перед видаленням користувача або зміною його груп потрібно перевірити наслідки для файлів і служб.

• Основна модель Linux:

    User
      ↓
    UID
      ↓
    Primary Group + Supplementary Groups
      ↓
    GID + Group Membership
      ↓
    Process Credentials
      ↓
    Access Control
      ↓
    Files, Directories and System Resources

• **Головна мета вивчення users and groups — зрозуміти, як Linux ідентифікує користувачів і групи, та як ця інформація використовується для керування доступом до системних ресурсів.**
