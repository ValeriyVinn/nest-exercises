# 06. Umask

`umask` (user file-creation mode mask) — це маска прав доступу, яка визначає, які дозволи потрібно прибрати з типових прав під час створення нових файлів і каталогів у Linux.

Вона впливає на права нових об'єктів, створених поточним процесом і його дочірніми процесами. `umask` не змінює права вже наявних файлів і каталогів.

## ✔ Що потрібно знати

- Що таке `umask` і для чого вона потрібна.
- Як переглянути поточне значення `umask`.
- Як встановити маску у символьному та числовому форматах.
- Чому для файлів і каталогів використовуються різні початкові права.
- Як обчислюються кінцеві права нового файла або каталогу.
- Як `umask` пов'язана з `chmod`, `rwx` та восьмеричною системою прав.
- Як тимчасово змінити маску для поточної сесії.
- Як налаштувати `umask` для майбутніх сесій.
- Як перевіряти фактичні права за допомогою `ls -l` і `stat`.
- Чому `umask` — це не повноцінний механізм керування правами доступу.

---

## 1. Навіщо потрібна umask

У Linux кожен файл і каталог має права доступу для трьох категорій користувачів:

- `u` — user, власник;
- `g` — group, група;
- `o` — others, інші користувачі.

Кожна категорія може отримати такі дозволи:

- `r` — читання;
- `w` — запис;
- `x` — виконання або доступ до каталогу.

Коли програма створює новий файл або каталог, Linux враховує початкові права, які запитує програма, і поточну маску `umask`.

Наприклад, якщо поточна маска дорівнює `022`, за типових початкових прав результат буде таким:

    Новий файл:      666 - 022 → 644
    Новий каталог:   777 - 022 → 755

Це означає:

- новий файл зазвичай матиме права `rw-r--r--`;
- новий каталог зазвичай матиме права `rwxr-xr-x`.

Важливо: це приклад для типових початкових режимів створення. Програма може запитувати інші права, а її власна логіка також може впливати на результат.

### Навіщо це потрібно

Уявімо, що ти створюєш файл із навчальним кодом:

    touch app.js

Ти не хочеш, щоб усі користувачі системи могли змінювати його вміст. `umask` дозволяє заздалегідь обмежити права нових об'єктів без необхідності щоразу виконувати `chmod`.

---

## 2. Перегляд поточного значення umask

Щоб подивитися поточну маску, виконай:

    umask

Приклад результату:

    0022

У деяких оболонках результат може відображатися як `022`.

Це нормальна поведінка: початковий нуль у восьмеричному записі не змінює значення маски.

### Символьний формат

Можна переглянути маску в символьному форматі:

    umask -S

Приклад результату:

    u=rwx,g=rx,o=rx

Цей запис показує дозволи, які відповідають масці `022` у символьному представленні.

**Зверни увагу:** `umask -S` показує дозволи, які маска залишає, а не ті, які вона забороняє.

### Перевірка в терміналі

    umask
    umask -S

Перша команда показує числову маску, друга — символьне представлення.

## 3. Як працює система прав доступу

Перед вивченням `umask` потрібно пам'ятати числові значення прав.

| Дозвіл | Символ | Числове значення |
|---|---|---:|
| Читання | `r` | 4 |
| Запис | `w` | 2 |
| Виконання | `x` | 1 |
| Немає дозволів | `-` | 0 |

Права трьох категорій записуються окремими цифрами.

Наприклад:

    rwx rwx rwx → 777
    rwx r-x r-x → 755
    rw- r-- r-- → 644
    rw- rw- --- → 660
    rw- --- --- → 600

Пам'ятай:

- перша цифра — права власника;
- друга цифра — права групи;
- третя цифра — права інших користувачів.

### Приклад

    chmod 640 report.txt

Отримаємо:

    rw- r-- ---

Власник може читати й змінювати файл, група може лише читати, а інші користувачі не мають доступу.

Докладніше про числові права дивись у темі `03-chmod`.

---

## 4. Початкові права для файлів і каталогів

Для розуміння `umask` потрібно знати типові початкові режими створення.

### Звичайні файли

Типовий початковий режим:

    666

У символьному форматі:

    rw-rw-rw-

У ньому немає права `x`, тобто виконання.

Це зроблено тому, що новий файл із текстом або даними не повинен автоматично ставати виконуваною програмою.

### Каталоги

Типовий початковий режим:

    777

У символьному форматі:

    rwxrwxrwx

Для каталогів право `x` потрібне, щоб мати змогу переходити до каталогу та звертатися до об'єктів усередині нього за відповідних дозволів.

### Чому режими різні

| Об'єкт | Типовий початковий режим | Причина |
|---|---:|---|
| Звичайний файл | `666` | Читання та запис без автоматичного дозволу виконання |
| Каталог | `777` | Читання, зміна вмісту та доступ до каталогу |

Це початкові режими, які зазвичай запитуються під час створення. Фактичні права можуть бути суворішими через `umask` або додаткові механізми доступу.

## 5. Як обчислюються права за допомогою umask

`umask` — це маска, яка прибирає певні біти дозволів із запитаних початкових прав.

У типових прикладах можна користуватися таким арифметичним записом:

    Початковий режим - umask = кінцевий режим

Наприклад:

    666 - 022 = 644

Але важливо розуміти: **це зручне скорочення для типових випадків, а не універсальне правило звичайного віднімання.** Насправді `umask` працює на рівні бітів дозволів.

Для типових режимів створення практично зручно користуватися таблицею нижче.

### Приклад 1. Маска 022

    umask 022

Новий файл:

    666 → 644
    rw-rw-rw- → rw-r--r--

Новий каталог:

    777 → 755
    rwxrwxrwx → rwxr-xr-x

Маска `022` прибирає право запису для групи та інших користувачів.

### Приклад 2. Маска 027

    umask 027

Новий файл:

    666 → 640
    rw-rw-rw- → rw-r-----

Новий каталог:

    777 → 750
    rwxrwxrwx → rwxr-x---

Маска `027` прибирає:

- право запису для групи;
- усі типові дозволи для інших користувачів, крім тих, які маска залишає, а саме жодного.

Результат:

- власник має повний доступ до каталогу;
- група може читати та заходити до каталогу;
- інші користувачі не мають доступу.

### Приклад 3. Маска 077

    umask 077

Новий файл:

    666 → 600
    rw-rw-rw- → rw-------

Новий каталог:

    777 → 700
    rwxrwxrwx → rwx------

Тільки власник отримує дозволи за типових початкових режимів.

### Приклад 4. Маска 002

    umask 002

Новий файл:

    666 → 664
    rw-rw-rw- → rw-rw-r--

Новий каталог:

    777 → 775
    rwxrwxrwx → rwxrwxr-x

Цей варіант часто корисний для спільної роботи в групі, коли члени групи мають право змінювати файли.

Однак для спільної роботи лише `umask 002` може бути недостатньо: доступ також залежить від групи власників, групового каталогу та інших налаштувань.

## 6. Таблиця поширених значень umask

| `umask` | Типові права файла | Типові права каталогу | Пояснення |
|---|---:|---:|---|
| `000` | `666` | `777` | Маска не прибирає типові дозволи |
| `002` | `664` | `775` | Група може записувати |
| `007` | `660` | `770` | Інші користувачі не мають доступу |
| `022` | `644` | `755` | Група й інші не можуть записувати |
| `027` | `640` | `750` | Інші не мають доступу |
| `077` | `600` | `700` | Доступ лише власнику |
| `111` | `666` | `666` | Прибирається право виконання, але файли зазвичай і так не запитують його |

Останній приклад потребує уточнення: маска `111` прибирає право виконання з усіх категорій. Для звичайного файла з типовим початковим режимом `666` результат не зміниться, оскільки права `x` там уже відсутні. Для каталогу типовий режим `777` перетвориться на `666`, і це зазвичай зробить каталог непридатним для нормального доступу до його вмісту.

---

## 7. Зміна umask

Щоб установити нове значення маски, використай команду:

    umask 022

Інший приклад:

    umask 027

Або:

    umask 077

Команда змінює маску поточної оболонки. Зазвичай вона діє для об'єктів, створених цією оболонкою та процесами, які успадковують відповідне значення.

### Важливо

Зміна `umask`:

- не змінює права вже наявних файлів;
- не змінює права вже наявних каталогів;
- не є постійним налаштуванням для всіх майбутніх входів у систему;
- впливає на нові об'єкти, коли процеси створюють їх із відповідними режимами.

### Перевірка

    umask
    umask 027
    umask

Після другої команди третя повинна показати нове значення маски.

## 8. Символьний формат umask

Крім числового формату, `umask` підтримує символьний запис.

Наприклад:

    umask u=rwx,g=rx,o=

Цей запис задає маску так, щоб дозволи, які вона залишає, відповідали таким категоріям:

- власник: `rwx`;
- група: `r-x`;
- інші: жодних дозволів.

Еквівалентне числове значення в цьому випадку:

    027

Можна також використовувати символьні операції:

    umask u-w
    umask g-w
    umask o-rwx

Проте для початківця числовий формат зазвичай простіше читати й перевіряти.

**Порада:** коли вивчаєш Linux, почни з числових значень `002`, `022`, `027` і `077`. Символьний формат опануй після того, як добре зрозумієш числову маску.

## 9. Практика: створення файла й каталогу

Створи навчальну директорію:

    mkdir -p ~/linux-practice/umask
    cd ~/linux-practice/umask

Перевір поточну маску:

    umask

Встанови маску `022`:

    umask 022

Створи файл і каталог:

    touch file-022.txt
    mkdir dir-022

Переглянь права:

    ls -l
    stat -c '%A %a %n' file-022.txt dir-022

За типових умов очікуваний результат:

    -rw-r--r-- 644 file-022.txt
    drwxr-xr-x 755 dir-022

Точний формат виведення `stat` залежить від команди й системи, але числові режими зазвичай будуть `644` і `755`.

### Перевірка з umask 077

    umask 077

Створи ще два об'єкти:

    touch file-077.txt
    mkdir dir-077

Перевір:

    stat -c '%A %a %n' file-077.txt dir-077

За типових умов:

    -rw------- 600 file-077.txt
    drwx------ 700 dir-077

Порівняй результати: нові об'єкти отримали різні права через різні маски.

---

## 10. Практика: порівняння кількох масок

Виконай команди:

    umask 002
    touch file-002.txt
    mkdir dir-002

    umask 022
    touch file-022-b.txt
    mkdir dir-022-b

    umask 077
    touch file-077-b.txt
    mkdir dir-077-b

Перевір усі результати:

    ls -l
    stat -c '%a %n' file-002.txt file-022-b.txt file-077-b.txt
    stat -c '%a %n' dir-002 dir-022-b dir-077-b

Очікувані типові права:

    file-002.txt  → 664
    dir-002       → 775

    file-022-b.txt → 644
    dir-022-b      → 755

    file-077-b.txt → 600
    dir-077-b      → 700

Зверни увагу, що зміна маски впливає на об'єкти, створені після зміни, а не на попередні.

## 11. Як зробити umask постійною

Команда `umask 027` зазвичай змінює маску лише в поточній оболонці та процесах, які її успадкували.

Якщо закрити термінал і відкрити новий, маска може повернутися до значення, заданого системою або конфігурацією оболонки.

Для інтерактивної Bash-оболонки можна додати команду до `~/.bashrc`.

Відкрий файл:

    nano ~/.bashrc

Додай наприкінці:

    umask 027

Збережи файл і перезавантаж налаштування:

    source ~/.bashrc

Перевір:

    umask

Тепер інтерактивні Bash-оболонки, які читають цей файл, зазвичай використовуватимуть задану маску.

### Чому це не завжди працює для всіх програм

Linux має різні способи запуску процесів і різні конфігураційні файли для оболонок, входу в систему та системних служб.

Тому потрібно розрізняти:

- інтерактивну оболонку Bash;
- оболонку входу в систему;
- SSH-сеанс;
- графічну сесію;
- системну службу;
- процес, запущений іншим користувачем.

Якщо потрібно змінити маску для конкретної служби або всіх сеансів користувача, слід перевіряти, як саме запускається відповідний процес і звідки він успадковує `umask`.

## 12. Тимчасова umask для однієї команди

Можна виконати команду в окремій дочірній оболонці з іншою маскою:

    (umask 077; touch private.txt; mkdir private-dir)

Дужки створюють підоболонку. Усередині неї:

1. встановлюється маска `077`;
2. створюється файл;
3. створюється каталог;
4. після завершення підоболонки її локальні зміни маски не змінюють маску батьківської оболонки.

Перевір:

    stat -c '%a %n' private.txt private-dir
    umask

За типових умов файл матиме права `600`, каталог — `700`, а остання команда покаже маску батьківської оболонки.

### Чому не можна просто написати `umask 077; touch private.txt`?

Можна, але тоді маска зміниться в поточній оболонці й залишиться такою до наступної зміни або завершення оболонки.

Дужки корисні, якщо потрібно обмежити дію маски певним набором команд.

## 13. Umask і перенаправлення в Bash

`umask` впливає також на створення файла через перенаправлення, наприклад:

    umask 027
    echo "Hello Linux" > report.txt

Якщо `report.txt` ще не існує, Bash створює його з урахуванням маски й початкових прав, які запитує оболонка.

За типових умов новий файл матиме права:

    640

Якщо файл уже існує, перенаправлення `>` зазвичай очищає його вміст, але **не встановлює заново права відповідно до поточної `umask`**.

Перевір:

    ls -l report.txt
    stat -c '%a %n' report.txt

### Перенаправлення не є chmod

Команди:

    echo "Text" > report.txt
    chmod 600 report.txt

виконують різні дії.

- Перша записує текст у файл і створює файл, якщо його немає.
- Друга змінює права доступу до вже наявного файла.

## 14. Umask і chmod — у чому різниця

Це дві різні команди з різним призначенням.

| Команда | Призначення |
|---|---|
| `umask` | Визначає, які дозволи прибираються під час створення нових об'єктів |
| `chmod` | Змінює права доступу до вже наявних об'єктів або встановлює права після створення |
| `chown` | Змінює власника |
| `chgrp` | Змінює групу власника |

Приклад:

    umask 077
    touch private.txt
    chmod 644 private.txt

Спочатку файл створюється за маскою `077`. За типових умов він отримує права `600`.

Потім `chmod 644` явно встановлює права:

    rw-r--r--

Отже, `chmod` може змінити права так, що кінцевий результат більше не відповідає обмеженням, які давала маска під час створення.

**Запам'ятай:** `umask` не є постійним обмеженням, яке автоматично забороняє встановити ширші права через `chmod`.

## 15. Umask і спільна робота над проєктом

Уявімо, що кілька користувачів працюють над спільним проєктом.

Потрібно, щоб власник і члени групи могли редагувати файли, але сторонні користувачі не мали доступу.

Один із можливих варіантів:

    umask 007

За типових початкових режимів:

    Файл:    660
    Каталог: 770

У символьному форматі:

    Файл:    rw-rw----
    Каталог: rwxrwx---

Це дозволяє власнику й групі мати відповідні дозволи, а іншим користувачам — не мати дозволів через звичайні біти доступу.

Однак для коректної спільної роботи також можуть знадобитися:

- спільна група для учасників;
- правильна група власника каталогу;
- setgid-біт для каталогу;
- за потреби ACL;
- узгоджені налаштування `umask` для всіх учасників.

Приклад створення каталогу для групової роботи:

    mkdir shared-project
    chgrp developers shared-project
    chmod 2770 shared-project

Тут `developers` — приклад назви групи. Вона має існувати, а користувач, який виконує `chgrp`, повинен мати необхідні права.

Число `2` на початку режиму `2770` встановлює setgid-біт для каталогу. Нові об'єкти в такому каталозі зазвичай успадковують його групу, що полегшує спільну роботу.

**Важливо:** setgid на каталозі не гарантує, що всі нові файли будуть доступні для запису всім членам групи. Наприклад, `umask 077` усе одно прибере права групи під час створення типових файлів. Для співпраці потрібно узгодити групу, маску та інші правила доступу.

## 16. Umask і безпека

Неправильно налаштована маска може призвести до того, що нові файли отримуватимуть надто широкі права доступу.

### Приклад небажаного результату

    umask 000
    touch confidential.txt

За типових початкових прав файл може отримати режим `666`:

    rw-rw-rw-

Це означає, що всі категорії користувачів, які мають доступ до файла через звичайну систему прав, можуть читати й змінювати його.

Для конфіденційних даних така конфігурація зазвичай небажана.

### Більш обмежений варіант

    umask 077
    touch confidential.txt

За типових умов:

    600

Файл доступний для читання та запису власнику, а група й інші користувачі не отримують цих дозволів.

### Яке значення вибрати

Універсального значення для всіх випадків немає.

- `022` — поширений варіант для звичайної роботи, де читання іншими користувачами допустиме.
- `027` — суворіший варіант, який прибирає доступ для інших користувачів.
- `077` — корисний для приватних файлів, які не потрібно відкривати групі або іншим користувачам.
- `002` — може бути зручним для спільної групової роботи, якщо решта налаштувань це підтримує.

Реальний доступ також залежить від власника, групи, ACL, бітів спеціальних дозволів і механізмів безпеки системи.

## 17. Перевірка прав за допомогою stat

Команда `stat` допомагає перевірити фактичні права об'єкта.

Для одного файла:

    stat report.txt

Для короткого виведення:

    stat -c '%A %a %n' report.txt

Наприклад:

    -rw-r----- 640 report.txt

Тут:

- `%A` — права в символьному форматі;
- `%a` — права у восьмеричному форматі;
- `%n` — назва файла.

Для кількох об'єктів:

    stat -c '%A %a %n' *.txt

Для каталогів:

    stat -c '%A %a %n' */

Якщо потрібно переглянути власника й групу:

    stat -c '%U %G %a %n' report.txt

Тут `%U` — ім'я власника, а `%G` — ім'я групи.

## 18. Типові помилки

### Помилка 1. Вважати, що umask змінює наявні файли

Команда:

    umask 077

не змінює права файлів, які вже існують.

Щоб змінити права конкретного файла, використай:

    chmod 600 report.txt

### Помилка 2. Вважати, що umask — це готові права файла

Наприклад:

    umask 022

не означає, що нові файли отримуватимуть права `022`.

За типових умов файл матиме `644`, а каталог — `755`.

`022` — це маска, яка прибирає певні дозволи.

### Помилка 3. Застосовувати звичайне віднімання до будь-яких режимів

Запис:

    666 - 022 = 644

корисний для типового випадку, але `umask` насправді працює з бітами дозволів. Для нетипових режимів не варто покладатися на звичайну арифметику.

### Помилка 4. Очікувати, що umask змінить права під час кожного запису

Якщо файл уже існує, повторний запис у нього зазвичай не встановлює нові права за поточною маскою.

### Помилка 5. Вважати, що umask замінює chmod

`umask` впливає на створення нових об'єктів. `chmod` змінює права доступу безпосередньо.

### Помилка 6. Вважати, що umask однакова для всіх процесів

Різні оболонки, служби та користувацькі сесії можуть мати різні значення маски.

Перевіряй її саме в тому середовищі, де створюється потрібний файл.

### Помилка 7. Не враховувати ACL

Якщо на каталозі або файлі налаштовані ACL, фактичні дозволи можуть бути складнішими за звичайну трійку `u/g/o`. Для ACL потрібно окремо вивчити команди `getfacl` і `setfacl`.

## 19. Практичні вправи

### Вправа 1. Перевір поточну маску

Виконай:

    umask
    umask -S

Запиши обидва результати та поясни, що вони означають.

### Вправа 2. Створи файл із маскою 022

Виконай:

    umask 022
    touch exercise-022.txt
    stat -c '%A %a %n' exercise-022.txt

Питання: чому типовий результат — `644`, а не `022`?

### Вправа 3. Створи каталог із маскою 027

Виконай:

    umask 027
    mkdir exercise-dir-027
    stat -c '%A %a %n' exercise-dir-027

Питання: які права отримали власник, група та інші користувачі?

### Вправа 4. Порівняй дві маски

Виконай:

    umask 002
    touch group-file.txt
    mkdir group-dir

    umask 077
    touch private-file.txt
    mkdir private-dir

Перевір:

    stat -c '%a %n' group-file.txt private-file.txt
    stat -c '%a %n' group-dir private-dir

Поясни, чим відрізняються права нових файлів і каталогів.

### Вправа 5. Переконайся, що umask не змінює наявні права

Виконай:

    umask 022
    touch existing.txt
    chmod 600 existing.txt

Потім:

    umask 077
    stat -c '%a %n' existing.txt

Питання: чи змінилися права файла після встановлення нової маски? Чому?

### Вправа 6. Тимчасова маска

Виконай:

    umask 022
    (umask 077; touch temporary-private.txt)
    umask

Перевір права файла:

    stat -c '%a %n' temporary-private.txt

Поясни, чому файл створений із суворішими правами, хоча маска батьківської оболонки залишилася `022`.

### Вправа 7. Самостійне завдання

Створи три файли та три каталоги, використовуючи маски:

    002
    027
    077

Перевір результати через `stat`.

Для кожної маски запиши:

- права нового файла;
- права нового каталогу;
- хто може читати;
- хто може змінювати;
- хто може заходити до каталогу.

## 21. Що запам'ятати

- `umask` визначає, які біти дозволів прибираються під час створення нових об'єктів.
- Типовий початковий режим файла — `666`.
- Типовий початковий режим каталогу — `777`.
- За типових умов `umask 022` дає файл `644` і каталог `755`.
- За типових умов `umask 027` дає файл `640` і каталог `750`.
- За типових умов `umask 077` дає файл `600` і каталог `700`.
- `umask` не змінює права вже наявних файлів і каталогів.
- `chmod` змінює права безпосередньо.
- `umask` у поточній оболонці зазвичай успадковується дочірніми процесами.
- Щоб перевірити результат, використовуй `ls -l` або `stat`.
- Для спільної роботи враховуй групи, setgid, ACL та маску всіх учасників.
- Реальні права залежать від режиму, який запитує програма, та інших механізмів доступу.

## 22. Шпаргалка команд

Переглянути поточну маску:

    umask

Переглянути маску в символьному форматі:

    umask -S

Встановити маску `022`:

    umask 022

Встановити маску `027`:

    umask 027

Встановити маску `077`:

    umask 077

Створити файл:

    touch file.txt

Створити каталог:

    mkdir dir

Переглянути права:

    ls -l

Переглянути права у зручному форматі:

    stat -c '%A %a %n' file.txt dir

Змінити права наявного файла:

    chmod 600 file.txt

Виконати команди з тимчасовою маскою в підоболонці:

    (umask 077; touch private.txt)

Зберегти маску для інтерактивної Bash-оболонки:

    nano ~/.bashrc

Додати в конфігураційний файл:

    umask 027

Перезавантажити конфігурацію:

    source ~/.bashrc
