# 04. chown і chgrp — зміна власника та групи в Linux

`chown` (change owner) і `chgrp` (change group) — команди Linux для керування власником файлів і директорій та їхньою групою.

Кожен файл і каталог у Linux має власника-користувача та групу-власника. Вони разом із правами доступу визначають, хто може читати, змінювати або виконувати об'єкт.

- `chown` — змінює власника та, за потреби, групу.
- `chgrp` — змінює групу-власника.
- `chmod` — змінює права доступу, але не власника.

## 1. Коли потрібні chown і chgrp

Ці команди використовують, коли потрібно:

- передати файл іншому користувачу;
- призначити файлу правильну групу;
- налаштувати спільний доступ до директорії;
- виправити права власності після копіювання або розпакування файлів;
- підготувати директорії для серверного застосунку;
- налаштувати доступ до файлів, з якими працює окремий системний користувач;
- виправити ситуацію, коли файли належать `root`, а розробник не може їх змінювати.

Наприклад:

    sudo chown valer report.txt
    sudo chgrp developers report.txt
    sudo chown valer:developers report.txt

Команди зміни власника часто потребують адміністративних привілеїв. Звичайний користувач зазвичай може змінювати власника лише в межах обмежень системи, а змінювати групу — лише на групу, до якої він має відповідні повноваження.

---

## 2. Власник і група файлу

Перевірити власника та групу можна за допомогою:

    ls -l report.txt

Приклад результату:

    -rw-r--r-- 1 valer developers 1200 Oct 18 20:00 report.txt

Розглянемо частину рядка:

    valer developers

- `valer` — власник файлу;
- `developers` — група-власник файлу.

Переглянути детальнішу інформацію можна командою:

    stat report.txt

Приклад фрагмента результату:

    Uid: (1000/valer)  Gid: (1002/developers)

- `Uid` — числовий ідентифікатор власника;
- `Gid` — числовий ідентифікатор групи.

Linux використовує числові ідентифікатори користувачів (UID) і груп (GID). Імена на кшталт `valer` і `developers` — зручне текстове представлення цих ідентифікаторів.

## 3. Основна відмінність між chown, chgrp і chmod

| Команда | Що змінює | Приклад |
|---|---|---|
| `chown` | Власника, за потреби групу | `chown valer file.txt` |
| `chgrp` | Групу-власника | `chgrp developers file.txt` |
| `chmod` | Права доступу | `chmod 644 file.txt` |

Наприклад, файл має:

    -rw-r--r-- 1 root root 1200 Oct 18 20:00 report.txt

Змінюємо власника:

    sudo chown valer report.txt

Тепер власником буде `valer`, але група залишиться `root`, якщо її не змінювати.

Змінюємо групу:

    sudo chgrp developers report.txt

Тепер групою-власником буде `developers`.

Змінюємо права:

    chmod 640 report.txt

Тепер власник має читання та запис, група — лише читання, а інші користувачі не мають звичайних прав доступу.

**Запам'ятайте:** власник, група та права доступу — це три пов'язані, але різні властивості файлу.

---

## 4. Команда chown

Загальний синтаксис:

    chown [OPTIONS] OWNER FILE

Де:

- `chown` — команда зміни власника;
- `OPTIONS` — додаткові параметри;
- `OWNER` — новий власник;
- `FILE` — файл або директорія.

### 4.1. Змінити власника файлу

    sudo chown valer report.txt

Власником `report.txt` стане користувач `valer`.

Перевірити результат:

    ls -l report.txt

### 4.2. Змінити власника директорії

    sudo chown valer project/

Ця команда змінює власника самої директорії `project/`, але не обов'язково її вмісту.

Перевірити:

    ls -ld project/

Параметр `-d` у `ls` показує саму директорію, а не список її вмісту.

### 4.3. Змінити власника на поточного користувача

Якщо поточний користувач має відповідні повноваження:

    sudo chown "$USER" report.txt

Змінна `$USER` зазвичай містить ім'я поточного користувача в середовищі оболонки.

### 4.4. Змінити власника за числовим UID

За потреби власника можна вказати числовим ідентифікатором:

    sudo chown 1000 report.txt

Це призначає файлу власника з UID `1000`, якщо такий ідентифікатор має відповідне значення в системі.

На практиці зазвичай зручніше використовувати ім'я користувача.

---

## 5. Команда chgrp

`chgrp` (change group) змінює групу-власника файлу або директорії.

Загальний синтаксис:

    chgrp [OPTIONS] GROUP FILE

Де:

- `GROUP` — назва або числовий GID групи;
- `FILE` — файл або директорія.

### 5.1. Змінити групу файлу

    sudo chgrp developers report.txt

Групою-власником `report.txt` стане `developers`.

Перевірити:

    ls -l report.txt

### 5.2. Змінити групу директорії

    sudo chgrp developers project/

Змінюється група самої директорії.

Перевірити:

    ls -ld project/

### 5.3. Коли потрібен chgrp

Наприклад, кілька розробників працюють зі спільними файлами. Файли належать власнику `valer`, але їхньою групою має бути `developers`.

    sudo chgrp developers report.txt

Після цього права доступу для групи визначатимуться окремо, наприклад через `chmod`.

Важливо: призначення групи не надає автоматично права читання чи запису. Для цього потрібні відповідні дозволи та членство користувача в групі.

---

## 6. Зміна власника та групи одночасно

За допомогою `chown` можна змінити власника й групу однією командою.

Загальний синтаксис:

    sudo chown OWNER:GROUP FILE

### 6.1. Задати власника та групу

    sudo chown valer:developers report.txt

Результат:

    -rw-r--r-- 1 valer developers 1200 Oct 18 20:00 report.txt

Тепер:

- власник — `valer`;
- група — `developers`.

### 6.2. Змінити лише групу через chown

Якщо перед двокрапкою нічого не вказано, можна змінити лише групу:

    sudo chown :developers report.txt

Це змінює групу-власника, не змінюючи власника файлу.

Для такої операції також існує команда:

    sudo chgrp developers report.txt

Обидва підходи можуть бути доречними, але `chgrp` виразніше показує намір змінити саме групу.

### 6.3. Змінити лише власника

    sudo chown valer report.txt

Якщо групу не вказано, вона залишається незмінною.

### 6.4. Використовувати поточного власника або групу

У `chown` можна застосовувати `:` для розділення власника та групи. Якщо потрібно залишити поточного власника, але змінити групу, використовуйте:

    sudo chown :developers report.txt

Цей синтаксис зручний для сценаріїв адміністрування, де потрібно змінити тільки одну частину власності.

---

## 7. Рекурсивна зміна власника та групи: параметр -R

Параметр `-R` означає рекурсивну обробку: команда застосовується до директорії та об'єктів усередині неї.

### 7.1. Рекурсивно змінити власника

    sudo chown -R valer project/

Команда змінює власника директорії `project/` та її вмісту.

### 7.2. Рекурсивно змінити власника й групу

    sudo chown -R valer:developers project/

Команда змінює власника та групу директорії й об'єктів усередині неї.

### 7.3. Рекурсивно змінити лише групу

    sudo chgrp -R developers project/

Група-власник змінюється для директорії та її вмісту.

### 7.4. Чому потрібно бути обережним

Команди з `-R` можуть змінити власність великої кількості файлів.

Не запускайте їх навмання в каталогах:

- `/`;
- `/etc`;
- `/usr`;
- `/var`;
- системних каталогах застосунків;
- директоріях, якими керує пакетний менеджер;
- каталогах із файлами інших користувачів.

Наприклад, команда:

    sudo chown -R "$USER":"$USER" /

може серйозно пошкодити систему, змінивши власників системних файлів.

**Правило:** перед рекурсивною зміною перевірте шлях, призначення каталогу та наслідки операції.

---

## 8. Символічні посилання та параметри chown

Символічне посилання (symlink) — це окремий об'єкт, який указує на інший файл або директорію.

Переглянути його можна командою:

    ls -l current-link

Приклад:

    lrwxrwxrwx 1 valer valer 10 Oct 18 20:00 current-link -> report.txt

За замовчуванням поведінка `chown` щодо символічних посилань залежить від параметрів команди: зазвичай команда не переходить за символічним посиланням, переданим як аргумент, і не змінює власника цільового об'єкта через нього.

Основні параметри:

| Параметр | Значення |
|---|---|
| `-R` | Рекурсивна обробка директорії та її вмісту |
| `-h` | Змінювати власника самого символічного посилання, а не його цілі |
| `-H` | У рекурсивному режимі переходити за символічним посиланням, якщо воно вказане як аргумент командного рядка |
| `-L` | У рекурсивному режимі переходити за символічними посиланнями на директорії |
| `-P` | У рекурсивному режимі не переходити за символічними посиланнями; зазвичай це стандартна поведінка |

Ці параметри особливо важливі для рекурсивних операцій. Переходи за посиланнями можуть привести команду до об'єктів за межами очікуваної директорії.

Якщо не впевнені в поведінці посилань, спочатку перевірте їхню структуру та використовуйте обережний режим.

## 9. Як перевірити користувачів і групи

Щоб правильно призначати власників і групи, потрібно знати, які користувачі та групи існують у системі.

### 9.1. Поточний користувач

    whoami

Показує ім'я поточного користувача.

### 9.2. UID і GID поточного користувача

    id

Приклад:

    uid=1000(valer) gid=1000(valer) groups=1000(valer),1002(developers)

Команда показує:

- UID — ідентифікатор користувача;
- основний GID — ідентифікатор основної групи;
- `groups` — групи, до яких належить користувач.

### 9.3. Групи поточного користувача

    groups

Показує назви груп, до яких належить поточний користувач.

### 9.4. Перевірити конкретну групу

    getent group developers

Команда показує запис групи `developers`, якщо така група існує.

### 9.5. Перевірити конкретного користувача

    id valer

Показує UID, основну групу та інші групи користувача `valer`.

### 9.6. Список користувачів і груп

У Linux інформація про локальні облікові записи традиційно міститься у файлах:

    /etc/passwd
    /etc/group

Переглянути записи можна так:

    less /etc/passwd
    less /etc/group

У сучасних системах облікові записи також можуть надходити з інших джерел, тому для перевірки зручніше використовувати `getent`.

## 10. Чому зміна групи може не дати доступу

Припустимо, файл має такі права:

    -rw-r----- 1 valer developers report.txt

Це означає:

- власник `valer` має читання та запис;
- група `developers` має читання;
- інші користувачі не мають звичайних прав.

Якщо користувач не входить до групи `developers`, саме призначення цієї групи файлу не надасть йому доступу.

Перевірити членство користувача можна так:

    id username

Якщо користувач повинен отримати доступ через групу, перевірте:

1. Чи існує група.
2. Чи є користувач її учасником.
3. Чи має файл відповідні права для групи.
4. Чи має користувач право проходження через усі батьківські директорії.

Приклад перевірки:

    ls -l report.txt
    ls -ld /home/valer/projects
    id username

Після зміни членства в групі може знадобитися новий сеанс входу, щоб нові групові права потрапили до облікових даних процесу.

## 11. Власність файлів у проєкті розробника

Припустимо, проєкт має структуру:

    nest-exercises/
    ├── README.md
    ├── package.json
    ├── .env
    ├── scripts/
    │   └── backup.sh
    └── practice/
        └── linux/

Зазвичай файли, з якими ви працюєте особисто, мають належати вашому користувачу. Проблеми часто виникають після запуску команд із `sudo`, які створюють файли від імені `root`.

### 11.1. Перевірити власника проєкту

    ls -ld nest-exercises
    ls -l nest-exercises

Якщо потрібно переглянути власників у вкладених каталогах:

    find nest-exercises -maxdepth 3 -printf '%u:%g %p\n'

Команда показує власника, групу та шлях до кожного знайденого об'єкта в межах заданої глибини.

### 11.2. Змінити власника одного файлу

    sudo chown "$USER":"$USER" nest-exercises/README.md

Ця команда призначає файлу поточного користувача та групу з таким самим ім'ям, якщо така група існує.

### 11.3. Виправити власність власного навчального каталогу

Якщо ви перевірили, що весь каталог має належати вам, можна застосувати рекурсивну зміну:

    sudo chown -R "$USER":"$USER" nest-exercises/practice/linux/

Використовуйте таку команду лише тоді, коли впевнені, що всі об'єкти всередині каталогу мають належати вашому користувачу й цій групі.

Не запускайте рекурсивну зміну лише тому, що одна команда завершилася помилкою. Спочатку знайдіть конкретні файли з неправильним власником.

## 12. Особливості sudo та root

`root` — привілейований системний користувач, який має широкі повноваження в системі.

Команди `chown` і `chgrp` часто запускають із `sudo`, коли потрібно змінити власність файлів, які не належать поточному користувачу.

Приклади:

    sudo chown root:root /tmp/example.conf
    sudo chgrp developers shared.txt

Однак `sudo` не слід використовувати автоматично для кожної файлової операції.

Для власного навчального проєкту краще, щоб файли належали звичайному користувачу. Якщо постійно доводиться застосовувати `sudo` для редагування файлів у власному проєкті, варто перевірити їхнього власника.

Переглянути власника:

    ls -l file.txt

Перевірити поточного користувача:

    whoami

Переглянути UID, GID та групи:

    id

Не змінюйте власність системних файлів без чіткого розуміння призначення цих файлів.

## 13. Типові помилки

### Помилка 1. Плутати chown і chmod

    sudo chown valer report.txt

Змінює власника.

    chmod 644 report.txt

Змінює права доступу.

Це різні операції.

### Помилка 2. Вважати, що chgrp надає права доступу

    sudo chgrp developers report.txt

Команда призначає групу, але сама по собі не надає групі читання чи запису. Права визначаються окремо.

### Помилка 3. Змінювати власника всього проєкту без перевірки

    sudo chown -R "$USER":"$USER" project/

Команда змінює власника й групу всіх об'єктів у каталозі. Якщо деякі файли повинні належати іншому користувачу або сервісу, це може порушити роботу застосунку.

### Помилка 4. Запускати редактор через sudo без потреби

Наприклад:

    sudo code .

Запуск графічного редактора з підвищеними привілеями зазвичай не потрібен для звичайної розробки й може спричинити проблеми з файлами конфігурації або власністю.

Краще виправити власність потрібних файлів, якщо це безпечно та доречно.

### Помилка 5. Використовувати неправильне ім'я групи

    sudo chgrp developer report.txt

Якщо групи `developer` не існує, команда завершиться помилкою.

Перевірте:

    getent group developer
    getent group developers

### Помилка 6. Забути про членство в групі

Призначення файлу групи `developers` не означає, що поточний користувач автоматично належить до цієї групи.

Перевірте:

    id

### Помилка 7. Змінювати власність через символічне посилання без перевірки

Символічне посилання може вказувати на об'єкт за межами поточного каталогу. Перед рекурсивними операціями перевірте, куди ведуть посилання, та враховуйте параметри `-h`, `-H`, `-L` і `-P`.

## 14. Корисні команди для щоденної роботи

Переглянути власника та групу:

    ls -l file.txt

Переглянути власність самої директорії:

## 15. Практичні завдання

Виконуйте завдання лише у власній навчальній директорії.

### Завдання 1. Створити файл і перевірити власність

    mkdir -p ~/linux-practice/ownership
    cd ~/linux-practice/ownership
    touch notes.txt
    ls -l notes.txt
    stat notes.txt

З'ясуйте, хто є власником і яка група призначена файлу.

### Завдання 2. Перевірити поточного користувача

    whoami
    id
    groups

Порівняйте ім'я користувача, UID, основну групу та додаткові групи.

### Завдання 3. Змінити власника

Якщо у вашій системі є інший тестовий користувач і ви маєте відповідні привілеї, змініть власника тестового файлу:

    sudo chown testuser notes.txt
    ls -l notes.txt

Замініть `testuser` на ім'я користувача, який справді існує у вашій системі.

Якщо такого користувача немає, пропустіть це завдання.

### Завдання 4. Змінити групу

Перевірте наявність групи:

    getent group developers

Якщо група існує і ви маєте відповідні повноваження:

    sudo chgrp developers notes.txt
    ls -l notes.txt

Якщо групи немає, не використовуйте цю команду бездумно. Можна виконати вправу з іншою наявною групою або пропустити її.

### Завдання 5. Змінити власника й групу

У навчальному середовищі, де це дозволено:

    sudo chown "$USER":"$USER" notes.txt
    ls -l notes.txt

Переконайтеся, що власником і групою стали відповідні облікові записи.

### Завдання 6. Порівняти chown і chmod

    ls -l notes.txt
    chmod 600 notes.txt
    ls -l notes.txt

Поясніть, що змінилося, а що залишилося незмінним.

### Завдання 7. Перевірити власність вкладених об'єктів

    mkdir -p project/src
    touch project/README.md
    touch project/src/app.js
    find project -printf '%u:%g %p\n'

Перегляньте власників директорії, файлів і вкладених каталогів.

## 16. Що потрібно пам'ятати

- `chown` змінює власника, а також може змінювати групу.
- `chgrp` змінює групу-власника.
- `chmod` змінює права доступу.
- `ls -l` показує власника та групу після прав доступу.
- `stat` надає детальнішу інформацію про файл.
- `id` показує UID, GID та групи користувача.
- `chown OWNER:GROUP FILE` дозволяє змінити власника й групу однією командою.
- `chown :GROUP FILE` дозволяє змінити лише групу.
- `-R` застосовує зміну рекурсивно до директорії та її вмісту.
- `sudo` потрібен для багатьох операцій із чужими файлами, але не повинен використовуватися без потреби.
- Призначення групи не надає автоматично прав читання чи запису.
- Для доступу через групу користувач повинен бути її учасником і мати потрібні дозволи.
- Рекурсивна зміна власності системних каталогів може серйозно пошкодити Linux.
- Символічні посилання потребують особливої уваги під час рекурсивних операцій.

## 19. Мінішпаргалка

    # Переглянути власника та групу
    ls -l file.txt
    ls -ld directory/
    stat file.txt

    # Поточний користувач і групи
    whoami
    id
    groups

    # Перевірити користувача або групу
    id valer
    getent group developers

    # Змінити власника
    sudo chown valer file.txt

    # Змінити групу
    sudo chgrp developers file.txt

    # Змінити власника та групу
    sudo chown valer:developers file.txt

    # Змінити лише групу через chown
    sudo chown :developers file.txt

    # Рекурсивно змінити власника
    sudo chown -R valer project/

    # Рекурсивно змінити власника та групу
    sudo chown -R valer:developers project/

    # Рекурсивно змінити групу
    sudo chgrp -R developers project/

    # Переглянути власників у каталозі
    find project/ -maxdepth 3 -printf '%u:%g %p\n'

    # Пам'ятай:
    # chown  — власник і, за потреби, група
    # chgrp  — група
    # chmod  — права доступу
    # UID    — ідентифікатор користувача
    # GID    — ідентифікатор групи
    # -R     — рекурсивна обробка

## Висновок

`chown` і `chgrp` потрібні для керування власником та групою файлів у Linux. Разом із `chmod` вони дають змогу налаштувати, хто володіє файлом і які дії дозволені користувачам.

Для повсякденної роботи розробника важливо вміти перевіряти власність файлів, розуміти членство в групах і виправляти помилки доступу без зайвого використання `sudo`.

Головне правило: **перед зміною власності перевірте, кому має належати файл, а перед рекурсивною зміною — переконайтеся, що кожен об'єкт у каталозі справді повинен отримати нового власника або групу.**
