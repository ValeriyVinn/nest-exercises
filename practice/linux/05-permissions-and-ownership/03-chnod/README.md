# 03. chmod — зміна прав доступу в Linux

`chmod` (change mode) — команда Linux для зміни прав доступу до файлів і директорій.

За допомогою `chmod` можна визначити, хто має право:
- читати файл (`r` — read);
- змінювати файл (`w` — write);
- виконувати файл або переходити до директорії (`x` — execute).

Права доступу визначають, що користувачі можуть робити з файлами та директоріями в системі.

## 1. Коли потрібен chmod

Команда `chmod` використовується, коли потрібно:

- дозволити запускати скрипт;
- заборонити іншим користувачам читати приватний файл;
- надати групі право працювати з файлами;
- дозволити переглядати вміст директорії;
- виправити помилку `Permission denied`;
- обмежити доступ до конфігураційних файлів;
- налаштувати права для проєкту або серверного застосунку.

Приклади:

    chmod +x script.sh
    chmod 600 .env
    chmod 644 README.md
    chmod 755 deploy.sh

Детальніше про значення цих чисел і символів — у наступних розділах.

---

## 2. Основний синтаксис chmod

Загальний синтаксис:

    chmod [OPTIONS] MODE FILE

Де:

- `chmod` — команда зміни прав;
- `OPTIONS` — додаткові параметри;
- `MODE` — нові права доступу;
- `FILE` — файл або директорія, до якої застосовуються права.

Приклади:

    chmod 644 README.md
    chmod u+x script.sh
    chmod g-w report.txt

Перевірити права можна командою:

    ls -l README.md

Приклад результату:

    -rw-r--r-- 1 valer valer 1200 Oct 18 20:00 README.md

Команда `chmod` змінює права доступу, але **не змінює власника файлу**. Для зміни власника та групи використовують `chown` і `chgrp`.

---

## 3. Хто отримує права доступу

У Linux права доступу традиційно поділяються на три категорії:

| Категорія | Позначення | Значення |
|---|---|---|
| Власник | `u` | User — власник файлу |
| Група | `g` | Group — група файлу |
| Інші | `o` | Others — решта користувачів |
| Усі категорії | `a` | All — власник, група й інші |

Наприклад:

    chmod u+x script.sh

Додає право виконання власнику.

    chmod g-w report.txt

Забирає право запису в групи.

    chmod o-r secret.txt

Забирає право читання в інших користувачів.

    chmod a+r README.md

Додає право читання всім категоріям.

Якщо категорію не вказано, символічний режим `chmod` зазвичай використовує `a`, але результат може обмежуватися поточним значенням `umask`.

---

## 4. Три основні права доступу

| Символ | Назва | Для файлу | Для директорії |
|---|---|---|---|
| `r` | Read | Читати вміст | Переглядати список імен |
| `w` | Write | Змінювати вміст | Створювати, видаляти та перейменовувати записи |
| `x` | Execute | Виконувати файл | Переходити до директорії та звертатися до об'єктів усередині |

Важливо: права для файлів і директорій мають різний практичний зміст.

Наприклад, право `w` на файл не визначає саме по собі, чи можна видалити цей файл. Видалення зазвичай залежить від прав на директорію, у якій він розташований.

---

## 5. Два способи задавати права

Команда `chmod` підтримує два основні формати:

1. **Символьний** — використовує `u`, `g`, `o`, `a` та `r`, `w`, `x`.
2. **Числовий (вісімковий)** — використовує цифри, наприклад `644`, `755`, `600`.

Символьний формат зручний, коли потрібно змінити лише одне право.

Числовий формат зручний, коли потрібно встановити повний набір прав для власника, групи та інших користувачів.

---

## 6. Символьний формат chmod

### 6.1. Оператори

| Оператор | Значення |
|---|---|
| `+` | Додати право |
| `-` | Забрати право |
| `=` | Встановити точний набір прав для вибраної категорії |

Приклади:

    chmod u+x script.sh
    chmod g-w report.txt
    chmod o-r secret.txt
    chmod u=rw file.txt

Розбір:

- `u+x` — додати виконання власнику;
- `g-w` — забрати запис у групи;
- `o-r` — забрати читання в інших;
- `u=rw` — встановити власнику лише читання та запис.

Оператор `=` замінює попередній набір прав у вибраній категорії.

### 6.2. Додавання прав

    chmod u+x script.sh

Дозволяє власнику виконувати файл.

    chmod g+w shared.txt

Дозволяє групі змінювати файл.

    chmod o+r public.txt

Дозволяє іншим користувачам читати файл.

    chmod a+r README.md

Додає право читання власнику, групі та іншим користувачам.

### 6.3. Видалення прав

    chmod u-x script.sh

Забирає право виконання у власника.

    chmod g-w report.txt

Забирає право запису в групи.

    chmod o-r private.txt

Забирає право читання в інших користувачів.

    chmod a-w document.txt

Забирає право запису в усіх трьох категорій.

### 6.4. Точне встановлення прав

    chmod u=rw,g=r,o= file.txt

Встановлює:

- власник — читання та запис;
- група — лише читання;
- інші — жодних прав.

Результат:

    -rw-r----- file.txt

Ще один приклад:

    chmod u=rwx,g=rx,o= app.sh

Результат:

    -rwxr-x--- app.sh

Власник може читати, змінювати та виконувати файл. Група може читати й виконувати. Інші користувачі не мають прав.

### 6.5. Комбінація кількох змін

    chmod u+x,g-w,o-r file.txt

Одна команда може змінювати права кількох категорій.

Ще приклад:

    chmod u=rw,g=r,o=r README.md

Встановлює власнику `rw`, а групі та іншим — `r`.

---

## 7. Числовий формат chmod

Числовий формат використовує три цифри:

    chmod XYZ file

Де:

- `X` — права власника;
- `Y` — права групи;
- `Z` — права інших користувачів.

Кожна цифра описує комбінацію трьох прав: `r`, `w`, `x`.

### 7.1. Значення прав

| Право | Число |
|---|---:|
| `r` | 4 |
| `w` | 2 |
| `x` | 1 |
| Немає прав | 0 |

Щоб отримати число для категорії, значення прав додають.

| Комбінація | Обчислення | Число |
|---|---|---:|
| `---` | 0 | 0 |
| `--x` | 1 | 1 |
| `-w-` | 2 | 2 |
| `-wx` | 2 + 1 | 3 |
| `r--` | 4 | 4 |
| `r-x` | 4 + 1 | 5 |
| `rw-` | 4 + 2 | 6 |
| `rwx` | 4 + 2 + 1 | 7 |

Отже:

- `7` = `rwx`;
- `6` = `rw-`;
- `5` = `r-x`;
- `4` = `r--`;
- `0` = `---`.

### 7.2. Приклад: chmod 644

    chmod 644 README.md

Розшифрування:

- `6` — власник: `rw-`;
- `4` — група: `r--`;
- `4` — інші: `r--`.

Результат:

    -rw-r--r-- README.md

Власник може читати й змінювати файл. Група та інші можуть лише читати.

### 7.3. Приклад: chmod 755

    chmod 755 script.sh

Розшифрування:

- `7` — власник: `rwx`;
- `5` — група: `r-x`;
- `5` — інші: `r-x`.

Результат:

    -rwxr-xr-x script.sh

Власник може читати, змінювати та виконувати файл. Інші користувачі можуть читати й виконувати, але не змінювати його через право запису у файлі.

### 7.4. Приклад: chmod 600

    chmod 600 .env

Результат:

    -rw-------

Лише власник має право читати й змінювати файл.

Це поширений варіант для приватних конфігураційних файлів, хоча потрібні права залежать від конкретного застосунку.

---

## 8. Поширені числові режими

| Режим | Права | Типове застосування |
|---|---|---|
| `644` | `rw-r--r--` | Звичайні текстові файли |
| `600` | `rw-------` | Приватні файли власника |
| `640` | `rw-r-----` | Файл доступний власнику та групі для читання |
| `664` | `rw-rw-r--` | Спільний файл із записом для групи |
| `755` | `rwxr-xr-x` | Директорії та виконувані файли з читанням для інших |
| `700` | `rwx------` | Приватна директорія власника |
| `750` | `rwxr-x---` | Доступ власнику та групі |
| `775` | `rwxrwxr-x` | Спільна директорія з правом запису для групи |
| `711` | `rwx--x--x` | Директорія, до якої можна переходити, але не переглядати список імен |
| `444` | `r--r--r--` | Файл лише для читання за звичайними правами |
| `000` | `----------` | Немає звичайних прав доступу для жодної категорії |
| `777` | `rwxrwxrwx` | Повні права для всіх; зазвичай небажаний варіант |

Не використовуйте `777` як універсальне виправлення помилки `Permission denied`. Краще визначити, кому саме потрібен доступ, і надати лише необхідні права.

Також пам'ятайте: `444` не робить файл абсолютно незмінним за будь-яких обставин. Власник із відповідними повноваженнями може змінити його права, а привілейовані процеси можуть мати додаткові можливості.

---

## 9. Як перевірити права доступу

### 9.1. Перегляд прав файлу

    ls -l README.md

Приклад:

    -rw-r--r-- 1 valer valer 1200 Oct 18 20:00 README.md

Перші десять символів описують тип об'єкта та його права:

    - rw- r-- r--

- `-` — звичайний файл;
- `rw-` — права власника;
- `r--` — права групи;
- `r--` — права інших користувачів.

### 9.2. Перегляд прав директорії

    ls -ld practice

Параметр `-d` показує саму директорію, а не її вміст.

### 9.3. Детальна інформація

    stat README.md

Команда `stat` показує інформацію про файл, зокрема права доступу, власника, групу та часи зміни.

У результаті можна побачити рядок на кшталт:

    Access: (0644/-rw-r--r--)  Uid: (1000/valer)  Gid: (1000/valer)

### 9.4. Перевірка прав уздовж шляху

    namei -l /home/valer/projects/nest-exercises/README.md

`namei -l` показує компоненти шляху та їхні права. Це корисно, якщо доступ до файлу блокує одна з батьківських директорій.

## 10. Права доступу до файлів і директорій

### 10.1. Права для файлу

Припустимо, файл має права:

    -rw-r--r-- report.txt

Власник може читати й змінювати його вміст. Група та інші користувачі можуть читати, але не записувати.

Щоб додати виконання власнику:

    chmod u+x script.sh

Щоб забрати право запису в інших:

    chmod o-w report.txt

### 10.2. Права для директорії

Для директорій права означають інше:

- `r` — можна переглядати список імен у директорії;
- `w` — можна створювати, видаляти та перейменовувати записи, якщо також є необхідний доступ до директорії;
- `x` — можна переходити до директорії та звертатися до об'єктів у ній за їхніми іменами.

Приклад:

    chmod 755 public/

Власник отримує `rwx`, а група та інші — `r-x`.

### 10.3. Чому для директорії потрібне x

Право `x` для директорії називають правом пошуку або проходження (search/traverse).

Якщо користувач не має `x` на директорію, він може не мати змоги звертатися до файлів усередині неї, навіть якщо знає їхні назви.

Для доступу до файлу за повним шляхом потрібне право проходження на кожну відповідну батьківську директорію.

### 10.4. Читання директорії без виконання

Якщо директорія має `r`, але не має `x`, користувач може бути здатний отримати список імен, проте не зможе нормально звертатися до записів за цими іменами.

### 10.5. Виконання директорії без читання

Якщо директорія має `x`, але не має `r`, користувач може звертатися до відомих йому імен усередині директорії, якщо має необхідні права на весь шлях і самі об'єкти. Але переглядати повний список імен він не зможе.

### 10.6. Запис у директорію

Право `w` на директорію дає можливість змінювати її записи, наприклад створювати або видаляти файли. Зазвичай для цього потрібні одночасно `w` і `x` на директорію.

Тому право запису у файл і право видалення цього файлу — не одне й те саме.

## 11. Додавання права виконання скрипту

Частий сценарій у Linux — запуск власного Bash-скрипту.

Нехай є файл `hello.sh`:

    #!/usr/bin/env bash
    echo "Hello, Linux!"

Переглядаємо права:

    ls -l hello.sh

Приклад результату:

    -rw-r--r-- 1 valer valer 35 Oct 18 20:00 hello.sh

У власника немає права виконання. Спробуємо запустити файл безпосередньо:

    ./hello.sh

Можлива помилка:

    Permission denied

Додаємо право виконання власнику:

    chmod u+x hello.sh

Перевіряємо:

    ls -l hello.sh

Приклад:

    -rwxr--r-- 1 valer valer 35 Oct 18 20:00 hello.sh

Тепер можна виконати:

    ./hello.sh

Очікуваний результат:

    Hello, Linux!

Для запуску через `./hello.sh` потрібні право виконання файлу, доступ до директорій у шляху та коректний інтерпретатор, зазначений у shebang.

Інший спосіб — передати скрипт інтерпретатору явно:

    bash hello.sh

У цьому випадку Bash читає файл як вхідний сценарій, тому право `x` на самому файлі зазвичай не потрібне. Водночас користувач повинен мати право читання файлу та доступ до його шляху.

Розширення `.sh` саме по собі не робить файл виконуваним.

## 12. Рекурсивна зміна прав: параметр -R

Параметр `-R` означає рекурсивну зміну прав: команда застосовується до директорії та її вмісту, включно з вкладеними об'єктами.

Приклад:

    chmod -R 755 public/

Це встановлює права `755` для всіх відповідних файлів і директорій усередині `public/`.

**Обережно:** команда може встановити право виконання всім звичайним файлам, включно з документами та конфігураціями. Це часто не те, що потрібно.

Безпечніший підхід — встановлювати права окремо для директорій і файлів, якщо їхні призначення різні.

Наприклад, у межах контрольованого навчального каталогу:

    find public/ -type d -exec chmod 755 {} +
    find public/ -type f -exec chmod 644 {} +

Пояснення:

- `find public/` — пошук об'єктів усередині `public/`;
- `-type d` — вибрати директорії;
- `-type f` — вибрати звичайні файли;
- `-exec chmod ... {} +` — застосувати команду до знайдених об'єктів.

Це лише приклад для каталогу, в якому такі права справді доречні. Не запускайте масову зміну прав у системних директоріях або в каталозі з файлами, які потребують спеціальних дозволів.

## 13. Застосування chmod у навчальному проєкті

Припустимо, структура проєкту така:

    nest-exercises/
    ├── README.md
    ├── .env
    ├── scripts/
    │   └── backup.sh
    └── public/

### 13.1. README.md

Для звичайного текстового файлу часто використовують `644`:

    chmod 644 README.md

Власник може читати й редагувати файл, інші користувачі — читати.

### 13.2. Файл .env

Файл `.env` може містити паролі, токени та рядки підключення до бази даних.

Для приватного файлу часто доречний режим `600`:

    chmod 600 .env

Це обмежує звичайний доступ до власника файлу.

Однак права доступу — лише одна частина захисту секретів. Не додавайте `.env` із реальними секретами до публічного Git-репозиторію.

### 13.3. Скрипт backup.sh

Дозволяємо власнику запускати скрипт:

    chmod u+x scripts/backup.sh

Якщо скрипт має бути доступний для запуску групі та іншим користувачам, спочатку перевірте, чи це справді необхідно.

### 13.4. Директорія public

Для звичайної директорії, яку мають переглядати користувачі, часто використовують `755`:

    chmod 755 public/

Це дозволяє власнику змінювати вміст, а іншим — переглядати імена та проходити до доступних об'єктів. Можливість читати конкретні файли додатково залежить від прав самих файлів.

---

## 14. Чому chmod не завжди виправляє Permission denied

Помилка `Permission denied` не обов'язково означає, що потрібно змінити права самого файлу.

Можливі причини:

1. Немає потрібного права `r`, `w` або `x` на сам файл.
2. Немає права `x` на одну з батьківських директорій.
3. Власник або група файлу не ті, що очікувалися.
4. Файлова система змонтована з обмеженнями, наприклад `noexec`.
5. Діють додаткові механізми безпеки або ACL.
6. Скрипт не має коректного shebang або інтерпретатора.
7. Доступ обмежує політика системи, контейнера чи сервісу.

Почніть із перевірки:

    id
    ls -l script.sh
    namei -l /шлях/до/script.sh
    stat script.sh

Не використовуйте `chmod 777` навмання. Спершу з'ясуйте, яке саме право відсутнє і кому його потрібно надати.

---

## 15. Типові помилки

### Помилка 1. Використовувати chmod 777 для всього

    chmod -R 777 project/

Це створює надмірно широкі дозволи: кожен користувач може читати, змінювати та виконувати об'єкти відповідно до цих прав.

Краще визначити потрібні права окремо для файлів і директорій.

### Помилка 2. Додавати x до всіх файлів

    chmod -R 755 project/

Звичайним текстовим файлам не завжди потрібне право виконання. Виконуваними мають бути ті файли, які справді повинні запускатися як програми або скрипти.

### Помилка 3. Плутати права файлу та директорії

`w` на файлі дозволяє змінювати його вміст, а `w` на директорії дозволяє змінювати записи в ній. Це різні операції.

### Помилка 4. Вважати, що права додаються з усіх категорій

Linux не просто об'єднує права власника, групи й інших. Для звичайної перевірки доступу враховується відповідна категорія: власник, група або інші.

### Помилка 5. Вважати, що chmod змінює власника

    chmod 644 report.txt

Змінює права доступу, але не власника чи групу.

### Помилка 6. Забувати про батьківські директорії

Навіть якщо файл має право читання, користувач не зможе відкрити його за шляхом, якщо не має необхідного права проходження через одну з батьківських директорій.

### Помилка 7. Вважати, що chmod завжди вирішує проблему

Доступ можуть обмежувати ACL, параметри монтування, системні політики та інші механізми. Потрібно перевіряти причину помилки, а не змінювати всі права навмання.

## 16. Корисні команди для роботи з правами

Переглянути права файлу:

    ls -l file.txt

Переглянути права самої директорії:

    ls -ld directory/

Переглянути докладні атрибути:

    stat file.txt

Перевірити права компонентів шляху:

    namei -l /home/valer/projects/file.txt

Додати право виконання власнику:

    chmod u+x script.sh

Забрати право запису в інших:

    chmod o-w file.txt

Надати власнику повний доступ, а групі та іншим — читання й виконання:

    chmod 755 script.sh

Обмежити доступ до приватного файлу:

    chmod 600 .env

Знайти звичайні файли з конкретними правами:

    find . -type f -perm 0644

Знайти об'єкти, для яких право запису надане іншим:

    find . -perm -0002

Пошук через `find` може виявити багато об'єктів, тому перед масовими змінами спочатку перегляньте результати пошуку.

## 17. Практичні завдання

Виконуйте завдання у власній навчальній директорії, а не в системних каталогах.

### Завдання 1. Переглянути права

    touch notes.txt
    ls -l notes.txt

Подивіться, які права призначені новому файлу.

Пам'ятайте: початкові права залежать від стандартного режиму створення та `umask`.

### Завдання 2. Встановити права 644

    chmod 644 notes.txt
    ls -l notes.txt

Переконайтеся, що файл має права:

    -rw-r--r--

### Завдання 3. Змінити права символьним способом

    chmod u+x notes.txt
    ls -l notes.txt

Перевірте, як змінився перший набір прав.

Після вправи поверніть звичайні права текстового файлу:

    chmod 644 notes.txt

### Завдання 4. Створити скрипт

    printf '#!/usr/bin/env bash\necho "Hello, Linux!"\n' > hello.sh
    chmod u+x hello.sh
    ./hello.sh

Очікуваний результат:

    Hello, Linux!

### Завдання 5. Порівняти права директорії

    mkdir practice-dir
    ls -ld practice-dir
    chmod 700 practice-dir
    ls -ld practice-dir

Порівняйте початкові права з `700`.

### Завдання 6. Дослідити доступ

    mkdir private-dir
    touch private-dir/notes.txt
    chmod 700 private-dir
    chmod 644 private-dir/notes.txt
    ls -ld private-dir
    ls -l private-dir/notes.txt

Подумайте, чому права `644` на файл самі по собі не гарантують доступу до нього через `private-dir` іншому користувачеві.

## 18. Що потрібно пам'ятати

- `chmod` змінює права доступу, а не власника чи групу.
- Є два основні способи задавати права: символьний і числовий.
- `u`, `g`, `o`, `a` позначають власника, групу, інших та всі категорії.
- `+` додає право, `-` забирає, `=` встановлює точний набір прав для категорії.
- `r = 4`, `w = 2`, `x = 1`.
- У числовому режимі перша цифра стосується власника, друга — групи, третя — інших.
- `644` часто використовують для текстових файлів, `755` — для директорій і виконуваних файлів, `600` — для приватних файлів.
- Право `x` на директорію потрібне для проходження до об'єктів усередині неї.
- `chmod -R` змінює права рекурсивно, тому потребує обережності.
- `chmod 777` зазвичай надає надмірний доступ.
- Для пошуку причини `Permission denied` перевіряйте весь шлях, власника, групу та додаткові обмеження.

## 20. Шлях навчання

### Core — базовий рівень

- Розуміти `r`, `w`, `x`.
- Знати категорії `u`, `g`, `o`, `a`.
- Використовувати `chmod +`, `-` та `=`.
- Читати права у виводі `ls -l`.
- Розшифровувати режими `644`, `755`, `600`.

### Junior — практичний рівень

- Налаштовувати права для скриптів і директорій.
- Розуміти різницю між правами файлу та директорії.
- Перевіряти права за допомогою `stat` і `namei -l`.
- Використовувати `chmod -R` обережно.
- Діагностувати типові випадки `Permission denied`.

### Middle — поглиблений рівень

- Враховувати власника, групи, ACL і параметри монтування.
- Розуміти наслідки рекурсивної зміни прав у великих проєктах.
- Проєктувати мінімально необхідні права для серверних застосунків.
- Розрізняти звичайні дозволи та додаткові механізми контролю доступу.

### Senior — системний рівень

- Враховувати права доступу в багатокористувацьких системах, контейнерах і сервісах.
- Вибудовувати політики доступу з принципом найменших привілеїв.
- Аналізувати взаємодію звичайних дозволів, ACL, привілеїв процесів і політик безпеки.
- Автоматизувати перевірку прав та виявлення небезпечних конфігурацій.

## 21. Мінішпаргалка

    # Перевірити права
    ls -l file.txt
    ls -ld directory/
    stat file.txt
    namei -l /path/to/file.txt

    # Символьний режим
    chmod u+x script.sh
    chmod g-w file.txt
    chmod o-r file.txt
    chmod u=rw,g=r,o= file.txt
    chmod a+r README.md

    # Числовий режим
    chmod 644 README.md
    chmod 600 .env
    chmod 755 script.sh
    chmod 700 private-dir/

    # Рекурсивна зміна (обережно)
    chmod -R 755 directory/

    # Знайти файли з конкретними правами
    find . -type f -perm 0644

    # Знайти об'єкти з правом запису для інших
    find . -perm -0002

    # Основні значення
    # r = 4
    # w = 2
    # x = 1
    # 7 = rwx
    # 6 = rw-
    # 5 = r-x
    # 4 = r--
    # 0 = ---

## Висновок

`chmod` — одна з основних команд для керування доступом у Linux. Вона дає змогу призначати права власнику, групі та іншим користувачам як символьним, так і числовим способом.

Для впевненої роботи важливо не лише запам'ятати `644`, `755` і `600`, а й розуміти, **які саме дії дозволяють ці права, чим відрізняються права файлу від прав директорії та як безпечно діагностувати помилки доступу**.
