# 02. Arguments

Arguments (аргументи) в Bash — це значення, які передаються скрипту під час його запуску. Вони дозволяють використовувати один скрипт для різних даних без необхідності змінювати його код.

Аргументи використовуються, коли потрібно:

- передати ім'я файлу або директорії;
- указати ім'я користувача;
- передати число або текст;
- вибрати режим роботи скрипту;
- указати шлях до проєкту;
- передати декілька значень одночасно;
- створювати універсальні скрипти для автоматизації;
- запускати команди з різними параметрами;
- перевіряти, чи передано необхідні дані;
- передавати аргументи функціям та іншим скриптам.

Наприклад, замість створення окремого скрипту для кожного користувача можна створити один:

    #!/usr/bin/env bash

    echo "Hello, $1!"

Запуск:

    bash hello.sh Valeriy
    bash hello.sh Linux
    bash hello.sh Developer

Результат:

    Hello, Valeriy!
    Hello, Linux!
    Hello, Developer!

Тут `$1` — перший позиційний параметр, тобто перший аргумент після назви скрипту.

Основні елементи роботи з аргументами Bash:

    positional parameters
    $0
    $1, $2, $3...
    $#
    $@
    $*
    "$@"
    "$*"
    shift
    argument validation
    default values
    quoting
    exit status
    command-line interface (CLI)

## Що потрібно пам'ятати

• Аргументи передаються скрипту під час його запуску.

• `$0` зазвичай містить ім'я або шлях, через який запущено скрипт.

• `$1` — перший позиційний параметр.

• `$2` — другий позиційний параметр.

• `$3` — третій позиційний параметр.

• Для параметрів із номером 10 і більше потрібно використовувати фігурні дужки:

    ${10}
    ${11}
    ${12}

• `$#` містить кількість позиційних параметрів, переданих скрипту.

• `"$@"` дозволяє передавати кожен аргумент як окремий елемент, зберігаючи аргументи з пробілами.

• `"$*"` об'єднує всі позиційні параметри в один рядок, використовуючи перший символ змінної `IFS` як роздільник.

• `shift` видаляє перший позиційний параметр і зсуває решту параметрів на одну позицію вліво.

• Подвійні лапки навколо аргументів допомагають зберегти пробіли та запобігають небажаному розбиттю слів і розгортанню шаблонів імен файлів.

• Аргументи не стають автоматично числами: зазвичай Bash отримує їх як текстові значення.

• Якщо аргумент обов'язковий, потрібно перевіряти, чи був він переданий.

• Для необов'язкових аргументів можна використовувати значення за замовчуванням.

• `$1` без перевірки може бути порожнім, якщо перший аргумент не передано.

• `exit 1` дозволяє завершити скрипт із ненульовим кодом, наприклад, якщо аргумент відсутній.

• `"$@"` особливо важливий, коли потрібно передати аргументи іншій команді або скрипту без втрати їхніх меж.

• У Bash аргументи функції також доступні через позиційні параметри, але всередині функції вони тимчасово стосуються аргументів цієї функції.

• Для складніших CLI-інтерфейсів із параметрами на кшталт `--file` або `--verbose` зазвичай використовують `while`, `case` і `shift`.

# Arguments

Argument — значення, яке передається програмі або скрипту під час запуску.

Наприклад:

    bash hello.sh Valeriy

У цьому прикладі:

    bash       → інтерпретатор
    hello.sh   → файл скрипту
    Valeriy    → аргумент скрипту

Якщо скрипт містить:

    #!/usr/bin/env bash

    echo "Hello, $1!"

Результат:

    Hello, Valeriy!

Аргумент `Valeriy` доступний через `$1`.

---

# Positional Parameters

Positional parameters — спеціальні параметри Bash, які містять позиційні аргументи.

Приклад запуску:

    bash user-info.sh Valeriy 56 Vinnytsia

Скрипт:

    #!/usr/bin/env bash

    echo "Name: $1"
    echo "Age: $2"
    echo "City: $3"

Результат:

    Name: Valeriy
    Age: 56
    City: Vinnytsia

Відповідність:

    $1 → Valeriy
    $2 → 56
    $3 → Vinnytsia

Позиція аргументу визначає, через який параметр його можна отримати.

---

# $0

`$0` — спеціальний параметр, який зазвичай містить ім'я або шлях, через який запущено скрипт.

Приклад:

    #!/usr/bin/env bash

    echo "Script: $0"

Запуск:

    bash hello.sh

Приклад результату:

    Script: hello.sh

Якщо запускати через шлях:

    bash ./scripts/hello.sh

то `$0` зазвичай міститиме:

    ./scripts/hello.sh

Точне значення залежить від способу запуску.

`$0` корисний для повідомлень про помилки та довідкової інформації.

Наприклад:

    #!/usr/bin/env bash

    printf "Usage: %s <name>\n" "$0"

Результат:

    Usage: hello.sh <name>

У цьому прикладі `$0` використовується для показу назви скрипту в повідомленні.

---

# $1, $2, $3

Позиційні параметри дають змогу отримувати аргументи за їхньою позицією.

Приклад:

    #!/usr/bin/env bash

    printf "First: %s\n" "$1"
    printf "Second: %s\n" "$2"
    printf "Third: %s\n" "$3"

Запуск:

    bash args.sh apple banana orange

Результат:

    First: apple
    Second: banana
    Third: orange

Важливо: якщо аргумент не передано, відповідний позиційний параметр зазвичай буде порожнім.

Наприклад:

    bash args.sh apple

Результат:

    First: apple
    Second:
    Third:

Тому обов'язкові аргументи потрібно перевіряти.

---

# Аргументи з номером 10 і більше

Для однозначних позиційних параметрів можна використовувати:

    $1
    $2
    $3

Але запис:

    $10

не означає десятий аргумент.

Bash інтерпретує його як `$1`, за яким іде символ `0`.

Для десятого та наступних аргументів використовують фігурні дужки:

    ${10}
    ${11}
    ${12}

Приклад:

    #!/usr/bin/env bash

    printf "First argument: %s\n" "$1"
    printf "Tenth argument: %s\n" "${10}"

Запуск:

    bash args.sh a b c d e f g h i j

Результат:

    First argument: a
    Tenth argument: j

Правило:

    $1     → перший аргумент
    $9     → дев'ятий аргумент
    ${10}  → десятий аргумент
    ${11}  → одинадцятий аргумент

---

# $#

`$#` — кількість позиційних параметрів.

Наприклад:

    #!/usr/bin/env bash

    printf "Arguments count: %s\n" "$#"

Запуск:

    bash args.sh apple banana orange

Результат:

    Arguments count: 3

Якщо аргументів немає:

    bash args.sh

Результат:

    Arguments count: 0

`$#` часто використовують для перевірки кількості аргументів.

---

## Перевірка кількості аргументів

Приклад: скрипт повинен отримати два аргументи.

    #!/usr/bin/env bash

    if [[ $# -ne 2 ]]; then
        printf "Usage: %s <name> <city>\n" "$0"
        exit 1
    fi

    printf "Name: %s\n" "$1"
    printf "City: %s\n" "$2"

Запуск із правильними аргументами:

    bash user-info.sh Valeriy Vinnytsia

Результат:

    Name: Valeriy
    City: Vinnytsia

Запуск без аргументів:

    bash user-info.sh

Результат:

    Usage: user-info.sh <name> <city>

Скрипт завершується з кодом `1`.

Тут:

    $#       → кількість аргументів
    -ne      → not equal
    exit 1   → завершити скрипт із ненульовим кодом

`[[ ... ]]` — конструкція Bash для перевірки умов. Детальніше вона розглядатиметься в темі `03-if-else`.

---

# $@ — усі аргументи

`$@` представляє всі позиційні параметри.

Приклад:

    #!/usr/bin/env bash

    printf "Arguments: %s\n" "$@"

Запуск:

    bash args.sh apple banana orange

Проте без подвійних лапок `$@` може зазнавати розбиття слів і розгортання шаблонів імен файлів.

Тому під час роботи з усіма аргументами зазвичай використовують:

    "$@"

---

# "$@"

`"$@"` — рекомендований спосіб передавання всіх позиційних параметрів зі збереженням кожного аргументу як окремого елемента.

Приклад:

    #!/usr/bin/env bash

    printf 'Argument: <%s>\n' "$@"

Запуск:

    bash args.sh apple banana orange

Результат:

    Argument: <apple>
    Argument: <banana>
    Argument: <orange>

Кожен аргумент передається окремо.

---

## "$@" та аргументи з пробілами

Запуск:

    bash args.sh "hello world" "Linux scripting" test

Скрипт:

    #!/usr/bin/env bash

    printf 'Argument: <%s>\n' "$@"

Результат:

    Argument: <hello world>
    Argument: <Linux scripting>
    Argument: <test>

Завдяки подвійним лапкам кожен аргумент зберіг свою цілісність.

Безпечний шаблон:

    command "$@"

Це особливо важливо, коли потрібно передати аргументи іншій команді або скрипту.

---

# $* — усі аргументи

`$*` також представляє всі позиційні параметри, але поводиться інакше, ніж `"$@"`.

Без подвійних лапок `$*` зазнає розбиття слів і розгортання шаблонів імен файлів.

У подвійних лапках:

    "$*"

усі позиційні параметри об'єднуються в один рядок. Роздільником є перший символ змінної `IFS`.

Приклад:

    #!/usr/bin/env bash

    printf 'All arguments: <%s>\n' "$*"

Запуск:

    bash args.sh apple banana orange

Результат:

    All arguments: <apple banana orange>

У цьому прикладі всі аргументи передано як один аргумент команді `printf`.

---

# "$@" vs "$*"

Це одна з найважливіших відмінностей Bash.

Приклад запуску:

    bash args.sh "hello world" "Linux scripting" test

Скрипт:

    #!/usr/bin/env bash

    printf 'Using "$@":\n'
    printf '<%s>\n' "$@"

    printf 'Using "$*":\n'
    printf '<%s>\n' "$*"

Результат:

    Using "$@":
    <hello world>
    <Linux scripting>
    <test>
    Using "$*":
    <hello world Linux scripting test>

Порівняння:

    "$@" → кожен аргумент окремо
    "$*" → усі аргументи як один рядок

Для передавання аргументів іншій команді зазвичай використовують:

    command "$@"

---

# Перебір усіх аргументів

Якщо потрібно обробити кожен аргумент окремо, можна використовувати цикл.

Приклад:

    #!/usr/bin/env bash

    for arg in "$@"; do
        printf "Argument: %s\n" "$arg"
    done

Запуск:

    bash args.sh apple banana orange

Результат:

    Argument: apple
    Argument: banana
    Argument: orange

У цьому прикладі:

    "$@" → усі позиційні параметри
    for  → перебирає кожен аргумент
    arg  → змінна поточного аргументу

Цикли докладніше розглядатимуться в темі `04-loops`.

---

# Передавання аргументів іншому скрипту

Одна з важливих задач автоматизації — запуск одного скрипту з іншого.

Наприклад, файл `show-args.sh`:

    #!/usr/bin/env bash

    printf 'Received: <%s>\n' "$@"

Інший файл `main.sh`:

    #!/usr/bin/env bash

    bash ./show-args.sh "$@"

Запуск:

    bash main.sh "hello world" Linux

Результат:

    Received: <hello world>
    Received: <Linux>

`"$@"` передає кожен аргумент окремо й зберігає пробіли всередині аргументів.

Не рекомендовано:

    bash ./show-args.sh $@

Тут аргументи можуть бути неправильно розбиті на слова або розгорнуті як шаблони імен файлів.

# shift

`shift` зсуває позиційні параметри вліво.

Після виконання:

    shift

колишній `$2` стає `$1`, колишній `$3` стає `$2` і так далі.

Початкові аргументи:

    $1 → apple
    $2 → banana
    $3 → orange

Після `shift`:

    $1 → banana
    $2 → orange

Перший аргумент більше не доступний через позиційні параметри.

---

## Приклад shift

    #!/usr/bin/env bash

    printf "Before shift:\n"
    printf "First: %s\n" "$1"
    printf "Second: %s\n" "$2"

    shift

    printf "After shift:\n"
    printf "First: %s\n" "$1"
    printf "Second: %s\n" "$2"

Запуск:

    bash args.sh apple banana orange

Результат:

    Before shift:
    First: apple
    Second: banana
    After shift:
    First: banana
    Second: orange

Після `shift` параметр `$1` містить наступний аргумент.

---

## shift із числом

Можна зсунути параметри на декілька позицій:

    shift 2

Це видаляє перші два позиційні параметри.

Наприклад, початково:

    $1 → a
    $2 → b
    $3 → c
    $4 → d

Після:

    shift 2

залишаються:

    $1 → c
    $2 → d

Не можна безпечно зсувати позиційні параметри на число, яке перевищує їхню кількість: у такому разі Bash повідомить про помилку.

---

# shift та обробка аргументів

`shift` часто використовується під час обробки параметрів командного рядка.

Наприклад:

    #!/usr/bin/env bash

    while [[ $# -gt 0 ]]; do
        printf "Current argument: %s\n" "$1"
        shift
    done

Запуск:

    bash args.sh apple banana orange

Результат:

    Current argument: apple
    Current argument: banana
    Current argument: orange

Логіка:

    $# > 0
        ↓
    прочитати $1
        ↓
    shift
        ↓
    перевірити $# знову
        ↓
    повторювати, доки аргументи залишаються

У цьому прикладі:

    -gt → greater than
    $#  → кількість аргументів
    $1  → поточний перший аргумент
    shift → перейти до наступного

Умова та цикл докладніше розглядатимуться в темах `03-if-else` і `04-loops`.

# Аргументи та подвійні лапки

Під час роботи з аргументами подвійні лапки мають велике значення.

Приклад:

    #!/usr/bin/env bash

    printf "First argument: %s\n" "$1"

Запуск:

    bash args.sh "hello world"

Результат:

    First argument: hello world

Аргумент містить пробіл, але залишається одним аргументом.

Якщо під час запуску не взяти текст у лапки:

    bash args.sh hello world

то скрипт отримає два аргументи:

    $1 → hello
    $2 → world

Лапки під час запуску визначають межі аргументів.

Лапки всередині скрипту допомагають правильно використовувати значення параметрів.

---

# Перевірка обов'язкових аргументів

Якщо скрипт вимагає аргумент, потрібно перевіряти, чи передано його.

Наприклад, `greet.sh`:

    #!/usr/bin/env bash

    if [[ $# -lt 1 ]]; then
        printf "Usage: %s <name>\n" "$0" >&2
        exit 1
    fi

    printf "Hello, %s!\n" "$1"

Запуск без аргументу:

    bash greet.sh

Результат:

    Usage: greet.sh <name>

Запуск із аргументом:

    bash greet.sh Valeriy

Результат:

    Hello, Valeriy!

Тут:

    $# -lt 1 → аргументів менше одного
    >&2      → перенаправлення повідомлення в stderr
    exit 1   → завершення з ненульовим кодом

`stderr` — стандартний потік для повідомлень про помилки.

---

# Перевірка точного числа аргументів

Приклад: скрипту потрібно рівно два аргументи.

    #!/usr/bin/env bash

    if [[ $# -ne 2 ]]; then
        printf "Usage: %s <source> <destination>\n" "$0" >&2
        exit 1
    fi

    printf "Source: %s\n" "$1"
    printf "Destination: %s\n" "$2"

Правильний запуск:

    bash copy-info.sh source.txt backup.txt

Результат:

    Source: source.txt
    Destination: backup.txt

Якщо аргументів менше або більше двох, скрипт виведе повідомлення про правильний спосіб запуску.

Основні числові оператори в `[[ ... ]]`:

    -eq → дорівнює
    -ne → не дорівнює
    -gt → більше
    -ge → більше або дорівнює
    -lt → менше
    -le → менше або дорівнює

Докладніше вони розглядатимуться в темі `03-if-else`.

# Значення за замовчуванням

Іноді аргумент є необов'язковим.

У такому випадку можна задати значення за замовчуванням.

Приклад:

    #!/usr/bin/env bash

    name="${1:-Guest}"

    printf "Hello, %s!\n" "$name"

Запуск без аргументу:

    bash greet.sh

Результат:

    Hello, Guest!

Запуск з аргументом:

    bash greet.sh Valeriy

Результат:

    Hello, Valeriy!

Вираз:

    ${1:-Guest}

означає: використати `$1`, якщо він установлений і не є порожнім рядком; інакше використати `Guest`.

---

## ${1-default}

Є також форма:

    ${1-Guest}

Вона використовує значення за замовчуванням, якщо параметр не встановлений.

Різниця:

    ${1-Guest}
    ${1:-Guest}

Перша форма використовує `Guest`, якщо параметр не встановлений.

Друга форма використовує `Guest`, якщо параметр не встановлений або є порожнім рядком.

Наприклад, запуск із порожнім аргументом:

    bash greet.sh ""

Для:

    ${1-Guest}

значенням буде порожній рядок.

Для:

    ${1:-Guest}

значенням буде `Guest`.

Для типових необов'язкових аргументів часто зручніше використовувати `:-`.

---

# ${1:?error message}

Ця форма дозволяє повідомити про відсутній або порожній обов'язковий параметр.

Приклад:

    #!/usr/bin/env bash

    name="${1:?Error: name is required}"

    printf "Hello, %s!\n" "$name"

Якщо аргумент відсутній або порожній, Bash виведе повідомлення про помилку та завершить виконання поточного shell-контексту з ненульовим статусом.

Важливо: поведінка залежить від того, чи скрипт виконується окремим Bash-процесом, чи завантажується через `source`. Під час використання `source` така помилка може вплинути на поточну оболонку.

Для навчальних скриптів часто зрозуміліше явно перевіряти аргументи через `if`.

# Простий CLI

CLI — Command-Line Interface, тобто інтерфейс командного рядка.

Bash-скрипт може приймати аргументи для керування своєю поведінкою.

Наприклад:

    bash backup.sh documents
    bash backup.sh pictures
    bash backup.sh projects

Аргумент визначає, з якою директорією потрібно працювати.

Простий CLI-інтерфейс може мати:

    command
    positional arguments
    optional arguments
    flags
    options
    help message
    validation
    exit status

У цій темі головна увага приділяється позиційним аргументам. Параметри з назвами на кшталт `--help` і `--verbose` будуть розглянуті як наступний рівень роботи з CLI.

---

# Аргументи та --help

Багато команд підтримують параметр:

    --help

Він зазвичай виводить довідку щодо використання команди.

Для власного скрипту можна реалізувати простий варіант.

Приклад:

    #!/usr/bin/env bash

    if [[ "${1:-}" == "--help" ]]; then
        printf "Usage: %s <name>\n" "$0"
        printf "Print a greeting for the specified name.\n"
        exit 0
    fi

    if [[ $# -lt 1 ]]; then
        printf "Error: name is required.\n" >&2
        printf "Usage: %s <name>\n" "$0" >&2
        exit 1
    fi

    printf "Hello, %s!\n" "$1"

Використання:

    bash greet.sh --help

Приклад результату:

    Usage: greet.sh <name>
    Print a greeting for the specified name.

Звичайний запуск:

    bash greet.sh Valeriy

Результат:

    Hello, Valeriy!

У цьому прикладі `--help` — звичайний рядковий аргумент, який скрипт спеціально перевіряє.

# Аргументи з іменованими параметрами

У простих скриптах аргументи часто позиційні:

    bash script.sh source.txt destination.txt

Тут:

    $1 → source.txt
    $2 → destination.txt

Але іноді зручніше використовувати параметри з назвами:

    bash script.sh --source source.txt --destination backup.txt

У Bash немає автоматичного універсального механізму, який сам перетворює такі аргументи на змінні з відповідними назвами. Скрипт повинен сам розібрати аргументи.

Для цього часто використовують:

    while
    case
    shift

Приклад простого парсера:

    #!/usr/bin/env bash

    source_file=""
    destination=""

    while [[ $# -gt 0 ]]; do
        case "$1" in
            --source)
                if [[ $# -lt 2 ]]; then
                    printf "Error: --source requires a value\n" >&2
                    exit 1
                fi

                source_file="$2"
                shift 2
                ;;

            --destination)
                if [[ $# -lt 2 ]]; then
                    printf "Error: --destination requires a value\n" >&2
                    exit 1
                fi

                destination="$2"
                shift 2
                ;;

            --help)
                printf "Usage: %s --source FILE --destination DIR\n" "$0"
                exit 0
                ;;

            *)
                printf "Unknown argument: %s\n" "$1" >&2
                exit 1
                ;;
        esac
    done

    printf "Source: %s\n" "$source_file"
    printf "Destination: %s\n" "$destination"

Приклад запуску:

    bash script.sh --source notes.txt --destination backup

Тут:

    case      → вибирає дію за значенням $1
    $2        → значення після назви параметра
    shift 2   → видаляє оброблений параметр і його значення
    --help    → показує довідку
    *)        → обробляє невідомий аргумент

Це базовий приклад. Для надійного робочого скрипту потрібно також перевіряти обов'язковість параметрів, повторення опцій і коректність отриманих значень.

# Подвійний дефіс --

Подвійний дефіс `--` часто використовується командами як маркер завершення опцій.

Після нього аргументи трактуються як звичайні позиційні аргументи, а не як опції.

Наприклад:

    rm -- -file.txt

Це допомагає передати ім'я файлу, яке починається з дефіса, не сплутавши його з опцією команди.

У власних скриптах можна домовитися, що все після `--` вважається звичайними аргументами.

Важливо: `--` не є автоматичною мовною конструкцією Bash, яка змінює поведінку будь-якого скрипту. Її значення залежить від того, як скрипт або команда обробляє цей маркер.

# Arguments у функціях

У Bash функції також можуть отримувати аргументи.

Приклад:

    #!/usr/bin/env bash

    greet() {
        printf "Hello, %s!\n" "$1"
    }

    greet "Valeriy"
    greet "Linux"

Результат:

    Hello, Valeriy!
    Hello, Linux!

Усередині функції:

    $1 → перший аргумент функції
    $2 → другий аргумент функції
    $# → кількість аргументів функції
    "$@" → усі аргументи функції

Позиційні параметри функції тимчасово замінюють позиційні параметри зовнішнього контексту на час її виконання.

Після завершення функції позиційні параметри зовнішнього скрипту знову доступні.

Докладніше функції розглядатимуться в темі `05-functions`.

# Типові помилки

## 1. Плутати $0 та $1

    $0 → назва або шлях запуску скрипту
    $1 → перший позиційний аргумент

Не слід використовувати `$0`, коли потрібне значення першого аргументу.

## 2. Використовувати $10 замість ${10}

Неправильно:

    echo "$10"

Правильно:

    echo "${10}"

## 3. Забувати лапки навколо аргументів

Небажаний варіант:

    command $@

Рекомендований варіант:

    command "$@"

## 4. Плутати "$@" та "$*"

    "$@" → окремий аргумент для кожного позиційного параметра
    "$*" → один рядок з усіх позиційних параметрів

## 5. Не перевіряти обов'язкові аргументи

Якщо скрипт очікує ім'я файлу, але аргумент не передано, `$1` буде порожнім.

Краще перевіряти:

    if [[ $# -lt 1 ]]; then
        printf "Error: filename is required\n" >&2
        exit 1
    fi

## 6. Неправильно обробляти аргументи з пробілами

Запуск:

    bash script.sh hello world

передає два аргументи.

Запуск:

    bash script.sh "hello world"

передає один аргумент.

## 7. Не враховувати кількість аргументів

Якщо скрипт очікує два параметри, варто перевіряти:

    [[ $# -eq 2 ]]

## 8. Забувати, що аргументи — це текстові значення

Наприклад:

    bash sum.sh 10 20

Bash не перетворює `$1` і `$2` на типізовані числові змінні автоматично.

Для арифметики в Bash використовують арифметичні конструкції, наприклад:

    result=$(($1 + $2))

Але перед обчисленнями варто перевіряти, що передані значення відповідають очікуваному формату.

## 9. Використовувати shift без перевірки аргументів

Якщо скрипт очікує аргументи, перед `shift` потрібно враховувати їхню кількість.

## 10. Вважати, що --help працює автоматично

Параметр `--help` працює лише тоді, коли команда або скрипт реалізує відповідну логіку.

## 11. Передавати аргументи іншому скрипту без лапок

Небажано:

    bash child.sh $@

Правильно:

    bash child.sh "$@"

## 12. Не перевіряти значення аргументів

Наявність аргументу не означає, що його значення коректне.

Наприклад, якщо очікується число, скрипт має перевірити, що користувач справді передав число, перш ніж виконувати арифметику.

## Значення за замовчуванням

    name="${1:-Guest}"

Використати `Guest`, якщо `$1` не встановлений або порожній.

## Передавання аргументів

    bash child.sh "$@"

Передати всі аргументи дочірньому скрипту, зберігши межі кожного аргументу.

## Перебір аргументів

    for arg in "$@"; do
        printf "%s\n" "$arg"
    done

Обробити кожен аргумент окремо.

## Простий help

    if [[ "${1:-}" == "--help" ]]; then
        printf "Usage: %s <name>\n" "$0"
        exit 0
    fi

# Головне

• Аргументи роблять Bash-скрипти універсальними.

• `$0` зазвичай містить ім'я або шлях запуску скрипту.

• `$1`, `$2`, `$3` містять позиційні аргументи.

• Для десятого аргументу й наступних використовують `${10}`, `${11}` тощо.

• `$#` містить кількість позиційних параметрів.

• `"$@"` представляє всі аргументи окремо, зберігаючи пробіли всередині кожного аргументу.

• `"$*"` представляє всі аргументи як один рядок із роздільником, визначеним через `IFS`.

• Для передавання аргументів іншій команді зазвичай використовують `"$@"`.

• `shift` зсуває позиційні параметри вліво.

• `shift 2` пропускає перші два позиційні параметри.

• Подвійні лапки важливі для коректної обробки аргументів із пробілами.

• `[[ $# -lt 1 ]]` дозволяє перевірити, чи передано хоча б один аргумент.

• `[[ $# -eq 2 ]]` дозволяє перевірити, чи передано рівно два аргументи.

• `exit 1` дозволяє завершити скрипт із ненульовим кодом, якщо аргументи неправильні.

• `${1:-Guest}` задає значення за замовчуванням, якщо перший параметр не встановлений або порожній.

• `${1:?message}` дозволяє повідомити про відсутній або порожній параметр, але її потрібно застосовувати з розумінням поведінки shell.

• Аргументи функцій також доступні через `$1`, `$2`, `$#` та `"$@"` у контексті виклику функції.

• Параметри на кшталт `--help`, `--file` і `--verbose` потрібно обробляти логікою самого скрипту.

• Для складнішого CLI часто використовують `while`, `case` та `shift`.

• Основна модель роботи з аргументами:

    Запуск скрипту
          ↓
    Отримання аргументів
          ↓
    Перевірка кількості
          ↓
    Перевірка значень
          ↓
    Обробка аргументів
          ↓
    Виконання основної логіки
          ↓
    Завершення з відповідним кодом

• Основне правило безпечного передавання аргументів:

    command "$@"

• Правильна обробка аргументів робить скрипти надійнішими, зрозумілішими та придатними для повторного використання.
