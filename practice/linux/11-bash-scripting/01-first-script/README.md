# 01. First Script

Bash script — це текстовий файл із командами Bash, які виконуються послідовно для автоматизації завдань у Linux.

Bash scripting дозволяє об'єднувати команди Linux в один файл, щоб виконувати повторювані операції автоматично.

Bash-скрипти використовуються, коли потрібно:

- автоматизувати повсякденні операції в Linux;
- працювати з файлами та директоріями;
- запускати послідовність команд;
- перевіряти стан системи;
- працювати з процесами, користувачами та дозволами;
- запускати Node.js-проєкти та інші програми;
- створювати резервні копії;
- автоматизувати розгортання застосунків;
- виконувати завдання за розкладом через `cron`.

## Що потрібно пам'ятати

• Bash-скрипт — це текстовий файл із командами, які виконує Bash.

• Розширення `.sh` є поширеною домовленістю, але не є обов'язковим.

• Shebang указує, який інтерпретатор потрібно використовувати для запуску скрипту.

• Для Bash-скриптів часто використовують:

    #!/usr/bin/env bash

• На Linux також часто зустрічається:

    #!/bin/bash

• Коментар у Bash починається із символу `#`, якщо він не перебуває всередині рядка або іншого контексту, де має інше значення.

• `echo` виводить текст, а `printf` дозволяє точніше контролювати формат виведення.

• Команди в скрипті зазвичай виконуються послідовно, одна за одною.

• Для запуску скрипту через Bash достатньо:

    bash script.sh

• Для безпосереднього запуску скрипту потрібно надати право на виконання:

    chmod +x script.sh

• Після цього скрипт можна запускати так:

    ./script.sh

• `./` означає запуск файлу з поточної директорії.

• Shebang використовується під час безпосереднього запуску скрипту. Якщо явно викликати `bash script.sh`, Bash читає файл як свій скрипт, а shebang не визначає інтерпретатор.

• `sh script.sh` запускає скрипт через `sh`, а не обов'язково через Bash. Синтаксис Bash може не працювати в інших shell.

• Код завершення останньої команди доступний через `$?`.

• Код `0` зазвичай означає успішне виконання, а ненульовий код — помилку або інший неуспішний результат.

• Bash-скрипт не потребує компіляції: інтерпретатор читає та виконує його команди.

• Важливо розрізняти поточну директорію термінала та директорію, у якій розташований сам скрипт.

# Що таке Bash scripting

Bash scripting — написання скриптів мовою Bash для автоматизації роботи в командному рядку Linux.

Звичайна команда в терміналі:

    pwd

Ту саму команду можна записати у файл:

    #!/usr/bin/env bash

    pwd

Тепер цю команду можна запускати багаторазово через скрипт.

Наприклад, файл `system-info.sh`:

    #!/usr/bin/env bash

    echo "System information"

    pwd
    whoami
    date

Після запуску Bash виконає команди послідовно.

# Script File

Bash-скрипт — звичайний текстовий файл.

Наприклад:

    hello.sh

Вміст файлу:

    #!/usr/bin/env bash

    echo "Hello, Linux!"

Файл можна створити в терміналі за допомогою текстового редактора.

Наприклад, через `nano`:

    nano hello.sh

Вставити код:

    #!/usr/bin/env bash

    echo "Hello, Linux!"

Зберегти файл у `nano`:

    Ctrl + O
    Enter
    Ctrl + X

Перевірити його вміст:

    cat hello.sh

Важливо: файл повинен містити звичайний текст, а не форматований документ.

# Розширення .sh

Для Bash-скриптів часто використовують розширення:

    .sh

Наприклад:

    hello.sh
    backup.sh
    deploy.sh
    system-info.sh

Але Linux не вимагає обов'язкового розширення `.sh`.

Наприклад, допустимі назви:

    hello

    backup
    deploy.sh

Розширення допомагає людині зрозуміти призначення файлу, але саме по собі не визначає інтерпретатор і не надає права на виконання.

# Shebang

Shebang — спеціальний перший рядок скрипту, який починається з:

    #!

Він указує системі, який інтерпретатор використовувати під час безпосереднього запуску виконуваного файлу.

Стандартний варіант для Bash:

    #!/usr/bin/env bash

Інший поширений варіант:

    #!/bin/bash

Наприклад:

    #!/usr/bin/env bash

    echo "Hello, Linux!"

Shebang потрібно розміщувати на початку файлу.

Правильно:

    #!/usr/bin/env bash

    echo "Hello"

Не варто розміщувати перед ним звичайний коментар:

    # My first script
    #!/usr/bin/env bash

У такому випадку перший рядок уже не є shebang для безпосереднього запуску.

Правильно:

    #!/usr/bin/env bash

    # My first script

    echo "Hello"

---

## #!/usr/bin/env bash

Цей рядок запускає `env`, який знаходить `bash` у каталогах, зазначених у змінній середовища `PATH`.

    #!/usr/bin/env bash

Такий варіант зручний, коли Bash доступний через `PATH`.

---

## #!/bin/bash

Цей варіант указує конкретний шлях до Bash:

    #!/bin/bash

Він поширений у Linux-системах, де Bash розташований у `/bin/bash`.

Якщо потрібно перевірити розташування Bash:

    command -v bash

Приклад результату:

    /usr/bin/bash

Конкретний шлях залежить від системи.

---

## Shebang vs запуск через Bash

Є два поширені способи запуску скрипту.

### Спосіб 1 — безпосередній запуск

    chmod +x hello.sh

    ./hello.sh

Система використовує shebang для визначення інтерпретатора.

### Спосіб 2 — запуск через Bash

    bash hello.sh

У цьому випадку Bash сам читає файл і виконує команди. Право на виконання самого файлу для такого запуску не потрібне.

# Коментарі

Коментар — текст у скрипті, призначений для пояснення коду.

Коментар починається із символу:

    #

Приклад:

    #!/usr/bin/env bash

    # Display a greeting
    echo "Hello, Linux!"

Коментарі не виконуються як команди.

Вони допомагають:

- пояснювати призначення скрипту;
- документувати важливі рішення;
- відокремлювати логічні блоки;
- полегшувати подальше обслуговування коду.

---

## Однорядковий коментар

    # This is a comment

    echo "Hello"

---

## Коментарі між командами

    # Display current user
    whoami

    # Display current directory
    pwd

    # Display current date
    date

---

## Коментар після команди

    echo "Hello" # Display a greeting

Такий запис допустимий, якщо символ `#` починає коментар поза контекстом рядка або іншого синтаксису.

# echo

`echo` виводить текст у стандартний потік виведення — `stdout`.

Приклад:

    echo "Hello, Linux!"

Результат:

    Hello, Linux!

---

## Кілька команд echo

    #!/usr/bin/env bash

    echo "Hello!"
    echo "Welcome to Linux."
    echo "This is my first script."

Результат:

    Hello!
    Welcome to Linux.
    This is my first script.

За замовчуванням кожен виклик `echo` завершує рядок символом нового рядка.

---

## echo та змінні

Змінні докладніше розглядатимуться в наступних темах.

Поки достатньо знати, що значення змінної можна вивести так:

    #!/usr/bin/env bash

    name="Valeriy"

    echo "Hello, $name!"

Результат:

    Hello, Valeriy!

---

# printf

`printf` — команда для форматованого виведення.

Вона дає більше контролю над форматуванням тексту, ніж `echo`.

Приклад:

    #!/usr/bin/env bash

    printf "Hello, Linux!\n"

Результат:

    Hello, Linux!

Тут `\n` означає перехід на новий рядок.

---

## Кілька рядків через printf

    #!/usr/bin/env bash

    printf "First line\n"
    printf "Second line\n"
    printf "Third line\n"

Результат:

    First line
    Second line
    Third line

---

## printf з форматуванням

    #!/usr/bin/env bash

    name="Valeriy"
    age=56

    printf "Name: %s\n" "$name"
    printf "Age: %d\n" "$age"

Результат:

    Name: Valeriy
    Age: 56

Основні формати:

    %s  → рядок
    %d  → ціле число
    %f  → число з плаваючою комою

Для Bash-скриптів `printf` часто є хорошим вибором, коли важливе передбачуване форматування.

---

# echo vs printf

`echo`:

    echo "Hello, Linux!"

`printf`:

    printf "Hello, Linux!\n"

Основна різниця:

    echo    → просте виведення тексту
    printf  → контрольоване форматоване виведення

Для простих повідомлень `echo` зазвичай достатньо.

Для форматування, керування новими рядками та виведення значень у визначеному форматі зручно використовувати `printf`.

# Command Sequence

Bash-скрипт може містити декілька команд.

Наприклад:

    #!/usr/bin/env bash

    echo "System report"
    echo "-------------"

    whoami
    pwd
    date
    uname -s

Команди зазвичай виконуються в порядку їх розташування.

Логіка:

    Start
      ↓
    echo "System report"
      ↓
    echo "-------------"
      ↓
    whoami
      ↓
    pwd
      ↓
    date
      ↓
    uname -s
      ↓
    End

Це базова модель виконання скрипту.

У наступних темах будуть розглядатися умови, цикли, функції та обробка помилок, які дозволяють змінювати цей порядок.

# Поточна директорія та шлях до скрипту

Це важливе поняття для роботи з Bash.

Поточна робоча директорія — каталог, у якому зараз перебуває термінал.

Перевірити її можна командою:

    pwd

Наприклад:

    /home/user/projects

Якщо скрипт розташований у цій директорії, його можна запустити так:

    ./hello.sh

Якщо скрипт розташований в іншій директорії, потрібно вказати відповідний шлях.

---

## Relative Path

Відносний шлях задається відносно поточної робочої директорії.

Наприклад, структура:

    projects/
    ├── hello.sh
    └── scripts/
        └── system-info.sh

Якщо поточна директорія — `projects`, запуск:

    ./hello.sh

А запуск скрипту з піддиректорії:

    ./scripts/system-info.sh

Відносний шлях залежить від поточної робочої директорії.

---

## Absolute Path

Абсолютний шлях починається від кореневої директорії `/`.

Наприклад:

    /home/user/projects/hello.sh

Запуск:

    bash /home/user/projects/hello.sh

Або, якщо файл виконуваний:

    /home/user/projects/hello.sh

Абсолютний шлях не залежить від поточної робочої директорії.

---

## Важлива відмінність

Поточна робоча директорія:

    pwd

Каталог, у якому розташований скрипт, не обов'язково збігається з поточною робочою директорією.

Наприклад, якщо виконати:

    bash /home/user/scripts/hello.sh

з директорії:

    /home/user/projects

то `pwd` усередині скрипту зазвичай виведе:

    /home/user/projects

а не:

    /home/user/scripts

Це важливо для скриптів, які працюють із файлами за відносними шляхами.

# Права на виконання

Linux використовує права доступу до файлів.

Перевірити права:

    ls -l hello.sh

Приклад результату:

    -rw-r--r-- 1 user user 45 Oct 19 10:00 hello.sh

У цьому прикладі файл не має біта виконання.

Надати право на виконання:

    chmod +x hello.sh

Перевірити ще раз:

    ls -l hello.sh

Приклад результату:

    -rwxr-xr-x 1 user user 45 Oct 19 10:00 hello.sh

Тепер файл можна безпосередньо запускати:

    ./hello.sh

Детальніше права доступу розглядаються в розділі:

    05-permissions-and-ownership

# bash script vs executable script

Є два основні способи запуску.

## Через інтерпретатор

    bash hello.sh

Особливості:

- файл читається Bash;
- право на виконання файлу не обов'язкове;
- shebang не вибирає інтерпретатор для цього запуску;
- зручно для початкового тестування.

## Безпосередньо

    ./hello.sh

Особливості:

- файл повинен мати право на виконання;
- система використовує shebang для визначення інтерпретатора;
- скрипт запускається як виконуваний файл.

# Exit Status

Exit status — числовий код завершення команди або скрипту.

Загальне правило:

    0      → успішне виконання
    non-zero → помилка або інший неуспішний результат

Перевірити код завершення останньої команди можна через:

    $?

Приклад:

    #!/usr/bin/env bash

    echo "Hello"

    echo $?

Результат:

    Hello
    0

Команда `echo "Hello"` успішно завершилася, тому її код завершення — `0`.

---

## Перевірка коду після команди

    ls
    echo $?

Якщо `ls` успішно виконається, наступний `echo` зазвичай виведе:

    0

Інший приклад:

    ls /directory-that-does-not-exist
    echo $?

Команда `ls` повідомить про помилку й поверне ненульовий код завершення.

Конкретне ненульове значення залежить від команди.

Важливо: `$?` містить код завершення попередньої команди. Якщо спочатку виконати `echo`, то `$?` стосуватиметься вже `echo`.

---

# Команда exit

Команда `exit` завершує поточний Bash-скрипт із заданим кодом.

Приклад:

    #!/usr/bin/env bash

    echo "Script started"

    exit 0

    echo "This line will not execute"

Після `exit 0` скрипт завершується, тому останній `echo` не виконується.

Приклад завершення з ненульовим кодом:

    #!/usr/bin/env bash

    echo "An error occurred"

    exit 1

Перевірити код завершення після запуску:

    bash hello.sh
    echo $?

Результат:

    1

Детальніше `exit`, перевірка помилок і коди завершення розглядатимуться в темі:

    08-error-handling

# Виведення системної інформації

Створимо практичний скрипт `system-report.sh`.

    #!/usr/bin/env bash

    # Basic Linux system report

    printf "===== SYSTEM REPORT =====\n"

    printf "User: "
    whoami

    printf "Working directory: "
    pwd

    printf "Current date: "
    date

    printf "Kernel: "
    uname -r

    printf "Shell variable: %s\n" "$SHELL"

    printf "===== END OF REPORT =====\n"

Запуск:

    bash system-report.sh

Або:

    chmod +x system-report.sh
    ./system-report.sh

Зверни увагу: змінна `$SHELL` зазвичай указує на login shell користувача. Вона не обов'язково визначає shell, який фактично виконує поточний скрипт.

# Безпечне виведення тексту

Якщо текст містить пробіли, його зазвичай потрібно брати в лапки.

Наприклад:

    echo "Hello, Linux!"

Це читабельніше, ніж:

    echo Hello, Linux!

У простому `echo` обидва приклади виведуть схожий текст, але лапки стають особливо важливими під час роботи зі змінними.

Приклад:

    name="Linux user"

    printf "Hello, %s!\n" "$name"

Результат:

    Hello, Linux user!

Подвійні лапки навколо `"$name"` допомагають зберегти значення змінної як один аргумент, навіть якщо воно містить пробіли.

Докладніше робота зі змінними та лапками розглядатиметься в темі `02-arguments` та наступних темах Bash.

# set -e

`set -e` — режим Bash, за якого shell у багатьох ситуаціях завершує виконання скрипту, коли проста команда повертає ненульовий код завершення.

Приклад:

    #!/usr/bin/env bash

    set -e

    echo "Step 1"

    ls /directory-that-does-not-exist

    echo "Step 2"

У звичайному сценарії, якщо `ls` завершується помилкою, скрипт зупиниться й не виведе `Step 2`.

Але `set -e` не є універсальним механізмом обробки помилок: його поведінка залежить від контексту команд, умов, списків команд і функцій.

Для першого скрипту достатньо знати про існування цього режиму. Детальніше його буде розглянуто в темі:

    08-error-handling

# Типова структура Bash-скрипту

Невеликий скрипт може мати таку структуру:

    #!/usr/bin/env bash

    # Description:
    # Displays basic information about the system.

    echo "Starting script"

    # Main commands
    whoami
    pwd
    date

    echo "Script finished"

У більш складних скриптах також можуть бути:

    variables
    input arguments
    conditions
    loops
    functions
    arrays
    file tests
    error handling
    exit status

Ці елементи вивчатимуться в наступних темах розділу `11-bash-scripting`.

# Практичний приклад: інформація про користувача

Файл:

    user-info.sh

Код:

    #!/usr/bin/env bash

    # Display current user information

    printf "Current user: "
    whoami

    printf "Home directory: %s\n" "$HOME"

    printf "Current directory: "
    pwd

Запуск:

    bash user-info.sh

У цьому прикладі:

    whoami → ім'я поточного користувача
    $HOME  → домашня директорія користувача
    pwd    → поточна робоча директорія

`$HOME` — змінна середовища, яка зазвичай містить шлях до домашньої директорії користувача.

# Практичний приклад: дата й час

Файл:

    date-info.sh

Код:

    #!/usr/bin/env bash

    # Display date and time

    printf "Current date and time:\n"

    date

    printf "\nDate only:\n"

    date +%F

    printf "\nTime only:\n"

    date +%T

Приклад результату:

    Current date and time:
    Mon Oct 19 11:00:00 EEST 2026

    Date only:
    2026-10-19

    Time only:
    11:00:00

Фактичний результат залежить від поточних дати, часу та локалі системи.

# Практичний приклад: перевірка Bash

Файл:

    bash-info.sh

Код:

    #!/usr/bin/env bash

    printf "Bash location: "
    command -v bash

    printf "Bash version:\n"
    bash --version

Запуск:

    bash bash-info.sh

Цей скрипт показує розташування Bash і версійну інформацію.

Зверни увагу: команда `bash --version` може вивести декілька рядків, тому загальний результат буде довшим за один рядок.

# Типовий робочий процес

Під час створення Bash-скрипту зручно дотримуватися такого порядку:

    1. Створити файл
           ↓
    2. Записати shebang
           ↓
    3. Додати команди
           ↓
    4. Зберегти файл
           ↓
    5. Переглянути вміст
           ↓
    6. Запустити через Bash
           ↓
    7. Перевірити результат
           ↓
    8. За потреби надати право на виконання
           ↓
    9. Запустити через ./
          ↓
    10. Виправити помилки та повторити

Основні команди:

    nano hello.sh
    cat hello.sh
    bash hello.sh
    chmod +x hello.sh
    ./hello.sh

# Типові помилки

## 1. Забули shebang

Приклад:

    echo "Hello, Linux!"

Такий файл може виконуватися через:

    bash hello.sh

Але для безпосереднього запуску краще додати правильний shebang:

    #!/usr/bin/env bash

    echo "Hello, Linux!"

## 2. Немає права на виконання

Помилка під час запуску:

    ./hello.sh

Може виглядати так:

    Permission denied

Виправлення:

    chmod +x hello.sh

Альтернативно, для запуску через Bash:

    bash hello.sh

## 3. Неправильний шлях

Команда:

    ./hello.sh

шукає `hello.sh` у поточній робочій директорії.

Перевірити її:

    pwd

Перевірити наявність файлу:

    ls -l hello.sh

## 4. Bash-скрипт запускають через sh

Наприклад:

    sh hello.sh

Це може призвести до помилок, якщо скрипт використовує специфічний синтаксис Bash.

Для Bash-скрипту використовуй:

    bash hello.sh

або безпосередній запуск із правильним shebang:

    ./hello.sh

## 5. Shebang написаний неправильно

Наприклад:

    #!/usr/bin/env/bash

Це не стандартний правильний шлях для такого варіанту shebang.

Правильно:

    #!/usr/bin/env bash

## 6. Shebang розміщено не на першому рядку

Неправильно:

    # My script
    #!/usr/bin/env bash

Правильно:

    #!/usr/bin/env bash

    # My script

## 7. Плутанина між echo та printf

Для `printf` новий рядок зазвичай потрібно задавати явно:

    printf "Hello\n"

Без `\n` наступне виведення може продовжитися в тому самому рядку.

## 8. Неправильно використано лапки

Наприклад:

    name="Linux user"

    printf "%s\n" $name

У цьому випадку розгортання змінної без лапок може призвести до розбиття значення на декілька аргументів.

Краще:

    printf "%s\n" "$name"

## 9. Очікування, що скрипт змінить поточну директорію термінала

Якщо запустити:

    bash script.sh

команда `cd` усередині скрипту не змінить робочу директорію батьківського термінала після завершення скрипту.

Це відбувається тому, що скрипт виконується в окремому процесі Bash.

Для іншої поведінки існує запуск через `source` або `.`:

    source script.sh

Але цей спосіб виконує команди в поточному shell, тому потрібно бути обережним. Не запускай через `source` незнайомі скрипти.

## 10. Неправильне розуміння коду завершення

Команда:

    echo $?

показує код завершення попередньої команди, а не автоматично код завершення всього скрипту в будь-який момент.

Перевіряти його потрібно одразу після потрібної команди.

# Основи налагодження

Debugging — пошук і виправлення помилок у програмі або скрипті.

Для першого етапу достатньо декількох практичних прийомів.

## Перевірка вмісту

    cat hello.sh

## Перевірка шляху

    pwd
    ls -l hello.sh

## Перевірка інтерпретатора

    command -v bash

## Запуск у режимі трасування

Bash підтримує режим `-x`, який показує команди перед їх виконанням:

    bash -x hello.sh

Наприклад, для скрипту:

    #!/usr/bin/env bash

    name="Linux"

    echo "Hello, $name!"

Команда:

    bash -x hello.sh

покаже команди, які Bash виконує, і допоможе простежити послідовність виконання.

## Перевірка синтаксису

Команда:

    bash -n hello.sh

перевіряє синтаксис скрипту, не виконуючи його звичайні команди.

Це корисно перед запуском складніших скриптів.

# Головне

• Bash scripting дозволяє автоматизувати команди Linux.

• Bash-скрипт — це текстовий файл, який містить команди та конструкції Bash.

• Розширення `.sh` є домовленістю, а не обов'язковою вимогою.

• Shebang указує інтерпретатор для безпосереднього запуску скрипту.

• `#!/usr/bin/env bash` — поширений варіант shebang.

• `echo` зручно використовувати для простого виведення тексту.

• `printf` дає більше контролю над форматуванням.

• Команди скрипту зазвичай виконуються послідовно.

• `bash script.sh` запускає файл через Bash без необхідності встановлювати біт виконання.

• `chmod +x script.sh` надає право на виконання.

• `./script.sh` запускає файл із поточної директорії.

• Поточна робоча директорія та директорія самого скрипту можуть відрізнятися.

• `pwd` показує поточну робочу директорію.

• `whoami` показує ім'я поточного користувача.

• `date` виводить дату й час.

• `uname` показує інформацію про систему та ядро.

• `$?` містить код завершення попередньої команди.

• Код `0` зазвичай означає успіх, а ненульовий код — помилку або інший неуспішний результат.

• `bash -n` допомагає перевірити синтаксис без звичайного виконання команд скрипту.

• `bash -x` допомагає простежити виконання команд.

• `set -e` може зупинити скрипт після помилки, але не замінює повноцінну обробку помилок.

• `source` виконує скрипт у поточному shell, тому може змінити його стан.

• Перший Bash-скрипт має бути простим, зрозумілим і передбачуваним.

• Наступні теми розширять базові знання через аргументи, умови, цикли, функції, масиви та обробку помилок.
