# Bash Scripting — If / Else

У цьому розділі розглядаємо умовні конструкції Bash: `if`, `elif`, `else`, `case`, оператори порівняння, перевірку рядків, чисел, файлів і директорій.

Умови дають змогу скрипту приймати рішення залежно від вхідних даних, аргументів командного рядка, існування файлів, прав доступу та результатів виконання команд.

Умовні конструкції — одна з основ автоматизації Linux. Вони допомагають створювати скрипти, які не просто виконують команди послідовно, а реагують на різні ситуації.

---

## 1. Основи умовних конструкцій

### ✔ Що потрібно знати

- `if` — перевіряє умову.
- `then` — визначає команди, які виконуються, якщо умова істинна.
- `elif` — перевіряє наступну умову, якщо попередня не виконалася.
- `else` — виконує команди, якщо жодна попередня умова не виконалася.
- `fi` — завершує конструкцію `if`.
- `[[ ... ]]` — конструкція Bash для перевірки умов.
- `(( ... ))` — арифметична конструкція Bash.
- `case` — вибирає дію залежно від значення змінної або аргументу.
- `&&` — логічне «І» у відповідному контексті команд.
- `||` — логічне «АБО» у відповідному контексті команд.
- `!` — заперечення умови.
- `exit` — завершує скрипт із заданим кодом завершення.

### ✔ Загальна структура `if`

    #!/usr/bin/env bash

    if [[ умова ]]; then
        # Команди, якщо умова істинна
    fi

У Bash умова визначається статусом завершення команди або результатом спеціальної конструкції перевірки.

У конструкції `[[ ... ]]` результатом перевірки є статус:

- `0` — умова істинна.
- `1` — умова хибна.

Це може здатися незвичним: у Bash **нуль означає успіх або істину, а ненульовий код — невдачу або хибність**.

## 2. Конструкція `if`

### ✔ Найпростіший приклад

    #!/usr/bin/env bash

    name="Valeriy"

    if [[ "$name" == "Valeriy" ]]; then
        echo "Привіт, Valeriy!"
    fi

Результат:

    Привіт, Valeriy!

Якщо умова не виконується, команди всередині `if` просто пропускаються.

### ✔ Перевірка числа

    #!/usr/bin/env bash

    age=25

    if (( age >= 18 )); then
        echo "Повнолітній"
    fi

Для арифметичних порівнянь зручно використовувати `(( ... ))`.

Усередині цієї конструкції числові змінні можна використовувати без `$`.

    if (( age >= 18 )); then
        ...
    fi

Це Bash-арифметика, а не звичайний текстовий рядок.

### ✔ `if` із командами

Умова може перевіряти не лише значення змінної, а й успішність виконання команди.

    #!/usr/bin/env bash

    if grep -q "error" application.log; then
        echo "У журналі знайдено error"
    fi

Пояснення:

- `grep` шукає текст `error`.
- `-q` приховує знайдені рядки й залишає тільки код завершення.
- Якщо збіг знайдено, `grep` повертає `0`, тому виконується `then`.
- Якщо збігів немає, `grep` повертає `1`.

Важливо: код завершення команди — це не завжди просто відповідь «так» або «ні». Наприклад, `grep` може повернути інший ненульовий код, якщо сталася помилка.

## 3. Конструкція `if / else`

`else` виконує альтернативний блок, якщо умова в `if` хибна.

### ✔ Приклад

    #!/usr/bin/env bash

    number=7

    if (( number % 2 == 0 )); then
        echo "Число парне"
    else
        echo "Число непарне"
    fi

Результат:

    Число непарне

### ✔ Перевірка наявності аргументу

    #!/usr/bin/env bash

    if [[ -n "${1:-}" ]]; then
        echo "Привіт, $1!"
    else
        echo "Привіт, користувачу!"
    fi

Запуск:

    ./greet.sh Valeriy

Результат:

    Привіт, Valeriy!

Запуск без аргументу:

    ./greet.sh

Результат:

    Привіт, користувачу!

Пояснення:

- `$1` — перший аргумент скрипта.
- `-n` перевіряє, чи рядок має ненульову довжину.
- `${1:-}` повертає порожній рядок, якщо перший аргумент не задано або змінна не встановлена.
- Лапки допомагають зберігати значення як один рядок.

## 4. Конструкція `if / elif / else`

Використовується, коли потрібно перевірити декілька взаємовиключних варіантів.

### ✔ Синтаксис

    if [[ перша_умова ]]; then
        # Перша дія
    elif [[ друга_умова ]]; then
        # Друга дія
    elif [[ третя_умова ]]; then
        # Третя дія
    else
        # Дія за замовчуванням
    fi

Bash перевіряє умови послідовно зверху вниз. Виконується тільки перший блок, умова якого істинна.

### ✔ Приклад: оцінка за балами

    #!/usr/bin/env bash

    score=85

    if (( score >= 90 )); then
        echo "Відмінно"
    elif (( score >= 75 )); then
        echo "Добре"
    elif (( score >= 60 )); then
        echo "Задовільно"
    else
        echo "Потрібно повторити матеріал"
    fi

Результат:

    Добре

### ✔ Приклад: статус сервера

    #!/usr/bin/env bash

    status="running"

    if [[ "$status" == "running" ]]; then
        echo "Сервер працює"
    elif [[ "$status" == "stopped" ]]; then
        echo "Сервер зупинено"
    else
        echo "Невідомий статус"
    fi

### ✔ Порядок умов має значення

Неправильно:

    if (( score >= 60 )); then
        echo "Задовільно"
    elif (( score >= 90 )); then
        echo "Відмінно"
    fi

Якщо `score=95`, перша умова вже істинна. Тому до `elif` виконання не дійде.

Правильно розташовувати умови від більш специфічних або строгих до загальніших:

    if (( score >= 90 )); then
        echo "Відмінно"
    elif (( score >= 75 )); then
        echo "Добре"
    elif (( score >= 60 )); then
        echo "Задовільно"
    else
        echo "Не склав"
    fi

## 5. Порівняння рядків

Для порівняння рядків у Bash зазвичай використовують `[[ ... ]]`.

### ✔ Основні оператори

| Оператор | Значення |
|---|---|
| `==` | Рядки однакові |
| `!=` | Рядки різні |
| `-z` | Рядок порожній |
| `-n` | Рядок непорожній |
| `<` | Лексикографічно менший |
| `>` | Лексикографічно більший |

Для `<` і `>` у `[[ ... ]]` не потрібне екранування, яке було б необхідне в деяких інших конструкціях оболонки.

### ✔ Рівність рядків

    #!/usr/bin/env bash

    user="admin"

    if [[ "$user" == "admin" ]]; then
        echo "Доступ адміністратора"
    else
        echo "Звичайний користувач"
    fi

### ✔ Нерівність рядків

    #!/usr/bin/env bash

    environment="development"

    if [[ "$environment" != "production" ]]; then
        echo "Можна використовувати тестові налаштування"
    fi

### ✔ Перевірка порожнього рядка

    #!/usr/bin/env bash

    input=""

    if [[ -z "$input" ]]; then
        echo "Рядок порожній"
    fi

### ✔ Перевірка непорожнього рядка

    #!/usr/bin/env bash

    input="Hello"

    if [[ -n "$input" ]]; then
        echo "Рядок містить дані"
    fi

### ✔ Порівняння рядків з аргументами

    #!/usr/bin/env bash

    if [[ "${1:-}" == "start" ]]; then
        echo "Запускаємо програму"
    elif [[ "${1:-}" == "stop" ]]; then
        echo "Зупиняємо програму"
    else
        echo "Використання: $0 {start|stop}"
        exit 1
    fi

Запуск:

    ./service.sh start
    ./service.sh stop
    ./service.sh restart

У третьому випадку скрипт повідомить, що аргумент невідомий, і завершиться з кодом `1`.

### ✔ Регістр символів

Звичайне порівняння рядків чутливе до регістру:

    [[ "Admin" == "admin" ]]

Результат перевірки — хибний.

Якщо потрібно приймати декілька варіантів написання, можна перевірити їх окремо:

    if [[ "$user" == "admin" || "$user" == "Admin" ]]; then
        echo "Адміністратор"
    fi

## 6. Числові порівняння

У Bash є два поширені способи порівнювати числа:

1. Через арифметичну конструкцію `(( ... ))`.
2. Через `[[ ... ]]` з числовими операторами `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge`.

Для простих арифметичних перевірок зазвичай зручніше `(( ... ))`.

### ✔ Оператори

| Оператор у `(( ... ))` | Оператор у `[[ ... ]]` | Значення |
|---|---|---|
| `==` | `-eq` | Дорівнює |
| `!=` | `-ne` | Не дорівнює |
| `<` | `-lt` | Менше |
| `<=` | `-le` | Менше або дорівнює |
| `>` | `-gt` | Більше |
| `>=` | `-ge` | Більше або дорівнює |

Не плутай оператори для чисел і рядків. Наприклад, `[[ "$a" < "$b" ]]` порівнює рядки, а не числові значення.

### ✔ Приклади

    #!/usr/bin/env bash

    a=10
    b=20

    if (( a < b )); then
        echo "$a менше за $b"
    fi

    if (( a != b )); then
        echo "Числа різні"
    fi

Результат:

    10 менше за 20
    Числа різні

### ✔ Те саме через `[[ ... ]]`

    if [[ "$a" -lt "$b" ]]; then
        echo "a менше за b"
    fi

### ✔ Перевірка діапазону

    #!/usr/bin/env bash

    temperature=25

    if (( temperature < 0 )); then
        echo "Мороз"
    elif (( temperature <= 20 )); then
        echo "Прохолодно"
    elif (( temperature <= 30 )); then
        echo "Тепло"
    else
        echo "Спекотно"
    fi

### ✔ Важливе застереження

`(( ... ))` призначений для арифметичних виразів. Не слід передавати туди довільний текст, отриманий від користувача, не перевіривши його.

Якщо скрипт приймає число через аргумент, потрібно перевірити, що аргумент справді містить ціле число.

    #!/usr/bin/env bash

    if [[ ! "${1:-}" =~ ^-?[0-9]+$ ]]; then
        echo "Помилка: потрібно передати ціле число"
        exit 1
    fi

    number=$1

    if (( number > 0 )); then
        echo "Додатне число"
    elif (( number < 0 )); then
        echo "Від'ємне число"
    else
        echo "Нуль"
    fi

Вираз `^-?[0-9]+$` перевіряє ціле число: необов'язковий мінус і одна або більше цифр.

Цей приклад не приймає десяткові дроби, знак `+` або пробіли всередині числа.

## 7. Логічні оператори `&&`, `||`, `!`

Логічні оператори дають змогу об'єднувати умови.

### ✔ Логічне «І» — `&&`

Умова істинна, коли обидві перевірки істинні.

    #!/usr/bin/env bash

    age=25
    has_id="yes"

    if (( age >= 18 )) && [[ "$has_id" == "yes" ]]; then
        echo "Доступ дозволено"
    else
        echo "Доступ заборонено"
    fi

### ✔ Логічне «АБО» — `||`

Умова істинна, якщо істинна хоча б одна перевірка.

    #!/usr/bin/env bash

    role="admin"

    if [[ "$role" == "admin" || "$role" == "operator" ]]; then
        echo "Дозволено виконувати команду"
    else
        echo "Недостатньо прав"
    fi

### ✔ Заперечення — `!`

Оператор `!` змінює результат перевірки на протилежний.

    #!/usr/bin/env bash

    if [[ ! -f "config.txt" ]]; then
        echo "Файл config.txt не знайдено"
    fi

### ✔ Кілька умов

    #!/usr/bin/env bash

    username="admin"
    status="active"

    if [[ "$username" == "admin" && "$status" == "active" ]]; then
        echo "Адміністратор активний"
    fi

Усередині `[[ ... ]]` можна об'єднувати перевірки за допомогою `&&` і `||`.

### ✔ Коротке замикання

Bash використовує коротке замикання для `&&` та `||`:

- У `умова1 && умова2` друга умова не виконується, якщо перша хибна.
- У `умова1 || умова2` друга умова не виконується, якщо перша істинна.

Це корисно, коли друга перевірка має сенс тільки за певної умови.

### ✔ `&&` і `||` як оператори керування командами

Ці символи також можуть поєднувати команди поза `[[ ... ]]`.

    mkdir backup && echo "Каталог створено"

Друга команда виконається, лише якщо `mkdir` завершиться успішно.

    grep -q "error" application.log || echo "Збігів не знайдено"

У цьому прикладі повідомлення з'явиться, якщо `grep` поверне ненульовий код. Це може означати як відсутність збігів, так і помилку читання файлу, тому для важливих сценаріїв потрібно розрізняти ці випадки.

## 8. Перевірка файлів і директорій

У Linux-скриптах дуже часто потрібно перевіряти, чи існує файл, чи є він каталогом, чи можна його читати або записувати.

Для таких перевірок використовують `[[ ... ]]` зі спеціальними операторами.

### ✔ Основні оператори

| Оператор | Що перевіряє |
|---|---|
| `-e` | Шлях існує |
| `-f` | Існує звичайний файл |
| `-d` | Існує каталог |
| `-L` | Шлях є символічним посиланням |
| `-r` | Файл доступний для читання |
| `-w` | Файл доступний для запису |
| `-x` | Файл доступний для виконання |
| `-s` | Файл існує та має ненульовий розмір |

### ✔ Перевірка існування файлу

    #!/usr/bin/env bash

    if [[ -e "config.txt" ]]; then
        echo "Шлях config.txt існує"
    else
        echo "Шлях config.txt не знайдено"
    fi

`-e` перевіряє існування шляху, але не гарантує, що це звичайний файл.

### ✔ Перевірка звичайного файлу

    #!/usr/bin/env bash

    if [[ -f "config.txt" ]]; then
        echo "Звичайний файл існує"
    else
        echo "Звичайного файлу немає"
    fi

### ✔ Перевірка каталогу

    #!/usr/bin/env bash

    if [[ -d "backup" ]]; then
        echo "Каталог backup існує"
    else
        echo "Каталогу backup немає"
    fi

### ✔ Перевірка прав доступу

    #!/usr/bin/env bash

    file="report.txt"

    if [[ -r "$file" ]]; then
        echo "Файл доступний для читання"
    else
        echo "Файл не доступний для читання"
    fi

Перевірка `-r` не гарантує, що файл можна буде прочитати пізніше: права доступу або сам файл можуть змінитися.

### ✔ Перевірка перед копіюванням

    #!/usr/bin/env bash

    source_file="report.txt"
    destination="backup"

    if [[ ! -f "$source_file" ]]; then
        echo "Помилка: файл $source_file не знайдено"
        exit 1
    fi

    if [[ ! -d "$destination" ]]; then
        echo "Створюємо каталог $destination"
        mkdir -p "$destination" || exit 1
    fi

    cp -- "$source_file" "$destination/" || exit 1

    echo "Файл скопійовано"

Пояснення:

- `[[ ! -f "$source_file" ]]` — перевіряє, чи немає звичайного файлу.
- `mkdir -p` створює каталог, якщо його ще немає.
- `|| exit 1` завершує скрипт, якщо команда завершилася з помилкою.
- `cp --` використовує `--`, щоб шлях, який починається з дефіса, не сприймався як параметр команди.

## 9. Конструкція `case`

`case` — зручна альтернатива довгому ланцюжку `if / elif`, коли потрібно порівнювати одне значення з багатьма варіантами.

### ✔ Синтаксис

    case "$variable" in
        pattern1)
            # Команди для першого варіанта
            ;;
        pattern2)
            # Команди для другого варіанта
            ;;
        *)
            # Варіант за замовчуванням
            ;;
    esac

Пояснення:

- `case` — початок конструкції.
- `in` — початок переліку шаблонів.
- `pattern)` — шаблон, з яким порівнюється значення.
- `;;` — завершує блок конкретного варіанта.
- `*` — шаблон для всіх інших значень.
- `esac` — завершує конструкцію `case`.

### ✔ Приклад: команда користувача

    #!/usr/bin/env bash

    command="${1:-}"

    case "$command" in
        start)
            echo "Запускаємо програму"
            ;;
        stop)
            echo "Зупиняємо програму"
            ;;
        restart)
            echo "Перезапускаємо програму"
            ;;
        *)
            echo "Використання: $0 {start|stop|restart}"
            exit 1
            ;;
    esac

Запуск:

    ./service.sh start
    ./service.sh stop
    ./service.sh restart

### ✔ Кілька варіантів в одному шаблоні

    #!/usr/bin/env bash

    case "${1:-}" in
        -h|--help|help)
            echo "Довідка скрипта"
            ;;
        -v|--version)
            echo "Версія 1.0"
            ;;
        *)
            echo "Невідома команда"
            exit 1
            ;;
    esac

Символ `|` у шаблонах `case` означає «або».

### ✔ Шаблони в `case`

Шаблони підтримують прості символи підстановки:

- `*` — будь-яка кількість символів, зокрема нуль.
- `?` — рівно один символ.
- `[abc]` — один символ із переліку.
- `[0-9]` — один символ із діапазону.

Приклад:

    #!/usr/bin/env bash

    filename="report.txt"

    case "$filename" in
        *.txt)
            echo "Текстовий файл"
            ;;
        *.jpg|*.png)
            echo "Зображення"
            ;;
        *)
            echo "Невідомий тип файлу"
            ;;
    esac

Важливо: шаблони `case` — це шаблони імен, а не регулярні вирази.

## 10. Перевірка аргументів скрипта

Умовні конструкції особливо корисні для перевірки аргументів командного рядка.

### ✔ Перевірка кількості аргументів

Змінна `$#` містить кількість позиційних параметрів, переданих скрипту.

    #!/usr/bin/env bash

    if [[ $# -ne 1 ]]; then
        echo "Використання: $0 NAME"
        exit 1
    fi

    echo "Привіт, $1!"

Запуск:

    ./greet.sh Valeriy

Результат:

    Привіт, Valeriy!

Якщо передати нуль або два аргументи, скрипт покаже повідомлення про використання.

### ✔ Перевірка двох аргументів

    #!/usr/bin/env bash

    if [[ $# -ne 2 ]]; then
        echo "Використання: $0 SOURCE DESTINATION"
        exit 1
    fi

    source_file=$1
    destination=$2

    echo "Джерело: $source_file"
    echo "Призначення: $destination"

### ✔ Перевірка аргументу та його значення

    #!/usr/bin/env bash

    if [[ $# -lt 1 ]]; then
        echo "Помилка: передайте команду"
        exit 1
    fi

    if [[ "$1" != "start" && "$1" != "stop" ]]; then
        echo "Помилка: допустимі команди start або stop"
        exit 1
    fi

    echo "Команда: $1"

Пам'ятай:

- `-eq`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` — числові оператори для `[[ ... ]]`.
- `==`, `!=`, `<`, `>` у `[[ ... ]]` — порівняння рядків або шаблонів відповідно до правил Bash.
- `(( ... ))` — зручний варіант для арифметичних умов.

## 11. Значення за замовчуванням

Іноді аргумент необов'язковий. Якщо його не передали, скрипт може використовувати значення за замовчуванням.

### ✔ Приклад

    #!/usr/bin/env bash

    name="${1:-Guest}"

    echo "Привіт, $name!"

Запуск:

    ./greet.sh

Результат:

    Привіт, Guest!

Запуск:

    ./greet.sh Olena

Результат:

    Привіт, Olena!

Вираз `${1:-Guest}` означає: використати значення першого параметра, якщо він встановлений і непорожній; інакше використати `Guest`.

### ✔ Різниця між `:-` і `-`

    name="${1:-Guest}"

Використовує `Guest`, якщо параметр не встановлений або порожній.

    name="${1-Guest}"

Використовує `Guest`, тільки якщо параметр не встановлений. Якщо параметр встановлений, але порожній, результат буде порожнім рядком.

Для необов'язкових аргументів зазвичай зручніший варіант `:-`.

## 12. Практичний приклад: перевірка файлу

Створимо скрипт `file-info.sh`, який приймає шлях до файлу та перевіряє його властивості.

    #!/usr/bin/env bash

    if [[ $# -ne 1 ]]; then
        echo "Використання: $0 FILE"
        exit 1
    fi

    file=$1

    if [[ ! -e "$file" ]]; then
        echo "Помилка: шлях не існує"
        exit 1
    elif [[ -d "$file" ]]; then
        echo "Це каталог"
    elif [[ -f "$file" ]]; then
        echo "Це звичайний файл"

        if [[ -r "$file" ]]; then
            echo "Доступний для читання"
        fi

        if [[ -w "$file" ]]; then
            echo "Доступний для запису"
        fi

        if [[ -s "$file" ]]; then
            echo "Файл не порожній"
        else
            echo "Файл порожній"
        fi
    else
        echo "Шлях існує, але це не звичайний файл і не каталог"
    fi

Зроби файл виконуваним:

    chmod +x file-info.sh

Запусти:

    ./file-info.sh report.txt
    ./file-info.sh backup
    ./file-info.sh missing.txt

Цей приклад поєднує перевірку аргументів, `if / elif / else`, перевірку існування шляху та перевірку типу файлу.

## 13. Практичний приклад: калькулятор

Створимо `calculator.sh`, який приймає два цілі числа та виконує одну операцію.

    #!/usr/bin/env bash

    if [[ $# -ne 3 ]]; then
        echo "Використання: $0 NUMBER OPERATION NUMBER"
        echo "Приклад: $0 10 + 5"
        exit 1
    fi

    a=$1
    operation=$2
    b=$3

    if [[ ! "$a" =~ ^-?[0-9]+$ || ! "$b" =~ ^-?[0-9]+$ ]]; then
        echo "Помилка: аргументи повинні бути цілими числами"
        exit 1
    fi

    case "$operation" in
        +)
            result=$((a + b))
            ;;
        -)
            result=$((a - b))
            ;;
        \*)
            result=$((a * b))
            ;;
        /)
            if (( b == 0 )); then
                echo "Помилка: ділення на нуль"
                exit 1
            fi

            result=$((a / b))
            ;;
        *)
            echo "Помилка: допустимі операції +, -, * та /"
            exit 1
            ;;
    esac

    echo "Результат: $result"

Запуск:

    ./calculator.sh 10 + 5
    ./calculator.sh 10 - 5
    ./calculator.sh 10 '*' 5
    ./calculator.sh 20 / 4

Результати:

    Результат: 15
    Результат: 5
    Результат: 50
    Результат: 5

Пояснення:

- `[[ "$a" =~ ^-?[0-9]+$ ]]` перевіряє, чи аргумент є цілим числом.
- `case` вибирає арифметичну операцію.
- `$(( ... ))` обчислює арифметичний вираз.
- `\*` у шаблоні `case` означає буквальну зірочку.
- У командному рядку символ `*` потрібно брати в лапки або екранувати, щоб оболонка не розгорнула його у список файлів.
- Ділення в Bash виконується для цілих чисел: наприклад, `7 / 2` дає `3`, а не `3.5`.

Це навчальний калькулятор для цілих чисел. Для роботи з дробами потрібен інший підхід, наприклад `awk` або спеціалізована утиліта.

## 14. Практичний приклад: `--help` і `--version`

Для зручності користувачів скрипти часто підтримують довідку та інформацію про версію.

    #!/usr/bin/env bash

    version="1.0.0"

    show_help() {
        echo "Використання: $0 [OPTION]"
        echo
        echo "Опції:"
        echo "  -h, --help       Показати довідку"
        echo "  -v, --version    Показати версію"
    }

    case "${1:-}" in
        -h|--help)
            show_help
            ;;
        -v|--version)
            echo "$version"
            ;;
        "")
            echo "Помилка: потрібно вказати опцію"
            show_help
            exit 1
            ;;
        *)
            echo "Помилка: невідома опція: $1"
            show_help
            exit 1
            ;;
    esac

Запуск:

    ./tool.sh --help
    ./tool.sh --version
    ./tool.sh --unknown

У прикладі використано функцію `show_help`, яка зменшує дублювання коду.

Це простий обробник одного аргументу. Для складніших скриптів із багатьма опціями, значеннями опцій та комбінаціями параметрів варто вивчити `getopts`.

## 15. Перевірка статусу команди

У Bash умова `if` може безпосередньо перевіряти результат виконання команди.

### ✔ Приклад із `mkdir`

    #!/usr/bin/env bash

    if mkdir backup; then
        echo "Каталог успішно створено"
    else
        echo "Не вдалося створити каталог"
        exit 1
    fi

Якщо каталог уже існує, `mkdir backup` без параметра `-p` зазвичай завершиться з помилкою, а скрипт виконає блок `else`.

### ✔ Приклад із `command -v`

    #!/usr/bin/env bash

    if command -v git >/dev/null 2>&1; then
        echo "Git встановлено"
    else
        echo "Git не знайдено в PATH"
    fi

Пояснення:

- `command -v git` перевіряє, чи доступна команда `git`.
- `>/dev/null` приховує стандартний вивід.
- `2>&1` спрямовує повідомлення про помилки туди ж.
- Умова залежить від коду завершення `command -v`.

### ✔ Перевірка помилки команди

    if cp -- source.txt backup/; then
        echo "Копіювання успішне"
    else
        echo "Помилка копіювання"
        exit 1
    fi

Це зазвичай краще, ніж намагатися вгадати успішність операції за текстом, який команда вивела в термінал.

## 16. Умови й коди завершення

Кожна команда в Linux повертає код завершення.

- `0` — команда завершилася успішно.
- Ненульове значення — команда повідомляє про помилку або інший неуспішний результат.

Змінна `$?` містить код завершення останньої виконаної команди.

### ✔ Приклад

    mkdir backup

    if [[ $? -eq 0 ]]; then
        echo "Команда успішна"
    else
        echo "Команда завершилася з помилкою"
    fi

Однак краще перевіряти команду безпосередньо через `if`:

    if mkdir backup; then
        echo "Команда успішна"
    else
        echo "Команда завершилася з помилкою"
    fi

Чому другий варіант кращий? Між виконанням команди та перевіркою `$?` випадково може виконатися інша команда, і тоді `$?` уже міститиме інший код завершення.

### ✔ `exit 0` і `exit 1`

    exit 0

Означає успішне завершення скрипта.

    exit 1

Означає завершення з помилкою або невдалим результатом.

Для власних скриптів можна використовувати різні ненульові коди, щоб позначати різні види помилок.

## 17. Вкладені умови

В одній умові можна перевіряти іншу умову.

### ✔ Приклад

    #!/usr/bin/env bash

    file="report.txt"

    if [[ -e "$file" ]]; then
        echo "Шлях існує"

        if [[ -f "$file" ]]; then
            echo "Це звичайний файл"

            if [[ -r "$file" ]]; then
                echo "Файл доступний для читання"
            else
                echo "Файл недоступний для читання"
            fi
        else
            echo "Це не звичайний файл"
        fi
    else
        echo "Шлях не існує"
    fi

Вкладені умови корисні, коли наступна перевірка має сенс лише після успішного проходження попередньої.

Але надмірна вкладеність ускладнює читання. Часто простіше використовувати раннє завершення через `exit`.

### ✔ Варіант із раннім завершенням

    #!/usr/bin/env bash

    file="report.txt"

    if [[ ! -e "$file" ]]; then
        echo "Помилка: шлях не існує"
        exit 1
    fi

    if [[ ! -f "$file" ]]; then
        echo "Помилка: це не звичайний файл"
        exit 1
    fi

    if [[ ! -r "$file" ]]; then
        echo "Помилка: файл недоступний для читання"
        exit 1
    fi

    echo "Файл існує, є звичайним і доступний для читання"

Такий стиль часто зручний у практичних Bash-скриптах.

## 18. `[[ ... ]]` і `[ ... ]`

У Bash можна зустріти обидва варіанти перевірки умов.

### ✔ `[[ ... ]]`

    if [[ "$name" == "Valeriy" ]]; then
        echo "Знайдено"
    fi

Це конструкція Bash, яка підтримує зручніші правила роботи з рядками, шаблонами та логічними операторами.

### ✔ `[ ... ]`

    if [ "$name" = "Valeriy" ]; then
        echo "Знайдено"
    fi

`[` — це команда, яка має правила синтаксису, подібні до класичного `test`.

### ✔ Основні відмінності

| Властивість | `[[ ... ]]` | `[ ... ]` |
|---|---|---|
| Тип | Конструкція Bash | Команда `test` |
| Потрібні лапки для рядкових змінних | Зазвичай варто використовувати | Особливо важливо |
| Безпечна обробка пробілів у змінних | Зручніша | Вимагає уважного quoting |
| `&&` і `||` усередині умови | Підтримуються | Потрібно об'єднувати окремі перевірки зовні |
| Регулярні вирази через `=~` | Підтримуються | Не підтримуються в такому вигляді |
| Переносимість у різні оболонки | Bash та сумісні оболонки | Ширша сумісність |

Для Bash-скриптів, які запускаються саме через Bash, зазвичай зручно використовувати `[[ ... ]]`.

Якщо потрібна сумісність із POSIX `sh`, слід використовувати сумісний синтаксис і враховувати відмінності між оболонками.

---

## 19. Регулярні вирази в умовах

У Bash оператор `=~` у конструкції `[[ ... ]]` дає змогу перевіряти рядок регулярним виразом.

### ✔ Перевірка числа

    #!/usr/bin/env bash

    value="12345"

    if [[ "$value" =~ ^[0-9]+$ ]]; then
        echo "Це додатне ціле число або нуль"
    else
        echo "Це не ціле невід'ємне число"
    fi

### ✔ Перевірка формату

    #!/usr/bin/env bash

    username="user_123"

    if [[ "$username" =~ ^[a-zA-Z_][a-zA-Z0-9_]*$ ]]; then
        echo "Формат імені допустимий"
    else
        echo "Недопустимий формат імені"
    fi

Пояснення:

- `^` — початок рядка.
- `$` — кінець рядка.
- `[0-9]` — одна цифра.
- `[a-zA-Z_]` — літера латиниці або символ `_`.
- `+` — один або більше повторів попереднього елемента.
- `*` — нуль або більше повторів попереднього елемента.

У `[[ "$value" =~ REGEX ]]` регулярний вираз зазвичай пишуть без лапок праворуч, щоб Bash застосував його як регулярний вираз.

Регулярні вирази корисні для валідації аргументів, імен, чисел і простих форматів даних. Вони не замінюють повноцінну перевірку складних форматів на кшталт адрес електронної пошти чи URL.

## 20. Поширені помилки

### ✔ Помилка 1. Забули `then`

Неправильно:

    if [[ "$name" == "admin" ]]
        echo "Адміністратор"
    fi

Правильно:

    if [[ "$name" == "admin" ]]; then
        echo "Адміністратор"
    fi

### ✔ Помилка 2. Забули `fi`

Неправильно:

    if [[ -f "report.txt" ]]; then
        echo "Файл знайдено"

Правильно:

    if [[ -f "report.txt" ]]; then
        echo "Файл знайдено"
    fi

### ✔ Помилка 3. Використали `=` для числового порівняння

Не рекомендується:

    if [[ "$a" > "$b" ]]; then
        echo "a більше за b"
    fi

Це порівняння рядків, а не чисел.

Правильно:

    if (( a > b )); then
        echo "a більше за b"
    fi

Або:

    if [[ "$a" -gt "$b" ]]; then
        echo "a більше за b"
    fi

### ✔ Помилка 4. Не взяли змінну в лапки

Ризикований варіант:

    if [[ -f $file ]]; then
        echo "Файл знайдено"
    fi

Для `[[ ... ]]` розбиття на слова та розгортання шаблонів у звичайних змінних не відбувається так, як у `[ ... ]`, але послідовно використовувати лапки для рядкових значень — добра звичка.

Рекомендований варіант:

    if [[ -f "$file" ]]; then
        echo "Файл знайдено"
    fi

### ✔ Помилка 5. Використали `&&` замість `-a`

Не потрібно:

    if [ "$a" -gt 0 -a "$b" -gt 0 ]; then
        echo "Обидва додатні"
    fi

Краще:

    if [[ "$a" -gt 0 && "$b" -gt 0 ]]; then
        echo "Обидва додатні"
    fi

А для чисел у Bash ще простіше:

    if (( a > 0 && b > 0 )); then
        echo "Обидва додатні"
    fi

### ✔ Помилка 6. Неправильний порядок `elif`

Якщо спочатку перевірити широку умову, специфічніша може ніколи не виконатися.

    if (( score >= 60 )); then
        echo "Склав"
    elif (( score >= 90 )); then
        echo "Відмінно"
    fi

Потрібно починати з найвищого порогу.

### ✔ Помилка 7. Переплутали статус команди й текстовий результат

Не варто перевіряти вивід команди, якщо можна перевірити її код завершення.

Рекомендовано:

    if command -v node >/dev/null 2>&1; then
        echo "Node.js доступний"
    else
        echo "Node.js не знайдено"
    fi

### ✔ Помилка 8. Вважають, що `-e` означає звичайний файл

`-e` перевіряє існування шляху, а не його тип.

Для звичайного файлу використовуй `-f`, для каталогу — `-d`.

### ✔ Помилка 9. Використали `(( ... ))` для перевірки тексту

Неправильно:

    if (( username == "admin" )); then
        echo "Адміністратор"
    fi

Правильно:

    if [[ "$username" == "admin" ]]; then
        echo "Адміністратор"
    fi

### ✔ Помилка 10. Не врахували відсутній аргумент

Якщо скрипт запускається з `set -u`, звернення до неініціалізованого позиційного параметра може завершити скрипт із помилкою.

Безпечний варіант:

    if [[ "${1:-}" == "start" ]]; then
        echo "Запуск"
    fi

## 21. Як перевіряти Bash-скрипти

Перед запуском скрипта можна перевірити його синтаксис.

### ✔ Перевірка синтаксису

    bash -n script.sh

Команда перевіряє синтаксис без виконання основної логіки скрипта.

### ✔ Запуск у режимі трасування

    bash -x script.sh

Bash показуватиме команди та розгорнуті значення під час виконання. Це допомагає зрозуміти, чому конкретна умова спрацювала або не спрацювала.

### ✔ Перевірка через ShellCheck

Якщо встановлено `shellcheck`, можна виконати:

    shellcheck script.sh

ShellCheck знаходить багато типових помилок і підказує, як зробити Bash-скрипт надійнішим.

### ✔ Перевірка коду завершення

    ./script.sh
    echo $?

`0` зазвичай означає успішне завершення. Ненульове значення означає помилку або інший неуспішний результат.

## 22. Практика

### ✔ Завдання 1. Перевірка віку

Створи `age-check.sh`.

Вимоги:

1. Приймає вік як перший аргумент.
2. Перевіряє, чи передано аргумент.
3. Перевіряє, чи аргумент є цілим невід'ємним числом.
4. Якщо вік менший за 18 — виводить `Неповнолітній`.
5. Якщо вік від 18 до 64 — виводить `Дорослий`.
6. Якщо вік 65 або більше — виводить `Пенсійний вік`.
7. Якщо аргумент некоректний, завершується з кодом `1`.

Приклади запуску:

    ./age-check.sh 16
    ./age-check.sh 35
    ./age-check.sh 70
    ./age-check.sh abc

### ✔ Завдання 2. Перевірка файлу

Створи `check-file.sh`.

Вимоги:

1. Приймає шлях до файлу.
2. Якщо аргумент не переданий, виводить підказку.
3. Перевіряє, чи існує шлях.
4. Визначає, чи це файл або каталог.
5. Для звичайного файлу перевіряє доступність для читання.
6. У разі помилки повертає ненульовий код завершення.

### ✔ Завдання 3. Команда сервісу

Створи `service.sh`.

Підтримувані аргументи:

    ./service.sh start
    ./service.sh stop
    ./service.sh restart
    ./service.sh status

Використай `case`, щоб виводити відповідне повідомлення.

Для невідомої команди покажи довідку й заверши скрипт із кодом `1`.

### ✔ Завдання 4. Перевірка середовища

Створи `check-tools.sh`.

Вимоги:

1. Перевір, чи доступні команди `git`, `node` та `npm`.
2. Для кожної команди виведи, чи знайдено її в `PATH`.
3. Якщо хоча б однієї команди немає, скрипт має завершитися з ненульовим кодом.
4. Використай `command -v` і `if`.

### ✔ Завдання 5. Калькулятор

Розшир приклад калькулятора:

1. Підтримай операції `+`, `-`, `*`, `/`.
2. Перевір кількість аргументів.
3. Перевір, що числа є цілими.
4. Заборони ділення на нуль.
5. Виводь зрозумілі повідомлення про помилки.
6. Перевір коди завершення.

### ✔ Завдання 6. Довідка

Створи скрипт `tool.sh`, який підтримує:

    ./tool.sh --help
    ./tool.sh --version

Якщо аргумент відсутній або невідомий, виводь повідомлення про використання скрипта.

## 24. Що потрібно пам'ятати

- `if` починає умовну конструкцію.
- `then` починає блок команд.
- `elif` додає альтернативну умову.
- `else` виконується, якщо попередні умови не виконалися.
- `fi` завершує `if`.
- `case` зручний для вибору між багатьма варіантами.
- `[[ ... ]]` використовують для перевірки рядків, файлів і логічних умов у Bash.
- `(( ... ))` використовують для арифметичних умов.
- `&&` означає логічне «І».
- `||` означає логічне «АБО».
- `!` заперечує умову.
- `-e` перевіряє існування шляху.
- `-f` перевіряє звичайний файл.
- `-d` перевіряє каталог.
- `-r`, `-w`, `-x` перевіряють відповідні права доступу.
- `-z` перевіряє порожній рядок.
- `-n` перевіряє непорожній рядок.
- `command -v` допомагає перевірити доступність команди.
- `if command; then ...` перевіряє код завершення команди.
- `exit 0` означає успішне завершення.
- `exit 1` означає завершення з помилкою або невдалим результатом.
- `$#` містить кількість аргументів.
- `${1:-}` дає змогу безпечно перевірити необов'язковий перший аргумент.
- Умови потрібно розташовувати в правильному порядку.
- Для скриптів варто перевіряти синтаксис через `bash -n` і за можливості використовувати `shellcheck`.

## 25. Міні-шпаргалка

    # if
    if [[ "$name" == "admin" ]]; then
        echo "Адміністратор"
    fi

    # if / else
    if [[ -f "$file" ]]; then
        echo "Файл знайдено"
    else
        echo "Файл не знайдено"
    fi

    # if / elif / else
    if (( score >= 90 )); then
        echo "Відмінно"
    elif (( score >= 75 )); then
        echo "Добре"
    else
        echo "Потрібно попрацювати"
    fi

    # Рядки
    [[ "$a" == "$b" ]]
    [[ "$a" != "$b" ]]
    [[ -z "$value" ]]
    [[ -n "$value" ]]

    # Числа
    (( a == b ))
    (( a != b ))
    (( a < b ))
    (( a <= b ))
    (( a > b ))
    (( a >= b ))

    # Файли та каталоги
    [[ -e "$path" ]]
    [[ -f "$file" ]]
    [[ -d "$directory" ]]
    [[ -r "$file" ]]
    [[ -w "$file" ]]
    [[ -x "$file" ]]
    [[ -s "$file" ]]

    # Логічні оператори
    [[ "$a" == "yes" && "$b" == "yes" ]]
    [[ "$a" == "yes" || "$b" == "yes" ]]
    [[ ! -f "$file" ]]

    # Перевірка команди
    if command -v git >/dev/null 2>&1; then
        echo "Git доступний"
    fi

    # Перевірка кількості аргументів
    if [[ $# -ne 2 ]]; then
        echo "Використання: $0 ARG1 ARG2"
        exit 1
    fi

    # case
    case "${1:-}" in
        start)
            echo "Запуск"
            ;;
        stop)
            echo "Зупинка"
            ;;
        *)
            echo "Невідома команда"
            exit 1
            ;;
    esac

    # Код завершення
    exit 0
    exit 1

## 26. Підсумок

Умовні конструкції — основний інструмент для створення Bash-скриптів, які приймають рішення залежно від даних і стану системи.

Після опанування цієї теми ти маєш уміти:

- створювати умови `if`, `elif` і `else`;
- використовувати `case` для вибору команди;
- порівнювати рядки й числа;
- перевіряти файли, каталоги та права доступу;
- об'єднувати умови за допомогою `&&`, `||` і `!`;
- перевіряти аргументи командного рядка;
- реагувати на коди завершення команд;
- повертати зрозумілі повідомлення про помилки;
- перевіряти синтаксис Bash-скриптів.

**Головна практична звичка:** спочатку перевір вхідні дані та передумови, потім виконуй основну дію, а в разі помилки повертай зрозуміле повідомлення й відповідний код завершення.

Наступна тема: `04-loops` — цикли `for`, `while`, `until`, `break` і `continue`.
