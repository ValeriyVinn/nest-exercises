# Bash Scripting — Functions

У цьому розділі розглядаємо функції Bash: як оголошувати функції, викликати їх, передавати аргументи, повертати статус виконання, працювати з локальними змінними та повторно використовувати код.

Функції дають змогу розділити великий скрипт на невеликі логічні частини. Замість того щоб багато разів копіювати однакові команди, можна описати їх один раз і викликати функцію в потрібному місці.

У Linux функції особливо корисні для автоматизації: перевірки файлів і каталогів, обробки аргументів, виведення повідомлень, перевірки залежностей, резервного копіювання та обробки помилок.

---

## 1. Основи функцій Bash

### ✔ Що потрібно знати

- `function_name()` — оголошення функції.
- `function_name` — виклик функції.
- `$1`, `$2`, `$3` — позиційні параметри функції.
- `$#` — кількість аргументів функції.
- `"$@"` — усі аргументи функції зі збереженням меж між ними.
- `local` — оголошення локальної змінної функції.
- `return` — завершення функції та повернення статусу виконання.
- `$?` — статус завершення останньої команди або функції.
- `$(function_name)` — отримання текстового виводу функції через підстановку команди.
- `printf` — форматований вивід.
- `exit` — завершення всього скрипта, а не лише функції.

### ✔ Навіщо потрібні функції?

Без функцій однаковий код доводиться повторювати:

    echo "Перевіряю файл..."
    if [[ -f "data.txt" ]]; then
        echo "Файл знайдено"
    else
        echo "Файл не знайдено"
    fi

    echo "Перевіряю інший файл..."
    if [[ -f "report.txt" ]]; then
        echo "Файл знайдено"
    else
        echo "Файл не знайдено"
    fi

За допомогою функції однакову логіку можна описати один раз:

    check_file() {
        local file=$1

        echo "Перевіряю файл: $file"

        if [[ -f "$file" ]]; then
            echo "Файл знайдено"
        else
            echo "Файл не знайдено"
        fi
    }

    check_file "data.txt"
    check_file "report.txt"

### ✔ Переваги функцій

- Менше дублювання коду.
- Простіше читати скрипт.
- Легше знаходити й виправляти помилки.
- Зручніше тестувати окремі частини програми.
- Легше розширювати скрипт новими можливостями.
- Можна відокремити основну логіку від допоміжних операцій.

## 2. Оголошення функції

У Bash є два поширені способи оголошення функцій.

### ✔ Спосіб 1. Рекомендований для звичайних Bash-скриптів

    function_name() {
        # Команди функції
    }

Приклад:

    #!/usr/bin/env bash

    say_hello() {
        echo "Привіт, Linux!"
    }

    say_hello

Результат:

    Привіт, Linux!

### ✔ Спосіб 2. Із ключовим словом `function`

    function say_hello {
        echo "Привіт, Linux!"
    }

    say_hello

Також існує форма:

    function say_hello() {
        echo "Привіт, Linux!"
    }

У Bash усі ці форми підтримуються. Для навчання та звичайних скриптів зручно послідовно використовувати форму `name() { ...; }`.

### ✔ Основні частини

    say_hello() {
        echo "Привіт!"
    }

- `say_hello` — назва функції.
- `()` — позначає оголошення функції.
- `{ ... }` — тіло функції.
- `echo` — команда, яка виконується під час виклику.

Оголошення функції саме по собі не запускає її тіло. Для виконання потрібно викликати функцію за її назвою.

### ✔ Функція з кількома командами

    show_system_info() {
        echo "Користувач:"
        whoami

        echo "Поточний каталог:"
        pwd

        echo "Дата:"
        date
    }

    show_system_info

Усередині функції можна використовувати звичайні команди Bash, умови, цикли, інші функції та перенаправлення вводу-виводу.

## 3. Виклик функції

Функцію викликають за її назвою без додавання дужок.

### ✔ Приклад

    greet() {
        echo "Вітаю!"
    }

    greet

Правильно:

    greet

У звичайному виклику Bash не потрібно писати:

    greet()

Такий запис не є звичайним синтаксисом виклику функції Bash.

### ✔ Кілька викликів

    show_message() {
        echo "Це повідомлення"
    }

    show_message
    show_message
    show_message

Результат:

    Це повідомлення
    Це повідомлення
    Це повідомлення

### ✔ Виклик функції всередині іншої функції

    first() {
        echo "Перша функція"
    }

    second() {
        echo "Друга функція"
        first
    }

    second

Результат:

    Друга функція
    Перша функція

Функції можна комбінувати, створюючи складніші сценарії з невеликих логічних блоків.

### ✔ Порядок оголошення

У звичайному скрипті функція має бути оголошена до того, як її викличе основна частина скрипта.

    say_hello() {
        echo "Привіт!"
    }

    say_hello

Поширена структура скрипта:

    #!/usr/bin/env bash

    # 1. Оголошення функцій
    say_hello() {
        echo "Привіт!"
    }

    show_date() {
        date
    }

    # 2. Основна логіка скрипта
    say_hello
    show_date

## 4. Аргументи функції

Функції Bash можуть отримувати аргументи так само, як скрипти.

### ✔ Приклад

    greet() {
        echo "Привіт, $1!"
    }

    greet "Alice"
    greet "Bob"

Результат:

    Привіт, Alice!
    Привіт, Bob!

Усередині функції:

- `$1` — перший аргумент функції.
- `$2` — другий аргумент.
- `$3` — третій аргумент.
- `$#` — кількість аргументів функції.
- `"$@"` — усі аргументи функції окремо.

**Важливо:** позиційні параметри всередині функції відповідають аргументам саме цієї функції, а не безпосередньо аргументам скрипта.

### ✔ Функція з двома аргументами

    show_user() {
        local name=$1
        local age=$2

        echo "Ім'я: $name"
        echo "Вік: $age"
    }

    show_user "Alice" 25

Результат:

    Ім'я: Alice
    Вік: 25

### ✔ Аргументи з пробілами

    show_message() {
        printf 'Повідомлення: %s\n' "$1"
    }

    show_message "Hello world"

Результат:

    Повідомлення: Hello world

Коли передаєш аргумент із пробілами, використовуй лапки:

    show_message "Hello world"

Без лапок Bash може розділити текст на кілька аргументів:

    show_message Hello world

У цьому випадку `$1` міститиме лише `Hello`, а `world` стане другим аргументом.

### ✔ Усі аргументи через `"$@"`

    show_arguments() {
        for argument in "$@"; do
            printf 'Аргумент: %s\n' "$argument"
        done
    }

    show_arguments Alice 25 "Hello world"

Результат:

    Аргумент: Alice
    Аргумент: 25
    Аргумент: Hello world

`"$@"` зберігає кожен аргумент окремо, включно з аргументами, що містять пробіли.

### ✔ Кількість аргументів

    show_count() {
        echo "Кількість аргументів: $#"
    }

    show_count Alice 25 "Hello world"

Результат:

    Кількість аргументів: 3

### ✔ Перевірка кількості аргументів

    add_numbers() {
        if [[ $# -ne 2 ]]; then
            echo "Помилка: потрібно передати два числа" >&2
            return 1
        fi

        echo "Аргументи: $1 і $2"
    }

    add_numbers 10 20
    add_numbers 10

`return 1` завершує функцію з ненульовим статусом. Скрипт при цьому може продовжувати роботу, якщо виклик функції не спричиняє окремого завершення програми.

## 5. Локальні змінні — `local`

Змінні, оголошені всередині функції без `local`, у Bash зазвичай мають глобальну область видимості.

Щоб уникати випадкової зміни змінних за межами функції, використовуй `local`.

### ✔ Без `local`

    name="Global"

    change_name() {
        name="Local"
    }

    change_name

    echo "$name"

Результат:

    Local

Функція змінила змінну, яка доступна за її межами.

### ✔ Із `local`

    name="Global"

    change_name() {
        local name="Local"
        echo "У функції: $name"
    }

    change_name

    echo "Поза функцією: $name"

Результат:

    У функції: Local
    Поза функцією: Global

Локальна змінна існує в межах виклику функції та не змінює однойменну глобальну змінну.

### ✔ Рекомендований стиль

    calculate_total() {
        local price=$1
        local quantity=$2
        local total

        total=$((price * quantity))

        echo "$total"
    }

    calculate_total 100 3

Результат:

    300

У функції змінні `price`, `quantity` і `total` оголошені локальними.

### ✔ Важлива особливість Bash

Локальні змінні в Bash можуть бути видимими й у функціях, які викликаються зсередини поточної функції. Це пов'язано з динамічною областю видимості Bash.

Для початку достатньо дотримуватися простого правила: **оголошуй через `local` усі змінні, які потрібні лише всередині функції**.

### ✔ Змінна та `local` в одному рядку

Можна написати:

    local name=$1

Але якщо потрібно перевірити статус підстановки команди, не об'єднуй її виклик з оголошенням локальної змінної.

Наприклад:

    get_current_dir() {
        local directory

        directory=$(pwd) || return 1

        printf '%s\n' "$directory"
    }

Так можна коректно перевірити статус виконання `pwd`.

## 6. `return` — статус завершення функції

У Bash `return` зазвичай використовують для повернення статусу виконання функції, а не для повернення довільного текстового значення.

### ✔ Синтаксис

    function_name() {
        # Команди

        return 0
    }

Статус:

- `0` — успішне виконання.
- Ненульове значення — помилка або інший результат, який потрібно трактувати окремо.
- Діапазон статусів — від `0` до `255`.

### ✔ Приклад успіху

    check_success() {
        return 0
    }

    check_success

    echo "$?"

Результат:

    0

### ✔ Приклад помилки

    check_error() {
        return 1
    }

    check_error

    echo "$?"

Результат:

    1

`$?` містить статус завершення останньої виконаної команди. Тому перевіряй його одразу після потрібного виклику.

### ✔ Практичний приклад перевірки файлу

    check_file() {
        local file=$1

        if [[ -f "$file" ]]; then
            return 0
        else
            return 1
        fi
    }

    if check_file "data.txt"; then
        echo "Файл існує"
    else
        echo "Файл не знайдено"
    fi

Тут функція повертає статус, а основний код вирішує, що робити далі.

### ✔ Коротший варіант

    check_file() {
        [[ -f "$1" ]]
    }

    if check_file "data.txt"; then
        echo "Файл існує"
    else
        echo "Файл не знайдено"
    fi

У цьому прикладі функція завершується статусом останньої команди — перевірки `[[ -f "$1" ]]`.

Це поширений і компактний стиль Bash.

### ✔ Важливо: `return` не повертає звичайний текст

Не варто писати:

    get_name() {
        return "Alice"
    }

`return` призначений для числового статусу, а не для рядка.

Для повернення тексту використовуй стандартний вивід і підстановку команди — це розглянемо в наступному розділі.

## 7. Повернення текстових результатів

У Bash функції можуть передавати текст через стандартний вивід.

### ✔ Простий приклад

    get_greeting() {
        echo "Привіт, Linux!"
    }

    message=$(get_greeting)

    echo "$message"

Результат:

    Привіт, Linux!

Вираз `$(get_greeting)` запускає функцію в контексті підстановки команди й отримує її стандартний вивід.

### ✔ Повернення обчисленого значення

    calculate_sum() {
        local a=$1
        local b=$2

        printf '%s\n' "$((a + b))"
    }

    result=$(calculate_sum 10 20)

    echo "Сума: $result"

Результат:

    Сума: 30

### ✔ Функція з текстовим результатом і статусом

    get_username() {
        if [[ -n "${USER:-}" ]]; then
            printf '%s\n' "$USER"
        else
            echo "Не вдалося визначити користувача" >&2
            return 1
        fi
    }

    if username=$(get_username); then
        echo "Користувач: $username"
    else
        echo "Помилка отримання імені користувача" >&2
        exit 1
    fi

Тут:

- текст повертається через стандартний вивід;
- повідомлення про помилку направляється в стандартний потік помилок через `>&2`;
- `return 1` позначає невдале виконання;
- `if username=$(get_username)` перевіряє статус підстановки команди.

### ✔ Чому не можна змішувати текст і дані бездумно?

Якщо функція друкує діагностичні повідомлення в стандартний вивід, вони також потрапляють у результат `$(...)`.

Наприклад:

    get_value() {
        echo "Обчислюю..."
        echo 42
    }

    result=$(get_value)

Змінна `result` міститиме обидва рядки:

    Обчислюю...
    42

Якщо потрібне лише значення, діагностичні повідомлення краще направляти до стандартного потоку помилок:

    get_value() {
        echo "Обчислюю..." >&2
        echo 42
    }

Тоді в `result` буде лише `42`.

### ✔ Порівняння способів повернення

| Спосіб | Для чого підходить |
|---|---|
| `return 0` | Успішний статус |
| `return 1` | Невдалий статус або результат перевірки |
| `printf` | Передавання текстового результату |
| `echo` | Простий текстовий вивід |
| `$(function_name)` | Отримання тексту зі стандартного виводу функції |
| Глобальна змінна | Можлива, але часто створює зайву залежність |

**Запам'ятай:** статус функції та текстовий результат — це різні речі.

## 8. Перевірка результату функції

Функції часто використовують у командах `if`, `&&` і `||`.

### ✔ Перевірка через `if`

    is_root() {
        [[ "$EUID" -eq 0 ]]
    }

    if is_root; then
        echo "Скрипт запущено від root"
    else
        echo "Скрипт запущено не від root"
    fi

Функція повертає статус перевірки.

### ✔ Використання `&&`

    is_root() {
        [[ "$EUID" -eq 0 ]]
    }

    is_root && echo "Root-доступ є"

Команда після `&&` виконається, якщо попередня команда завершилася зі статусом `0`.

### ✔ Використання `||`

    is_root() {
        [[ "$EUID" -eq 0 ]]
    }

    is_root || echo "Потрібен root-доступ"

Команда після `||` виконається, якщо попередня команда завершилася з ненульовим статусом.

### ✔ Не плутай статус функції та статус останньої команди

    example() {
        return 1
        echo "Цей рядок не виконається"
    }

    example
    status=$?

    echo "Статус: $status"

Результат:

    Статус: 1

Після `return` функція завершується, тому наступні команди її тіла не виконуються.

## 9. Функції та аргументи скрипта

Аргументи самого скрипта й аргументи функції мають різні контексти.

### ✔ Приклад

    #!/usr/bin/env bash

    show_arguments() {
        echo "Аргумент функції 1: $1"
        echo "Аргумент функції 2: $2"
    }

    echo "Аргумент скрипта 1: $1"

    show_arguments "Alice" "Hello world"

Запуск:

    ./script.sh input.txt

Результат:

    Аргумент скрипта 1: input.txt
    Аргумент функції 1: Alice
    Аргумент функції 2: Hello world

Під час виконання функції `$1` і `$2` посилаються на аргументи функції. Після завершення функції позиційні параметри скрипта знову доступні в основному контексті.

### ✔ Передавання аргументів скрипта функції

    #!/usr/bin/env bash

    print_arguments() {
        for argument in "$@"; do
            printf 'Аргумент: %s\n' "$argument"
        done
    }

    print_arguments "$@"

Запуск:

    ./script.sh Alice 25 "Hello world"

Функція отримає три окремі аргументи.

### ✔ Чому потрібні лапки навколо `"$@"`?

Правильно:

    print_arguments "$@"

Неправильно:

    print_arguments $@

Без лапок Bash може розбити аргументи за пробілами й виконати розгортання шаблонів файлів. Це може змінити кількість і значення аргументів.

## 10. Функції та змінні середовища

Функції Bash можуть читати змінні середовища та інші доступні змінні оболонки.

### ✔ Приклад

    show_user() {
        echo "Користувач: ${USER:-невідомий}"
    }

    show_user

`${USER:-невідомий}` означає: використати значення `USER`, якщо воно задане й непорожнє; інакше використати текст `невідомий`.

### ✔ Аргумент чи змінна середовища?

Аргумент передається безпосередньо під час виклику:

    greet() {
        echo "Привіт, $1!"
    }

    greet "Alice"

Змінна середовища доступна функції через середовище процесу або успадкований контекст оболонки:

    export APP_MODE="development"

    show_mode() {
        echo "Режим: ${APP_MODE:-невідомий}"
    }

    show_mode

Змінні середовища зручні для налаштувань, а аргументи — для значень, які передаються конкретному виклику функції.

### ✔ Важливо про `export`

Змінна, оголошена в Bash, не обов'язково автоматично стає змінною середовища дочірніх процесів.

    APP_MODE="development"

    export APP_MODE

`export` позначає змінну для передавання в середовище дочірніх процесів.

## 11. Функції та перевірка аргументів

Надійна функція повинна перевіряти, чи отримала вона потрібні аргументи.

### ✔ Перевірка одного аргументу

    show_file() {
        if [[ $# -ne 1 ]]; then
            echo "Використання: show_file FILE" >&2
            return 1
        fi

        local file=$1

        if [[ ! -f "$file" ]]; then
            echo "Помилка: файл не знайдено: $file" >&2
            return 1
        fi

        printf 'Файл: %s\n' "$file"
    }

    show_file "data.txt"

### ✔ Перевірка двох аргументів

    add_numbers() {
        if [[ $# -ne 2 ]]; then
            echo "Використання: add_numbers NUMBER1 NUMBER2" >&2
            return 1
        fi

        local a=$1
        local b=$2

        if [[ ! "$a" =~ ^-?[0-9]+$ || ! "$b" =~ ^-?[0-9]+$ ]]; then
            echo "Помилка: потрібні цілі числа" >&2
            return 1
        fi

        printf '%s\n' "$((a + b))"
    }

    if result=$(add_numbers 10 20); then
        echo "Сума: $result"
    else
        echo "Не вдалося обчислити суму" >&2
        exit 1
    fi

Це навчальна перевірка цілих чисел. Для дуже великих чисел потрібно враховувати межі Bash-арифметики.

### ✔ Чому використовуємо `return 1`, а не `exit 1`?

Функція часто є частиною більшого скрипта. Якщо аргументи неправильні, вона може повідомити про помилку, повернути статус і дозволити викликачеві вирішити, що робити далі.

- `return 1` — завершує функцію.
- `exit 1` — завершує весь скрипт.

Використовуй `exit` у функції лише тоді, коли функція за призначенням повинна завершувати всю програму.

## 12. Функції та цикли

Функції зручно використовувати всередині циклів, щоб повторно виконувати одну операцію для різних значень.

### ✔ Перевірка файлів

    check_file() {
        local file=$1

        if [[ -f "$file" ]]; then
            printf '[OK] %s\n' "$file"
        else
            printf '[MISSING] %s\n' "$file"
        fi
    }

    for file in "data.txt" "report.txt" "notes.txt"; do
        check_file "$file"
    done

### ✔ Перевірка команд

    check_command() {
        local command_name=$1

        if command -v "$command_name" >/dev/null 2>&1; then
            printf '[OK] %s доступна\n' "$command_name"
        else
            printf '[MISSING] %s не знайдена\n' "$command_name"
        fi
    }

    for tool in git node npm python3; do
        check_command "$tool"
    done

`command -v` перевіряє, чи доступна команда в поточному середовищі оболонки.

### ✔ Чому це зручно?

Якщо потрібно змінити формат повідомлень або логіку перевірки, достатньо відредагувати функцію. Не потрібно змінювати кожен виклик окремо.

## 13. Функції та `source`

У Bash можна завантажити визначення функцій з іншого файлу за допомогою `source` або його скороченої форми `.`.

Це дає змогу винести спільні функції в окремий файл.

### ✔ Структура проєкту

    linux/
    └── functions-demo/
        ├── main.sh
        └── functions.sh

### ✔ Файл `functions.sh`

    say_hello() {
        printf 'Привіт, %s!\n' "$1"
    }

    show_date() {
        date
    }

### ✔ Файл `main.sh`

    #!/usr/bin/env bash

    source "./functions.sh"

    say_hello "Linux"
    show_date

### ✔ Запуск

    cd linux/functions-demo
    bash main.sh

Файл `functions.sh` не потрібно запускати окремо. Він містить визначення функцій, які завантажуються в поточну оболонку скрипта.

### ✔ Важливий нюанс із шляхами

Відносний шлях `./functions.sh` залежить від поточного робочого каталогу, з якого запускається скрипт.

Якщо потрібно, щоб скрипт знаходив файл відносно власного розташування, можна використати:

    #!/usr/bin/env bash

    SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"

    source "$SCRIPT_DIR/functions.sh"

`BASH_SOURCE[0]` містить шлях до файлу Bash, у якому виконується відповідний код. У цьому прикладі шлях використовується для пошуку `functions.sh` поруч із головним скриптом.

`source` виконує код підключеного файлу в поточній оболонці. Тому підключай лише файли, яким довіряєш.

## 14. Рекурсивні функції

Рекурсія — це ситуація, коли функція викликає сама себе.

У Bash рекурсія можлива, але для більшості простих завдань цикли часто зрозуміліші й економніші.

### ✔ Навчальний приклад

    countdown() {
        local number=$1

        if (( number <= 0 )); then
            echo "Старт!"
            return 0
        fi

        echo "$number"

        countdown "$((number - 1))"
    }

    countdown 5

Результат:

    5
    4
    3
    2
    1
    Старт!

### ✔ Як працює рекурсія?

1. Функція отримує число.
2. Якщо число менше або дорівнює нулю, вона завершується.
3. Інакше виводить число.
4. Викликає саму себе з числом на одиницю меншим.

### ✔ Чому потрібна базова умова?

Без умови завершення функція викликатиме сама себе нескінченно або до вичерпання ресурсів.

У практичних Bash-скриптах для повторюваних операцій зазвичай краще починати з циклів `for`, `while` або `until`. Рекурсію використовуй тоді, коли вона справді спрощує алгоритм.

## 15. Обробка помилок у функціях

Функції часто повертають статус, щоб викликач міг правильно обробити помилку.

### ✔ Приклад перевірки каталогу

    check_directory() {
        local directory=$1

        if [[ ! -d "$directory" ]]; then
            echo "Помилка: каталог не існує: $directory" >&2
            return 1
        fi

        return 0
    }

    if check_directory "documents"; then
        echo "Каталог готовий до використання"
    else
        echo "Перевір каталог і повтори спробу" >&2
    fi

### ✔ Перевірка статусу зовнішньої команди

    create_backup_dir() {
        local directory=$1

        if ! mkdir -p -- "$directory"; then
            echo "Помилка створення каталогу: $directory" >&2
            return 1
        fi

        echo "Каталог готовий: $directory"
    }

    if create_backup_dir "backup"; then
        echo "Можна продовжувати"
    else
        echo "Операцію перервано" >&2
        exit 1
    fi

### ✔ Навіщо `>&2`?

У Linux зазвичай використовують два основні потоки:

- `stdout` — стандартний вивід, файловий дескриптор `1`.
- `stderr` — стандартний потік помилок, файловий дескриптор `2`.

Конструкція:

    echo "Помилка" >&2

направляє повідомлення до `stderr`. Це корисно, коли стандартний вивід функції використовується для передачі даних.

### ✔ Функція не повинна приховувати помилку

Не рекомендується бездумно ігнорувати статуси команд.

    # Ризикований варіант
    create_backup_dir() {
        mkdir -p -- "$1"
        echo "Каталог створено"
    }

Якщо `mkdir` завершиться помилкою, повідомлення все одно може стверджувати, що каталог створено.

Краще перевірити результат:

    create_backup_dir() {
        if mkdir -p -- "$1"; then
            echo "Каталог готовий"
        else
            echo "Не вдалося створити каталог" >&2
            return 1
        fi
    }

## 16. Функції та `set -euo pipefail`

У Bash-скриптах часто зустрічається суворий режим:

    set -euo pipefail

Він вмикає кілька правил поведінки оболонки:

- `-e` — у багатьох ситуаціях завершує скрипт після команди з ненульовим статусом.
- `-u` — повідомляє про використання неініціалізованих змінних.
- `pipefail` — дозволяє конвеєру повертати ненульовий статус, якщо неуспішною була одна з його команд.

Цей режим може допомагати, але не замінює розуміння статусів команд і явної обробки помилок.

### ✔ Обережне використання у функціях

    #!/usr/bin/env bash

    set -euo pipefail

    show_file() {
        local file=$1

        if [[ -f "$file" ]]; then
            printf 'Файл знайдено: %s\n' "$file"
        else
            printf 'Файл не знайдено: %s\n' "$file" >&2
            return 1
        fi
    }

    if show_file "data.txt"; then
        echo "Перевірка завершена"
    else
        echo "Перевірка не пройдена" >&2
    fi

Тут виклик функції перебуває в умові `if`, тому його ненульовий статус використовується для вибору гілки, а не просто спричиняє автоматичне завершення скрипта через `-e`.

### ✔ Не забувай про `-u`

Якщо функція звертається до необов'язкового параметра, перевіряй його наявність:

    greet() {
        local name=${1:-гість}
        printf 'Привіт, %s!\n' "$name"
    }

    greet
    greet "Alice"

Результат:

    Привіт, гість!
    Привіт, Alice!

`"${1:-гість}"` використовує `гість`, якщо перший аргумент не заданий або порожній.

### ✔ Важливе зауваження

Поведінка `set -e` залежить від контексту: умов, логічних операторів, підстановок команд, функцій та інших конструкцій Bash. Не вважай його універсальним механізмом обробки всіх помилок.

Для надійного скрипта перевіряй критичні операції явно.

## 17. Функції та форматований вивід

Для повідомлень у функціях часто зручніше використовувати `printf`, ніж `echo`.

### ✔ Простий приклад

    print_message() {
        printf 'Повідомлення: %s\n' "$1"
    }

    print_message "Скрипт запущено"

### ✔ Функція для інформаційних повідомлень

    log_info() {
        printf '[INFO] %s\n' "$*"
    }

    log_info "Початок роботи"
    log_info "Перевірка файлів"

Тут `$*` використовується для формування одного текстового повідомлення. Для передачі аргументів як окремих значень використовуй `"$@"`.

### ✔ Функція для помилок

    log_error() {
        printf '[ERROR] %s\n' "$*" >&2
    }

    log_error "Не вдалося відкрити файл"

### ✔ Чому `printf` часто кращий?

- Формат виводу явно заданий.
- `\n` додає новий рядок.
- `%s` виводить значення як рядок.
- Менше неоднозначностей з інтерпретацією спеціальних символів порівняно з різними режимами `echo`.

### ✔ Приклад форматування

    show_user() {
        local name=$1
        local age=$2

        printf 'Ім’я: %s\nВік: %s\n' "$name" "$age"
    }

    show_user "Alice" 25

Результат:

    Ім’я: Alice
    Вік: 25

## 18. Практичний проєкт: калькулятор із функціями

Створимо `calculator.sh`, який приймає операцію та два числа.

### ✔ Код

    #!/usr/bin/env bash

    add() {
        local a=$1
        local b=$2

        printf '%s\n' "$((a + b))"
    }

    subtract() {
        local a=$1
        local b=$2

        printf '%s\n' "$((a - b))"
    }

    multiply() {
        local a=$1
        local b=$2

        printf '%s\n' "$((a * b))"
    }

    usage() {
        echo "Використання: $0 {add|subtract|multiply} NUMBER1 NUMBER2" >&2
    }

    if [[ $# -ne 3 ]]; then
        usage
        exit 1
    fi

    operation=$1
    a=$2
    b=$3

    if [[ ! "$a" =~ ^-?[0-9]+$ || ! "$b" =~ ^-?[0-9]+$ ]]; then
        echo "Помилка: потрібно передати цілі числа" >&2
        exit 1
    fi

    case "$operation" in
        add)
            result=$(add "$a" "$b")
            ;;
        subtract)
            result=$(subtract "$a" "$b")
            ;;
        multiply)
            result=$(multiply "$a" "$b")
            ;;
        *)
            usage
            exit 1
            ;;
    esac

    printf 'Результат: %s\n' "$result"

### ✔ Запуск

    chmod +x calculator.sh

    ./calculator.sh add 10 20
    ./calculator.sh subtract 30 12
    ./calculator.sh multiply 7 8

Результати:

    Результат: 30
    Результат: 18
    Результат: 56

### ✔ Що тут використано?

- Окремі функції для арифметичних операцій.
- Локальні змінні.
- Аргументи функцій.
- `printf` для передачі результату.
- `$(...)` для отримання результату функції.
- `if` для перевірки кількості й формату аргументів.
- `case` для вибору операції.
- `exit 1` для завершення скрипта з помилкою.

Цей калькулятор працює з цілими числами. Bash не призначений для точних обчислень із десятковими дробами, а також має обмеження діапазону цілих чисел.

## 19. Практичний проєкт: перевірка файлів

Створимо `check-files.sh`, який перевіряє декілька файлів.

### ✔ Код

    #!/usr/bin/env bash

    check_file() {
        local file=$1

        if [[ -f "$file" ]]; then
            printf '[OK]      %s\n' "$file"
            return 0
        else
            printf '[MISSING] %s\n' "$file"
            return 1
        fi
    }

    files=("README.md" "package.json" "server.js")

    missing=0

    for file in "${files[@]}"; do
        if ! check_file "$file"; then
            ((missing += 1))
        fi
    done

    echo

    if (( missing == 0 )); then
        echo "Усі файли знайдено"
    else
        echo "Відсутніх файлів: $missing"
        exit 1
    fi

### ✔ Запуск

    chmod +x check-files.sh
    ./check-files.sh

### ✔ Чого навчає цей проєкт?

- Створювати функцію для повторюваної перевірки.
- Передавати шлях до файлу через аргумент.
- Використовувати `local`.
- Повертати статус через `return`.
- Перевіряти статус функції в умові `if`.
- Перебирати масив через `for`.
- Підраховувати помилки.
- Завершувати скрипт із відповідним статусом.

## 21. Поширені помилки

### ✔ Помилка 1. Функцію оголосили, але не викликали

    greet() {
        echo "Привіт!"
    }

Цей код лише оголошує функцію. Щоб вона виконалася, потрібно викликати її:

    greet

### ✔ Помилка 2. Використали `return` для тексту

Неправильно:

    get_message() {
        return "Hello"
    }

Правильно:

    get_message() {
        printf '%s\n' "Hello"
    }

    message=$(get_message)

`return` повертає статус, а текст передається через стандартний вивід.

### ✔ Помилка 3. Забули лапки навколо аргументу

Неправильно:

    show_file() {
        cat $1
    }

Правильно:

    show_file() {
        cat -- "$1"
    }

Лапки зберігають аргумент як єдине значення, навіть якщо шлях містить пробіли. `--` допомагає не трактувати шлях, який починається з дефіса, як опцію команди.

### ✔ Помилка 4. Не використали `local`

    calculate() {
        result=$(( $1 + $2 ))
    }

Змінна `result` може змінити значення глобальної змінної з такою самою назвою.

Краще:

    calculate() {
        local result=$(( $1 + $2 ))
        printf '%s\n' "$result"
    }

### ✔ Помилка 5. Використали `exit` замість `return`

Якщо функція є частиною великого скрипта, `exit 1` може завершити всю програму раніше, ніж потрібно.

Часто краще:

    validate_input() {
        if [[ -z "$1" ]]; then
            echo "Порожнє значення" >&2
            return 1
        fi
    }

Тепер основний код може сам вирішити, як обробити помилку.

### ✔ Помилка 6. Вивели повідомлення разом із результатом

Неправильно для функції, результат якої використовується як дані:

    get_number() {
        echo "Обчислюю..."
        echo 42
    }

    result=$(get_number)

Змінна `result` міститиме обидва рядки.

Якщо потрібен лише результат, діагностику направляй до `stderr`:

    get_number() {
        echo "Обчислюю..." >&2
        printf '%s\n' 42
    }

### ✔ Помилка 7. Не перевірили аргументи

    divide() {
        local a=$1
        local b=$2
    }

Якщо аргументів недостатньо, функція може працювати неправильно або отримати порожні значення.

Краще перевіряти кількість аргументів:

    divide() {
        if [[ $# -ne 2 ]]; then
            echo "Потрібно два аргументи" >&2
            return 1
        fi

        local a=$1
        local b=$2
    }

### ✔ Помилка 8. Переплутали аргументи функції й скрипта

Позиційні параметри функції під час її виконання посилаються на аргументи, передані цій функції.

    greet() {
        echo "$1"
    }

    greet "Alice"

У цьому прикладі `$1` усередині `greet` — це `Alice`, а не перший аргумент скрипта.

### ✔ Помилка 9. Використали `"$@"` без лапок

Правильно:

    process_arguments() {
        for argument in "$@"; do
            printf '%s\n' "$argument"
        done
    }

Лапки зберігають окремі аргументи. Без них аргументи з пробілами можуть розбиватися на декілька значень.

### ✔ Помилка 10. Не перевірили статус функції

    check_file "data.txt"
    echo "Файл готовий"

Повідомлення буде виведене незалежно від того, чи існує файл, якщо функція не завершує весь скрипт.

Краще:

    if check_file "data.txt"; then
        echo "Файл готовий"
    else
        echo "Файл не пройшов перевірку"
    fi

## 22. Як налагоджувати функції

### ✔ Перевірка синтаксису

    bash -n script.sh

Перевіряє синтаксис без звичайного виконання скрипта.

### ✔ Трасування команд

    bash -x script.sh

Показує команди, які виконуються, та їхні розгорнуті значення.

### ✔ Виведення аргументів

    debug_arguments() {
        printf 'Кількість аргументів: %s\n' "$#"

        for argument in "$@"; do
            printf 'Аргумент: <%s>\n' "$argument"
        done
    }

    debug_arguments "Hello world" "Linux" ""

Цей приклад допомагає побачити межі аргументів, зокрема порожній третій аргумент.

### ✔ Перевірка коду через ShellCheck

    shellcheck script.sh

ShellCheck знаходить багато поширених проблем Bash-коду, зокрема помилки з лапками, змінними та умовами.

## 25. Що потрібно пам'ятати

- Функція — це іменований блок команд, який можна викликати повторно.
- Форма `name() { ...; }` — зручний стандартний стиль оголошення функцій Bash.
- Оголошення функції не запускає її автоматично.
- Функцію викликають за назвою: `name`.
- `$1`, `$2` та інші позиційні параметри всередині функції відповідають її аргументам.
- `$#` — кількість аргументів функції.
- `"$@"` — усі аргументи окремо зі збереженням меж.
- `local` створює локальну змінну функції.
- `return 0` зазвичай означає успіх.
- `return 1` зазвичай означає помилку або невдалу перевірку.
- `return` завершує функцію, а `exit` — весь скрипт.
- `$(function_name)` отримує стандартний вивід функції.
- Для числового статусу використовуй `return`.
- Для текстового результату використовуй `printf` або інший вивід.
- `$?` потрібно перевіряти одразу після команди, статус якої важливий.
- Повідомлення про помилки зручно направляти до `stderr` через `>&2`.
- Перевіряй кількість і формат аргументів.
- Використовуй лапки навколо змінних, які містять шляхи або аргументи.
- `source` підключає код іншого файла в поточну оболонку.
- `BASH_SOURCE[0]` допомагає визначити шлях до файла, у якому виконується код.
- `set -euo pipefail` може підвищити строгість скрипта, але не замінює явну перевірку помилок.
- `bash -n script.sh` перевіряє синтаксис.
- `bash -x script.sh` допомагає відстежувати виконання.
- `shellcheck script.sh` допомагає виявляти типові помилки.

## 26. Міні-шпаргалка

    # Оголошення функції
    say_hello() {
        echo "Привіт!"
    }

    # Виклик функції
    say_hello

    # Функція з аргументом
    greet() {
        printf 'Привіт, %s!\n' "$1"
    }

    greet "Alice"

    # Локальні змінні
    calculate() {
        local a=$1
        local b=$2
        local result=$((a + b))

        printf '%s\n' "$result"
    }

    calculate 10 20

    # Кількість аргументів
    show_count() {
        echo "$#"
    }

    show_count one two three

    # Перебір аргументів
    show_arguments() {
        for argument in "$@"; do
            printf '%s\n' "$argument"
        done
    }

    show_arguments "Hello world" Linux

    # Повернення статусу
    check_file() {
        [[ -f "$1" ]]
    }

    if check_file "data.txt"; then
        echo "Файл існує"
    else
        echo "Файл відсутній"
    fi

    # Повернення текстового результату
    get_sum() {
        printf '%s\n' "$(($1 + $2))"
    }

    result=$(get_sum 10 20)
    echo "$result"

    # Обробка помилки
    validate() {
        if [[ $# -ne 1 ]]; then
            echo "Потрібен один аргумент" >&2
            return 1
        fi

        return 0
    }

    if validate "value"; then
        echo "Аргументи правильні"
    fi

    # Повідомлення про помилку
    log_error() {
        printf '[ERROR] %s\n' "$*" >&2
    }

    log_error "Не вдалося відкрити файл"

    # Підключення функцій з іншого файла
    SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
    source "$SCRIPT_DIR/functions.sh"

    # Перевірка синтаксису
    bash -n script.sh

    # Трасування
    bash -x script.sh

    # ShellCheck
    shellcheck script.sh

## 27. Підсумок

Функції допомагають організовувати Bash-скрипти, повторно використовувати код і відокремлювати логіку на невеликі частини.

Після опанування цієї теми ти маєш уміти:

- оголошувати та викликати функції;
- передавати аргументи й працювати з `"$@"`;
- використовувати `local` для локальних змінних;
- перевіряти кількість і формат аргументів;
- повертати статус виконання через `return`;
- передавати текстові результати через стандартний вивід;
- обробляти помилки через статуси команд і функцій;
- розділяти інформаційні повідомлення та помилки;
- підключати спільні функції через `source`;
- створювати модульні Bash-скрипти;
- налагоджувати функції за допомогою `bash -x` і ShellCheck.

**Головне правило:** функція повинна виконувати одну зрозумілу задачу, отримувати потрібні дані через аргументи, використовувати локальні змінні там, де це доречно, і мати передбачуваний спосіб повідомлення про результат — через статус, текстовий вивід або обидва механізми.

Наступна тема: `06-arrays` — масиви Bash, індекси, перебір елементів, додавання значень і передавання масивів у функції.
