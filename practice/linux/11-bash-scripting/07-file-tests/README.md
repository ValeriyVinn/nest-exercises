# Bash Scripting — 07. File Tests

Перевірки файлів (`file tests`) у Bash — це умовні вирази, які дозволяють перевіряти існування файлів і каталогів, їхній тип, права доступу, розмір та інші властивості.

Вони використовуються в автоматизації, резервному копіюванні, перевірці конфігурацій, обробці даних і створенні надійних Bash-скриптів.

Наприклад, перед читанням конфігураційного файлу скрипт може перевірити, чи існує цей файл:

    #!/usr/bin/env bash

    config="config.txt"

    if [[ -f "$config" ]]; then
        echo "Файл існує"
    else
        echo "Файл не знайдено"
    fi

## 1. Основи перевірки файлів

### 1.1. Що таке file tests

File tests — це перевірки, які виконуються за допомогою умовних операторів Bash.

Основний синтаксис:

    [[ умова ]]

Приклад:

    if [[ -f "config.txt" ]]; then
        echo "Це звичайний файл"
    fi

Тут:

- `[[ ... ]]` — конструкція умовної перевірки Bash.
- `-f` — перевіряє, чи існує шлях і чи вказує він на звичайний файл.
- `"config.txt"` — шлях, який перевіряється.
- `if` — виконує блок команд, якщо умова істинна.

### 1.2. Де використовуються file tests

Перевірки файлів потрібні, коли скрипт повинен:

- перевірити наявність конфігурації;
- переконатися, що каталог існує;
- перевірити, чи можна прочитати файл;
- не перезаписати важливі дані випадково;
- перевірити, чи файл порожній;
- знайти файли певного типу;
- перевірити, чи існує виконуваний файл;
- визначити, чи потрібно створювати каталог;
- перевірити результати попередньої команди.

### 1.3. `[[ ... ]]` і `[ ... ]`

У Bash існують дві поширені форми умовних перевірок.

Сучасний рекомендований варіант:

    if [[ -f "$file" ]]; then
        echo "Файл існує"
    fi

Сумісний із багатьма POSIX-оболонками варіант:

    if [ -f "$file" ]; then
        echo "Файл існує"
    fi

Для Bash-скриптів зазвичай зручніше використовувати `[[ ... ]]`.

Переваги `[[ ... ]]`:

- менше проблем із розбиттям слів;
- немає звичайного розкриття шаблонів файлів усередині виразу;
- підтримує логічні оператори `&&` та `||`;
- дозволяє зручніше працювати з умовами Bash.

Важливо: `[[ ... ]]` — це конструкція Bash, а не зовнішня команда.

## 2. Перевірка існування шляху

### 2.1. Перевірка `-e`

Оператор `-e` перевіряє, чи існує шлях.

    path="config.txt"

    if [[ -e "$path" ]]; then
        echo "Шлях існує"
    else
        echo "Шлях не існує"
    fi

Він підходить як для файлів, так і для каталогів та інших типів файлових об'єктів.

Приклад із каталогом:

    if [[ -e "/home" ]]; then
        echo "Шлях існує"
    fi

### 2.2. Перевірка `-f`

Оператор `-f` перевіряє, чи існує звичайний файл.

    file="script.sh"

    if [[ -f "$file" ]]; then
        echo "Звичайний файл існує"
    else
        echo "Звичайного файлу немає"
    fi

Це один із найчастіше використовуваних file tests.

Він підходить для перевірки:

- текстових файлів;
- конфігурацій;
- скриптів;
- JSON-файлів;
- файлів із даними;
- інших звичайних файлів.

`-f` також повертає істину для символічного посилання, яке веде до звичайного файлу.

### 2.3. Перевірка `-d`

Оператор `-d` перевіряє, чи існує каталог.

    directory="logs"

    if [[ -d "$directory" ]]; then
        echo "Каталог існує"
    else
        echo "Каталогу немає"
    fi

Це корисно перед створенням файлів у певному каталозі.

Приклад:

    directory="logs"

    if [[ ! -d "$directory" ]]; then
        mkdir -p "$directory"
    fi

Команда `mkdir -p` створює каталог, якщо його немає, і не завершується помилкою лише через те, що каталог уже існує.

### 2.4. Різниця між `-e`, `-f` і `-d`

| Перевірка | Значення |
|---|---|
| `-e path` | Шлях існує |
| `-f path` | Шлях веде до звичайного файлу |
| `-d path` | Шлях веде до каталогу |

Приклад:

    path="."

    [[ -e "$path" ]] && echo "Шлях існує"
    [[ -f "$path" ]] && echo "Це звичайний файл"
    [[ -d "$path" ]] && echo "Це каталог"

Для поточного каталогу `.` результатом буде повідомлення `Шлях існує` і `Це каталог`.

### 2.5. Символічні посилання та `-L`

Оператор `-L` перевіряє, чи є шлях символічним посиланням.

    path="current"

    if [[ -L "$path" ]]; then
        echo "Це символічне посилання"
    fi

Припустимо, створено посилання:

    ln -s /tmp/example.txt current

Тепер:

    [[ -L "current" ]] && echo "Символічне посилання"
    [[ -f "current" ]] && echo "Посилання веде до звичайного файлу"

Якщо ціль посилання існує і є звичайним файлом, обидві перевірки можуть повернути істину.

Якщо ціль видалити, саме символічне посилання може залишитися:

    [[ -L "current" ]] && echo "Посилання існує"
    [[ -e "current" ]] || echo "Ціль не існує"

Це важлива відмінність між перевіркою самого посилання та перевіркою доступного шляху до його цілі.

## 3. Перевірка типів файлових об'єктів

### 3.1. Звичайний файл — `-f`

    if [[ -f "$path" ]]; then
        echo "Звичайний файл"
    fi

Звичайний файл може містити текст, зображення, програму, архів або інші дані.

Перевірка `-f` не визначає формат чи вміст файлу. Вона перевіряє лише тип файлового об'єкта.

### 3.2. Каталог — `-d`

    if [[ -d "$path" ]]; then
        echo "Каталог"
    fi

Каталог містить записи про інші файлові об'єкти.

### 3.3. Символічне посилання — `-L`

    if [[ -L "$path" ]]; then
        echo "Символічне посилання"
    fi

Символічне посилання містить шлях до іншого об'єкта.

Воно може бути справним або вказувати на неіснуючу ціль.

### 3.4. Іменований канал — `-p`

Оператор `-p` перевіряє, чи є об'єкт іменованим каналом (`FIFO`).

    if [[ -p "$path" ]]; then
        echo "Іменований канал"
    fi

FIFO використовується для обміну даними між процесами.

Для звичайних навчальних скриптів ця перевірка потрібна нечасто, але вона може бути корисною в системній автоматизації.

### 3.5. Блоковий пристрій — `-b`

Оператор `-b` перевіряє, чи є об'єкт блоковим пристроєм.

    if [[ -b "$path" ]]; then
        echo "Блоковий пристрій"
    fi

Блокові пристрої забезпечують доступ до даних блоками. Прикладами можуть бути диски та їхні розділи.

Працюючи з пристроями, не виконуй операції запису або форматування без чіткого розуміння їхніх наслідків.

### 3.6. Символьний пристрій — `-c`

Оператор `-c` перевіряє, чи є об'єкт символьним пристроєм.

    if [[ -c "$path" ]]; then
        echo "Символьний пристрій"
    fi

Приклади пристроїв цього типу в Linux — деякі термінальні та системні пристрої.

### 3.7. Сокет — `-S`

Оператор `-S` перевіряє, чи є об'єкт Unix domain socket.

    if [[ -S "$path" ]]; then
        echo "Unix-сокет"
    fi

Unix-сокети використовуються для локального обміну даними між процесами.

### 3.8. Коротка таблиця типів

| Оператор | Тип об'єкта |
|---|---|
| `-e` | Шлях існує |
| `-f` | Звичайний файл |
| `-d` | Каталог |
| `-L` | Символічне посилання |
| `-p` | Іменований канал (FIFO) |
| `-b` | Блоковий пристрій |
| `-c` | Символьний пристрій |
| `-S` | Unix-сокет |

## 4. Перевірка прав доступу

### 4.1. Читання — `-r`

Оператор `-r` перевіряє, чи доступний шлях для читання поточному користувачу.

    file="config.txt"

    if [[ -r "$file" ]]; then
        echo "Файл доступний для читання"
    else
        echo "Файл недоступний для читання"
    fi

Це корисно перед спробою прочитати конфігурацію або файл даних.

Важливо: перевірка доступу не гарантує, що наступна операція обов'язково завершиться успішно. Стан файлової системи або права доступу можуть змінитися між перевіркою та використанням файлу.

### 4.2. Запис — `-w`

Оператор `-w` перевіряє, чи доступний шлях для запису поточному користувачу.

    file="output.txt"

    if [[ -w "$file" ]]; then
        echo "Можна записувати"
    else
        echo "Немає доступу для запису"
    fi

Якщо файл не існує, `-w` не перевіряє, чи можна створити його в батьківському каталозі.

Для нового файлу важливо перевіряти права на каталог, у якому він створюватиметься.

### 4.3. Виконання — `-x`

Оператор `-x` перевіряє, чи має поточний користувач право виконання або проходу для відповідного типу файлового об'єкта.

Для файлу:

    script="backup.sh"

    if [[ -x "$script" ]]; then
        echo "Файл має право виконання"
    else
        echo "Файл не має права виконання"
    fi

Для каталогу право виконання означає можливість проходу через нього за відповідних умов доступу.

Перевірка `-x` не означає, що файл обов'язково є коректним виконуваним скриптом.

### 4.4. Інші перевірки доступу

Оператор `-O` перевіряє, чи належить файл поточному користувачу за його ефективним UID.

    if [[ -O "$file" ]]; then
        echo "Файл належить ефективному користувачу"
    fi

Оператор `-G` перевіряє, чи належить файл групі ефективного GID процесу.

    if [[ -G "$file" ]]; then
        echo "Файл належить ефективній групі"
    fi

Ці перевірки можуть бути корисними для системних скриптів, але для більшості початкових завдань достатньо `-r`, `-w` і `-x`.

### 4.5. Таблиця перевірок доступу

| Оператор | Значення |
|---|---|
| `-r` | Доступний для читання |
| `-w` | Доступний для запису |
| `-x` | Доступний для виконання або проходу |
| `-O` | Належить ефективному користувачу |
| `-G` | Належить ефективній групі |

## 5. Перевірка розміру файлу

### 5.1. Перевірка `-s`

Оператор `-s` перевіряє, чи існує шлях і чи має об'єкт ненульовий розмір.

    file="data.txt"

    if [[ -s "$file" ]]; then
        echo "Файл має ненульовий розмір"
    else
        echo "Файл порожній або шлях недоступний"
    fi

Для звичайного файлу це зручний спосіб перевірити, чи містить він хоча б один байт.

Зверни увагу: результат `false` не обов'язково означає, що файл існує й порожній. Шлях може не існувати або бути недоступним.

### 5.2. Різниця між `-e` та `-s`

    file="data.txt"

    if [[ -e "$file" ]]; then
        echo "Шлях існує"
    fi

    if [[ -s "$file" ]]; then
        echo "Шлях має ненульовий розмір"
    fi

Можливі ситуації:

- файл існує та містить дані — обидві перевірки істинні;
- файл існує, але має нульовий розмір — `-e` істинна, `-s` хибна;
- файл не існує — обидві перевірки хибні.

### 5.3. Перевірка порожнього файлу

    file="data.txt"

    if [[ -f "$file" && ! -s "$file" ]]; then
        echo "Файл існує та має нульовий розмір"
    fi

Тут:

- `-f` перевіряє, що шлях веде до звичайного файлу;
- `!` заперечує результат наступної умови;
- `-s` перевіряє ненульовий розмір;
- `&&` вимагає, щоб обидві умови були істинними.

## 6. Логічні оператори у file tests

### 6.1. Оператор `!`

Оператор `!` заперечує умову.

    if [[ ! -e "$file" ]]; then
        echo "Шлях не існує"
    fi

Це один із найпоширеніших способів перевірити відсутність файлу або каталогу.

### 6.2. Оператор `&&`

`&&` означає логічне «І»: обидві умови мають бути істинними.

    if [[ -f "$file" && -r "$file" ]]; then
        echo "Файл існує та доступний для читання"
    fi

Такий запис підходить для перевірки декількох властивостей одного шляху.

### 6.3. Оператор `||`

`||` означає логічне «АБО»: достатньо, щоб істинною була хоча б одна умова.

    if [[ -f "$file" || -d "$file" ]]; then
        echo "Шлях веде до файлу або каталогу"
    fi

### 6.4. Комбінація умов

    if [[ -f "$file" && -r "$file" && -s "$file" ]]; then
        echo "Файл існує, доступний для читання та не порожній"
    else
        echo "Файл не відповідає всім умовам"
    fi

Цей приклад перевіряє три властивості:

1. Звичайний файл.
2. Доступність для читання.
3. Ненульовий розмір.

### 6.5. Групування умов

    if [[ ( -f "$file" && -r "$file" ) || -d "$file" ]]; then
        echo "Файл доступний для читання або шлях є каталогом"
    fi

Дужки дозволяють явно визначити порядок групування умов усередині `[[ ... ]]`.

## 7. Порівняння файлів

### 7.1. Оператор `-ef`

Оператор `-ef` перевіряє, чи вказують два шляхи на той самий файловий об'єкт.

Зазвичай це означає, що обидва шляхи мають однакові номер пристрою та inode.

    if [[ "file1.txt" -ef "file2.txt" ]]; then
        echo "Обидва шляхи вказують на той самий об'єкт"
    else
        echo "Це різні файлові об'єкти"
    fi

Наприклад, два шляхи можуть вказувати на той самий файл через жорстке посилання або символічне посилання.

### 7.2. Перевірка, чи один файл новіший за інший

Оператор `-nt` перевіряє, чи перший файл новіший за другий за часом модифікації.

    if [[ "source.txt" -nt "backup.txt" ]]; then
        echo "Джерело новіше за резервну копію"
    fi

Це може бути корисно для простих сценаріїв резервного копіювання.

### 7.3. Перевірка, чи один файл старіший за інший

Оператор `-ot` перевіряє, чи перший файл старіший за другий.

    if [[ "source.txt" -ot "backup.txt" ]]; then
        echo "Джерело старіше за резервну копію"
    fi

### 7.4. Порівняння часу модифікації

Приклад:

    source="source.txt"
    backup="backup.txt"

    if [[ ! -e "$backup" ]]; then
        echo "Резервної копії немає"
    elif [[ "$source" -nt "$backup" ]]; then
        echo "Потрібно оновити резервну копію"
    else
        echo "Резервна копія не старіша за джерело"
    fi

Це базова логіка. У реальних сценаріях резервного копіювання також потрібно враховувати помилки копіювання, права доступу та зміни файлів під час операції.

## 8. Робота з файлами за допомогою `if`

### 8.1. Перевірка конфігураційного файлу

    #!/usr/bin/env bash

    config="config.txt"

    if [[ -f "$config" ]]; then
        echo "Конфігурацію знайдено"
    else
        echo "Помилка: конфігураційний файл відсутній"
        exit 1
    fi

`exit 1` завершує скрипт із ненульовим кодом, який зазвичай означає помилку.

### 8.2. Створення файлу, якщо його немає

    #!/usr/bin/env bash

    file="output.txt"

    if [[ ! -e "$file" ]]; then
        touch "$file"
        echo "Файл створено"
    else
        echo "Файл уже існує"
    fi

`touch` створює порожній файл, якщо його немає. Якщо файл уже існує, команда зазвичай оновлює його час доступу та модифікації відповідно до параметрів і системних правил.

Увага: перевірка перед створенням не є захистом від одночасної роботи декількох процесів. Між перевіркою та створенням стан може змінитися.

### 8.3. Перевірка каталогу перед записом

    #!/usr/bin/env bash

    output_dir="reports"

    if [[ ! -d "$output_dir" ]]; then
        mkdir -p "$output_dir" || {
            echo "Не вдалося створити каталог" >&2
            exit 1
        }
    fi

    printf 'Звіт створено\n' > "$output_dir/report.txt"

Останній рядок записує текст у файл. Якщо файл уже існує, оператор `>` перезапише його вміст.

Щоб додавати текст наприкінці файлу, використовуй `>>`:

    printf 'Новий запис\n' >> "$output_dir/report.txt"

### 8.4. Перевірка перед читанням

    #!/usr/bin/env bash

    file="data.txt"

    if [[ -f "$file" && -r "$file" ]]; then
        cat -- "$file"
    else
        echo "Файл не існує або недоступний для читання" >&2
        exit 1
    fi

Параметр `--` завершує обробку параметрів команди. Це допомагає уникнути трактування імені файлу, яке починається з дефіса, як параметра команди.

Проте перевірка та подальше читання — це дві окремі операції. У критичних сценаріях краще обробляти помилку безпосередньо під час читання.

## 9. Перевірки файлів у циклах

### 9.1. Перевірка списку файлів

    #!/usr/bin/env bash

    files=("config.txt" "data.txt" "output.txt")

    for file in "${files[@]}"; do
        if [[ -f "$file" ]]; then
            printf 'Знайдено: %s\n' "$file"
        else
            printf 'Відсутній: %s\n' "$file"
        fi
    done

`"${files[@]}"` передає кожен елемент масиву окремо, навіть якщо шлях містить пробіли.

### 9.2. Перевірка каталогів

    #!/usr/bin/env bash

    directories=(
        "$HOME/projects"
        "$HOME/Documents"
        "$HOME/Downloads"
    )

    for directory in "${directories[@]}"; do
        if [[ -d "$directory" ]]; then
            printf 'Каталог існує: %s\n' "$directory"
        else
            printf 'Каталог відсутній: %s\n' "$directory"
        fi
    done

### 9.3. Перевірка прав доступу

    #!/usr/bin/env bash

    files=("script.sh" "config.txt" "data.txt")

    for file in "${files[@]}"; do
        if [[ -f "$file" && -r "$file" ]]; then
            printf 'Можна читати: %s\n' "$file"
        else
            printf 'Немає звичайного доступного для читання файлу: %s\n' "$file"
        fi
    done

### 9.4. Пошук порожніх файлів

    #!/usr/bin/env bash

    for file in ./*.txt; do
        [[ -f "$file" ]] || continue

        if [[ ! -s "$file" ]]; then
            printf 'Порожній файл: %s\n' "$file"
        fi
    done

Тут:

- `./*.txt` — шаблон імен файлів;
- `[[ -f "$file" ]]` — перевірка звичайного файлу;
- `|| continue` — пропуск поточної ітерації, якщо перевірка не пройшла;
- `! -s` — перевірка нульового розміру.

Перевірка `-f` також не дозволяє обробляти нерозкритий шаблон як звичайний файл, якщо відповідних `.txt` немає.

## 10. Перевірка шляху та безпечне використання

### 10.1. Чому потрібні подвійні лапки

Правильно:

    file="my report.txt"

    if [[ -f "$file" ]]; then
        echo "Файл існує"
    fi

Не рекомендується:

    if [[ -f $file ]]; then
        echo "Файл існує"
    fi

Усередині `[[ ... ]]` Bash захищає від звичайного розбиття слів і розкриття шаблонів, але подвійні лапки все одно роблять намір явним і забезпечують кращу звичку для подальшого використання змінних у командах.

### 10.2. Імена, що починаються з дефіса

Якщо шлях передається зовнішній команді, наприклад `cat`, ім'я файлу на кшталт `-data.txt` може бути сприйняте як параметр.

Використовуй `--`, коли команда його підтримує:

    cat -- "$file"

Для перевірок у `[[ ... ]]` ім'я є значенням виразу, а не параметром зовнішньої команди:

    if [[ -f "$file" ]]; then
        echo "Файл існує"
    fi

### 10.3. Перевірка не гарантує успішної операції

Такий код:

    if [[ -r "$file" ]]; then
        cat -- "$file"
    fi

не гарантує, що `cat` обов'язково завершиться успішно. Наприклад, файл може бути видалений або права доступу можуть змінитися після перевірки.

Для важливих операцій перевіряй код завершення самої команди:

    if cat -- "$file"; then
        echo "Читання завершено успішно"
    else
        echo "Помилка читання" >&2
        exit 1
    fi

### 10.4. Символічні посилання

Перевірка `-e` зазвичай повертає істину, якщо ціль символічного посилання існує.

Перевірка `-L` дозволяє визначити, чи є сам шлях символічним посиланням, навіть якщо ціль відсутня.

    path="current"

    if [[ -L "$path" ]]; then
        echo "Шлях є символічним посиланням"
    fi

    if [[ ! -e "$path" ]]; then
        echo "Ціль не існує або шлях недоступний"
    fi

## 11. Практичні приклади

### 11.1. Скрипт перевірки файлу

    #!/usr/bin/env bash

    set -u

    file="${1:-}"

    if [[ -z "$file" ]]; then
        echo "Використання: $0 <шлях-до-файлу>" >&2
        exit 2
    fi

    if [[ -f "$file" ]]; then
        printf 'Файл знайдено: %s\n' "$file"
    else
        printf 'Звичайний файл не знайдено: %s\n' "$file" >&2
        exit 1
    fi

Запуск:

    bash check-file.sh config.txt

Скрипт:

1. Отримує шлях із першого аргументу.
2. Перевіряє, чи передано аргумент.
3. Перевіряє, чи існує звичайний файл.
4. Виводить повідомлення та відповідний код завершення.

### 11.2. Скрипт перевірки каталогу

    #!/usr/bin/env bash

    directory="${1:-}"

    if [[ -z "$directory" ]]; then
        echo "Використання: $0 <каталог>" >&2
        exit 2
    fi

    if [[ -d "$directory" ]]; then
        printf 'Каталог існує: %s\n' "$directory"
    else
        printf 'Каталог не знайдено: %s\n' "$directory" >&2
        exit 1
    fi

### 11.3. Перевірка конфігурації та створення каталогу логів

    #!/usr/bin/env bash

    set -u

    config="config.txt"
    log_dir="logs"
    log_file="$log_dir/app.log"

    if [[ ! -f "$config" ]]; then
        echo "Помилка: немає конфігураційного файлу" >&2
        exit 1
    fi

    if [[ ! -r "$config" ]]; then
        echo "Помилка: конфігурація недоступна для читання" >&2
        exit 1
    fi

    if ! mkdir -p "$log_dir"; then
        echo "Помилка: не вдалося створити каталог логів" >&2
        exit 1
    fi

    if ! printf 'Скрипт запущено\n' >> "$log_file"; then
        echo "Помилка: не вдалося записати лог" >&2
        exit 1
    fi

    echo "Перевірки завершено"

Цей приклад поєднує перевірки файлів, умовні оператори, створення каталогу та перевірку успішності запису.

### 11.4. Перевірка доступності скрипту для виконання

    #!/usr/bin/env bash

    script="${1:-}"

    if [[ -z "$script" ]]; then
        echo "Використання: $0 <скрипт>" >&2
        exit 2
    fi

    if [[ ! -f "$script" ]]; then
        echo "Звичайний файл не знайдено" >&2
        exit 1
    fi

    if [[ -x "$script" ]]; then
        echo "Файл має право виконання"
    else
        echo "Файл не має права виконання"
        echo "За потреби: chmod +x \"$script\""
    fi

Ця перевірка не гарантує, що скрипт запуститься успішно. Вона лише перевіряє право виконання для поточного користувача.

### 11.5. Перевірка файлів перед резервним копіюванням

    #!/usr/bin/env bash

    source_dir="documents"
    backup_dir="backup"

    if [[ ! -d "$source_dir" ]]; then
        echo "Помилка: вихідний каталог відсутній" >&2
        exit 1
    fi

    if ! mkdir -p "$backup_dir"; then
        echo "Помилка створення каталогу резервних копій" >&2
        exit 1
    fi

    for file in "$source_dir"/*; do
        [[ -f "$file" ]] || continue

        if cp -- "$file" "$backup_dir/"; then
            printf 'Скопійовано: %s\n' "$file"
        else
            printf 'Помилка копіювання: %s\n' "$file" >&2
        fi
    done

Цей приклад копіює звичайні файли з каталогу `documents` до каталогу `backup`.

Він не обробляє рекурсивно вкладені каталоги та не копіює символічні посилання як окремі посилання. Для складнішого резервного копіювання варто розглянути спеціалізовані інструменти, наприклад `rsync`.

## 12. Типові помилки

### Помилка 1. Перевіряють `-f`, коли потрібен каталог

Неправильно:

    if [[ -f "$directory" ]]; then
        echo "Каталог існує"
    fi

Правильно:

    if [[ -d "$directory" ]]; then
        echo "Каталог існує"
    fi

### Помилка 2. Плутають існування шляху та ненульовий розмір

    if [[ -s "$file" ]]; then
        echo "Файл існує"
    fi

Проблема: `-s` перевіряє ненульовий розмір, а не лише існування.

Якщо потрібно перевірити існування:

    [[ -e "$file" ]]

Якщо потрібен звичайний файл:

    [[ -f "$file" ]]

### Помилка 3. Перевіряють лише існування перед читанням

    if [[ -e "$file" ]]; then
        cat -- "$file"
    fi

Проблема: шлях може існувати, але вказувати на каталог або бути недоступним для читання.

Для звичайного файлу доречніше:

    if [[ -f "$file" && -r "$file" ]]; then
        cat -- "$file"
    fi

Для надійної обробки також перевіряй код завершення команди читання.

### Помилка 4. Не використовують лапки

Небажано:

    if [[ -f $file ]]; then
        echo "Файл існує"
    fi

Рекомендовано:

    if [[ -f "$file" ]]; then
        echo "Файл існує"
    fi

### Помилка 5. Вважають, що `-x` гарантує запуск

    if [[ -x "$script" ]]; then
        "$script"
    fi

Проблема: право виконання не гарантує успішного запуску. Можуть бути помилки інтерпретатора, формату файлу, залежностей або середовища.

Правильніше перевіряти також результат виконання:

    if "$script"; then
        echo "Скрипт завершився успішно"
    else
        echo "Помилка виконання скрипту" >&2
    fi

Виконуй лише скрипти, яким довіряєш.

### Помилка 6. Вважають, що `-e` завжди означає, що ціль посилання існує

Символічне посилання може залишитися після видалення цілі.

    [[ -L "$path" ]] && echo "Це символічне посилання"
    [[ -e "$path" ]] || echo "Ціль не існує або шлях недоступний"

### Помилка 7. Не перевіряють результат створення каталогу

Небажано:

    mkdir -p "$directory"
    echo "Каталог створено"

Команда може завершитися помилкою, але повідомлення все одно буде виведене.

Краще:

    if mkdir -p "$directory"; then
        echo "Каталог доступний"
    else
        echo "Не вдалося створити каталог" >&2
        exit 1
    fi

## 13. Налагодження Bash-скриптів

### 13.1. Перевірка синтаксису

    bash -n script.sh

Команда перевіряє синтаксис скрипту без його виконання.

### 13.2. Трасування виконання

    bash -x script.sh

Параметр `-x` виводить команди під час виконання та допомагає побачити, які значення отримують змінні.

### 13.3. Перевірка коду завершення

Після команди можна переглянути `$?`:

    [[ -f "config.txt" ]]

    echo "$?"

Результат:

- `0` — умова істинна;
- ненульове значення — умова хибна.

Для умовних конструкцій зазвичай зручніше використовувати `if`, а не окремо читати `$?`.

    if [[ -f "config.txt" ]]; then
        echo "Файл існує"
    else
        echo "Файл відсутній"
    fi

### 13.4. Перевірка стилю

    shellcheck script.sh

ShellCheck допомагає виявляти типові помилки та покращувати якість Bash-скриптів.

## 14. Практичні завдання

### Завдання 1. Перевірка файлу

Створи `check-file.sh`, який отримує шлях до файлу як аргумент.

Скрипт повинен:

- перевірити, чи передано аргумент;
- перевірити, чи існує звичайний файл;
- вивести результат;
- повертати ненульовий код, якщо файл не знайдено.

### Завдання 2. Перевірка каталогу

Створи `check-directory.sh`.

Скрипт отримує шлях до каталогу та повідомляє, чи існує він.

### Завдання 3. Створення каталогу

Напиши скрипт, який перевіряє каталог `logs`.

Якщо каталогу немає, скрипт повинен створити його за допомогою `mkdir -p`.

Оброби помилку створення.

### Завдання 4. Перевірка порожнього файлу

Створи скрипт, який розрізняє такі ситуації:

- файл не існує;
- шлях веде до звичайного файлу нульового розміру;
- файл містить дані;
- шлях не веде до звичайного файлу.

### Завдання 5. Перевірка доступу

Напиши скрипт, який перевіряє для заданого файлу:

- існування;
- доступність для читання;
- доступність для запису;
- право виконання.

Виведи окреме повідомлення для кожної перевірки.

### Завдання 6. Перевірка конфігурації

Створи скрипт, який перевіряє наявність `config.txt` та доступність для читання.

Якщо перевірка не пройшла, заверши скрипт із кодом `1`.

### Завдання 7. Список файлів

Створи масив із п'яти імен файлів.

За допомогою циклу `for` перевір, які файли існують.

### Завдання 8. Пошук порожніх файлів

Напиши скрипт, який знаходить порожні файли `.txt` у поточному каталозі.

Використай шаблон `./*.txt` і перевірку `-s`.

### Завдання 9. Перевірка символічного посилання

Створи символічне посилання на файл.

Перевір його за допомогою `-L`, `-e` та `-f`.

Потім видали ціль і повтори перевірки.

Поясни, чому результати відрізняються.

### Завдання 10. Перевірка перед копіюванням

Створи скрипт, який:

- перевіряє існування вихідного каталогу;
- створює каталог резервних копій;
- копіює звичайні файли;
- повідомляє про помилки копіювання.

✔ `[[ -r "$file" ]]` — файл доступний для читання.

✔ `[[ -w "$file" ]]` — файл доступний для запису.

✔ `[[ -x "$file" ]]` — шлях доступний для виконання або проходу відповідно до його типу.

✔ `[[ -s "$file" ]]` — шлях існує та має ненульовий розмір.

✔ `[[ "$file1" -ef "$file2" ]]` — обидва шляхи вказують на той самий файловий об'єкт.

✔ `[[ "$file1" -nt "$file2" ]]` — перший файл новіший за другий.

✔ `[[ "$file1" -ot "$file2" ]]` — перший файл старіший за другий.

✔ `!` заперечує умову.

✔ `&&` вимагає істинності обох умов.

✔ `||` дозволяє виконання, якщо істинна хоча б одна умова.

✔ Для шляхів у змінних використовуй подвійні лапки.

✔ Перевіряй код завершення важливих команд, а не лише попередні умови.

## 18. Підсумок

Перевірки файлів — одна з основ надійного Bash-скриптингу. Вони допомагають перевіряти вхідні дані, контролювати доступ до файлів і каталогів, запобігати типовим помилкам та правильно обробляти результати команд.

Для впевненої роботи потрібно вміти:

- перевіряти існування файлів і каталогів;
- розрізняти звичайні файли, каталоги та символічні посилання;
- перевіряти права доступу й розмір файлу;
- комбінувати умови за допомогою `!`, `&&` і `||`;
- перевіряти файлові об'єкти в циклах;
- обробляти помилки створення, читання та копіювання;
- враховувати, що стан файлової системи може змінитися після перевірки.

Головне правило: **використовуй відповідний file test для потрібної властивості, бери шляхи в подвійні лапки та перевіряй результат самої операції, якщо її успіх важливий.**
