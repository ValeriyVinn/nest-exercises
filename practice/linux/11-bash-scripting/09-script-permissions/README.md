# 09. Права доступу до Bash-скриптів (Script Permissions)

Права доступу до Bash-скриптів визначають, хто може читати, змінювати та виконувати скрипт у Linux.

Щоб запустити Bash-скрипт, недостатньо створити файл із розширенням `.sh`. Потрібно розуміти права доступу, команду `chmod`, власника файлу, групи користувачів, а також різницю між прямим виконанням скрипта та запуском через інтерпретатор `bash`.

Ця тема важлива для автоматизації завдань, написання системних скриптів, роботи з Linux-серверами та розгортання застосунків.

## ✔ Основні поняття

- Що таке права доступу до файлів у Linux.
- Що означають права `r`, `w`, `x`.
- Як працюють права для власника, групи та інших користувачів.
- Як переглядати права за допомогою `ls -l` і `stat`.
- Як змінювати права командою `chmod`.
- Як використовувати символьний і числовий формати прав.
- Як виконувати Bash-скрипти.
- Чим відрізняються `./script.sh`, `bash script.sh` і `source script.sh`.
- Для чого потрібен shebang `#!/usr/bin/env bash`.
- Як змінювати власника та групу за допомогою `chown` і `chgrp`.
- Як працюють `umask` і права за замовчуванням.
- Як діагностувати помилки `Permission denied`.
- Як безпечно налаштовувати права для автоматизації.

# 1. Що таке права доступу в Linux

У Linux кожен файл і каталог має набір прав доступу.

Права визначають, які операції дозволені певним користувачам.

Основні операції:

- `r` — read — читання.
- `w` — write — запис або зміна.
- `x` — execute — виконання.

Переглянути права файлів у поточному каталозі:

    ls -l

Приклад результату:

    -rw-r--r-- 1 valer valer 1200 Oct 19 10:00 script.sh
    -rwxr-xr-x 1 valer valer  850 Oct 19 10:05 backup.sh

Перші десять символів описують тип файлу та його права.

Розглянемо рядок:

    -rwxr-xr--

Він складається з таких частин:

    - | rwx | r-x | r--

- `-` — звичайний файл.
- `rwx` — права власника.
- `r-x` — права групи.
- `r--` — права інших користувачів.

## 1.1. Перший символ: тип файлу

Перший символ у виведенні `ls -l` показує тип об'єкта.

| Символ | Тип |
|---|---|
| `-` | Звичайний файл |
| `d` | Каталог |
| `l` | Символічне посилання |
| `c` | Символьний пристрій |
| `b` | Блоковий пристрій |
| `p` | Іменований канал (FIFO) |
| `s` | Сокет |

Наприклад:

    -rwxr-xr-x  # звичайний виконуваний файл
    drwxr-xr-x  # каталог
    lrwxrwxrwx  # символічне посилання

## 1.2. Три категорії користувачів

Після першого символу йдуть три групи по три символи.

| Категорія | Позначення | Значення |
|---|---|---|
| Власник | `u` | User |
| Група | `g` | Group |
| Інші | `o` | Others |

Позначення `a` означає всіх одразу — `u`, `g` та `o`.

Наприклад:

    -rwxr-xr--

Розшифрування:

- Власник має `rwx`.
- Група має `r-x`.
- Інші користувачі мають `r--`.

## 1.3. Значення `r`, `w`, `x`

| Право | Для файлу | Для каталогу |
|---|---|---|
| `r` | Читати вміст | Переглядати список імен |
| `w` | Змінювати вміст | Створювати, видаляти та перейменовувати записи за відповідних умов |
| `x` | Виконувати файл | Проходити через каталог і звертатися до об'єктів за шляхом |

Важливо: для каталогів право `x` означає можливість проходити через каталог, а не запускати його як програму.

Для доступу до файлу за повним шляхом зазвичай потрібне право `x` на кожному каталозі в цьому шляху.

Наприклад, щоб прочитати файл:

    /home/valer/projects/script.sh

користувач повинен мати необхідні права на сам файл і право проходу через каталоги `/home`, `/home/valer` та `/home/valer/projects`.

# 2. Як переглядати права доступу

## 2.1. Команда `ls -l`

Переглянути права файлів:

    ls -l

Переглянути права конкретного скрипта:

    ls -l script.sh

Переглянути права прихованих файлів:

    ls -la

Переглянути права конкретного каталогу та його вмісту:

    ls -ld scripts/

Параметр `-d` показує сам каталог, а не список його вмісту.

Приклад:

    $ ls -l backup.sh
    -rw-r--r-- 1 valer valer 850 Oct 19 10:05 backup.sh

У цьому випадку файл поки що не має права виконання для жодної категорії користувачів.

## 2.2. Команда `stat`

Команда `stat` показує детальну інформацію про файл.

    stat script.sh

Приклад результату:

    File: script.sh
    Size: 1200
    Access: (0644/-rw-r--r--)
    Uid: (1000/valer)
    Gid: (1000/valer)

Особливо корисний рядок:

    Access: (0644/-rw-r--r--)

Він показує права одночасно у числовому та символьному форматах.

Щоб отримати лише числові права:

    stat -c '%a' script.sh

Приклад:

    644

Щоб переглянути права, власника та групу:

    stat -c '%A %a %U %G %n' script.sh

## 2.3. Команда `namei`

Якщо виникла помилка доступу до файлу, проблема може бути не в самому файлі, а в одному з каталогів шляху.

Команда `namei` допомагає перевірити права на кожну частину шляху:

    namei -l /home/valer/projects/script.sh

Вона особливо корисна для діагностики помилок `Permission denied`.

# 3. Як працює команда `chmod`

`chmod` (change mode) змінює права доступу до файлів і каталогів.

Загальний синтаксис:

    chmod [OPTIONS] MODE FILE

Наприклад:

    chmod +x script.sh

Додає право виконання відповідно до правил символьного режиму.

Після цього можна запускати скрипт безпосередньо:

    ./script.sh

## 3.1. Додавання права виконання

Додати право виконання для власника:

    chmod u+x script.sh

Додати право виконання для групи:

    chmod g+x script.sh

Додати право виконання для інших:

    chmod o+x script.sh

Додати право виконання для всіх категорій:

    chmod a+x script.sh

Короткий варіант:

    chmod +x script.sh

Якщо категорію не вказано, зазвичай мається на увазі `a`, але результат також залежить від `umask`.

Для типового навчального скрипта команда `chmod +x script.sh` — найпростіший спосіб надати право виконання.

## 3.2. Видалення права виконання

Видалити право виконання у власника:

    chmod u-x script.sh

Видалити право виконання у групи:

    chmod g-x script.sh

Видалити право виконання в інших:

    chmod o-x script.sh

Видалити право виконання у всіх:

    chmod a-x script.sh

## 3.3. Встановлення конкретних прав

Оператор `=` встановлює права точно для вказаної категорії.

Наприклад:

    chmod u=rwx script.sh

Встановити власнику читання та запис, а виконання заборонити:

    chmod u=rw script.sh

Встановити групі тільки читання:

    chmod g=r script.sh

Встановити іншим відсутність прав:

    chmod o= script.sh

Можна змінити права кількох категорій одночасно:

    chmod u=rwx,g=rx,o=r script.sh

Результат:

    -rwxr-xr--

## 3.4. Основні оператори `chmod`

| Оператор | Значення | Приклад |
|---|---|---|
| `+` | Додати права | `chmod u+x script.sh` |
| `-` | Забрати права | `chmod o-w script.sh` |
| `=` | Встановити права точно | `chmod u=rw script.sh` |

# 4. Числовий формат прав: 755, 644, 700

Права доступу можна задавати числовим форматом.

Кожне право має числове значення:

| Право | Значення |
|---|---:|
| `r` | 4 |
| `w` | 2 |
| `x` | 1 |
| Немає права | 0 |

Для кожної категорії користувачів числа додаються.

Приклади:

    rwx = 4 + 2 + 1 = 7
    rw- = 4 + 2     = 6
    r-x = 4     + 1 = 5
    r-- = 4         = 4
    -wx =     2 + 1 = 3
    -w- =     2     = 2
    --x =         1 = 1
    --- = 0

## 4.1. Як розшифрувати 755

Команда:

    chmod 755 script.sh

Число складається з трьох цифр:

    7 | 5 | 5
    u | g | o

Розшифрування:

    7 = rwx
    5 = r-x
    5 = r-x

Результат:

    -rwxr-xr-x

Власник може читати, змінювати та виконувати файл. Група й інші можуть читати та виконувати його, але не змінювати вміст без додаткових прав.

## 4.2. Як розшифрувати 644

Команда:

    chmod 644 script.sh

Розшифрування:

    6 = rw-
    4 = r--
    4 = r--

Результат:

    -rw-r--r--

Файл можна читати, але безпосередньо виконувати його не можна.

Це типовий режим для звичайного текстового файлу.

## 4.3. Як розшифрувати 700

Команда:

    chmod 700 script.sh

Результат:

    -rwx------

Тільки власник має права читання, запису та виконання.

Група й інші не мають жодних прав на цей файл.

## 4.4. Найпоширеніші режими

| Режим | Права | Типове використання |
|---|---|---|
| `644` | `rw-r--r--` | Звичайні текстові файли |
| `600` | `rw-------` | Файли, доступні лише власнику |
| `755` | `rwxr-xr-x` | Виконувані скрипти та каталоги |
| `750` | `rwxr-x---` | Скрипти для власника та групи |
| `700` | `rwx------` | Приватні скрипти |
| `775` | `rwxrwxr-x` | Спільна робота власника й групи |
| `777` | `rwxrwxrwx` | Усі мають усі стандартні права |

**Важливо:** не використовуй `777` як універсальний спосіб виправлення помилок доступу. Це часто створює зайві ризики безпеки.

## 4.5. Практичні приклади

Зробити скрипт доступним для виконання всім, але змінювати його вміст може тільки власник:

    chmod 755 script.sh

Зробити скрипт приватним:

    chmod 700 script.sh

Дозволити групі читати й виконувати скрипт, але не змінювати його:

    chmod 750 script.sh

Заборонити іншим користувачам читати файл:

    chmod 750 script.sh

Для режиму `750` права інших користувачів дорівнюють `---`.

# 5. Запуск Bash-скриптів

Існує кілька способів запускати скрипти. Вони мають важливі відмінності.

## 5.1. Прямий запуск через `./script.sh`

Приклад файлу `hello.sh`:

    #!/usr/bin/env bash

    echo "Hello from Bash!"

Надати право виконання:

    chmod +x hello.sh

Запустити:

    ./hello.sh

Система використовує shebang, щоб визначити інтерпретатор, а ядро перевіряє можливість виконання файлу та доступ до нього.

Шлях `./hello.sh` означає, що файл розташований у поточному каталозі.

Якщо скрипт розташований в іншому каталозі, можна вказати шлях:

    ./scripts/hello.sh

Або абсолютний шлях:

    /home/valer/projects/scripts/hello.sh

## 5.2. Запуск через `bash script.sh`

Команда:

    bash script.sh

запускає інтерпретатор Bash і передає йому файл для виконання.

У такому випадку для самого файлу зазвичай не потрібне право `x`, але потрібне право читання файлу та доступ до каталогів шляху.

Наприклад:

    chmod 644 script.sh
    bash script.sh

Цей варіант може працювати, хоча файл не має права безпосереднього виконання.

Однак якщо файл має синтаксичні помилки або для його роботи потрібні недоступні ресурси, команда все одно може завершитися помилкою.

## 5.3. Порівняння способів запуску

| Команда | Потрібне право `x` на скрипт | Використання |
|---|---|---|
| `./script.sh` | Так | Прямий запуск |
| `bash script.sh` | Ні, зазвичай достатньо читання | Запуск через Bash |
| `source script.sh` | Ні | Виконання в поточній оболонці |

В усіх випадках залишаються важливими права на каталоги, доступ до інтерпретатора та доступ до файлів, з якими працює скрипт.

## 5.4. Команда `source`

Команда:

    source script.sh

виконує команди файлу в поточному процесі Bash.

Короткий еквівалент у Bash:

    . script.sh

Це відрізняється від звичайного запуску.

Наприклад, файл `variables.sh`:

    MY_NAME="Valeriy"
    export PROJECT_MODE="development"

Якщо виконати:

    bash variables.sh

зміни змінних не залишаться в поточній оболонці після завершення дочірнього процесу.

Якщо виконати:

    source variables.sh

змінна `MY_NAME` залишиться доступною в поточній оболонці.

Перевірити:

    echo "$MY_NAME"
    echo "$PROJECT_MODE"

**Важливо:** `source` виконує команди безпосередньо в поточній оболонці. Не використовуй його для невідомих або ненадійних скриптів.

# 6. Shebang: `#!/usr/bin/env bash`

Shebang — це спеціальний перший рядок скрипта, який указує, який інтерпретатор потрібно використати для його запуску.

Приклад:

    #!/usr/bin/env bash

    echo "Script started"

Інший поширений варіант:

    #!/bin/bash

Обидва варіанти можуть бути доречними.

## 6.1. Різниця між двома варіантами

`#!/bin/bash` указує конкретний шлях до Bash.

`#!/usr/bin/env bash` шукає команду `bash` у каталогах, зазначених у змінній середовища `PATH`.

Перевірити шлях до Bash:

    command -v bash

Приклад результату:

    /usr/bin/bash

## 6.2. Чому shebang важливий

Якщо запустити:

    ./script.sh

операційна система використовує shebang для вибору інтерпретатора.

Якщо запустити:

    bash script.sh

команду `bash` ти вже вказав явно. У такому разі shebang не визначає, який інтерпретатор запускати.

## 6.3. Типові помилки shebang

### Shebang відсутній

Скрипт може запускатися через `bash script.sh`, але прямий запуск може завершитися помилкою або поводитися не так, як очікується.

### Неправильний шлях

Наприклад:

    #!/wrong/path/bash

Прямий запуск завершиться помилкою, оскільки вказаного інтерпретатора немає.

### Windows line endings

Якщо файл збережений із закінченнями рядків CRLF, Linux може неправильно інтерпретувати shebang.

Перевірити тип закінчень рядків:

    file script.sh

За потреби перетворити CRLF на LF за допомогою `dos2unix`:

    dos2unix script.sh

Якщо `dos2unix` не встановлений, можна скористатися іншим інструментом перетворення рядків або налаштувати LF у редакторі.

# 7. Власник файлу та група

Крім прав доступу, Linux зберігає власника файлу та групу.

Переглянути інформацію:

    ls -l script.sh

Приклад:

    -rwxr-xr-x 1 valer developers 850 Oct 19 10:05 script.sh

Тут:

- `valer` — власник файлу.
- `developers` — група файлу.

## 7.1. Команда `chown`

`chown` (change owner) змінює власника файлу або каталогу.

Змінити власника:

    sudo chown valer script.sh

Змінити власника та групу:

    sudo chown valer:developers script.sh

Змінити лише групу через `chown`:

    sudo chown :developers script.sh

Змінити власника та групу рекурсивно:

    sudo chown -R valer:developers scripts/

Параметр `-R` застосовує зміну до каталогу та його вмісту.

**Обережно:** не використовуй рекурсивний `chown` без перевірки шляху. Помилка може змінити власника великої кількості файлів.

## 7.2. Команда `chgrp`

`chgrp` (change group) змінює групу файлу.

    chgrp developers script.sh

Якщо користувач не має потрібних повноважень, система відмовить у зміні.

Для системних файлів або файлів, власником яких ти не є, можуть знадобитися адміністративні права:

    sudo chgrp developers script.sh

## 7.3. Перегляд поточного користувача та груп

Поточний користувач:

    whoami

Групи поточного користувача:

    groups

Детальна інформація про користувача та його групи:

    id

# 8. Команда `umask` і права за замовчуванням

`umask` визначає, які права за замовчуванням не будуть надані новим файлам і каталогам.

Переглянути поточне значення:

    umask

Приклад:

    0022

У типовому випадку нові звичайні файли створюються з базовими правами `666`, а каталоги — з базовими правами `777`. Значення `umask` прибирає частину цих прав.

Для `umask 022` результат зазвичай такий:

    Новий файл:      644
    Новий каталог:   755

Причина в тому, що звичайні файли зазвичай не отримують право виконання автоматично.

## 8.1. Встановлення `umask`

Встановити значення `022` у поточній оболонці:

    umask 022

Зробити права нових файлів більш приватними для типових сценаріїв:

    umask 077

При типовому створенні нових об'єктів `umask 077` дає такі результати:

    Новий файл:      600
    Новий каталог:   700

Фактичні права можуть залежати від програми, яка створює файл, оскільки вона сама передає бажані початкові права.

## 8.2. Важливі особливості `umask`

- `umask` не змінює права вже створених файлів.
- `umask` впливає на нові файли та каталоги, створені процесами в цій оболонці або її дочірніх процесах.
- Значення `umask` не замінює правильне налаштування прав за допомогою `chmod`.
- Право виконання для звичайних текстових файлів автоматично не додається.

# 9. Рекурсивна зміна прав

Параметр `-R` команди `chmod` застосовує права до каталогу та його вмісту.

Наприклад:

    chmod -R 755 scripts/

Але ця команда встановить право виконання і для звичайних файлів, які можуть не бути скриптами.

Часто це небажано.

## 9.1. Чому `chmod -R 755` може бути помилкою

Уявімо структуру:

    scripts/
    ├── backup.sh
    ├── cleanup.sh
    └── README.md

Якщо виконати:

    chmod -R 755 scripts/

то `README.md` також отримає право виконання.

Для звичайного текстового документа це зайве.

## 9.2. Правильніший підхід

Зробити каталог доступним для проходу та перегляду:

    chmod 755 scripts/

Зробити конкретні скрипти виконуваними:

    chmod 755 scripts/backup.sh
    chmod 755 scripts/cleanup.sh

Або знайти всі файли з розширенням `.sh` і додати їм право виконання:

    find scripts/ -type f -name "*.sh" -exec chmod u+x {} \;

Команда додає право виконання власнику кожного знайденого скрипта.

Якщо потрібно встановити конкретний режим для знайдених скриптів:

    find scripts/ -type f -name "*.sh" -exec chmod 755 {} \;

Перед масовими змінами корисно спочатку переглянути список файлів:

    find scripts/ -type f -name "*.sh" -print

**Принцип:** встановлюй права відповідно до призначення файлів, а не однаково для всіх об'єктів.

# 10. Як виправити `Permission denied`

Помилка:

    bash: ./script.sh: Permission denied

не завжди означає, що потрібно виконати `chmod 777`.

Спочатку потрібно визначити причину.

## 10.1. Перевірити права самого скрипта

    ls -l script.sh

Якщо бачиш:

    -rw-r--r-- 1 valer valer 1200 Oct 19 10:00 script.sh

додай право виконання власнику:

    chmod u+x script.sh

Після цього:

    ./script.sh

## 10.2. Перевірити права на каталог

Переглянути права каталогу:

    ls -ld .

Якщо проблема в одному з батьківських каталогів, перевірити шлях:

    namei -l /home/valer/projects/script.sh

Для доступу до файлу користувачу потрібні відповідні права проходу через каталоги.

## 10.3. Перевірити shebang

Переглянути перший рядок:

    head -n 1 script.sh

Очікуваний приклад:

    #!/usr/bin/env bash

Перевірити, чи доступний Bash:

    command -v bash

## 10.4. Перевірити файлову систему

На деяких файлових системах або змонтованих розділах може діяти параметр `noexec`, який забороняє пряме виконання файлів.

Переглянути інформацію про змонтовані файлові системи:

    findmnt

Якщо файл розташований на розділі з `noexec`, додавання `x` через `chmod` не обов'язково вирішить проблему.

Не змінюй параметри монтування системних розділів без розуміння наслідків.

## 10.5. Перевірити формат рядків

Якщо скрипт перенесено з Windows, перевір його тип:

    file script.sh

За потреби:

    dos2unix script.sh

## 10.6. Запустити через Bash для діагностики

Спробуй:

    bash script.sh

Якщо цей варіант працює, а `./script.sh` — ні, перевір:

- право виконання;
- shebang;
- наявність інтерпретатора за вказаним шляхом;
- параметри монтування файлової системи.

Якщо обидва варіанти не працюють, причина може бути в синтаксисі, відсутніх файлах, правах на ресурси або логіці скрипта.

# 11. Безпека Bash-скриптів

Права доступу — це частина безпеки автоматизації.

Скрипт може читати приватні дані, видаляти файли, змінювати системні параметри або запускати інші програми.

## 11.1. Не використовуй `777` без потреби

Команда:

    chmod 777 script.sh

дозволяє всім користувачам читати, змінювати та виконувати файл.

Якщо інший користувач може змінити скрипт, який потім запускається з підвищеними привілеями, це може призвести до серйозної проблеми безпеки.

Надавай лише необхідні права.

## 11.2. Приватні скрипти

Для скрипта, доступного лише власнику:

    chmod 700 private.sh

Це корисно, якщо скрипт містить внутрішні робочі процедури або працює з приватними файлами.

Проте права `700` не є універсальним способом захисту секретів: важливо також контролювати доступ до резервних копій, журналів і середовища виконання.

## 11.3. Скрипти із секретами

Не зберігай паролі, токени та приватні ключі у відкритому вигляді в загальнодоступних скриптах.

Для файлу з чутливими налаштуваннями можна встановити:

    chmod 600 .env

Але це не замінює належного керування секретами та перевірки того, хто має доступ до каталогу.

## 11.4. Використання `sudo`

`sudo` дозволяє запускати команди з адміністративними привілеями, якщо це дозволено конфігурацією системи.

Наприклад:

    sudo ./system-script.sh

Не потрібно автоматично запускати кожен скрипт через `sudo`.

Перед цим перевір:

- які команди виконує скрипт;
- які файли він змінює;
- чи безпечно обробляє аргументи;
- чи може інший користувач змінити скрипт або його залежності.

Особливо небезпечно запускати через `sudo` скрипт, який має права на зміну для звичайних користувачів.

# 12. Практичний приклад: створення та запуск скрипта

Створимо простий Bash-скрипт.

## 12.1. Створення файлу

    mkdir -p ~/linux-practice/permissions
    cd ~/linux-practice/permissions

Створи файл:

    nano hello.sh

Вміст:

    #!/usr/bin/env bash

    echo "Hello from Bash!"
    echo "Current user: $(whoami)"
    echo "Current directory: $PWD"

Збережи файл.

## 12.2. Перевірка прав

    ls -l hello.sh

Можливий результат:

    -rw-r--r-- 1 valer valer 100 Oct 19 10:00 hello.sh

## 12.3. Запуск без права виконання

    ./hello.sh

Очікувано, прямий запуск не вдасться, якщо файл не має права виконання або існує інше обмеження.

Спробуй:

    bash hello.sh

Цей запуск зазвичай працює, якщо файл доступний для читання.

## 12.4. Додавання права виконання

    chmod u+x hello.sh

Перевір:

    ls -l hello.sh

Тепер права мають приблизно такий вигляд:

    -rwxr--r-- 1 valer valer 100 Oct 19 10:00 hello.sh

Запусти:

    ./hello.sh

## 12.5. Встановлення режиму 755

    chmod 755 hello.sh

Перевір права:

    stat -c '%A %a %n' hello.sh

Приклад результату:

    -rwxr-xr-x 755 hello.sh

## 12.6. Встановлення приватного режиму

    chmod 700 hello.sh

Перевір:

    ls -l hello.sh

Очікуваний формат:

    -rwx------ 1 valer valer 100 Oct 19 10:00 hello.sh

Тепер звичайні інші користувачі не матимуть прав на читання, запис і виконання цього файлу.

# 13. Корисні команди для роботи з правами

| Команда | Призначення |
|---|---|
| `ls -l` | Переглянути права файлів |
| `ls -la` | Переглянути всі файли, включно з прихованими |
| `ls -ld dir/` | Переглянути права каталогу |
| `stat file` | Детальна інформація про файл |
| `stat -c '%a' file` | Числові права файлу |
| `chmod +x file` | Додати право виконання відповідно до символьного режиму |
| `chmod 755 file` | Встановити права `rwxr-xr-x` |
| `chmod 644 file` | Встановити права `rw-r--r--` |
| `chmod 700 file` | Встановити права `rwx------` |
| `chmod -R MODE dir/` | Рекурсивно змінити права |
| `chown user file` | Змінити власника |
| `chown user:group file` | Змінити власника та групу |
| `chgrp group file` | Змінити групу |
| `umask` | Переглянути маску прав за замовчуванням |
| `namei -l PATH` | Перевірити права на частини шляху |
| `find dir -type f` | Знайти звичайні файли |
| `command -v bash` | Знайти доступний Bash |
| `file script.sh` | Визначити тип файлу та перевірити формат |
| `id` | Переглянути користувача, UID, GID та групи |

# 14. Типові помилки

## Помилка 1. Запускати скрипт без права виконання

Команда:

    ./script.sh

Помилка:

    Permission denied

Виправлення для звичайного власного скрипта:

    chmod u+x script.sh
    ./script.sh

## Помилка 2. Вважати, що розширення `.sh` робить файл виконуваним

Розширення `.sh` — це лише частина імені файлу. Воно саме по собі не встановлює права.

Виконуваність залежить від прав, інтерпретатора та інших умов.

## Помилка 3. Використовувати `chmod 777` для всіх проблем

Це надає надмірні права і може створити ризики безпеки.

Спочатку знайди причину помилки, потім зміни лише необхідні права.

## Помилка 4. Плутати `bash script.sh` і `./script.sh`

`bash script.sh` запускає Bash і передає йому файл.

`./script.sh` намагається запустити файл безпосередньо, використовуючи його формат виконання та shebang.

## Помилка 5. Забувати про права каталогів

Навіть якщо файл має право читання або виконання, відсутність права `x` на одному з каталогів шляху може заблокувати доступ до нього.

## Помилка 6. Виконувати `chmod -R 755` для всього проєкту

Це може зробити виконуваними документи, конфігурації та інші звичайні файли.

Змінюй права вибірково.

## Помилка 7. Вважати, що `chmod` змінює власника

`chmod` змінює права доступу.

`chown` змінює власника та, за відповідним синтаксисом, групу.

`chgrp` змінює групу.

## Помилка 8. Вважати, що `umask` змінює наявні файли

`umask` впливає на створення нових файлів і каталогів, а не на вже створені об'єкти.

## Помилка 9. Ігнорувати формат рядків після редагування у Windows

Невідповідні закінчення рядків можуть спричинити помилки під час прямого запуску.

Перевір файл за допомогою `file` та, за потреби, `dos2unix`.

# 15. Практичні завдання

## Рівень 1. Основи

### Завдання 1. Перегляд прав

1. Створи файл `hello.sh`.
2. Переглянь його права через `ls -l`.
3. Переглянь числові права через `stat`.
4. Поясни значення кожної цифри.

### Завдання 2. Право виконання

1. Створи скрипт із shebang.
2. Спробуй запустити його через `./hello.sh`.
3. Додай право виконання.
4. Запусти ще раз.
5. Порівняй результати.

### Завдання 3. Числові режими

Послідовно встанови режими:

    chmod 644 hello.sh
    chmod 755 hello.sh
    chmod 700 hello.sh

Після кожної команди виконай:

    ls -l hello.sh

Поясни, як змінюються права власника, групи та інших користувачів.

### Завдання 4. Символьний формат

Виконай:

    chmod u+x hello.sh
    chmod g+x hello.sh
    chmod o-x hello.sh

Перевір результат і поясни кожну зміну.

## Рівень 2. Практика

### Завдання 5. Приватний скрипт

Створи `private.sh`.

Встанови права:

    chmod 700 private.sh

Перевір їх через `stat`.

Поясни, чому цей режим підходить для скрипта, який повинен бути доступний лише власнику.

### Завдання 6. Каталог зі скриптами

Створи структуру:

    scripts/
    ├── backup.sh
    ├── cleanup.sh
    └── README.md

Встанови право виконання для `backup.sh` і `cleanup.sh`, але не для `README.md`.

Перевір результат:

    ls -l scripts/

### Завдання 7. Пошук скриптів

Знайди всі файли з розширенням `.sh` у каталозі `scripts/`:

    find scripts/ -type f -name "*.sh" -print

Після перевірки списку додай право виконання власнику:

    find scripts/ -type f -name "*.sh" -exec chmod u+x {} \;

### Завдання 8. Діагностика

У навмисно невиконуваному скрипті встанови режим:

    chmod 644 hello.sh

Спробуй прямий запуск і запуск через Bash.

Поясни різницю між результатами.

## Рівень 3. Автоматизація

### Завдання 9. Перевірка перед запуском

Напиши скрипт `run-check.sh`, який:

- приймає шлях до іншого скрипта як аргумент;
- перевіряє, чи передано аргумент;
- перевіряє, чи існує файл;
- перевіряє, чи це звичайний файл;
- перевіряє, чи файл доступний для читання;
- повідомляє користувачу, якщо файл не має права виконання;
- не змінює права автоматично без явної команди користувача.

Підказки:

    $# 
    -f
    -r
    -x

### Завдання 10. Аудит прав

Напиши скрипт, який:

- приймає каталог;
- перевіряє, чи існує каталог;
- знаходить файли `.sh`;
- показує права кожного файлу;
- виводить власника та групу;
- не змінює жодних файлів.

Корисні команди:

    find
    stat
    printf

### Завдання 11. Безпечне налаштування

Створи навчальний каталог зі скриптами та документацією.

Налаштуй права так, щоб:

- власник міг змінювати всі свої скрипти;
- група могла читати та виконувати вибрані скрипти;
- інші користувачі не могли читати приватний скрипт;
- документація не мала зайвого права виконання.

Перевір усі права через `ls -l` та `stat`.

# 16. Питання для співбесіди

## Core — початковий рівень

### 1. Що означають `r`, `w`, `x`?

- `r` — читання.
- `w` — запис.
- `x` — виконання для файлів або проходження через каталоги.

### 2. Що означають `755`?

    rwxr-xr-x

Власник має всі три стандартні права, група та інші користувачі — читання й виконання.

### 3. Чим відрізняються `chmod` і `chown`?

- `chmod` змінює права доступу.
- `chown` змінює власника та може змінювати групу.

### 4. Як зробити Bash-скрипт виконуваним?

    chmod +x script.sh

### 5. Для чого потрібен shebang?

Він указує інтерпретатор, який має використовуватися під час прямого запуску скрипта.

### 6. Чи достатньо розширення `.sh` для запуску скрипта?

Ні. Потрібні відповідні права доступу та коректні умови виконання.

## Junior — практичний рівень

### 7. Чим відрізняються `./script.sh` і `bash script.sh`?

Перший варіант запускає файл безпосередньо й зазвичай потребує права `x`. Другий явно запускає Bash і передає йому файл, для якого зазвичай достатньо права читання.

### 8. Що означає `700`?

    rwx------

Лише власник має права читання, запису та виконання.

### 9. Що робить `umask`?

Визначає, які права за замовчуванням не надаються під час створення нових файлів і каталогів.

### 10. Чому `chmod -R 755` може бути небезпечним?

Він може зробити виконуваними звичайні файли, які не повинні запускатися, та надати надмірні права доступу.

### 11. Як перевірити числові права файлу?

    stat -c '%a' script.sh

### 12. Як перевірити права на весь шлях до файлу?

    namei -l /path/to/script.sh

## Middle — поглиблений рівень

### 13. Чому `bash script.sh` може працювати, а `./script.sh` — ні?

Можливі причини:

- немає права виконання;
- неправильний shebang;
- відсутній інтерпретатор за вказаним шляхом;
- файл розташований на файловій системі з параметром `noexec`.

### 14. Чому право `x` для каталогу важливе?

Воно дозволяє проходити через каталог і звертатися до його вмісту за шляхом. Без нього доступ до вкладених файлів може бути неможливим, навіть якщо права самого файлу це дозволяють.

### 15. Чи гарантує `chmod 600 .env` повний захист секретів?

Ні. Воно обмежує стандартний доступ до цього файлу, але не захищає автоматично копії, резервні копії, журнали, процеси або інші місця, де секрети можуть зберігатися.

### 16. Що робить `chmod u+x script.sh`?

Додає право виконання власнику, не змінюючи навмисно інші права.

### 17. Чому `umask 022` зазвичай дає `644` для файлів і `755` для каталогів?

Типові початкові права — `666` для звичайних файлів і `777` для каталогів. `umask 022` прибирає право запису для групи та інших користувачів. Файли при цьому зазвичай не отримують право виконання.

## Senior — системний рівень

### 18. Як безпечно організувати права для скриптів автоматизації?

Потрібно:

- визначити власника й робочу групу;
- надати мінімально необхідні права;
- захистити скрипти, які запускаються з підвищеними привілеями;
- не допускати запису сторонніми користувачами в каталоги та залежності таких скриптів;
- перевіряти аргументи та шляхи;
- уникати надмірного використання `sudo`;
- перевіряти права на всі частини шляху.

### 19. Чому `chmod` не завжди вирішує `Permission denied`?

Причиною можуть бути права батьківських каталогів, власник, група, ACL, параметр монтування `noexec`, обмеження безпеки або відсутній інтерпретатор.

### 20. Як перевірити додаткові ACL?

На системах із підтримкою ACL можна використати:

    getfacl script.sh

Для зміни ACL використовується `setfacl`, якщо він доступний і встановлений.

### 21. Чи є `chmod 755` правильним режимом для кожного скрипта?

Ні. Режим залежить від того, хто повинен читати, змінювати та запускати файл. Для приватних скриптів може бути доречним `700`, а для скриптів із груповим доступом — `750`.

# 17. Що потрібно запам'ятати

✔ `chmod` змінює права доступу.

✔ `chown` змінює власника та, за відповідним синтаксисом, групу.

✔ `chgrp` змінює групу файлу.

✔ `r` означає читання, `w` — запис, `x` — виконання або прохід через каталог.

✔ Права поділяються на три категорії: власник (`u`), група (`g`) та інші (`o`).

✔ `chmod +x script.sh` додає право виконання відповідно до символьного режиму.

✔ `chmod 755 script.sh` встановлює права `rwxr-xr-x`.

✔ `chmod 644 script.sh` встановлює права `rw-r--r--`.

✔ `chmod 700 script.sh` встановлює права `rwx------`.

✔ `./script.sh` — прямий запуск, а `bash script.sh` — запуск через інтерпретатор Bash.

✔ `source script.sh` виконує команди в поточній оболонці.

✔ Shebang, наприклад `#!/usr/bin/env bash`, указує інтерпретатор для прямого запуску.

✔ `umask` впливає на права нових файлів і каталогів.

✔ Для каталогів право `x` дозволяє проходити через них.

✔ `chmod -R 755` не слід бездумно застосовувати до всіх файлів проєкту.

✔ `Permission denied` не завжди означає відсутність права `x` на самому скрипті.

✔ `777` зазвичай не є правильним способом виправлення помилок доступу.

# 19. Підсумок

Права доступу — важлива частина роботи з Bash-скриптами в Linux.

Щоб упевнено запускати та автоматизувати завдання, потрібно вміти:

1. Читати права через `ls -l` і `stat`.
2. Розуміти значення `r`, `w`, `x`.
3. Застосовувати `chmod` у символьному та числовому форматах.
4. Відрізняти прямий запуск від запуску через Bash.
5. Використовувати shebang.
6. Розуміти роль власника, групи та `umask`.
7. Діагностувати `Permission denied`.
8. Налаштовувати права без зайвих ризиків для безпеки.

**Головний принцип:** надавай кожному файлу лише ті права, які справді потрібні для його призначення. Для Bash-скриптів це означає не просто додати `x`, а розуміти, хто може читати, змінювати та виконувати скрипт.
