# 05. RSYNC — синхронізація файлів і каталогів

## 1. Що таке rsync

**`rsync`** — це утиліта Linux для копіювання та синхронізації файлів і каталогів між комп'ютерами або в межах однієї файлової системи.

`rsync` особливо корисний, коли потрібно регулярно оновлювати файли на сервері, передавати резервні копії або синхронізувати локальний проєкт із віддаленим каталогом.

Наприклад, ти розробляєш Node.js-застосунок локально й хочеш оновити його файли на Linux-сервері. Замість повторного копіювання всього проєкту можна використати `rsync`, який ефективно передає зміни.

    rsync -av ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Основні поняття

✔ **Rsync** — утиліта для синхронізації файлів.

✔ **Synchronization** — приведення файлів у джерелі та призначенні до потрібного стану.

✔ **Source** — джерело, звідки беруться файли.

✔ **Destination** — каталог або комп'ютер, куди передаються файли.

✔ **Incremental transfer** — передавання змін замість безумовного повторного копіювання всіх даних.

✔ **Remote host** — віддалений комп'ютер або сервер.

✔ **SSH transport** — використання SSH для захищеного передавання даних між комп'ютерами.

✔ **Dry run** — пробний запуск, який показує заплановані дії без фактичної синхронізації.

✔ **Deletion** — видалення файлів у призначенні, якщо вони відсутні в джерелі та використовується відповідний параметр.

### Що потрібно запам'ятати

`rsync` — це не просто копіювання файлів. Це інструмент синхронізації, який дозволяє ефективно оновлювати каталоги, зберігати атрибути файлів, обмежувати передавання та контролювати видалення.

**Особливо важливо:** параметр `--delete` може видаляти файли в каталозі призначення. Перед його використанням завжди перевіряй команду через `--dry-run`.

## 2. Перевірка та встановлення rsync

Перевір, чи встановлено утиліту:

    rsync --version

Якщо команда відсутня, в Ubuntu її можна встановити:

    sudo apt update
    sudo apt install rsync

Перевір версію:

    rsync --version

На локальному комп'ютері та віддаленому сервері `rsync` має бути встановлений, якщо ти плануєш використовувати його через SSH.

Перевірити наявність утиліти на сервері можна так:

    ssh valeriy@server.example.com 'rsync --version'

Якщо команда не знайдена, потрібно встановити `rsync` на сервері або попросити адміністратора це зробити.

### Що потрібно запам'ятати

- `rsync` може працювати локально, без SSH.
- Для передавання між комп'ютерами його часто використовують разом із SSH.
- Для SSH-передавання потрібні доступ до сервера та права на відповідні каталоги.

## 3. Загальний синтаксис

Загальний синтаксис команди:

    rsync [OPTIONS] SOURCE DESTINATION

Де:

- `OPTIONS` — параметри копіювання та синхронізації;
- `SOURCE` — джерело файлів;
- `DESTINATION` — місце призначення.

Наприклад:

    rsync -av ./project/ ./project-backup/

Це синхронізує вміст каталогу `project` із каталогом `project-backup` на тому самому комп'ютері.

Для віддаленого сервера:

    rsync -av ./project/ valeriy@server.example.com:/home/valeriy/project/

Для копіювання з сервера на локальний комп'ютер:

    rsync -av valeriy@server.example.com:/home/valeriy/project/ ./project/

### Формат віддаленого шляху

    USER@HOST:/PATH

Наприклад:

    valeriy@server.example.com:/home/valeriy/project/

Тут:

- `valeriy` — користувач на сервері;
- `server.example.com` — адреса сервера;
- `/home/valeriy/project/` — віддалений каталог.

Домен `example.com` у прикладах є демонстраційним. Для реальної роботи використовуй адресу свого сервера.

## 4. Основні параметри `rsync`

Найчастіше в командах зустрічається комбінація:

    rsync -av SOURCE DESTINATION

Розглянемо її частини.

### `-a` — archive mode

Параметр `-a` вмикає архівний режим.

Він зберігає структуру каталогів і, наскільки це можливо та дозволено, атрибути файлів, зокрема:

- символічні посилання;
- права доступу;
- часові мітки;
- власника та групу за наявності необхідних прав;
- рекурсивну обробку каталогів.

Архівний режим приблизно відповідає комбінації:

    -rlptgoD

Це не означає, що звичайний користувач автоматично може зберігати будь-якого власника або групу. Для деяких атрибутів потрібні додаткові привілеї.

### `-v` — verbose

Показує більше інформації про процес синхронізації.

    rsync -v ./notes.txt ./backup/

Це допомагає бачити, які файли обробляються.

### `-r` — recursive

Рекурсивно копіює каталоги та їхній вміст.

    rsync -r ./project/ ./backup/

Для типових завдань зручніше використовувати `-a`, який уже включає рекурсивне копіювання.

### `-z` — compression

Стискає дані під час передавання.

    rsync -avz ./project/ valeriy@server.example.com:/home/valeriy/project/

Стиснення може допомогти для текстових даних через повільну мережу, але не завжди пришвидшує передавання вже стиснених файлів.

### `-n` — dry run

Показує, що команда планує зробити, але не виконує фактичного копіювання або видалення.

    rsync -av --dry-run ./project/ valeriy@server.example.com:/home/valeriy/project/

`-n` — короткий варіант `--dry-run`.

### `-u` — update

Не перезаписує файли в призначенні, якщо вони новіші за відповідні файли в джерелі.

    rsync -avu ./project/ ./backup/

Це може бути корисним у певних сценаріях, але не замінює повноцінного керування версіями файлів.

### `--delete`

Видаляє файли в призначенні, яких немає в джерелі.

    rsync -av --delete ./project/ ./backup/

**Увага:** ця команда може видалити файли з `./backup/`, якщо їх немає в `./project/`.

Перед використанням перевір результат:

    rsync -av --delete --dry-run ./project/ ./backup/

### Що потрібно запам'ятати

| Параметр | Призначення |
|---|---|
| `-a` | Архівний режим |
| `-v` | Докладніше виведення |
| `-r` | Рекурсивне копіювання каталогів |
| `-z` | Стиснення даних під час передавання |
| `-n` | Пробний запуск |
| `-u` | Не перезаписувати новіші файли в призначенні |
| `--delete` | Видаляти в призначенні файли, відсутні в джерелі |
| `-P` | Показувати прогрес і зберігати частково передані файли |
| `-h` | Людинозрозумілий формат чисел |
| `--exclude` | Виключити файли або каталоги |
| `--include` | Дозволити відповідні файли в правилах фільтрації |

## 5. Локальна синхронізація каталогів

`rsync` можна використовувати без SSH — для синхронізації каталогів на одному комп'ютері.

Наприклад, є структура:

    project/
    ├── package.json
    ├── server.js
    └── README.md

Створи каталог для резервної копії:

    mkdir -p backup

Синхронізуй файли:

    rsync -av ./project/ ./backup/

Після виконання в `backup/` буде скопійовано вміст каталогу `project/`.

### Перевірка результату

    ls -la ./backup/

### Повторна синхронізація

Зміни файл:

    echo "New line" >> ./project/README.md

Повтори команду:

    rsync -av ./project/ ./backup/

`rsync` перевірить файли та передасть ті зміни, які потрібно застосувати.

### Що потрібно запам'ятати

`rsync` корисний не тільки для серверів. Його можна використовувати для:

- локальних резервних копій;
- синхронізації робочих каталогів;
- перенесення даних між дисками;
- оновлення вмісту резервного каталогу.

## 6. Найважливіше: різниця між `SOURCE/` і `SOURCE`

Кінцевий символ `/` у джерелі має велике значення.

Припустимо, є каталог:

    project/
    ├── server.js
    └── package.json

### Варіант 1. Джерело з `/`

    rsync -av ./project/ ./backup/

Це означає: синхронізувати **вміст** каталогу `project/` із каталогом `backup/`.

Результат:

    backup/
    ├── server.js
    └── package.json

### Варіант 2. Джерело без `/`

    rsync -av ./project ./backup/

У цьому випадку копіюється сам каталог `project` разом із його вмістом.

Якщо `backup/` уже існує, результат зазвичай матиме вигляд:

    backup/
    └── project/
        ├── server.js
        └── package.json

### Порівняння

| Команда | Що копіюється |
|---|---|
| `rsync -av ./project/ ./backup/` | Вміст `project/` |
| `rsync -av ./project ./backup/` | Каталог `project` разом із вмістом |

### Що потрібно запам'ятати

Перед запуском `rsync` завжди перевіряй кінцевий `/` у шляху джерела.

Ця маленька деталь може змінити структуру результату синхронізації.

## 7. Синхронізація локального каталогу з віддаленим сервером

Це один із найважливіших сценаріїв для розробника.

Припустимо, локально є проєкт:

    my-app/
    ├── package.json
    ├── package-lock.json
    ├── server.js
    └── README.md

Щоб синхронізувати його вміст із сервером:

    rsync -av ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Як це працює

1. Локальний `rsync` аналізує джерело.
2. SSH встановлює захищене з'єднання із сервером.
3. `rsync` на віддаленій стороні допомагає перевірити файли.
4. Передаються дані, які потрібні для оновлення призначення.
5. Команда завершується після завершення синхронізації.

Для роботи цього сценарію зазвичай потрібні `rsync` на обох комп'ютерах та робочий SSH-доступ.

### Перевірка без змін

Спочатку можна виконати:

    rsync -av --dry-run ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

Перевір, які файли планується передати.

Потім виконай реальну синхронізацію:

    rsync -av ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Синхронізація під іншим користувачем

    rsync -av ./my-app/ deploy@server.example.com:/var/www/my-app/

Ця команда працюватиме лише за умови, що користувач `deploy` має право записувати у вказаний каталог.

Не припускай, що каталог `/var/www/` доступний для запису звичайному користувачу. За потреби потрібно правильно налаштувати права на сервері.

## 8. Синхронізація з сервера на локальний комп'ютер

Можна виконувати синхронізацію у зворотному напрямку.

    rsync -av valeriy@server.example.com:/home/valeriy/project/ ./project/

Тут:

- джерело — каталог на віддаленому сервері;
- призначення — локальний каталог `./project/`.

Це корисно, коли потрібно:

- завантажити файли із сервера;
- отримати резервну копію;
- скопіювати журнали;
- перенести результати обробки даних на локальний комп'ютер.

### Приклад: завантаження журналів

    mkdir -p ./server-logs

    rsync -av valeriy@server.example.com:/var/log/my-app/ ./server-logs/

Ця команда працюватиме, лише якщо віддалений користувач має право читати відповідні журнали.

### Важливо

Під час зворотної синхронізації уважно перевіряй порядок аргументів.

    rsync SOURCE DESTINATION

Якщо переплутати джерело та призначення, можна змінити не той каталог, який планував.

## 9. Використання SSH-ключів і конфігурації

Якщо ти вже налаштував SSH-ключі, `rsync` може використовувати їх через SSH.

Приклад із псевдонімом у `~/.ssh/config`:

    Host my-server
        HostName server.example.com
        User valeriy
        Port 2222
        IdentityFile ~/.ssh/id_ed25519_server
        IdentitiesOnly yes

Тоді команда стає коротшою:

    rsync -av ./project/ my-server:/home/valeriy/project/

Параметри сервера беруться з SSH-конфігурації.

### Використання конкретного ключа без конфігурації

    rsync -av -e "ssh -i ~/.ssh/id_ed25519_server" ./project/ valeriy@server.example.com:/home/valeriy/project/

Параметр `-e` задає віддалену оболонку або транспорт, який використовує `rsync`. У цьому прикладі він запускає SSH із конкретним ключем.

### Нестандартний порт

    rsync -av -e "ssh -p 2222" ./project/ valeriy@server.example.com:/home/valeriy/project/

Зверни увагу: тут використовується `ssh -p`, а не `scp -P`.

### Що потрібно запам'ятати

Якщо сервер уже налаштований у `~/.ssh/config`, не потрібно щоразу вручну вказувати адресу, порт та ключ.

Для щоденної роботи з кількома серверами SSH-псевдоніми значно спрощують команди `ssh`, `scp` та `rsync`.

## 10. Виключення файлів і каталогів

Під час синхронізації проєктів часто не потрібно передавати всі файли.

Наприклад, у Node.js-проєкті зазвичай можна виключити:

- `node_modules/`;
- `.git/`;
- тимчасові файли;
- локальні журнали;
- кеші;
- файли середовища розробки.

### Виключення одного каталогу

    rsync -av --exclude='node_modules/' ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Виключення кількох каталогів

    rsync -av \
      --exclude='node_modules/' \
      --exclude='.git/' \
      --exclude='logs/' \
      ./my-app/ \
      valeriy@server.example.com:/home/valeriy/my-app/

Зворотний слеш у кінці рядка дозволяє продовжити команду на наступному рядку в Bash.

### Виключення файлів певного типу

    rsync -av --exclude='*.log' ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

Це правило виключає файли, які відповідають шаблону `*.log`.

### Виключення кількох типів файлів

    rsync -av \
      --exclude='*.log' \
      --exclude='*.tmp' \
      ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Використання файлу виключень

Створи файл `.rsync-exclude`:

    node_modules/
    .git/
    *.log
    *.tmp

Запусти синхронізацію:

    rsync -av --exclude-from='.rsync-exclude' ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

Шаблони в правилах виключення потрібно підбирати відповідно до структури джерела.

### Увага до `.env`

Файл `.env` часто містить паролі, токени та інші секрети.

Якщо він не повинен потрапити на сервер або до резервної копії, явно виключи його:

    rsync -av --exclude='.env' ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

Але не виключай `.env` автоматично, якщо саме цей файл потрібен застосунку на сервері. Краще визначити окремий безпечний спосіб керування конфігурацією та секретами.

## 11. Параметр `--delete`: небезпечне, але корисне видалення

За замовчуванням `rsync` не видаляє всі зайві файли в призначенні лише тому, що їх немає в джерелі.

Параметр `--delete` змінює цю поведінку.

    rsync -av --delete ./project/ ./backup/

Якщо в `backup/` є файл, якого немає у `project/`, він може бути видалений.

### Приклад

Джерело:

    project/
    ├── app.js
    └── package.json

Призначення:

    backup/
    ├── app.js
    ├── package.json
    └── old-file.txt

Команда:

    rsync -av --delete ./project/ ./backup/

після успішної синхронізації видалить `old-file.txt` із `backup/`, оскільки цього файлу немає в джерелі.

### Безпечний порядок роботи

Спочатку перевір заплановані зміни:

    rsync -av --delete --dry-run ./project/ ./backup/

Уважно переглянь виведення.

Лише після перевірки виконай реальну синхронізацію:

    rsync -av --delete ./project/ ./backup/

### Важливо

- Переконайся, що джерело та призначення вказані правильно.
- Перевір кінцевий `/` у шляхах.
- Не використовуй `--delete` без розуміння наслідків.
- Не запускай небезпечну команду від імені `root`, якщо це не потрібно.
- Для важливих даних передбач резервну копію.

**`--delete` не є резервним копіюванням.** Якщо потрібне збереження попередніх версій, розглянь версійні резервні копії або інший відповідний інструмент.

## 12. Пробний запуск: `--dry-run`

`--dry-run` дозволяє побачити, що `rsync` планує зробити, не виконуючи реальної синхронізації.

Наприклад:

    rsync -av --dry-run ./project/ ./backup/

Або для віддаленого сервера:

    rsync -av --dry-run ./project/ valeriy@server.example.com:/home/valeriy/project/

Це особливо корисно, коли команда містить:

- `--delete`;
- складні правила `--exclude`;
- велику кількість каталогів;
- віддалений шлях;
- шляхи, які легко переплутати.

### Як читати результат

`rsync` може показувати список файлів, які планує передати або обробити.

Якщо використовується `--delete`, у виведенні можуть бути позначки видалення файлів, наприклад `*deleting`.

### Чи змінює `--dry-run` файли?

Звичайний пробний запуск не виконує заплановане копіювання та видалення. Проте він усе одно встановлює з'єднання та читає інформацію, потрібну для аналізу.

Не сприймай `--dry-run` як повну гарантію того, що реальний запуск не матиме несподіваних наслідків: стан файлів може змінитися між перевіркою та виконанням.

---

## 13. Прогрес передавання: `-P`

Під час копіювання великих файлів зручно бачити прогрес.

    rsync -avP ./backup.tar.gz valeriy@server.example.com:/home/valeriy/backups/

Параметр `-P` поєднує два параметри:

    --partial --progress

- `--progress` показує прогрес передавання;
- `--partial` дозволяє зберігати частково передані файли для можливого продовження наступної спроби.

### Приклад для великого каталогу

    rsync -avP ./large-project/ valeriy@server.example.com:/home/valeriy/large-project/

Це допомагає бачити, як передаються великі файли.

### Що потрібно запам'ятати

`-P` не означає, що будь-яке перерване копіювання гарантовано продовжиться з тієї самої позиції. Поведінка залежить від файлів, параметрів і того, як `rsync` порівнює джерело та призначення.

---

## 14. Обмеження швидкості передавання

Якщо синхронізація споживає надто багато пропускної здатності, можна обмежити швидкість за допомогою `--bwlimit`.

    rsync -av --bwlimit=1000 ./project/ valeriy@server.example.com:/home/valeriy/project/

Значення задається приблизно в KiB/s у сучасних версіях `rsync`, хоча точна інтерпретація може залежати від версії та підтримуваного синтаксису.

Для практики використовуй помірні значення та перевіряй документацію встановленої версії:

    rsync --help

### Коли це корисно

- на повільному інтернет-з'єднанні;
- під час копіювання великих резервних копій;
- коли не потрібно повністю займати канал;
- під час синхронізації в робочий час.

## 15. Як rsync визначає, що потрібно передати

`rsync` аналізує файли джерела та призначення, щоб визначити, що потрібно оновити.

За замовчуванням для багатьох звичайних сценаріїв він використовує швидку перевірку на основі розміру файлу та часу модифікації.

Якщо розмір і час модифікації збігаються, файл зазвичай не передається повторно.

### Що це означає

Якщо ти змінив `server.js`, `rsync` може передати саме цей файл, не копіюючи повторно всі інші файли проєкту.

Проте не слід вважати стандартну перевірку абсолютною гарантією тотожності вмісту.

### Перевірка контрольних сум

Параметр `-c` змушує `rsync` використовувати контрольні суми для визначення, чи відрізняється вміст файлів.

    rsync -avc ./project/ ./backup/

Це може потребувати додаткового читання файлів і часу, особливо для великих каталогів.

### Коли використовувати `-c`

- коли важливо перевірити зміни вмісту;
- коли часові мітки не є надійним показником;
- під час окремих перевірок цілісності.

Для звичайної щоденної синхронізації часто достатньо стандартної поведінки `rsync`.

---

## 16. Символічні посилання, права доступу та власник файлів

Архівний режим `-a` намагається зберігати багато атрибутів файлів.

    rsync -av ./project/ ./backup/

Однак фактичний результат залежить від:

- прав користувача;
- файлової системи;
- параметрів `rsync`;
- підтримки атрибутів у джерелі та призначенні;
- прав на віддаленому сервері.

### Права доступу

`rsync -a` зазвичай зберігає режими доступу файлів, якщо це можливо.

### Власник і група

Для збереження власника та групи можуть знадобитися адміністративні права.

Не запускай `rsync` через `sudo` автоматично: це може призвести до створення файлів із небажаним власником або зміни доступу.

### Символічні посилання

Архівний режим зазвичай копіює символічні посилання як посилання, а не як звичайні файли, на які вони вказують.

### Перевірка після синхронізації

    ls -la ./backup/

Для перевірки прав доступу:

    stat ./backup/file.txt

Для перегляду власника та групи:

    ls -l ./backup/file.txt

## 17. Синхронізація проєкту Node.js

Припустимо, ти маєш локальний проєкт:

    my-app/
    ├── package.json
    ├── package-lock.json
    ├── server.js
    ├── README.md
    ├── .git/
    └── node_modules/

Потрібно передати код на сервер, але не копіювати `.git/` та `node_modules/`.

### Команда

    rsync -av \
      --exclude='.git/' \
      --exclude='node_modules/' \
      ./my-app/ \
      valeriy@server.example.com:/home/valeriy/my-app/

### Перевірка перед передаванням

    rsync -av --dry-run \
      --exclude='.git/' \
      --exclude='node_modules/' \
      ./my-app/ \
      valeriy@server.example.com:/home/valeriy/my-app/

### На сервері

Після передавання можна підключитися:

    ssh valeriy@server.example.com

Перейти до проєкту:

    cd ~/my-app

Встановити залежності:

    npm ci

Перевірити версію Node.js:

    node -v

### Важливе зауваження

Це лише приклад передавання файлів. Реальне розгортання застосунку може також потребувати:

- налаштування змінних середовища;
- доступу до бази даних;
- налаштування `systemd`;
- конфігурації reverse proxy;
- TLS-сертифіката;
- налаштування firewall;
- перевірки прав доступу.

`rsync` не виконує ці кроки автоматично.

## 18. Резервне копіювання за допомогою rsync

`rsync` часто використовують для копіювання важливих каталогів у резервне сховище.

Наприклад:

    rsync -av ~/projects/ /mnt/backup/projects/

Це синхронізує вміст `~/projects/` із `/mnt/backup/projects/`.

### Перевірка перед копіюванням

    rsync -av --dry-run ~/projects/ /mnt/backup/projects/

### Синхронізація з віддаленим сховищем

    rsync -av ~/projects/ valeriy@backup.example.com:/home/valeriy/backups/projects/

### Чим синхронізація відрізняється від резервної копії

Звичайна синхронізація не обов'язково зберігає старі версії файлів.

Якщо ти зміниш або видалиш файл у джерелі, наступна синхронізація може перенести нову версію або видалити відповідний файл у призначенні, залежно від параметрів.

Тому для справжнього резервного копіювання варто розглянути:

- окремі каталоги для різних дат;
- збереження попередніх версій;
- snapshots;
- резервне копіювання на інший фізичний пристрій;
- віддалене сховище з окремими правами доступу;
- періодичну перевірку можливості відновлення.

**Резервна копія корисна лише тоді, коли з неї можна відновити дані.**

## 19. Діагностика помилок rsync

### `rsync: command not found`

Утиліта не встановлена або недоступна через `PATH`.

Перевір:

    command -v rsync

В Ubuntu встанови:

    sudo apt update
    sudo apt install rsync

Якщо команда виконується через SSH, перевір наявність `rsync` на віддаленому сервері.

### `Permission denied`

Можливі причини:

- немає права читати файли джерела;
- немає права записувати у призначення;
- SSH-автентифікація не пройшла;
- віддалений користувач не має доступу до потрібного каталогу.

Перевір SSH окремо:

    ssh valeriy@server.example.com

### `Connection timed out`

Можливі причини:

- сервер недоступний;
- неправильний порт;
- мережеві обмеження;
- firewall блокує SSH.

Перевір підключення:

    ssh -v valeriy@server.example.com

### `No such file or directory`

Можливі причини:

- неправильно вказаний шлях;
- каталог призначення не існує;
- помилка в імені файлу;
- локальна команда запускається не з того каталогу.

Перевір:

    pwd
    ls -la

### `rsync error: ...`

`rsync` може показувати додаткову інформацію та код завершення.

Після виконання команди перевір код:

    echo $?

Код `0` зазвичай означає успішне завершення. Ненульовий код вказує на помилку або інший неуспішний результат, який потрібно проаналізувати.

Не покладайся лише на останній рядок виведення. Переглянь попередні повідомлення, щоб знайти першопричину.

### Як увімкнути докладний режим

    rsync -avv ./project/ valeriy@server.example.com:/home/valeriy/project/

Два параметри `-v` дають докладніше виведення, ніж один.

## 20. Практика: синхронізація локального каталогу

Виконуй вправу на власному комп'ютері або в тестовому каталозі.

### Крок 1. Створи структуру

    mkdir -p rsync-practice/source
    mkdir -p rsync-practice/backup

Створи файли:

    echo "First file" > rsync-practice/source/first.txt
    echo "Second file" > rsync-practice/source/second.txt

### Крок 2. Перевір джерело

    find rsync-practice/source -maxdepth 2 -type f

### Крок 3. Виконай пробну синхронізацію

    rsync -av --dry-run rsync-practice/source/ rsync-practice/backup/

Переконайся, що команда планує копіювати потрібні файли.

### Крок 4. Виконай синхронізацію

    rsync -av rsync-practice/source/ rsync-practice/backup/

### Крок 5. Перевір результат

    find rsync-practice/backup -maxdepth 2 -type f

### Крок 6. Зміни файл у джерелі

    echo "Updated content" >> rsync-practice/source/first.txt

Повтори синхронізацію:

    rsync -av rsync-practice/source/ rsync-practice/backup/

Перевір вміст:

    cat rsync-practice/backup/first.txt

### Крок 7. Перевір правила виключення

Створи файл:

    touch rsync-practice/source/debug.log

Виконай:

    rsync -av --exclude='*.log' rsync-practice/source/ rsync-practice/backup/

Перевір, чи потрапив `debug.log` до каталогу призначення.

### Крок 8. Перевір `--delete` у пробному режимі

Створи файл у призначенні:

    touch rsync-practice/backup/old-file.txt

Запусти:

    rsync -av --delete --dry-run rsync-practice/source/ rsync-practice/backup/

Зверни увагу, які файли планується видалити.

Не прибирай `--dry-run`, доки не впевнишся, що розумієш результат.

## 21. Практика: синхронізація з віддаленим сервером

Для цієї вправи потрібен власний сервер або тестова Linux-віртуальна машина з SSH.

### Крок 1. Перевір SSH

    ssh USER@SERVER

### Крок 2. Створи локальний каталог

    mkdir -p remote-practice
    echo "Remote rsync test" > remote-practice/message.txt

### Крок 3. Виконай пробну синхронізацію

    rsync -av --dry-run ./remote-practice/ USER@SERVER:/tmp/remote-practice/

Перевір адресу, шлях і список файлів у виведенні.

### Крок 4. Синхронізуй файли

    rsync -av ./remote-practice/ USER@SERVER:/tmp/remote-practice/

### Крок 5. Перевір файл на сервері

    ssh USER@SERVER 'cat /tmp/remote-practice/message.txt'

### Крок 6. Зміни локальний файл

    echo "Second line" >> remote-practice/message.txt

Повтори синхронізацію:

    rsync -av ./remote-practice/ USER@SERVER:/tmp/remote-practice/

### Крок 7. Перевір результат

    ssh USER@SERVER 'cat /tmp/remote-practice/message.txt'

### Крок 8. Перевір передавання через нестандартний порт

Якщо SSH працює на порту `2222`:

    rsync -av -e "ssh -p 2222" ./remote-practice/ USER@SERVER:/tmp/remote-practice/

Виконуй цей крок лише тоді, коли сервер справді використовує цей порт.

## 24. Мінішпаргалка

    # Версія rsync
    rsync --version

    # Локальна синхронізація
    rsync -av ./source/ ./backup/

    # Синхронізація локального каталогу із сервером
    rsync -av ./project/ USER@HOST:/home/USER/project/

    # Завантаження каталогу із сервера
    rsync -av USER@HOST:/home/USER/project/ ./project/

    # Пробний запуск
    rsync -av --dry-run ./project/ ./backup/

    # Синхронізація з прогресом
    rsync -avP ./project/ USER@HOST:/home/USER/project/

    # Стиснення під час передавання
    rsync -avz ./project/ USER@HOST:/home/USER/project/

    # Виключити node_modules
    rsync -av --exclude='node_modules/' ./project/ USER@HOST:/home/USER/project/

    # Виключити файли журналів
    rsync -av --exclude='*.log' ./project/ USER@HOST:/home/USER/project/

    # Використати файл виключень
    rsync -av --exclude-from='.rsync-exclude' ./project/ USER@HOST:/home/USER/project/

    # Використати нестандартний SSH-порт
    rsync -av -e "ssh -p 2222" ./project/ USER@HOST:/home/USER/project/

    # Використати конкретний SSH-ключ
    rsync -av -e "ssh -i ~/.ssh/id_ed25519" ./project/ USER@HOST:/home/USER/project/

    # Видаляти зайві файли в призначенні — спочатку перевірити!
    rsync -av --delete --dry-run ./project/ ./backup/

    # Реальна синхронізація з видаленням — лише після перевірки
    rsync -av --delete ./project/ ./backup/

    # Перевірити код завершення
    echo $?

## 25. Головні правила

1. `rsync` призначений для ефективної синхронізації файлів і каталогів.
2. `rsync -av SOURCE DESTINATION` — базова команда для багатьох задач.
3. `-a` зберігає структуру каталогів і багато атрибутів файлів у межах доступних можливостей.
4. `SOURCE/` означає вміст каталогу, а `SOURCE` — сам каталог разом із вмістом.
5. `--dry-run` допомагає перевірити заплановані дії перед синхронізацією.
6. `--exclude` дозволяє пропускати непотрібні файли та каталоги.
7. `--delete` може видаляти файли в призначенні, тому використовуй його обережно.
8. Для віддаленої синхронізації через SSH потрібні доступ до сервера та `rsync` на обох сторонах.
9. Для регулярного оновлення проєктів `rsync` часто зручніший за повторне копіювання всього каталогу через `scp`.
10. Звичайна синхронізація не гарантує збереження старих версій файлів — для цього потрібна окрема стратегія резервного копіювання.

**Основна ідея:** `rsync` допомагає підтримувати локальні та віддалені каталоги в потрібному стані, передавати зміни й автоматизувати копіювання. Для Linux-адміністрування, резервного копіювання та розгортання Node.js-застосунків це один із найкорисніших інструментів.
