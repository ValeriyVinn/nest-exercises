# 04. SCP — безпечне копіювання файлів через SSH

## 1. Що таке SCP

**SCP (Secure Copy Protocol)** — це спосіб копіювання файлів і каталогів між комп'ютерами через SSH-з'єднання.

За допомогою `scp` можна:

- копіювати файли з локального комп'ютера на віддалений сервер;
- завантажувати файли з сервера на локальний комп'ютер;
- копіювати каталоги разом із їхнім вмістом;
- передавати файли між віддаленими серверами;
- використовувати SSH-ключі та нестандартні SSH-порти.

Наприклад, ти розробляєш Node.js-застосунок на своєму ноутбуці й хочеш скопіювати файл на Linux-сервер.

    scp ./server.js valeriy@server.example.com:/home/valeriy/app/

Файл `server.js` буде скопійовано з локального комп'ютера до каталогу `/home/valeriy/app/` на сервері.

### Основні поняття

✔ **SCP** — команда для копіювання файлів через SSH.

✔ **Local machine** — локальний комп'ютер, на якому ти вводиш команду.

✔ **Remote host** — віддалений комп'ютер або сервер.

✔ **Source** — джерело, звідки копіюються дані.

✔ **Destination** — місце, куди копіюються дані.

✔ **Remote path** — шлях до файлу або каталогу на віддаленому комп'ютері.

✔ **SSH authentication** — перевірка прав доступу до сервера.

✔ **Recursive copy** — рекурсивне копіювання каталогу разом із його вмістом.

✔ **Port** — мережевий порт SSH-сервера. Типове значення — `22`.

### Що потрібно запам'ятати

`scp` використовує SSH для захищеного передавання даних. Тому для копіювання зазвичай потрібні ті самі відомості для підключення, що й для команди `ssh`: адреса сервера, ім'я користувача, порт і відповідні облікові дані або ключі.

У сучасних версіях OpenSSH реалізація `scp` за замовчуванням використовує SFTP поверх SSH. Старий SCP-протокол можна запросити параметром `-O`, але зазвичай цього не потрібно.

## 2. Синтаксис команди `scp`

Загальний синтаксис:

    scp [OPTIONS] SOURCE DESTINATION

Де:

- `OPTIONS` — необов'язкові параметри команди;
- `SOURCE` — файл або каталог, який потрібно скопіювати;
- `DESTINATION` — місце призначення.

Для віддалених шляхів використовується формат:

    USER@HOST:PATH

Наприклад:

    valeriy@server.example.com:/home/valeriy/notes.txt

Цей запис означає файл `notes.txt` у каталозі `/home/valeriy/` на сервері `server.example.com` під користувачем `valeriy`.

### Приклади синтаксису

Скопіювати локальний файл на сервер:

    scp ./notes.txt valeriy@server.example.com:/home/valeriy/

Завантажити файл із сервера:

    scp valeriy@server.example.com:/home/valeriy/notes.txt ./

Скопіювати файл між двома віддаленими серверами:

    scp user1@server1.example.com:/tmp/file.txt user2@server2.example.com:/tmp/

Останній варіант залежить від мережевої доступності обох серверів, їхньої автентифікації та підтримки потрібного способу передавання.

## 3. Копіювання файлу з локального комп'ютера на сервер

Це один із найпоширеніших сценаріїв використання `scp`.

### Копіювання одного файлу

    scp ./notes.txt valeriy@server.example.com:/home/valeriy/

Тут:

- `./notes.txt` — локальний файл;
- `valeriy` — користувач на віддаленому сервері;
- `server.example.com` — адреса сервера;
- `/home/valeriy/` — каталог призначення.

Після успішного виконання файл буде доступний на сервері.

### Копіювання з перейменуванням

    scp ./notes.txt valeriy@server.example.com:/home/valeriy/server-notes.txt

У цьому прикладі файл `notes.txt` на локальному комп'ютері буде скопійовано під ім'ям `server-notes.txt` на сервері.

### Копіювання до іншого каталогу

    scp ./server.js valeriy@server.example.com:/tmp/

Файл буде скопійовано до `/tmp/`.

Використовуй цей каталог для тимчасових тестів, а не для постійного зберігання важливих файлів застосунку.

### Що потрібно запам'ятати

Якщо кінцевий шлях указує на каталог, файл зазвичай зберігає початкове ім'я.

Якщо вказати повний шлях із новим ім'ям файлу, під час копіювання він буде перейменований.

Каталог призначення повинен існувати, а віддалений користувач повинен мати право запису до нього.

---

## 4. Копіювання файлу із сервера на локальний комп'ютер

`scp` також дозволяє завантажувати файли з віддаленого сервера.

### Завантаження файлу до поточного каталогу

    scp valeriy@server.example.com:/home/valeriy/notes.txt ./

Символ `./` означає поточний локальний каталог.

### Завантаження з перейменуванням

    scp valeriy@server.example.com:/home/valeriy/notes.txt ./server-notes.txt

Локальна копія матиме назву `server-notes.txt`.

### Завантаження до конкретного локального каталогу

    scp valeriy@server.example.com:/home/valeriy/notes.txt ~/Downloads/

Файл буде скопійовано до локального каталогу `Downloads`.

### Як зрозуміти напрямок копіювання

У команді `scp` джерело завжди стоїть перед призначенням.

    scp SOURCE DESTINATION

Тому:

    scp ./file.txt user@server.example.com:/tmp/

означає «локальний комп'ютер → сервер», а:

    scp user@server.example.com:/tmp/file.txt ./

означає «сервер → локальний комп'ютер».

## 5. Копіювання каталогів: параметр `-r`

За замовчуванням `scp` призначений для копіювання окремих файлів. Щоб копіювати каталог разом із його вмістом, використовуй параметр `-r`.

`-r` означає **recursive** — рекурсивно.

### Копіювання каталогу на сервер

    scp -r ./project valeriy@server.example.com:/home/valeriy/

Каталог `project` буде скопійовано на сервер разом із його вмістом.

Результат матиме приблизно таку структуру:

    /home/valeriy/
    └── project/
        ├── package.json
        ├── server.js
        └── README.md

### Копіювання каталогу із сервера

    scp -r valeriy@server.example.com:/home/valeriy/project ./

Каталог `project` буде завантажено до поточного локального каталогу.

### Копіювання каталогу під іншою назвою

    scp -r ./project valeriy@server.example.com:/home/valeriy/project-backup/

У результаті каталог буде скопійовано до місця призначення з ім'ям `project-backup`, якщо цей шлях відповідає бажаній структурі.

### Що потрібно запам'ятати

- `-r` потрібен для копіювання каталогів.
- Без `-r` команда не призначена для копіювання дерева каталогів.
- Якщо каталог містить багато файлів, копіювання може тривати довго.
- `scp -r` не є повноцінним інструментом синхронізації: для регулярного оновлення великих каталогів часто краще підходить `rsync`.

## 6. Копіювання кількох файлів

Можна передати декілька локальних файлів однією командою.

    scp ./index.html ./style.css ./app.js valeriy@server.example.com:/home/valeriy/app/

У цьому прикладі на сервер буде скопійовано три файли.

Також можна використовувати шаблони оболонки:

    scp ./logs/*.log valeriy@server.example.com:/home/valeriy/logs/

Тут локальна оболонка зазвичай розгортає `*.log` у список відповідних файлів до запуску `scp`.

Якщо ж шаблон має оброблятися на віддаленому боці, потрібно уважніше працювати з лапками та синтаксисом шляху.

### Копіювання всіх файлів певного типу

Наприклад, усіх файлів Markdown:

    scp ./*.md valeriy@server.example.com:/home/valeriy/docs/

Пам'ятай: якщо шаблон не відповідає жодному файлу, команда може завершитися помилкою.

## 7. Копіювання через нестандартний SSH-порт

За замовчуванням SSH використовує порт `22`.

Якщо сервер налаштований на інший порт, наприклад `2222`, у `scp` потрібно передати параметр `-P` — саме велику літеру.

### Завантаження файлу на сервер

    scp -P 2222 ./notes.txt valeriy@server.example.com:/home/valeriy/

### Завантаження файлу із сервера

    scp -P 2222 valeriy@server.example.com:/home/valeriy/notes.txt ./

### Важлива відмінність

У командах `ssh` і `scp` параметри порту різняться:

    ssh -p 2222 valeriy@server.example.com

    scp -P 2222 ./notes.txt valeriy@server.example.com:/home/valeriy/

Запам'ятай:

- `ssh` використовує малу `-p`;
- `scp` використовує велику `-P`.

Це одна з найпоширеніших дрібних помилок під час роботи з SSH-інструментами.

## 8. Використання приватного SSH-ключа

Якщо для автентифікації використовується приватний ключ, можна явно вказати його за допомогою `-i`.

### Копіювання на сервер

    scp -i ~/.ssh/id_ed25519 ./notes.txt valeriy@server.example.com:/home/valeriy/

### Завантаження із сервера

    scp -i ~/.ssh/id_ed25519 valeriy@server.example.com:/home/valeriy/notes.txt ./

Параметр `-i` задає шлях до приватного ключа.

Якщо ключ захищений passphrase, SSH може попросити її ввести або використати вже розблокований ключ через `ssh-agent`.

### Якщо ключ має іншу назву

Наприклад:

    scp -i ~/.ssh/id_ed25519_server ./notes.txt valeriy@server.example.com:/home/valeriy/

Використовуй саме той ключ, який відповідає налаштуванням віддаленого сервера.

### Перевір права доступу до ключа

    chmod 600 ~/.ssh/id_ed25519

Ця команда надає власнику право читання й запису, але прибирає доступ до файлу для групи та інших користувачів.

Не змінюй права приватного ключа без потреби, якщо вони вже налаштовані правильно.

**Ніколи не копіюй приватний ключ на віддалений сервер просто для того, щоб `scp` запрацював.** Приватний ключ зазвичай залишається на твоєму локальному комп'ютері.

## 9. Використання SSH-конфігурації

Якщо для сервера вже створено псевдонім у файлі `~/.ssh/config`, `scp` може використовувати його замість повного набору параметрів.

Наприклад, конфігурація:

    Host my-server
        HostName server.example.com
        User valeriy
        Port 2222
        IdentityFile ~/.ssh/id_ed25519_server
        IdentitiesOnly yes

Тоді замість довгої команди:

    scp -P 2222 -i ~/.ssh/id_ed25519_server ./notes.txt valeriy@server.example.com:/home/valeriy/

можна написати:

    scp ./notes.txt my-server:/home/valeriy/

SSH-клієнт автоматично використає налаштування псевдоніма `my-server`.

Завантаження файлу із сервера:

    scp my-server:/home/valeriy/notes.txt ./

### Чому це зручно

- не потрібно щоразу вводити адресу сервера;
- не потрібно постійно згадувати нестандартний порт;
- можна зберігати окремі налаштування для різних серверів;
- команди `ssh`, `scp` та інші SSH-інструменти можуть використовувати ту саму конфігурацію.

Докладніше налаштування `~/.ssh/config` розглядається в темі `02-ssh-configuration`.

## 10. Копіювання між двома віддаленими серверами

`scp` може копіювати файл з одного віддаленого сервера на інший.

Загальний синтаксис:

    scp USER1@HOST1:/path/to/source USER2@HOST2:/path/to/destination

Приклад:

    scp user1@server1.example.com:/tmp/report.txt user2@server2.example.com:/tmp/

Залежно від версії OpenSSH та параметрів команди передавання може виконуватися через локальний комп'ютер або безпосередньо між віддаленими хостами. Для керування цим у сучасному `scp` існує параметр `-R`, який запитує копіювання між віддаленими хостами через віддалений хост, що виконує команду.

    scp -R user1@server1.example.com:/tmp/report.txt user2@server2.example.com:/tmp/

Використовуй `-R` лише тоді, коли розумієш, який хост ініціюватиме з'єднання до іншого сервера.

У такому сценарії потрібно врахувати:

- чи доступний другий сервер із першого;
- чи є потрібні ключі та облікові дані на відповідному хості;
- чи дозволяє SSH-конфігурація потрібне з'єднання;
- чи має віддалений користувач право читати джерело та записувати результат.

Якщо потрібне передавання з повним контролем над потоком даних, часто простіше завантажити файл на локальний комп'ютер, а потім передати його на інший сервер двома окремими командами.

## 11. Корисні параметри `scp`

| Параметр | Призначення |
|---|---|
| `-r` | Рекурсивно копіювати каталоги |
| `-P PORT` | Вказати порт SSH-сервера |
| `-i FILE` | Використати конкретний приватний ключ |
| `-v` | Показати докладну діагностичну інформацію |
| `-p` | Зберегти час модифікації, час доступу та режими файлів у межах можливостей системи |
| `-q` | Приховати індикатор прогресу та більшість діагностичних повідомлень |
| `-C` | Увімкнути стиснення під час передавання |
| `-l LIMIT` | Обмежити швидкість передавання в Kbit/s |
| `-F FILE` | Використати альтернативний SSH-конфігураційний файл |
| `-o OPTION=VALUE` | Передати параметр SSH |
| `-J HOST` | Підключатися через проміжний SSH-хост |
| `-O` | Використати застарілий SCP-протокол замість SFTP |
| `-R` | Для копіювання між віддаленими хостами запросити виконання передавання з віддаленого боку |

### Приклад: докладна діагностика

    scp -v ./notes.txt valeriy@server.example.com:/home/valeriy/

### Приклад: обмеження швидкості

    scp -l 1000 ./large-file.zip valeriy@server.example.com:/home/valeriy/

Значення `1000` задає приблизний ліміт у 1000 Kbit/s, а не 1000 KB/s.

### Приклад: стиснення

    scp -C ./large-file.txt valeriy@server.example.com:/home/valeriy/

Стиснення може допомогти для текстових файлів, але не обов'язково пришвидшить передавання вже стиснених файлів, наприклад ZIP-архівів.

### Приклад: параметр SSH

    scp -o ConnectTimeout=10 ./notes.txt valeriy@server.example.com:/home/valeriy/

Команда обмежує час очікування встановлення з'єднання.

### Приклад: проміжний SSH-хост

    scp -J jumpuser@bastion.example.com ./notes.txt deploy@private.example.com:/tmp/

Параметр `-J` дозволяє пройти через проміжний SSH-сервер. Він корисний, коли цільовий сервер доступний лише з внутрішньої мережі.

## 12. Як працюють відносні та абсолютні шляхи

Під час роботи з `scp` важливо розрізняти локальні та віддалені шляхи.

### Відносний локальний шлях

    scp ./notes.txt valeriy@server.example.com:/tmp/

`./notes.txt` означає файл у поточному локальному каталозі.

### Абсолютний локальний шлях

    scp /home/valeriy/notes.txt valeriy@server.example.com:/tmp/

`/home/valeriy/notes.txt` — абсолютний шлях у локальній файловій системі.

### Віддалений шлях

    scp ./notes.txt valeriy@server.example.com:/home/valeriy/docs/

Після двокрапки вказується шлях на віддаленому комп'ютері.

### Символ `~`

У віддаленому шляху `~` може позначати домашній каталог віддаленого користувача.

Наприклад:

    scp ./notes.txt valeriy@server.example.com:~/docs/

Це зазвичай означає каталог `docs` у домашньому каталозі користувача `valeriy`.

Якщо шлях містить пробіли або спеціальні символи, потрібно правильно використовувати лапки та враховувати, яка оболонка обробляє цей рядок.

## 13. Копіювання файлів проєкту на сервер

Розглянемо практичний приклад із Node.js-проєктом.

Локальна структура:

    my-app/
    ├── package.json
    ├── package-lock.json
    ├── server.js
    └── README.md

Щоб скопіювати каталог на сервер:

    scp -r ./my-app valeriy@server.example.com:/home/valeriy/

Після копіювання на сервері очікується така структура:

    /home/valeriy/
    └── my-app/
        ├── package.json
        ├── package-lock.json
        ├── server.js
        └── README.md

### Чи потрібно копіювати `node_modules`

Для звичайного навчального або робочого Node.js-проєкту зазвичай не варто передавати `node_modules` через `scp`.

Краще передати файли проєкту та lock-файл, а залежності встановити на сервері:

    cd ~/my-app
    npm ci

Команда `npm ci` потребує коректного lock-файлу та сумісного середовища.

### Передавання вибраних файлів

    scp ./package.json ./package-lock.json ./server.js valeriy@server.example.com:/home/valeriy/my-app/

Це дозволяє передавати лише потрібні файли, не копіюючи весь каталог.

### Важливе зауваження

`scp` лише копіює файли. Він не:

- встановлює Node.js;
- встановлює залежності;
- запускає застосунок;
- налаштовує `systemd`;
- відкриває порт у firewall;
- налаштовує вебсервер або HTTPS.

Ці операції виконуються окремо.

## 14. SCP чи SFTP чи RSYNC?

Усі три інструменти можуть використовувати SSH, але призначені для різних сценаріїв.

| Інструмент | Для чого найкраще підходить |
|---|---|
| `scp` | Просте копіювання файлів і каталогів |
| `sftp` | Інтерактивне передавання та керування файлами на віддаленій стороні |
| `rsync` | Синхронізація каталогів, повторне передавання змінених даних, ефективне оновлення |
| `ssh` | Віддалений термінал і виконання команд |

### Коли вибирати `scp`

Коли потрібно швидко передати один файл:

    scp ./backup.sql valeriy@server.example.com:/home/valeriy/backups/

### Коли вибирати `sftp`

Коли потрібно інтерактивно переглядати віддалені каталоги та завантажувати або відправляти файли:

    sftp valeriy@server.example.com

### Коли вибирати `rsync`

Коли потрібно регулярно синхронізувати проєкт:

    rsync -av ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

Для перевірки змін перед синхронізацією:

    rsync -av --dry-run ./my-app/ valeriy@server.example.com:/home/valeriy/my-app/

### Що потрібно запам'ятати

`scp` — простий інструмент копіювання. Якщо ти постійно оновлюєш великий проєкт на сервері, `rsync` часто буде зручнішим.

## 15. Типові помилки SCP

### `No such file or directory`

Приклад:

    scp: stat local "./notes.txt": No such file or directory

Можливі причини:

- локального файлу не існує;
- команда виконується не з того каталогу;
- неправильно вказано шлях;
- помилка в назві файлу.

Перевір локальний каталог:

    pwd
    ls -la

### `Permission denied`

Можливі причини:

- неправильне ім'я користувача;
- відсутні права на читання локального джерела;
- немає прав на запис у віддалений каталог;
- не пройшла SSH-автентифікація.

Перевір підключення окремо:

    ssh valeriy@server.example.com

Якщо SSH-підключення не працює, спочатку виправ його, а потім повторюй `scp`.

### `Connection refused`

Можливі причини:

- SSH-сервер не працює;
- вказано неправильний порт;
- сервер відхиляє підключення.

Якщо маєш доступ до сервера іншим способом, перевір:

    sudo systemctl status ssh

### `Connection timed out`

Можливі причини:

- сервер недоступний через мережу;
- firewall блокує порт;
- неправильна адреса;
- немає потрібного мережевого маршруту.

### `Host key verification failed`

SSH не зміг підтвердити ключ хоста або перевірка ключа завершилася помилкою.

Перевір адресу та fingerprint сервера. Не вимикай перевірку ключа лише для усунення повідомлення.

### `Permission denied (publickey)`

Можливі причини:

- використовується неправильний приватний ключ;
- відкритий ключ не встановлений на сервері;
- вибрано неправильного користувача;
- права доступу до ключів або каталогів налаштовані неправильно.

Перевір діагностику:

    scp -v ./notes.txt valeriy@server.example.com:/home/valeriy/

За потреби перевір саме SSH:

    ssh -v valeriy@server.example.com

### Каталог призначення не існує

Наприклад, команда:

    scp ./notes.txt valeriy@server.example.com:/home/valeriy/new-folder/

може завершитися помилкою, якщо каталогу `new-folder` немає.

Створи каталог на сервері:

    ssh valeriy@server.example.com 'mkdir -p ~/new-folder'

Потім повтори копіювання:

    scp ./notes.txt valeriy@server.example.com:~/new-folder/

## 16. Безпека під час використання SCP

Оскільки `scp` використовує SSH, для нього важливі ті самі основні правила безпеки.

### Основні правила

✔ Перевіряй адресу сервера перед копіюванням.

✔ Не ігноруй попередження про зміну ключа хоста.

✔ Не передавай приватні SSH-ключі на сервер без обґрунтованої потреби.

✔ Використовуй окремі облікові записи з необхідними правами.

✔ Не копіюй конфіденційні файли у відкриті або загальнодоступні каталоги.

✔ Перевіряй шлях призначення перед передаванням важливих даних.

✔ Не вважай успішне копіювання гарантією правильного розгортання застосунку.

✔ Для великих або важливих копіювань перевіряй результат на стороні призначення.

### Перевірка результату

Після копіювання можна перевірити наявність файлу:

    ssh valeriy@server.example.com 'ls -l ~/notes.txt'

Або прочитати його вміст:

    ssh valeriy@server.example.com 'cat ~/notes.txt'

Для бінарних файлів або резервних копій краще перевіряти контрольні суми:

    sha256sum ./backup.tar.gz

На сервері:

    ssh valeriy@server.example.com 'sha256sum ~/backup.tar.gz'

Контрольні суми мають збігатися, якщо файл скопійовано без змін.

## 17. Практика: передавання файлів між Ubuntu та сервером

Виконуй цю практику, коли маєш доступ до власного Linux-сервера або тестової віртуальної машини з SSH.

### Крок 1. Створи тестовий файл

    echo "SCP practice" > scp-test.txt

Перевір його:

    cat scp-test.txt

### Крок 2. Скопіюй файл на сервер

    scp ./scp-test.txt USER@SERVER:/tmp/

Заміни `USER` та `SERVER` на реальні дані свого сервера.

### Крок 3. Перевір файл на сервері

    ssh USER@SERVER 'cat /tmp/scp-test.txt'

Очікуваний результат:

    SCP practice

### Крок 4. Завантаж файл назад

    scp USER@SERVER:/tmp/scp-test.txt ./scp-test-downloaded.txt

### Крок 5. Порівняй файли

    cmp ./scp-test.txt ./scp-test-downloaded.txt

Якщо команда нічого не вивела й завершилася з кодом `0`, файли однакові.

Перевір код завершення:

    echo $?

### Крок 6. Створи каталог і скопіюй його

    mkdir -p scp-practice
    echo "First file" > scp-practice/first.txt
    echo "Second file" > scp-practice/second.txt

Скопіюй каталог:

    scp -r ./scp-practice USER@SERVER:/tmp/

Перевір його вміст:

    ssh USER@SERVER 'ls -la /tmp/scp-practice'

### Крок 7. Спробуй копіювання з нестандартним портом

    scp -P 2222 ./scp-test.txt USER@SERVER:/tmp/

Виконуй цю команду лише тоді, коли твій сервер справді використовує порт `2222`.

### Крок 8. Увімкни діагностику

    scp -v ./scp-test.txt USER@SERVER:/tmp/

Знайди виведення про встановлення SSH-з'єднання, автентифікацію та передавання файлу.

## 20. Мінішпаргалка

    # Скопіювати файл на сервер
    scp ./file.txt USER@HOST:/tmp/

    # Завантажити файл із сервера
    scp USER@HOST:/tmp/file.txt ./

    # Скопіювати каталог
    scp -r ./project USER@HOST:/home/USER/

    # Скопіювати кілька файлів
    scp ./index.html ./style.css ./app.js USER@HOST:/tmp/

    # Використати нестандартний порт
    scp -P 2222 ./file.txt USER@HOST:/tmp/

    # Використати конкретний приватний ключ
    scp -i ~/.ssh/id_ed25519 ./file.txt USER@HOST:/tmp/

    # Увімкнути діагностику
    scp -v ./file.txt USER@HOST:/tmp/

    # Обмежити швидкість передавання
    scp -l 1000 ./large-file.zip USER@HOST:/tmp/

    # Скопіювати через проміжний сервер
    scp -J jumpuser@bastion.example.com ./file.txt USER@HOST:/tmp/

    # Перевірити віддалений файл
    ssh USER@HOST 'ls -l /tmp/file.txt'

    # Перевірити контрольну суму локального файлу
    sha256sum ./file.txt

    # Перевірити контрольну суму віддаленого файлу
    ssh USER@HOST 'sha256sum /tmp/file.txt'

## 21. Головні правила

1. `scp` — інструмент копіювання файлів через SSH.
2. Загальний синтаксис — `scp SOURCE DESTINATION`.
3. Щоб копіювати каталог, використовуй `-r`.
4. Для нестандартного SSH-порту в `scp` використовуй велику `-P`.
5. Для конкретного приватного ключа використовуй `-i`.
6. SSH-псевдоніми з `~/.ssh/config` можуть спростити команди копіювання.
7. `scp` копіює файли, але не встановлює залежності й не запускає застосунки.
8. Для регулярної синхронізації каталогів часто зручніший `rsync`.
9. Для діагностики використовуй `scp -v` та, за потреби, окремо перевіряй `ssh`.
10. Для важливих файлів перевіряй результат копіювання та контрольні суми.

**Основна ідея:** `scp` допомагає безпечно передавати файли між локальним Linux-комп'ютером і віддаленим сервером. Це корисна навичка для резервного копіювання, адміністрування серверів і розгортання вебзастосунків.
