# 02. head-tail

`head` і `tail` — команди Linux для перегляду початку та кінця текстових файлів.

Вони особливо корисні під час роботи з логами, конфігураціями, результатами виконання програм і великими файлами, коли не потрібно читати весь вміст.

Команди використовуються, коли потрібно:

- переглянути перші рядки файлу;
- переглянути останні рядки файлу;
- обмежити кількість рядків у виведенні;
- переглянути початок або кінець великого файлу;
- стежити за новими записами в журналі;
- перевірити, як змінюється лог під час роботи програми;
- переглянути частину результату іншої команди;
- поєднати перегляд файлів із `grep`, `sort` та іншими інструментами.

Основні команди:

    head
    tail

Також варто знати:

    cat
    less
    grep
    wc
    sort
    uniq

Команди `cat` і `less` розглядаються в попередньому розділі:

    01-cat-less

## Що потрібно пам'ятати

• `head` показує початок файлу.

• `tail` показує кінець файлу.

• За замовчуванням обидві команди виводять по 10 рядків.

• `head -n 5 file.txt` показує перші 5 рядків.

• `tail -n 5 file.txt` показує останні 5 рядків.

• `head -n 20 file.txt` і `tail -n 20 file.txt` обмежують виведення двадцятьма рядками.

• Параметр `-c` дозволяє працювати з кількістю байтів, а не рядків.

• `tail -f application.log` дозволяє стежити за новими записами у файлі.

• `tail -F application.log` додатково намагається повторно відкрити файл, якщо його видалили або замінили, наприклад під час ротації логів.

• `Ctrl + C` зазвичай завершує роботу `tail -f` і повертає до командного рядка.

• `head` і `tail` можуть читати дані зі стандартного вводу, якщо файл не вказано.

• Обидві команди можна використовувати з pipe.

• `head` і `tail` не редагують файл під час звичайного перегляду.

• Для великих журналів `tail -f` часто зручніший за постійне повторне виконання `cat`.

• Якщо потрібно прочитати весь файл із навігацією та пошуком, краще використати `less`.

# head

`head` — команда Linux для виведення початку файлу.

Основний синтаксис:

    head [OPTIONS] [FILE...]

Якщо параметри не вказані, команда виводить перші 10 рядків кожного файлу.

Наприклад:

    head notes.txt

Якщо файл містить:

    Linux
    Bash
    Terminal
    Files
    Directories
    Permissions
    Processes
    Services
    Networking
    Packages
    Storage
    Logs

Результат:

    Linux
    Bash
    Terminal
    Files
    Directories
    Permissions
    Processes
    Services
    Networking
    Packages

За замовчуванням останні два рядки не виводяться.

---

# head -n

Параметр `-n` задає кількість рядків, які потрібно показати.

Синтаксис:

    head -n NUMBER file.txt

Наприклад:

    head -n 3 notes.txt

Результат:

    Linux
    Bash
    Terminal

Тут:

    -n 3 → показати перші 3 рядки

---

## Перегляд перших 5 рядків

    head -n 5 application.log

Команда покаже перші п'ять рядків журналу.

Це зручно, коли потрібно перевірити:

- формат файлу;
- заголовки;
- структуру CSV;
- початкові повідомлення програми;
- початок конфігурації.

---

## Перегляд одного рядка

    head -n 1 file.txt

Показує лише перший рядок файлу.

Це може бути корисно для перегляду заголовка CSV-файлу.

Наприклад, файл `users.csv`:

    id,name,email
    1,John,john@example.com
    2,Anna,anna@example.com
    3,Peter,peter@example.com

Команда:

    head -n 1 users.csv

Результат:

    id,name,email

---

## Короткий запис -n

У GNU `head` можна використовувати коротку форму:

    head -n 5 file.txt

Але для навчання краще спочатку звикнути до зрозумілого варіанта `-n`.

---

# head -c

Параметр `-c` задає кількість байтів, які потрібно вивести з початку файлу.

Синтаксис:

    head -c NUMBER file.txt

Наприклад:

    head -c 10 notes.txt

Команда виведе перші 10 байтів файлу.

Важливо розрізняти:

    -n → кількість рядків
    -c → кількість байтів

Байт не завжди дорівнює одному символу. Наприклад, символи української абетки в UTF-8 зазвичай займають більше одного байта.

Тому `head -c 10` може завершити виведення посеред багатобайтового символу.

Параметр `-c` корисний для роботи з байтовими фрагментами, але для звичайного читання тексту частіше використовують `-n`.

---

# head -q

Параметр `-q` вимикає заголовки з іменами файлів, коли передано кілька файлів.

Наприклад:

    head -q first.txt second.txt

Команда виведе початок обох файлів без додаткових заголовків.

Це корисно, коли потрібно отримати тільки текст.

---

# head -v

Параметр `-v` змушує показувати назву файлу перед його вмістом, навіть якщо передано лише один файл.

Наприклад:

    head -v notes.txt

Виведення матиме заголовок із назвою файлу.

Це допомагає розрізняти результати під час роботи з кількома файлами.

---

# head: кілька файлів

`head` може приймати кілька файлів.

    head -n 3 first.txt second.txt

Команда виведе перші три рядки кожного файла.

За замовчуванням GNU `head` додає заголовки з назвами файлів, щоб можна було зрозуміти, до якого файла належить кожен фрагмент.

Щоб прибрати ці заголовки:

    head -q -n 3 first.txt second.txt

Щоб примусово показувати заголовки:

    head -v -n 3 first.txt second.txt

---

# tail

`tail` — команда Linux для виведення кінця файлу.

Основний синтаксис:

    tail [OPTIONS] [FILE...]

Якщо параметри не вказані, команда виводить останні 10 рядків.

Наприклад:

    tail notes.txt

Якщо файл містить:

    Linux
    Bash
    Terminal
    Files
    Directories
    Permissions
    Processes
    Services
    Networking
    Packages
    Storage
    Logs

Результат:

    Terminal
    Files
    Directories
    Permissions
    Processes
    Services
    Networking
    Packages
    Storage
    Logs

Перші два рядки не виводяться.

---

# tail -n

Параметр `-n` задає кількість останніх рядків.

Синтаксис:

    tail -n NUMBER file.txt

Наприклад:

    tail -n 3 notes.txt

Результат:

    Packages
    Storage
    Logs

---

## Перегляд останніх 5 рядків

    tail -n 5 application.log

Команда покаже останні п'ять рядків журналу.

Це зручно, коли потрібно перевірити:

- останні повідомлення програми;
- результати останнього запуску;
- помилки наприкінці журналу;
- завершення процесу;
- останні записи у звіті.

---

## Перегляд останнього рядка

    tail -n 1 application.log

Показує тільки останній рядок файлу.

Це корисно, коли потрібно швидко перевірити останній запис.

---

# tail -c

Параметр `-c` дозволяє вивести останні байти файлу.

    tail -c 20 notes.txt

Команда покаже останні 20 байтів.

Порівняння:

    head -c 20 file.txt → перші 20 байтів
    tail -c 20 file.txt → останні 20 байтів

Як і з `head -c`, пам'ятай, що кількість байтів не завжди відповідає кількості символів.

---

# tail -f

`tail -f` — одна з найважливіших команд для роботи з логами.

Параметр `-f` означає *follow* — стежити за доповненням файла.

Синтаксис:

    tail -f application.log

Команда:

1. Виводить останні рядки файла.
2. Продовжує працювати.
3. Очікує на появу нових даних у файлі.
4. Виводить нові рядки в міру їх додавання.

Це дозволяє спостерігати за роботою програми в реальному часі.

---

## Приклад роботи tail -f

Створи файл журналу:

    touch application.log

Запусти:

    tail -f application.log

Команда залишиться активною та чекатиме на нові записи.

Відкрий другий термінал у тому самому каталозі й виконай:

    echo "Application started" >> application.log

У першому терміналі з'явиться:

    Application started

Додай ще один запис у другому терміналі:

    echo "User connected" >> application.log

У першому терміналі з'явиться:

    User connected

Таким чином можна спостерігати за новими повідомленнями без повторного відкриття файла.

Щоб завершити стеження:

    Ctrl + C

Важливо: `tail -f` не запускає програму й не генерує лог самостійно. Він лише стежить за змінами файла.

---

# tail -F

Параметр `-F` призначений для стеження за файлом із повторним відкриттям у разі його заміни або повторного створення.

    tail -F application.log

Це особливо корисно для журналів, які проходять через процес ротації логів.

Наприклад, система може:

1. перейменувати старий лог;
2. створити новий файл із тією самою назвою;
3. продовжити запис подій у новий файл.

У такій ситуації звичайний `tail -f` може продовжувати читати старий відкритий файл, залежно від того, як саме його замінили.

`tail -F` повторно перевіряє файл за його назвою та намагається відкрити його знову.

Порівняння:

    tail -f file.log → стежити за доповненням відкритого файла
    tail -F file.log → стежити з повторним відкриттям файла

`-F` є розширеним режимом GNU `tail`, еквівалентним поєднанню логіки `--follow=name` та `--retry`.

---

# tail -s

Параметр `-s` задає інтервал перевірки файла в секундах у режимі стеження.

Наприклад:

    tail -f -s 2 application.log

Команда перевірятиме появу нових даних з інтервалом приблизно дві секунди.

Типова поведінка залежить від реалізації та параметрів команди.

Цей параметр не означає, що записи створюються кожні дві секунди. Він визначає інтервал перевірки змін файла в режимі стеження.

---

# tail -n +NUMBER

Це важливий варіант `tail`.

Зазвичай:

    tail -n 5 file.txt

означає:

    показати останні 5 рядків

Але команда:

    tail -n +5 file.txt

означає:

    показати файл, починаючи з рядка № 5

Наприклад, файл:

    one
    two
    three
    four
    five
    six

Команда:

    tail -n +3 file.txt

Результат:

    three
    four
    five
    six

Тобто:

    tail -n 3 file.txt  → останні 3 рядки
    tail -n +3 file.txt → від третього рядка до кінця

Не плутай ці два варіанти.

---

# head -n -NUMBER

У GNU `head` є ще один корисний варіант:

    head -n -NUMBER file.txt

Він виводить увесь файл, крім останніх `NUMBER` рядків.

Наприклад:

    head -n -2 file.txt

Якщо файл містить:

    one
    two
    three
    four
    five

Результат:

    one
    two
    three

Останні два рядки не виводяться.

Це розширення GNU. На інших Unix-подібних системах підтримка такого синтаксису може відрізнятися.

---

# head і tail разом

Команди можна комбінувати для отримання потрібного фрагмента файла.

Наприклад, щоб подивитися перші 5 рядків:

    head -n 5 file.txt

Щоб подивитися останні 5 рядків:

    tail -n 5 file.txt

Якщо потрібно переглянути рядки з 11-го по 15-й, можна використати:

    tail -n +11 file.txt | head -n 5

Логіка:

    tail -n +11 file.txt
        ↓
    вивести рядки від 11-го до кінця
        ↓
    head -n 5
        ↓
    залишити перші 5 рядків цього потоку

Результат — рядки з 11-го по 15-й, якщо файл має достатню кількість рядків.

Цей прийом корисний для роботи з великими текстовими файлами.

---

# head і tail зі стандартним вводом

Якщо файл не вказано, обидві команди можуть читати дані зі стандартного вводу.

Наприклад:

    printf 'one\ntwo\nthree\nfour\nfive\n' | head -n 2

Результат:

    one
    two

Тут:

    printf → створює текстовий потік
    |      → передає його наступній команді
    head   → показує перші 2 рядки

Інший приклад:

    printf 'one\ntwo\nthree\nfour\nfive\n' | tail -n 2

Результат:

    four
    five

---

# head і tail з іншими командами

`head` і `tail` часто використовуються в конвеєрах команд.

## Приклад 1 — перші рядки списку

    ls -la | head -n 5

Команда показує перші п'ять рядків виводу `ls -la`.

Зверни увагу: список може містити службові рядки та заголовки, залежно від команди й середовища.

---

## Приклад 2 — останні рядки списку

    ls -la | tail -n 5

Показує останні п'ять рядків результату.

---

## Приклад 3 — перші рядки після сортування

    sort names.txt | head -n 5

Спочатку `sort` сортує вміст, а потім `head` показує перші п'ять рядків відсортованого результату.

---

## Приклад 4 — останні рядки після сортування

    sort names.txt | tail -n 5

Показує останні п'ять рядків відсортованого результату.

---

## Приклад 5 — знайти останні помилки

    grep -i 'error' application.log | tail -n 10

Команда:

1. знаходить рядки, що містять `error`, без урахування регістру;
2. передає знайдені рядки до `tail`;
3. показує останні десять збігів у потоці.

Це не обов'язково останні десять рядків усього файла, а саме останні десять рядків, які відповідають пошуку.

Команда `grep` детально розглядається в розділі:

    03-grep

# Перегляд логів Linux

Логи — це файли або системні записи, які містять інформацію про роботу програм і служб.

Вони допомагають досліджувати:

- помилки;
- запуски програм;
- підключення;
- роботу серверів;
- системні події;
- проблеми конфігурації.

Приклади лог-файлів:

    /var/log/syslog
    /var/log/auth.log
    /var/log/kern.log

Наявність і назви файлів залежать від дистрибутива та конфігурації.

---

## Переглянути останні рядки логу

    tail -n 20 /var/log/syslog

Команда показує останні двадцять рядків, якщо файл існує та доступний для читання.

---

## Стежити за новими записами

    tail -f /var/log/syslog

Команда виводить останні рядки та продовжує показувати нові записи.

Для системного файла може знадобитися:

    sudo tail -f /var/log/syslog

Не запускай `sudo` без необхідності.

---

## Переглянути журнал автентифікації

    sudo tail -n 20 /var/log/auth.log

У деяких системах цей файл відсутній або використовується інший механізм журналювання.

Якщо файл недоступний, це не означає автоматично, що система не записує події автентифікації.

---

## Журнали systemd

На системах із `systemd` можна використовувати `journalctl`.

Наприклад:

    journalctl -n 20

Показує останні двадцять записів системного журналу, доступних поточному користувачу.

Для стеження за новими записами:

    journalctl -f

Це аналогічний за призначенням підхід до перегляду журналу в реальному часі, але `journalctl` працює із системним журналом, а не з довільним текстовим файлом.

Для журналу конкретної служби можна використовувати:

    journalctl -u ssh

Назва служби залежить від системи. У деяких дистрибутивах служба SSH називається `sshd`.

# Міні-проєкт: моніторинг логу

Мета — навчитися стежити за змінами текстового файла та переглядати останні повідомлення.

Створи каталог:

    mkdir -p ~/linux-practice/log-monitor
    cd ~/linux-practice/log-monitor

Створи журнал:

    printf 'Application started\nUser logged in\nRequest processed\n' > application.log

Переглянь останні записи:

    tail -n 5 application.log

Запусти моніторинг:

    tail -f application.log

В іншому терміналі додай повідомлення:

    echo "New request received" >> ~/linux-practice/log-monitor/application.log

Додай ще одне:

    echo "Request completed" >> ~/linux-practice/log-monitor/application.log

Переконайся, що обидва повідомлення з'явилися в першому терміналі.

Заверши моніторинг за допомогою `Ctrl + C`.

Після цього виконай:

    tail -n 3 ~/linux-practice/log-monitor/application.log

Перевір останні три записи.

### Що ти маєш зрозуміти

- `tail -n` переглядає останні рядки;
- `tail -f` продовжує стежити за доповненням файла;
- `echo ... >> file` додає текст у кінець файла;
- два термінали можуть працювати з одним файлом одночасно;
- команда моніторингу не створює нові записи самостійно.

---

# Типові помилки

## ❌ Плутати head і tail

    head file.txt → початок файла
    tail file.txt → кінець файла

---

## ❌ Вважати, що за замовчуванням виводиться весь файл

    head file.txt
    tail file.txt

Обидві команди за замовчуванням показують по десять рядків, а не весь файл.

---

## ❌ Плутати -n 5 та -n +5

    tail -n 5 file.txt

Показує останні п'ять рядків.

    tail -n +5 file.txt

Показує файл, починаючи з п'ятого рядка.

---

## ❌ Очікувати, що tail -f завершиться самостійно

    tail -f application.log

Зазвичай команда продовжує працювати, доки її не зупинити або не виникне помилка.

Для завершення натисни:

    Ctrl + C

---

## ❌ Вважати, що tail -f генерує дані

`tail -f` лише спостерігає за файлом.

Якщо ніхто не додає нових даних, нових рядків не буде.

---

## ❌ Плутати байти та символи

    head -c 10 file.txt

Показує перші десять байтів, а не обов'язково десять символів.

Для текстових файлів із багатомовними символами ця різниця особливо важлива.

---

## ❌ Вважати, що tail -f завжди відстежує файл після ротації

Після заміни файла звичайний режим `-f` може продовжити стежити за старим відкритим файлом.

Для типового сценарію ротації логів використовують:

    tail -F application.log

---

## ❌ Використовувати абсолютні шляхи без перевірки

Наприклад:

    tail /var/log/syslog

Файл може бути відсутній у конкретному дистрибутиві.

Спочатку перевіряй доступність файла та враховуй особливості своєї системи.

---

## ❌ Використовувати sudo без потреби

Спочатку спробуй:

    tail -n 20 application.log

Якщо файл системний і доступ заборонений, тоді можна розглянути використання `sudo`.

# Міні-шпаргалка

## head

    head file.txt

Перші 10 рядків.

    head -n 5 file.txt

Перші 5 рядків.

    head -n 1 file.txt

Перший рядок.

    head -c 20 file.txt

Перші 20 байтів.

    head -n -2 file.txt

У GNU `head` — увесь файл, крім останніх двох рядків.

---

## tail

    tail file.txt

Останні 10 рядків.

    tail -n 5 file.txt

Останні 5 рядків.

    tail -n 1 file.txt

Останній рядок.

    tail -c 20 file.txt

Останні 20 байтів.

    tail -n +5 file.txt

Від п'ятого рядка до кінця.

---

## Моніторинг

    tail -f application.log

Стежити за новими записами.

    tail -F application.log

Стежити з повторним відкриттям файла після його заміни або повторного створення.

    Ctrl + C

Зупинити стеження.

---

## Pipe

    grep -i 'error' application.log | tail -n 5

Показати останні п'ять знайдених рядків із `error`.

    tail -n +11 file.txt | head -n 5

Показати рядки з 11-го по 15-й.

    ls -la | head -n 5

Показати перші п'ять рядків виводу команди.

---

## Основні правила

    head → початок файла
    tail → кінець файла
    -n   → кількість рядків
    -c   → кількість байтів
    -f   → стеження за доповненням файла
    -F   → стеження з повторним відкриттям
    |    → передавання виводу наступній команді
    Ctrl + C → зупинка моніторингу

# Головне

• `head` показує початок файла, а `tail` — його кінець.

• За замовчуванням обидві команди виводять десять рядків.

• `-n` задає кількість рядків, а `-c` — кількість байтів.

• `tail -n 5` показує останні п'ять рядків.

• `tail -n +5` показує файл, починаючи з п'ятого рядка.

• У GNU/Linux `head -n -2` дозволяє вивести файл без останніх двох рядків.

• `tail -f` використовується для спостереження за новими записами в логах.

• `tail -F` корисний, коли файл може бути замінений під час ротації логів.

• `Ctrl + C` зазвичай завершує режим моніторингу.

• `head` і `tail` можуть читати дані зі стандартного вводу.

• За допомогою pipe можна комбінувати їх із `grep`, `sort` та іншими командами.

• Команди особливо корисні під час діагностики програм і серверів.

• Для системного журналу, керованого `systemd`, корисно також знати `journalctl`.
