# 03. grep — пошук тексту у файлах

`grep` — це команда Linux для пошуку рядків, які відповідають заданому тексту або шаблону, у файлах і потоці даних.

За допомогою `grep` можна шукати слова в конфігураційних файлах, знаходити помилки в логах, фільтрувати результати інших команд, шукати потрібні рядки в коді та працювати з регулярними виразами.

Для розробника `grep` — один з основних інструментів роботи з терміналом. Він допомагає швидко знаходити потрібну інформацію без відкривання файлів у редакторі.

## ✔ Основні поняття

- `grep` — пошук тексту за шаблоном.
- `grep "text" file.txt` — пошук тексту у файлі.
- `-i` — пошук без урахування регістру.
- `-n` — показувати номери рядків.
- `-v` — показувати рядки, які НЕ відповідають шаблону.
- `-r` / `-R` — рекурсивний пошук у каталогах.
- `-l` — показувати тільки назви файлів, у яких знайдено збіг.
- `-c` — підраховувати кількість рядків зі збігами.
- `-w` — шукати ціле слово.
- `-x` — шукати рядки, які повністю відповідають шаблону.
- `-E` — використовувати розширені регулярні вирази.
- `-F` — шукати буквальний текст, а не регулярний вираз.
- `-o` — показувати тільки знайдені фрагменти.
- `--color=auto` — підсвічувати знайдені збіги.
- `| grep` — фільтрувати результат іншої команди.
- `grep` повертає код завершення `0`, якщо знайдено збіг, `1`, якщо збігів немає, і зазвичай `2` у разі помилки.

## 1. Базовий синтаксис

Загальний синтаксис команди:

    grep [OPTIONS] PATTERN [FILE...]

Де:

- `grep` — команда пошуку.
- `OPTIONS` — необов'язкові параметри пошуку.
- `PATTERN` — текст або шаблон, який потрібно знайти.
- `FILE` — один або декілька файлів.

Наприклад, створимо тестовий файл:

    mkdir -p ~/linux-practice/grep
    cd ~/linux-practice/grep

    printf 'Linux is powerful\nJavaScript is popular\nLinux is flexible\nPython is useful\n' > languages.txt

Вміст `languages.txt`:

    Linux is powerful
    JavaScript is popular
    Linux is flexible
    Python is useful

Шукаємо слово `Linux`:

    grep "Linux" languages.txt

Результат:

    Linux is powerful
    Linux is flexible

`grep` виводить тільки ті рядки, у яких знайдено збіг.

### 1.1. Пошук тексту у декількох файлах

Створимо ще один файл:

    printf 'Linux server\nNode.js backend\nLinux terminal\n' > technologies.txt

Шукаємо `Linux` у двох файлах:

    grep "Linux" languages.txt technologies.txt

Результат міститиме назви файлів і знайдені рядки, наприклад:

    languages.txt:Linux is powerful
    languages.txt:Linux is flexible
    technologies.txt:Linux server
    technologies.txt:Linux terminal

Якщо пошук виконується в одному файлі, назва файлу зазвичай не виводиться. Для кількох файлів `grep` зазвичай додає назву файлу перед знайденим рядком.

### 1.2. Пошук у стандартному введенні

Якщо не вказувати файл, `grep` може читати дані зі стандартного введення — наприклад, із клавіатури або каналу `|`.

    printf 'Linux\nWindows\nUbuntu\nmacOS\n' | grep "Linux"

Результат:

    Linux

Цей спосіб особливо корисний для фільтрації результатів інших команд.

## 2. Пошук без урахування регістру — `-i`

За замовчуванням `grep` розрізняє великі й малі літери.

    printf 'Linux\nlinux\nLINUX\n' > case.txt

Звичайний пошук:

    grep "Linux" case.txt

Результат:

    Linux

Пошук без урахування регістру:

    grep -i "linux" case.txt

Результат:

    Linux
    linux
    LINUX

**Коли використовувати:**

- коли невідомо, як написано слово;
- під час пошуку назв технологій;
- під час аналізу логів;
- коли текст може містити різний регістр.

## 3. Номери рядків — `-n`

Параметр `-n` додає номер кожного знайденого рядка.

    grep -n "Linux" languages.txt

Приклад результату:

    1:Linux is powerful
    3:Linux is flexible

Нумерація починається з `1`.

Це зручно, коли потрібно швидко перейти до потрібного рядка у файлі.

### 3.1. Номери рядків і регістр

Параметри можна комбінувати:

    grep -in "linux" case.txt

Команда одночасно:

- шукає без урахування регістру;
- показує номери рядків.

Загальне правило: багато параметрів `grep` можна поєднувати в одній команді.

## 4. Пошук цілих слів — `-w`

Звичайний пошук підрядка може знаходити збіги всередині інших слів.

Створимо файл:

    printf 'cat\ncategory\nconcatenate\nmy cat sleeps\n' > words.txt

Звичайний пошук:

    grep "cat" words.txt

Знайде всі чотири рядки, оскільки послідовність `cat` присутня в кожному з них.

Пошук цілого слова:

    grep -w "cat" words.txt

Результат:

    cat
    my cat sleeps

`-w` корисний, коли потрібно знайти саме слово, а не його частину.

**Важливо:** поняття «ціле слово» в `grep` визначається межами слова, а не обов'язково правилами природної мови.

## 5. Пошук рядків, які повністю відповідають шаблону — `-x`

Параметр `-x` вимагає, щоб увесь рядок відповідав заданому шаблону.

    printf 'Linux\nLinux server\nUbuntu\nLinux\n' > systems.txt

Звичайний пошук:

    grep "Linux" systems.txt

Знайде:

    Linux
    Linux server
    Linux

Пошук повного рядка:

    grep -x "Linux" systems.txt

Результат:

    Linux
    Linux

Різниця:

- `-w` — шаблон має відповідати цілому слову в рядку.
- `-x` — шаблон має відповідати всьому рядку.

## 6. Інвертований пошук — `-v`

Параметр `-v` показує рядки, які **не відповідають** заданому шаблону.

    grep -v "Linux" languages.txt

Результат:

    JavaScript is popular
    Python is useful

Це інвертує звичайний пошук.

### 6.1. Коли використовувати `-v`

Наприклад, потрібно показати всі рядки логу, крім інформаційних повідомлень:

    grep -v "INFO" app.log

Або всі рядки конфігурації, крім коментарів:

    grep -v "^#" config.conf

Останній приклад використовує регулярний вираз. Символ `^` означає початок рядка.

**Зверни увагу:** `grep -v` не видаляє рядки з файлу. Він лише показує їх у терміналі.

## 7. Підрахунок рядків — `-c`

Параметр `-c` показує кількість рядків, у яких знайдено збіг.

    grep -c "Linux" languages.txt

Результат:

    2

Якщо шукати у декількох файлах:

    grep -c "Linux" languages.txt technologies.txt

Команда покаже кількість рядків зі збігами окремо для кожного файлу.

**Важливо:** `-c` рахує рядки, що відповідають шаблону, а не загальну кількість входжень тексту.

Наприклад:

    printf 'Linux Linux Linux\nLinux\n' | grep -c "Linux"

Результат:

    2

Хоча слово `Linux` зустрічається чотири рази, збіг є лише у двох рядках.

### 7.1. Підрахунок окремих входжень

Якщо потрібно підрахувати саме входження тексту, можна використати `-o` разом із `wc -l`:

    grep -o "Linux" languages.txt | wc -l

`grep -o` виводить кожен знайдений фрагмент окремо, а `wc -l` рахує отримані рядки.

## 8. Показувати лише назви файлів — `-l`

Параметр `-l` виводить тільки назви файлів, у яких знайдено збіг.

    grep -l "Linux" *.txt

Це корисно, коли потрібно знайти файли, що містять певний текст, але не потрібно бачити всі знайдені рядки.

### 8.1. Файли без збігів — `-L`

Параметр `-L` виконує протилежне завдання: показує назви файлів, у яких немає збігів.

    grep -L "Linux" *.txt

Різниця:

- `-l` — файли, де збіг є;
- `-L` — файли, де збігів немає.

## 9. Рекурсивний пошук у каталогах — `-r` і `-R`

Якщо потрібно шукати текст не в одному файлі, а в усіх файлах каталогу та його підкаталогів, використовують рекурсивний пошук.

    grep -r "TODO" .

Тут:

- `-r` — рекурсивно обходити каталоги;
- `"TODO"` — текст для пошуку;
- `.` — поточний каталог.

Наприклад, можна знайти всі рядки з `TODO` у проєкті.

    grep -rn "TODO" .

Команда покаже назви файлів, номери рядків і відповідний текст.

### 9.1. Різниця між `-r` і `-R`

- `-r` — рекурсивний пошук; у GNU `grep` символічні посилання всередині каталогів зазвичай не обходяться.
- `-R` — рекурсивний пошук із переходом за символічними посиланнями.

У повсякденній роботі часто достатньо `-r`.

### 9.2. Обмеження пошуку певними файлами

За допомогою `--include` можна обмежити пошук певним типом файлів:

    grep -rn --include="*.js" "console.log" .

Це шукає `console.log` лише у файлах із розширенням `.js`.

Можна використовувати й інші типи:

    grep -rn --include="*.ts" "TODO" .
    grep -rn --include="*.css" "color:" .

### 9.3. Виключення файлів і каталогів

Параметр `--exclude` виключає файли за шаблоном:

    grep -rn --exclude="*.log" "ERROR" .

Параметр `--exclude-dir` виключає каталоги:

    grep -rn --exclude-dir=node_modules "useState" .

Для пошуку в JavaScript-проєктах це особливо корисно, оскільки `node_modules` містить багато сторонніх файлів.

## 10. Показувати тільки знайдений текст — `-o`

Параметр `-o` виводить тільки ті фрагменти, які відповідають шаблону, а не весь рядок.

    printf 'User: Valeriy\nUser: Anna\nUser: Petro\n' > users.txt

Звичайний пошук:

    grep "User" users.txt

Результат:

    User: Valeriy
    User: Anna
    User: Petro

З параметром `-o`:

    grep -o "User" users.txt

Результат:

    User
    User
    User

Цей параметр зручний для отримання окремих значень із тексту та подальшої обробки через `sort`, `uniq` або `wc`.

## 11. Підсвічування збігів — `--color`

Для зручності читання можна використовувати:

    grep --color=auto "Linux" languages.txt

Знайдений текст буде підсвічено, якщо термінал підтримує кольори.

Часто `grep` автоматично використовує підсвічування в інтерактивному терміналі, але це залежить від налаштувань системи.

Для постійного використання можна налаштувати псевдонім у `~/.bashrc`:

    alias grep='grep --color=auto'

Після зміни файлу налаштувань застосуй його:

    source ~/.bashrc

**Порада:** не обов'язково налаштовувати псевдонім відразу. Спочатку корисно навчитися працювати зі стандартною командою.

## 12. Пошук із розширеними регулярними виразами — `-E`

За замовчуванням `grep` використовує базові регулярні вирази. Параметр `-E` вмикає розширені регулярні вирази — ERE.

Вони дозволяють зручніше створювати складніші шаблони.

### 12.1. Пошук одного з кількох варіантів

Приклад:

    grep -E "Linux|Ubuntu" systems.txt

Символ `|` означає «або».

Команда знайде рядки, що містять `Linux` або `Ubuntu`.

Без `-E` символ `|` у звичайному шаблоні не працює як оператор «або».

### 12.2. Пошук рядків, які починаються з певного тексту

Символ `^` позначає початок рядка.

    grep "^Linux" systems.txt

Знайде рядки, які починаються зі слова `Linux`.

Наприклад:

    Linux
    Linux server

Але не знайде:

    My Linux server

### 12.3. Пошук рядків, які закінчуються певним текстом

Символ `$` позначає кінець рядка.

    grep "server$" systems.txt

Знайде рядки, що закінчуються словом `server`.

Наприклад:

    Linux server

### 12.4. Пошук порожніх рядків

Регулярний вираз `^$` відповідає порожньому рядку:

    grep -n "^$" file.txt

Команда покаже номери порожніх рядків.

Щоб знайти непорожні рядки:

    grep -v "^$" file.txt

Це виключає рядки, які повністю порожні.

### 12.5. Пошук рядків, що містять цифри

Клас символів `[0-9]` відповідає одній цифрі.

    grep -E "[0-9]" file.txt

Команда знайде всі рядки, у яких є хоча б одна цифра.

### 12.6. Кілька альтернатив

Наприклад, пошук рядків із `ERROR`, `WARNING` або `CRITICAL`:

    grep -E "ERROR|WARNING|CRITICAL" app.log

Такий підхід корисний під час аналізу логів.

## 13. Базові регулярні вирази

Регулярний вираз — це шаблон, за яким `grep` знаходить відповідний текст.

Основні символи:

| Символ | Значення | Приклад |
|---|---|---|
| `.` | Будь-який один символ, крім символу нового рядка | `Linu.` |
| `^` | Початок рядка | `^Linux` |
| `$` | Кінець рядка | `server$` |
| `*` | Нуль або більше повторень попереднього елемента | `ab*` |
| `[abc]` | Один символ із набору | `[abc]at` |
| `[0-9]` | Одна цифра | `[0-9]` |
| `[^abc]` | Один символ, якого немає в наборі | `[^0-9]` |
| `\` | Екранування спеціального символу або спеціальне значення | `\.` |

Приклади:

    grep "^Error" app.log
    grep "failed$" app.log
    grep -E "[0-9]+" file.txt

У третьому прикладі `+` означає одну або більше цифр саме тому, що використовується `-E`.

### 13.1. Точка як звичайний символ

У регулярних виразах крапка `.` означає будь-який один символ. Якщо потрібно знайти саме крапку, її потрібно екранувати.

    grep -E "\.js$" files.txt

Це знаходить рядки, які закінчуються на `.js`.

Без екранування крапка відповідала б будь-якому символу.

### 13.2. Пошук із буквальним текстом — `-F`

Якщо потрібно шукати текст без інтерпретації регулярних виразів, використовуй `-F`.

    grep -F "price = $100" file.txt

Тут символи `$`, `.`, `*`, `[` та інші спеціальні символи розглядаються як звичайний текст.

Це зручно, коли шукаєш фрагмент коду, URL, шлях або текст зі спеціальними символами.

**Запам'ятай:**

- `grep` — звичайні регулярні вирази;
- `grep -E` — розширені регулярні вирази;
- `grep -F` — буквальний пошук.

## 14. Контекст знайденого рядка — `-A`, `-B`, `-C`

Іноді недостатньо побачити лише рядок зі збігом. Потрібно переглянути рядки до або після нього.

Для цього використовують параметри контексту.

### 14.1. Рядки після збігу — `-A`

`-A NUM` показує задану кількість рядків після знайденого рядка.

    grep -A 2 "ERROR" app.log

Показує рядок із `ERROR` і два рядки після нього.

### 14.2. Рядки перед збігом — `-B`

`-B NUM` показує рядки перед знайденим рядком.

    grep -B 2 "ERROR" app.log

Показує два рядки перед збігом і сам рядок зі збігом.

### 14.3. Контекст до і після — `-C`

`-C NUM` показує рядки до та після збігу.

    grep -C 3 "ERROR" app.log

Показує до трьох рядків перед збігом і до трьох рядків після нього.

Це особливо корисно для пошуку помилок у логах серверів.

## 15. Використання `grep` разом із каналами — `|`

Канал `|` передає стандартний вивід однієї команди на стандартне введення іншої.

`grep` часто використовують як фільтр.

### 15.1. Фільтрація процесів

    ps aux | grep "node"

Команда показує рядки результату `ps aux`, які містять `node`.

Зверни увагу: такий пошук може також показувати сам процес `grep`.

Щоб зменшити ймовірність цього, можна використати:

    ps aux | grep "[n]ode"

Цей прийом часто використовують у Linux, але він не замінює спеціалізовані інструменти керування процесами.

### 15.2. Фільтрація файлів

    ls -l | grep "\.txt$"

Показує рядки результату `ls -l`, що закінчуються на `.txt`.

Однак для роботи з назвами файлів краще використовувати можливості самої оболонки, наприклад:

    ls *.txt

А для пошуку файлів у каталогах — `find`.

### 15.3. Фільтрація логів

    cat app.log | grep "ERROR"

Це працює, але для одного файлу простіше написати:

    grep "ERROR" app.log

Не потрібно використовувати `cat`, якщо можна передати файл безпосередньо команді.

### 15.4. Кілька фільтрів

Можна послідовно застосовувати декілька команд:

    ps aux | grep "node" | grep -v "grep"

Спочатку знаходяться рядки з `node`, потім виключаються рядки, що містять `grep`.

Кожен елемент конвеєра обробляє результат попереднього.

## 16. Пошук у системних логах

`grep` — один з найкорисніших інструментів для аналізу текстових логів.

Приклади:

    grep "ERROR" app.log
    grep -in "failed" app.log
    grep -nE "ERROR|WARNING" app.log
    grep -C 2 "Connection refused" app.log

Якщо лог великий, можна спочатку переглянути останні рядки:

    tail -n 100 app.log | grep "ERROR"

Ця команда шукає помилки лише в останніх 100 рядках файлу.

### 16.1. Пошук у журналі systemd

Якщо система використовує `systemd`, можна фільтрувати повідомлення `journalctl`:

    journalctl | grep -i "error"

Для перегляду повідомлень конкретного сервісу:

    journalctl -u nginx | grep -i "error"

Для аналізу повідомлень поточного завантаження системи:

    journalctl -b | grep -i "failed"

**Примітка:** для деяких журналів потрібні відповідні права доступу. Не кожен рядок із текстом `error` обов'язково означає критичну проблему.

## 17. Пошук у конфігураційних файлах

`grep` допомагає знаходити параметри в конфігураціях.

Наприклад:

    grep -n "Port" /etc/ssh/sshd_config

Пошук рядків, що починаються з `Port`:

    grep -n "^Port" /etc/ssh/sshd_config

Пошук рядків, які починаються з `#`:

    grep -n "^#" /etc/ssh/sshd_config

Пошук рядків, які не є коментарями:

    grep -v "^#" /etc/ssh/sshd_config

Остання команда також виведе порожні рядки. Щоб виключити і коментарі, і порожні рядки:

    grep -vE "^#|^$" /etc/ssh/sshd_config

Це приклад поєднання інвертованого пошуку та регулярних виразів.

**Важливо:** перегляд конфігурацій зазвичай не потребує `sudo`. Використовуй підвищені права лише тоді, коли вони справді необхідні.

## 18. Пошук у проєктах розробника

У JavaScript-, TypeScript- та Node.js-проєктах `grep` може допомогти знайти:

- `TODO` і `FIXME`;
- виклики `console.log`;
- назви функцій;
- використання певного API;
- повідомлення про помилки;
- згадки певного компонента.

Приклади:

    grep -rn --include="*.js" "console.log" .
    grep -rn --include="*.ts" "TODO" .
    grep -rn --include="*.tsx" "useState" .
    grep -rn --include="*.json" '"scripts"' .

Виключення каталогу залежностей:

    grep -rn --exclude-dir=node_modules "TODO" .

Виключення каталогів збірки:

    grep -rn --exclude-dir=node_modules --exclude-dir=.next "TODO" .

**Порада:** `grep` добре підходить для простого текстового пошуку, але він не розуміє структуру JavaScript або TypeScript. Для складних пошуків по синтаксису коду можуть бути корисні спеціалізовані інструменти.

## 19. Код завершення `grep`

`grep` повертає код завершення, який можна перевірити через `$?`.

- `0` — знайдено хоча б один збіг.
- `1` — збігів немає.
- `2` — сталася помилка, наприклад файл не вдалося відкрити.

Приклад:

    grep "Linux" languages.txt
    echo $?

Якщо збіг є, результатом буде:

    0

Якщо збігу немає:

    grep "Rust" languages.txt
    echo $?

Результат:

    1

Якщо файл не існує:

    grep "Linux" missing.txt
    echo $?

Зазвичай результатом буде:

    2

### 19.1. Перевірка наявності тексту в Bash

Наприклад, потрібно перевірити, чи містить файл певне повідомлення.

    if grep -q "ERROR" app.log; then
        echo "Знайдено помилки"
    else
        echo "Збігів немає"
    fi

Тут:

- `-q` — тихий режим, без виведення знайдених рядків;
- `if` перевіряє код завершення команди;
- `then` виконується, якщо збіг знайдено;
- `else` — якщо збігів немає.

Це основа для автоматизації перевірок у Bash-скриптах.

**Важливо:** `-q` зручний для перевірки наявності тексту, але в автоматизації варто враховувати й помилки читання файлів.

| `-w` | Шукати ціле слово |

| `-l` | Показувати назви файлів зі збігами |

## 21. Типові помилки

### 21.1. Забути лапки навколо шаблону

Неправильно або неоднозначно:

    grep Linux server.txt

У цьому випадку `Linux` буде шаблоном, а `server.txt` — назвою файлу. Якщо файл називається `server.txt`, команда правильна за синтаксисом, але якщо потрібно шукати фразу `Linux server`, це не те, що потрібно.

Правильно для пошуку фрази:

    grep "Linux server" server.txt

Лапки особливо важливі, коли шаблон містить пробіли або спеціальні символи оболонки.

### 21.2. Очікувати пошук без урахування регістру

Команда:

    grep "error" app.log

не знайде `ERROR`, якщо в рядку немає відповідного написання малими літерами.

Якщо регістр не має значення:

    grep -i "error" app.log

### 21.3. Плутати `-c` з підрахунком усіх входжень

    grep -c "error" app.log

Це рахує рядки зі збігами, а не кожне входження слова.

Для підрахунку окремих входжень:

    grep -o "error" app.log | wc -l

Якщо регістр має бути довільним:

    grep -oi "error" app.log | wc -l

### 21.4. Не екранувати крапку в регулярному виразі

    grep -E ".js$" files.txt

Тут крапка означає будь-який символ, тому шаблон може знайти більше, ніж файли `.js`.

Для буквальної крапки:

    grep -E "\.js$" files.txt

Або використай `-F`, якщо потрібен буквальний пошук без регулярних виразів.

### 21.5. Шукати рекурсивно в усіх залежностях

    grep -rn "useState" .

У великому проєкті ця команда може вивести тисячі рядків із `node_modules` та інших каталогів.

Краще обмежити пошук:

    grep -rn --exclude-dir=node_modules --exclude-dir=.next "useState" .

### 21.6. Вважати, що відсутність результату означає помилку

Якщо `grep` нічого не вивів, це не обов'язково помилка. Можливо, збігів просто немає.

Перевірити код завершення можна так:

    grep "Rust" languages.txt
    echo $?

Код `1` означає, що команда виконалася, але не знайшла збігів.

### 21.7. Плутати `grep` із редагуванням файлу

Команда:

    grep -v "^#" config.conf

лише виводить рядки без коментарів. Вона не змінює `config.conf`.

Щоб записати результат в інший файл:

    grep -v "^#" config.conf > config-without-comments.conf

Будь уважний із перенаправленням `>`: воно перезаписує цільовий файл.

## 22. Практичні вправи

Для вправ використовуй каталог `~/linux-practice/grep`.

### Рівень 1 — Core

1. Створи файл `users.txt` із п'ятьма іменами.
2. Знайди рядки, що містять конкретне ім'я.

4. Покажи по два рядки до та після кожної помилки.

    grep -E "ERROR|WARNING" app.log
    grep -C 2 "ERROR" app.log
    grep -c "ERROR" app.log

### Рівень 3 — Junior+

1. Створи декілька файлів `.js`, `.ts` і `.txt`.
2. Знайди всі файли, що містять `TODO`.
3. Виведи тільки назви файлів зі збігами.
4. Виключи `node_modules` з пошуку.
5. Знайди рядки, які закінчуються на `.js`.

Приклади команд:

    grep -rn "TODO" .
    grep -rl "TODO" .
    grep -rn --exclude-dir=node_modules "TODO" .

### Рівень 4 — Bash

1. Перевір, чи містить лог слово `ERROR`.
2. Якщо містить — виведи повідомлення про помилку.
3. Якщо не містить — виведи повідомлення, що збігів немає.
4. Окремо оброби ситуацію, коли файл не існує.

Приклад базової перевірки:

    if grep -q "ERROR" app.log; then
        echo "Знайдено помилки"
    else
        echo "Збігів немає"
    fi

Для надійнішого скрипту потрібно окремо перевірити наявність файлу або врахувати код завершення `grep`, щоб не трактувати помилку читання як відсутність збігів.

## 23. Мініпроєкт — аналізатор логів

Мета: створити простий сценарій аналізу `app.log` за допомогою `grep`.

Створи файл:

    touch app.log

Додай тестові повідомлення:

    cat > app.log <<'EOF'
    INFO Server started
    INFO Database connected
    WARNING Slow response
    ERROR Database timeout
    INFO Request completed
    ERROR Connection refused
    WARNING Retry scheduled
    EOF

### Завдання 1. Знайти помилки

    grep -n "ERROR" app.log

### Завдання 2. Порахувати помилки

    grep -c "ERROR" app.log

### Завдання 3. Знайти помилки та попередження

    grep -nE "ERROR|WARNING" app.log

### Завдання 4. Переглянути контекст помилки

    grep -C 1 "ERROR" app.log

### Завдання 5. Вивести всі рядки, крім INFO

    grep -v "INFO" app.log

### Завдання 6. Перевірити наявність помилок у Bash

    if grep -q "ERROR" app.log; then
        echo "У журналі є помилки"
    else
        echo "Помилок не знайдено"
    fi

### Завдання 7. Зберегти помилки в окремий файл

    grep "ERROR" app.log > errors.log

Перевір результат:

    cat errors.log

**Результат:** ти навчишся використовувати `grep` не лише окремо, а й у практичних завданнях із логами та автоматизацією.

## 26. Мінішпаргалка

    # Пошук тексту у файлі
    grep "Linux" file.txt

    # Пошук без урахування регістру
    grep -i "linux" file.txt

    # Показати номери рядків
    grep -n "Linux" file.txt

    # Шукати ціле слово
    grep -w "Linux" file.txt

    # Шукати рядки, які повністю збігаються
    grep -x "Linux" file.txt

    # Показати рядки без збігів
    grep -v "Linux" file.txt

    # Порахувати рядки зі збігами
    grep -c "Linux" file.txt

    # Показати тільки знайдений текст
    grep -o "Linux" file.txt

    # Показати назви файлів зі збігами
    grep -l "Linux" *.txt

    # Рекурсивний пошук
    grep -rn "TODO" .

    # Виключити каталог
    grep -rn --exclude-dir=node_modules "TODO" .

    # Пошук за кількома варіантами
    grep -E "ERROR|WARNING" app.log

    # Пошук рядків, що починаються з тексту
    grep "^Linux" file.txt

    # Пошук рядків, що закінчуються на текст
    grep "server$" file.txt

    # Показати контекст навколо збігу
    grep -C 2 "ERROR" app.log

    # Пошук у потоці даних
    ps aux | grep "node"

    # Перевірити наявність тексту без виведення рядків
    grep -q "ERROR" app.log

    # Записати знайдені рядки в інший файл
    grep "ERROR" app.log > errors.log

## 27. Головне, що потрібно запам'ятати

- `grep` шукає рядки за заданим текстом або шаблоном.
- `-i` ігнорує регістр, `-n` показує номери рядків, `-v` інвертує пошук.
- `-w` шукає ціле слово, а `-x` вимагає збігу всього рядка.
- `-c` рахує рядки зі збігами, а `-o` виводить окремі знайдені фрагменти.
- `-r` дозволяє шукати в каталогах рекурсивно.
- `-E` вмикає розширені регулярні вирази, а `-F` шукає буквальний текст.
- `-A`, `-B` і `-C` показують контекст навколо знайденого рядка.
- `grep` часто використовується разом із каналами `|` для фільтрації результатів інших команд.
- Код завершення `0` означає, що збіг знайдено; `1` — що збігів немає; `2` зазвичай означає помилку.
- Для роботи з логами, конфігураціями та кодом `grep` є одним із найкорисніших інструментів Linux.

**Наступний крок:** `04-wc-sort-uniq` — підрахунок рядків і слів, сортування результатів та пошук унікальних значень.
