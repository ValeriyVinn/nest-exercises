# 06. Redirection — Перенаправлення введення та виведення в Linux

Перенаправлення (redirection) — це механізм Bash, який дозволяє змінювати джерело введення команди та місце, куди надходять її результати.

Замість того щоб виводити повідомлення безпосередньо в термінал, можна записати їх у файл, додати до наявного файлу, відокремити звичайний вивід від повідомлень про помилки або передати команді вміст файлу як вхідні дані.

Перенаправлення — одна з фундаментальних тем Linux. Воно широко використовується в Bash-скриптах, автоматизації, роботі з логами, запуску серверів і діагностиці помилок.

## 1. Що потрібно знати

✔ Стандартні потоки введення та виведення: `stdin`, `stdout`, `stderr`.

✔ Перенаправлення виведення: `>`.

✔ Додавання виведення до файлу: `>>`.

✔ Перенаправлення стандартного введення: `<`.

✔ Перенаправлення повідомлень про помилки: `2>`.

✔ Об'єднання стандартного виведення та помилок: `> file 2>&1` і `&>`.

✔ Відокремлення звичайного виведення від помилок.

✔ Перенаправлення в `/dev/null`.

✔ Використання `<<` (here-document) і `<<<` (here-string).

✔ Розуміння порядку перенаправлень.

✔ Практичне застосування перенаправлень у командах і Bash-скриптах.

---

## 2. Стандартні потоки введення та виведення

Кожна звичайна команда Linux може працювати зі стандартними потоками.

| Потік | Файловий дескриптор | Призначення |
|---|---:|---|
| `stdin` | `0` | Стандартне введення |
| `stdout` | `1` | Звичайний результат команди |
| `stderr` | `2` | Повідомлення про помилки |

За замовчуванням введення часто надходить із клавіатури, а виведення та помилки відображаються в терміналі.

    # Звичайний вивід команди
    ls

    # Перегляд каталогу
    ls /etc

    # Спроба переглянути неіснуючий каталог
    ls /directory-does-not-exist

Остання команда зазвичай виведе повідомлення про помилку в термінал.

Важливо: `stdout` і `stderr` — це окремі потоки, хоча за замовчуванням вони можуть відображатися в одному терміналі.

### 2.1. Що таке файловий дескриптор

Файловий дескриптор (file descriptor) — це невелике невід'ємне число, за допомогою якого процес звертається до відкритого файлу або іншого ресурсу введення-виведення.

Основні дескриптори:

    0 — stdin
    1 — stdout
    2 — stderr

Наприклад:

    ls > files.txt

Ця команда перенаправляє `stdout` команди `ls` у файл `files.txt`.

Повідомлення про помилки при цьому залишаються у `stderr` і за замовчуванням продовжують відображатися в терміналі.

## 3. Перенаправлення стандартного виведення: `>`

Оператор `>` записує стандартне виведення команди у файл.

Синтаксис:

    command > file.txt

Приклад:

    ls > files.txt

Тепер результат `ls` записано у файл `files.txt`, а не показано в терміналі.

Переглянемо файл:

    cat files.txt

### 3.1. Перезапис файлу

Якщо файл уже існує, оператор `>` зазвичай очищає його вміст перед записом нового результату.

    echo "First message" > messages.txt
    echo "Second message" > messages.txt

Перевіримо:

    cat messages.txt

Результат:

    Second message

Перший рядок буде втрачено, оскільки друга команда перезаписала файл.

Якщо файлу не існує, він зазвичай створюється автоматично, якщо каталог доступний для запису.

### 3.2. Запис результату іншої команди

    date > current-date.txt

    pwd > current-directory.txt

    whoami > current-user.txt

Перегляд:

    cat current-date.txt
    cat current-directory.txt
    cat current-user.txt

Так можна зберігати результати команд для подальшого використання.

### 3.3. Запис кількох команд у різні файли

    ls > files.txt
    pwd > location.txt
    date > date.txt

Кожна команда записує свій результат у відповідний файл.

**Застереження:** перенаправлення `>` може знищити попередній вміст файлу. Перед його використанням перевіряй ім'я файлу та призначення команди.

---

## 4. Додавання виведення до файлу: `>>`

Оператор `>>` додає результат у кінець файлу, не видаляючи попередній вміст.

Синтаксис:

    command >> file.txt

Приклад:

    echo "First message" > messages.txt
    echo "Second message" >> messages.txt
    echo "Third message" >> messages.txt

Перевіримо:

    cat messages.txt

Результат:

    First message
    Second message
    Third message

### 4.1. Коли використовувати `>>`

Оператор `>>` зручний для:

- накопичення логів;
- запису результатів послідовних запусків;
- збереження історії виконання завдань;
- доповнення текстових файлів;
- додавання інформації до звітів.

Приклад простого журналу:

    echo "Program started" >> app.log
    date >> app.log
    echo "Program finished" >> app.log

Перегляд:

    cat app.log

### 4.2. Різниця між `>` та `>>`

| Оператор | Поведінка |
|---|---|
| `>` | Перезаписує файл |
| `>>` | Додає дані в кінець файлу |

Запам'ятай:

    echo "New content" > file.txt

    echo "Additional content" >> file.txt

Перший варіант замінює вміст, другий — доповнює його.

---

## 5. Перенаправлення стандартного введення: `<`

Оператор `<` передає вміст файлу команді як стандартне введення (`stdin`).

Синтаксис:

    command < file.txt

Приклад:

    wc -l < files.txt

Команда `wc -l` рахує рядки, отримані через стандартне введення.

Порівняй:

    wc -l files.txt

    wc -l < files.txt

Обидві команди рахують рядки у файлі, але в першому випадку `wc` отримує ім'я файлу як аргумент, а в другому читає дані зі стандартного введення.

Тому формат виведення може відрізнятися: у першому випадку зазвичай показується ім'я файлу, у другому — лише кількість.

### 5.1. Передавання вмісту файлу команді

    sort < names.txt

    sort < names.txt > sorted-names.txt

Другий приклад читає дані з `names.txt`, сортує їх і записує результат у `sorted-names.txt`.

### 5.2. Перенаправлення введення у скриптах

Якщо програма читає дані зі стандартного введення, їй можна передати файл:

    node app.js < input.txt

Це працює лише тоді, коли програма дійсно читає дані зі `stdin`. Сам факт передавання файлу не змушує програму автоматично обробляти його вміст.

## 6. Перенаправлення повідомлень про помилки: `2>`

Стандартні помилки передаються через файловий дескриптор `2`.

Оператор `2>` перенаправляє `stderr` у файл.

Синтаксис:

    command 2> errors.txt

Приклад:

    ls /directory-does-not-exist 2> errors.txt

Повідомлення про помилку буде записано у `errors.txt`.

Переглянемо:

    cat errors.txt

### 6.1. Відокремлення результату від помилок

    ls /etc /directory-does-not-exist > output.txt 2> errors.txt

Тут:

- `output.txt` містить звичайний вивід;
- `errors.txt` містить повідомлення про помилки.

Перевіримо обидва файли:

    cat output.txt
    cat errors.txt

Цей підхід корисний, коли потрібно отримати успішні результати та діагностику окремо.

### 6.2. Додавання помилок до файлу

Оператор `2>>` додає повідомлення про помилки в кінець файлу:

    ls /directory-does-not-exist 2>> errors.log

Повторне виконання команди доповнюватиме журнал, а не перезаписуватиме його.

### 6.3. Перенаправлення лише помилок не приховує звичайний вивід

    ls /etc /directory-does-not-exist 2> errors.txt

Звичайний список із `/etc` усе ще відображатиметься в терміналі. У файл потраплять тільки повідомлення зі `stderr`.

---

## 7. Перенаправлення stdout і stderr одночасно

Іноді потрібно записати в один файл як звичайний результат, так і повідомлення про помилки.

### 7.1. Варіант `> file 2>&1`

    command > output.log 2>&1

Наприклад:

    ls /etc /directory-does-not-exist > output.log 2>&1

Результат і повідомлення про помилку будуть спрямовані у `output.log`.

Що відбувається:

1. `> output.log` перенаправляє `stdout` у файл.
2. `2>&1` спрямовує `stderr` туди, куди на цей момент спрямований `stdout`.

Тобто дескриптор `2` копіює поточне призначення дескриптора `1`.

### 7.2. Скорочений варіант `&>`

У Bash можна використовувати:

    command &> output.log

Наприклад:

    ls /etc /directory-does-not-exist &> output.log

Це перенаправляє і `stdout`, і `stderr` у той самий файл, перезаписуючи його.

Для додавання обох потоків до кінця файлу в Bash використовують:

    command &>> output.log

### 7.3. Варіант `> file 2>&1` і `&> file`

| Команда | Призначення |
|---|---|
| `command > file` | Лише `stdout` |
| `command 2> file` | Лише `stderr` |
| `command > file 2>&1` | `stdout` і `stderr` в одному файлі |
| `command &> file` | Те саме в Bash |
| `command >> file 2>&1` | Додавання обох потоків |
| `command &>> file` | Додавання обох потоків у Bash |

Для переносимості між різними оболонками частіше використовують форму `> file 2>&1`. Оператори `&>` і `&>>` характерні для Bash і не є універсальним синтаксисом усіх оболонок.

## 8. Порядок перенаправлень має значення

Це одна з найважливіших тем.

Розглянемо дві команди:

    command > output.log 2>&1

    command 2>&1 > output.log

Вони **не еквівалентні**.

### 8.1. Спочатку stdout, потім stderr

    ls /etc /directory-does-not-exist > output.log 2>&1

Послідовність:

1. `stdout` перенаправляється у `output.log`.
2. `stderr` перенаправляється туди, куди зараз спрямований `stdout`, — у той самий файл.

Отже, обидва потоки записуються у файл.

### 8.2. Спочатку stderr, потім stdout

    ls /etc /directory-does-not-exist 2>&1 > output.log

Послідовність:

1. `stderr` спрямовується туди, куди на цей момент спрямований `stdout`, — зазвичай у термінал.
2. `stdout` перенаправляється у `output.log`.

У результаті звичайний вивід потрапляє у файл, а помилки залишаються в терміналі.

**Правило:** перенаправлення обробляються зліва направо. Дескриптор `2>&1` копіює поточне призначення дескриптора `1`, а не встановлює постійний зв'язок між ними.

## 9. Приховування виведення за допомогою `/dev/null`

`/dev/null` — спеціальний пристрій Linux, який відкидає записані в нього дані.

Його часто називають «чорною дірою».

### 9.1. Приховати звичайний вивід

    ls > /dev/null

Команда виконується, але її звичайний вивід не відображається.

### 9.2. Приховати повідомлення про помилки

    ls /directory-does-not-exist 2> /dev/null

Помилка не показується в терміналі та не записується у звичайний файл — вона відкидається.

### 9.3. Приховати обидва потоки

    command > /dev/null 2>&1

Або в Bash:

    command &> /dev/null

Приклад:

    ls /etc /directory-does-not-exist > /dev/null 2>&1

Обидва потоки приховані.

### 9.4. Коли використовувати `/dev/null`

- коли перевіряєш, чи завершується команда без потреби бачити її вивід;
- коли зайвий вивід заважає роботі скрипта;
- коли потрібно приховати очікувані повідомлення про помилки;
- коли важливий код завершення команди, а не її текстовий результат.

**Застереження:** не приховуй помилки автоматично. Під час налагодження краще зберігати їх у файлі або показувати в терміналі.

## 10. Перенаправлення введення через here-document: `<<`

Here-document дозволяє передати команді багаторядковий текст без створення окремого файлу.

Синтаксис:

    command << DELIMITER
    first line
    second line
    third line
    DELIMITER

`DELIMITER` — довільний маркер завершення. Він має окремо стояти на початку рядка в позиції завершення.

Приклад:

    cat << EOF
    Hello, Linux!
    This is a multiline message.
    We are learning redirection.
    EOF

Результат:

    Hello, Linux!
    This is a multiline message.
    We are learning redirection.

Команда `cat` читає багаторядковий текст зі стандартного введення та виводить його в термінал.

### 10.1. Запис багаторядкового тексту у файл

    cat > notes.txt << EOF
    Linux fundamentals
    Redirection
    Standard output and errors
    EOF

Тут текст передається команді `cat`, а її результат перенаправляється у `notes.txt`.

Перевіримо:

    cat notes.txt

### 10.2. Використання маркера в лапках

У Bash маркер можна взяти в лапки:

    cat << 'EOF'
    $HOME
    $(date)
    EOF

У цьому випадку Bash не підставляє значення змінних і не виконує підстановку команд усередині тексту.

Без лапок:

    cat << EOF
    Home directory: $HOME
    Current date: $(date)
    EOF

Bash підставить значення `$HOME` і результат команди `date`.

### 10.3. Коли використовувати here-document

- для створення конфігураційних файлів;
- для передавання багаторядкових даних скриптам;
- для автоматизації введення;
- для швидкого створення текстових документів;
- для SQL-запитів та інших багаторядкових команд.

## 11. Передавання одного рядка через here-string: `<<<`

Here-string передає команді один рядок через стандартне введення.

Синтаксис у Bash:

    command <<< "text"

Приклад:

    wc -w <<< "Linux is powerful"

Результат — кількість слів у переданому рядку.

Ще один приклад:

    tr 'a-z' 'A-Z' <<< "hello linux"

Результат:

    HELLO LINUX

### 11.1. Порівняння `<<<` і `<<`

| Оператор | Призначення |
|---|---|
| `<<<` | Передавання одного рядка |
| `<<` | Передавання багаторядкового тексту |

Приклад here-string:

    grep "Linux" <<< "I am learning Linux"

Приклад here-document:

    grep "Linux" << EOF
    I am learning Linux
    Linux is an operating system.
    I like programming.
    EOF

Обидва оператори доступні в Bash. Вони не є POSIX-сумісними можливостями для всіх оболонок.

## 12. Об'єднання перенаправлень із командами

Перенаправлення можна поєднувати з командами пошуку, сортування та обробки тексту.

### 12.1. Зберегти список файлів

    ls -la > directory-list.txt

    cat directory-list.txt

### 12.2. Записати результати пошуку

    grep "error" app.log > errors.txt

Якщо збігів немає, файл усе одно може бути створений або очищений, адже оболонка обробляє перенаправлення до запуску команди.

### 12.3. Зберегти результат сортування

    sort names.txt > sorted-names.txt

### 12.4. Записати результат підрахунку

    wc -l < names.txt > line-count.txt

### 12.5. Зберегти вивід і помилки окремо

    grep "error" app.log > matches.txt 2> grep-errors.txt

### 12.6. Зберегти всі повідомлення команди

    find . -type f > found-files.txt 2> find-errors.txt

Тут:

- `found-files.txt` містить знайдені файли;
- `find-errors.txt` містить повідомлення про помилки, наприклад про каталоги, до яких немає доступу.

### 12.7. Запустити команду без повідомлень у терміналі

    find . -type f > /dev/null 2>&1

Команда виконується, але обидва потоки відкидаються.

## 13. Перенаправлення та коди завершення

Код завершення (exit status) показує, чи вважається виконання команди успішним.

Зазвичай:

- `0` — успішне завершення;
- ненульове значення — помилка або інший спеціальний результат.

Перевірити код завершення попередньої команди можна через `$?`.

Приклад:

    ls /etc > output.txt
    echo $?

Зазвичай результат:

    0

Тепер перевіримо помилковий шлях:

    ls /directory-does-not-exist 2> errors.txt
    echo $?

Команда `ls` зазвичай поверне ненульовий код.

### 13.1. Важливий нюанс

Перенаправлення виведення не змінює саме по собі код завершення команди. Але помилка перенаправлення може завадити запуску команди або спричинити невдале виконання.

Наприклад, якщо немає прав на створення файлу в певному каталозі, оболонка може повідомити про помилку ще до запуску команди.

Приклад:

    ls > /root/private-output.txt
    echo $?

Якщо поточний користувач не має потрібних прав, перенаправлення може завершитися помилкою.

## 14. Перенаправлення у Bash-скриптах

У скриптах перенаправлення дозволяють автоматично створювати звіти, вести журнали та відокремлювати повідомлення про помилки.

### 14.1. Простий скрипт зі звітом

Створимо файл `report.sh`:

    #!/usr/bin/env bash

    echo "Report started" > report.log
    date >> report.log
    echo "Current user: $(whoami)" >> report.log
    echo "Report finished" >> report.log

Запуск:

    chmod +x report.sh
    ./report.sh

Перегляд:

    cat report.log

Перший рядок відкриває файл для перезапису, а наступні команди додають дані.

### 14.2. Запис помилок у журнал

    #!/usr/bin/env bash

    ls /etc > output.log 2> errors.log

Цей скрипт записує звичайний вивід і помилки в різні файли.

### 14.3. Зберігати весь вивід скрипта

На початку скрипта можна написати:

    #!/usr/bin/env bash

    exec > script-output.log 2>&1

    echo "Script started"
    date
    ls /etc
    echo "Script finished"

Команда `exec` без зовнішньої команди змінює перенаправлення потоків поточної оболонки. Тому наступні команди скрипта виводитимуть `stdout` і `stderr` у `script-output.log`.

Важливо: якщо перенаправлення налаштовано через `exec`, воно діятиме для наступних команд поточної оболонки або скрипта, доки його не змінити або доки оболонка не завершиться.

### 14.4. Виводити повідомлення про помилки в stderr

У Bash можна явно записати повідомлення у стандартний потік помилок:

    echo "Error: configuration file not found" >&2

Це корисно у скриптах, оскільки звичайний вивід і діагностичні повідомлення можна перенаправляти окремо.

Наприклад:

    echo "Processing completed"
    echo "Warning: one file was skipped" >&2

Тепер звичайний вивід можна зберегти окремо від попереджень:

    ./script.sh > output.log 2> errors.log

## 15. Типові помилки

### 15.1. Випадково перезаписати важливий файл

Неправильно, якщо потрібно зберегти попередній вміст:

    echo "New entry" > history.log

Правильно для доповнення:

    echo "New entry" >> history.log

### 15.2. Вважати, що `>` перенаправляє помилки

    ls /etc /directory-does-not-exist > output.txt

Тут перенаправлено лише `stdout`. Повідомлення про помилку може залишитися в терміналі.

Щоб перенаправити `stderr`:

    ls /etc /directory-does-not-exist 2> errors.txt

Щоб перенаправити обидва потоки:

    ls /etc /directory-does-not-exist > output.txt 2>&1

### 15.3. Неправильний порядок перенаправлень

    command 2>&1 > output.log

Ця команда не спрямовує обидва потоки у файл. Помилки спрямовуються до поточного `stdout` до того, як `stdout` перенаправляється у файл.

Правильний варіант для спільного файлу:

    command > output.log 2>&1

### 15.4. Використовувати `sudo` тільки перед командою

Приклад:

    sudo echo "text" > /root/test.txt

Ця команда може завершитися помилкою, тому що `sudo` підвищує привілеї для `echo`, але перенаправлення `>` виконує поточна оболонка від імені звичайного користувача.

Для запису у файл, доступний лише root, можна використати `sudo tee`:

    echo "text" | sudo tee /root/test.txt

Для додавання тексту:

    echo "additional text" | sudo tee -a /root/test.txt

За замовчуванням `tee` також виводить текст у термінал. Щоб приховати його:

    echo "text" | sudo tee /root/test.txt > /dev/null

### 15.5. Не перевіряти каталог і права доступу

Команда:

    command > /some/path/output.log

може не спрацювати, якщо каталогу не існує або користувач не має прав на запис.

Перевіряй каталог:

    pwd
    ls -ld /some/path

### 15.6. Вважати, що here-document автоматично зберігає текст у файл

Ця команда лише виводить текст:

    cat << EOF
    Hello
    EOF

Щоб записати його у файл, потрібне перенаправлення:

    cat > message.txt << EOF
    Hello
    EOF

### 15.7. Не враховувати особливості оболонки

Оператори `&>` і `<<<` підтримуються Bash, але можуть не підтримуватися в інших оболонках або працювати інакше.

Перевірити оболонку:

    echo "$SHELL"

Це показує налаштовану оболонку входу, а не обов'язково оболонку, що виконує поточний скрипт.

## 16. Практика

### Вправа 1. Записати результат команди

1. Запиши список файлів поточного каталогу у `files.txt`.
2. Переглянь вміст файлу.
3. Повтори команду після створення нового файлу та порівняй результат.

    ls > files.txt
    cat files.txt

### Вправа 2. Перевірити перезапис і додавання

1. Створи файл із першим рядком.
2. Додай другий рядок.
3. Додай третій рядок.
4. Переглянь результат.

    echo "First" > test.txt
    echo "Second" >> test.txt
    echo "Third" >> test.txt
    cat test.txt

Очікуваний результат:

    First
    Second
    Third

### Вправа 3. Відокремити вивід від помилок

Виконай команду, яка звертається до наявного й неіснуючого каталогу.

    ls /etc /directory-does-not-exist > output.txt 2> errors.txt

Перевір:

    cat output.txt
    cat errors.txt

Запитання: чому в одному файлі список, а в іншому повідомлення про помилку?

### Вправа 4. Приховати помилки

Виконай:

    ls /directory-does-not-exist 2> /dev/null

Запитання: чи означає відсутність повідомлення, що команда завершилася успішно?

Перевір код завершення:

    echo $?

### Вправа 5. Порівняти порядок перенаправлень

Виконай обидві команди:

    ls /etc /directory-does-not-exist > first.log 2>&1

    ls /etc /directory-does-not-exist 2>&1 > second.log

Порівняй вивід у терміналі та вміст файлів.

### Вправа 6. Передати текст через here-document

Створи файл `linux-notes.txt` з трьома рядками.

    cat > linux-notes.txt << EOF
    Linux
    Bash
    Redirection
    EOF

Перевір:

    cat linux-notes.txt

### Вправа 7. Записати звіт

Створи `system-report.txt`, що міститиме:

- поточний каталог;
- ім'я користувача;
- дату й час;
- список файлів поточного каталогу.

Використай `>`, а для наступних рядків — `>>`.

    pwd > system-report.txt
    whoami >> system-report.txt
    date >> system-report.txt
    ls >> system-report.txt

Переглянь результат:

    cat system-report.txt

## 17. Мініпроєкт: журнал виконання команд

Мета — створити простий Bash-скрипт, який збирає системну інформацію та записує результати й помилки в окремі файли.

Створи каталог для практики:

    mkdir -p ~/linux-practice/redirection
    cd ~/linux-practice/redirection

Створи файл `system-report.sh`:

    #!/usr/bin/env bash

    echo "=== System report ===" > report.log
    date >> report.log
    echo "User: $(whoami)" >> report.log
    echo "Directory: $(pwd)" >> report.log
    echo "=== Files ===" >> report.log

    ls -la >> report.log 2> errors.log

    echo "Report saved to report.log"

Надай дозвіл на виконання:

    chmod +x system-report.sh

Запусти:

    ./system-report.sh

Переглянь звіт:

    cat report.log

Перевір файл помилок:

    cat errors.log

Якщо помилок не було, `errors.log` може бути порожнім.

### Завдання для вдосконалення

1. Додай до звіту назву операційної системи через `uname -a`.
2. Записуй повідомлення про запуск скрипта в окремий файл `run.log`.
3. Зроби так, щоб новий запуск додавав запис до `run.log`, а не перезаписував його.
4. Перенаправляй помилки у `errors.log`.
5. Перевір, що станеться, якщо навмисно вказати неіснуючий каталог у команді `ls`.

## 20. Мінішпаргалка

| Завдання | Команда |
|---|---|
| Записати вивід у файл | `command > file.txt` |
| Додати вивід у кінець файлу | `command >> file.txt` |
| Прочитати файл через stdin | `command < file.txt` |
| Записати помилки | `command 2> errors.txt` |
| Додати помилки | `command 2>> errors.txt` |
| Записати stdout і stderr | `command > output.log 2>&1` |
| Об'єднати потоки в Bash | `command &> output.log` |
| Додати обидва потоки в Bash | `command &>> output.log` |
| Приховати stdout | `command > /dev/null` |
| Приховати stderr | `command 2> /dev/null` |
| Приховати обидва потоки | `command > /dev/null 2>&1` |
| Передати багаторядковий текст | `command << EOF` |
| Передати один рядок | `command <<< "text"` |
| Вивести повідомлення в stderr | `echo "Error" >&2` |
| Перевірити код завершення | `echo $?` |
| Записати у файл від імені root | `echo "text" \| sudo tee /root/file.txt` |
| Додати до файлу від імені root | `echo "text" \| sudo tee -a /root/file.txt` |

## 21. Що запам'ятати

1. `stdin` — стандартне введення, дескриптор `0`.
2. `stdout` — стандартний вивід, дескриптор `1`.
3. `stderr` — стандартні помилки, дескриптор `2`.
4. `>` перезаписує файл, а `>>` доповнює його.
5. `<` передає вміст файлу команді через стандартне введення.
6. `2>` перенаправляє повідомлення про помилки.
7. `> file 2>&1` спрямовує обидва потоки в один файл.
8. Порядок перенаправлень має значення.
9. `/dev/null` відкидає дані, записані в нього.
10. `<<` і `<<<` — зручні засоби передавання тексту в Bash.
11. Перенаправлення не гарантує успішного виконання команди — перевіряй її код завершення.
12. Перед використанням `>` переконайся, що не знищиш потрібний вміст файлу.

**Головна ідея:** перенаправлення дозволяють керувати тим, звідки команда отримує дані та куди спрямовує результати й помилки. Це основа роботи з логами, автоматизації та Bash-скриптів.
