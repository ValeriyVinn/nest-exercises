# 07. Pipes — Конвеєри команд у Linux

Конвеєр (pipe) — це механізм Linux, який дозволяє передавати стандартний вивід однієї команди безпосередньо на стандартне введення іншої команди.

Для створення конвеєра використовується оператор `|`.

Замість того щоб спочатку зберігати результат команди у файл, а потім відкривати цей файл іншою командою, можна об'єднати кілька команд в один ланцюжок.

Конвеєри — один із найважливіших інструментів Linux. Вони дають змогу комбінувати невеликі утиліти для пошуку, сортування, підрахунку, фільтрації та обробки текстових даних.

## 1. Що потрібно знати

✔ Що таке конвеєр і як працює оператор `|`.

✔ Як передавати `stdout` однієї команди в `stdin` іншої.

✔ Як поєднувати дві, три та більше команд.

✔ Як використовувати `grep`, `sort`, `uniq`, `wc`, `head`, `tail` у конвеєрах.

✔ Чим конвеєр відрізняється від перенаправлення у файл.

✔ Як працюють `stderr` і конвеєри.

✔ Як використовувати `tee` для одночасного виведення та збереження результату.

✔ Як працює `pipefail` і чому важливі коди завершення команд.

✔ Як читати та будувати складні конвеєри.

✔ Як застосовувати конвеєри в адмініструванні Linux і розробці.

## 2. Що таке конвеєр

Конвеєр передає результат однієї команди наступній команді.

Загальний синтаксис:

    command1 | command2

Результат `command1` надходить на стандартне введення `command2`.

Наприклад:

    ls | wc -l

Що відбувається:

1. `ls` формує список елементів поточного каталогу.
2. Оператор `|` передає стандартний вивід `ls` на стандартне введення `wc`.
3. `wc -l` підраховує кількість рядків, отриманих на вході.

Результат — кількість рядків у виводі `ls`.

Зверни увагу: `ls | wc -l` не завжди дорівнює точній кількості файлів. На результат впливають формат виведення `ls`, приховані файли та інші обставини. Для підрахунку файлів краще використовувати відповідні інструменти, наприклад `find`.

### 2.1. Схема роботи

    command1
        |
        v
    stdout
        |
        v
      pipe
        |
        v
      stdin
        |
        v
    command2

Конвеєр з'єднує вихідний потік однієї команди зі вхідним потоком наступної.

### 2.2. Простий приклад

    printf "apple\nbanana\norange\n" | wc -l

Результат:

    3

Команда `printf` передає три рядки, а `wc -l` рахує їх.

Тут `printf` використовується для створення передбачуваного текстового введення, щоб результат був зрозумілим.

## 3. Конвеєр із двох команд

Найпростіший конвеєр об'єднує дві команди.

### 3.1. Підрахунок рядків

    cat notes.txt | wc -l

Команда `cat` читає файл і передає його вміст через конвеєр у `wc -l`.

Однак у цьому випадку можна обійтися без конвеєра:

    wc -l notes.txt

Другий варіант простіший і зазвичай кращий, якщо потрібно лише порахувати рядки у файлі.

**Правило:** не додавай конвеєр, якщо попередня команда не виконує корисної роботи.

### 3.2. Пошук рядків із текстом

    cat app.log | grep "ERROR"

Команда `grep` відбирає рядки, які містять `ERROR`.

Простіший варіант:

    grep "ERROR" app.log

`grep` може читати файл самостійно, тому `cat` тут зайвий.

Але конвеєр стає корисним, коли потрібно послідовно обробити результат кількома командами.

### 3.3. Сортування рядків

    printf "orange\napple\nbanana\n" | sort

Результат:

    apple
    banana
    orange

Команда `printf` передає рядки, а `sort` сортує їх за алфавітом.

### 3.4. Підрахунок слів

    printf "Linux is powerful\n" | wc -w

Результат:

    3

Параметр `-w` рахує слова.

## 4. Конвеєр із кількох команд

Конвеєри можуть містити три, чотири й більше команд.

Загальний синтаксис:

    command1 | command2 | command3 | command4

Вихід кожної команди стає входом наступної.

### 4.1. Пошук і підрахунок

    grep "ERROR" app.log | wc -l

Послідовність:

1. `grep` відбирає рядки з `ERROR`.
2. `wc -l` рахує кількість відібраних рядків.

### 4.2. Пошук, сортування та підрахунок

    grep "ERROR" app.log | sort | wc -l

Ця команда також рахує рядки з `ERROR`, але спочатку сортує їх.

Для самого підрахунку сортування зайве. Проте воно буде потрібне, якщо далі планується групування однакових рядків через `uniq`.

### 4.3. Пошук унікальних повідомлень

    grep "ERROR" app.log | sort | uniq

Що відбувається:

1. `grep` знаходить рядки з `ERROR`.
2. `sort` розташовує однакові рядки поруч.
3. `uniq` прибирає сусідні дублікати.

Важливо: `uniq` зазвичай обробляє лише послідовні однакові рядки. Саме тому перед ним часто використовують `sort`.

### 4.4. Підрахунок повторень

    grep "ERROR" app.log | sort | uniq -c

Приклад результату:

    3 ERROR: Connection failed
    2 ERROR: File not found
    5 ERROR: Request timeout

`uniq -c` додає кількість повторень кожного рядка.

Якщо потрібно показати найчастіші повідомлення першими:

    grep "ERROR" app.log | sort | uniq -c | sort -nr

Пояснення:

- перший `sort` групує однакові рядки;
- `uniq -c` рахує повторення;
- другий `sort -nr` сортує числові значення у зворотному порядку.

Зверни увагу: цей спосіб сортує за числом повторень, але за однакових значень порядок може бути неалфавітним.

## 5. Конвеєри з `grep`

`grep` — одна з найпоширеніших команд для фільтрації тексту.

Вона залишає лише ті рядки, які відповідають заданому шаблону.

### 5.1. Знайти рядки з ключовим словом

    cat app.log | grep "ERROR"

Кращий варіант, якщо потрібно читати лише один файл:

    grep "ERROR" app.log

### 5.2. Знайти рядки без ключового слова

    grep -v "DEBUG" app.log

Параметр `-v` інвертує результат: показує рядки, які не відповідають шаблону.

### 5.3. Пошук без урахування регістру

    grep -i "error" app.log

Команда знайде, наприклад, `ERROR`, `Error` і `error`.

### 5.4. Поєднати фільтрацію та підрахунок

    grep -i "error" app.log | wc -l

Це рахує кількість рядків, які містять `error` без урахування регістру.

### 5.5. Знайти рядки з кількома умовами

    grep "ERROR" app.log | grep "database"

Перший `grep` залишає рядки з `ERROR`, другий — серед них рядки з `database`.

Отже, результат міститиме рядки, які відповідають обом умовам.

### 5.6. Пошук із контекстом

`grep` має параметри для показу сусідніх рядків:

    grep -A 2 "ERROR" app.log

Показує два рядки після кожного збігу.

    grep -B 2 "ERROR" app.log

Показує два рядки перед кожним збігом.

    grep -C 2 "ERROR" app.log

Показує два рядки до та два після збігу.

Ці параметри корисні для аналізу журналів, коли важливо бачити контекст події.

## 6. Конвеєри з `sort` і `uniq`

`sort` сортує рядки, а `uniq` працює з послідовними повтореннями.

Разом вони дозволяють знаходити унікальні значення та аналізувати повторення.

### 6.1. Сортування тексту

    printf "pear\napple\norange\nbanana\n" | sort

Результат:

    apple
    banana
    orange
    pear

### 6.2. Прибрати дублікати

    printf "apple\nbanana\napple\norange\nbanana\n" | sort | uniq

Результат:

    apple
    banana
    orange

### 6.3. Порахувати повторення

    printf "apple\nbanana\napple\norange\nbanana\napple\n" | sort | uniq -c

Результат:

    3 apple
    2 banana
    1 orange

### 6.4. Показати лише повторювані рядки

    printf "apple\nbanana\napple\norange\nbanana\n" | sort | uniq -d

Результат:

    apple
    banana

Параметр `-d` показує лише рядки, які повторюються.

### 6.5. Показати лише рядки без повторень

    printf "apple\nbanana\napple\norange\nbanana\n" | sort | uniq -u

Результат:

    orange

Параметр `-u` показує рядки, які трапляються лише один раз у вхідних даних.

### 6.6. Знайти найчастіші значення

    printf "apple\nbanana\napple\norange\nbanana\napple\n" | sort | uniq -c | sort -nr

Результат:

    3 apple
    2 banana
    1 orange

Цей шаблон часто використовується для аналізу логів, списків користувачів і статистики.

## 7. Конвеєри з `head` і `tail`

`head` показує початок вхідних даних, а `tail` — кінець.

### 7.1. Перші рядки

    ls -la | head

За замовчуванням `head` показує перші 10 рядків.

Щоб показати лише п'ять:

    ls -la | head -n 5

### 7.2. Останні рядки

    ls -la | tail

За замовчуванням `tail` показує останні 10 рядків.

Показати останні п'ять:

    ls -la | tail -n 5

### 7.3. Знайти останні помилки у журналі

    grep "ERROR" app.log | tail -n 10

Команда показує останні 10 рядків, які містять `ERROR`, серед тих даних, які прочитав `grep`.

### 7.4. Вибрати перші результати після сортування

    sort names.txt | head -n 5

Це показує перші п'ять рядків відсортованого файлу.

### 7.5. Обмежити результат пошуку

    grep -i "error" app.log | head -n 20

Це зручно, коли журнал великий і потрібно переглянути лише початкову частину результатів.

## 8. Конвеєри з `cut`, `tr` і `wc`

Ці команди дозволяють вибирати поля, перетворювати символи та рахувати дані.

### 8.1. Вибрати окреме поле

Припустимо, є файл `users.txt`:

    101:Valeriy:admin
    102:Olena:user
    103:Petro:user

Отримати лише імена:

    cut -d ':' -f 2 users.txt

Результат:

    Valeriy
    Olena
    Petro

Порахувати кількість імен:

    cut -d ':' -f 2 users.txt | wc -l

### 8.2. Перетворити текст на великі літери

    printf "linux\nbash\nterminal\n" | tr 'a-z' 'A-Z'

Результат:

    LINUX
    BASH
    TERMINAL

### 8.3. Видалити зайві символи

    printf "user123admin456\n" | tr -d '0-9'

Результат:

    useradmin

### 8.4. Поєднати `cut`, `sort` і `uniq`

    cut -d ':' -f 3 users.txt | sort | uniq -c

Ця команда отримує третє поле, сортує значення та рахує повторення.

Для прикладу вище результат буде приблизно таким:

    2 user
    1 admin

Це корисний спосіб підрахувати кількість користувачів за ролями.

## 9. Конвеєри з `find`

`find` шукає файли й каталоги за заданими умовами. Його результат можна передавати іншим командам.

### 9.1. Знайти файли та порахувати рядки результату

    find . -type f | wc -l

Команда рахує кількість рядків, які вивів `find`, зазвичай — кількість знайдених файлів.

Цей підхід підходить для звичайних шляхів, але під час роботи з незвичайними іменами файлів надійніше використовувати `find` з іншими засобами, що підтримують нульові роздільники.

### 9.2. Знайти JavaScript-файли

    find . -type f -name "*.js"

### 9.3. Знайти JavaScript-файли та відфільтрувати певний каталог

    find . -type f -name "*.js" | grep -v "node_modules"

Команда виключає рядки, що містять `node_modules` у шляху.

Для надійнішого виключення каталогу можна задати умову безпосередньо в `find`:

    find . -type d -name node_modules -prune -o -type f -name "*.js" -print

Тут `-prune` не дозволяє обходити каталоги `node_modules`.

### 9.4. Знайти найбільші файли за розміром

    find . -type f -printf '%s %p\n' | sort -nr | head -n 10

Пояснення:

1. `find` виводить розмір файлу в байтах і шлях.
2. `sort -nr` сортує числові розміри у зворотному порядку.
3. `head -n 10` залишає перші десять рядків.

Зверни увагу: цей варіант використовує параметр `-printf`, який підтримується GNU `find` у Linux, але не всіма реалізаціями `find` в інших операційних системах.

## 10. Конвеєри та перенаправлення у файл

Конвеєри й перенаправлення вирішують різні завдання.

- `|` передає потік даних іншій команді.
- `>` записує стандартний вивід у файл.
- `>>` додає стандартний вивід у кінець файлу.
- `2>` записує стандартні помилки у файл.

### 10.1. Передавання результату іншій команді

    ls | sort

Результат `ls` передається команді `sort`.

### 10.2. Запис результату у файл

    ls > files.txt

Результат `ls` записується у файл.

### 10.3. Обробка та запис результату

    ls | sort > sorted-files.txt

Послідовність:

1. `ls` формує список.
2. `sort` сортує рядки.
3. `>` записує остаточний результат у файл.

### 10.4. Конвеєр і перенаправлення одночасно

    grep "ERROR" app.log | sort | uniq -c > error-summary.txt

Результат усіх етапів конвеєра буде записаний у `error-summary.txt`.

### 10.5. Запис результату та перегляд у терміналі

Для цього зручно використовувати `tee`:

    ls | tee files.txt

Команда `tee` записує отримані дані у файл і водночас передає їх далі, за замовчуванням — у термінал.

Можна продовжити конвеєр:

    ls | tee files.txt | sort

У цьому випадку:

1. `ls` передає список команді `tee`.
2. `tee` записує список у `files.txt`.
3. `tee` передає ті самі дані команді `sort`.
4. `sort` виводить відсортований список у термінал.

Важливо: у `files.txt` буде збережено початковий результат `ls`, а не результат сортування.

Щоб записати саме відсортований результат:

    ls | sort | tee sorted-files.txt

### 10.6. Додавання через `tee`

Щоб додати дані в кінець файлу, використовуй параметр `-a`:

    date | tee -a history.log

Це виведе дату в термінал і додасть її до `history.log`.

## 11. Що відбувається з помилками в конвеєрі

За замовчуванням оператор `|` передає лише стандартний вивід (`stdout`) попередньої команди на стандартне введення (`stdin`) наступної.

Стандартні помилки (`stderr`) автоматично не передаються наступній команді.

### 11.1. Приклад

    ls /etc /directory-does-not-exist | grep "ERROR"

Повідомлення про помилку від `ls` зазвичай з'явиться в терміналі, а `grep` отримає стандартний вивід `ls`.

Якщо повідомлення про помилку не містить `ERROR`, команда `grep` його не знайде, оскільки цей потік не потрапив у конвеєр.

### 11.2. Передати помилки у конвеєр у Bash

У Bash є оператор `|&`, який передає і `stdout`, і `stderr` попередньої команди наступній. За поведінкою він еквівалентний:

    command 2>&1 | command2

Приклад:

    ls /etc /directory-does-not-exist |& grep "cannot access"

Це може показати відповідні повідомлення про помилки, якщо текст помилки відповідає шаблону.

Оператор `|&` — це можливість Bash, а не універсальний синтаксис усіх оболонок.

### 11.3. Записати помилки окремо

    find /root -type f > found-files.txt 2> errors.txt

У цьому прикладі:

- знайдені шляхи записуються у `found-files.txt`;
- повідомлення про помилки записуються в `errors.txt`.

### 11.4. Передати і вивід, і помилки наступній команді

    find /root -type f 2>&1 | grep "Permission denied"

Це об'єднує `stderr` зі `stdout` перед передаванням у `grep`.

Тепер `grep` може відфільтрувати повідомлення про помилки разом зі звичайним виводом.

## 12. Коди завершення конвеєра

Кожна команда має код завершення.

Зазвичай:

- `0` означає успіх;
- ненульовий код означає помилку або інший спеціальний результат.

### 12.1. Перевірка коду завершення

    grep "ERROR" app.log
    echo $?

Якщо `grep` знайшов відповідність, він зазвичай повертає `0`.

Якщо відповідностей немає, він повертає `1`.

Інші ненульові коди можуть сигналізувати про помилки, наприклад про неможливість відкрити файл.

### 12.2. Код завершення конвеєра

Розглянемо:

    grep "NOT_FOUND" app.log | wc -l
    echo $?

Навіть якщо `grep` не знайшов жодного збігу, `wc -l` зазвичай успішно завершується й повертає `0`.

Тому стандартний код завершення всього конвеєра за замовчуванням — код завершення останньої команди, тобто `wc`.

Це важлива особливість: успішне завершення останньої команди не обов'язково означає, що всі попередні команди виконалися успішно.

### 12.3. Змінна `PIPESTATUS` у Bash

У Bash масив `PIPESTATUS` містить коди завершення команд останнього конвеєра.

Приклад:

    false | true
    echo "${PIPESTATUS[@]}"

Типовий результат:

    1 0

Команда `false` повертає ненульовий код, а `true` — нульовий.

Важливо: `PIPESTATUS` потрібно зчитувати одразу після конвеєра, оскільки наступна команда може змінити його значення.

Наприклад:

    false | true
    statuses=("${PIPESTATUS[@]}")
    printf '%s\n' "${statuses[@]}"

Збереження масиву одразу дозволяє використати коди завершення пізніше.

### 12.4. Опція `pipefail`

У Bash можна увімкнути режим `pipefail`:

    set -o pipefail

Після цього конвеєр повертає ненульовий код, якщо хоча б одна команда в конвеєрі завершується з помилкою. Якщо кілька команд завершилися з помилками, повертається код останньої команди з ненульовим результатом.

Приклад:

    set -o pipefail
    false | true
    echo $?

Результат:

    1

Без `pipefail` цей конвеєр зазвичай повернув би `0`, оскільки остання команда `true` завершується успішно.

### 12.5. `pipefail` у Bash-скриптах

Для скриптів часто використовують:

    #!/usr/bin/env bash

    set -o pipefail

    grep "ERROR" app.log | sort | uniq -c > error-summary.txt

Тепер помилка однієї з команд у конвеєрі не буде автоматично прихована успішним завершенням останньої команди.

Зверни увагу: `grep` повертає `1`, коли не знаходить збігів. У деяких скриптах це нормальна ситуація, а в інших — помилка бізнес-логіки. Тому обробку таких випадків потрібно продумувати окремо.

## 13. Конвеєри та процеси

Коли Bash виконує конвеєр, команди зазвичай запускаються як окремі процеси або виконуються в окремих середовищах відповідно до правил оболонки.

Оператор `|` з'єднує їх через потік даних.

### 13.1. Конвеєр не обов'язково створює проміжний файл

    cat large-file.txt | grep "ERROR" | wc -l

Дані передаються через конвеєр без потреби створювати окремий файл для кожного проміжного результату.

Однак це не означає, що кожна програма обробляє дані строго по одному рядку або що вона не використовує буферизацію. Поведінка залежить від конкретних програм.

### 13.2. Конвеєри та продуктивність

Конвеєри можуть бути ефективними, оскільки дозволяють поєднувати спеціалізовані утиліти без проміжних файлів.

Проте надмірна кількість непотрібних команд створює додаткову роботу.

Наприклад:

    cat app.log | grep "ERROR" | wc -l

Можна спростити:

    grep "ERROR" app.log | wc -l

Використовуй конвеєри для логічного ланцюжка обробки, а не просто для збільшення кількості команд.

## 14. Практичні сценарії

### 14.1. Порахувати кількість помилок у журналі

    grep -c "ERROR" app.log

Або за допомогою конвеєра:

    grep "ERROR" app.log | wc -l

Перший варіант простіший, якщо потрібно порахувати рядки, які містять `ERROR`.

### 14.2. Знайти найчастіші повідомлення про помилки

    grep "ERROR" app.log | sort | uniq -c | sort -nr | head -n 10

Цей конвеєр показує до десяти найчастіших рядків із `ERROR`.

### 14.3. Порахувати користувачів за ролями

Припустимо, `users.txt` містить:

    101:Valeriy:admin
    102:Olena:user
    103:Petro:user
    104:Iryna:admin
    105:Andrii:user

Команда:

    cut -d ':' -f 3 users.txt | sort | uniq -c

Результат:

    2 admin
    3 user

### 14.4. Знайти файли певного типу

    find . -type f -name "*.ts" | sort

Команда знаходить TypeScript-файли та сортує їхні шляхи.

### 14.5. Показати останні записи журналу з помилками

    grep -i "error" app.log | tail -n 20

Команда показує до двадцяти останніх рядків, що містять `error`.

### 14.6. Порахувати унікальні IP-адреси в простому форматі логів

Якщо файл `access.log` має формат, у якому перше поле — IP-адреса, можна спробувати:

    cut -d ' ' -f 1 access.log | sort | uniq

Щоб підрахувати кількість записів для кожної адреси:

    cut -d ' ' -f 1 access.log | sort | uniq -c | sort -nr

Цей приклад працює лише тоді, коли структура файлу відповідає очікуваному формату. Для складних форматів логів може знадобитися спеціалізований парсер.

### 14.7. Знайти великі файли та показати перші десять

    find . -type f -printf '%s %p\n' | sort -nr | head -n 10

Показує десять найбільших файлів за розміром у байтах.

### 14.8. Переглянути список пакетів і знайти потрібний

В Ubuntu та інших Debian-подібних системах:

    apt list --installed 2>/dev/null | grep -i "postgresql"

Тут `2>/dev/null` приховує повідомлення зі `stderr`, а `grep` фільтрує список за словом `postgresql`.

Для простого пошуку встановлених пакетів можна також використовувати:

    dpkg -l | grep -i "postgresql"

## 15. Типові помилки

### 15.1. Вважати, що `|` передає результат у файл

Неправильно, якщо потрібно зберегти результат:

    ls | sort

Ця команда виводить результат у термінал.

Правильно:

    ls | sort > sorted-files.txt

### 15.2. Додавати `cat` без потреби

Зайвий конвеєр:

    cat app.log | grep "ERROR"

Простіше:

    grep "ERROR" app.log

Однак `cat` може бути корисним, коли потрібно об'єднати кілька файлів або передати вміст іншій команді в конкретному сценарії.

### 15.3. Забувати про сортування перед `uniq`

Якщо однакові рядки не стоять поруч, `uniq` може не об'єднати всі їхні повторення.

Для підрахунку всіх повторень:

    sort names.txt | uniq -c

### 15.4. Вважати, що конвеєр автоматично передає stderr

Звичайний конвеєр:

    command1 | command2

передає `stdout`, але не `stderr`.

У Bash, якщо потрібно передати обидва потоки:

    command1 |& command2

Або:

    command1 2>&1 | command2

### 15.5. Не враховувати код завершення конвеєра

    grep "MISSING" app.log | wc -l

Навіть коли збігів немає, `wc` може завершитися успішно. Якщо важливий результат `grep`, потрібно враховувати його код завершення або використовувати відповідну логіку обробки.

### 15.6. Вважати, що конвеєр автоматично зупиняється після помилки

За замовчуванням оболонка може продовжити виконання наступних команд у конвеєрі, навіть якщо одна з попередніх завершилася з помилкою.

У Bash опція:

    set -o pipefail

допомагає виявляти помилки всередині конвеєра.

### 15.7. Не розуміти, що `head` може завершити читання раніше

    large-command | head -n 5

`head` припиняє читання після отримання потрібної кількості рядків. Якщо попередня команда продовжує писати дані, вона може отримати сигнал `SIGPIPE`.

Це звичайна поведінка для конвеєрів, у яких наступна команда споживає лише частину результату.

## 16. Практика

### Вправа 1. Простий конвеєр

Передай текст у `wc`, щоб порахувати рядки.

    printf "one\ntwo\nthree\nfour\n" | wc -l

Запитання: який результат ти очікуєш отримати?

### Вправа 2. Пошук і підрахунок

Створи файл `app.log`:

    cat > app.log << EOF
    INFO Application started
    ERROR Database connection failed
    INFO User logged in
    ERROR Request timeout
    WARNING Disk space is low
    ERROR Database connection failed
    EOF

Знайди рядки з `ERROR`:

    grep "ERROR" app.log

Порахуй їх:

    grep "ERROR" app.log | wc -l

### Вправа 3. Унікальні помилки

Виконай:

    grep "ERROR" app.log | sort | uniq

Запитання: чому повторюваний рядок з'являється лише один раз?

### Вправа 4. Підрахунок повторень

    grep "ERROR" app.log | sort | uniq -c

Запитання: яке повідомлення про помилку трапляється найчастіше?

### Вправа 5. Найчастіші повідомлення

    grep "ERROR" app.log | sort | uniq -c | sort -nr

Розшир завдання так, щоб залишити лише перші два результати:

    grep "ERROR" app.log | sort | uniq -c | sort -nr | head -n 2

### Вправа 6. Робота з полями

Створи `users.txt`:

    101:Valeriy:admin
    102:Olena:user
    103:Petro:user
    104:Iryna:admin
    105:Andrii:user

Отримай лише ролі:

    cut -d ':' -f 3 users.txt

Порахуй кількість користувачів за ролями:

    cut -d ':' -f 3 users.txt | sort | uniq -c

### Вправа 7. Зберегти результат і показати його

    grep "ERROR" app.log | tee errors.txt

Перевір файл:

    cat errors.txt

Зміни команду так, щоб у файл потрапляли лише унікальні повідомлення про помилки.

### Вправа 8. Знайти файли та порахувати їх

    find . -type f | wc -l

Потім знайди лише файли Markdown:

    find . -type f -name "*.md" | sort

Запитання: чим відрізняються ці два конвеєри?

### Вправа 9. Вивчити коди завершення

Виконай:

    false | true
    echo $?

Потім:

    set -o pipefail
    false | true
    echo $?

Поясни, чому результати відрізняються.

## 17. Мініпроєкт: аналізатор журналу

Мета — створити простий аналізатор текстового журналу, який:

- знаходить повідомлення про помилки;
- підраховує їхню кількість;
- створює список унікальних помилок;
- визначає найчастіші повідомлення;
- зберігає результати у файли.

### 17.1. Створи робочий каталог

    mkdir -p ~/linux-practice/pipes
    cd ~/linux-practice/pipes

### 17.2. Створи тестовий журнал

    cat > app.log << EOF
    INFO Application started
    ERROR Database connection failed
    INFO User logged in
    ERROR Request timeout
    WARNING Disk space is low
    ERROR Database connection failed
    ERROR Database connection failed
    INFO Request completed
    ERROR Request timeout
    EOF

### 17.3. Знайди всі помилки

    grep "ERROR" app.log > errors.txt

Перевір:

    cat errors.txt

### 17.4. Порахуй кількість помилок

    grep "ERROR" app.log | wc -l

Збережи результат у файл:

    grep "ERROR" app.log | wc -l > error-count.txt

### 17.5. Створи список унікальних помилок

    grep "ERROR" app.log | sort | uniq > unique-errors.txt

Переглянь:

    cat unique-errors.txt

### 17.6. Порахуй повторення помилок

    grep "ERROR" app.log | sort | uniq -c | sort -nr > error-summary.txt

Переглянь:

    cat error-summary.txt

### 17.7. Розширений варіант

Створи `analyze-log.sh`:

    #!/usr/bin/env bash

    set -o pipefail

    if [[ ! -f app.log ]]; then
        echo "Error: app.log not found" >&2
        exit 1
    fi

    grep "ERROR" app.log > errors.txt
    grep "ERROR" app.log | wc -l > error-count.txt
    grep "ERROR" app.log | sort | uniq > unique-errors.txt
    grep "ERROR" app.log | sort | uniq -c | sort -nr > error-summary.txt

    echo "Analysis completed."
    echo "Files created:"
    echo "- errors.txt"
    echo "- error-count.txt"
    echo "- unique-errors.txt"
    echo "- error-summary.txt"

Надай дозвіл на виконання:

    chmod +x analyze-log.sh

Запусти:

    ./analyze-log.sh

### Завдання для вдосконалення

1. Додай підрахунок рядків `WARNING`.
2. Додай окремий файл `warnings.txt`.
3. Зроби пошук без урахування регістру.
4. Додай дату виконання аналізу до `report.log`.
5. Записуй унікальні повідомлення в алфавітному порядку.
6. Перевір поведінку скрипта, якщо `app.log` відсутній.
7. Додай обробку випадку, коли `grep` не знаходить жодної помилки.

Останній пункт особливо важливий: `grep` повертає код `1`, якщо збігів немає. У реальному скрипті потрібно визначити, чи означає це очікувану відсутність помилок, чи ситуацію, яку слід вважати невдалою операцією.

## 21. Що запам'ятати

1. Оператор `|` передає `stdout` однієї команди на `stdin` наступної.
2. Конвеєри дозволяють комбінувати невеликі утиліти для складнішої обробки даних.
3. `grep` фільтрує рядки, `sort` сортує, `uniq` обробляє послідовні повторення, а `wc` рахує.
4. `sort | uniq -c` — типовий шаблон для підрахунку повторень.
5. `head` і `tail` допомагають обмежувати обсяг результату.
6. `tee` дозволяє одночасно зберегти результат і передати його далі.
7. Звичайний `|` не передає `stderr`; у Bash для цього можна використовувати `|&`.
8. Код завершення конвеєра за замовчуванням визначається останньою командою.
9. `set -o pipefail` допомагає виявляти помилки всередині конвеєра.
10. `PIPESTATUS` у Bash дає змогу перевірити коди завершення окремих команд.
11. Не додавай зайві команди, якщо можна виконати завдання простіше.
12. Завжди перевіряй поведінку конвеєра на порожніх даних і в разі помилок.

**Головна ідея:** конвеєри перетворюють набір простих Linux-команд на гнучкий інструмент обробки даних. Вони особливо корисні для пошуку інформації, аналізу логів, автоматизації та адміністрування системи.
