# Which, Type та Command — пошук і перевірка команд у Linux

`which`, `type` і `command` — це команди та можливості Bash, які допомагають з'ясувати, звідки запускається команда, як оболонка її розпізнає та як виконати її з певною поведінкою.

Вони корисні для діагностики `PATH`, пошуку виконуваних файлів, перевірки alias і функцій, написання Bash-скриптів та налагодження команд у Linux.

## 1. Для чого потрібні which, type і command

Коли ти вводиш команду в терміналі, Bash має визначити, що саме ти хочеш запустити.

Наприклад:

    ls
    node
    git
    cd

Ці назви можуть відповідати різним типам команд:

- **Alias** — псевдонім іншої команди.
- **Function** — функція Bash.
- **Builtin** — вбудована команда Bash.
- **Executable file** — виконуваний файл, знайдений через `PATH`.

Команди `which`, `type` і `command` допомагають дослідити або контролювати цю поведінку.

### Основні відмінності

| Команда | Призначення |
|---|---|
| `which` | Знаходить виконуваний файл команди через `PATH` |
| `type` | Пояснює, як Bash розпізнає назву команди |
| `command` | Виконує команду або допомагає перевірити її доступність |
| `type -a` | Показує всі відомі Bash варіанти команди |
| `command -v` | Показує, як оболонка інтерпретує команду, або її шлях |
| `command -V` | Виводить розширене пояснення про команду |

**Що потрібно пам'ятати:**

- `which` шукає виконуваний файл, а не всі можливі типи команд Bash.
- `type` зазвичай є найкращим інструментом для діагностики команд у Bash.
- `command -v` зручний у скриптах для перевірки наявності команди.
- `command` не є повною заміною `which` або `type`: у них різні завдання.

## 2. Команда which

`which` шукає виконуваний файл із заданою назвою в каталогах, перелічених у змінній середовища `PATH`.

### 2.1. Базовий синтаксис

    which COMMAND

Приклади:

    which ls
    which bash
    which git
    which node
    which python3

Можливий результат:

    /usr/bin/ls
    /usr/bin/bash
    /usr/bin/git
    /home/user/.nvm/versions/node/v24.21.0/bin/node
    /usr/bin/python3

Конкретні шляхи залежать від системи та встановлених програм.

### 2.2. Якщо команда не знайдена

    which nonexistent-command

Якщо відповідного виконуваного файла немає в `PATH`, `which` зазвичай нічого не виведе та завершиться з ненульовим кодом.

Перевірити код завершення можна так:

    which nonexistent-command
    echo $?

`0` зазвичай означає успіх, а ненульове значення — помилку або відсутність результату.

Не варто покладатися на конкретне ненульове значення для всіх реалізацій `which`.

### 2.3. Пошук кількох команд

    which ls bash git

Залежно від реалізації `which` команда може вивести шляхи до всіх знайдених виконуваних файлів.

### 2.4. Обмеження which

`which` не призначена для повного дослідження того, як Bash обробляє назву команди.

Наприклад:

    which cd

Команда `cd` зазвичай є вбудованою командою Bash, а не окремим виконуваним файлом. Тому `which cd` може нічого не показати.

Інший приклад:

    alias ll='ls -lah'
    which ll

Навіть якщо `ll` визначено як alias, `which` може його не показати.

Для таких випадків використовуй `type`.

**Практичне правило:** `which` зручна для швидкого пошуку виконуваних файлів, але для аналізу команд у Bash краще використовувати `type` або `command -v`.

## 3. Команда type

`type` — вбудована команда Bash, яка показує, як оболонка інтерпретує задану назву.

Вона може визначити:

- alias;
- функцію;
- вбудовану команду;
- виконуваний файл;
- інші доступні форми інтерпретації команди, залежно від контексту.

### 3.1. Базовий синтаксис

    type COMMAND

Приклади:

    type ls
    type cd
    type echo
    type git
    type node

Можливий результат:

    ls is aliased to ...
    cd is a shell builtin
    echo is a shell builtin
    git is /usr/bin/git
    node is /home/user/.nvm/versions/node/v24.21.0/bin/node

Формулювання та конкретні результати залежать від конфігурації Bash.

### 3.2. Перевірка alias

Спочатку створимо alias:

    alias ll='ls -lah'

Перевіримо його:

    type ll

Можливий результат:

    ll is aliased to `ls -lah'

Перевірити всі визначені alias можна командою:

    alias

Вивести визначення конкретного alias:

    alias ll

Видалити alias:

    unalias ll

Alias зазвичай існує лише в поточній оболонці або в тих оболонках, де його конфігурацію було завантажено.

### 3.3. Перевірка вбудованих команд Bash

    type cd
    type pwd
    type read
    type export
    type source

Можливий результат:

    cd is a shell builtin
    pwd is a shell builtin
    read is a shell builtin
    export is a shell builtin
    source is a shell builtin

Вбудовані команди виконуються самою оболонкою.

Наприклад, `cd` має змінювати поточний каталог саме в поточному процесі Bash. Якби вона запускалася лише як зовнішня програма, то не могла б змінити робочий каталог батьківської оболонки.

### 3.4. Перевірка функцій Bash

Створимо просту функцію:

    greet() {
        echo "Hello, Linux!"
    }

Перевіримо її тип:

    type greet

Можливий результат:

    greet is a function

Щоб побачити визначення функції:

    type -a greet

Або:

    declare -f greet

Виклик функції:

    greet

Результат:

    Hello, Linux!

### 3.5. Показати всі варіанти команди: type -a

Ключ `-a` наказує показати всі знайдені інтерпретації команди, а не лише першу.

    type -a ls
    type -a echo
    type -a python3
    type -a node

Наприклад, якщо `ls` одночасно має alias і виконуваний файл, результат може містити обидва варіанти.

Це корисно, коли потрібно зрозуміти, чому запускається не та версія програми, яку ти очікуєш.

### 3.6. Показати шлях до зовнішнього файла: type -P

Ключ `-P` шукає зовнішній виконуваний файл, ігноруючи alias та функції як результат пошуку.

    type -P ls
    type -P git
    type -P node

Якщо файл знайдено, команда виведе його шлях.

На відміну від звичайного `type`, ця форма корисна, коли потрібен саме зовнішній виконуваний файл.

### 3.7. Перевірити лише зовнішню команду: type -p

    type -p git
    type -p node

`-p` просить показати шлях до виконуваного файла, якщо його знайдено за правилами пошуку Bash. Поведінка залежить від того, чи Bash має відповідний запис у своїй таблиці команд.

Якщо потрібен саме пошук зовнішнього виконуваного файла незалежно від alias або функцій, часто зрозуміліше використовувати `type -P`.

## 4. Команда command

`command` — вбудована команда Bash, яка дозволяє виконати команду, не застосовуючи однойменну функцію оболонки.

Вона також має опції для перевірки того, як оболонка розпізнає команду.

### 4.1. Базовий синтаксис

    command COMMAND [ARGUMENTS...]

Приклади:

    command ls
    command pwd
    command git --version
    command node --version

У цьому випадку `command` виконує вказану команду, оминаючи пошук функції оболонки з такою назвою.

Важливо: це не означає, що `command` завжди запускає зовнішній файл. Вбудовані команди оболонки, як-от `pwd`, також можуть виконуватися.

### 4.2. Обхід однойменної функції

Припустімо, ми створили функцію з назвою `ls`:

    ls() {
        echo "Це моя функція ls"
    }

Звичайний виклик:

    ls

Результат:

    Це моя функція ls

Виклик через `command`:

    command ls

Тепер Bash не використовуватиме функцію `ls` і шукатиме відповідну команду за звичайними правилами пошуку, зокрема серед вбудованих команд та виконуваних файлів.

Щоб перевірити, що саме визначено:

    type -a ls

Після практики функцію можна видалити:

    unset -f ls

### 4.3. Перевірка команди: command -v

`command -v` показує, як оболонка розпізнає задану назву.

    command -v ls
    command -v cd
    command -v git
    command -v node

Можливі результати:

    ls
    cd
    /usr/bin/git
    /home/user/.nvm/versions/node/v24.21.0/bin/node

Точний результат залежить від того, чи назва відповідає alias, функції, вбудованій команді або зовнішньому файлу.

Ця форма особливо корисна в Bash-скриптах.

Наприклад:

    if command -v git >/dev/null 2>&1; then
        echo "Git встановлено або доступний оболонці"
    else
        echo "Git не знайдено"
    fi

Тут:

- `command -v git` перевіряє доступність команди;
- `>/dev/null` приховує стандартний вивід;
- `2>&1` спрямовує стандартний потік помилок туди ж;
- `if` перевіряє код завершення команди.

**Важливо:** якщо потрібно перевірити саме наявність зовнішнього виконуваного файла, `command -v` не завжди достатньо, оскільки результатом може бути alias, функція або вбудована команда.

### 4.4. Розширена інформація: command -V

    command -V ls
    command -V cd
    command -V git

`-V` виводить опис того, як оболонка розпізнає команду.

Наприклад, Bash може повідомити, що `cd` є вбудованою командою, а `git` — виконуваним файлом.

Порівняй:

    command -v cd
    command -V cd
    type cd

Усі три команди допомагають перевірити `cd`, але їхній формат і призначення відрізняються.

### 4.5. command у скриптах

Наприклад, скрипт перевіряє, чи доступний Node.js:

    #!/usr/bin/env bash

    if command -v node >/dev/null 2>&1; then
        echo "Node.js доступний"
        node --version
    else
        echo "Node.js не знайдено"
        exit 1
    fi

Такий підхід зручний, якщо скрипт залежить від `node`, `npm`, `git`, `curl` або інших програм.

## 5. Змінна PATH

`PATH` — змінна середовища, яка містить список каталогів, де оболонка шукає зовнішні виконувані файли.

### 5.1. Перегляд PATH

    echo "$PATH"

Приклад результату:

    /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

Каталоги розділені двокрапками `:`.

Порядок важливий: якщо в кількох каталогах є виконувані файли з однаковою назвою, за звичайного пошуку використовується перший відповідний файл.

### 5.2. Вивести кожен каталог окремо

    printf '%s\n' "$PATH" | tr ':' '\n'

Це зручніше для читання довгого списку.

### 5.3. Перевірити, звідки запускається команда

    command -v python3
    command -v node
    command -v npm
    command -v git

Потім можна переглянути відповідні файли:

    ls -l "$(command -v git)"

Обережно: така конструкція передбачає, що `command -v git` повертає шлях до файла. Для alias, функцій та деяких інших випадків цей підхід може бути непридатним.

### 5.4. Чому команда може не знаходитися

Можливі причини:

- програма не встановлена;
- каталог із програмою відсутній у `PATH`;
- файл не має права на виконання;
- вказано неправильну назву;
- програма встановлена в нестандартному каталозі;
- поточна оболонка ще не завантажила оновлені налаштування.

Для початкової діагностики:

    echo "$PATH"
    command -v PROGRAM
    type -a PROGRAM

Заміни `PROGRAM` на назву потрібної програми.

## 6. Порядок пошуку команд у Bash

Коли ти вводиш назву команди, Bash перевіряє її за власними правилами. Для типового інтерактивного Bash важливо розуміти такі категорії:

1. Alias — якщо його розгортання застосовується в поточному контексті.
2. Ключові слова оболонки, наприклад `if`, `for`, `while`.
3. Функції оболонки.
4. Вбудовані команди Bash.
5. Зовнішні виконувані файли, знайдені за `PATH`.

Точні правила залежать від контексту та того, як саме вводиться команда. Наприклад, alias зазвичай розгортається під час читання команди, а не як окремий етап виконання вже розібраного рядка.

### 6.1. Приклад із різними типами команд

    type if
    type cd
    type ls
    type -a ls

Ці команди демонструють, що назва може бути ключовим словом, вбудованою командою або зовнішнім файлом.

### 6.2. Якщо потрібно обійти alias

Для зовнішньої команди можна використати:

    command ls

Або поставити зворотну косу риску перед назвою команди:

    \ls

Це запобігає розгортанню alias для цієї назви в Bash.

Однак `\ls` не є універсальним способом обходу функцій. Для обходу функції зручніше використовувати `command ls`.

## 7. Порівняння which, type і command

| Завдання | Рекомендований варіант |
|---|---|
| Знайти виконуваний файл у `PATH` | `which git` |
| Дізнатися, як Bash розпізнає команду | `type git` |
| Показати всі варіанти команди | `type -a git` |
| Знайти саме зовнішній файл | `type -P git` |
| Перевірити доступність команди в скрипті | `command -v git` |
| Отримати опис типу команди | `command -V git` |
| Виконати команду в обхід однойменної функції | `command git` |
| Перевірити, чи доступний Node.js | `command -v node` |
| Дізнатися, чи є `cd` вбудованою командою | `type cd` |

### Що краще використовувати щодня?

Для звичайної роботи:

    type COMMAND

Для Bash-скриптів:

    command -v COMMAND

Для пошуку зовнішнього виконуваного файла:

    type -P COMMAND

`which` теж корисна, але її можливості залежать від конкретної реалізації, тому не варто використовувати її як єдиний інструмент перевірки команд.

## 8. Практичні приклади

### 8.1. Перевірити встановлення Git

    command -v git
    git --version

Якщо перша команда вивела шлях або інше коректне позначення доступної команди, можна перевірити версію Git.

### 8.2. Перевірити Node.js і npm

    command -v node
    command -v npm

    node --version
    npm --version

Якщо використовуєш `nvm`, шляхи можуть вести до каталогу конкретної версії Node.js у домашній директорії.

### 8.3. Знайти всі доступні варіанти Python

    type -a python
    type -a python3
    type -P python3

Це допомагає виявити ситуацію, коли встановлено кілька версій Python або назву перевизначено.

### 8.4. Знайти причину незвичної поведінки команди

Припустімо, `ls` працює не так, як очікується.

    type ls
    type -a ls
    command -v ls
    type -P ls

Ці команди допоможуть з'ясувати, чи впливають на результат alias, функція або розташування виконуваного файла.

### 8.5. Перевірити кілька залежностей у Bash-скрипті

    #!/usr/bin/env bash

    set -u

    for cmd in git node npm; do
        if command -v "$cmd" >/dev/null 2>&1; then
            printf 'OK: %s доступна\n' "$cmd"
        else
            printf 'ERROR: %s не знайдена\n' "$cmd" >&2
            exit 1
        fi
    done

Цей скрипт перевіряє доступність трьох команд і завершується з помилкою, якщо одну з них не знайдено.

Зверни увагу на `"$cmd"`: лапки зберігають значення змінної як один аргумент.

### 8.6. Перевірити команду та виконати її

    if command -v git >/dev/null 2>&1; then
        git status
    else
        echo "Git недоступний"
    fi

Це типовий шаблон для скриптів, які залежать від зовнішніх програм.

## 9. Типові помилки

### Помилка 1. Використовувати which для перевірки будь-якої команди

    which cd

Проблема: `cd` зазвичай є вбудованою командою Bash.

Правильніше:

    type cd
    command -v cd

### Помилка 2. Вважати, що шлях із which — це завжди команда, яка реально виконається

Alias або функція можуть вплинути на звичайний виклик.

Перевір:

    type -a ls
    command -v ls

### Помилка 3. Не перевіряти PATH

Якщо програма встановлена, але її каталог відсутній у `PATH`, оболонка може не знайти її за короткою назвою.

Перевір:

    echo "$PATH"
    type -P PROGRAM

### Помилка 4. Перевіряти доступність команди через текстовий результат

Не варто аналізувати виведений текст `which` або `type`, якщо можна перевірити код завершення.

Наприклад:

    if command -v git >/dev/null 2>&1; then
        echo "Git доступний"
    else
        echo "Git недоступний"
    fi

### Помилка 5. Плутати доступність команди з її працездатністю

Успішний результат `command -v node` означає, що оболонка може розпізнати назву `node`. Це не гарантує, що програма запускається правильно або що вона сумісна з поточним проєктом.

Для додаткової перевірки:

    node --version

### Помилка 6. Не враховувати функції оболонки

Якщо команда поводиться незвично, перевір:

    type -a COMMAND

Це часто швидше, ніж одразу змінювати `PATH` або перевстановлювати програму.

## 13. Мінішпаргалка

    # Пошук виконуваного файла
    which git

    # Як Bash розпізнає команду
    type git

    # Усі варіанти команди
    type -a git

    # Шлях до зовнішнього виконуваного файла
    type -P git

    # Перевірка доступності команди
    command -v git

    # Розширена інформація про команду
    command -V git

    # Виконати команду в обхід однойменної функції
    command ls

    # Переглянути PATH
    echo "$PATH"

    # Розбити PATH на окремі рядки
    printf '%s\n' "$PATH" | tr ':' '\n'

    # Перевірити доступність команди в скрипті
    if command -v git >/dev/null 2>&1; then
        echo "Git доступний"
    else
        echo "Git не знайдено"
    fi

## 14. Що потрібно запам'ятати

- `which` — швидкий пошук зовнішнього виконуваного файла через `PATH`.
- `type` — пояснює, як Bash розпізнає назву команди.
- `type -a` — показує всі відомі варіанти команди.
- `type -P` — шукає зовнішній виконуваний файл.
- `command -v` — зручний спосіб перевірити доступність команди в Bash-скрипті.
- `command -V` — виводить опис команди.
- `command COMMAND` — виконує команду в обхід однойменної функції оболонки.
- `PATH` — список каталогів, у яких шукаються зовнішні виконувані файли.
- Якщо команда поводиться незвично, почни з `type -a COMMAND`.
- Для автоматизації перевіряй код завершення, а не текст виводу.

**Головна ідея:** `which` допомагає знайти файл, `type` — зрозуміти команду, а `command` — перевірити доступність або керувати способом її виклику.
