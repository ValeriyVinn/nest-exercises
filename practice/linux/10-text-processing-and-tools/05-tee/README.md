# 05. tee

`tee` — це команда Linux, яка читає дані зі стандартного введення (`stdin`), виводить їх у стандартне виведення (`stdout`) і одночасно записує їх в один або кілька файлів.

Назва `tee` походить від форми літери T у трубопроводах: потік даних розгалужується на кілька напрямків.

`tee` особливо корисна, коли потрібно одночасно:

- побачити результат команди в терміналі;
- зберегти результат у файл;
- записати виведення команди в лог;
- передати дані наступній команді через pipe;
- зберегти проміжний результат конвеєра;
- записати діагностичну інформацію під час налагодження Bash-скриптів.

Основна схема роботи:

    command → tee → terminal
                  ↓
                 file

`tee` часто використовується разом із:

    |
    >
    >>
    sudo
    grep
    find
    sort
    wc
    stdout
    stderr
    logging
    Bash scripts

## Що потрібно пам'ятати

• `tee` читає дані зі `stdin`.

• `tee` виводить отримані дані в `stdout` і записує їх у зазначені файли.

• За замовчуванням `tee` перезаписує наявні файли.

• Опція `-a` додає дані в кінець файлу замість перезаписування.

• `tee` може записувати дані одночасно в кілька файлів.

• `tee` часто використовується в pipeline, коли потрібно і побачити, і зберегти результат команди.

• `>` перенаправляє виведення у файл, а `tee` дозволяє одночасно залишити його у `stdout`.

• `sudo tee` допомагає записувати дані у файли, доступні для запису лише привілейованим користувачам.

• Звичайний `tee` обробляє `stdout`, а не `stderr`, якщо помилки явно не перенаправлені до його входу.

• `tee` не перетворює текст і не фільтрує його — вона копіює отриманий потік.

• `tee` не є повною заміною `xargs`: `tee` розгалужує потік даних, а `xargs` формує аргументи команд.

# Що таке tee

`tee` — утиліта Linux для копіювання стандартного введення одночасно у стандартне виведення та файли.

Загальний синтаксис:

    tee [OPTIONS] [FILE...]

Наприклад:

    echo "Hello Linux" | tee output.txt

Результат у терміналі:

    Hello Linux

У файлі `output.txt` також буде записано:

    Hello Linux

Що відбулося:

    echo
      ↓
    stdout
      ↓
    pipe
      ↓
    tee
      ├── stdout → terminal
      └── file   → output.txt

Тобто `tee` створює два напрямки для одного потоку даних.

---

# stdin та stdout

Щоб розуміти `tee`, потрібно знати два основні поняття.

## stdin

`stdin` (standard input) — стандартне введення програми.

Це може бути:

- введення з клавіатури;
- результат попередньої команди через pipe;
- дані, перенаправлені з файлу.

Приклад:

    printf '%s\n' apple banana orange | tee fruits.txt

`tee` отримує три рядки через `stdin`.

## stdout

`stdout` (standard output) — стандартне виведення програми.

Зазвичай це термінал, але його можна передати наступній команді.

Приклад:

    printf '%s\n' apple banana orange | tee fruits.txt

Результат у терміналі:

    apple
    banana
    orange

Ті самі рядки записуються у файл `fruits.txt`.

---

# Базове використання tee

## Записати результат команди у файл

    echo "Hello Linux" | tee output.txt

Результат:

    Hello Linux

Файл `output.txt` міститиме:

    Hello Linux

Якщо файл не існує, `tee` створить його, якщо це дозволяють права доступу до каталогу.

Якщо файл уже існує, за замовчуванням його вміст буде перезаписано.

---

## Записати результат команди та побачити його в терміналі

    date | tee current-date.txt

Команда `date` виводить поточні дату й час.

`tee` одночасно:

    1. показує результат у терміналі;
    2. записує його у current-date.txt.

---

## Записати результат ls

    ls -la | tee directory-list.txt

Команда показує вміст поточного каталогу та зберігає результат у файлі.

---

## Записати результат команди wc

    find . -type f | wc -l | tee file-count.txt

Команда рахує кількість звичайних файлів, знайдених у поточному каталозі та його підкаталогах, і зберігає результат у `file-count.txt`.

Тут `tee` отримує результат уже після обробки командою `wc -l`.

---

# tee та pipe

Pipe (`|`) передає стандартне виведення однієї команди на стандартне введення іншої.

Загальний синтаксис:

    command1 | command2

Наприклад:

    printf '%s\n' apple banana orange | grep 'banana'

Результат:

    banana

Тепер використаємо `tee`:

    printf '%s\n' apple banana orange | tee fruits.txt | grep 'banana'

Результат у терміналі:

    banana

У файлі `fruits.txt` залишаться всі три рядки:

    apple
    banana
    orange

Логіка роботи:

    printf
      ↓
    tee
      ├── записує всі рядки у fruits.txt
      ↓
    grep
      ├── залишає рядки, що містять banana
      ↓
    terminal

Важливо: `tee` передає далі всі дані, які отримала, незалежно від того, як наступна команда їх обробляє.

---

# tee vs перенаправлення >

Це одна з найважливіших відмінностей.

## Перенаправлення >

Оператор `>` записує стандартне виведення команди у файл.

    echo "Hello Linux" > output.txt

Результат у терміналі не відображається.

Файл `output.txt` міститиме:

    Hello Linux

Якщо файл уже існує, його вміст буде перезаписано.

## Команда tee

    echo "Hello Linux" | tee output.txt

Результат:

    Hello Linux

Текст одночасно з'являється в терміналі та записується у файл.

## Порівняння

    command > file
        → записати stdout у файл

    command | tee file
        → показати stdout і записати його у файл

    command >> file
        → додати stdout у кінець файлу

    command | tee -a file
        → показати stdout і додати його у кінець файлу

`tee` особливо корисна, коли потрібно зберегти проміжний результат конвеєра, не втрачаючи можливості бачити його в терміналі.

---

# Опція -a

`-a` (`--append`) додає дані в кінець файлу замість перезаписування.

Синтаксис:

    command | tee -a FILE

Наприклад:

    echo "First line" | tee output.txt

Потім:

    echo "Second line" | tee -a output.txt

У терміналі буде показано відповідні рядки.

Файл `output.txt` міститиме:

    First line
    Second line

Без `-a` другий виклик перезаписав би файл, і залишився б тільки рядок `Second line`.

---

## Записувати повідомлення в лог

Наприклад:

    echo "Application started" | tee -a app.log
    echo "Database connected" | tee -a app.log
    echo "Application finished" | tee -a app.log

У терміналі видно всі повідомлення, і водночас вони додаються до `app.log`.

Це простий спосіб вести лог під час виконання команд або скриптів.

---

# Запис у кілька файлів

`tee` може приймати кілька імен файлів.

Синтаксис:

    command | tee FILE1 FILE2 FILE3

Наприклад:

    echo "Hello Linux" | tee output1.txt output2.txt output3.txt

Результат у терміналі:

    Hello Linux

Текст буде записаний у всі три файли:

    output1.txt
    output2.txt
    output3.txt

---

## Додавання до кількох файлів

    echo "New event" | tee -a app.log system.log debug.log

Повідомлення буде:

- показане в терміналі;
- додане до `app.log`;
- додане до `system.log`;
- додане до `debug.log`.

Усі файли отримають однаковий текст.

---

# tee у багатокроковому pipeline

`tee` особливо корисна у складних конвеєрах команд.

Наприклад:

    printf '%s\n' apple banana orange grape |
        tee all-fruits.txt |
        grep 'a' |
        tee fruits-with-a.txt |
        sort

Результат:

    apple
    banana
    grape
    orange

Файл `all-fruits.txt` міститиме всі початкові рядки:

    apple
    banana
    orange
    grape

Файл `fruits-with-a.txt` міститиме рядки, які пройшли через `grep`:

    apple
    banana
    orange
    grape

У цьому прикладі всі чотири слова містять літеру `a`.

Схема:

    source
      ↓
    tee all-fruits.txt
      ↓
    grep 'a'
      ↓
    tee fruits-with-a.txt
      ↓
    sort
      ↓
    terminal

Кожен `tee` зберігає поточний потік на своєму етапі.

---

# tee для налагодження pipeline

Якщо складний pipeline повертає неочікуваний результат, `tee` допомагає перевірити проміжні дані.

Наприклад:

    find . -type f |
        tee found-files.txt |
        grep '\.js$' |
        tee js-files.txt |
        wc -l

Тут:

    find
        → знаходить файли

    tee found-files.txt
        → зберігає список усіх знайдених файлів

    grep '\.js$'
        → залишає шляхи, що закінчуються на .js

    tee js-files.txt
        → зберігає список JavaScript-файлів

    wc -l
        → рахує кількість рядків

Якщо кінцевий результат неправильний, можна перевірити `found-files.txt` і `js-files.txt`, щоб визначити, на якому етапі виникла проблема.

Важливо: цей простий приклад передає шляхи як текстові рядки. Для повноцінної обробки довільних імен файлів, які можуть містити символи нового рядка, потрібні NUL-розділені дані та інші відповідні інструменти.

# tee та sudo

Іноді потрібно записати дані у файл, до якого звичайний користувач не має права запису.

Наприклад, конфігураційні файли в `/etc`.

На перший погляд може здатися, що це спрацює:

    sudo echo "Example setting" > /etc/example.conf

Але це не працює так, як очікується.

Причина: перенаправлення `>` виконує оболонка поточного користувача до запуску `sudo`. Саме оболонка намагається відкрити файл для запису.

Тому навіть якщо `echo` виконується з правами `root`, перенаправлення може завершитися помилкою доступу.

## Правильний підхід із sudo tee

    echo "Example setting" | sudo tee /etc/example.conf

Тут:

    echo
        → формує текст

    sudo tee
        → запускає tee з підвищеними правами

    /etc/example.conf
        → файл, у який записуються дані

Тепер саме `tee` відкриває файл із правами, наданими `sudo`.

Увага: ця команда перезаписує вміст файлу. Не використовуй її для системних конфігурацій без розуміння наслідків.

---

## Додавання до системного файлу

Щоб додати текст у кінець файлу:

    echo "Example setting" | sudo tee -a /etc/example.conf

Опція `-a` означає append.

Важливо:

• `sudo tee FILE` перезаписує файл.

• `sudo tee -a FILE` додає текст у кінець.

• Не всі системні файли призначені для довільного додавання рядків.

• Перед зміною системної конфігурації варто створити резервну копію та перевірити синтаксис конфігурації.

# tee та stderr

За замовчуванням `tee` читає дані зі `stdin`, тому вона отримує звичайне стандартне виведення (`stdout`), якщо потоки не перенаправлені.

Помилки команди часто надходять у `stderr` і не потрапляють до `tee` автоматично.

Наприклад:

    ls existing-file missing-file | tee output.txt

Залежно від наявності файлів, `ls` може показати список успішно знайдених об'єктів у `stdout`, а повідомлення про помилку вивести в `stderr`.

Файл `output.txt` зазвичай міститиме лише стандартне виведення.

---

## Записати stdout і stderr разом

У Bash можна перенаправити `stderr` у `stdout`:

    command 2>&1 | tee command.log

Тут:

    2
        → file descriptor stderr

    1
        → file descriptor stdout

    2>&1
        → спрямувати stderr туди, куди зараз спрямований stdout

    tee command.log
        → отримати об'єднаний потік і записати його у файл

Наприклад:

    ls existing-file missing-file 2>&1 | tee ls.log

Тепер у `ls.log` потраплять і звичайне виведення, і повідомлення про помилку.

Порядок перенаправлень має значення.

---

## Записати тільки stderr

Можна спрямувати `stderr` у `tee`, залишивши `stdout` окремо:

    command 2> >(tee errors.log >&2)

Це приклад використання process substitution у Bash.

Що відбувається:

    command
      ├── stdout → звичайний stdout
      └── stderr → tee
                      ├── errors.log
                      └── stderr

Такий шаблон корисний у Bash-скриптах, коли потрібно зберегти повідомлення про помилки, але водночас продовжувати показувати їх у терміналі.

Process substitution `>(...)` є можливістю Bash та деяких інших оболонок, але не POSIX `sh`.

---

# tee та /dev/null

`/dev/null` — спеціальний пристрій, який відкидає записані в нього дані.

Наприклад:

    echo "Hello" | tee /dev/null

Результат у терміналі:

    Hello

`tee` передає текст у `stdout`, але копія, спрямована в `/dev/null`, відкидається.

Це може бути корисно, коли потрібно зберегти структуру pipeline, але не створювати файл.

Інший приклад:

    command | tee /dev/null | grep 'ERROR'

У цьому випадку `tee` не зберігає дані у звичайний файл, але передає їх далі.

Проте якщо не потрібно записувати дані в інше місце, часто простіше використати:

    command | grep 'ERROR'

---

# Опція -i

`-i` (`--ignore-interrupts`) просить `tee` ігнорувати сигнали переривання `SIGINT`.

Приклад:

    command | tee -i output.log

Ця опція може бути корисною в окремих сценаріях роботи з потоками, але для повсякденних команд зазвичай не потрібна.

Важливо: `-i` не означає, що вся команда або весь pipeline ігнорує всі сигнали. Вона стосується поведінки самої `tee`.

---

# tee та логування

Логування — один із найпоширеніших способів використання `tee`.

Наприклад, потрібно виконати команду та зберегти її виведення.

    npm run build 2>&1 | tee build.log

Тут:

    npm run build
        → запускає процес збирання проєкту

    2>&1
        → об'єднує stdout і stderr

    tee build.log
        → показує результат і записує його в build.log

Такий підхід зручний для проєктів JavaScript, TypeScript, Next.js та NestJS.

Важливо: через pipeline код завершення за замовчуванням може відображати результат останньої команди (`tee`), а не першої команди (`npm run build`).

---

## Зберегти код завершення команди в Bash

У Bash можна ввімкнути `pipefail`:

    set -o pipefail

    npm run build 2>&1 | tee build.log

За ввімкненого `pipefail` pipeline повертає ненульовий код, якщо одна з команд завершилася помилкою. Якщо кілька команд завершилися помилкою, код pipeline відповідає останній команді в конвеєрі, що завершилася ненульовим кодом.

Для окремого отримання статусу першої команди в Bash можна використати масив `PIPESTATUS`:

    npm run build 2>&1 | tee build.log

    command_status=${PIPESTATUS[0]}

    if [ "$command_status" -eq 0 ]; then
        echo "Build successful"
    else
        echo "Build failed"
    fi

Важливо: потрібно зберегти значення `PIPESTATUS` одразу після pipeline, до виконання інших команд, оскільки подальші команди змінюють його.

# tee та Bash-скрипти

`tee` зручно використовувати у скриптах для збереження проміжних результатів.

Наприклад:

    #!/usr/bin/env bash

    set -o pipefail

    echo "Starting script" | tee -a script.log

    find . -type f -name '*.js' |
        tee -a script.log |
        wc -l |
        tee -a script.log

    echo "Script finished" | tee -a script.log

Цей скрипт:

    1. Записує повідомлення про початок.
    2. Знаходить JavaScript-файли.
    3. Зберігає список знайдених шляхів у лог.
    4. Рахує кількість рядків у потоці.
    5. Додає результат до логу.
    6. Записує повідомлення про завершення.

У цьому прикладі `find` видає звичайний текстовий список шляхів. Для надійної роботи з довільними іменами файлів потрібно адаптувати обробку, наприклад використовувати NUL-розділення.

---

# tee та файлові дескриптори

У Linux стандартно використовуються три основні файлові дескриптори:

    0 → stdin
    1 → stdout
    2 → stderr

`tee` читає зі стандартного введення та записує:

    stdout
    files

Приклад:

    printf '%s\n' one two three | tee output.txt

Схема:

    stdin (0)
       ↓
      tee
       ├── stdout (1)
       └── output.txt

Якщо потрібно об'єднати `stderr` і `stdout`, можна використати:

    command 2>&1 | tee output.log

---

# tee та xargs

Ці команди мають різне призначення.

`tee`:

    command | tee output.txt

Копіює потік у файл і передає його далі через `stdout`.

`xargs`:

    printf '%s\n' a b c | xargs echo

Читає вхідні дані та формує аргументи для іншої команди.

Порівняння:

    tee
        → розгалужує потік даних

    xargs
        → формує аргументи команди

`tee` не замінює `xargs`, і навпаки.

# Практичні приклади

## Приклад 1 — зберегти дату

    date | tee current-date.txt

## Приклад 2 — зберегти список файлів

    ls -la | tee files.txt

## Приклад 3 — додати повідомлення в лог

    echo "Task completed" | tee -a app.log

## Приклад 4 — записати результат пошуку

    grep -R -n 'TODO' . | tee todos.txt

## Приклад 5 — зберегти кількість файлів

    find . -type f | wc -l | tee file-count.txt

## Приклад 6 — зберегти результат і передати його далі

    printf '%s\n' apple banana orange | tee fruits.txt | sort

## Приклад 7 — зберегти результат npm build

    npm run build 2>&1 | tee build.log

## Приклад 8 — записати stdout і stderr

    command 2>&1 | tee output.log

## Приклад 9 — записати в кілька файлів

    echo "System check" | tee check.log system.log

## Приклад 10 — додати дані до кількох логів

    echo "New request" | tee -a app.log requests.log

## Приклад 11 — записати дані у файл із правами root

    echo "Example setting" | sudo tee /etc/example.conf

Увага: команда перезаписує файл.

## Приклад 12 — додати дані у файл із правами root

    echo "Example setting" | sudo tee -a /etc/example.conf

## Приклад 13 — зберегти проміжний результат grep

    find . -type f -name '*.js' |
        tee all-js-files.txt |
        grep 'server' |
        tee server-files.txt

## Приклад 14 — записати результати тестів

    npm test 2>&1 | tee test-results.log

## Приклад 15 — записати виведення компілятора

    npx tsc --noEmit 2>&1 | tee typescript-check.log

# Типові помилки

## 1. Очікувати, що tee лише записує файл

Команда:

    echo "Hello" | tee output.txt

не лише записує файл, а й виводить текст у `stdout`.

Якщо потрібно тільки записати файл, можна використати:

    echo "Hello" > output.txt

---

## 2. Випадково перезаписати файл

Команда:

    echo "New line" | tee output.txt

перезаписує наявний файл.

Якщо потрібно додати рядок:

    echo "New line" | tee -a output.txt

---

## 3. Забувати про stderr

Команда:

    command | tee output.log

зазвичай записує лише `stdout`.

Якщо потрібні також помилки:

    command 2>&1 | tee output.log

---

## 4. Неправильно використовувати sudo

❌ Такий запис може завершитися помилкою доступу:

    sudo echo "Text" > /etc/example.conf

✔ Краще:

    echo "Text" | sudo tee /etc/example.conf

Для додавання до файлу:

    echo "Text" | sudo tee -a /etc/example.conf

---

## 5. Вважати, що успіх tee означає успіх усієї команди

Приклад:

    false | tee output.log

`false` повертає ненульовий код завершення, але `tee` може завершитися успішно.

У Bash використовуй:

    set -o pipefail

Це дозволяє виявити помилку в попередній команді pipeline.

---

## 6. Очікувати, що tee змінює дані

Команда:

    printf '%s\n' apple banana | tee output.txt

не фільтрує і не сортує дані.

Для фільтрації використовуй:

    grep

Для сортування:

    sort

Для підрахунку:

    wc

`tee` призначена для копіювання потоку.

---

## 7. Не враховувати права доступу

Якщо немає прав запису до файлу або каталогу, `tee` може повідомити про помилку.

Наприклад:

    echo "Text" | tee /root/example.txt

Звичайний користувач зазвичай не має права записувати у `/root`.

Для адміністративних операцій можна використовувати `sudo tee`, якщо це дозволено системою.

---

## 8. Використовувати tee там, де він не потрібен

Якщо потрібно просто записати результат у файл:

    command > output.txt

Якщо потрібно записати та побачити результат:

    command | tee output.txt

Вибирай інструмент залежно від задачі.

# Основні правила

    tee
        → копіює stdin у stdout і файли

    tee file
        → записує у файл і показує результат

    tee -a file
        → додає дані в кінець файлу

    tee file1 file2
        → записує в кілька файлів

    >
        → перенаправляє stdout у файл

    >>
        → додає stdout у кінець файлу

    2>&1
        → перенаправляє stderr туди, куди спрямовано stdout

    command | tee file
        → показати результат і зберегти його

    command 2>&1 | tee file
        → показати й зберегти stdout та stderr

    sudo tee file
        → записати файл із правами sudo

    set -o pipefail
        → враховувати помилки команд у pipeline

# Головне

• `tee` читає дані зі `stdin`, виводить їх у `stdout` і записує у файли.

• `tee` особливо корисна, коли потрібно одночасно бачити результат команди та зберігати його.

• За замовчуванням `tee` перезаписує файли.

• `tee -a` додає дані в кінець файлу.

• `tee` може записувати дані одночасно в кілька файлів.

• У pipeline `tee` дозволяє зберігати проміжні результати для перевірки та налагодження.

• Звичайний `tee` обробляє `stdout`, а `stderr` потрібно перенаправляти окремо.

• Для запису обох потоків зазвичай використовують:

    command 2>&1 | tee output.log

• Для запису у файл, доступний лише для адміністратора, можна використовувати:

    command | sudo tee /path/to/file

• Для додавання до такого файлу:

    command | sudo tee -a /path/to/file

• У Bash `set -o pipefail` допомагає виявляти помилки в pipeline.

• `tee` не фільтрує та не сортує дані — вона копіює потік.

• `tee` і `xargs` мають різне призначення:

    tee
        → копіює та розгалужує потік

    xargs
        → формує аргументи команд

• Основна модель роботи:

    command
       ↓
      stdout
       ↓
      pipe
       ↓
      tee
       ├── terminal
       ├── file
       └── next command

• `tee` — важливий інструмент для роботи з Linux-терміналом, Bash-скриптами, логами та налагодженням конвеєрів команд.
