# 01. Regular Expressions (Regex)

Regular Expressions (регулярні вирази, або regex) — це спеціальні шаблони, які використовуються для пошуку, перевірки, вилучення та заміни тексту.

У Linux регулярні вирази часто використовуються разом із командами:

    grep
    grep -E
    sed
    awk
    find
    less
    vim

Regex допомагає знаходити текст не лише за точним збігом, а й за певними правилами.

Наприклад, можна знайти:

- усі рядки, що містять слово `error`;
- рядки, які починаються з `INFO`;
- рядки, які закінчуються на `.js`;
- усі послідовності цифр;
- рядки, що містять IP-адреси;
- слова певної довжини;
- рядки, які відповідають заданому формату;
- текст, який потрібно замінити або витягнути.

Регулярні вирази особливо корисні для аналізу логів, пошуку в конфігураційних файлах, обробки текстових даних і автоматизації завдань.

У цьому розділі розглядаються регулярні вирази в Linux, а не регулярні вирази JavaScript. Основні принципи схожі, але синтаксис, режими та підтримувані можливості залежать від конкретного інструмента.

## Що потрібно пам'ятати

• Regex — це шаблон для пошуку або обробки тексту.

• Звичайні символи зазвичай відповідають самим собі.

• Метасимволи мають спеціальне значення.

• `.` у regex означає будь-який один символ, крім символу нового рядка в типових режимах.

• `*` означає нуль або більше повторень попереднього елемента.

• `+` означає один або більше повторень у режимі ERE.

• `?` означає нуль або одне повторення в режимі ERE.

• `[abc]` означає один символ із набору `a`, `b`, `c`.

• `[0-9]` означає одну цифру.

• `[^0-9]` означає один символ, який не є цифрою.

• `^` на початку шаблону позначає початок рядка.

• `$` наприкінці шаблону позначає кінець рядка.

• `|` у режимі ERE означає альтернативу.

• `()` у режимі ERE використовуються для групування.

• `\` часто використовується для екранування спеціальних символів.

• `grep` за замовчуванням використовує BRE, а `grep -E` — ERE.

• `grep -F` шукає буквальний текст, а не регулярний вираз.

• `grep -P` підтримує PCRE у версіях GNU grep, де цей режим доступний.

• Не всі інструменти Linux підтримують однаковий синтаксис regex.

• Regex потрібно перевіряти на реальних прикладах, особливо якщо він використовується для автоматизації.

# Що таке Regular Expression

Регулярний вираз — це опис текстового шаблону.

Наприклад, текстовий файл `app.log`:

    INFO Server started
    ERROR Database connection failed
    INFO Request completed
    ERROR Invalid password

Знайти всі рядки, що містять `ERROR`:

    grep 'ERROR' app.log

Результат:

    ERROR Database connection failed
    ERROR Invalid password

Тут:

    grep       → команда пошуку
    'ERROR'    → regex pattern
    app.log    → файл

У цьому випадку шаблон містить лише звичайні символи.

Але regex дозволяє описувати складніші правила.

Наприклад, знайти рядки, що починаються з `ERROR`:

    grep '^ERROR' app.log

Знайти рядки, що закінчуються на `failed`:

    grep 'failed$' app.log

Знайти рядки, які містять одну або більше цифр, використовуючи ERE:

    grep -E '[0-9]+' app.log

---

# Literal Characters

Literal character — звичайний символ, який шукається буквально.

Наприклад:

    grep 'error' app.log

Знайде рядки, що містять послідовність:

    error

Інші приклади:

    grep 'localhost' config.txt

    grep '127.0.0.1' config.txt

    grep 'database' app.log

Звичайні літери та цифри зазвичай не потребують спеціального екранування.

Важливо пам'ятати про регістр:

    error
    ERROR
    Error

Це різні послідовності символів для звичайного чутливого до регістру пошуку.

Щоб ігнорувати регістр у `grep`, використовують:

    grep -i 'error' app.log

---

# Metacharacters

Metacharacters — символи, які мають спеціальне значення в регулярних виразах.

Основні метасимволи:

    .  ^  $  *  +  ?  [ ]  ( )  { }  |

Їхнє значення залежить від режиму regex.

Наприклад:

    grep -E 'a.b' file.txt

Шаблон:

    a.b

означає:

    a
    будь-який один символ
    b

Він може відповідати:

    a-b
    a_b
    a1b
    acb

Але не відповідає:

    ab

оскільки між `a` та `b` немає символу.

---

# Dot — крапка

Крапка `.` означає будь-який один символ, крім символу нового рядка в типових режимах regex.

Приклад:

    grep -E 'c.t' words.txt

Можливі збіги:

    cat
    cot
    cut
    c9t

Не відповідає:

    ct

оскільки немає символу між `c` і `t`.

Інший приклад:

    grep -E 'log.' app.log

Може знайти:

    logs
    log1
    log-

Крапка не означає буквально крапку.

## Як шукати крапку буквально

Крапка в regex є метасимволом, тому для пошуку саме символу `.` її потрібно екранувати.

Наприклад:

    grep -E '\.js' files.txt

Знайде текст, що містить:

    .js

Наприклад:

    app.js
    server.js
    index.js

Однак цей шаблон не означає, що рядок обов'язково закінчується на `.js`.

Щоб шукати рядки, які закінчуються на `.js`:

    grep -E '\.js$' files.txt

---

# Anchors

Anchors — спеціальні символи, які позначають позицію в тексті.

Основні anchors:

    ^  → початок рядка
    $  → кінець рядка

Вони не шукають звичайний символ. Вони перевіряють позицію.

---

## Початок рядка — ^

Наприклад, файл `app.log`:

    INFO Server started
    ERROR Database failed
    INFO Request completed
    ERROR Invalid password

Знайти рядки, що починаються з `ERROR`:

    grep -E '^ERROR' app.log

Результат:

    ERROR Database failed
    ERROR Invalid password

Шаблон:

    ^ERROR

означає:

    початок рядка
        ↓
    ERROR

Якщо `ERROR` розташований у середині рядка, такий рядок не відповідатиме шаблону.

Наприклад:

    2026-10-19 ERROR Database failed

Цей рядок не відповідає `^ERROR`.

---

## Кінець рядка — $

Символ `$` означає кінець рядка.

Наприклад:

    grep -E 'failed$' app.log

Знайде рядки, що закінчуються на:

    failed

Не знайде рядок:

    failed to connect

оскільки після `failed` є інший текст.

Щоб знайти рядки, які закінчуються на `.js`:

    grep -E '\.js$' files.txt

---

## Порожній рядок

Команда:

    grep -E '^$' file.txt

Знаходить порожні рядки.

Пояснення:

    ^  → початок рядка
    $  → кінець рядка

Між ними немає жодного символу.

Щоб знайти непорожні рядки:

    grep -E '.' file.txt

Це працює для звичайних текстових файлів: рядок має містити хоча б один символ, який відповідає крапці.

---

# Character Classes

Character class — набір символів, з якого має збігатися один символ.

Синтаксис:

    [characters]

Наприклад:

    grep -E '[abc]' file.txt

Знайде рядки, які містять хоча б один із символів:

    a
    b
    c

Важливо: `[abc]` відповідає одному символу, а не слову `abc`.

Приклади:

    [aeiou]  → одна голосна літера
    [xyz]    → x або y або z
    [012]    → 0 або 1 або 2

---

## Character Range

Діапазон символів задається через дефіс усередині character class.

Приклади:

    [0-9]  → одна цифра
    [a-z]  → одна мала латинська літера
    [A-Z]  → одна велика латинська літера
    [a-zA-Z] → одна латинська літера будь-якого регістру

Знайти рядки, що містять цифри:

    grep -E '[0-9]' file.txt

Знайти рядки, що містять латинські літери:

    grep -E '[a-zA-Z]' file.txt

Знайти рядки, що містять послідовність із чотирьох цифр:

    grep -E '[0-9][0-9][0-9][0-9]' file.txt

Такий шаблон знайде чотири цифри поспіль навіть усередині довшої послідовності.

---

## Negated Character Class

Символ `^` на початку character class означає заперечення.

Приклад:

    [^0-9]

Означає один символ, який не є цифрою.

Інші приклади:

    [^abc]     → символ, крім a, b або c
    [^0-9]     → символ, який не є цифрою
    [^a-z]     → символ поза діапазоном a-z

Знайти рядки, що містять хоча б один символ, який не є цифрою:

    grep -E '[^0-9]' file.txt

Важливо розрізняти:

    ^abc    → рядок починається з abc
    [^abc]  → один символ, який не є a, b або c

Значення `^` залежить від позиції.

---

# Quantifiers

Quantifiers — квантифікатори, які визначають кількість повторень попереднього елемента.

Основні квантифікатори ERE:

    *       → 0 або більше повторень
    +       → 1 або більше повторень
    ?       → 0 або 1 повторення
    {n}     → рівно n повторень
    {n,}    → n або більше повторень
    {n,m}   → від n до m повторень

У цьому розділі ці форми розглядаються для `grep -E`.

---

## Asterisk — *

`*` означає нуль або більше повторень попереднього елемента.

Наприклад:

    grep -E 'ab*c' file.txt

Може знайти:

    ac
    abc
    abbc
    abbbc

Пояснення:

    a
    b*  → нуль або більше символів b
    c

Важливо: `*` стосується лише попереднього елемента.

Наприклад:

    [0-9]*

означає нуль або більше цифр.

Оскільки допускається нуль повторень, шаблон може відповідати навіть позиції без цифр. Для пошуку хоча б однієї цифри в ERE використовують:

    [0-9]+

---

## Plus — +

`+` означає одне або більше повторень попереднього елемента в ERE.

Приклад:

    grep -E 'ab+c' file.txt

Знайде:

    abc
    abbc
    abbbc

Не знайде:

    ac

оскільки має бути хоча б одна `b`.

Знайти рядки, що містять одну або більше цифр:

    grep -E '[0-9]+' file.txt

Знайти послідовності малих латинських літер:

    grep -E '[a-z]+' file.txt

---

## Question Mark — ?

`?` означає нуль або одне повторення попереднього елемента в ERE.

Приклад:

    grep -E 'colou?r' file.txt

Відповідає:

    color
    colour

Літера `u` може бути відсутньою або бути присутньою один раз.

Інший приклад:

    grep -E 'https?://' urls.txt

Знайде рядки, що містять:

    http://
    https://

---

## Exact Repetition — {n}

`{n}` задає точну кількість повторень.

Наприклад:

    grep -E '[0-9]{4}' file.txt

Знайде послідовності з чотирьох цифр.

Приклад:

    2026
    1998
    1234

Шаблон:

    [0-9]{4}

означає:

    цифра
    цифра
    цифра
    цифра

Це не гарантує, що весь рядок складається лише з чотирьох цифр.

Щоб перевірити, чи весь рядок складається рівно з чотирьох цифр:

    grep -E '^[0-9]{4}$' file.txt

---

## Repetition Range — {n,m}

Задає мінімальну та максимальну кількість повторень.

Наприклад:

    grep -E '[0-9]{2,4}' file.txt

Знайде послідовності щонайменше з двох і щонайбільше з чотирьох цифр.

Приклади можливих збігів:

    12
    123
    1234

Щоб знайти рядки, які містять від двох до чотирьох цифр і нічого іншого:

    grep -E '^[0-9]{2,4}$' file.txt

---

# Alternation — |

Alternation означає вибір між кількома варіантами.

У ERE використовується символ:

    |

Наприклад:

    grep -E 'error|warning' app.log

Знайде рядки, що містять:

    error

або:

    warning

Інший приклад:

    grep -E 'cat|dog' animals.txt

Шаблон відповідає словам або частинам тексту:

    cat
    dog

Однак він може також збігатися з частиною довшого слова.

Наприклад, `concatenate` містить `cat`.

Якщо потрібно шукати окремі слова, можна використовувати межі слів у GNU grep:

    grep -E '\<(cat|dog)\>' animals.txt

Або для GNU grep із підтримкою PCRE:

    grep -P '\b(cat|dog)\b' animals.txt

Синтаксис меж слів залежить від інструмента та режиму.

---

# Grouping — ()

Дужки дозволяють об'єднувати частини регулярного виразу.

У ERE:

    (pattern)

Наприклад:

    grep -E '^(error|warning)$' status.txt

Знайде рядки, які повністю дорівнюють:

    error
    warning

Пояснення:

    ^             → початок рядка
    (error|warning) → один із двох варіантів
    $             → кінець рядка

Ще один приклад:

    grep -E '^(ab){3}$' file.txt

Знайде рядок:

    ababab

Тут:

    (ab){3}

означає три повторення групи `ab`.

Групування особливо корисне для складніших шаблонів.

---

# Escaping

Escaping — екранування спеціальних символів, щоб вони трактувалися буквально або мали спеціальне значення в потрібному режимі.

У багатьох регулярних виразах для цього використовується зворотна коса риска:

    \

Наприклад, крапка:

    .

означає будь-який один символ.

А:

    \.

означає буквальну крапку.

Пошук файлів JavaScript:

    grep -E '\.js$' files.txt

Знайде рядки, що закінчуються на:

    .js

---

## Пошук символу $

Щоб знайти буквальний символ `$`, потрібно екранувати його.

Наприклад:

    grep -E '\$[0-9]+' prices.txt

Може знайти:

    $10
    $25
    $100

Тут:

    \$    → буквальний символ $
    [0-9]+ → одна або більше цифр

---

## Пошук символу *

Щоб шукати буквальну зірочку в ERE:

    grep -E '\*' file.txt

Знайде рядки, що містять:

    *

---

## Regex і shell escaping

Під час використання regex у Bash важливо враховувати два рівні обробки:

    1. shell
    2. regex engine

Наприклад:

    grep -E '\.js$' files.txt

Одинарні лапки захищають шаблон від більшості інтерпретацій оболонкою.

Тому для звичайних regex-шаблонів у Bash зручно використовувати одинарні лапки:

    grep -E '^[0-9]+$' numbers.txt

Подвійні лапки дозволяють shell підставляти змінні та виконувати деякі види розширення.

Наприклад:

    pattern='^[0-9]+$'

    grep -E "$pattern" numbers.txt

Важливо: одинарні лапки не вимикають інтерпретацію regex самою командою. Вони лише захищають шаблон від небажаної обробки оболонкою.

# BRE vs ERE

У Linux поширені два режими POSIX-регулярних виразів:

    BRE → Basic Regular Expressions
    ERE → Extended Regular Expressions

Для GNU grep:

    grep     → BRE
    grep -E   → ERE

Різниця полягає в тому, як інтерпретуються деякі метасимволи.

| Можливість | BRE | ERE |
|---|---|---|
| Альтернатива | `\|` у GNU grep | `|` |
| Групування | `\(...\)` | `(...)` |
| Один або більше | `\+` у GNU grep | `+` |
| Нуль або один | `\?` у GNU grep | `?` |
| Повторення `{n}` | `\{n\}` | `{n}` |
| Крапка | `.` | `.` |
| Початок рядка | `^` | `^` |
| Кінець рядка | `$` | `$` |

У BRE символи `+`, `?`, `|`, `(`, `)` та `{` зазвичай не мають того самого спеціального значення, що в ERE. GNU grep підтримує деякі розширення BRE з екрануванням.

Для початкового рівня зручно використовувати:

    grep -E

оскільки синтаксис ERE часто простіший для читання.

Наприклад, ERE:

    grep -E '^(error|warning)$' status.txt

Еквівалентний шаблон у BRE для GNU grep:

    grep '^\(error\|warning\)$' status.txt

Для повсякденної роботи достатньо добре знати ERE та розуміти, що інші інструменти можуть використовувати інші режими.

# grep — пошук за регулярним виразом

`grep` — одна з головних команд Linux для пошуку тексту за шаблоном.

Основний синтаксис:

    grep 'PATTERN' file.txt

Наприклад:

    grep 'ERROR' app.log

Знайти рядки, що починаються з `ERROR`:

    grep -E '^ERROR' app.log

Знайти рядки, що містять цифри:

    grep -E '[0-9]+' app.log

Знайти рядки, що закінчуються на `.conf`:

    grep -E '\.conf$' files.txt

---

## Корисні параметри grep

### -E — Extended Regex

Дозволяє використовувати синтаксис ERE.

    grep -E '[0-9]+' file.txt

### -i — Ignore Case

Ігнорує регістр символів.

    grep -i 'error' app.log

Знайде:

    error
    ERROR
    Error

### -n — Number Lines

Показує номери рядків.

    grep -n 'ERROR' app.log

### -r — Recursive Search

Рекурсивно шукає у файлах каталогів.

    grep -r -n -E 'TODO|FIXME' src/

### -v — Invert Match

Показує рядки, які не відповідають шаблону.

    grep -v '^#' config.txt

Знайде рядки, які не починаються із символу `#`.

Ця команда також виведе порожні рядки, якщо вони є.

Щоб виключити коментарі та порожні рядки:

    grep -v -E '^[[:space:]]*(#|$)' config.txt

### -o — Only Matching

Виводить лише частини рядка, які збіглися з шаблоном.

    grep -o -E '[0-9]+' file.txt

Для тексту:

    User 42 connected in 15 seconds

Результат:

    42
    15

### -c — Count Matching Lines

Показує кількість рядків, що відповідають шаблону.

    grep -c 'ERROR' app.log

Важливо: `-c` рахує рядки, а не загальну кількість збігів у файлі.

### -l — Files with Matches

Показує лише назви файлів, у яких знайдено збіг.

    grep -r -l -E 'TODO|FIXME' src/

### -F — Fixed Strings

Шукає буквальний текст без інтерпретації regex.

    grep -F 'a.b' file.txt

Тут `.` — звичайна крапка, а не метасимвол regex.

### -w — Whole Word

Шукає цілі слова.

    grep -w 'cat' animals.txt

Це корисно, коли потрібно уникнути збігу з частиною іншого слова.

Поведінка `-w` залежить від визначення слова конкретним інструментом.

### -P — Perl-Compatible Regex

У GNU grep із підтримкою PCRE:

    grep -P '\d+' file.txt

`\d` відповідає цифрі в режимі PCRE.

Цей режим не є універсальним для всіх реалізацій grep. Для переносимих POSIX-шаблонів краще використовувати:

    grep -E '[0-9]+'

---

# POSIX Character Classes

POSIX character classes — стандартні класи символів, які зручно використовувати замість ручного переліку символів.

Синтаксис:

    [[:class:]]

Основні класи:

    [[:digit:]]   → цифри
    [[:alpha:]]   → літери
    [[:alnum:]]   → літери та цифри
    [[:lower:]]   → малі літери
    [[:upper:]]   → великі літери
    [[:space:]]   → пробільні символи
    [[:blank:]]   → пробіл або табуляція
    [[:punct:]]   → пунктуаційні символи
    [[:xdigit:]]  → шістнадцяткові цифри
    [[:cntrl:]]   → керівні символи
    [[:print:]]   → друковані символи
    [[:graph:]]   → видимі друковані символи без пробілу

Приклади нижче використовують `grep -E`.

## Цифри

    grep -E '[[:digit:]]+' file.txt

Еквівалентний поширений шаблон:

    grep -E '[0-9]+' file.txt

## Літери

    grep -E '[[:alpha:]]+' file.txt

## Літери та цифри

    grep -E '[[:alnum:]]+' file.txt

## Пробільні символи

    grep -E '[[:space:]]+' file.txt

## Шістнадцяткові цифри

    grep -E '[[:xdigit:]]+' file.txt

POSIX-класи залежать від локалі та правил конкретної реалізації. Для ASCII-форматів на кшталт простих ідентифікаторів іноді зручні явні діапазони `[A-Za-z0-9]`.

---

# Whitespace

Whitespace — пробільні символи, наприклад:

    space
    tab
    newline

У regex часто потрібно знаходити або видаляти зайві пробіли.

## Один або більше пробільних символів

    grep -E '[[:space:]]+' file.txt

## Рядок, що містить лише пробільні символи

    grep -E '^[[:space:]]+$' file.txt

## Порожні або пробільні рядки

    grep -E '^[[:space:]]*$' file.txt

## Рядки, що починаються з пробілу або табуляції

    grep -E '^[[:space:]]' file.txt

## Рядки, що закінчуються пробільним символом

    grep -E '[[:space:]]$' file.txt

Для POSIX-сумісного пошуку пробілів зручно використовувати `[[:space:]]`, а не покладатися на `\s`, який підтримується не в усіх режимах.

---

# Word Boundaries

Word boundary — межа слова.

Це поняття корисне, коли потрібно знайти слово, а не його частину.

Наприклад, у тексті:

    cat
    cats
    concatenate
    black cat

Пошук:

    grep -E 'cat' animals.txt

може знайти всі рядки, що містять `cat`, зокрема `cats` і `concatenate`.

У GNU grep для пошуку цілого слова можна використати:

    grep -w 'cat' animals.txt

У режимі PCRE:

    grep -P '\bcat\b' animals.txt

`\b` позначає межу слова в PCRE.

Для початкового рівня достатньо запам'ятати:

    grep -w 'word' file.txt

Але потрібно пам'ятати, що визначення слова залежить від інструмента, режиму та локалі.

---

# Regex для перевірки формату

Регулярні вирази часто використовують для перевірки тексту, який має певну структуру.

Важливо: regex перевіряє відповідність шаблону, але не завжди підтверджує семантичну правильність даних.

---

## Рядок лише з цифр

    grep -E '^[0-9]+$' numbers.txt

Відповідає:

    123
    4567
    9

Не відповідає:

    12abc
    abc12
    12 34

## Рівно чотири цифри

    grep -E '^[0-9]{4}$' years.txt

Може знайти:

    1998
    2026
    2040

Це перевіряє формат із чотирьох цифр, але не визначає, чи є число допустимим роком.

## Ідентифікатор із латинських літер, цифр та підкреслення

    grep -E '^[A-Za-z_][A-Za-z0-9_]*$' identifiers.txt

Шаблон відповідає рядкам, які:

    1. починаються з літери або _
    2. продовжуються літерами, цифрами або _
    3. не містять інших символів

Це спрощений шаблон для ідентифікаторів, а не повна перевірка правил конкретної мови програмування.

## Рядки, які починаються з HTTP-коду

    grep -E '^[0-9]{3} ' app.log

Може знайти:

    200 OK
    404 Not Found
    500 Internal Server Error

Цей шаблон перевіряє лише три цифри та пробіл на початку рядка.

## Прості email-подібні рядки

    grep -E '^[^[:space:]@]+@[^[:space:]@]+\.[^[:space:]@]+$' emails.txt

Цей шаблон відсіює деякі очевидно неправильні рядки, але не є повною перевіркою email за всіма правилами стандартів.

Для складних форматів, зокрема email, URL та IP-адрес, не варто вважати короткий regex повноцінним валідатором.

---

# Regex для логів

Логи — один із найкорисніших напрямів застосування регулярних виразів у Linux.

Приклад `app.log`:

    2026-10-19 INFO Server started
    2026-10-19 ERROR Database connection failed
    2026-10-19 WARN Disk usage is high
    2026-10-19 ERROR Invalid password
    2026-10-19 INFO Request completed

## Знайти всі ERROR

    grep -E 'ERROR' app.log

## Знайти ERROR та WARN

    grep -E 'ERROR|WARN' app.log

## Знайти рядки, що починаються з дати у форматі YYYY-MM-DD

    grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}' app.log

Цей шаблон перевіряє лише структуру дати, а не те, чи існує така дата в календарі.

## Знайти рядки з конкретним роком

    grep -E '^2026-' app.log

## Знайти рядки, що закінчуються на failed

    grep -E 'failed$' app.log

## Знайти рядки з цифрами

    grep -E '[0-9]+' app.log

## Показати номери рядків з помилками

    grep -n -E 'ERROR|FATAL' app.log

## Знайти помилки у всіх логах каталогу

    grep -r -n -E 'ERROR|FATAL' logs/

## Ігнорувати регістр

    grep -i -E 'error|warning' app.log

## Показати лише рядки без INFO

    grep -v 'INFO' app.log

# Regex разом із Pipeline

Regex особливо корисний у конвеєрах команд.

Pipeline передає стандартний вивід однієї команди на стандартний ввід іншої.

Символ:

    |

Наприклад:

    cat app.log | grep -E 'ERROR'

Але якщо команда вміє читати файл безпосередньо, `cat` не потрібен:

    grep -E 'ERROR' app.log

Це коротший і зазвичай кращий варіант.

## Відфільтрувати помилки та порахувати рядки

    grep -E 'ERROR|FATAL' app.log | wc -l

## Витягнути всі послідовності цифр

    grep -o -E '[0-9]+' app.log

## Відфільтрувати коментарі

    grep -v -E '^[[:space:]]*(#|$)' config.txt

## Знайти TODO у вихідному коді

    grep -r -n -E 'TODO|FIXME' src/

## Знайти рядки, що містять цифри, і відсортувати їх

    grep -E '[0-9]+' file.txt | sort

Важливо: `sort` сортує текст лексикографічно за замовчуванням, а не обов'язково за числовим значенням.

# Regex та sed

`sed` — потоковий редактор тексту, який часто використовує регулярні вирази для пошуку та заміни.

У GNU sed за замовчуванням використовується BRE.

Для ERE можна використовувати параметр:

    sed -E

## Замінити перше входження в кожному рядку

    sed 's/error/ERROR/' app.log

## Замінити всі входження в кожному рядку

    sed 's/error/ERROR/g' app.log

## Видалити порожні рядки

    sed '/^$/d' file.txt

## Видалити рядки, що починаються з коментаря

    sed '/^[[:space:]]*#/d' config.txt

## Замінити послідовність цифр на [NUMBER]

    sed -E 's/[0-9]+/[NUMBER]/g' file.txt

Приклад:

    User 42 connected in 15 seconds

Результат:

    User [NUMBER] connected in [NUMBER] seconds

## Замінити кілька пробілів одним

    sed -E 's/[[:space:]]+/ /g' file.txt

Ця команда замінює послідовності пробільних символів одним звичайним пробілом. Вона також може замінювати табуляції та інші пробільні символи, якщо вони присутні в оброблюваній області.

Докладніше про `sed`:

    02-sed/README.md

# Regex та awk

`awk` — інструмент для обробки тексту, особливо структурованих рядків і колонок.

В `awk` регулярні вирази можна використовувати для вибору рядків.

## Знайти рядки, що містять ERROR

    awk '/ERROR/ { print }' app.log

## Знайти рядки, що починаються з ERROR

    awk '/^ERROR/ { print }' app.log

## Знайти рядки, які містять цифри

    awk '/[0-9]+/ { print }' file.txt

У GNU awk (gawk) зазвичай підтримуються ERE, тому `+` означає одне або більше повторень.

## Вибрати рядки з першим полем ERROR

    awk '$1 == "ERROR" { print }' app.log

Тут `$1` — перше поле, а не символ кінця рядка.

## Вибрати рядки, де друге поле більше за 100

    awk '$2 > 100 { print }' data.txt

Це вже числова умова, а не regex.

Докладніше про `awk`:

    03-awk/README.md

# Regex vs Wildcards

Regex та shell wildcards схожі зовні, але мають різне призначення.

Wildcards використовуються оболонкою для підбору імен файлів.

Regex використовуються інструментами для пошуку текстових шаблонів.

| Символ | Shell wildcard | Regex |
|---|---|---|
| `*` | Будь-яка послідовність символів у шаблоні імені | Нуль або більше повторень попереднього елемента |
| `?` | Один будь-який символ | У ERE — нуль або одне повторення попереднього елемента |
| `[abc]` | Один символ із набору | Один символ із набору |
| `[0-9]` | Одна цифра в типовому ASCII-діапазоні | Одна цифра в заданому діапазоні |
| `.` | Звичайна крапка | Будь-який один символ у типовому режимі |

Приклад shell wildcard:

    ls *.js

Шукає файли, назви яких закінчуються на `.js`.

Приклад regex:

    grep -E '.*\.js$' files.txt

Шукає рядки, що закінчуються на `.js`.

Пояснення regex:

    .*     → будь-яка кількість символів
    \.     → буквальна крапка
    js     → буквальні символи
    $      → кінець рядка

Важливо: shell обробляє wildcard до запуску команди, тоді як regex інтерпретує програма, якій передано шаблон.

---

# Regex vs Fixed String

Не кожен пошук потребує регулярних виразів.

Якщо потрібно знайти буквальний текст, можна використати:

    grep -F

Наприклад, знайти рядок:

    app.log

Звичайний regex:

    grep 'app.log' file.txt

Тут крапка може відповідати будь-якому одному символу.

Буквальний пошук:

    grep -F 'app.log' file.txt

У цьому випадку крапка означає саме крапку.

Ще один приклад:

    grep -F 'https://example.com/a?b=1' urls.txt

Це зручно для пошуку URL, шляхів, ідентифікаторів та інших рядків, у яких багато символів мають спеціальне значення в regex.

Правило:

    потрібен шаблон → grep -E
    потрібен буквальний текст → grep -F

---

# Greedy Matching

Greedy matching — жадібний пошук, коли квантифікатор намагається охопити якомога більше тексту, залишаючись сумісним із шаблоном.

Наприклад, рядок:

    <title>Linux</title>

Шаблон:

    <.*>

може відповідати всьому рядку:

    <title>Linux</title>

Оскільки `.*` може включати символи `>` та інші символи до кінця рядка.

У POSIX ERE немає стандартного квантифікатора `*?` для нежадібного пошуку, який зустрічається в деяких інших regex-движках.

Якщо потрібно обробити простий рядок з тегами, можна використати точніший шаблон:

    <[^>]*>

Він шукає:

    <
    нуль або більше символів, крім >
    >

Для наведеного прикладу він знаходить окремі фрагменти:

    <title>
    </title>

Однак regex не є повноцінним парсером HTML. Для складного HTML краще використовувати інструменти, які розуміють структуру документа.

---

# Backreferences

Backreference — посилання на текст, який збігся з попередньою групою.

Підтримка та синтаксис залежать від режиму regex.

У GNU grep з BRE можна використовувати групи та посилання на них.

Наприклад:

    grep -E '([a-z])\1' words.txt

У GNU grep з ERE такий синтаксис підтримується для backreferences.

Шаблон шукає два однакові символи підряд, якщо вони входять до діапазону `[a-z]`.

Можливі збіги:

    book
    coffee
    letter

У цьому шаблоні:

    ([a-z]) → перша група, одна мала літера
    \1      → повторення того самого символу

Ще один приклад:

    grep -E '^([0-9]{2})-\1$' file.txt

Може знайти:

    12-12
    34-34

Але не знайде:

    12-34

Backreferences корисні для пошуку повторюваних фрагментів, але для початкового рівня достатньо розуміти їхню ідею.

---

# PCRE — Perl-Compatible Regular Expressions

PCRE — сімейство регулярних виразів, сумісних із синтаксисом Perl.

У GNU grep режим PCRE вмикається параметром:

    grep -P

Він доступний не в усіх реалізаціях grep.

PCRE підтримує додаткові можливості, які відсутні в базовому POSIX ERE.

Поширені приклади:

    \d  → цифра
    \w  → символ слова
    \s  → пробільний символ
    \b  → межа слова

Приклади:

    grep -P '\d+' file.txt

    grep -P '\bERROR\b' app.log

    grep -P '^\s*#' config.txt

У POSIX ERE переносимими альтернативами є:

    [0-9]+
    grep -w 'ERROR' app.log
    ^[[:space:]]*#

Не потрібно вивчати PCRE на початковому етапі. Спочатку варто засвоїти базові шаблони ERE.

# Common Regex Patterns

Нижче наведені шаблони, які часто використовуються в Linux.

У прикладах для `grep -E` використовується ERE.

## Будь-яка кількість символів

    .*

## Один або більше символів

    .+

## Лише цифри

    ^[0-9]+$

## Рядок лише з латинських літер

    ^[A-Za-z]+$

## Латинські літери та цифри

    ^[A-Za-z0-9]+$

## Рядок, що починається з літери

    ^[A-Za-z]

## Рядок, що закінчується на `.txt`

    \.txt$

## Рядок, що починається з `ERROR`

    ^ERROR

## Рядок, що закінчується на `failed`

    failed$

## Порожній рядок

    ^$

## Порожній або пробільний рядок

    ^[[:space:]]*$

## Рядок, що містить хоча б одну цифру

    [0-9]+

## Рядок, що містить хоча б одну малу латинську літеру

    [a-z]

## Рядок, що містить ERROR або WARNING

    ERROR|WARNING

## Рядок, що складається з трьох цифр

    ^[0-9]{3}$

## Прості назви файлів `.js`

    ^.*\.js$

## Рядок, що починається з коментаря або пробілів перед коментарем

    ^[[:space:]]*#

## Рядок без пробільних символів

    ^[^[:space:]]+$

## Послідовність із двох або більше цифр

    [0-9]{2,}

## Слово, що містить лише малі латинські літери

    ^[a-z]+$

# Практичні приклади

## Приклад 1 — знайти помилки

Файл:

    app.log

Команда:

    grep -E 'ERROR|FATAL' app.log

Знаходить рядки, що містять `ERROR` або `FATAL`.

---

## Приклад 2 — знайти всі рядки з датою

    grep -E '^[0-9]{4}-[0-9]{2}-[0-9]{2}' app.log

Шукає рядки, що починаються з дати у форматі:

    YYYY-MM-DD

---

## Приклад 3 — знайти файли JavaScript у списку

    grep -E '\.js$' files.txt

Знаходить рядки, що закінчуються на `.js`.

---

## Приклад 4 — знайти рядки, які містять тільки цифри

    grep -E '^[0-9]+$' numbers.txt

Приклад вхідних даних:

    123
    456
    abc
    12abc
    789

Результат:

    123
    456
    789

---

## Приклад 5 — знайти рядки без цифр

    grep -v -E '[0-9]' file.txt

Виводить рядки, які не містять жодної цифри.

---

## Приклад 6 — знайти коментарі у конфігурації

    grep -E '^[[:space:]]*#' config.txt

Знаходить рядки, де символ `#` стоїть на початку або після пробільних символів.

---

## Приклад 7 — видалити коментарі та порожні рядки

    grep -v -E '^[[:space:]]*(#|$)' config.txt

Виводить рядки, які не є порожніми та не починаються з коментаря після необов'язкових пробільних символів.

---

## Приклад 8 — витягнути числа з тексту

    grep -o -E '[0-9]+' file.txt

Для тексту:

    User 42 connected in 15 seconds

Результат:

    42
    15

---

## Приклад 9 — знайти повторені символи

    grep -E '([a-z])\1' words.txt

Шукає рядки, що містять дві однакові малі латинські літери підряд.

Приклади:

    book
    coffee
    letter

---

## Приклад 10 — знайти рядки, які починаються з HTTP-методу

    grep -E '^(GET|POST|PUT|DELETE) ' access.log

Знаходить рядки, що починаються з одного з перелічених HTTP-методів, за яким іде пробіл.

Це спрощений приклад для журналів із відповідним форматом.

---

## Приклад 11 — знайти IP-подібні рядки

    grep -E '[0-9]{1,3}(\.[0-9]{1,3}){3}' access.log

Шаблон знаходить послідовність із чотирьох числових частин, розділених крапками.

Він може знайти рядки на кшталт:

    192.168.1.10
    999.999.999.999

Другий приклад не є правильною IPv4-адресою, хоча відповідає цьому спрощеному шаблону.

Для повної перевірки IPv4-адреси потрібна додаткова перевірка діапазонів кожного октету.

---

## Приклад 12 — знайти URL, що починаються з HTTPS

    grep -E 'https://' urls.txt

Знаходить рядки, що містять:

    https://

Крапки в цьому шаблоні немає, тому додаткове екранування не потрібне.

---

## Приклад 13 — знайти слова, що починаються з `dev`

    grep -E '\bdev[A-Za-z0-9_]*' file.txt

У GNU grep із підтримкою PCRE для меж слів краще використовувати:

    grep -P '\bdev\w*' file.txt

Для переносимого POSIX ERE можна використовувати явні обмеження:

    grep -E '(^|[^[:alnum:]_])dev[A-Za-z0-9_]*' file.txt

Останній варіант знаходить слово, що починається з `dev`, на початку рядка або після символу, який не є літерою, цифрою чи підкресленням. При цьому збіг може містити попередній роздільник.

# Типові помилки

## Помилка 1 — забувати, що крапка є метасимволом

Неправильно для буквального пошуку:

    grep -E 'app.js' file.txt

Такий шаблон також може відповідати:

    appXjs

Правильно:

    grep -F 'app.js' file.txt

Або:

    grep -E 'app\.js' file.txt

---

## Помилка 2 — плутати regex та shell wildcards

Shell wildcard:

    *.js

Regex:

    .*\.js$

Це різні синтаксиси, які використовуються різними механізмами.

---

## Помилка 3 — забувати про режим regex

У ERE:

    grep -E 'a+b' file.txt

`+` означає одне або більше повторень `a`.

У звичайному BRE GNU grep для аналогічного шаблону використовують:

    grep 'a\+b' file.txt

Для навчання зручніше явно вказувати:

    grep -E

---

## Помилка 4 — використовувати `*`, коли потрібен `+`

Шаблон:

    [0-9]*

допускає нуль цифр.

Якщо потрібно хоча б одну цифру:

    [0-9]+

---

## Помилка 5 — забувати anchors

Шаблон:

    [0-9]+

знаходить послідовність цифр будь-де в рядку.

Шаблон:

    ^[0-9]+$

вимагає, щоб увесь рядок складався лише з цифр.

---

## Помилка 6 — вважати, що `^` завжди означає початок рядка

У звичайному regex:

    ^ERROR

означає початок рядка.

Але всередині character class:

    [^0-9]

символ `^` означає заперечення набору символів.

---

## Помилка 7 — забувати про регістр

За замовчуванням:

    grep 'error' app.log

не обов'язково знайде:

    ERROR

Для ігнорування регістру:

    grep -i 'error' app.log

---

## Помилка 8 — вважати короткий шаблон повним валідатором

Наприклад:

    grep -E '[0-9]{1,3}(\.[0-9]{1,3}){3}' file.txt

знаходить IP-подібні послідовності, але не перевіряє повністю правильність IPv4-адреси.

Regex може перевіряти формат, але складні правила часто потребують додаткової логіки.

---

## Помилка 9 — забувати про лапки

Рекомендовано:

    grep -E '^[0-9]+$' file.txt

Лапки допомагають уникнути небажаної інтерпретації шаблону оболонкою.

---

## Помилка 10 — вважати, що всі regex-движки однакові

Різні інструменти можуть підтримувати різні можливості:

    grep
    grep -E
    grep -P
    sed
    awk
    JavaScript RegExp
    Python re

Перед використанням складного шаблону потрібно перевірити синтаксис конкретного інструмента.

# Як навчитися читати Regex

Складний шаблон краще розбирати на маленькі частини.

Наприклад:

    ^[A-Za-z][A-Za-z0-9_]*$

Розглянемо його послідовно.

    ^

Початок рядка.

    [A-Za-z]

Одна латинська літера.

    [A-Za-z0-9_]*

Нуль або більше латинських літер, цифр або символів `_`.

    $

Кінець рядка.

У цілому:

    ^[A-Za-z][A-Za-z0-9_]*$

означає рядок, який починається з латинської літери та продовжується літерами, цифрами або підкресленнями.

Можливі збіги:

    user
    user1
    user_name
    Name2026

Не відповідають:

    1user
    _user
    user-name
    user name

Це приклад навчального шаблону, а не універсальний стандарт ідентифікаторів.

# Міні-шпаргалка

## Основні метасимволи

    .       → будь-який один символ
    ^       → початок рядка
    $       → кінець рядка
    *       → 0 або більше повторень
    +       → 1 або більше повторень в ERE
    ?       → 0 або 1 повторення в ERE
    |       → альтернатива в ERE
    (...)   → групування в ERE
    [...]   → набір символів
    [^...]  → заперечення набору на початку класу
    {n}     → рівно n повторень в ERE
    {n,}    → n або більше повторень в ERE
    {n,m}   → від n до m повторень в ERE
    \.      → буквальна крапка

## Пошук цифр

    grep -E '[0-9]+' file.txt

## Рядок лише з цифр

    grep -E '^[0-9]+$' file.txt

## Рядок лише з латинських літер

    grep -E '^[A-Za-z]+$' file.txt

## Рядок, що починається з ERROR

    grep -E '^ERROR' app.log

## Рядок, що закінчується на .js

    grep -E '\.js$' files.txt

## ERROR або WARNING

    grep -E 'ERROR|WARNING' app.log

## Ігнорувати регістр

    grep -i -E 'error|warning' app.log

## Виключити коментарі та порожні рядки

    grep -v -E '^[[:space:]]*(#|$)' config.txt

## Показати лише числа

    grep -o -E '[0-9]+' file.txt

## Знайти порожні рядки

    grep -E '^$' file.txt

## Знайти рядки з пробілами на початку

    grep -E '^[[:space:]]+' file.txt

## Знайти рядки з пробілами наприкінці

    grep -E '[[:space:]]+$' file.txt

## Пошук буквального тексту

    grep -F 'app.js' file.txt

## Рекурсивний пошук

    grep -r -n -E 'TODO|FIXME' src/

## Regex у sed

    sed -E 's/[0-9]+/[NUMBER]/g' file.txt

## Regex в awk

    awk '/ERROR/ { print }' app.log

# Головне

• Regular Expression — це шаблон для пошуку та обробки тексту.

• `grep` — основна команда Linux для пошуку рядків за шаблоном.

• `grep -E` використовує Extended Regular Expressions.

• `grep -F` шукає буквальний текст без інтерпретації regex.

• `.` відповідає будь-якому одному символу, а `\.` — буквальній крапці.

• `^` позначає початок рядка, а `$` — його кінець.

• `[0-9]` відповідає одній цифрі.

• `[a-z]` відповідає одній малій латинській літері.

• `[^0-9]` відповідає одному символу, який не є цифрою.

• `*` означає нуль або більше повторень.

• `+` означає одне або більше повторень у ERE.

• `?` означає нуль або одне повторення в ERE.

• `{n}` задає точну кількість повторень у ERE.

• `|` дозволяє вибирати між альтернативами.

• `()` дозволяють групувати частини шаблону в ERE.

• Regex і shell wildcards — різні механізми.

• Для пошуку цілого рядка за певним форматом часто використовують anchors:

    ^PATTERN$

• Для пошуку помилок у логах корисні шаблони:

    grep -E 'ERROR|FATAL' app.log

• Для витягування чисел:

    grep -o -E '[0-9]+' file.txt

• Для пошуку коментарів і пропуску порожніх рядків:

    grep -v -E '^[[:space:]]*(#|$)' config.txt

• Regex широко застосовується разом із:

    grep
    sed
    awk

• Один і той самий шаблон може працювати по-різному в різних regex-движках.

• Regex може перевіряти формат даних, але не завжди гарантує їхню семантичну правильність.

• Для початкового рівня Linux найважливіше навчитися читати шаблони, комбінувати їх і застосовувати для практичного пошуку в текстових файлах.

• Основна модель роботи:

    Текстовий файл
          ↓
    Regex pattern
          ↓
    grep / sed / awk
          ↓
    Знайдені рядки або оброблений текст

• Regex — це інструмент, який дозволяє перейти від пошуку конкретного слова до пошуку тексту за правилами.
