# 04. xargs

`xargs` — це команда Linux, яка читає дані зі стандартного введення (`stdin`) або файлу та використовує їх як аргументи для іншої команди.

`xargs` особливо корисна, коли потрібно передати результати однієї команди іншій команді.

Наприклад, за допомогою `find` можна знайти файли, а за допомогою `xargs` — передати їх команді `ls`, `grep`, `wc`, `rm` або іншій програмі.

`xargs` часто використовується разом із:

    find
    grep
    ls
    wc
    cat
    rm
    mkdir
    touch
    grep
    sort
    cut

Основне призначення `xargs`:

    input → xargs → command arguments → command execution

## Що потрібно пам'ятати

• `xargs` перетворює вхідні дані на аргументи команди.

• Найчастіше `xargs` читає дані зі `stdin`.

• Символ `|` передає `stdout` однієї команди на `stdin` іншої.

• `xargs` зазвичай розбиває вхідні дані за пробільними символами: пробілами, табуляціями та новими рядками.

• Звичайний `xargs` не завжди безпечно обробляє імена файлів із пробілами або спеціальними символами.

• Для роботи з іменами файлів, які можуть містити пробіли або переведення рядка, використовуй `find -print0` разом із `xargs -0`.

• `-n` обмежує кількість аргументів, переданих за один запуск команди.

• `-I` дозволяє вказати місце, куди підставляється кожен вхідний елемент.

• `-0` змушує `xargs` використовувати нульовий байт як роздільник.

• `-r` у GNU `xargs` не запускає команду, якщо вхід порожній.

• `-t` показує команду перед виконанням.

• `-p` запитує підтвердження перед виконанням команди.

• `-P` дозволяє запускати кілька процесів паралельно.

• `xargs` може запускати команду кілька разів, якщо аргументів забагато для одного виклику.

• Перед використанням `xargs rm` або іншої команди, яка змінює чи видаляє дані, перевір результати безпечним способом.

# Що таке xargs

`xargs` — команда для формування аргументів іншої команди на основі вхідних даних.

Загальний синтаксис:

    xargs [OPTIONS] [COMMAND [INITIAL-ARGS...]]

Наприклад:

    printf '%s\n' apple banana orange | xargs echo

Результат:

    apple banana orange

Що відбулося:

    printf
        ↓
    apple
    banana
    orange
        ↓
    stdin
        ↓
    xargs
        ↓
    echo apple banana orange

`xargs` прочитала три слова та передала їх команді `echo` як аргументи.

Якщо команда не вказана, `xargs` за замовчуванням використовує `echo`.

---

# stdin та stdout

Щоб розуміти `xargs`, потрібно знати два основні поняття.

## stdin

`stdin` (standard input) — стандартне введення програми.

Зазвичай це клавіатура або дані, отримані через pipe.

Приклад:

    printf '%s\n' apple banana orange | xargs

Результат:

    apple banana orange

`xargs` отримує дані через `stdin`.

## stdout

`stdout` (standard output) — стандартне виведення програми.

Зазвичай це термінал, але виведення можна передати іншій команді.

Приклад:

    printf '%s\n' apple banana orange

Результат:

    apple
    banana
    orange

Передавання виведення іншій команді:

    printf '%s\n' apple banana orange | xargs echo

Результат:

    apple banana orange

---

# Pipe та xargs

Pipe (`|`) передає стандартне виведення однієї команди на стандартне введення іншої.

Синтаксис:

    command1 | command2

Приклад без `xargs`:

    printf '%s\n' apple banana orange | wc -l

Результат:

    3

Тут `wc -l` читає текст зі `stdin` і рахує рядки.

А тепер використаємо `xargs`:

    printf '%s\n' apple banana orange | xargs echo

Результат:

    apple banana orange

Різниця:

    wc -l
        → читає текст і рахує рядки

    xargs echo
        → читає текст і передає його як аргументи echo

Важливо: не кожна команда потребує `xargs`. Якщо команда вміє читати `stdin` безпосередньо, часто можна обійтися без неї.

---

# Як працює xargs

Розглянемо приклад:

    printf '%s\n' one two three | xargs printf '[%s]\n'

Результат:

    [one]
    [two]
    [three]

Логіка роботи:

    1. printf створює вхідні дані.
    2. Pipe передає їх до xargs.
    3. xargs читає вхідні дані.
    4. xargs формує аргументи.
    5. Запускається друга команда.
    6. Команда обробляє передані аргументи.

У цьому прикладі `xargs` передає всі три слова одному запуску `printf`.

Команда:

    printf '[%s]\n' one two three

дає такий самий результат.

# Базове використання

## Передати список аргументів команді

    printf '%s\n' apple banana orange | xargs echo

Результат:

    apple banana orange

---

## Передати числа команді

    printf '%s\n' 10 20 30 | xargs echo Numbers:

Результат:

    Numbers: 10 20 30

Аргументи після `echo` є початковими аргументами команди.

`xargs` додає до них значення, прочитані зі `stdin`.

---

## Передати дані команді wc

    printf '%s\n' apple banana orange | xargs -n 1 echo | wc -l

Результат:

    3

Тут `-n 1` змушує `xargs` передавати по одному аргументу за запуск.

`echo` виводить кожне слово окремим рядком, а `wc -l` рахує рядки.

---

# Опція -n

`-n` задає максимальну кількість вхідних аргументів, які передаються команді за один запуск.

Синтаксис:

    xargs -n NUMBER COMMAND

Наприклад:

    printf '%s\n' apple banana orange | xargs -n 1 echo

Результат:

    apple
    banana
    orange

Команда запускається окремо для кожного слова.

Інший приклад:

    printf '%s\n' a b c d e | xargs -n 2 echo

Результат:

    a b
    c d
    e

Тут кожен запуск отримує не більше двох вхідних аргументів.

Ще приклад:

    printf '%s\n' 1 2 3 4 5 6 | xargs -n 3 echo

Результат:

    1 2 3
    4 5 6

Важливо:

    -n 1 → максимум 1 аргумент за запуск
    -n 2 → максимум 2 аргументи за запуск
    -n 3 → максимум 3 аргументи за запуск

Це не означає, що `xargs` обов'язково виконає команду саме таку кількість разів: кількість запусків залежить від кількості аргументів та інших обмежень.

---

# Опція -I

`-I` дозволяє визначити спеціальний рядок-замінник, який `xargs` підставляє замість кожного вхідного елемента.

Загальний синтаксис:

    xargs -I REPLACE_STRING COMMAND

Наприклад:

    printf '%s\n' apple banana orange | xargs -I {} echo 'Fruit: {}'

Результат:

    Fruit: apple
    Fruit: banana
    Fruit: orange

Тут:

    {} → спеціальний рядок-замінник

Для кожного вхідного елемента `xargs` підставляє його замість `{}`.

---

## Створення файлів через -I

Приклад:

    printf '%s\n' first.txt second.txt third.txt | xargs -I {} touch {}

Команда створює три файли:

    first.txt
    second.txt
    third.txt

Використовуй цей приклад лише в тестовому каталозі, оскільки `touch` створює файли, якщо їх немає, та змінює часові мітки наявних файлів.

---

## Інший рядок-замінник

Замість `{}` можна використати інший рядок.

    printf '%s\n' apple banana | xargs -I ITEM echo 'Fruit: ITEM'

Результат:

    Fruit: apple
    Fruit: banana

`ITEM` тут виконує ту саму роль, що й `{}`.

---

## xargs -n vs xargs -I

`-n` обмежує кількість аргументів за запуск.

    printf '%s\n' a b c | xargs -n 1 echo

Результат:

    a
    b
    c

`-I` підставляє кожен вхідний елемент у задане місце.

    printf '%s\n' a b c | xargs -I {} echo 'Value: {}'

Результат:

    Value: a
    Value: b
    Value: c

У GNU `xargs` використання `-I` також передбачає обробку одного вхідного рядка за запуск та має власні правила для рядків і замінників.

Для простого перебору аргументів використовуй `-n`, а коли потрібно вставити значення в певне місце команди — `-I`.

---

# Опція -0

`-0` (або `--null`) змушує `xargs` розділяти вхідні дані за нульовим байтом (`NUL`), а не за пробілами чи новими рядками.

Це один із найважливіших параметрів під час роботи з іменами файлів.

Проблема звичайного `xargs`:

    printf '%s\n' 'my file.txt' | xargs -n 1 echo

Результат:

    my
    file.txt

Звичайний `xargs` сприймає пробіл як роздільник аргументів.

Але ім'я файлу:

    my file.txt

є одним ім'ям, а не двома.

Виправлення:

    printf '%s\0' 'my file.txt' | xargs -0 -n 1 echo

Результат:

    my file.txt

Тут:

    \0 → нульовий байт у форматі printf
    -0 → читати вхідні дані до нульового байта

---

# find та xargs

`find` шукає файли й каталоги, а `xargs` може передавати знайдені шляхи іншій команді.

Загальна схема:

    find → xargs → command

Наприклад:

    find . -type f | xargs wc -l

Команда шукає файли в поточному каталозі та передає їх `wc -l`.

`wc -l` рахує кількість рядків у кожному файлі.

Однак цей варіант може працювати неправильно, якщо імена файлів містять пробіли, табуляції або символи нового рядка.

Для надійної обробки імен файлів використовуй `-print0` і `-0`.

---

## find -print0 та xargs -0

Безпечніший шаблон:

    find . -type f -print0 | xargs -0 wc -l

Тут:

    find . -type f
        → знайти звичайні файли

    -print0
        → вивести шляхи, розділені NUL

    xargs -0
        → прочитати шляхи, розділені NUL

    wc -l
        → порахувати рядки у файлах

Це стандартний шаблон для передавання знайдених файлів команді через `xargs`.

---

## Знайти всі файли .js

    find . -type f -name '*.js' -print0 | xargs -0 ls -l

Команда:

    1. Шукає звичайні файли.
    2. Відбирає файли з розширенням .js.
    3. Передає їх до ls -l.
    4. Виводить інформацію про знайдені файли.

Лапки навколо `*.js` потрібні, щоб шаблон обробляв `find`, а не оболонка Bash.

---

## Знайти всі файли .md

    find . -type f -name '*.md' -print0 | xargs -0 wc -l

Команда рахує кількість рядків у Markdown-файлах.

---

## Знайти файли та передати їх grep

    find . -type f -name '*.js' -print0 | xargs -0 grep -n 'console.log'

Команда шукає рядки `console.log` у знайдених JavaScript-файлах.

Опція `-n` команди `grep` показує номери рядків.

Якщо важливо обмежити пошук певними типами файлів, `find` допомагає відфільтрувати їх до передачі в `grep`.

---

# xargs та порожній ввід

За замовчуванням GNU `xargs` може запустити команду навіть тоді, коли вхідні дані порожні.

Наприклад:

    printf '' | xargs echo 'Hello'

Результат:

    Hello

Команда `echo` запускається без додаткових аргументів із введення.

Опція `-r` (або `--no-run-if-empty` у GNU `xargs`) дозволяє не запускати команду за порожнього вводу.

    printf '' | xargs -r echo 'Hello'

Результат:

    # нічого не виводиться

Це особливо важливо, коли команда може змінювати або видаляти файли.

Зверни увагу: поведінка без `-r` може відрізнятися в інших реалізаціях `xargs`.

---

# Опція -t

`-t` виводить команду до її виконання.

Приклад:

    printf '%s\n' apple banana | xargs -t echo Fruit:

Можливий результат у терміналі:

    echo Fruit: apple banana
    Fruit: apple banana

Це корисно для перевірки того, які аргументи фактично отримує команда.

---

# Опція -p

`-p` запитує підтвердження перед кожним запуском команди.

Приклад:

    printf '%s\n' first.txt second.txt | xargs -p -n 1 touch

`xargs` покаже команду та запропонує підтвердити її виконання.

Це корисно, коли потрібно перевіряти команди перед виконанням.

Особливо доречно використовувати `-p` під час навчання або перед потенційно небезпечними операціями.

---

# Опція -P

`-P` задає максимальну кількість процесів, які `xargs` може виконувати паралельно.

Синтаксис:

    xargs -P NUMBER COMMAND

Наприклад:

    printf '%s\n' 1 2 3 4 | xargs -n 1 -P 2 sleep

Цей приклад запускає `sleep` для кожного аргументу, використовуючи до двох паралельних процесів.

Оскільки `sleep` сприймає числа як тривалість очікування в секундах, кожен процес чекає відповідну кількість секунд.

Ще один приклад:

    printf '%s\n' 1 2 3 4 | xargs -n 1 -P 2 sh -c 'echo "Processing $1"; sleep 1' sh

Тут:

    -n 1 → один вхідний аргумент за запуск
    -P 2 → до двох паралельних запусків

Важливо:

• Результати паралельних процесів можуть виводитися в непередбачуваному порядку.

• Паралельне виконання не завжди прискорює роботу.

• Не запускай паралельно операції, які можуть конфліктувати під час запису в ті самі файли.

• Кількість процесів потрібно обирати з урахуванням ресурсів системи та характеру задачі.

---

# Опція -d

У GNU `xargs` опція `-d` дозволяє встановити власний роздільник.

Наприклад:

    printf 'apple,banana,orange\n' | xargs -d ',' -n 1 echo

Результат:

    apple
    banana
    orange

Тут кома є роздільником.

Важливо: `-d` є розширенням GNU `xargs` і не підтримується однаково в усіх Unix-подібних системах.

Для обробки імен файлів краще використовувати `-0`, якщо джерело може створити NUL-розділений список.

---

# Опція -a

`-a FILE` дозволяє читати аргументи з файлу замість стандартного введення.

Наприклад, створимо список:

    printf '%s\n' apple banana orange > fruits.txt

Тепер передамо його `xargs`:

    xargs -a fruits.txt echo Fruit:

Результат:

    Fruit: apple banana orange

Файл `fruits.txt` використовується як джерело аргументів.

Це зручно, коли список уже збережено у файлі.

---

# Опція -E

У GNU `xargs` опція `-E STRING` задає маркер завершення вводу.

Якщо `xargs` зустрічає цей рядок як окремий вхідний елемент, подальший ввід не обробляється.

Приклад:

    printf '%s\n' apple banana STOP orange | xargs -E STOP echo

Результат:

    apple banana

`STOP` тут є маркером завершення.

Важливо: поведінка та підтримка цієї опції залежать від реалізації `xargs`. Для повсякденного використання вона потрібна нечасто.

---

# xargs та аргументи команд

Важливо розрізняти текст, який передається через `stdin`, і аргументи, які отримує програма.

Наприклад:

    printf '%s\n' first second third | xargs echo

`echo` отримує аргументи приблизно так:

    argv[0] = echo
    argv[1] = first
    argv[2] = second
    argv[3] = third

Це спрощена модель аргументів програми.

`xargs` не вставляє текст у команду Bash як звичайний текстовий рядок. Вона формує аргументи та запускає команду.

Саме тому `xargs` не є повною заміною `eval` або засобом виконання довільного shell-коду.

---

# xargs та shell

За замовчуванням `xargs` запускає вказану програму безпосередньо, а не через інтерактивну оболонку.

Наприклад:

    printf '%s\n' hello | xargs echo

Тут запускається `echo` з аргументом `hello`.

Якщо потрібна складніша shell-логіка, можна явно використати `sh -c`.

Приклад:

    printf '%s\n' apple banana orange | xargs -I {} sh -c 'echo "Fruit: $1"' sh {}

Результат:

    Fruit: apple
    Fruit: banana
    Fruit: orange

Пояснення:

    sh -c 'COMMAND' sh ARGUMENT

У цьому шаблоні:

    $0 → sh
    $1 → переданий аргумент

Останній `sh` встановлює значення `$0`, а `{}` передає вхідний елемент як `$1`.

Такий спосіб дає змогу передавати значення як окремі аргументи, а не вставляти їх безпосередньо в текст shell-команди.

---

# Безпека xargs

`xargs` може виконувати команди з реальними наслідками: створювати, змінювати та видаляти файли.

Тому потрібно розрізняти правильне передавання аргументів і небезпечне формування shell-команд.

## Не вставляй недовірені дані в shell-код

Небажаний підхід:

    xargs -I {} sh -c "echo {}"

Якщо вхідні дані містять спеціальні символи оболонки, їхня інтерпретація може відрізнятися від очікуваної.

Краще передавати значення як окремий аргумент:

    printf '%s\n' 'some value' | xargs -I {} sh -c 'printf "%s\n" "$1"' sh {}

Або використовувати `printf`, `find` та інші інструменти без запуску оболонки, якщо вона не потрібна.

## Перед видаленням файлів перевір список

Спочатку подивись, які файли знайдено:

    find . -type f -name '*.tmp' -print

Після перевірки можна виконати команду з NUL-розділенням:

    find . -type f -name '*.tmp' -print0 | xargs -0 -r rm --

Пояснення:

    -print0 → виводить шляхи з роздільником NUL
    -0      → читає NUL-розділені шляхи
    -r      → не запускає команду за порожнього вводу
    rm --   → завершує обробку опцій перед іменами файлів

Увага: остання команда видаляє знайдені файли. Виконуй її лише після перевірки каталогу та шаблону пошуку.

`--` допомагає захиститися від інтерпретації імен файлів, які починаються з дефіса, як опцій команди `rm`.

# xargs та find -exec

`find` має власний механізм запуску команд через `-exec`.

Наприклад:

    find . -type f -name '*.txt' -exec wc -l {} \;

Ця команда запускає `wc -l` окремо для кожного знайденого файла.

Інший варіант:

    find . -type f -name '*.txt' -exec wc -l {} +

Тут `find` групує кілька шляхів в один виклик команди, наскільки це можливо.

Також можна використати `xargs`:

    find . -type f -name '*.txt' -print0 | xargs -0 wc -l

Обидва підходи мають свої переваги.

---

## find -exec vs xargs

`find -exec`:

    find . -type f -exec command {} \;

Запускає команду для кожного знайденого файла.

Варіант із `+`:

    find . -type f -exec command {} +

Групує шляхи для ефективнішого виконання.

`xargs`:

    find . -type f -print0 | xargs -0 command

Передає шляхи через pipe та може підтримувати додаткові можливості, наприклад паралельне виконання через `-P`.

Коли вибирати:

• `find -exec ... {} \;` — коли потрібен окремий запуск для кожного файла.

• `find -exec ... {} +` — коли потрібно групувати файли без окремого використання `xargs`.

• `find -print0 | xargs -0 ...` — коли потрібен конвеєр команд або додаткові можливості `xargs`.

Для багатьох задач із `find` варіант `-exec ... {} +` простіший і цілком достатній.

# xargs vs while read

Ще один спосіб обробляти список файлів — цикл Bash.

Приклад:

    while IFS= read -r file; do
        printf '%s\n' "$file"
    done < files.txt

Тут кожен рядок файлу читається як окреме значення.

Однак такий підхід не підходить для всіх можливих імен файлів, оскільки ім'я може містити символ нового рядка.

Для довільних імен файлів можна використовувати NUL-розділення:

    while IFS= read -r -d '' file; do
        printf '%s\n' "$file"
    done < <(find . -type f -print0)

У Bash:

    IFS=
        → вимикає стандартне обрізання пробілів

    read -r
        → не обробляє зворотні слеші як escape-послідовності

    -d ''
        → читає до NUL-байта в Bash

    find -print0
        → формує NUL-розділений список

Для звичайного передавання списку файлів команді часто достатньо `find -print0 | xargs -0`.

# ARG_MAX та обмеження аргументів

Операційні системи мають обмеження на загальний розмір аргументів і змінних середовища, які можна передати новому процесу.

На Unix-подібних системах це обмеження часто пов'язане з `ARG_MAX`.

Якщо передати надто багато аргументів за один запуск, виникає ризик помилки на кшталт:

    Argument list too long

`xargs` допомагає уникнути цієї проблеми, автоматично розбиваючи великий список на кілька запусків команди.

Наприклад:

    find . -type f -print0 | xargs -0 wc -l

Якщо знайдено дуже багато файлів, `xargs` може запустити `wc` кілька разів, передаючи різні групи шляхів.

Важливо пам'ятати:

• `xargs` не гарантує, що вся робота відбудеться за один запуск.

• Команда може виконуватися кілька разів.

• Для команд, які накопичують або змінюють спільний стан, потрібно враховувати цю особливість.

# Практичні шаблони

## 1. Передати список аргументів

    printf '%s\n' one two three | xargs echo

Результат:

    one two three

## 2. Передати по одному аргументу

    printf '%s\n' one two three | xargs -n 1 echo

Результат:

    one
    two
    three

## 3. Додати префікс до кожного значення

    printf '%s\n' app server database | xargs -I {} echo 'Service: {}'

Результат:

    Service: app
    Service: server
    Service: database

## 4. Порахувати рядки у файлах

    find . -type f -name '*.md' -print0 | xargs -0 wc -l

## 5. Знайти всі JavaScript-файли

    find . -type f -name '*.js' -print0 | xargs -0 ls -l

## 6. Знайти використання console.log

    find . -type f -name '*.js' -print0 | xargs -0 grep -n 'console.log'

## 7. Передати список файлів із текстового файлу

    xargs -a files.txt ls -l

## 8. Показати команду перед запуском

    printf '%s\n' one two three | xargs -t echo

## 9. Підтвердити запуск

    printf '%s\n' first.txt second.txt | xargs -p -n 1 touch

## 10. Запустити кілька процесів паралельно

    printf '%s\n' 1 2 3 4 | xargs -n 1 -P 2 echo

## 11. Обробити імена файлів із пробілами

    find . -type f -print0 | xargs -0 -n 1 printf '%s\n'

## 12. Видалити тимчасові файли після перевірки

    find . -type f -name '*.tmp' -print

    find . -type f -name '*.tmp' -print0 | xargs -0 -r rm --

Другу команду виконуй лише після перевірки першої.

# Типові помилки

## 1. Імена файлів із пробілами

❌ Ненадійний варіант:

    find . -type f | xargs ls -l

Імена з пробілами можуть розбиватися на кілька аргументів.

✔ Надійніший варіант:

    find . -type f -print0 | xargs -0 ls -l

---

## 2. Неправильне використання лапок

❌ Неправильне очікування:

    printf '%s\n' 'my file.txt' | xargs echo

Можна очікувати, що ім'я передасться як один аргумент, але звичайний `xargs` розбиває його за пробілом.

✔ Правильно для цього прикладу:

    printf '%s\0' 'my file.txt' | xargs -0 echo

---

## 3. Використання -I без потреби

Якщо потрібно просто передати список аргументів, часто достатньо:

    printf '%s\n' a b c | xargs -n 1 echo

`-I` потрібна тоді, коли значення необхідно вставити в певне місце команди.

---

## 4. Забувати про порожній ввід

Команда:

    printf '' | xargs echo Hello

У GNU `xargs` виведе:

    Hello

Якщо запуск за порожнього вводу небажаний:

    printf '' | xargs -r echo Hello

---

## 5. Припускати, що команда виконається один раз

❌ Неправильне припущення:

    find . -type f -print0 | xargs -0 command

Це не гарантує одного запуску `command`.

✔ Пам'ятай:

    xargs → один або кілька запусків

---

## 6. Небезпечне використання sh -c

❌ Не вставляй недовірені значення безпосередньо в текст shell-команди.

✔ Передавай їх як окремі аргументи:

    printf '%s\n' 'some value' | xargs -I {} sh -c 'printf "%s\n" "$1"' sh {}

---

## 7. Використання rm без перевірки

❌ Не запускай одразу:

    find . -type f -name '*.log' -print0 | xargs -0 rm --

✔ Спочатку переглянь список:

    find . -type f -name '*.log' -print

Після перевірки можна виконати видалення, якщо воно справді потрібне.

---

## 8. Використання -d замість -0 для імен файлів

`-d ','` підходить для спеціально сформованого списку, де кома є роздільником.

Але довільні імена файлів можуть містити кому.

Для роботи з іменами файлів зазвичай використовуй:

    find . -print0 | xargs -0 command

# Міні-шпаргалка

## Базовий синтаксис

    command | xargs another_command

Передає вхідні дані як аргументи іншої команди.

## Передати список

    printf '%s\n' a b c | xargs echo

Результат:

    a b c

## По одному аргументу

    printf '%s\n' a b c | xargs -n 1 echo

Результат:

    a
    b
    c

## Рядок-замінник

    printf '%s\n' a b c | xargs -I {} echo 'Value: {}'

## Імена файлів

    find . -type f -print0 | xargs -0 command

## Порожній ввід

    xargs -r command

У GNU `xargs` не запускає команду за порожнього вводу.

## Показати команду

    xargs -t command

## Підтвердити запуск

    xargs -p command

## Паралельне виконання

    xargs -n 1 -P 4 command

До чотирьох паралельних процесів, по одному вхідному аргументу за запуск.

## Читати аргументи з файлу

    xargs -a files.txt command

## Власний роздільник у GNU xargs

    xargs -d ',' command

## Перед видаленням

    find . -type f -name '*.tmp' -print

Спочатку перевір список, а потім за потреби виконуй:

    find . -type f -name '*.tmp' -print0 | xargs -0 -r rm --

# Основні правила

    xargs
        → перетворює ввід на аргументи команди

    |
        → передає stdout у stdin

    -n
        → обмежує кількість аргументів за запуск

    -I
        → підставляє вхідний елемент у задане місце

    -0
        → читає аргументи, розділені NUL

    -r
        → не запускає команду за порожнього вводу в GNU xargs

    -t
        → показує команду перед запуском

    -p
        → запитує підтвердження

    -P
        → дозволяє паралельні запуски

    -a
        → читає аргументи з файлу

    -d
        → задає роздільник у GNU xargs

    find -print0
        → формує NUL-розділений список шляхів

    xargs -0
        → правильно читає NUL-розділений список шляхів

    find -exec {} +
        → групує знайдені шляхи для запуску команди

# Головне

• `xargs` використовується для передавання вхідних даних як аргументів іншій команді.

• Найчастіше `xargs` працює разом із pipe та `find`.

• `xargs` формує аргументи програми, а не просто передає їй текст через `stdin`.

• Звичайний `xargs` розбиває ввід за пробільними символами, тому може неправильно обробляти імена файлів із пробілами.

• Для надійної обробки шляхів використовуй:

    find . -type f -print0 | xargs -0 command

• `-n` дозволяє контролювати кількість вхідних аргументів за запуск.

• `-I` дозволяє вставляти кожен вхідний елемент у задане місце команди.

• `-r` у GNU `xargs` запобігає запуску команди за порожнього вводу.

• `-P` дозволяє виконувати кілька процесів паралельно.

• `xargs` може автоматично розбивати великий список аргументів на кілька запусків команди.

• `find -exec ... {} +` часто є простішою альтернативою для пакетної обробки знайдених файлів.

• Не потрібно використовувати `xargs`, якщо команда вже вміє правильно обробляти дані зі `stdin`.

• Не вставляй недовірені дані безпосередньо в shell-код через `sh -c`.

• Перед використанням команд, що видаляють або змінюють файли, спочатку перевір список аргументів.

• Основна модель роботи:

    input
      ↓
    xargs
      ↓
    command arguments
      ↓
    command execution

• `xargs` особливо корисна в Linux для автоматизації роботи з файлами, текстом і результатами інших команд.
